# 02. 向量、矩阵、张量与 shape

## 为什么这一章必须尽早读

如果你学语言模型时对张量没有稳定直觉，那么几乎所有代码都会显得很乱。

你会看到：

- `[batch, seq, hidden]`
- `[batch, seq, vocab]`
- `transpose`
- `reshape`
- `matmul`

然后脑子里没有画面。

一旦没有画面，你就很难判断：

- 当前张量表示的是什么对象
- 某个维度为什么会变化
- 某个 `view` 或 `permute` 是否合理

所以在神经网络和语言模型里，张量不是附属数学背景，而是你理解整个系统的第一语言。

## 从最简单的对象开始：标量、向量、矩阵

### 标量

一个单独的数字，例如：

```text
3.14
```

它没有方向，也没有多个位置，就是一个值。

### 向量

一维数列，例如：

```text
[0.2, -1.3, 4.8]
```

你可以把它理解成：

- 一个特征列表
- 一个位置的表示
- 一个点在高维空间中的坐标

### 矩阵

二维表，例如：

```text
[
  [1.0, 2.0],
  [3.0, 4.0],
]
```

它可以表示：

- 多个向量按行或按列堆在一起
- 线性变换
- 一批样本的特征表

## 张量是什么

最实用的理解方式是：

> 张量就是“带 shape 的多维数值容器”。

这一定义非常朴素，但对工程理解很有效。

你不必一开始就陷入很抽象的数学张量定义。对于神经网络实现来说，更重要的是：

- 它有多少维
- 每一维代表什么
- 数据怎样在这些维之间流动

## shape 为什么比“数字有多少个”更重要

假设你有 4,096 个数。

它们可以被解释成很多不同结构：

- `[4096]`
- `[64, 64]`
- `[8, 512]`
- `[2, 4, 512]`

这些形状虽然元素总数相同，但语义完全不同。

所以在深度学习里，你不能只看“有多少个数”，更要看：

> 这些数按什么维度组织，它们在每一维上代表什么。

这就是 shape 的意义。

## 语言模型里最常见的三维张量

语言模型中最典型的一个张量形状是：

\[
[B, T, H]
\]

其中：

- `B` 是 batch size
- `T` 是 sequence length
- `H` 是 hidden size

你应该把它读成：

> 一批序列，每条序列有若干位置，每个位置都有一个长度为 `H` 的表示向量。

这一个形状几乎贯穿整个模型主体。

如果这件事在脑中不稳，后面的 block、Attention、logits 全都会显得很抽象。

## batch 维代表什么

batch 维表示一次并行处理多少个样本。

例如：

\[
[4, 128, 512]
\]

如果第一维是 `4`，意味着：

> 当前不是只在处理一条序列，而是在同时处理 4 条序列。

模型通常会对 batch 中的样本并行计算，这也是现代训练高效的重要原因之一。

## sequence 维代表什么

序列维表示：

> 当前每个样本里有多少个位置。

在语言模型里，这通常就是 token 序列长度。

例如：

\[
[4, 128, 512]
\]

中间那个 `128` 可以理解成：

> 每条样本都包含 128 个 token 位置。

## hidden 维代表什么

最后一维 `H` 是隐藏维度，也就是每个位置在模型内部被表示成多宽的向量。

例如：

\[
[4, 128, 512]
\]

最后的 `512` 表示：

> 每个 token 在这个阶段都由一个 512 维向量表示。

这不是“附加装饰信息”，而是模型内部真正做计算的对象。

## embedding 为什么会把 `[B, T]` 变成 `[B, T, H]`

输入 token id 一开始通常是：

\[
[B, T]
\]

因为每个位置只是一个整数索引。

经过 embedding 后，它会变成：

\[
[B, T, H]
\]

这意味着：

> 每个离散 token 被查表映射成了一个连续向量。

这一步是“从符号到表示”的关键转换。

## 线性层通常改变的是最后一维

在很多神经网络代码里，你会看到：

\[
[B, T, H] \rightarrow [B, T, H']
\]

为什么前两维不变？

因为很多层做的事情是：

> 对每个位置的表示向量应用同一个线性变换。

它不会改变：

- 有多少个样本
- 每个样本有多少个位置

它改变的是：

- 每个位置内部表示的宽度和内容

这就是为什么最后一维通常最常被投影和变换。

## 为什么矩阵乘法会在模型中反复出现

矩阵乘法之所以重要，是因为它天然适合表达线性变换。

你可以把一个线性层理解成：

> 用一个参数矩阵，把输入向量投影到另一个空间。

对于单个向量：

\[
x \in \mathbb{R}^{H}
\]

乘上一个权重矩阵后，可能得到：

\[
y \in \mathbb{R}^{H'}
\]

当你一次处理整个 batch 和整个序列时，这种变换会被批量并行应用到很多位置上。

## transpose、reshape、view 到底在做什么

这些操作本身不一定改变数值内容，但它们会改变你如何解释和组织这些数值。

### reshape / view

重新组织元素排列方式，前提通常是元素总数相同。

### transpose / permute

改变维度顺序。

这在 Attention 里很常见，因为不同计算阶段可能需要把：

- 头数
- 序列长度
- head 维度

放在不同位置上。

你在看到这些操作时，最重要的不是记函数名，而是持续追问：

> 改变后的 shape 现在在表达什么对象？

## 张量 shape 为什么也是调试工具

很多实现错误，最终最早暴露的信号并不是损失异常，而是 shape 不对。

例如：

- 词表维和隐藏维混了
- batch 维和序列维对不上
- flatten 时丢掉了本该保留的结构信息

因此在神经网络项目中，打印 shape 不是低级调试，而是最基础、最有效的验证方式之一。

一个成熟的直觉应该是：

> 看到 shape，我不仅知道“这是几维”，还知道“每一维的语义是什么，它为什么该长成这样”。

## 这一章真正要记住的核心句子

如果这一章只记住一句话，那应该是：

> 张量不是一堆数字，而是一组按维度组织起来的数据对象；在语言模型里，理解每个维度分别代表 batch、sequence、hidden 或 vocab，是读懂代码和定位错误的前提。

## 练习题

1. 为什么同样数量的数字，在不同 shape 下含义会完全不同？
2. 语言模型里最常见的 `[B, T, H]` 各自表示什么？
3. embedding 为什么会把 `[B, T]` 变成 `[B, T, H]`？
4. 为什么很多线性层主要改变最后一维？
5. 为什么 shape 检查本身就是一种重要的调试方法？
