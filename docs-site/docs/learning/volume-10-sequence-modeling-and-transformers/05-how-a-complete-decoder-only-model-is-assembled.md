# 07. 一个完整 decoder-only 模型怎样组装

## 这一章要完成的过渡

走到这里，卷八前面的章节已经把很多关键部件分别讲清楚了。

你已经知道：

- 文本为什么必须先变成 token 序列
- next-token prediction 为什么会长成右移一位的监督结构
- attention 为什么会出现
- QKV 怎样把按需读取历史写成结构
- causal mask 怎样保护自回归语义
- 位置方法怎样把顺序和距离写回模型
- block 为什么能成为可反复堆叠的主体砖块

如果这些知识还停留在“按章节会背”的状态，那么你对语言模型的理解依然是不闭环的。

因为真正的模型不是若干术语排成一行，也不是某个 `model.py` 里出现的几层模块定义。
真正的模型是一台机器。

这台机器会把：

- 原始文本
- 变成离散 token ids
- 映射到连续隐藏空间
- 在多层 causal block 中反复改写表示
- 最终回到词表上的 logits
- 在训练时形成 loss
- 在推理时继续生成下一个 token

所以这一章的任务非常明确：

> 把前面散开的知识重新装回一条完整数据流，真正回答“一个小而完整的 decoder-only 语言模型，从输入到输出，到底怎样成为一台可训练、可推理、可解释的系统”。

这也是卷八最后一个非常关键的动作：

> 从“砖块是怎么工作的”推进到“整台机器是怎么闭合起来的”。

## 先把“完整模型”这个词讲清楚

很多初学者一说“模型”，脑子里就会先出现：

- token embedding
- 一叠 Transformer blocks
- 一个线性输出头

这种理解不算完全错，但通常过窄。

如果你把“完整 decoder-only 模型”理解得足够严谨，它至少包含三层东西。

第一层是符号协议层。

也就是：

> 原始文本怎样被切成 token，词表里有哪些条目，特殊符号怎样约定，整数 id 如何分配。

第二层是神经网络主体层。

也就是：

> token ids 怎样进入 embedding，怎样进入位置方法，怎样经过多层 block，被改写成最终 logits。

第三层是运行协议层。

也就是：

> 训练时怎样对齐标签、怎样形成 loss、怎样更新参数；推理时怎样自回归展开、怎样从 logits 变成下一 token、怎样利用缓存。

只有这三层一起成立，你手上的才是一台真正完整的语言模型。

所以这一章不会只回答：

> 网络里有哪几层？

它还要回答：

> 这些层怎样连同 tokenizer、标签协议、输出协议和推理协议闭成一台完整机器？

## 整机骨架先看一遍：不要一开始就掉进代码细节

如果先把所有细节折叠起来，一台标准 decoder-only 语言模型的核心路径可以被写成：

```text
原始文本
-> 文本规范化与 tokenizer
-> token ids
-> token embedding
-> 位置方法
-> N 层 causal Transformer blocks
-> final norm
-> LM head
-> logits
-> （训练时）cross-entropy loss
-> （推理时）采样并追加下一个 token
```

这条链看上去简单，但里面已经藏着几个非常重要的判断。

第一，tokenizer 不是网络外的可有可无小工具，而是整机输入输出协议的一部分。

第二，训练和推理并不是两台不同的网络。
它们共享同一台主体，差别主要在于：

- 外层调用协议不同
- 是否提供目标标签
- 是并行处理整段序列，还是逐 token 地继续展开

第三，完整模型不只是一条前向函数。
它还包括：

- 输入端怎样离散化
- 输出端怎样解释
- 训练时怎样闭合成监督系统
- 推理时怎样闭合成生成系统

只要这三点先在脑子里站稳，后面很多工程细节都会自然很多。

## 整台机器真正的起点，不是张量，而是离散符号协议

很多人第一次画语言模型结构图时，习惯直接从 embedding 开始。
从纯神经网络实现角度看，这没问题。
但从系统理解角度看，这样开始得太晚了。

因为语言模型真正面对的第一个关键问题不是：

> 向量维度是多少？

而是：

> 什么算一个输入单位？

这个问题不是由线性层决定的，而是由 tokenizer 和词表协议决定的。

如果这个离散协议没有先讲清楚，后面的 embedding、输出头、loss、采样都会显得像漂浮在半空中的技术细节。

所以真正完整的整机理解，必须从一句更靠前的话开始：

> 模型首先要先定义自己的离散语言。

它要先决定自己眼里的基本符号单位是什么，然后后面的网络主体才有东西可学。

## 为什么 tokenizer 属于整机定义，而不是模型外附件

这是学习项目里最容易被低估的一点。

很多初学者会把 tokenizer 看成：

- 训练前的预处理脚本
- 随手可换的小配件
- 反正只是把文本切一切

更准确的理解应该是：

> tokenizer 决定了模型看到的基本符号单位，也决定了模型最终要预测的类别空间。

因为 tokenizer 会定义：

- 词表里有哪些 token
- 每个 token 的整数 id 是什么
- 空格、标点、大小写、字节或子词边界怎样进入符号系统
- 哪些 token 是特殊边界协议的一部分

这些决定会一路影响：

- embedding 表大小
- LM head 输出维度
- 样本长度分布
- special token 的训练语义
- 文本在生成后如何被还原回人类可读字符串

所以换 tokenizer 不是像换一把扳手。
更像是：

> 换了一套输入输出语言。

这就是为什么 tokenizer 应被视为完整模型资产的一部分，而不是模型外面的闲置脚本。

## 从原始文本到 token ids，中间到底发生了什么

在真实项目里，从原始文本到模型输入，并不只是“一键 encode”这么简单。

一条更完整的链通常是：

1. 文本清洗或规范化  
2. 按 tokenizer 规则切分  
3. 必要时插入 special token  
4. 映射到词表整数 id  
5. 再按训练所需切成固定长度样本  

这条链上每一步都不只是工程杂务。
它们都在改写模型将要看到的序列世界。

例如：

- 规范化策略改变，token 分布会改变
- special token 协议改变，边界语义会改变
- 切片策略改变，模型看到的上下文统计会改变

所以当我们说“完整模型”，其实已经隐含包含了这条离散化管线。

整机并不是从 `forward()` 的第一行才开始。
整机在文本被定义成 token 的那一刻，就已经开始了。

## token ids 到底是什么

经过 tokenizer 之后，文本会变成一串类似下面这样的整数：

```text
[41, 982, 17, 5, 203]
```

这串整数特别容易让初学者产生一个误解：

> 这些数值大小本身是不是带有某种强弱、远近或语义关系？

答案是否定的。

这些数不是连续数值特征，而是：

> 词表索引。

这意味着：

- id 为 1000 不比 id 为 10 更“强”
- id 之间的差值不代表语义距离
- 整数本身只是标签，不是特征空间坐标

因此，模型不能直接把这些整数当作普通连续输入来处理。

也正因为如此，embedding 必须出现。

## embedding 为什么是神经网络主体真正的入口

神经网络主体擅长处理的是：

- 连续向量
- 可微表示
- 高维空间中的几何关系

而 token ids 只是离散索引。

所以网络主体的第一件大事，就是把离散索引映射到连续表示空间：

\[
\text{Embedding}: \text{token id} \rightarrow \mathbb{R}^{d_{\text{model}}}
\]

如果输入 token ids 的形状是：

\[
[B, T]
\]

那么 embedding 之后通常会得到：

\[
[B, T, H]
\]

其中：

- `B` 是 batch size
- `T` 是序列长度
- `H` 是隐藏维度，也就是 `d_model`

这一步的意义非常深。

因为从这一刻开始，模型终于不再面对“词表编号”，而开始面对：

> 一组可被读取、可被混合、可被非线性加工、可被后续层持续改写的连续表示。

所以 embedding 绝不是“轻描淡写的一步初始化”。
它是真正把离散语言世界接进神经表示世界的第一道门。

## 为什么 embedding 绝不是小步骤

很多初学者会因为 embedding 在代码里只是一层表查找，就下意识低估它的重要性。

但从整机角度看，embedding 承担着至少三重职责。

第一，它是符号到连续空间的翻译器。

如果没有它，整个神经网络主体就无从开始。

第二，它决定了模型初始表示空间的容量和分辨率。

隐藏维度不是一个随手可填的数字，它决定了每个 token 起步时能拥有多少表达空间。

第三，它与输出头之间还有深刻关系。

因为语言模型最终还要回到词表空间预测下一个 token。
所以 embedding 和 LM head 并不是彼此无关的前后两层。
它们在很多架构里甚至会共享权重。

换句话说，embedding 不是“小入口”。
它是整台机器从符号世界进入表示世界的总入口。

## 位置方法为什么必须在主体很早阶段进入

上一章已经讲过，位置方法补的是序列几何，而不是语义小装饰。

一旦 token 被映射成 embedding，模型接下来就必须尽快解决一个问题：

> 同样的内容出现在不同位置时，为什么不应该被当成完全相同的事件？

这就是位置方法必须在主体很早阶段进入的原因。

因为如果在进入 block 之前，表示里还完全没有位置感，那么后面的 attention 一开始面对的仍然只是“内容项集合”，而不是带几何结构的序列。

位置方法进入主体的方式，大体有两条经典路线。

一条是先把位置融入输入表示。

也就是把位置向量与 token embedding 合并，让表示在进入第一层 block 之前就已经带上位置感。

另一条是直接把位置写进 attention 匹配过程。

也就是不只改输入表示，而是让 query-key 的关系本身带上位置结构。

无论选哪条路线，本质都一样：

> 模型必须在很早的时候就获得序列几何，否则后面的主体砖块会在缺少坐标感的前提下开始工作。

## 进入主体：为什么是一叠 causal Transformer blocks

经过 embedding 和位置处理以后，模型终于得到了一串可以被深度加工的连续表示。

接下来，主体的核心就进入了：

> 多层 causal Transformer blocks。

这里最重要的不是“层数很多”，而是每一层都在做同一类高层任务：

- 保留当前位置旧表示
- 允许它从合法历史中按需读取信息
- 在当前位置内部继续非线性加工
- 把更新后的主表示流继续交给下一层

这就是上一章所说的 block 作为“受控修正器”的意义。

因此，一叠 block 的真正含义不是：

> 把同一个盒子复制 N 次。

更准确的说法是：

> 让同一条 residual stream 在很多轮“读取 + 重写”中逐渐成熟。

所以主体的深度，本质上代表的不是参数堆叠本身，而是：

> 表示能获得多少轮上下文驱动的改写机会。

## final norm 为什么常出现在主体尾部

在很多 decoder-only 架构里，经过所有 block 之后，主体尾部还会再接一个 final norm。

这一步看上去很不起眼，但它的作用通常可以这样理解：

> 在把最终隐藏状态送进词表输出头之前，再对整条主表示流做一次末端整理。

前面很多层 block 都在对 residual stream 加修正。
当表示已经经过很多轮叠加以后，最后再做一次归一化整理，可以让输出头面对更可控的输入状态。

所以 final norm 不是与 block 无关的零碎附件。
它更像整条主体流水线在进入输出端之前的最后一道整流工序。

## 输出头在整机里到底做什么

当模型经过所有 block 以后，每个位置最终拥有一份成熟得多的隐藏表示。

但这份隐藏表示还不是模型的最终预测。

语言模型最终要做的是：

> 对词表中的每一个 token 给出一个未归一化偏好分数。

这就是 LM head 的职责。

如果词表大小是 `V`，隐藏维度是 `H`，那么 LM head 通常可以被看成一个：

\[
H \rightarrow V
\]

的线性映射。

于是最终输出张量形状会变成：

\[
[B, T, V]
\]

这里的最后一维不再是隐藏空间，而是词表上的候选类别空间。

所以 LM head 的角色不是“最后随手接个分类器”。
更准确地说：

> 它负责把主体内部已经成熟的表示，重新翻译回模型自己的离散语言空间。

## 为什么 LM head 不是最后顺手接的一层线性层

很多人会觉得 LM head 只是最后做了一次线性投影，所以好像并不重要。

这种看法低估了它在整机中的位置。

LM head 的重要性在于，它承担了一个非常关键的翻译动作：

> 把隐藏空间中的连续表示，重新投影成对整个词表的未归一化偏好。

也就是说，模型直到这一刻，才真正重新回到“下一个 token 应该是谁”的问题上。

前面的 embedding 是从词表走进隐藏空间。
这里的 LM head 则是从隐藏空间走回词表。

于是整机在很高层可以被看成一个闭环：

- 从离散符号出发
- 进入连续表示世界
- 在连续世界里经过多轮上下文读写
- 最终再回到离散符号分布

只要把这条环路看清，LM head 的重要性就不可能再被误解成“最后接一下输出层”。

## 为什么很多模型会共享输入 embedding 和输出头权重

在不少语言模型里，输入 embedding 矩阵和输出头权重会共享。

这是一个很有代表性的设计，因为它恰好暴露了整机的对称性。

输入端做的是：

> 从词表索引走到隐藏表示。

输出端做的是：

> 从隐藏表示走回词表偏好。

这两件事并不是完全相同，但显然有很强关联。

因此，权重共享背后的直觉可以先这样理解：

> 既然输入和输出都围绕同一套词表空间展开，那么让“进入表示空间的门”和“回到词表空间的门”共享同一套几何结构，往往是合理的。

不必一开始把它理解成复杂技巧。
先记住：它体现的是整机在词表空间与隐藏空间之间的一种结构对称。

## logits 到底是什么，为什么它们还不是 token

经过 LM head 以后，模型得到的是 logits，而不是直接得到 token。

这一点特别重要，因为它决定了训练和推理为什么能共享同一台主体，却又走出不同协议。

logits 最简洁的理解是：

> 模型对词表中每个候选 token 给出的未归一化偏好分数。

它们还不是概率，也还不是最终选中的 token。

这一步故意停在 logits，而不是直接做出离散决定，有两个非常大的好处。

第一，训练时可以直接用 logits 与目标 token 做交叉熵，获得稳定可导的损失信号。

第二，推理时可以灵活决定选择策略。

你可以：

- 贪心选最大
- 加 temperature
- 做 top-k
- 做 top-p

也就是说，logits 是训练协议和推理协议都能接受的共同接口层。

这也是为什么很多知识点到了这里才真正闭合：

> 前面的主体负责把表示磨出来，而 logits 则把这些表示暴露成一个既可训练、又可生成的统一输出接口。

## 到这里，纯前向的整机路径可以怎样写

如果先不引入训练和推理协议，只看“给定一个 token 前缀，网络主体前向会做什么”，整条路径可以被写成：

```text
token ids
-> embedding lookup
-> 位置方法
-> block 1
-> block 2
-> ...
-> block N
-> final norm
-> LM head
-> logits
```

这就是整台模型的纯前向骨架。

请注意，这条骨架仍然只是一台“会算 logits 的网络”。
要让它变成真正的语言模型系统，还必须再补两件事情：

- 训练时如何把 logits 接到目标标签和 loss 上
- 推理时如何把 logits 接到采样和自回归展开上

也就是说，整机前向只是闭环的一半。

## 训练时怎样把这台主体闭合成“可学习系统”

训练的关键不在于换一台模型，而在于在同一台主体外面再加一层监督协议。

这层监督协议最核心的动作，就是：

> 把当前位置的 logits 对齐到“下一个 token”这个目标上。

如果输入序列是：

```text
x1 x2 x3 x4
```

那么模型在位置 `1` 产生的输出，不是去预测 `x1`，而是去预测 `x2`。
位置 `2` 的输出去预测 `x3`，以此类推。

这就是右移一位监督结构的真正含义。

于是，训练时整机闭环就变成：

```text
输入 token ids
-> 主体前向得到 logits
-> 按右移一位标签对齐目标 token ids
-> 计算交叉熵 loss
-> 反向传播
-> 参数更新
```

到这一刻，原本只是会吐出 logits 的主体，才真正变成了一台可学习系统。

## 为什么主体结构和训练协议必须分开理解

这是很多初学者特别容易混的一个点。

他们会把：

- embedding
- blocks
- LM head
- 右移标签
- loss

全部混成“模型结构的一部分”。

其实更稳的拆法是：

模型主体回答的是：

> 给定一段 token 前缀，我能算出每个位置对词表的偏好吗？

训练协议回答的是：

> 这些偏好应该拿来和谁比较？怎样把比较结果变成损失和梯度？

把这两层分开非常重要。
因为后面推理时，你会看到：

- 主体没变
- 输出接口没变

变的只是外层不再接目标标签，而是接采样与生成循环。

这也是为什么我们一直强调：

> 训练和推理共享同一台网络主体，只是外层协议不同。

## PAD、ignore index 和样本边界为什么也属于训练闭环的一部分

一旦真正进入训练协议，还会遇到一些初学者常低估的边界问题：

- 某些位置是不是 padding
- 某些位置是否应该参与 loss
- 样本边界处的 token 应不应该预测到另一个样本上

这些看起来像数据细节，实际上都属于训练闭环的一部分。

因为只要你在训练中错误地让某些无意义位置参与监督，或者让样本边界语义混乱，模型学到的就不再是你以为的任务。

所以“完整模型”不只是网络本身，也包括：

> 训练时哪些位置算有效监督，哪些位置不算。

这进一步说明整机理解必须比“看几层网络”更完整。

## 推理时整台机器又是怎样工作的

如果说训练是在同一台主体外面接上目标标签和 loss，那么推理则是在同一台主体外面接上一条生成协议。

最基本的推理闭环是：

1. 给模型一段前缀 token ids  
2. 前向得到当前各位置 logits  
3. 只取最后一个位置的 logits 作为“下一个 token”的候选分布接口  
4. 用某种采样策略选出一个 token  
5. 把新 token 追加到前缀后面  
6. 再把更长的新前缀送回模型继续算  

于是整机在推理时就从“并行监督系统”切换成了“自回归展开系统”。

请注意，真正变的不是模型砖块，而是：

> 外层从“和目标比较”变成了“用当前输出继续扩展输入”。

这就是训练和推理共享主体、但表现形式差异很大的根本原因。

## 为什么推理时通常只看最后一个位置的 logits

推理阶段虽然前向会为整段前缀算出一串位置的 logits，但真正对“下一个 token 是谁”有用的，通常只有最后一个位置的输出。

原因非常简单。

第 `i` 个位置的 logits 语义是：

> 基于当前位置之前的前缀，预测第 `i+1` 个 token 的分布。

于是，当你已经给出整个前缀以后，真正对应“前缀之后那个新 token”的，当然就是最后一个位置的输出。

所以推理不是“看所有位置一起投票”，而是：

> 每一步都用当前前缀末尾位置的输出，决定下一步追加谁。

只要这一点讲清楚，自回归生成的很多后续细节都会自然很多。

## prefill 和 decode 在整机里分别是什么

推理协议继续细分时，经常会出现两个词：

- prefill
- decode

它们不是两台不同机器，而是同一生成闭环里的两个阶段。

prefill 阶段可以先理解成：

> 把已有整段前缀第一次送进模型，让每一层的历史 key/value 都建立起来。

decode 阶段则是：

> 在前缀已经存在的基础上，每次只为新位置继续做一次增量生成。

所以二者的差别不是模型主体换了，而是当前是否还在“初始化整个前缀状态”，还是已经进入“逐步展开新增位置”的节奏。

这也解释了为什么 KV cache 会自然出现。

## KV cache 在完整整机里扮演什么角色

KV cache 的意义，并不是给模型换了另一种结构。
它只是利用了 decoder-only 单向因果结构带来的一个高效性事实：

> 过去位置的 key/value 一旦算好，在后续生成中就可以被反复复用，不需要每一步都从头重算。

所以把 KV cache 放回整机里理解，它更像：

> 推理协议对同一台主体的一种缓存加速层。

模型本体没有变：

- embedding 还是那个 embedding
- blocks 还是那些 blocks
- LM head 还是那个 LM head

变化的是：

> 推理系统开始记住过去已经算好的中间结果，以避免重复劳动。

因此，KV cache 应被理解成生成协议的一部分，而不是另一种模型架构。

## special token、config、checkpoint 为什么都属于“完整模型资产”

当你真正从整机角度看模型时，会发现“模型资产”远不止一个权重文件。

一个可复现、可加载、可部署的完整 decoder-only 模型，通常至少需要：

- tokenizer 相关文件
- 词表与 special token 协议
- 模型 config
- 训练得到的 checkpoint 或权重
- 推理时需要的解码约定

原因不难理解。

只拿到一份权重而没有 tokenizer，你就不知道输入输出协议是什么。
只拿到 tokenizer 而没有 config，你就不知道主体隐藏维度、层数、头数怎样定义。
只拿到 config 没有权重，你又只有机器骨架，没有实际学到的参数。

所以“完整模型资产”的更稳定义是：

> 任何会影响这台机器如何接收输入、如何组织内部结构、如何产生输出、如何被再次加载与运行的文件，都是模型的一部分。

这也是为什么真正的模型交付从来不只是一个 `*.pt` 或 `*.bin` 文件。

## 一个更稳的整机边界定义

到这里，可以把“完整 decoder-only 模型”的边界压成一句特别稳的话：

> 它不是一叠 Transformer blocks，而是一整套从离散符号协议出发，经过连续表示主体，再回到词表分布接口，并能在训练与推理两种协议下运行的完整机器。

这句话里每一段都很重要。

“离散符号协议”说明 tokenizer、词表和 special token 不在机器外面。

“连续表示主体”说明 embedding、位置方法、blocks、final norm、LM head 构成了神经核心。

“回到词表分布接口”说明最终输出不是任意向量，而是词表上的 logits。

“训练与推理两种协议”说明同一台主体既能接到 loss，也能接到生成循环。

只要这条边界立住，你就不容易再把模型误解成“若干层网络”而忽略协议层。

## 为什么“小而完整”的价值远大于“大但不闭环”

这也是学习项目里最值得反复提醒自己的一点。

很多人一开始就想追更大参数量、更长上下文、更复杂优化技巧。
但如果整机边界并不清楚，你最后很可能只是：

- 会跑一个仓库
- 会调几个超参数
- 会调用若干现成模块

却说不清：

- 输入协议是什么
- 主体在哪里开始、在哪里结束
- logits 怎样变成 loss
- logits 又怎样变成生成
- checkpoint 到底保存了什么

从学习价值角度看，一个真正“小而完整”的模型往往远远胜过一个“大但你只会调用”的模型。

因为前者能让你看清整台机器怎样闭合，而后者常常只让你看见几个局部接口。

## 常见误区

### 误区一：完整模型就是若干层 Transformer block

不对。

block 只是神经主体的一部分。
完整模型还包括 tokenizer、词表协议、输出接口，以及训练与推理协议。

### 误区二：embedding 只是很小的一步，不重要

不对。

embedding 是整机从离散符号世界进入连续表示世界的总入口。

### 误区三：训练模型和推理模型是两台不同机器

不对。

训练和推理共享同一台网络主体，变化主要发生在外层协议。

### 误区四：LM head 只是最后顺手接个分类器

不对。

它承担的是把隐藏表示重新翻译回词表分布空间的关键动作。

### 误区五：tokenizer 是模型外部小工具，换了也差不多

不对。

tokenizer 定义了输入输出协议、词表空间与特殊边界语义，换它等于换离散语言接口。

### 误区六：KV cache 属于另一种模型结构

不对。

它是同一主体在推理协议下的一种缓存加速机制，而不是另一台模型。

## 这一章真正要记住的核心句子

如果你只记住本章八句话，应该记住下面这些。

1. 完整 decoder-only 模型不只是若干层网络，而是一整套离散协议、神经主体和运行协议共同组成的机器。  
2. tokenizer 决定模型的离散输入输出语言，因此属于整机定义的一部分。  
3. embedding 是符号世界进入连续表示世界的总入口，不是可被轻视的小步骤。  
4. 多层 causal Transformer blocks 负责在统一 residual stream 上反复改写表示，final norm 与 LM head 则把成熟表示重新翻译回词表偏好。  
5. logits 是训练和推理共享的统一输出接口，它们还不是 token，而是对词表候选的未归一化偏好。  
6. 训练协议通过右移一位标签和交叉熵，把同一台主体闭合成可学习系统。  
7. 推理协议通过只读取最后位置的 logits、采样并追加新 token，把同一台主体闭合成自回归生成系统。  
8. 一个真正“小而完整”的模型学习价值，往往远大于一个规模更大但你只会调用局部接口的模型。

> 训练卷是在讲这台机器怎样被学出来，推理卷是在讲这台机器怎样在运行中暴露自己的行为。
