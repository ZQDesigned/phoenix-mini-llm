# 06. Transformer block 为什么能反复堆叠

## 这一章要完成的过渡

到这里为止，卷八已经逐步把现代语言模型里最重要的几类结构约束拆出来了。

你已经知道：

- 序列建模为什么会逼出 attention
- QKV 怎样把“按需读取历史”写成可训练结构
- causal mask 怎样把“只能看过去”写进注意力图
- 位置方法怎样补回顺序、距离和相对排列这种几何信息

如果这些内容还是分散地躺在脑子里，你会得到很多“会背的部件”，但还不算真正理解现代语言模型主体。

因为真正的 decoder-only 主体并不是：

- 一个 attention 公式
- 再加一个 mask
- 再加一个位置方法

然后把它们顺序摆开就结束了。

真正可以反复堆叠、可以被训练到很深、可以在同一条主表示流里持续改写状态的最小单元，是：

> Transformer block。

所以这一章要回答的不是“block 里有哪几层”，而是更深一层的问题：

> 为什么现代语言模型不是简单地把 attention 重复很多次，而是把 attention、FFN、残差和归一化组织成一个统一砖块？这个砖块到底补上了什么，才让深层堆叠变得可行？

这也是理解现代大模型主体时，一个特别关键的认知转折：

> 从“零件思维”进入“砖块思维”。

## 从零件思维进入砖块思维

很多初学者第一次学 Transformer 时，会把知识组织成这样的清单：

- attention 用来读上下文
- FFN 是一个逐位置的小 MLP
- residual 是跳连
- norm 是稳定训练

这种记法不能说错，但它有一个明显缺点：

> 它把 block 看成“一个 attention 外面又挂了几个配件”。

更准确的理解应该是：

> block 不是若干功能件的松散并列，而是一块职责完整、接口稳定、可被下一层继续接上的表示更新单元。

一旦你把它看成“砖块”，很多后面的问题就会立刻变自然：

- 为什么每层几乎长得一样
- 为什么输入输出形状几乎总是一样
- 为什么残差如此核心
- 为什么归一化位置会明显影响可训练性
- 为什么层数增加不等于“同一件事简单重复”

也就是说，这一章的核心任务不是再讲一遍 block 里有什么，而是讲清：

> 为什么这些部件必须被组织成现在这种闭环，模型主体才能既强、又深、又稳。

## 先问一个最朴素的问题：为什么不是“一层超大的 attention”

只要你已经接受“attention 很强”，一个特别自然的念头就会冒出来：

> 如果 attention 已经能让当前位置从上下文里动态读取历史，那我是不是只要把 attention 做得更大、更宽、更强，就可以不需要别的结构？

这个念头的问题在于，它把两件本应分开的事情混到了一起：

- 从哪里拿信息
- 拿到信息以后怎样在当前位置把它真正消化成新的表示

attention 的强项当然非常突出。
它能做：

- query-key 匹配
- 多来源信息路由
- 远近位置的柔性加权读取
- 把分散在线性空间里的内容重新聚合回来

但它并不天然等于：

- 在单个位置内部做足够强的非线性加工
- 在很多层叠加后仍然可靠保留旧信息
- 让很深的表示链既能前向稳定，又能反向稳定

也就是说，attention 解决的是：

> 我该从哪里拿信息？

它并没有自动解决：

> 我把信息拿回来以后，怎样在当前位置内部把它改写成更好的状态？

更没有自动解决：

> 这种“读取再改写”的过程如何在十几层、几十层里重复进行，而不把旧信息洗掉、不把梯度弄坏、不把数值尺度推向失控？

所以现代语言模型的主体从来不是“一个超大的 attention 层”。
它必须是一个更完整的更新闭环。

这正是 block 出现的根本原因。

## 一个 block 真正想完成什么

如果先不看具体公式，只用功能语言描述，一个合格的 block 至少要完成下面几件事：

1. 保留当前位置已经拥有的表示  
2. 允许当前位置从别的位置读取新的上下文信息  
3. 把这份新信息安全地写回当前表示流  
4. 在当前位置内部继续做非线性加工，而不只是“读了一次就结束”  
5. 让整层结束后，主表示流仍然保持稳定，方便下一层继续操作  
6. 在这一切发生的同时，让深层优化仍然可控  

只要这个闭环里缺了一块，深层堆叠都会明显变差。

例如：

- 没有 attention，当前位置就缺少跨位置通信能力
- 没有 FFN，当前位置缺少逐位置的深度重写能力
- 没有 residual，旧信息和梯度路径会明显脆弱
- 没有 norm，很多层叠加后的尺度控制会越来越困难

所以 block 不是“多加几个组件，让一层更强一点”。
更准确地说，它是在回答：

> 什么样的最小结构，既能读取上下文、又能加工表示、还允许这种操作被很多层安全重复？

## 先建立一个长期直觉：什么是 residual stream

真正理解 block 之前，最值得先在脑中立住的概念，不是 attention，也不是 FFN，而是：

> residual stream。

很多资料会直接讲“残差连接”，但不强调 residual stream 的整体视角。
结果读者知道每层里有 `x + something`，却不知道这条不断被保留、不断被轻微修正的主表示流，到底在模型里扮演什么角色。

你可以先把 residual stream 想成：

> 一条贯穿整台模型主体、跨越所有 block 的主干表示河流。

输入 token 进入模型后，不是被每一层完全重造一遍。
更像是同一条表示河流不断向前流动，而每个 block 都在这条河流上做两件事：

- 从上下文里读取一点新信息，加回主流
- 在当前位置内部做一次额外非线性加工，再加回主流

于是，整个主体的工作方式就不再像“很多独立网络排队处理数据”，而更像：

> 同一条 residual stream 被很多 block 轮流阅读、修正、再交给下一层继续修正。

这个视角非常重要，因为它会立刻解释三件事：

- 为什么 block 输入输出形状几乎总是相同
- 为什么统一隐藏维度如此关键
- 为什么残差不是小技巧，而是整台主体的主结构

## block 的常见骨架为什么长这样

如果用现代 decoder-only 模型里非常常见的 pre-norm 风格来浓缩，一个 block 往往接近下面这种骨架：

```python
x = x + SelfAttention(Norm(x))
x = x + FFN(Norm(x))
```

这两行虽然很短，但其实已经把 block 的四个核心判断全部写出来了。

第一，主表示流 `x` 永远被保留。

第二，attention 不是直接替换 `x`，而是生成一份修正量，加回 `x`。

第三，FFN 也不是另起一条完全独立的表示链，而是在同一条主流上再加一份修正。

第四，每次进入重大子层前，都先用归一化整理一下当前主流状态。

这说明一个很关键的设计态度：

> block 的子层不是主宰者，residual stream 才是主路径；attention 和 FFN 更像在主路径上提供受控修正。

只要这个判断站稳，后面“为什么能堆很多层”的很多答案都会自动清晰。

## 为什么 block 输入输出几乎总是同形状

在大多数实现里，一个 block 的输入输出都会保持：

\[
[B, T, H] \rightarrow [B, T, H]
\]

这里：

- `B` 是 batch size
- `T` 是序列长度
- `H` 是隐藏维度，也就是 `d_model`

这不是 API 设计上的偶然习惯，而是 residual stream 能存在的前提。

如果某一层输出的形状和输入完全不同，那么：

- 残差相加会变得别扭甚至不可能
- 下一层就不再能把自己视为“在同一条表示流上加修正”
- 整个主体会从“统一砖块重复堆叠”变成“每层接口都不一样的特例网络”

也就是说，统一形状不是为了代码整齐，而是为了保证一个更深层的结构事实：

> 每一层都在同一个表示空间里，针对同一条 residual stream 做增量式修改。

这也是为什么我们说 Transformer 主体不是很多层孤立网络，而是一条统一表示流上的多轮改写系统。

## attention 子层到底在 block 里负责什么

上一章已经把 attention 本身讲得很细了，这里需要把它重新放回 block 的职责分工里。

attention 子层在 block 里的核心职责，可以压成一句话：

> 它负责让当前位置和别的位置通信。

也就是说，attention 的价值不是“让模型变复杂”，而是让当前位置有机会去看：

- 最近刚出现的局部搭配
- 更远处仍然重要的历史线索
- 多个分散位置共同提供的上下文条件

它解决的是“跨位置读取”的问题。

如果没有它，每个位置几乎只能依靠自己局部已经携带的表示继续计算。
这会极大削弱语言模型对长程依赖和多源线索融合的能力。

但 attention 子层虽然能把信息读回来，它仍然主要是在做：

> 信息路由与上下文混合。

它不擅长的部分恰恰是：

> 在单个位置内部，对已经混合回来的信息做更强、更细、更非线性的重新加工。

这正是 FFN 必须存在的原因。

## FFN 子层到底在补什么

如果把 attention 看成“跨位置通信器”，那么 FFN 更像：

> 逐位置的非线性加工厂。

FFN 有一个特别容易被低估的性质：

> 它不在时间维或位置维上做通信，它在每个位置内部单独工作。

这意味着它回答的问题不是“我该看谁”，而是：

> 当我已经拿到了当前这个位置的上下文增强表示以后，我怎样在这个位置内部进一步组织、组合、放大、压缩这些特征？

这件事为什么重要？

因为 attention 拿回来的通常是一份“上下文混合结果”。
它告诉当前位置：

- 哪些别的位置重要
- 它们各自贡献了多少内容

但这仍然不等于当前位置已经完成了足够丰富的内部表示更新。

很多时候，模型还需要在当前位置内部做这些事情：

- 把若干通道组合成新的特征
- 把有用信号放大、把无关方向压低
- 形成更适合下一层继续读取的隐藏结构

这正是 FFN 的价值所在。

因此，attention 和 FFN 从来不是“一个主角一个配角”的关系。
更准确地说：

- attention 负责跨位置读
- FFN 负责逐位置写

两者缺一不可。

## 为什么只有 attention 不够

一旦理解了刚才那种分工，就不难看出为什么“只靠很多层 attention”会有明显短板。

如果只有 attention，模型当然可以一轮轮地从不同位置读取信息。
但这种读取主要还是围绕：

- 匹配
- 聚合
- 路由

展开。

它并不天然擅长做强的逐位置非线性重写。

换句话说，只有 attention 的系统更像在不断问：

> 我还应该再看谁？

却不够擅长回答：

> 我把这些信息汇进来以后，怎样在当前位置内部重构出新的高级特征？

这会导致表示系统更像一个“不断查资料的机器”，而不是一个“既查资料又真正重写理解状态的机器”。

语言模型显然需要后者。

所以，attention 虽然强大，但它不是 block 的全部。

## 为什么只有 FFN 也不够

反过来，如果你只有 FFN，没有 attention，会发生什么？

模型当然仍然能在每个位置内部做很多非线性计算。
但这些计算会有一个根本限制：

> 它们几乎只能依赖当前位置自己已经带着的内容。

缺少跨位置通信以后，当前位置很难显式地从远处历史、局部邻居或多个分散位置里动态拉取线索。
这会让语言模型重新退回一种非常受限的局部加工器。

因此，只有 FFN 的系统更像：

> 每个位置各自很努力，但彼此不太会交流。

而只有 attention 的系统则像：

> 大家会互相查资料，但单个位置内部不够会深加工。

block 之所以有效，恰恰在于它把这两种互补能力放进同一个循环里：

- 先读
- 再写

于是表示不仅能拿到外部信息，也能在本地真正消化它。

## 为什么 FFN 常常“先升维，再降维”

很多实现里的 FFN 大概长这样：

\[
\text{FFN}(x) = W_2 \,\phi(W_1 x)
\]

而其中 `W_1` 往往会把隐藏维度从 `H` 扩到一个更大的中间维度，例如 `4H` 附近，再由 `W_2` 降回 `H`。

这不是随手选的超参数习惯，它和 FFN 的职责直接有关。

FFN 的目标不是简单地“再做一次线性层”，而是给每个位置提供一个更宽的中间特征空间，让它能在本地构造更丰富的组合关系。

你可以把这理解成：

> attention 把外部材料送回来，FFN 需要一个更大的内部工作台，去把这些材料重新拼装、筛选和压缩。

如果没有升维，中间非线性加工空间会比较窄。
升维以后，模型在单个位置内部可以表达更多通道级组合。

再降回隐藏维度，则是为了重新回到统一 residual stream 的接口空间。

所以“升维再降维”不是炫技。
它本质上是：

> 在不打破统一主表示流接口的前提下，给逐位置加工临时提供更丰富的内部容量。

## 为什么说 FFN 主要在做“通道混合”

attention 的核心操作发生在位置之间。
FFN 的核心操作则更接近发生在通道之间。

对每一个位置来说，FFN 会拿当前这个位置的隐藏向量，把不同通道组合、重排、非线性激活，再输出一份新的向量修正量。

因此，FFN 特别适合处理这样的事情：

- 某几组特征组合在一起才有意义
- 某个方向应该在当前位置被强化
- 某类上下文读回来的信号应该被转写成下一层更易利用的内部结构

所以 FFN 不是“附属的小 MLP”。
更稳的理解是：

> attention 管位置间的通信，FFN 管位置内的特征重组。

block 只有同时拥有这两种机制，才像一个真正的表示工厂。

## 残差连接为什么不是技巧，而是生命线

到这里，attention 和 FFN 的功能分工已经清楚了。
但还有一个更结构性的疑问：

> 即使有这两个子层，为什么它们都不是直接替换输入，而是通过 `x + sublayer(...)` 的方式加回主流？

答案就在残差连接里。

如果没有残差，每一层都会像在说：

> 我来重新生成一份新表示，旧表示就此作废。

这会带来两个非常严重的问题。

第一，旧信息太容易被彻底覆盖。

深层模型里，很多有价值的低层信息并不是每层都该被完全抹掉。
如果每一层都直接重写全部表示，模型会更难保留那些仍应继续向后流动的成分。

第二，梯度传播路径会更脆弱。

反向传播时，越深的链越容易在没有直接通路的情况下变得难训。
而残差相当于给出了更短、更稳定的身份路径，让“至少保留旧状态”成为默认选项。

所以残差最稳的理解不是“跳连一下帮助训练”。
更准确的说法是：

> 它让 block 从“全量重写器”变成“增量修正器”。

## 残差最重要的直觉：先保留，再加修正

如果把残差再压成一句最核心的话，就是：

> 每个 block 默认先保留旧表示，再在其上加一份新修正。

这句话看似朴素，其实非常深。

它意味着模型的默认立场不再是：

> 我必须每层都重新创造完整意义。

而变成：

> 我只需要在已有意义上补一点、改一点、重排一点。

这会让深层表示更新方式更接近“多轮草稿修订”。

当前位置不是每层都被重新投胎，而是：

- 第一次读一些上下文，加一点修正
- 再经过 FFN，加一点修正
- 下一层继续在此基础上修正
- 再下一层继续修正

于是整个主体会呈现出一种非常强的渐进式特征：

> 信息不是层层断裂重建，而是在同一条主流上逐步雕刻。

这就是残差为什么对语言模型尤其适合。

因为语言理解本来就常常不是一次性完成，而更像多轮逐步消歧、逐步补全、逐步重构。

## 为什么残差要求统一隐藏维度

只要你记住“残差是把修正量加回主流”，就会立刻知道为什么隐藏维度必须统一。

如果当前主流是 `H` 维，而某个子层吐出的修正量不是 `H` 维，那么：

- 你不能直接相加
- 下一层也不再面对同一种主表示流
- 模型主体会失去统一的堆叠接口

因此，统一隐藏维度不只是工程便利。
它是在保证一个更根本的结构事实：

> 所有 block 都在对同一维度空间中的同一条 residual stream 进行修正。

一旦这个事实被破坏，“很多同构 block 重复堆叠”的优雅性也会一起被破坏。

## 归一化为什么不是配件，而是深层堆叠的稳定器

理解完 attention、FFN 和 residual，最后一个核心问题就是 norm。

很多初学者最容易低估的，恰恰是它。
因为 norm 看起来不产生“新能力”。
它不像 attention 那样会读上下文，也不像 FFN 那样会重组特征。

于是很容易被误学成：

> 它只是顺手整理一下数值。

这种理解太轻了。

对深层堆叠来说，norm 真正解决的是：

> 当很多个 block 都在不断往 residual stream 上叠加修正时，如何让尺度、分布和优化难度不至于逐层失控。

这件事为什么重要？

因为深层模型里，哪怕每层只加一点修正，很多层加起来也可能让主流状态的尺度漂移、不同样本间差异累积、梯度传播变难。

所以 norm 的核心职责不是制造语义，而是：

> 让这条表示主流在深层反复加工时仍然保持可训练、可控、可继续叠加。

## 归一化到底在稳定什么

归一化的细节有很多实现差异，但从高层看，它至少在稳定三件事。

第一，稳定不同样本、不同位置进入子层时的尺度状态。

如果某些位置的激活幅度特别大、某些位置特别小，那么后续子层的行为会变得更难预测。

第二，稳定 residual stream 在多轮加法叠加后的主表示范围。

因为每个 block 都会向主流再加一份东西，如果完全不做整理，这条主流可能越来越漂。

第三，稳定深层优化的局部几何。

训练深层网络时，我们不仅关心前向值能算出来，还关心梯度与更新是否可控。
norm 往往能明显改善这类训练可控性。

所以归一化不是“让数值看起来整齐一点”，而是在回答：

> 这条会被几十层反复修改的主表示流，怎样才能一直维持在一个比较好操作的状态里？

## LayerNorm 和 RMSNorm 可以先怎样理解

对初学者来说，这里不必一开始就陷进不同 norm 的全部公式差异。
先抓住它们的共同结构职责更重要。

无论是 LayerNorm 还是 RMSNorm，它们都在扮演一个类似的高层角色：

> 在当前位置内部，对即将进入子层的表示做一次尺度整理，让后续子层面对一个更可控的输入状态。

它们当然在具体归一化统计量上不同，但你完全可以先把它们统一看成：

> residual stream 的局部稳定器。

这个理解在入门阶段比死记公式更重要。

因为后面无论看到哪种具体 norm 变体，你都能先问一个稳定问题：

> 它在这个 block 里负责稳定哪一段表示流？

## 为什么 pre-norm 在现代 decoder-only 模型里这么常见

如果你看现代很多 decoder-only 架构，会发现常见写法更像：

```python
x = x + Attention(Norm(x))
x = x + FFN(Norm(x))
```

而不是：

```python
x = Norm(x + Attention(x))
x = Norm(x + FFN(x))
```

前者通常被称作 pre-norm，后者通常叫 post-norm。

对初学者来说，最需要先抓住的不是术语，而是设计动机。

pre-norm 的核心直觉可以概括为：

> 先把要进入重大变换的输入整理好，再让子层吐出一份相对可控的修正量加回主流。

这种做法对深层优化往往更稳，因为 residual 主路径本身会更直接地保留下去，而不是每次相加后再整体被强制重整一遍。

不必把这件事神秘化。
先记住一个足够稳的判断即可：

> 对深层 decoder-only 模型而言，pre-norm 往往更有利于把“稳定主流 + 受控修正”这条思路贯彻到底。

## 为什么说一个 block 像“微型表示工厂”

如果把这一章前面的所有内容揉到一起，一个 block 的工作可以被非常形象地理解成：

> 一座微型表示工厂。

它接收一条已经流到这里的 residual stream，然后依次完成：

- 先看看当前状态是否需要从别的位置再拿点什么
- 把拿回来的东西融进当前位置
- 再在当前位置内部做一次更深的非线性重写
- 最后把更新后的主流继续交给下一层

所以 block 不只是一个“有几层子网络的盒子”。
它是一座每经过一次，就会让表示再成熟一点的加工单元。

而很多 block 串起来，整台模型就像：

> 一条长流水线，让同一批 token 表示在多个阶段不断被读、被改、被重新组织。

这个类比有助于你理解为什么层数增加通常不是简单重复，而更像加工深度增加。

## 为什么层数增加不是“同一件事简单重复”

很多人看到 `N` 个同构 block 堆起来，会本能地觉得：

> 这不就是同一件事做了很多遍吗？

表面上看，结构确实重复。
但功能上，层数增加通常意味着：

> 表示获得了更多轮“读取上下文 + 本地重写 + 保留主流”的机会。

这和把同一道工序机械重复很多遍不完全一样。

因为每一层面对的输入，已经是前面很多层加工过的表示。
于是，不同深度的 block 虽然接口相同，但常常承担不同粒度的工作。

浅层更常处理什么？

- 局部搭配
- 表层词形或短程结构
- 更直接的邻近信息融合

更深层更常处理什么？

- 跨较远位置的语义整合
- 更复杂的实体延续
- 多步推理式的上下文重写

所以“同构堆叠”不等于“功能重复”。
更准确的说法是：

> 同样的表示更新工具，被反复用于越来越成熟的表示状态上，从而形成更深层次的改写。

## 为什么 block 可以重复 N 次，而不需要每层重新设计接口

这正是 block 设计最优雅的地方之一。

如果每一层都要重新设计自己的输入输出协议，那么：

- 结构会难以扩展
- 深层训练会更难维护
- 模型不容易被系统化地放大或缩小

而统一 block 的存在，让模型主体获得了一种非常强的模块化特性：

> 只要这块砖的接口稳定、职责完整、训练可控，你就可以在同一条 residual stream 上多放几块、少放几块、放很多块。

这会直接带来规模化优势。

因为模型扩展时，一个最常见的维度就是：

- 增加层数
- 增加隐藏维度
- 增加头数

如果 block 不是一个接口统一的稳定砖块，这些扩展都会更混乱。

所以 block 的价值不只是单层效果好，而是：

> 它让整个主体具备了规则化放大的可能。

## 为什么 decoder-only 模型尤其依赖这种统一 block

对 decoder-only 语言模型来说，主体的核心任务非常稳定：

- 输入是一个前缀序列
- 目标是对每个位置产生更成熟的隐藏表示
- 这些隐藏表示最终要映射到词表 logits

这类任务特别适合被组织成：

> 在统一 residual stream 上，一次又一次地做“受因果约束的上下文读取 + 逐位置非线性重写”。

也就是说，decoder-only 的问题结构本身就很支持这种 block 式设计。

它不需要每一层都发明不同接口，因为大多数层都在完成同一类高层任务：

> 让当前位置表示在保留旧状态的同时，借助上下文和本地加工逐渐变得更好。

所以 block 的稳定、统一和可重复性，在 decoder-only 模型里尤其有价值。

## 一个更稳的总理解：block 是“受控修正器”，不是“全量重写器”

到这里，可以把本章最重要的理解压成一句特别稳的话：

> Transformer block 不是每层都重新创造一份全新表示的全量重写器，而是沿着同一条 residual stream 不断施加受控修正的更新单元。

这句话几乎能解释本章全部关键点：

- attention 为什么只产出修正量
- FFN 为什么也只产出修正量
- residual 为什么是主路径
- norm 为什么是稳定器
- 输入输出为什么统一形状
- 为什么这种结构适合深层堆叠

只要你真正接受“受控修正器”这个理解，block 里的很多细节就不会再像模板配方，而会像同一条结构哲学的不同面。

## 常见误区

### 误区一：Transformer 主体就是很多层 attention

不对。

attention 只解决跨位置读取。
block 之所以成立，还需要逐位置重写、残差主流和归一化稳定器。

### 误区二：FFN 只是可有可无的附属 MLP

不对。

FFN 负责逐位置的非线性特征重组，没有它，模型更像会查资料，但不够会在当前位置内部深加工。

### 误区三：残差只是“防梯度消失”的小技巧

不对。

它更深的角色是让每层从“全量重写”变成“保留主流再加修正”的更新方式。

### 误区四：归一化只是做一点数值整理

不对。

它是在保护深层 residual stream 的可训练性和尺度可控性，是深层堆叠的稳定器。

### 误区五：层数增加只是把同一件事重复很多遍

不完整。

结构上同构，功能上却往往对应更深一轮的表示改写，因为每一层面对的输入已经是前面层加工过的状态。

### 误区六：统一隐藏维度只是为了代码好写

不对。

它是在保证所有 block 都能在同一条 residual stream 上施加修正，是深层堆叠接口统一性的前提。

## 这一章真正要记住的核心句子

如果你只记住本章八句话，应该记住下面这些。

1. Transformer block 不是若干零件的松散拼接，而是一块职责完整、可重复堆叠的表示更新砖块。  
2. attention 负责跨位置通信，FFN 负责逐位置非线性重写，两者解决的是互补问题。  
3. residual stream 是贯穿所有 block 的主表示流，现代 decoder-only 主体更像在这条主流上做多轮修正。  
4. 残差连接的核心作用不是“小技巧式跳连”，而是让每层从全量重写变成保留旧状态再加修正。  
5. 归一化不是配件，它在稳定主表示流的尺度、分布与深层优化可控性。  
6. block 输入输出统一形状，是 residual 叠加和同构堆叠得以成立的结构前提。  
7. 层数增加不是简单重复，而是给表示更多轮“读上下文 + 本地重写”的机会。  
8. block 最稳的总体理解是：它是一台在同一 residual stream 上施加受控修正的微型表示工厂。
