# 11. 生成文本：解码、采样与缓存

## 这一章要解决什么问题

训练一个模型和真正“让它写出文本”之间，还隔着一段非常关键的知识。

训练阶段，模型每一步都能看到真实上下文；推理阶段却不是这样。你必须回答：

- prompt 如何进入模型
- 模型如何一步步往后续写
- logits 怎样变成具体 token
- 为什么不同采样策略会让同一个模型表现得完全不同
- 为什么生成长文本时需要缓存

这一章的目标，就是把“模型如何从分布走向文本”这件事讲清楚。

## 第一件事：推理阶段最根本的变化，是没有真实后续 token 可以继续喂回去

训练阶段使用 teacher forcing：

- 模型预测下一个 token
- 但下一步仍然使用真实数据中的下一个 token 继续训练

推理阶段不是这样。

当你给模型一个 prompt 时，真实世界里并不存在“已经写好的下一个 token”可以继续喂给它。所以推理只能这样进行：

1. 给出当前上下文  
2. 让模型预测下一个 token 的分布  
3. 从这个分布里选出一个 token  
4. 把它接回上下文  
5. 重复上述过程

这就是自回归生成。

## 第二件事：模型在推理时真正做的是“滚动式预测”

假设你输入一句 prompt：

```text
Once upon a time
```

推理时模型不会一次性输出完整故事，而是：

- 先预测第一个新 token
- 再把这个新 token 接回去
- 再预测第二个新 token
- 如此反复

这意味着推理不是“一次完成的分类”，而是一段不断更新上下文的循环过程。

## 第三件事：为什么生成时通常只关心最后一个位置的 logits

模型在一次前向传播中，通常会为当前输入序列中的每个位置都产出 logits。

但在生成阶段，你真正关心的是：

> 在当前整个上下文之后，下一个 token 应该是什么？

因此真正用于决策的，通常是最后一个位置对应的输出分布。

这和训练不同。训练会同时利用所有位置上的预测去计算 loss；推理每轮只需要一个最新的决策点。

## 第四件事：解码到底是什么意思

“解码”在这里指的是：

> 把模型给出的词表分布，转成一个实际的 token 选择过程。

模型输出的是 logits，不是文本。解码要做的事情就是：

- 先从 logits 得到分布偏好
- 再决定最终选哪个 token

所以解码不是简单的“把 id 变回文字”，而是：

> 先做下一 token 的决策，再在最后把整串 token 还原成人类可读文本。

## 第五件事：greedy decoding 为什么简单但常常不够

greedy decoding 的规则最直接：

> 每一步都选概率最大的 token。

优点是：

- 简单
- 可重复
- 输出稳定

缺点是：

- 容易陷入重复
- 多样性差
- 有时会持续沿着最保守的路径走，越写越僵

所以 greedy 是一个很好的基线，但并不是所有生成任务都适合只用它。

## 第六件事：temperature 在改变分布的“尖锐程度”

如果模型给出的 logits 是一组未归一化分数，那么 temperature 的典型做法就是在 softmax 之前对 logits 做缩放。

### 温度低时

- 高分 token 更占优势
- 分布更尖锐
- 输出更保守

### 温度高时

- 分布更平
- 中等概率 token 更容易被选中
- 输出更随机

### 为什么这很重要

因为同一个模型并不是只学会了一条答案，而是学会了一整个条件分布。temperature 决定的是：

> 你从这个分布里采样时，是更偏向最高峰，还是允许更多探索。

## 第七件事：top-k 在做什么

top-k 的核心思想是：

> 不从整个词表里采样，而是只从当前概率最高的前 `k` 个候选里采样。

### 这样做的好处

- 剪掉大量极低概率尾部候选
- 减少胡乱跳词
- 通常让生成更稳定

### 它的代价

- 候选空间被硬性截断
- 如果 `k` 太小，文本会变得过于保守

所以 top-k 本质上是一种：

> 用固定候选数限制随机性的办法。

## 第八件事：top-p 又在做什么

top-p，也常叫 nucleus sampling，它的核心不是保留固定数量的候选，而是：

> 保留累计概率达到某个阈值 `p` 所需的最小候选集合。

### 它和 top-k 的区别

- top-k：候选数固定
- top-p：候选数自适应

如果分布很集中，top-p 可能只保留很少几个 token；如果分布比较分散，它会保留更多候选。

因此 top-p 往往更灵活，因为它按“概率质量”而不是按“候选个数”控制采样空间。

## 第九件事：为什么同一个模型换个采样策略，像换了一个性格

这是很多初学者第一次调生成参数时最震惊的地方。

原因很简单：

> 模型输出的不是唯一答案，而是一整个概率分布。

不同采样策略决定的是：

- 你到底如何从这个分布里选 token
- 你允许多大程度的不确定性
- 你是倾向稳定，还是倾向探索

因此同一个模型在：

- greedy
- 低 temperature
- 高 temperature
- top-k
- top-p

这些策略下，会表现得非常不同。

这并不表示模型“变了”，而表示你从同一个分布中采取了不同决策规则。

## 第十件事：为什么生成容易重复

重复是小型语言模型最常见的问题之一。

它可能来自多种原因：

- 模型训练还不充分
- 语料过于单一
- greedy 过于保守
- temperature 太低
- 采样空间被截得太狠
- 序列一旦进入某种高频循环，后续更难跳出

所以当你看到重复时，不要立刻简单下结论说：

> 模型太笨。

更准确的理解是：

> 训练质量和解码策略都可能导致重复。

## 第十一件事：EOS 为什么很重要

如果模型知道什么叫“序列结束”，它就能在适当的时候停下来。

没有这个边界，生成过程常常会出现：

- 句子拖得很长
- 逻辑已经结束却继续乱写
- 没有自然收尾

因此 `EOS` 不只是训练时的标记，它也会影响推理时的停止行为。

## 第十二件事：为什么需要 KV cache

这是推理效率里最重要的知识点之一。

假设模型已经看到很长的上下文。如果你每生成一个新 token，都重新把整段历史完整跑一遍，那么：

- 旧上下文会被重复计算很多次
- 上下文越长，生成越慢

KV cache 的核心思想是：

> 过去已经算过的 key/value 表示先缓存起来，下一步生成时只补算新增 token 对应的部分。

### 这样做的结果

- 历史信息仍然可用
- 但不需要每一步都重算整段历史

因此 KV cache 不只是小优化，而是自回归生成在较长上下文下保持可用速度的关键机制。

## 第十三件事：为什么缓存不会改变模型任务本身

有些初学者会误以为：

> 用了 cache，好像模型就变成另一套算法了。

其实不是。

缓存改变的是：

- 计算方式
- 运行效率

而不是：

- 训练目标
- 模型结构本质
- “下一个 token 预测”这个任务定义

所以你可以把它理解成：

> 同一个自回归推理过程的高效实现方式。

## 第十四件事：生成结果最终为什么还要解码回文本

推理循环内部操作的是 token id，而不是字符串本身。

最后你还需要把这些 token 序列：

- 去掉不该显示的 special token
- 按 tokenizer 规则合并
- 还原成人可读文本

这提醒你：

> 模型和人类之间的接口，并不直接发生在 logits 上，而是发生在“编码文本”和“解码文本”这两端。

## 第十五件事：初学阶段怎样观察生成行为最有效

一个非常实用的方法是：

- 固定几个 prompt
- 固定同一个 checkpoint
- 每次只改一个采样参数
- 观察输出差异

例如只比较：

- greedy
- `temperature = 0.8`
- `temperature = 1.2`
- `top_k = 20`
- `top_p = 0.9`

这样你更容易形成判断：

- 是模型本身的问题
- 还是解码策略让输出变差

## 第十六件事：初学者最容易误解的几点

### 误区 1：推理就是把训练那段代码再跑一遍

不对。训练和推理最大的区别在于，推理没有真实后续 token 可以继续喂回去。

### 误区 2：temperature 是“创造力按钮”

说得太娱乐化了。更准确地说，它是在重塑分布的尖锐程度。

### 误区 3：只要模型训练得够久，采样策略就不重要

不对。解码规则本身会深刻影响输出文本。

### 误区 4：KV cache 只是性能优化，不必理解

不对。它属于现代自回归推理的基础知识。

### 误区 5：生成效果不好，就一定说明模型结构错了

不一定。训练质量、prompt 组织、采样参数都可能是原因。

> **这一章真正想让你建立的推理观**
>
>   生成文本不是“模型自动吐字”，而是一个自回归循环：模型给出分布，你用某种规则从分布里做选择，再把结果接回上下文继续预测。理解这一点，采样和缓存才不会变成你只能照抄的黑箱步骤。
