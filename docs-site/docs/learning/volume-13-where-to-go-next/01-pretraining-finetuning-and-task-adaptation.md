# 01. 预训练、微调与任务适配

学完一个小型语言模型之后，几乎所有读者都会很快遇到三组新词：

- 预训练
- 微调
- 任务适配

它们出现的频率非常高，高到你几乎不可能绕开。

但也正因为出现得太频繁，很多人会很快用一种“差不多懂了”的方式把它们压扁：

- 预训练就是大规模训练
- 微调就是后面再训一下
- 任务适配就是让模型去做具体任务

这三句话方向上不算全错，但它们远远不够。

因为在现代大模型世界里，这三个词其实分别在回答三层完全不同的问题：

1. 模型的通用语言能力最初是从哪里来的？
2. 模型怎样被拉向更具体的领域、任务或行为目标？
3. 当数据、算力、时间和风险都有限时，现实里应该在哪一层动手？

这一章的任务，就是把这三层问题拆开，再重新织回同一张地图里。

## 1.1 为什么走到这里一定会遇到这三个词

当你第一次真正实现一个小模型时，你已经掌握了很多过去看起来非常“大模型化”的东西：

- 词表与 token
- next-token prediction
- causal attention
- 训练循环
- 采样与停止

这时你再看现实世界的大模型讨论，就会发现很多话题都不再围绕“Transformer 是什么”这种基础问题，而更多围绕：

- 这个模型是 base 还是 instruct
- 它做过 SFT 吗
- 要不要做 domain adaptation
- 用全量微调还是 LoRA
- 需要重新预训练，还是只做 RAG

也就是说，一旦基础模型结构已经建立，更高一层的问题自然就会变成：

> 这套已有能力是怎样形成的，又应该怎样被重新塑形？

而预训练、微调与任务适配，正是对这组问题的概括。

## 1.2 先把三层问题彻底分开

这是整章最重要的一步。

### 1.2.1 预训练回答的是“广义能力怎样形成”

它关注的是：

- 大规模语料
- 通用目标
- 基础语言能力
- 参数中可迁移结构的形成

### 1.2.2 微调回答的是“已有能力怎样被压向更具体目标”

它关注的是：

- 特定领域
- 特定格式
- 特定任务
- 特定行为风格

### 1.2.3 任务适配回答的是“在现实约束下该怎么改”

它关注的是策略选择：

- 要不要继续训练
- 改多少参数
- 用什么数据
- 是否根本不改模型，只改系统

如果你不先把这三层拆开，后面很多讨论都会混成一锅。

例如，有人说“我要做一个医疗模型”，这句话至少可能意味着：

- 继续在医疗语料上预训练
- 做医疗问答监督微调
- 只做检索增强而不改模型
- 做一个参数高效的医疗领域适配层

它们都是“朝医疗方向改”，但不是同一种动作。

## 1.3 一个更准确的总图景：能力形成、能力塑形与能力部署

为了后面不再混淆，我们可以先建立一张更大图。

### 1.3.1 第一阶段：能力形成

这里的核心是：

> 让模型在极大范围的语言分布上学到通用可迁移结构。

这主要对应预训练。

### 1.3.2 第二阶段：能力塑形

这里的核心是：

> 让模型把已有能力收束到更具体、更可用、更符合目标场景的行为上。

这主要对应各种微调与后续行为训练。

### 1.3.3 第三阶段：能力部署

这里的核心是：

> 在真实资源、延迟、成本和风险约束下，让模型真正适合当前任务。

这一步往往会引入：

- 参数高效微调
- 检索增强
- 量化
- 系统级工具调用

很多人以为“训练完模型以后，剩下都是工程细节”。更准确的说法是：

> 从预训练到微调再到任务适配，本来就是同一条能力塑形链的不同层次。

## 1.4 什么是预训练

可以先给出一个严谨但仍然直观的定义：

> 预训练是在大规模、尽可能广覆盖的语料分布上，用一个相对通用的目标持续训练模型，让它获得可迁移的基础表示与语言建模能力。

对 decoder-only 语言模型而言，这个“相对通用的目标”通常就是：

> 给定前文，预测下一个 token。

这个目标表面上很朴素，甚至显得有点单调，但它非常强大。

因为只要：

- 语料足够广
- token 预算足够大
- 模型容量足够承载
- 训练足够充分

模型为了把下一个 token 预测得更好，就不得不把大量统计结构压进参数里。

## 1.5 为什么 next-token prediction 能逼出通用能力

这是很多人第一次真正觉得惊讶的地方。

他们会问：

> 只是做下一个 token 预测，为什么最后会出现语法、知识、风格、问答、总结、推理这些看起来更高级的行为？

一个更成熟的回答是：

> 这些行为并不是额外凭空长出来的，而是为了在真实语料上持续降低预测误差，模型不得不吸收的大量可复用结构。

具体来说，想把下一个 token 预测得更好，模型就要逐渐学会：

- 常见词与罕见词的分布
- 句法结构如何约束后续表达
- 不同领域术语怎样共同出现
- 文档、对话、代码、公式各自的局部和全局模式
- 一段话通常怎样开头、推进、转折和收尾

换句话说，预训练不是在显式教模型：

- “这叫语法”
- “这叫医学知识”
- “这叫代码风格”

而是通过统一的预测目标，逼迫模型把这些对预测有帮助的规律全部压缩进参数。

## 1.6 预训练的核心不是“训练时间长”，而是“目标广而统一”

初学者常把预训练理解成：

> 规模更大、训练更久的普通训练。

这只说对了一半。

预训练真正特别的地方不只在于规模，而在于它有两种很特殊的性质。

### 1.6.1 第一，目标非常统一

大量不同文本类型：

- 新闻
- 小说
- 问答
- 代码
- 技术文档
- 数学文本

都可以被统一写成“根据前文预测下一个 token”。

这意味着预训练不需要为每类文本单独设计任务接口。

### 1.6.2 第二，覆盖范围非常广

因为目标足够统一，模型可以在非常广的分布上吸收规律，而不是只为某个狭窄任务工作。

也正因此，预训练更像是在构建：

> 广义语言与文本世界的底层表征能力。

## 1.7 为什么预训练如此强调“token 预算”而不只是“epoch”

在小项目里，很多人会很自然地说：

- 训练了几轮
- 跑了多少 epoch

而在更大模型世界里，讨论更常围绕：

- 训练了多少 token
- token budget 多大

原因很简单。

在大规模语料和流式数据场景下：

- 数据非常大
- 去重与混合复杂
- 样本打包方式可能变化
- 训练不一定按固定遍历轮数组织

这时比起“扫了几遍语料”，更稳定的口径往往是：

> 模型总共看见了多少 token。

这也是你从小模型世界进入大模型世界后，首先会感到视角变化的一点。

## 1.8 预训练到底在参数里留下了什么

如果不使用过度神秘化的语言，我们可以说：

> 预训练在参数里留下的是大量可复用的统计结构、表示习惯和条件预测偏好。

它包括但不限于：

- 对常见语言结构的压缩表示
- 对各种文本类型的局部续写规律
- 对长短程共现关系的建模能力
- 对某些事实性与风格性模式的记忆

这就是为什么一个经过大规模预训练的基座模型，即使没有专门针对某任务训练，也常常已经表现出：

- 一定的补全能力
- 一定的问答倾向
- 一定的摘要、翻译或风格模仿倾向

这些都是通用预测能力外显出来的副产品。

## 1.9 但预训练并不等于“什么都学会了”

这是必须尽早建立的判断。

预训练再强，也不意味着模型天然会：

- 严格遵守人类指令
- 稳定按某个固定格式作答
- 在特定行业领域达到最佳行为
- 对敏感或危险问题自动给出产品级约束响应

原因在于，预训练优化的仍然是：

> 通用语料分布上的平均 next-token 预测质量。

而很多真实使用需求希望的却是：

- “请回答这个问题，不要继续散文式续写”
- “请输出 JSON，不要自由发挥”
- “请以法律助理的口吻总结”
- “请不要越界回答医疗建议”

这些目标不会完整地自动从广域预训练中长出来。

这就是微调存在的根本原因。

## 1.10 基座模型到底是什么

在进入微调之前，先把“基座模型”钉稳。

所谓基座模型（base model），通常指的是：

> 主要通过通用预训练得到的、还没有被大幅塑形成特定交互行为的模型。

它往往擅长：

- 续写
- 补全
- 模式延续
- 保留丰富的通用预训练分布痕迹

但它不一定擅长：

- 严格听指令
- 对问答边界把握稳定
- 在产品场景下表现出强一致行为

很多初学者把“聊天模型”直接等同于“更强的基座模型”，这不准确。

更准确的理解是：

> 聊天模型通常是在基座模型之上，又经过了额外的行为塑形阶段。

## 1.11 什么是微调

现在给出第二个核心定义：

> 微调是在一个已经具备通用能力的预训练模型基础上，继续用更窄、更具体、更直接贴近目标的数据和目标去训练，使模型向特定行为或任务方向偏移。

请注意这里的几个关键词：

- 已有通用能力
- 更窄的数据分布
- 更具体的行为或任务

微调不是重新从零建立语言能力，而是：

> 利用已经存在的能力，做方向更明确的后续塑形。

## 1.12 微调真正改变的是什么

直觉上看，微调像是给模型“补课”。

更准确地说，它通常在改变两件事。

### 1.12.1 第一，改变模型更常遇到的数据分布

如果预训练数据极广，模型得到的是一种广义平均能力。

但你真正关心的任务往往只落在一个局部区域，例如：

- 医疗问答
- 代码修复
- 法律摘要
- 企业知识库问答
- 某品牌客服风格回复

当你继续用这些更聚焦的数据训练时，模型参数会逐渐向这个局部区域偏移。

### 1.12.2 第二，改变模型更直接面对的目标形式

预训练时，模型看到的常常是普通连续文本。

微调时，数据组织方式可能会变成：

- 指令 -> 回答
- 问题 -> 标签
- 文档 -> 摘要
- 上下文 -> 结构化抽取结果

这意味着模型不只是在看某个领域文本，而是在学：

> 如何把已有语言能力转化成某种特定任务接口下的响应模式。

## 1.13 为什么“听指令”不是预训练自动送给你的

这是一条非常重要的分界线。

一个基座模型可能非常懂语言，但它未必天然懂：

- 现在问题结束了，该直接给答案
- 该限制在指定格式内输出
- 该把解释长度控制在用户要求内
- 该把角色稳定维持成客服、助教或系统代理

因为这些都不是“理解语言统计”本身就必然包含的行为。

它们更像是：

> 对已有语言能力施加额外行为约束。

而这类行为约束，通常就通过某种形式的微调或后续行为训练进入模型。

## 1.14 监督微调是什么

在微调家族中，最常见也最直观的一类是监督微调（SFT, supervised fine-tuning）。

它本质上是在说：

> 我现在有一组更明确的输入输出示范，希望模型照着这种方式回答。

例如数据可能长成：

- 指令 -> 理想回答
- 问题 -> 正确答案
- 文档 -> 摘要
- 用户问题 + 背景 -> 结构化输出

模型在这类数据上继续训练时，学到的不只是领域知识倾向，更是：

- 回答风格
- 任务接口
- 输出格式
- 行为边界

这就是为什么很多“聊天模型”或“指令模型”的关键步骤之一，是监督微调。

## 1.15 微调并不总是“让模型更懂领域”

这是另一个很重要的判断。

很多人一听到微调，就自然想到：

- 医疗微调
- 金融微调
- 法律微调

这当然是一类场景，但微调还有另一类非常常见的目标：

> 不是让模型更懂某个领域，而是让模型更会按某种方式响应。

例如：

- 更会遵守指令
- 更会输出规范格式
- 更会做问答而不是续写
- 更会维持对话角色

这说明微调既可能是知识分布塑形，也可能是行为协议塑形。

## 1.16 所谓“任务适配”，其实是一个更大的决策问题

现在进入第三层。

任务适配不是某一种单独算法，而更像一个总问题：

> 在当前任务目标、数据条件、资源限制和风险要求下，怎样让已有模型最合适地服务当前任务？

这个定义很重要，因为现实里你并不总是应该默认：

- 继续全量训练

很多时候，你面对的是这样的局面：

- 数据不够大
- GPU 资源不够
- 时间很紧
- 只想先做概念验证
- 风险不允许大幅改动底模

这时真正的问题不是“要不要训练”，而是：

> 在多少层改，怎么改，值不值得改。

## 1.17 任务适配常见的几条路径

为了让这个概念更清楚，我们把常见路径先并列摆出来。

### 1.17.1 路径一：根本不改模型，只改使用方式

例如：

- prompt 设计
- few-shot 示例
- system prompt

这种方式成本最低，但上限也受限。

### 1.17.2 路径二：不改模型参数，改系统能力

例如：

- 检索增强生成（RAG）
- 工具调用
- 外部知识库

这类方法回答的是：

> 某些缺口是不是更适合通过系统外部能力补，而不是把所有东西压回参数里？

### 1.17.3 路径三：继续预训练或领域自适应预训练

适合：

- 你有大量未标注领域文本
- 目标首先是让模型“更熟悉这个世界”

### 1.17.4 路径四：监督微调

适合：

- 你已经有清晰的输入输出样本
- 你要的不是广义熟悉，而是具体响应行为

### 1.17.5 路径五：参数高效微调

适合：

- 资源有限
- 不方便全量改参数
- 想快速尝试多个版本

也就是说，任务适配不是单点技术，而是一组路径选择。

## 1.18 继续预训练适合什么问题

继续预训练，也常被理解成某种领域自适应预训练。

它最适合的问题是：

> 模型对某个领域的基础分布还不够熟。

例如：

- 医疗文献术语密度很高
- 法律文书结构非常特殊
- 某种代码语料有明显独特模式

如果你手里有大量未标注原始文本，而你希望模型先：

- 更懂这个领域的写法
- 更熟这个领域的术语与上下文关系

那么继续预训练往往比直接硬上问答微调更自然。

因为它先补的是：

> 模型对这个局部分布的广义熟悉度。

## 1.19 监督微调适合什么问题

监督微调更适合的问题是：

> 你已经知道输入长什么样，也知道理想输出该长什么样。

例如：

- 给定用户问题，输出专业回答
- 给定合同文本，输出结构化字段
- 给定一段代码，输出修复建议

这里你关心的不再只是“熟悉这个领域文本”，而是：

> 在某种明确任务接口下，稳定地给出目标响应。

所以监督微调更像是：

- 把通用能力压成具体任务能力
- 把续写倾向压成响应倾向

## 1.20 参数高效微调在补什么

现在进入一个现实世界非常重要的分支。

很多情况下，你并不想或不能全量改动整个模型：

- 显存不够
- 训练成本太高
- 想保留统一基座
- 需要快速试很多任务变体

于是就会出现参数高效微调（PEFT, parameter-efficient fine-tuning）这一类方法。

它们的核心思想不是：

> 把预训练和微调推翻重来。

而是：

> 如果我不方便改全部参数，能不能只加或只改一小部分可训练结构，让模型获得足够明显的任务偏移？

LoRA、QLoRA 这一类方法，就在回答这个问题。

## 1.21 LoRA 这类方法为什么会流行

虽然这一章不展开具体公式，但你至少要抓住它的现实意义。

LoRA 这类方法之所以流行，是因为它在很多场景下同时满足了几件很有价值的事：

- 降低训练资源要求
- 降低显存占用
- 保留共享基座
- 便于为不同任务挂不同适配层

也就是说，它不是为了“显得更高级”，而是因为现实里常常真的不值得为每个任务都维护一个全量新模型。

## 1.22 为什么“从零训练一个新模型”通常不是默认答案

当你刚学会从零实现小模型时，最自然的冲动是：

> 那我下一步是不是也应该从零训一个更大的？

从学习价值看，这个冲动可以理解。

但从现实效率看，这通常不是默认答案。

原因至少有四个。

### 1.22.1 第一，通用语言能力极其昂贵

大规模预训练不是“多跑几天”这么简单，而是：

- 数据准备重
- token 预算大
- 训练成本高
- 评估复杂

### 1.22.2 第二，大多数真实问题并不需要重新发明基础语言能力

更多时候，你面对的是：

- 某领域适配
- 某任务接口
- 某行为约束

这些通常更适合建立在已有基座之上。

### 1.22.3 第三，很多能力缺口更适合用系统层而不是参数层补

例如：

- 外部知识更新
- 工具访问
- 企业内部资料查询

这类问题往往更适合 RAG 或工具系统，而不是再训一个全新基础模型。

### 1.22.4 第四，维护成本本身也是约束

从零训一个新模型，不只是训练成本，还有：

- 版本维护
- 推理部署
- 安全与评估
- 后续适配分叉

所以一旦你进入真实世界，默认问题通常不再是“从零训不训”，而是：

> 现有模型的哪一层能力缺口值得改，改动最小但收益最大的点在哪里？

## 1.23 基座模型、指令模型、聊天模型之间到底差在哪

这也是大模型世界里最容易被说模糊的地方。

### 1.23.1 基座模型

主要依赖预训练形成。

它的气质往往是：

- 擅长续写
- 更贴近原始语料分布
- 不一定稳定听指令

### 1.23.2 指令模型

在基座之上，通过更明确的指令-响应数据进行行为塑形。

它更擅长：

- 按问题回答
- 遵守输入要求
- 减少无边界续写

### 1.23.3 聊天模型

通常又进一步叠加：

- 对话格式
- 多轮角色约束
- 安全与风格对齐

所以“聊天能力”不是某个神秘模块，而是：

> 基础语言能力之上，再叠加一系列行为塑形与产品目标约束的结果。

## 1.24 为什么微调不是免费午餐

很多初学者在理解微调后，会产生另一种新错觉：

> 既然基座不够，那我就继续微调，问题总能慢慢解决。

这同样太乐观。

微调当然非常强大，但它也会引入新的风险。

## 1.25 风险一：过拟合会更容易

预训练常常使用极大规模语料，而微调阶段的数据集通常小得多。

这意味着模型更容易：

- 记住数据集表面模式
- 把少量风格放大成过窄行为偏好
- 在验证样本外泛化不稳

所以微调并不是“越贴近任务数据越好”，而是要持续关心：

- 数据质量
- 数据覆盖
- 验证方式

## 1.26 风险二：灾难性遗忘可能出现

当你把模型强力拉向一个窄目标时，它可能会牺牲原本的一些广义能力。

这常被称为灾难性遗忘。

直观地说，就是：

> 模型学会了新偏好，却忘掉了原本更广的行为平衡。

例如：

- 变得更会某类问答，但更不自然
- 变得更会某领域格式，但更容易在别的场景僵化

这也是为什么很多适配方案会认真考虑：

- 改动幅度
- 数据混合
- 是否需要共享基座

## 1.27 风险三：评估会变得更难

预训练阶段你更多关心：

- 通用验证集
- perplexity
- 大范围平均趋势

而微调和任务适配阶段，你常常要同时看：

- 目标任务性能
- 格式正确率
- 行为稳定性
- 泛化边界
- 是否破坏了原有能力

也就是说，随着模型越来越“可用”，评估问题反而越来越复杂。

## 1.28 风险四：你可能在改错层

这点非常现实，也非常常见。

例如一个企业问答系统效果不好，真正的问题可能是：

- 模型不知道企业私有知识

这时如果你本能地上微调，可能就是在改错层。

因为这个问题也许更适合：

- 检索增强
- 知识库接入

而不是把全部企业知识压回参数。

所以任务适配最成熟的地方，恰恰不是“会很多调参手段”，而是：

> 能判断哪一层才值得改。

## 1.29 对小模型学习者来说，这一章最重要的现实意义是什么

如果把这一章和你刚完成的小模型项目连起来，它最重要的意义在于三点。

### 1.29.1 第一，小模型项目教你的不是玩具知识

你学会的：

- token 化
- 目标构造
- 训练闭环
- sampling
- evaluation

在更大模型世界里依然成立。

只是它们会被放到更大、更复杂的约束下重新组合。

### 1.29.2 第二，真实世界里更常见的是“改已有模型”，而不是“重新造底座”

这会改变你看问题的默认方式。

### 1.29.3 第三，所谓“更大模型能力”，常常是多层塑形共同作用的结果

不是单纯“参数更大”四个字就能解释。

你需要同时考虑：

- 预训练带来的通用能力
- 微调带来的行为偏移
- 系统层带来的能力补偿

## 1.30 如果你以后遇到一个新任务，应该先问什么

这章最终想训练你的，不是背定义，而是一组更成熟的问题顺序。

当你以后遇到一个新任务时，先别立刻问：

```text
我要不要重新训练一个模型？
```

更好的顺序是：

1. 这个任务缺的是通用能力，还是具体行为？
2. 我缺的是领域熟悉度，还是任务接口对齐？
3. 我手里有的是未标注语料，还是高质量输入输出样本？
4. 这个问题更适合改参数，还是接系统？
5. 在资源约束下，全量微调值不值得，还是应该用更轻的适配方式？

只要你开始按这个顺序思考，你就已经不再把大模型世界看成热词集合了。

## 1.31 本章应该留下的稳定判断

这一章最重要的不是某个定义，而是下面几条稳定判断。

第一，预训练、微调与任务适配不是同义词，它们分别属于能力形成、能力塑形与现实策略选择的不同层。

第二，预训练之所以强，不是因为“训练更久”，而是因为它用统一目标在大范围语料上逼出了可迁移结构。

第三，微调并不只是“继续训练一下”，而是在改变模型更常遇到的数据分布与更直接面对的目标形式。

第四，任务适配的核心不是“会不会训练”，而是“该在哪一层改、值不值得改”。

第五，真实世界里，更多时候不是从零重训一个新基础模型，而是在已有能力上做更聪明的塑形与系统组合。

## 1.32 本章小结

把这一章压缩成一句话：

> 预训练负责形成广义能力，微调负责把已有能力压向更具体目标，任务适配负责在现实约束下决定究竟该改哪一层、怎么改。

如果你能真正把这三层分开，大模型世界里大量原本混乱的讨论都会重新变得清楚。

接下来沿着这条线继续学时，你就会更容易理解：

- 为什么指令模型和基座模型不是一回事
- 为什么 LoRA 这类方法会出现
- 为什么很多问题更适合用 RAG 而不是继续微调
- 为什么“更强”并不只等于“更大”
