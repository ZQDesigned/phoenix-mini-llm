# 08. Transformer Block 与位置编码

## 这一章要解决什么问题

上一章我们解决了一个关键问题：

> 为什么模型需要 Attention 这种按内容路由信息的机制。

但一个真正可训练、可堆叠、可稳定工作的语言模型，并不是把 Attention 单独裸堆很多次就够了。

真实的 Transformer 会把多种部件组合成一个重复出现的单元，也就是 block。

这一章要回答的问题是：

> 为什么一个可用的 block 里除了 Attention，还需要位置编码、残差连接、归一化和前馈网络？

如果这个问题没有想清楚，后面你看任何模型结构图时，都会把这些部件误解成：

- 论文顺手加上的附件
- 工程上不得不抄的一套模板
- 不会影响本质理解的边角料

实际上不是。它们各自解决的是不同类型的问题。

## 先建立整体观：一个 block 是一轮“读上下文 + 改写表示”

对初学者来说，最有用的第一印象不是公式，而是把 block 想成一轮完整的数据处理。

如果把很多现代 decoder-only 结构压缩成最常见的形式，大致可以写成：

```python
x = x + Attention(Norm(x))
x = x + FFN(Norm(x))
```

这两行非常值得反复看。它已经暴露了一个 block 的几个核心角色：

- `Norm`
- `Attention`
- `Residual`
- `FFN`

如果再往前补上位置信息，那么你会发现：

> 一个 block 做的不是单一计算，而是一整轮“在稳定尺度下读取上下文，再对每个位置做内部加工，然后把结果作为下一层输入”。

## 为什么 Attention 不能单独承担全部工作

上一章我们说过，Attention 解决的是：

> 当前位置该从哪些历史位置拿信息。

这已经很关键，但它并没有自动解决另外几件事：

- 输入表示怎样知道顺序
- 多层堆叠时怎样保持稳定
- 每个位置在读完上下文后，怎样做强非线性加工
- 信息怎样跨层保留，不被一层层完全冲掉

所以如果你只把 Attention 看成主体，就会漏掉模型实际成功所依赖的另外一半结构。

一个更准确的说法是：

> Attention 负责“跨位置通信”，而 block 负责把“跨位置通信”和“稳定深层表示变换”组合起来。

## 位置信息为什么必须和 block 一起理解

Attention 本身并不知道顺序。它只会比较位置之间的内容表示。

这意味着，如果你不给模型任何位置信息，那么它看到的更像是一组向量集合，而不是一条有先后关系的序列。

这在语言里会立刻出问题。

例如：

```text
他打了我
我打了他
```

内容元素类似，但顺序改变，意义就完全变了。

所以模型必须在某个环节获得顺序信息。这个顺序信息可以：

- 加到 embedding 上
- 注入注意力所使用的表示中
- 通过相对位置关系参与打分

但不管具体形式如何，它都必须进入 block 体系里，成为模型表示的一部分。

### 位置编码到底在补什么

它补的不是“语义”，而是下面这些结构信息：

- 谁在前，谁在后
- 两个位置相距多远
- 当前 token 相对历史的位置关系是什么

语言建模之所以离不开位置方法，是因为语言不是无序集合，而是强顺序结构。

## 常见位置方法的基本直觉

你不需要在这一章背完整数学推导，但应该知道几类主流思路分别在做什么。

### 绝对位置表示

最朴素的想法是：

> 序列中第 0 个位置、第 1 个位置、第 2 个位置……各自有一份位置向量。

模型把 token embedding 和位置向量合在一起，于是同一个 token 出现在不同位置时，内部表示也会不同。

这种方法直观、容易实现，但它更强调“这个 token 在第几格”。

### 正弦位置编码

另一种经典做法是用一套固定的、随位置规律变化的函数值表示位置。

它的重要性不在于你今天就要掌握公式，而在于它说明了一件事：

> 位置信息不一定非得完全通过额外可学习参数来提供，也可以通过一种结构化规则注入。

### 相对位置方法

很多时候，模型更关心的不是“这个 token 是全局第 173 位”，而是：

> 它离我有多远，它是在我前面 2 格还是前面 20 格。

相对位置方法更强调这种相对距离关系。

### RoPE

RoPE，也就是旋转位置编码，是很多现代 decoder-only 结构常用的位置方法。

现在你最需要的理解不是推导，而是定位：

> 它把位置信息注入到注意力使用的表示中，让注意力在比较相似性时天然带上相对位置信息。

所以当你后面在小模型里看到 RoPE，不要把它当成“一个神秘插件”，而应理解成：

> 这是让 Attention 真正知道顺序关系的一种现代实现方式。

## 残差连接为什么关键

残差连接通常写成：

\[
y = x + f(x)
\]

很多初学者会先从表面记住“有个加法 shortcut”。但要真正理解它，必须先想一件事：

> 如果没有残差，深层网络里的每一层都必须完全重写输入表示。

这会带来几个问题。

### 第一，信息很容易被层层覆盖

如果第 1 层已经形成了一些有用结构，而第 2 层必须完全重写，第 3 层再完全重写，那么早期信息要想一直保留下去就会变得很难。

### 第二，梯度传播更困难

训练深层网络时，参数更新依赖梯度能健康地穿过很多层。如果每层都在做大幅重构，训练更容易不稳定。

### 第三，层的工作方式不自然

有了残差后，每一层可以更像是在说：

> 我先保留原表示，再基于它做一份修正。

这和人类修改草稿有点像。你不是每次都把全文推倒重写，而是在已有版本上打补丁、做改进。

### 为什么这对 Transformer 特别重要

因为 Transformer 通常要堆很多层。残差连接让这些层更容易形成一种逐层细化的关系，而不是层层互相摧毁前面的结果。

所以残差的本质不是“架构流行元素”，而是：

> 它让深层信息流和梯度流都变得更健康。

## 归一化到底在稳定什么

随着层数增加，隐藏状态的数值尺度会不断变化。

如果某些维度越来越大，某些维度越来越小，后续计算就会变得更难训练。因为后面的线性层、Attention、激活函数，都会受到输入尺度的影响。

归一化的直觉可以先理解成：

> 在把表示送入关键计算前，先把它整理到更稳定的数值范围和统计形态。

### LayerNorm 和 RMSNorm 的直觉

在 Transformer 家族里，常见的是：

- LayerNorm
- RMSNorm

你现在不需要先钻到公式差异里，但至少要知道：

- 它们都沿着隐藏维度工作
- 它们都在帮助深层训练稳定
- 它们不是“改变任务定义”，而是在管理表示尺度

换句话说，归一化层不负责让模型更懂语言，它负责让模型更容易学会。

## 为什么现代 decoder-only 模型常用 pre-norm

你会看到两种常见结构顺序：

1. 先做 Attention/FFN，再做 Norm  
2. 先做 Norm，再做 Attention/FFN  

后者通常被叫做 pre-norm。

为什么很多现代结构偏爱它？

因为当网络变深时，先把输入整理到一个更稳定的状态，再送入复杂变换，往往更利于训练。

更朴素地说：

> 先把桌面整理平，再在上面做精细操作，通常比桌面已经一团乱时继续往上叠操作更稳。

这并不意味着 post-norm 没有价值，但对很多从零搭建的小型 decoder-only 模型来说，pre-norm 是更常见、更稳妥的选择。

## 前馈网络 FFN 在做什么

这是另一个很容易被低估的部分。

很多人看到 Attention 后，会本能觉得：

> 既然模型已经能跨位置读上下文，FFN 可能只是顺手加的补充。

其实不是。

Attention 主要负责的是：

> 当前位置与其他位置之间的通信。

而 FFN 更像是在说：

> 当我已经拿到了需要的上下文之后，当前位置自己怎样加工、重组、强化这份信息？

### 为什么 FFN 是逐位置的

FFN 通常对每个位置独立工作。它不直接和其他位置通信，而是对每个位置的隐藏向量做同一套非线性变换。

这听起来像限制，实际上正好对应它的职责：

- Attention 负责跨位置混合信息
- FFN 负责每个位置内部深化表示

如果把 Attention 比作“去资料室查资料”，那么 FFN 更像“把查回来的资料在自己桌上整理、归纳、加工”。

### 为什么通常要先扩展再压回

很多 FFN 不是简单一层，而是会先把隐藏维度扩到更宽的中间空间，再经过激活后压回原维度。

例如：

\[
H \rightarrow 4H \rightarrow H
\]

或者使用更现代的门控变体，如 SwiGLU 一类结构。

这里最关键的直觉是：

> 模型需要一个更宽的中间计算空间，来完成更强的逐位置非线性加工。

所以 FFN 不是“再做一次线性层”，而是 block 表示能力的重要来源。

## Dropout 和训练态/推理态的区别

在很多 block 中，你还会看到 dropout。

它的核心作用不是让模型变强，而是帮助训练阶段避免某些模式过度依赖局部路径，从而提升泛化。

你现在不需要把它视为 LLM 成功的根部，但需要知道：

- 训练态和推理态并不完全一样
- 某些层在训练时会引入随机性
- 推理时这些随机屏蔽通常会关闭

对小型学习项目来说，dropout 可能不是第一优先级，但它属于你理解完整 block 时不能完全忽略的组成部分。

## 一个 block 里到底发生了什么

现在把一轮 block 处理按顺序走一遍。

### 第 1 步：输入已经带着内容和位置信息

进入 block 的 `x` 不是裸 token id，而是已经处在隐藏空间里的序列表示。这个表示里至少已经包含：

- token 内容线索
- 位置信息
- 前面若干层留下的上下文加工结果

### 第 2 步：归一化

先把当前表示整理到更适合后续计算的尺度。

### 第 3 步：Attention 读取上下文

当前位置根据当前需求，决定该从历史哪些位置读取信息，形成一份新的上下文感知表示。

### 第 4 步：残差加回原表示

这样当前位置既保留原有表示，又吸收了一次新的上下文修正。

### 第 5 步：再次归一化

准备进入下一段关键计算。

### 第 6 步：FFN 逐位置加工

每个位置对自己当前已经融合好的表示做更强的非线性变换。

### 第 7 步：再做一次残差相加

于是这一层 block 完成，输出继续交给下一层。

如果你把这个顺序看顺了，Transformer Block 就不再是一个抽象名词，而会变成一条你能够讲清楚的数据流。

## 为什么 block 的输入输出通常保持同形状

一个很关键的结构性质是：

\[
[B, T, H] \rightarrow [B, T, H]
\]

也就是说，block 进来和出去的基本形状通常相同。

这样做有几个重要好处。

### 第一，便于堆叠

如果每一层都保持相同的隐藏维度，那么你可以很自然地连续堆很多层。

### 第二，残差连接变简单

残差要求输入和输出能够相加。同形状意味着这件事天然成立。

### 第三，模型像在同一个表示空间里反复改写

这使得每一层的角色更像是“在已有语言表征上继续精炼”，而不是每层都切换到一种完全不同的空间定义。

## 为什么一个 block 可以成为可重复堆叠的砖块

理解 block 的最好方式，不是把它当作“注意力层配件包”，而是把它当作可重复使用的基础砖块。

它之所以适合作为砖块，是因为它同时满足了几件事：

- 有跨位置通信能力
- 有逐位置非线性加工能力
- 有稳定训练所需的归一化
- 有帮助深层堆叠的残差
- 有顺序感知能力
- 输入输出接口统一

当这几件事同时成立时，你就得到了一种既强大又可重复堆叠的单元。

这也是为什么很多模型图虽然看起来复杂，但本质上都是：

> embedding + 多个相似 block + 输出头

## 模型越深，block 里的信息会怎样变化

一个常见但值得警惕的误解是：

> 堆很多层，应该只是把同样的事情重复很多遍。

更准确的理解是：

> 相同的结构模板被重复使用，但不同层学到的统计功能通常不同。

浅层也许更偏向：

- 局部模式
- 短距离依赖
- 词法边界

中层可能开始组合：

- 更复杂的语义相关性
- 中程上下文关系
- 常见句法结构

更深层则可能形成：

- 更抽象的语境偏好
- 更高层的主题或风格线索

你不必把这理解成严格分工表，但要知道：

> 多层 block 的价值不是单层计算变长了，而是模型获得了多轮反复读取与改写表示的机会。

## 为什么不能随便删掉 block 里的部件

理解每个部件的职责后，你就更容易看清删掉它会发生什么。

### 没有位置信息

模型很难可靠地区分顺序关系。

### 没有 Attention

模型失去动态跨位置通信能力。

### 没有 FFN

模型失去强的逐位置非线性加工能力。

### 没有残差

深层训练会明显更困难，信息更容易被层层覆盖。

### 没有归一化

训练稳定性通常会明显恶化。

所以 block 里的这些部件不是可有可无的点缀，而是一套协作结构。

## 初学者最容易误解的几点

### 误区 1：Attention 已经足够强，所以 FFN 只是陪衬

不对。Attention 和 FFN 分别负责不同问题，一个做跨位置路由，一个做逐位置内部加工。

### 误区 2：残差连接只是为了模仿标准答案

不对。它直接关系到深层信息流和梯度流质量。

### 误区 3：位置编码只是锦上添花

不对。对语言序列来说，顺序是任务定义的一部分。

### 误区 4：归一化只是数值小技巧，不影响整体理解

不对。没有对数值尺度的管理，深层结构很难稳定训练。

### 误区 5：一个 block 就是一个注意力层

不准确。更合理的最小单位是“带有位置感知、归一化、残差和 FFN 的完整 block”。

## 这一章真正要建立的结构感

如果这一章你最后只记住一个画面，那么应该是：

> 一个 Transformer Block 是一轮完整的“稳定地读取上下文，并在此基础上改写每个位置表示”的过程。Attention 只是其中解决跨位置通信的部分，而不是整个单元的全部。

当你能把 block 看成这个完整过程，后面的整模型拼装就会简单很多。

4. 归一化主要在帮助模型稳定什么？
5. FFN 为什么虽然不跨位置通信，却仍然不可缺少？
6. 为什么 block 的输入输出通常保持相同形状？
