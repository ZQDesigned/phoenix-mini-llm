# 08. Transformer Block 与位置编码

## 这一章要解决什么问题

上一章你已经知道 Attention 能做什么：它让每个位置动态读取上下文。

但真正的语言模型并不是把一层 Attention 裸着堆很多次。一个可训练、可稳定堆叠的 Transformer，实际是由一个个结构完整的 block 组成。

这一章要回答的问题是：

> 为什么一个 block 里除了 Attention 之外，还需要残差连接、归一化、前馈网络和位置信息？

如果这个问题想不清楚，你后面看完整模型时就会把很多部件误解成“论文里顺手加上的东西”，而不会知道它们分别在解决什么。

## 第一件事：Attention 解决的是“看哪里”，不是“把一切都做完”

先把边界再强调一次。

Attention 最核心的能力是：

- 让当前位置和其他位置交互
- 根据内容决定依赖关系

但一个强模型还需要别的东西：

- 让深层网络稳定训练
- 让信息能跨层传递
- 让每个位置内部也能做强非线性变换
- 让模型知道顺序关系

所以 Transformer Block 不是“Attention 加一点别的”，而是一个完整的信息处理单元。

## 第二件事：什么叫一个 Transformer Block

如果把最常见的 block 数据流压缩成最小形式，可以写成：

```python
x = x + Attention(Norm(x))
x = x + FFN(Norm(x))
```

这段简化形式非常有价值，因为它已经暴露了 block 的四个核心部件：

- `Norm`
- `Attention`
- `Residual`
- `FFN`

理解了这四个角色，后面读任何小型 decoder-only 结构都会轻松很多。

## 第三件事：残差连接为什么关键

残差连接的形式通常可以写成：

\[
y = x + f(x)
\]

### 它解决了什么问题

如果没有残差，深层网络的每一层都必须完全重新塑造自己的表示。这会让：

- 训练更困难
- 梯度传播更差
- 早期有用信息更容易被覆盖掉

而残差连接允许网络这样工作：

> 先保留原有表示，再在其基础上叠加一个修正。

这让每一层更像是在做“增量改进”，而不是“全部重写”。

### 为什么这对深层结构尤其重要

因为当层数增加时，信息要跨很多层传播。如果每层都强迫自己完全改写输入，训练会明显更不稳定。

所以残差的本质不是“shortcut 很流行”，而是：

> 它让深层模型拥有更健康的信息流和梯度流。

## 第四件事：归一化在 block 里是在控制尺度

随着层数堆叠，隐藏状态的数值范围可能会越来越不稳定。某些维度过大、某些维度过小，都会让训练变差。

归一化层的作用可以朴素地理解成：

> 在进入关键计算之前，先把当前表示整理到更稳定的尺度。

### 常见归一化有哪些

在 Transformer 里常见的包括：

- LayerNorm
- RMSNorm

对初学者来说，这一章最重要的不是记住它们的所有差别，而是理解：

- 它们都在帮助训练稳定
- 它们通常沿着隐藏维度工作
- 它们不是改变语义目标，而是在管理表示尺度

## 第五件事：为什么很多现代 decoder-only 结构喜欢 pre-norm

你会经常看到两种顺序：

- 先归一化，再算 Attention/FFN
- 先算 Attention/FFN，再归一化

其中前者常被称为 pre-norm。

### 为什么 pre-norm 常见

对于很多深层 Transformer 来说，pre-norm 通常更利于训练稳定。你可以粗略理解成：

> 先把输入整理好，再交给复杂算子处理，深层时更稳妥。

你不需要此刻做架构学术比较，但需要知道：

- 顺序不是随便摆的
- 它直接关系到训练行为

## 第六件事：FFN 负责的是“每个位置内部怎样思考”

Attention 解决的是跨位置通信，但它不等于全部表示能力。

FFN，也就是前馈网络，通常对每个位置独立工作。它不直接和其他位置交互，而是在当前 token 已经融合完上下文之后，对这个位置的表示做更强的非线性变换。

### 一个很实用的记忆方式

你可以先这样记：

- Attention：看哪里
- FFN：看完之后，当前位置怎么加工这些信息

这当然不是严格数学定义，但对建立结构直觉非常有效。

### 为什么不能只保留 Attention

如果只有 Attention，模型具备了跨位置读取能力，但每个位置内部的非线性加工能力会不足。

因此，一个完整 block 里需要同时有：

- 跨位置交互
- 逐位置非线性变换

## 第七件事：位置编码为什么必须出现

上一章我们已经提到，Attention 本身并不会自动理解顺序。

如果完全不给模型位置信息，那么这些序列：

```text
A B C
C B A
```

在某些表示下可能显得过于相似，这显然不适合语言任务。

### 位置编码到底在补什么

它补的是：

- 谁在前，谁在后
- 相对距离如何
- 序列顺序怎样影响依赖关系

### 常见位置方法有哪些

初学阶段知道这几类就够了：

- 绝对位置向量
- 正弦位置编码
- 相对位置表示
- 旋转位置编码（RoPE）

它们实现不同，但共同目标都一样：

> 把“顺序信息”注入模型表示，让模型知道 token 不只是一个集合，而是一条有顺序的序列。

## 第八件事：为什么很多现代小模型会使用 RoPE

RoPE，rotary positional embedding，是近些年很多 decoder-only 模型常见的位置方法。

你现在不需要完整掌握它的推导，但应该知道：

- 它把位置信息注入到注意力使用的表示里
- 它特别强调相对位置关系
- 在很多实践里效果和可扩展性都不错

对于学习项目来说，知道它的定位就足够：

> RoPE 不是独立模块秀肌肉，而是一种把顺序关系交给 Attention 使用的方法。

## 第九件事：一个 block 里到底发生了什么

现在把数据流按直觉走一遍。

### 第 1 步：先归一化当前位置表示

这一步让进入关键计算的输入尺度更稳定。

### 第 2 步：通过 Attention 读取上下文

当前位置根据自己的 query，决定从历史哪些位置拿信息，并形成加权上下文摘要。

### 第 3 步：残差加回原表示

这样当前位置既保留原信息，又吸收了新的上下文修正。

### 第 4 步：再次归一化

为了让下一段复杂计算继续处在稳定范围。

### 第 5 步：通过 FFN 做逐位置非线性加工

这一步不再和其他位置直接通信，而是强化当前位置自身的表示能力。

### 第 6 步：再一次残差叠加

于是这一层处理完成，输出交给下一层 block。

你如果把这条链想顺了，Transformer Block 就不再是抽象名字，而会变成一个你可以逐步讲清的数据流。

## 第十件事：为什么 block 可以被很多层重复堆叠

一个很关键的结构性质是：

> block 的输入输出形状通常相同。

例如：

\[
[B, T, H] \rightarrow [B, T, H]
\]

这使得它可以被反复堆叠。

### 多层堆叠意味着什么

不是单纯“参数变多了”，而是：

- 模型有更多轮读取上下文的机会
- 模型有更多轮重写内部表示的机会
- 浅层和深层可以逐渐学到不同抽象层次的统计关系

所以层数的意义是深度，而不只是数量。

## 第十一件事：为什么一个 block 里不能随便删部件

这是理解 block 协同作用的最好方式。

### 没有 Attention

模型失去动态跨位置通信能力。

### 没有 FFN

模型失去强逐位置非线性加工能力。

### 没有残差

深层信息流和梯度流明显变差。

### 没有归一化

训练更容易不稳定。

### 没有位置信息

模型很难可靠区分顺序关系。

所以 block 不是“注意力外加几个可有可无的零件”，而是一套互相配合的结构。

## 第十二件事：为什么 Transformer Block 是语言模型学习里的真正基本单元

从学习角度看，你不应该把“注意力层”当成模型最小单位，更合理的最小单位是：

> 一个结构完整的 block。

原因是：

- 只讲 Attention 不足以解释稳定训练
- 只讲 FFN 不足以解释序列建模
- 只讲归一化和残差又脱离了上下文读取问题

一个 block 把这些要素合在一起，才构成了真正可堆叠的基础砖块。

## 第十三件事：初学者最容易误解的几点

### 误区 1：Attention 已经够复杂，所以 FFN 只是陪衬

不对。FFN 负责的是不同维度的问题，不能被简单省略。

### 误区 2：残差连接只是为了照抄标准结构

不对。它对深层训练稳定性至关重要。

### 误区 3：位置编码只是额外增强项

不对。没有顺序信息，语言序列的很多关键结构都无法被可靠表达。

### 误区 4：block 里的顺序可以随便换

也不对。归一化位置、残差位置都会改变训练行为。

<Callout title="这一章真正想让你建立的结构感" tone="note">
  Transformer Block 不是“Attention 加几个小组件”，而是“位置感知的上下文读取 + 稳定的信息传递 + 逐位置非线性加工”的完整单元。理解 block，才算真正开始理解 Transformer。
</Callout>
