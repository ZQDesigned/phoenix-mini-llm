# 卷八 语言建模为什么本质上是序列条件概率问题

> 本卷属于第三编“文本、分词与语言建模”，负责把 token 序列、训练样本窗口与 next-token prediction 接成同一条监督主线。

上一卷解决的是：

> 机器到底怎样获得可操作的文本单位。

但只知道 token 怎样来，还不等于已经定义好了语言模型。

你还需要继续回答三件更关键的事：

1. 为什么文本一旦变成序列，学习问题就会和普通表格预测明显不同。
2. 为什么训练不能直接把整本书当成一条样本，而要切成窗口。
3. 为什么训练目标最后会自然长成“给定历史预测下一个 token”。

这三件事连起来，才会真正把“文本对象”推进成“语言建模问题”。

## 为什么这一卷必须存在

很多资料在讲 tokenizer 之后，会立刻跳到 Transformer。

这种跳法省了中间层，但会留下一个很大的认知断口：

> 你知道文本已经被切成 token，却还不知道语言模型究竟在这些 token 上学什么。

于是后面很多关键设计都会显得像直接规定出来的模板：

- 序列要定长
- 样本要右移一位
- 模型只能看左边
- 推理要一个 token 一个 token 地往后写

这些做法当然都对，但如果中间没有这一卷，它们会显得更像配方，而不是问题自然推出的结果。

## 为什么语言模型不是“文本分类的加长版”

从普通机器学习过来的读者，最容易在这里犯的一个错，是把语言模型想成：

- 输入还是一串文本
- 输出还是一个标签
- 只是标签变复杂一点

这并不准确。

因为语言模型最本质的变化在于：

> 它的目标不再是给整条输入贴一个外部标签，而是在同一条序列内部不断制造“当前位置应该预测什么”的监督关系。

这意味着：

- 输入和目标不再完全是两份独立对象
- 序列顺序开始变得极其重要
- 历史长度开始直接影响问题难度
- 模型必须在每个位置上都处理条件依赖

所以语言模型不是把传统任务拉长一点。
它是在重新定义什么叫一条样本、什么叫一次预测、什么叫监督信号。

## 为什么“序列”本身就会制造困难

普通表格任务里，你常常可以把一条样本看成一组并列特征。

而序列任务不同。

一旦对象变成序列，立刻会出现几类新约束：

- 顺序不能随便打乱
- 不同位置的重要性不一样
- 当前判断往往依赖此前历史
- 历史越长，相关信息越可能分布得很远

这会直接改写模型设计逻辑。

也正因为如此，这一卷会先把“序列为什么更难”讲清楚，再去讲样本窗口和 next-token 目标。

## 为什么训练必须把长文本切成窗口

初学者常常会本能地问：

> 既然语言模型学的是整段文本规律，为什么不直接把整本书一次喂进去？

答案并不只是“显存不够”。

更深的原因在于，训练系统必须把原始长流改写成可重复、可比较、可批处理的样本单位。

这意味着你必须决定：

- 一次让模型看多长历史
- 样本边界放在哪里
- 文档边界如何保留
- 哪些位置参与 loss，哪些位置不参与

也就是说，窗口化不是后勤操作。

它是在定义：

> 模型每一步究竟在什么上下文长度上学习条件概率。

## 为什么目标会自然长成“右移一位”

语言模型最经典的训练目标看起来很简单：

> 给定前面的 token，预测下一个 token。

这经常被写成“右移一位”。

但“右移一位”不该被记成机械格式。

它真正表达的是：

- 序列里的每个位置，都把左侧历史当成条件
- 当前 token 充当这个条件下应该出现的结果
- 整段序列于是自然长成很多局部预测事件的并列集合

换句话说，语言模型的监督并不是外部再贴一张标签表。

它是从同一条序列内部直接长出来的。

## 这一卷真正想留下的是什么

最重要的不是一句“语言模型预测下一个 token”。

更重要的是你开始真正理解：

### 第一，next-token prediction 不是口号，而是问题重写方式

模型并不是突然决定去预测“下一个词”。

而是在文本已经被写成 token 序列、样本已经被切成窗口之后，这种目标最自然、最可训练、最容易批处理地长了出来。

### 第二，序列建模的困难早在 Transformer 之前就出现了

也就是说，后面的 attention 并不是凭空发明的新玩具。

它是为了应对这里已经暴露出来的长依赖、路径长度和读取困难。

### 第三，训练目标和推理行为从一开始就是同一条链

右移一位目标不是只在训练里出现的格式细节。

它会一直延续到后面：

- 训练时怎样算 loss
- 推理时怎样逐 token 生成
- cache 为什么有意义
