# 卷一 入门与学习地图

> 本卷属于全书的序篇，负责先建立学习方向、阅读方法与问题意识，再进入数学、学习系统与语言模型主体。

如果你是第一次认真学习大模型，很可能已经在网上看见过一长串耀眼的词：

- Transformer
- Attention
- Tokenizer
- Prompt
- LoRA
- RLHF
- RAG
- KV cache
- 量化
- 推理加速

这些词当然都重要。

但对初学者来说，更关键的问题不是“先认识多少名词”，而是：

> 你到底知不知道自己正在学习什么系统，以及应该按什么顺序进入它。

如果这个问题没有先答清楚，最常见的结果不是“学得慢一点”，而是会直接走向两种长期低效状态。

第一种状态是术语堆积。

你会逐渐能认出越来越多的名字，却无法把它们连成一条稳定的因果链。
你知道 Attention 是什么词，却说不清它到底在解决什么问题。
你知道 Tokenizer 很重要，却说不清它为什么不是一个可随便替换的小配件。
你知道语言模型会“生成文本”，却说不清训练时它到底在学什么。

第二种状态是工程幻觉。

你会觉得自己已经“做过项目”，因为你可以执行若干命令、安装若干依赖、运行若干脚本。
但如果把现成仓库拿掉，让你从空目录重新思考：

- 模型要解决什么任务
- 数据为什么要那样组织
- 损失为什么那样定义
- 为什么必须有上下文和位置
- 推理为什么会变成一步一步生成

你就会发现理解实际上并没有建立起来。

这一卷存在的原因，就是在进入任何具体技术细节之前，先把学习方向摆正。

它不负责把你变成“已经会做模型的人”。
它负责做更基础、也更重要的事情：

- 帮你明确这套知识到底在学什么
- 帮你校正不现实或不必要的目标
- 帮你把整套材料看成连续主线，而不是散乱文章
- 帮你建立一种真正适合从零学习大模型的阅读方法

换句话说，这一卷不是在讲“怎么开工”。
它是在讲：

> 为什么要这样开工，以及如果不开在正确的位置，后面会怎样一路读歪。

## 1.1 为什么整套书必须从这一卷开始

很多人会以为，真正的学习应该立刻从“硬内容”开始，例如：

- 数学公式
- 神经网络代码
- Transformer 结构图
- PyTorch 训练循环

这种看法表面上很积极，实际上常常会制造更大的理解断层。

因为大模型学习最大的困难，并不只是内容多。
而是它会把多个层次的东西同时压到你面前：

- 任务定义
- 数学对象
- 学习系统
- 文本表示
- 序列建模
- 训练机制
- 推理机制
- 评估与排障

如果你在进入这些层次之前，没有先知道：

- 哪些是地基
- 哪些是桥梁
- 哪些是后面的高级变体
- 哪些只是建立在前面之上的应用外壳

那么你学到的就不是一栋房子，而是一堆尚未装配的零件。

这一卷的意义，正是先把这栋房子的总结构告诉你。

它先不让你背更多术语，而是先回答几件最根本的事：

1. 什么叫语言模型  
2. 为什么今天的大模型首先是语言模型的延伸  
3. 为什么初学者不该从规模幻觉出发  
4. 什么叫“小而完整”的学习目标  
5. 这一整套知识档案究竟该怎样阅读  

只要这五件事稳住了，后面哪怕进入更难的章节，你也会一直知道自己在整条主线上所处的位置。

## 1.2 这卷所说的“从零开始”到底是什么意思

“从零开始”常常是一个被滥用的表达。

有些材料说自己从零开始，实际上默认你已经会：

- 微积分
- 线性代数
- 概率统计
- Python
- PyTorch
- 深度学习常见套路

也有一些材料把“从零开始”理解成完全避开抽象，只留下非常表面的操作说明。

这两种做法都不适合真正想学懂的人。

在这套知识档案里，“从零开始”的含义更严格，也更现实：

### 第一，你可以没有机器学习背景

如果你此前没有系统学过监督学习、损失函数、反向传播、优化器，也没有关系。
后面的知识主线会重新把这些概念搭起来。

### 第二，你可以没有深度学习项目经验

你不需要先做过图像分类、文本分类或任何现成的神经网络项目，才能进入这里。
这套材料会从“模型为什么能学”开始慢慢铺。

### 第三，你不需要先会大模型工程生态

你不需要预先理解：

- 分布式训练
- 指令微调
- 对齐训练
- 量化推理
- 大规模推理服务

这些东西本来就不该放在最前面。

### 第四，但你必须愿意面对抽象

从零开始并不等于不需要思考。

如果你希望完全不接触下面这些内容：

- 向量和矩阵
- 函数与非线性
- 概率与对数概率
- 梯度与优化
- token 与分布

那么你最终得到的只会是“操作记忆”，而不是可迁移的理解。

所以这套材料对初学者是友好的，但它不会把真正必要的抽象拿掉。
它会做的是：

> 用尽可能连续、可解释、可回看的方式，把抽象一点点接到直觉上。

## 1.3 这一卷首先要拆掉哪些常见误解

初学者在学习大模型时，最常见的偏差并不是不会写代码，而是目标设置错误。

下面这些误解如果不先拆掉，后面几乎每一章都会被误读。

### 误解一：学大模型就是学一个热门软件栈

这是最常见也最危险的误解之一。

如果你把大模型学习理解成：

- 会配环境
- 会下数据
- 会跑训练脚本
- 会接一个推理接口

那你学到的更像是一次“工具使用经历”，而不是对模型本体的理解。

工具当然重要，但工具是承载结构的容器。
不是结构本身。

### 误解二：语言模型就是一个高级聊天程序

“会聊天”只是语言模型的一种使用形态，不是它的根定义。

真正的定义要落到：

- 序列
- 条件概率
- 下一步预测
- 上下文依赖

这些更基础的概念上。

如果这一点没有先立住，后面你会把许多关键设计都误解成“为了聊天才存在”。

### 误解三：想学懂，就应该一开始追求更大的模型

这是规模崇拜带来的典型幻觉。

很多人会本能地认为：

> 既然目标是大模型，那么越接近大模型的规模，学习价值越高。

但对初学者来说，情况往往正好相反。

因为你真正要学的不是参数数量，而是下面这些东西之间的连接：

- 文本怎样被表示
- 训练目标怎样定义
- 模型怎样读上下文
- 损失怎样推动更新
- 推理怎样一步步展开

这些关键结构，在一个小而完整的模型里就已经全部存在。

### 误解四：如果一开始不学最新技巧，就会落后

这也很常见。

很多人担心如果不尽快进入：

- 多模态
- 工具调用
- 对齐
- 检索增强
- Agent

就会“错过真正的大模型时代”。

但如果基础主线没有建立，你学这些内容只会变成概念漂浮。

你可能会背很多系统名词，却不知道这些系统究竟建立在什么最小核心之上。

### 误解五：只要跟着教程跑通，就算从零学会了

跑通当然有价值。
但“复现结果”和“理解机制”是两件不同的事。

真正成熟的学习状态至少包含三层能力：

1. 你能把概念讲清楚  
2. 你能把关键部件自己重新拼起来  
3. 你能在出错时靠原理定位问题，而不是只会搜索报错文本  

这一卷的存在，就是为了在最开始把这三层目标分清楚。

## 1.4 为什么这套知识档案要围绕“小而完整”的模型展开

这一点会在下一章被更系统地展开，但在卷首就应该先明确立场。

我们这里追求的不是“最像新闻里那个巨大的模型”。
我们追求的是：

> 一个足够小，小到个人可以真正看清内部结构；同时又足够完整，完整到现代语言模型的关键环节都已经在里面出现的学习对象。

所谓“小而完整”，至少包含几个特征。

### 第一，它足够小，能在有限硬件上训练和调试

如果模型太大，你很快就会被：

- 显存限制
- 训练时间
- 依赖复杂度
- 调参成本

压住。

当这些现实限制压得过重时，注意力就会从“理解结构”转移到“设法让它勉强跑起来”。

### 第二，它足够完整，能够覆盖一条真正的模型闭环

这个闭环至少包括：

- 文本进入模型前的处理
- token 到表示的映射
- 序列建模与注意力
- 自回归训练目标
- 损失计算与参数更新
- 基本生成与评估

只要这一闭环在，小模型同样能够承载“真正的大模型基础知识”。

### 第三，它足够透明，能让你自己重建

学习价值最高的状态，不是“我会调用某个库里的成品模型”，而是：

> 我知道为什么模型会长成这样，并且能从概念一路把它重建出来。

正因为如此，这一整套文档才会把知识档案、复刻教程和踩坑记录三条线同时维护。

## 1.6 这一卷和复刻教程、踩坑记录分别是什么关系

为了避免知识档案、复刻教程和踩坑记录互相打架，这三个区域的职责必须非常清楚。

### 知识档案负责“知识主线”

这里优先回答：

- 这是什么
- 为什么会这样
- 它和前后知识怎样连起来

它的目标是让你真正具备可迁移理解。

### 复刻教程负责“复刻过程”

这里优先回答：

- 第一步做什么
- 第二步做什么
- 如何一步步把完整模型重新做出来

它会大量引用知识档案中的对应章节，但不应该吞掉知识档案本身的职责。

### 踩坑记录负责“真实开发中的误判与修正”

这里优先回答：

- 开发时最容易在哪一步想错
- 为什么这个错会发生
- 应该怎样重新校正

它的价值在于让读者知道：

> 一个项目并不是沿着完美直线长出来的，真正的理解常常是在犯错和修正里被打磨出来的。

所以你可以把三者理解成三种不同的书写视角：

- 知识档案是教材视角
- 复刻教程是手把手复刻视角
- 踩坑记录是开发复盘视角

## 1.7 读这一卷时，正确的问题意识是什么

这一卷虽然属于导论，但它不是“随便翻翻就行”的暖场。

真正合适的阅读姿态，是带着下面这些问题进入：

### 问题一：语言模型的根任务到底是什么

不是“它看起来会做什么”，而是“训练和推理层面它究竟被定义成了什么”。

### 问题二：为什么小模型足以承载基础学习

不是因为我们硬件差，所以只能退而求其次。
而是因为基础结构本来就应该先在可观察尺度上被掌握。

### 问题三：后面每一卷出现的必要性是什么

例如：

- 为什么学大模型还要先看线性代数
- 为什么还要专门讲概率和对数
- 为什么 tokenization 不能跳过
- 为什么 attention 不是突然冒出来的技巧

如果你带着这些问题走完整条主线，整套材料会变得非常连贯。

### 问题四：我最终要获得的能力究竟是什么

不是“记住所有热门名词”，而是逐渐获得下面这种能力：

> 给你一个空白目录，你能从任务定义出发，一步步解释并重建一个小型语言模型为什么会长成它现在的样子。

## 1.9 这一卷读完之后，你应当建立哪些最基本的判断

如果这一卷真正读懂了，你至少应该形成下面这些稳定判断。

### 判断一：大模型学习首先是模型学习，不是资讯追逐

热点会不断变化。
但语言模型的基础链条不会因为新名词出现就消失。

### 判断二：基础知识不是拖慢进度的负担，而是后面所有理解的承重墙

你不是因为“数学考得更好”才学线性代数、概率和梯度。
而是因为不学它们，后面的机制根本立不住。

### 判断三：小模型不是玩具，而是最适合建立结构理解的显微镜

同样的结构，在太大的系统里很容易被工程复杂度遮住。

### 判断四：真正的学习结果，是能够解释、重建、调试

不是只会运行命令。
不是只会跟着写。
不是只会在笔记里抄定义。

## 1.10 这一卷之后，不该再继续含糊的几个问题

进入下一卷之前，你应该已经不再对下面这些问题含糊其辞。

1. 语言模型是一个关于序列条件概率预测的系统，而不只是“会说话的软件”。  
2. 初学者应该先追求结构闭环，而不是参数规模。  
3. 整套知识档案的顺序，是从任务定义走向数学基础，再走向学习系统、文本表示、序列建模、训练、推理和后续扩展。  
4. 知识档案、复刻教程和踩坑记录承担的是不同职责，不能混用。  
5. 你接下来要做的，不是赶紧跳到热门技巧，而是先老老实实把主线地基走稳。  

## 1.11 如果你现在只能记住这一卷的一句话
