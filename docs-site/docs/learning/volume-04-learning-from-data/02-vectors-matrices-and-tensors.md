# 02. 样本、特征、标签、batch 与张量布局

这一章表面上在讲一些很朴素的词：

- 样本
- 特征
- 标签
- batch
- 张量布局

但它实际上碰到的是训练系统里极其根本的一层。

因为后面无论你写：

- 线性模型
- MLP
- Transformer
- 训练循环
- 交叉熵

都必须先默认自己已经知道：

- 模型到底在看什么输入
- 这些输入按什么单位组成样本
- 样本在张量里如何排布
- 目标张量和输出张量应该怎样一一对应

如果这些前提不清楚，训练代码看起来就会像一堆 API 操作，shape 也会变成“数字能对上，但语义不知道对不对”的谜题。

所以这一章不是在重复数学卷里已经讲过的“什么是向量和矩阵”。
它回答的是一个更接地气也更根本的问题：

> 当我们说“拿数据训练一个模型”时，训练问题里的对象到底是什么，它们又如何被翻译成可计算张量？

## 为什么这一章必须放在模型结构之前

很多人学机器学习时，注意力会自然跑向更显眼的东西：

- 哪种模型更强
- 哪个优化器更好
- 激活函数怎么选
- loss 用交叉熵还是别的

但在这些内容之前，其实有一个更早的问题必须先被回答：

> 你到底在训练什么问题？

这个问题听起来像一句废话，却经常是训练失败的根源。

因为“训练什么问题”不只是任务名，例如：

- 房价预测
- 图像分类
- 文本生成

它还包括：

- 一条样本如何定义
- 哪些字段会进入模型
- 目标如何构造
- 一个 batch 的最小监督单位是什么
- 哪些维度对应样本、时间、通道、类别或词表

这些要素一旦糊掉，后面的损失函数、梯度和优化就都建立在含糊问题之上。

所以这一章的目标不是教你背术语，而是先帮你建立一套稳定的对象感：

> 训练并不是把“一堆数据”扔给模型，而是把原始世界重新切成一组带角色、带边界、带布局的可学习对象。

## 从最朴素的监督学习问题开始

先不要碰大模型，先看一个人人都能理解的例子：

> 根据房屋信息预测房价。

假设你有一条记录：

- 面积：`92`
- 楼层：`12`
- 朝向：`south`
- 小区年龄：`8`
- 价格：`4.3M`

这条记录里至少已经出现了几种不同角色：

- 房屋本身这件观察对象
- 描述它的若干输入字段
- 你想预测的价格

这就是一个最小学习问题的雏形。

一旦你想真正训练模型，就必须进一步明确：

- 什么算一条样本
- 哪些字段属于输入
- 哪个值属于目标
- 这些对象如何被编码成数值
- 多条记录怎样被堆成一个 batch

也就是说，机器学习不是从“世界里有很多房子”开始，而是从：

> 我已经决定怎样把世界里的房子重写成训练系统可以消费的对象

开始。

## 样本是什么

样本可以先理解成：

> 训练数据中的一个完整观察单位。

在房价问题里，一套房屋记录就是一个样本。

在手写数字识别里，一张图片是一个样本。

在文本情感分类里，一条句子或一篇评论是一个样本。

在语言模型里，一段上下文窗口通常是一个样本。

所以“样本”最重要的不是具体媒介，而是：

> 它是训练时被当成一个整体交给模型处理的最小问题单位之一。

注意这里故意说“之一”，而不是简单说“唯一最小单位”。
因为在某些任务里，一条样本内部可能还包含多个监督位置，我们稍后会回到这一点。

## 样本不是自然单位，而是设计单位

很多初学者第一次看数据，会觉得样本好像是天然存在的。
例如：

- 表里一行就是一个样本
- 一张图片就是一个样本
- 一段文本就是一个样本

这种直觉在入门阶段有帮助，但不够准确。

更准确地说：

> 样本并不是世界自己给出的单位，而是为了某个学习目标，人为切出来的训练单位。

同一份原始材料，根据目标不同，可以被切成完全不同的样本。

例如同一篇文章，可以被组织成：

- 一条情感分类样本
- 多条句子级别的分类样本
- 一个问答匹配样本
- 多个固定长度的语言模型训练样本

原始文章没有变。
变化的是你到底准备让模型学什么。

这句话非常重要，因为它会直接影响后面你对语言模型的理解。

语言模型里“样本”往往不是一篇完整文章，而是从长 token 流中切出来的一段窗口。
如果你没有先接受“样本是设计出来的”，后面就很容易觉得这种切法像技巧，而不是自然结果。

## 特征是什么

特征是：

> 用来描述样本、供模型观察并据此做判断的输入信息。

在房价例子里：

- 面积
- 楼层
- 朝向
- 小区年龄

都属于特征。

也就是说，特征不是“样本本身”，而是样本的可观测描述维度。

这个区分非常重要。

样本回答的是：

> 我们正在看哪一个具体对象？

特征回答的是：

> 我们用哪些视角来描述这个对象？

如果把电子表格当作类比：

- 一行更像一个样本
- 一列更像一个特征

这个比喻很好用，但不要把它误当成真理本身。
因为进入图像、音频、文本等非表格数据后，样本与特征的关系会复杂得多。
但“样本是实例，特征是描述维度”的本质仍然成立。

## 标签和目标是什么

标签通常指：

> 训练时你希望模型逼近的真实答案。

在房价问题里，标签是房价。

在图像分类里，标签是类别 ID。

在机器翻译里，标签可能是一整句目标语言序列。

在语言模型里，标签通常是每个位置对应的“下一个 token”。

所以不要把标签狭隘地理解成“某个类别名”。
更一般地说，它是：

> 用来告诉模型“什么才是这条样本上我们想要的正确答案”的对象。

“目标”这个词和“标签”很接近，但侧重点稍有不同。

- 标签更像数据层给出的真值
- 目标更像训练层真正要对齐的对象

在简单监督学习里，两者几乎可以混用。
但在复杂任务里，目标常常需要额外构造。

例如语言模型里，原始文本不是现成标签表，而是需要经过切窗、右移一位、mask 无效位置等步骤，才变成真正的训练目标。

所以更稳的记法是：

> 标签强调“正确答案是什么”，目标强调“优化时真正要对齐什么”。

## 一个学习问题最少要有哪些角色

到这里，可以把一个最基本的监督学习问题压缩成几种角色：

- 样本：训练单位
- 特征：输入描述
- 标签或目标：希望逼近的答案
- 模型输出：当前预测
- 损失：预测与目标之间的差距

这几种角色一旦稳定下来，后面的神经网络、softmax、反向传播就都会变得自然得多。

反过来说，如果这些角色没有先稳住，后面的很多技术细节都会被误学成孤立技巧。

## 数据集不是一堆随机文件，而是一组样本集合

很多人会把“数据集”理解成：

- 一个文件夹
- 一堆 JSON
- 一批图片
- 一份表格

从存储角度这样想没有问题，但从学习角度还不够。

更准确地说：

> 数据集是一组被组织成训练单位的样本集合。

这个定义里有两个关键点。

第一，数据集是有限的。
现实世界可能非常大，但你真正拿来训练的集合永远有限。

第二，我们希望它能代表任务分布。
也就是说，我们希望这批有限样本足够反映未来会遇到的那类输入结构和目标规律。

这就引出另一对很重要的概念：

- 手头的数据集
- 背后的数据分布

模型训练时真正看到的是前者。
我们真正希望它学到的，是能迁移到后者的规律。

所以当你说“我有数据了”，更严谨的问题其实是：

- 这些数据是不是被组织成了正确样本
- 它们是否足够代表我要处理的分布
- 它们的输入和目标关系是否真的对应任务本身

## 从人类数据到模型输入，中间必须经过表示转换

到目前为止，我们讨论的仍然更接近日常语言层。

但模型不能直接吃：

- 中文句子
- 房屋朝向这个词
- 图片里的“猫”
- 文件里的时间戳字符串

模型只能处理数值对象。

这意味着从人类世界到训练世界，中间必须经过表示转换。

例如：

- 类别词要变成 ID 或 one-hot
- 文本要变成 token ID
- 图片要变成像素张量
- 表格字段要做编码、归一化或嵌入

所以“做数据预处理”并不是一个工程附属项。
它本质上是在做一件更根本的事：

> 把人类可理解对象翻译成模型可计算对象。

如果这一层翻译做错了，后面的模型再复杂也救不了任务定义本身。

## 张量布局到底是什么

一旦对象进入模型世界，另一个问题马上出现：

> 这些数字不是散在空中的，它们怎样被排列，才能让模型知道每一维代表什么？

这就是张量布局。

张量布局可以先直观理解成：

> 一个张量中，不同维度各自承担什么语义角色，以及这些角色按什么顺序排布。

例如一个最常见的表格输入张量：

```text
[B, D]
```

可能表示：

- `B`：batch size，也就是当前一次并行处理了多少条样本
- `D`：每条样本有多少个输入特征

而在文本任务里，你常见的布局会变成：

```text
[B, T]
```

表示：

- `B`：一批样本
- `T`：每条样本的序列长度

再进一步，embedding 之后经常会变成：

```text
[B, T, H]
```

表示：

- `B`：样本数
- `T`：位置数
- `H`：每个位置的隐藏表示维度

所以同一个“张量”并不只是很多数字堆在一起。
它始终带着一份语义契约：

> 每一维到底是谁。

## 为什么这一章要重新讲一次 shape

前面的数学卷已经讲过：

- 标量
- 向量
- 矩阵
- 张量
- shape

那为什么到了这里还要再讲？

因为在数学卷里，shape 的重点是对象类型和维度感。
而在这一章，shape 的重点变成了训练语义：

- 哪一维是样本维
- 哪一维是时间维
- 哪一维是特征维
- 哪一维是类别维
- 哪一维是词表维

也就是说，前面那一卷回答的是：

> 这是什么对象？

这一章回答的是：

> 这个对象在训练系统里扮演什么角色？

这也是为什么很多人会出现一种很典型的困惑：

- 数学上我知道这是三维张量
- 但训练里我仍然不知道这三维各自代表什么

这一章就是要把这个缺口补上。

## 最基础的布局：`[B, D]`

对表格或一般监督学习问题来说，最常见的输入布局是：

```text
[B, D]
```

这里的直觉非常重要。

它不是在说“有两个维度”这么简单，而是在说：

- 第一维按样本展开
- 第二维按特征展开

例如：

```text
B = 32
D = 10
```

表示你一次并行处理 `32` 条样本，每条样本由 `10` 个输入特征描述。

如果输出是单一回归值，输出常见布局可能是：

```text
[B, 1]
```

如果输出是 `C` 类分类分数，输出常见布局会是：

```text
[B, C]
```

这一步看似简单，却决定了你后面能不能看懂：

- 线性层的输入输出
- 分类 logits 的形状
- 标签和输出如何对齐

## 同样的 shape，不保证同样的语义

这是整章最值得反复记的一句话之一：

> 同样的 shape，不保证同样的语义。

例如两个张量都长成：

```text
[32, 128]
```

它们可能分别表示：

- `32` 条样本，每条 `128` 个输入特征
- `32` 个 token 位置，每个位置 `128` 维隐藏表示
- `32` 个词表候选，每个候选 `128` 维属性

数字完全一样，语义却完全不同。

所以当你调试模型时，只看 shape 对不对是远远不够的。
你还必须问：

- 这一维现在代表的是样本、位置、特征、隐藏状态还是类别？

这就是为什么“能跑”不等于“语义正确”。

## 文本任务为什么会多出序列维

表格问题里，一条样本通常可以被看成一个固定长度特征向量。
但文本不一样。

文本天然带着顺序：

- 第一个 token 在前
- 第二个 token 在后
- 位置变化本身会改变含义

这意味着一条文本样本不再只是“一个向量”，而更像：

> 一个按时间或位置展开的离散序列。

于是输入布局会从：

```text
[B, D]
```

自然扩展成：

```text
[B, T]
```

这里：

- `B` 是样本数
- `T` 是每条样本的 token 数

一旦进入 embedding 层，就会变成：

```text
[B, T, H]
```

这里的 `H` 是隐藏维度，也就是每个 token 位置被映射成的向量长度。

所以序列任务的关键变化不是“数据更多了”，而是：

> 每条样本内部多了一条有顺序意义的轴。

这就是后面序列建模、attention 和位置方法必须出现的更早背景。

## token ID 不是 embedding，embedding 也不是隐藏状态

这也是初学者在语言模型里最容易混淆的几层对象。

### token ID

`[B, T]` 里的整数通常只是离散编号。
它们告诉模型：

- 第几个 token 类型出现了

但它们本身不是连续语义表示。

### embedding

embedding 层把每个 token ID 映射成一个向量，于是得到：

```text
[B, T, H]
```

这一步才把离散符号带入连续空间。

### 隐藏状态

经过后续的线性层、attention、MLP、残差等处理后，张量形状可能仍然是：

```text
[B, T, H]
```

但这时它已经不再只是初始 embedding，而是被多轮改写后的隐藏表示。

所以不要被“shape 没变”迷惑。
shape 没变，不等于对象语义没变。

## logits 为什么常是 `[B, T, V]`

在语言模型输出端，一个极其关键的张量是：

```text
[B, T, V]
```

这里：

- `B` 是样本数
- `T` 是位置数
- `V` 是词表大小

它表示的是：

> 对于每个样本、每个位置，模型都给出了对整个词表的打分或偏好。

这就是 logits。

注意它和 `[B, T, H]` 看起来只差最后一维的字母，但语义完全不同：

- `H` 表示内部隐藏表示空间
- `V` 表示输出候选空间，也就是整个词表

很多 bug 就出在这里：

- 你以为自己还在处理隐藏表示
- 实际已经切换到了词表打分

所以对语言模型来说，最重要的不是单纯记住几个 shape，而是清楚知道：

> 当前张量到底处在输入空间、表示空间，还是输出候选空间。

## 为什么语言模型标签常是 `[B, T]`

既然输出是：

```text
[B, T, V]
```

那标签为什么经常不是 `[B, T, V]`，而只是：

```text
[B, T]
```

原因在于，标签通常只需要告诉模型：

> 每个位置真正应该出现的是哪个 token ID。

也就是说，对每个位置而言，真值常常只是一个词表索引，而不是一个完整概率分布。

于是训练时常见的关系是：

- 输出：对整个词表的打分
- 标签：正确 token 的编号

后面的交叉熵会把这两者接起来。

这一步如果没想明白，很多人会困惑：

- 为什么输出是三维
- 为什么标签是二维
- 为什么它们居然还能比较

本质上是因为二者并不要求形状完全相同，而要求：

> 它们在监督语义上是对齐的。

## 一条样本内部为什么可以有多个监督位置

在图像分类里，你常常可以说：

- 一条样本
- 一个标签

但语言模型会打破这条简单关系。

因为一条长度为 `T` 的序列样本，往往在每个有效位置都带着一个监督目标。

这意味着要区分两个层次：

### 样本级单位

当前 batch 里有多少条独立序列。

### 位置级监督单位

每条序列内部有多少个位置会产生损失。

这也是为什么语言模型虽然 batch size 可能不大，但实际每一步参与监督的位置数仍然可能很多。

这个概念会直接连到后面的：

- token 数统计
- loss 归一化
- padding mask
- 训练吞吐量

所以它不是一个小细节，而是语言模型训练统计的基础。

## batch 到底是什么

很多人第一次接触 batch，会把它理解成：

- 一次拿几条数据一起算

这个理解没有错，但还不够。

更完整地说，batch 同时有两层意义。

### 计算层意义

batch 让模型可以并行处理多条样本，提高硬件利用率。

### 统计层意义

batch 让一次参数更新不必只依赖单一样本，而是依赖一小组样本共同给出的误差信号。

也就是说，batch 不是单纯为了“更快”。
它还在影响：

- 梯度估计有多噪
- 每次更新有多稳定
- 显存占用有多高
- 训练曲线会怎样抖动

后面卷十一讲训练统计时，你会重新看到这层意义。

但在这一章先记住一句话就够了：

> batch 既是一种计算组织方式，也是一种统计采样方式。

## 为什么 batch 维几乎总在最前面

很多框架和代码约定都会让 batch 维放在最前面，例如：

- `[B, D]`
- `[B, C, H, W]`
- `[B, T]`
- `[B, T, H]`

这不是宇宙真理，但它是一个很稳定的工程与心智约定。

这样做的好处是：

- 不同任务之间的批处理接口更统一
- 你更容易一眼看出“当前一次并行了多少样本”
- 后续 reshape、mask、loss 对齐时更容易保持一致

一旦你在脑子里建立了“batch-first”的默认习惯，阅读深度学习代码会轻松很多。

## padding 和 mask 为什么总是一起出现

序列任务里，不同样本的长度经常不同。

但 batch 计算通常希望把它们堆成规则张量。

于是很自然会发生两件事：

第一，为了把不同长度样本堆到一起，需要在短序列后面补齐一些占位符。
这就是 padding。

第二，因为这些补出来的位置并不是真实内容，所以模型或损失在很多地方又必须知道：

- 哪些位置是真的
- 哪些位置只是补位

这就是 mask。

所以 padding 和 mask 不是两种独立技巧。
它们是一对逻辑上相伴而生的对象：

> 既然你把不规则序列强行堆成规则张量，就必须同时记录哪些部分其实不该被当真。

## metadata 为什么不等于 feature

另一个经常被忽略的问题是：

不是所有附带信息都应该直接进入模型当特征。

例如你可能有：

- 文件路径
- 样本 ID
- 时间戳字符串
- 数据来源标记
- 人工备注

这些信息有时只是元数据，用来：

- 定位样本
- 追溯来源
- 排查问题
- 做切分或统计

它们不一定适合作为模型输入特征。

所以看见一列信息时，不要立刻问“怎么编码进模型”。
先问：

> 它是在描述任务可用证据，还是只是在描述数据管理信息？

这也是“问题定义先于模型”的一个实际表现。

## 为什么“能跑”不等于“语义正确”

很多训练错误最危险的地方在于：

- 代码能跑
- shape 能对上
- loss 还能下降一点

但语义其实已经错了。

典型情况包括：

- 把 batch 维误当成特征维
- 把 token ID 当成连续数值特征直接喂线性层
- 把 hidden 维和 vocab 维混掉
- 把 padding 位置也当作真实监督
- 把标签顺序和输出顺序对错位

这些问题之所以难查，是因为它们常常不会立刻报 shape error。
模型只是悄悄学成了另一个问题。

所以当你调试训练时，永远不要只问：

- 这个张量形状对吗？

还要问：

- 这个张量里每一维现在代表什么？
- 它和目标的对应关系是否仍然成立？
- 哪些位置是真实监督，哪些位置只是补位？

这就是为什么张量布局其实也是调试工具。

## 为什么这一章对 LLM 特别重要

语言模型之所以让很多初学者一上来就头大，不是因为它的张量维度“更花哨”，而是因为它把前面讲的所有对象关系都同时放大了。

在 LLM 里，你必须同时稳住下面这些区别：

- 原始文本和训练样本不是一回事
- token ID 和 embedding 不是一回事
- embedding 和隐藏状态不是一回事
- 隐藏状态和 logits 不是一回事
- 一条样本和一个监督位置不是一回事
- padding 位置和真实位置不是一回事

如果这些边界不清楚，后面的 attention、mask、loss、KV cache 都会变得像黑话堆。

反过来说，只要这一层站稳，很多看似复杂的大模型张量都会重新变得可解释。

## 读完本章后，你应该能稳定回答什么

如果这一章真正起作用了，你应该能够稳定解释下面这些问题：

- 为什么样本不是天然单位，而是为任务设计出来的训练单位
- 为什么特征、标签和目标不能混成一个词
- 为什么数据集和数据分布必须区分
- 为什么同样的 shape 不保证同样的语义
- 为什么文本任务会自然多出序列维
- 为什么 token ID、embedding、hidden state、logits 必须分层理解
- 为什么语言模型一条样本内部可以有多个监督位置
- 为什么 padding 和 mask 总是成对出现

如果这些问题还答不稳，就不要急着往后跳到更复杂的模型结构。

## 小结

这一章最想留下的主句可以浓缩成这样：

> 训练不是把一堆数字交给模型，而是先把原始世界切成样本、特征和目标，再把这些对象按明确语义布局翻译成张量，最后让模型在这套语义契约上学习。

对语言模型来说，这句话还可以再具体一点：

> 文本必须先被重写成带位置关系的 token 序列，再被组织成 batch、时间维、隐藏维和词表维，模型才有可能真正开始学习。

只要这个认识站稳，后面的：

- 线性层
- softmax
- attention
- 训练循环

就都会重新回到同一条主线上：

> 模型究竟在处理什么对象，以及这些对象怎样被稳定地送进学习系统。
