# 01. 机器学习到底在学什么

很多人第一次认真接触机器学习时，学习顺序会很快滑向实现层：

- 安装框架
- 定义模型类
- 写 `forward`
- 选优化器
- 运行训练脚本

这种推进方式很常见，也很危险。

危险不在于它会让你学不会写代码，而在于它很容易让你在没有真正理解“学习”这个词的情况下，就开始处理一整套围绕“学习”设计出来的工具。

于是你会知道很多动作：

- 读数据
- 算输出
- 算 loss
- `backward()`
- `step()`

但你仍然可能说不清下面这些问题：

- 模型到底在从什么学到什么
- 为什么不是所有“看起来会动的训练过程”都叫学习
- 参数改变和“模型变聪明”之间到底是什么关系
- 为什么训练集变好，不自动等于模型真的学会
- 为什么语言模型不是在背句子，而是在学另一种更抽象的东西

这就是这一章存在的原因。

它不是导语，不是铺垫，也不是术语热身。
它先要把机器学习里最核心的一件事摆正：

> 学习到底是什么意思？

## 日常语言里的“学习”和机器学习里的“学习”差在哪里

在日常语言里，“学习”常常意味着：

- 记住一批知识
- 理解一个概念
- 掌握一项技能
- 经过练习变得更熟练

这些说法都很自然。
但如果直接把它们搬到机器学习里，就会产生不少误解。

因为在机器学习里，更准确的说法通常是：

> 模型通过接触数据、比较输出与目标之间的偏差，并根据这种偏差调整参数，使自己在某类输入上的输出行为逐步变得更符合目标。

这句话很长，但它非常重要。

它至少揭示了机器学习里的“学习”必须同时包含五个部分：

- 有数据
- 有目标
- 有模型
- 有偏差比较
- 有参数更新

只要这五件事没有真正连起来，“学习”在机器学习里就还只是一个模糊词。

## 先用一句最朴素的话定义机器学习

如果你想先抓住一个足够粗但正确的核心，可以把机器学习理解成：

> 用数据不断修正一个参数化函数，让它对某类输入给出越来越合理的输出。

这里面有三个词值得你抓紧不放。

第一，参数化函数。
模型不是神秘智能体，它首先是一类由参数控制的函数系统。

第二，修正。
学习不是一次性发生的启示，而是多次更新。

第三，越来越合理。
学习不是“绝对正确”，而是相对于某种目标在逐步改善。

这个定义之所以重要，是因为它能帮你把后面的很多技术词全部重新放回正确位置：

- 数据是在提供经验
- 损失是在定义什么叫不合理
- 梯度是在告诉我们参数该怎么改
- 优化器是在执行这种修改

因此，真正的学习主线不是“代码跑起来了”，而是：

> 参数化函数在目标驱动下，因数据而逐步改变。

## 学习最朴素的图景：逼近一个有用映射

如果继续往下压缩，机器学习最通用的图景还可以再说得更简单：

> 给定输入，模型要学会输出对这个任务有用的结果；训练过程则是在不断调整参数，让输入到输出的映射越来越接近我们想要的样子。

例如：

- 图片分类：从像素到类别
- 房价回归：从房屋特征到价格
- 情感分析：从文本到情感标签
- 语言模型：从历史 token 序列到下一个 token 的条件分布

这些任务表面差异很大，但在更底层的层面，它们都可以被统一描述成：

```text
输入 -> 参数化映射 -> 输出
```

这里“映射”这个词非常重要。
因为它提醒你：

- 学习不是背一批固定答案
- 学习是在形成一套可重复使用的输出规则

只要这个“映射”视角站稳，后面你再看：

- 线性模型
- 多层感知机
- Transformer

就会知道这些结构全都在服务同一件事：

> 怎样表达并学习这种映射。

## 为什么“映射”比“记答案”更接近学习本质

初学者非常容易把模型想成：

> 它是不是把输入和答案的对应关系背下来了？

这并不是一个愚蠢的问题。
事实上，很多模型确实可能表现出某种程度的记忆。

但把“学习”直接等同于“背答案”会带来两个严重问题。

第一，它会误导你理解目标。

机器学习真正想要的，不是让模型只在训练集上复述答案，而是让模型在新样本上也能延续某种规律。

也就是说，学习的理想目标是：

- 抓住规律

而不仅仅是：

- 存下细节

第二，它会误导你理解失败模式。

如果你把学习理解成记忆，那么你就会低估：

- 泛化为什么重要
- 验证集为什么必要
- 过拟合为什么是核心问题

所以，更准确的说法应该是：

> 模型可能会记住很多细节，但我们希望它学到的是一种对新输入仍然有效的规则结构。

## 参数到底是什么，为什么它们是学习的落点

讲机器学习，几乎不可能绕开“参数”。
但很多初学者一开始对参数的理解非常薄：

- 参数就是一堆数字
- 参数训练之后会变

这当然没错，但远远不够。

更有解释力的说法是：

> 参数是模型内部可调的数值自由度，它们共同决定了模型如何读取输入、如何组织中间表示，以及如何形成输出偏好。

这个定义比“权重和偏置”更重要，因为它强调了参数的功能，而不是只强调它们的形式。

参数真正决定的是：

- 输入里的哪些模式会被看重
- 哪些方向会被放大或压低
- 哪些输出候选更容易被偏好

换句话说，参数不是神经网络里的材料。
它们更像：

> 当前模型行为的编码。

因此，当我们说“模型学到了什么”，很多时候更底层的意思其实是：

> 参数被推到了某种新的区域，而在这个区域里，模型对输入的反应方式发生了变化。

## 结构和参数是什么关系

模型通常同时包含两层东西：

- 结构
- 参数

结构定义的是：

- 哪类计算会发生
- 信息大致怎样流动
- 有哪些可调部位

参数定义的是：

- 这些可调部位当前具体取值是什么

例如在最简单的线性层里：

- 结构规定：这是一次线性变换
- 参数规定：这次线性变换具体按什么权重组合输入

在更复杂的 Transformer 里也是一样：

- 结构规定：这里有注意力、有前馈层、有残差与归一化
- 参数规定：当前这些组件具体怎样偏好不同模式

因此，学习通常不是在发明一套全新结构。
更常见的情况是：

> 结构给定后，训练通过数据不断调整参数，让这套结构逐步长成适合任务的行为。

## 数据为什么会成为“老师”

模型不会凭空知道什么是好输出，什么是坏输出。

它之所以有可能学习，是因为数据提供了某种经验边界：

- 哪些输入会出现
- 这些输入通常应当对应哪些输出或目标
- 如果当前输出不够好，应该如何度量偏差

更准确地说，数据不是在“告诉模型真理”，而是在提供：

> 让模型通过反复比较和调整，逐步逼近规律的经验基础。

例如：

- 在分类任务里，数据提供输入与类别之间的对应关系
- 在回归任务里，数据提供输入与数值目标之间的对应关系
- 在语言模型里，数据提供历史 token 与下一个 token 之间的统计共现结构

最后一个例子尤其重要。

在语言模型里，数据表面上看只是很多文本。
但一旦被组织成训练样本，它就在持续告诉模型：

- 哪些前缀后面通常接什么
- 哪些词或子词更可能在什么上下文出现
- 哪些组合是自然的，哪些组合是不自然的

所以，数据之所以像“老师”，不是因为它会直接解释规则，而是因为：

> 它不断给模型制造可以比较的经验。

## 目标、损失和梯度为什么必须连在一起看

如果只有数据，没有目标，模型仍然不知道什么叫“更好”。

这意味着：

- 学习不是数据一来就自动发生
- 学习必须同时知道自己在朝哪个方向改进

这个“方向”就是目标。

在不同任务里，目标可以表现成不同形式：

- 预测正确类别
- 逼近某个连续数值
- 预测下一个 token 的条件分布

一旦目标被定义出来，训练系统才能开始比较：

- 当前输出和理想输出之间差多远

但“差多远”还不能直接用于更新。
它必须先被翻译成机器可操作的数值地形。

这就是损失函数存在的原因。

损失最重要的职责不是“给训练输出一个数字”，而是：

> 把任务层面的好坏翻译成优化层面可以操作的压力。

有了这层翻译，下一步自然就是：

> 如果我轻微改变一下参数，损失会往哪里走？

这就是梯度的语言。

梯度并不是为了炫数学存在的。
它的功能非常务实：

- 告诉你当前局部最敏感的方向
- 告诉你哪些参数的改变更影响目标
- 让“参数怎么改”变成一件有方向依据的事

因此，目标、损失和梯度最好永远一起理解，而不是拆开背定义。

## 所谓“学习”，本质上是一种反馈驱动的参数修正过程

如果把机器学习抽象到最本质的层面，它其实很像一个反馈系统。

模型从来不是：

- 看一眼数据
- 突然顿悟

而是：

- 做出当前判断
- 接收偏差信号
- 用偏差信号修正自己
- 再做下一次判断

也就是说，学习并不是一个静态定义，而是一个循环过程。

这个循环有四个核心环节：

- 当前模型
- 当前数据
- 当前偏差
- 当前更新

只要其中任何一环断了，学习就无法真正发生。

因此，很多“训练脚本能跑”但“模型学不到东西”的问题，本质上都是因为这条反馈链某个地方已经坏掉了。

## 为什么“学得更好”不是绝对概念，而是相对目标和分布的概念

机器学习里还有一个非常重要但常被忽视的事实：

> “更好”从来不是脱离任务和数据分布而独立存在的。

很多初学者会下意识把学习理解成：

- 模型越来越聪明

但“聪明”在机器学习里必须更具体地说：

- 对哪类输入更聪明
- 在什么目标下更聪明
- 相对于哪种评价方式更聪明

例如，一个模型可能：

- 在训练集上越来越好
- 但在验证集上没有同步提升

这意味着它变好了，但只是在某个很狭窄的意义上变好。

因此我们后面才会反复强调：

- 训练集表现
- 验证集表现
- 泛化能力

必须被区分开看。

## 机器学习为什么首先是一门统计学习，而不是逻辑推理

很多初学者最开始学机器学习时，仍然会保留一种传统编程直觉：

> 我是不是在给系统写规则？

机器学习和传统显式规则编程最重要的差别之一就在于：

- 规则编程依赖人明确写出行为逻辑
- 机器学习依赖模型从样本分布中逼近统计规律

也就是说，机器学习不是先知道规则，再执行。
它更像是：

> 先通过大量样本观察输入和输出之间反复出现的结构，然后用参数化函数去逼近这种结构。

这会直接带来几个结果。

第一，学习结果天然带概率色彩。
模型经常不是在做确定性演绎，而是在形成某种相对偏好或条件分布。

第二，数据分布极其关键。
模型学到的不是“世界本身”，而是训练数据分布里显露出来的模式。

第三，样本覆盖会直接影响能力边界。
如果某类模式几乎没在数据里出现，模型就很难可靠掌握它。

这也是为什么学习问题总要和数据分布一起理解，而不能只看模型结构。

## 模型到底是在“理解”还是在“拟合”

这是一个很容易带来哲学争论的问题。
在这套知识档案里，更务实的回答是：

> 从训练机制角度看，模型首先是在拟合一种输入到输出的统计结构。

这句话有两层价值。

第一，它避免了过早赋予模型人类式心理词汇。

第二，它更贴近训练系统真正做的事情：

- 用参数去逼近样本分布中的规律

当然，在某些复杂系统里，这种拟合会表现得非常像“理解”。
但如果你从学习机制入手，最好始终先站稳：

- 参数
- 目标
- 分布
- 更新

这四个更可分析的对象。

## 把这些话放到语言模型里，学习到底在学什么

到这里，可以把问题重新落到本项目真正关心的对象上：

> 语言模型到底在学什么？

最朴素也最准确的说法通常是：

> 它在学习：给定一段历史 token 序列，下一个 token 更可能是什么。

这句话比“它在学语言”更精确。

因为“学语言”太宽了。
而从训练机制上说，语言模型真正反复看到的是：

- 前缀
- 下一个 token

不断重复之后，模型逐渐学到的会包括：

- 常见词序模式
- 句法搭配
- 局部语义延续
- 文本风格偏好
- 更长距离的统计关联

但所有这些更高层现象，在训练时都不是直接作为“知识点”被塞进去的。
它们是：

> 从大量 next-token 预测任务中间接浮现出来的结构。

所以语言模型学习的底层任务仍然是：

- 条件分布学习

只是随着规模、数据和结构复杂度增加，这种条件分布会携带越来越丰富的语言规律。

## 为什么“预测下一个 token”看起来简单，却足以支撑复杂能力

初学者常常会有一个完全合理的疑问：

> 只是预测下一个 token，为什么最后会长出这么复杂的行为？

原因在于，这个任务虽然表面局部，但它反复作用在海量上下文上。

模型不是只预测一次下一个 token。
它是在大量不同前缀、不同风格、不同主题、不同长度的上下文中，不断学习：

- 什么在什么后面常出现
- 哪些长程依赖会影响下一个位置
- 哪些表面看似不同的上下文其实共享更深层的统计结构

因此，“预测下一个 token”之所以强，不是因为这个动作本身很神秘，而是因为：

> 当这个动作在海量分布上反复进行时，它会迫使模型压缩出许多对语言有用的内部规律。

这就是为什么一个看似很局部的目标，最终可以支撑远比它表面更复杂的能力。

## 学习为什么总带着不完全性和近似性

机器学习还有一个很重要的现实需要尽早接受：

> 模型几乎从来不是在获得某种完美规则，而是在有限数据、有限参数、有限计算和有限优化时间里做近似学习。

这意味着：

- 学到的规律可能不完整
- 某些模式可能偏差很大
- 不同初始化和训练路径可能得到不同局部结果
- 训练过程经常需要在资源和效果之间做折中

这并不是缺陷，而是现代机器学习的现实形态。

理解这一点，有助于你后面更平静地面对：

- loss 抖动
- 验证表现波动
- 生成质量不稳定
- 不同超参数带来的差异

因为你会明白：

学习从来不是“找到唯一正确答案”，而更像是在复杂空间里不断逼近更好的区域。

## 初学者最容易误解的三件事

第一，把学习误解成记忆。
这会让你低估泛化和验证的重要性。

第二，把学习误解成代码流程本身。
这会让你把“会写训练循环”和“理解学习机制”混为一谈。

第三，把学习误解成某个单一指标的变化。
这会让你过度依赖 loss，而忽略目标定义、数据分布和推理行为。

如果这三种误解不尽早拆掉，后面几乎所有进阶内容都会越学越累。

## 读完这一章之后，你应该能稳定回答什么

如果这一章真正起作用了，那么你至少应当开始能够回答下面这些问题：

- 为什么模型可以被看成参数化函数
- 为什么学习是参数在目标驱动下因数据而更新
- 为什么“学会”不是背下训练集答案
- 为什么 loss 下降只是学习证据的一部分
- 为什么机器学习首先是一种统计规律逼近，而不是规则手写
- 为什么语言模型本质上是在学条件分布，而不是直接背句子

如果这些问题你只能模糊点头，而不能用自己的话稳定讲出来，那么说明“学习是什么”这件事还没有真正站稳。

## 小结

这章最核心的结论可以浓缩成一句话：

> 机器学习不是让模型背下答案，而是让一个参数化函数在数据与目标提供的反馈下，通过反复更新参数，逐步学会一种对输入做出更合理输出的规则结构。

而对语言模型来说，这条主线会进一步具体化为：

> 在大量文本形成的前缀分布上，不断学习“给定历史，下一个 token 更可能是什么”。

只要这个认识真正站稳，后面的：

- 损失
- softmax
- 梯度
- Transformer
- 训练循环

就不再只是工具名，而会重新回到同一件事上：

> 一台模型究竟是怎样因为数据而逐步改变自己的。
