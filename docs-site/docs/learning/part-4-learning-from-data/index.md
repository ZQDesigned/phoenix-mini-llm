# 卷四 从数据到学习问题

> 本卷属于第二编“机器学习与神经网络”，负责先把原始世界改写成训练问题，再把后面的神经网络与优化讨论放到正确的问题边界里。

在真正开始神经网络之前，初学者最容易被跳过的一层，不是模型结构，而是问题结构。

很多人太早开始问：

- 模型怎么写
- loss 怎么定义
- 优化器怎么选
- 训练循环怎么跑

却没有先把另一件更靠前的事讲清楚：

> 你到底准备让模型学什么？这个“要学的东西”又是怎样从原始世界被压缩成一组可计算、可监督、可评估的训练对象？

这一卷就是专门处理这一步的。

它的地位看起来像过渡层，实际上更像地基层。

因为后面大量看似“模型出了问题”的现象，根源并不在模型，而在更早的地方：

- 样本切错了
- 输入和目标对错位了
- 数据拆分泄漏了
- shape 看似没问题，但语义维早就错了
- 任务本身就没有被定义成一个稳定的学习问题

如果这一步没站稳，训练流程越完整，误导反而越深。

## 为什么这一卷必须放在神经网络之前

很多教程会把机器学习讲成一条非常短的链：

1. 准备数据
2. 定义模型
3. 定义损失
4. 训练

这样的讲法省事，但它会掩盖一个关键事实：

> 模型学到的从来不是“世界本身”，而是你事先替它定义好的、可计算版本的世界。

也就是说，模型真正看到的不是：

- 一篇文章本身
- 一张图片本身
- 一段日志本身

而是你已经完成下列操作后的结果：

- 决定什么算一条样本
- 决定样本里哪些部分算输入
- 决定哪些部分算目标
- 决定这些对象如何编码成张量
- 决定评估时究竟比较什么

这意味着“开始训练”之前其实还有一项更根本的工作：

> 把原始材料重新组织成一个明确的学习问题。

而这正是这一卷的主题。

## 这一卷要解决的不是术语，而是边界

初学者常见的问题并不只是分不清几个名词。

更深的问题是他们分不清边界：

- 原始数据和训练样本的边界
- 输入和目标的边界
- 监督信号和任务目标的边界
- 物理存储结构和建模语义结构的边界
- 数据问题和模型问题的边界

一旦这些边界不清楚，后面很多现象都会被误判。

比如：

- 你以为模型欠拟合，实际上样本定义就不稳定
- 你以为 loss 有问题，实际上目标设计根本不对应任务
- 你以为 batch 维写对了，实际上每一维的语义已经错位

所以这一卷最重要的作用，不是“再补一点机器学习概念”，而是把学习问题的边界重新画清楚。

## 机器学习里的“问题”到底是什么

在日常语言里，我们会说：

- 我要做情感分析
- 我要做图像分类
- 我要训练一个聊天模型

这些说法对沟通已经够用了，但对训练还不够。

因为机器学习里的“问题”不能只是一句自然语言目标。
它必须被压缩成一组更严格的对象关系。

一个真正可训练的问题，至少要回答下面这些事：

- 输入对象是什么
- 输出对象是什么
- 监督信号从哪里来
- 一条样本怎样被切出来
- 训练时究竟比较什么
- 评估时究竟比较什么

如果这些问题没有被回答，那么你手里即使已经有海量数据，也还没有真正进入训练。

因此，更准确的表述不是：

> 我有数据，所以我能训练模型。

而是：

> 我已经把原始材料重写成一个明确的学习问题，所以模型才有可能开始学习。

## 原始世界与训练世界之间，隔着一层“样本化”

这是整卷最核心的观念之一。

原始数据可以是很多东西：

- 一本书
- 一篇文章
- 一张图片
- 一段代码仓库
- 一组表格记录
- 一条持续到来的日志流

这些对象都可能很重要，但它们还不是训练单位。

训练单位是样本，而样本不是天然存在的。

更准确地说：

> 样本是为了某个学习目标，从原始材料中切出来的一份局部对象，并且这份对象已经被赋予了输入、目标和监督角色。

这句话意味着三件事。

### 第一，样本不是自然单位，而是设计单位

同一份原始材料，可以根据不同目标被切成完全不同的样本。

同一篇文本可以变成：

- 句子级分类样本
- 问答配对样本
- 摘要输入输出对
- 语言模型的连续 token 预测样本

世界没变，学习问题变了。

### 第二，样本不是一段内容，而是一段带角色的内容

只截取一小段数据，并不自动构成训练样本。

你还必须知道：

- 哪些部分是输入
- 哪些部分是目标
- 哪些部分只是上下文
- 哪些部分应该被掩掉或忽略

### 第三，样本必须已经进入可计算形态

只在自然语言层面把目标说清楚，仍然不够。

如果样本还没有被翻译成：

- 序列
- 张量
- 标签
- 数值目标
- 掩码结构

那么它仍然没有真正进入训练系统。

## 为什么这一卷对语言模型尤其重要

在很多传统教学材料里，样本、特征、标签这些词经常拿图像分类举例。

这当然有帮助，但语言模型会把事情变得更微妙。

因为在语言模型里：

- 原始材料往往是长文本流
- 样本往往是从长流里切出来的固定长度窗口
- 输入和目标常常来自同一段序列，只是位置发生偏移
- “标签”不一定像分类任务那样是一个单独的类别列，而可能是整段右移后的 token 序列

这意味着如果读者没有在更一般的层面先理解“什么叫学习问题”，后面很容易把语言模型误会成一种特殊技巧集合，而不是一般机器学习问题在序列世界里的自然变体。

## 这一卷的三章分别在做什么

这一卷不追求章节数量多，而追求每一章都承担一个明确的认知任务。

### 第一章：机器学习到底在学什么

这一章先回答最朴素、但最经常被说得含糊的问题：

> 学习到底意味着什么？

它会解释：

- 为什么模型首先是参数化函数
- 为什么学习本质上是反馈驱动的参数修正
- 为什么 loss 的下降不自动等于真正学会
- 为什么机器学习从一开始就带着统计性质

### 第二章：样本、特征、标签、batch 与张量布局

这一章处理的是学习问题最容易混淆的对象层。

它会解释：

- 什么是一条样本
- 特征、标签、目标各自扮演什么角色
- batch 与 shape 为什么只有和语义绑定时才有意义
- 为什么“张量能跑”不等于“问题定义正确”

### 第三章：从线性模型到第一个神经网络

这一章是桥。

它负责把“问题定义”顺着一条连续路线，交给后面真正进入神经网络训练系统的那一卷。

它会帮助读者看见：

- 线性模型为何自然出现
- 线性模型为什么会遇到表达上限
- 神经网络并不是凭空发明出来的新世界，而是对前面问题的一次结构升级

## 这一卷读完之后，你应该能稳定回答什么

如果这一卷读稳，读者应该能够稳定解释下面这些问题：

- 为什么有数据并不等于已经定义好了训练问题
- 为什么样本是什么，本身就是建模设计的一部分
- 为什么输入和目标的划分会决定模型到底在学什么
- 为什么张量 shape 不能脱离语义单独理解
- 为什么许多训练失败其实应该先回到数据定义层排查

如果这些问题还答不稳，就不应该急着冲进后面的神经网络细节。

## 读这一卷时应该带着什么心态

这一卷不像后面的 Transformer 章节那样显眼，也不像训练与推理章节那样充满工程动作。

但它非常值得慢读。

更准确地说，这一卷是那种：

- 第一次读可能觉得“好像没有结构图那么刺激”
- 但后面每读一卷都会反复发现“原来这里早就埋过根”的内容

如果你愿意在这里多花一点时间，后面你会明显更不容易把：

- 数据问题误判成模型问题
- 问题定义误判成训练技巧问题
- 语义目标误判成纯 shape 问题

## 这一卷的一句话任务

如果只用一句话概括这一卷，它做的事情是：

> 在讨论模型怎样学习之前，先把“要学的究竟是什么”定义成一个稳定、可计算、可监督的对象。
