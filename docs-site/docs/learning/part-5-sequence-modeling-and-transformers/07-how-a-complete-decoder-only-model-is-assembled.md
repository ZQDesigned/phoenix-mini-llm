# 07. 一个完整 decoder-only 模型怎样组装

## 到这里终于可以把整台模型拼起来

前面几章我们已经分开理解了：

- token 与词表
- next-token prediction
- Attention
- causal mask
- 位置方法
- Transformer block

现在必须把这些零件重新装回同一台机器里。

这一章要回答的问题是：

> 一个真正可训练、可生成、可解释的小型 decoder-only 语言模型，整体数据流到底长什么样？

## 从外到内看一次完整路径

把细节先全部折叠起来，完整模型的最核心路径可以写成：

```text
token ids
-> embeddings
-> 位置方法
-> 多层 causal Transformer blocks
-> final norm
-> 输出头
-> logits
-> （训练时）loss
```

这条路径就是整台模型的骨架。

之后无论代码文件怎么拆、类名怎么起，本质上都在实现这条数据流。

## embedding 为什么是第一步

token id 本身只是编号。

它告诉你：

- 这是词表中的第几个条目

但它并不是一个可直接参与深层计算的表示。

所以第一步必须通过 embedding，把：

\[
[B, T]
\]

变成：

\[
[B, T, H]
\]

也就是说：

> 每个离散 token 被映射成一个连续向量。

从这一刻开始，模型才真正进入表示学习阶段。

## 位置方法为什么必须尽早进入

模型不能只知道：

- 这是什么 token

还必须知道：

- 它在序列的什么位置
- 它和其他位置的相对关系是什么

所以位置方法必须在模型主体很早就发挥作用。

不管具体是：

- 把位置向量加到 embedding 上
- 还是把位置信息注入注意力表示

其本质都是：

> 让后续 block 从第一轮开始就在“有顺序感”的表示上工作。

## 多层 block 是模型主体

embedding 和位置方法是把输入送进来，真正的大部分表示学习都发生在多层 block 里。

每一层 block 都会做两件大事：

- 让当前位置重新读取可见历史
- 让当前位置对读取后的信息做进一步加工

于是模型不是只“看一次上下文”，而是在很多层次上：

- 读
- 改写
- 再读
- 再改写

这就是深度的意义。

## final norm 为什么常常单独存在

很多 decoder-only 模型在所有 block 之后，还会有一层 final norm。

它的作用可以简单理解成：

> 在把最终隐藏状态送去做词表分类之前，再把整体表示整理到更适合输出头使用的尺度。

它不是最显眼的部件，但经常是一个合理且稳定的收口步骤。

## 输出头在做什么

经过多层 block 后，每个位置都有一个上下文感知的隐藏向量。

接下来模型要回答的问题是：

> 在当前位置条件下，词表里的每个 token 各有多大可能成为下一个 token？

于是输出头会把：

\[
[B, T, H]
\]

映射成：

\[
[B, T, V]
\]

其中 `V` 是词表大小。

这个结果就是 logits。

## 为什么输出头不是“最后随便接个线性层”

表面上看，它确实常常是一个线性投影。

但从系统角度看，它的意义非常重大，因为它在做：

> 从隐藏表示空间回到词表分类空间。

也就是说，它负责把模型内部学到的上下文表示，翻译回：

- 对整个词表的相对偏好

这也是为什么词表定义一变，输出头空间就跟着变。

## 为什么完整模型同时服务训练和推理

一个真正完整的模型主体，不应该只会做训练，也不应该只会做生成。

更准确地说，它应该是：

> 同一套表示主体，被两种不同外层协议调用。

### 训练时

- 输入一段 token
- 输出 logits
- 与目标对齐计算 loss

### 推理时

- 输入当前上下文
- 只关心最后一个位置的 logits
- 选出下一个 token
- 接回上下文继续循环

因此训练和推理最大的差别不在主体结构，而在：

- 外层循环
- 是否传入目标
- 是否需要缓存

## 为什么 tokenizer 也属于整模型定义

一台 decoder-only 模型看起来好像只是若干层张量运算，但它真正的边界还包括 tokenizer。

因为 tokenizer 决定了：

- 输入 id 对应什么 token
- 词表大小是多少
- 输出类别空间怎样解释

如果 tokenizer 变了，那么 embedding 和输出头的语义就一起变了。

所以完整模型不只包括：

- block
- norm
- head

也包括：

- tokenizer
- special token 约定
- 序列边界协议

## 为什么“小而完整”的完整性就体现在这里

对学习项目来说，一个小模型并不是参数少就算完成了。

真正的“完整”应该至少意味着：

- 文本能被正确 token 化
- token 能进入表示空间
- block 能做因果上下文建模
- 输出头能回到词表分布
- 训练能算出合理 loss
- 推理能按自回归方式继续生成

一旦这条链闭合，你手上的就不再是几个分散模块，而是一台真正能工作的语言模型。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> 一个完整 decoder-only 语言模型，是一条从 tokenizer 定义出的 token id 出发，经 embedding、位置方法和多层 causal Transformer block 形成上下文表示，再通过输出头回到词表分布，并同时被训练协议和推理协议调用的完整系统。
