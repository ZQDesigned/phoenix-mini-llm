# 05. 位置方法到底在补什么

## 这一章要完成的过渡

到上一章为止，卷八已经把 attention 的两个关键问题讲出来了。

第一，QKV 解决了：

> 模型怎样按内容去找历史中的相关信息？

第二，causal mask 解决了：

> 这种读取在语言模型里到底允许读到哪里？

如果读到这里，你很容易产生一个貌似合理、但实际上会把整个位置问题看轻的判断：

> 既然模型已经会按内容找信息，又知道不能看未来，那顺序问题是不是自然就有了？

答案是否定的。

因为“会找相关内容”和“知道哪些内容合法可见”，并不等于“知道这些内容在序列里怎样排列”。

换句话说，前两章分别解决了：

- 读取机制
- 读取合法性

而这一章要解决的是第三件独立的事：

> 序列几何。

这包括：

- 谁在前，谁在后
- 某个位置离当前位置多远
- 两个相同内容出现在不同位置时，为什么不应被当成完全相同的东西
- 某种关系是紧邻关系，还是跨很长距离的关系

所以本章不是在“加一个额外特征”。
它是在解释：

> 为什么 attention 就算已经拥有内容读取能力和因果合法性，仍然必须额外获得位置感，否则它对序列的理解会在根上不完整。

## 从最朴素的反例开始：内容一样，顺序一变，意义就变

位置问题最不应该从公式讲起，而应该先从语言本身的事实讲起。

看两个英语短句：

```text
dog bites man
man bites dog
```

它们几乎使用了同样的词，但顺序一换，事件中的施事和受事立刻对调。

中文里也有大量类似现象：

```text
我 不是 说 你 错 了
不是 我 说 你 错 了
```

词几乎相同，但语气焦点、责任归属、句子重心都发生了变化。

再比如：

```text
上海 飞 北京
北京 飞 上海
```

同样的两个城市名，谁在前谁在后，会直接改变出发地和目的地。

这些例子都在说明同一件事：

> 语言不是“出现了哪些内容”的问题，而是“这些内容以什么顺序、什么方向、什么邻接关系排列起来”的问题。

因此，一个只知道 token 内容、却不知道顺序结构的模型，即使知道词义，也会系统性地误读大量语言现象。

## QKV 和 causal mask 已经很强，但它们仍然不告诉模型“序列几何”

现在回到前两章建立的结构。

QKV 已经让模型可以根据当前需求，在上下文里检索相关信息。
这解决的是：

> 哪些位置在内容上可能与我当前的判断有关？

causal mask 已经让模型严格遵守自回归规则。
这解决的是：

> 当前时刻哪些位置根本没有资格成为候选来源？

但这两件事加起来，仍然没有直接回答下面这些问题：

- 两个都合法可见的位置，哪一个离我更近？
- 两个都出现过相同 token 的位置，为什么这次应该更看近处那个，而不是远处那个？
- 某个模式是“紧邻出现”，还是“隔了很多步再次出现”？
- 某个词出现在序列开头，和出现在序列结尾，为什么往往应当被模型区分？

这说明 attention 结构里至少有三类不同信息，不应互相混淆：

- 内容信息：谁像我现在要找的东西
- 合法性信息：谁可以被我看
- 几何信息：这些合法内容在序列中怎样排布

位置方法补上的，正是第三层。

## 为什么纯内容 attention 会对排列过于迟钝

这一点值得稍微说得理论一点。

attention 的核心比较是 query 与 key 的匹配。
如果没有额外位置线索，那么匹配发生的基础主要是：

> 表示内容本身。

这意味着结构天然更擅长回答：

- 哪些位置在语义或功能上相关
- 哪些位置像是在提供当前需要的内容

却不天然擅长回答：

- 这些相关位置距离当前位置有多远
- 它们之间的先后次序如何
- 相同内容在不同位置出现时，是否应该被赋予不同结构角色

在最极端的想象里，如果你只给模型一组内容向量，而完全不告诉它这些向量来自哪个位置，那么它更像是在面对：

> 一组可以被读取的内容项

而不是一个：

> 按顺序组织起来的序列

当然，decoder-only 的 causal mask 至少会提供一个粗糙的信息：右边未来不可见，左边过去可见。
但这仍然太粗。

它只能告诉模型：

- 谁在左边
- 谁在右边

却不能告诉模型：

- 左边第 1 个和左边第 100 个的区别
- 两个都在左边的位置，哪个更近
- 某种局部模式是否恰好发生在相邻位置

因此，如果没有额外位置方法，模型更像是在读一个“受左到右约束的内容集合”，而不是一个真正的几何序列。

## 位置方法到底在补哪三类信息

把位置问题拆开以后，你会发现位置方法并不是只补一种东西。
它至少在补三类彼此相关、但并不相同的信息。

第一类是绝对位置。

也就是：

> 这个 token 在整条序列里大概位于哪里？

例如，它在开头、中部还是结尾附近。
有时这很重要，因为序列不同区域常常承担不同功能。

第二类是相对距离。

也就是：

> 这个候选位置离当前位置到底有多远？

“就在左边一格”和“在左边一百格”虽然都属于合法历史，但结构意义显然完全不同。

第三类是相对方向。

在 decoder-only 设定里，未来天然被屏蔽，所以方向信息看上去似乎已经简单了很多。
但在更一般的序列建模里，方向本身仍然重要。
即使只看 decoder-only，模型也常常仍需要知道：

> 这是更近的左侧，还是更远的左侧？

因此，位置方法真正补的不是一句含糊的“位置特征”。
它补的是：

> 让内容关系重新落回序列几何中的那套坐标感。

## 为什么“第几个位置”和“离我多远”不是同一回事

初学者经常会把绝对位置和相对距离混在一起。
这会让很多后面的设计差异显得莫名其妙。

但这两者其实是两种完全不同的结构视角。

绝对位置更像全局坐标。

它回答的是：

> 这个 token 在整段中的编号或区域位置是什么？

相对距离更像关系坐标。

它回答的是：

> 当前位置和那个候选位置之间相隔多远？

这两个视角在语言里都可能有价值。

例如，句首和句尾往往承担不同功能，这更像绝对位置问题。

而“主语通常离谓语不太远”“某个括号里的补充成分只影响附近结构”，这更像相对距离问题。

一旦把这两类问题分清，你就会更容易理解为什么位置方法会分化出不同路线，而不是所有方案都长一个样子。

## 最朴素的位置方案：给每个位置一个绝对位置向量

最直观的位置方法是：

> 为序列中的每个位置准备一份位置表示，再把它与 token 表示结合起来。

如果某个位置的 token embedding 是 `x_t`，它的位置向量是 `p_t`，那么最简单的写法就是：

\[
h_t = x_t + p_t
\]

也就是说，在进入后续层之前，当前位置先把“我是什么内容”和“我位于哪里”融合到同一份表示里。

这是很多位置方法最经典的起点。

它的优点非常明显：

- 思路直观
- 易于实现
- 可以在模型一开始就把内容与位置绑定起来

但它真正重要的地方不是“加了个向量”。
而是：

> 它让同样内容的 token，在不同位置上拥有不同的初始表示。

这就已经打破了“只看内容”的结构限制。

## 为什么常见做法是“相加”，而不是“拼接”

看到 `x_t + p_t`，很多人会问：

> 为什么不是把内容和位置拼接起来，而是直接相加？

这个问题问得很好，因为它能帮你理解位置方法到底想嵌入到哪里。

相加的一个重要含义是：

> 位置不是一个外挂字段，而是直接进入内容表示空间，与内容一起被后续层共同处理。

这样做有几个好处。

第一，维度保持不变。
如果每层都以 `d_model` 维处理表示，那么相加不会改变后续结构的形状设计。

第二，内容与位置从一开始就在同一表示空间里融合。
后面的线性投影、注意力、前馈网络可以直接在融合后的表示上工作。

第三，工程实现足够简单。
位置方法本来就是整个模型每一步都会使用的基础设施，越基础的东西，越需要简单稳定。

当然，相加并不是逻辑上唯一可能的方案。
但它之所以经典，不只是因为“省事”，更因为它让位置进入了主表示流，而不是留在外围当注释。

## 绝对位置方法至少解决了什么问题

一旦有了绝对位置向量，模型最起码不再把“同一个 token 出现在不同位置”当成完全相同的输入事件。

例如，同一个逗号出现在句首附近和句尾附近，功能往往不同。
同一个“他”出现在一段对话前半段和后半段，可能也承载不同的指代关系。

绝对位置方法至少建立了这样一个能力：

> 模型可以把“内容相同但出现位置不同”的情况，区分成不同表示状态。

这是从“词袋化”走向“序列化”的第一步。

## 为什么绝对位置方法并不能解决全部问题

绝对位置方法虽然必要，但它很快就会暴露出自己的局限。

第一，它更像编号，不够像关系。

模型当然知道“你在第 17 个位置，他在第 24 个位置”，但这并不等于它天然知道“你们相距 7 格”在结构上意味着什么。

第二，许多绝对位置方案天生依赖最大长度设定。

如果你为每个位置都单独学习一个 embedding，那么序列可支持的最大长度通常要提前决定。
这会让外推到更长上下文时变得不自然。

第三，语言里的很多规律其实更关心相对关系，而不是绝对编号。

比如：

- 某个修饰语离中心词多远
- 两次出现的实体之间隔了多少内容
- 某个闭合符号距离它对应的开启符号有多远

这些问题看上去更像关系问题，而不是全局编号问题。

所以绝对位置是非常重要的一步，但它还不是终点。

## 正弦位置编码与学习型绝对位置，本质差别在哪里

绝对位置方法内部也并不只有一种实现。

一类典型做法是给每个位置直接学习一份位置 embedding。
这很直观：

> 第 1 个位置一份向量，第 2 个位置一份向量，依次类推。

另一类经典做法是正弦位置编码。
它不是为每个位置都学习独立参数，而是用一组确定的周期函数，把位置映射成一个多频率组合。

对初学者来说，最重要的不是一开始背正弦公式，而是先理解它想解决什么。

它想解决的是：

- 不必为每个位置单独学习参数
- 不同位置之间保留连续结构
- 更容易让模型利用位置之间的规律性，而不是把每个位置纯粹看成独立编号

所以正弦位置编码的价值，不在于“它是三角函数”本身。
真正有价值的是：

> 它把位置组织成一种有规律的连续模式，而不是一组彼此孤立的位置 ID。

学习型绝对位置 embedding 则更偏向：

> 让模型自己决定每个位置该长成什么样。

两者的差别，不只是“一个固定，一个可学习”。
更深的差别是：

- 一个更强调规则结构
- 一个更强调数据驱动适配

## 为什么相对位置往往更贴近语言里的很多规律

当你继续追问语言中的结构依赖时，会越来越自然地发现：

很多时候，我们真正在意的并不是“你在第几位”，而是“你离我多远”。

例如，局部搭配、短语边界、就近修饰、括号闭合、相邻格式标记，这些现象都更关心局部距离。

同样地，长程依赖也常常以“相隔了很远，但仍需要对齐”的方式出现。

所以相对位置之所以重要，是因为它更直接回答了一个 attention 非常关心的问题：

> 当前 query 在比较候选位置时，应不应该把距离本身也纳入判断？

这会让模型不只是知道“这个内容与我相关”，还知道“这个相关内容离我多近、多远、以怎样的距离关系存在”。

因此，相对位置方法通常更贴近“关系建模”的感觉，而不是“全局编号”的感觉。

## 为什么 RoPE 会反复出现

走到这里，现代 decoder-only 模型里最常被提到的位置方法之一，就会自然登场：RoPE。

很多人第一次听到 RoPE，会先记住“旋转位置编码”这个名字，然后开始把注意力全放在旋转这两个字上。
这其实容易抓错重点。

RoPE 真正强的地方不是“用了旋转”本身，而是：

> 它把位置信息直接写进了 query 与 key 的匹配关系里。

前面的绝对位置相加方案，更像是：

> 先把位置融合进输入表示，再由后续网络间接利用。

而 RoPE 的想法更激进：

> 既然 attention 的核心就在 query 和 key 的匹配，那不如直接让这个匹配过程本身带上位置结构。

这就是为什么它在现代注意力模型里非常有吸引力。

## 用直观的话理解 RoPE：不是“加位置”，而是“让比较本身带位置”

如果不先陷进公式，RoPE 可以先这样理解：

> 它不是简单地给每个位置贴一张位置标签，而是让不同位置的 query 和 key 在比较时自动体现彼此的相对位移关系。

这件事特别关键。

因为 attention 的核心不是位置单独存在，而是：

> 当前位置与候选位置在做匹配时，位置差异应当怎样影响这个匹配？

RoPE 给出的回答是：

> 通过对 query 和 key 做与位置相关的变换，让它们的点积结果天然携带相对位移信息。

于是位置不再只是外部元数据，而是直接进入了 attention 的配对逻辑。

## 一个低维直觉：为什么“旋转”能表达相对关系

要建立 RoPE 的直觉，不必一开始就上高维公式。
先想二维平面上的向量旋转就够了。

假设你有两个二维向量。
如果把它们分别按不同角度旋转，再去看它们之间的关系，你会发现：

> 它们最终的相对对齐程度，不只取决于内容方向，也会取决于两个旋转角之间的差。

这个“角度差”，正好和相对位移有天然对应关系。

RoPE 正是把这种思想推广到高维表示空间里。
它不是为了做几何表演，而是为了让：

> query-key 点积这种最核心的 attention 比较操作，本身就能感受到相对位置差异。

这就是为什么很多现代模型会更偏爱它。

## 为什么把位置写进匹配过程是个强想法

一旦你理解 RoPE 的位置，就会发现它抓住了 attention 的核心动脉。

因为在 attention 里，真正决定“看谁更多一点”的，不是 value，也不是最终输出，而是 query 与 key 的匹配分数。

如果位置只是在更早的输入表示里出现，那么模型当然有机会间接学到位置效应，但这个效应是绕了一圈才进入匹配过程。

而把位置直接写进匹配过程，相当于在最关键的地方发问：

> 当我判断这个候选位置与当前位置是否相关时，是否应该把你离我多远、处于什么相对位移，直接算进去？

这会让位置不再是附属说明，而是成为 attention 关系的一部分。

这就是一个很强的设计思想。

## 为什么长上下文时代会特别关心位置方法

在短上下文模型里，位置方法已经重要。
到了长上下文模型里，它会变得更加敏感。

原因很直接：

上下文一长，模型就更频繁地遇到下面这些问题：

- 同样内容在远近不同的位置重复出现
- 真正重要的线索离当前位置很远
- 局部关系和长程关系需要同时存在
- 训练长度和推理长度可能不完全一致

此时，位置方法就不再只是“有总比没有好”。
它会直接影响：

- 模型如何区分近邻和远距线索
- 长距离匹配是否稳定
- 更长上下文上的外推是否自然

因此，长上下文时代大家对位置方法格外敏感，并不是因为它突然成了热点名词，而是因为：

> 序列一旦拉长，几何问题会被放大得更明显。

## 位置方法和 causal mask 的职责边界一定要分清

讲到这里，必须再把一个特别容易混淆的点钉死。

causal mask 和位置方法都与“顺序”有关，但它们解决的根本不是同一件事。

causal mask 负责的是：

> 当前是否有权访问某个位置。

它给出的答案是合法性边界。

位置方法负责的是：

> 对于那些已经合法可见的位置，模型怎样区分它们的先后、远近和排列关系。

它给出的答案是几何结构。

因此，不要把 mask 当成位置方法的替代品。
mask 只是告诉模型“哪些位置不能看”。
它并没有充分告诉模型“剩下这些能看的位置彼此怎样排列”。

## 位置方法和多头注意力之间是什么关系

这一点也值得说明一下。

多头注意力允许模型并行学习多种关系视角。
一旦有了位置方法，不同头就不只是在内容空间里分工，也往往会在位置结构上形成不同偏好。

有的头可能更偏局部模式。
有的头可能更偏远距依赖。
有的头可能对句首、句尾或某类结构边界更敏感。

因此，位置方法不是和多头并列的两个功能块。
更准确的说法是：

> 位置方法在为所有头提供序列几何，而不同头可以在这套几何上学出不同的读取策略。

所以当我们说某些头“更关注近邻”或“更善于追踪长距离关系”时，背后通常都离不开位置结构的支持。

## 如果没有位置方法，模型最容易在哪些地方吃亏

把问题反过来问，通常更有帮助。

如果没有位置方法，模型最容易在哪些地方出问题？

首先，它会对同样内容在不同位置的差别变得迟钝。

其次，它会更难稳当地表达局部邻接结构。
例如两个 token 紧挨着出现，与中间隔了很多 token 再出现，结构意义本来差别很大。

再次，它会更难把“近处线索”和“远处线索”区分成不同几何角色。

最后，它在长上下文和外推场景下通常会更脆弱。
因为一旦距离和排列本身无法稳定进入模型关系，序列一拉长，问题就会被放大。

所以位置方法不是“让模型更精致”的小改良。
它是在弥补 attention 作为内容读取机制时天生缺失的一类结构感。

## 一个更稳的总理解：位置方法补的是“几何”，不是“语义”

到这里，可以把整章压成一句特别稳的话：

> QKV 负责内容匹配，causal mask 负责合法可见，位置方法负责序列几何。

这句话非常值得记住。

因为它会立刻帮你拆掉很多后续混淆。

例如：

- 为什么 causal mask 不能替代位置方法
- 为什么位置方法不是在补 token 语义
- 为什么绝对位置、相对位置、RoPE 虽然做法不同，却都在试图把几何重新接回 attention

一旦你把位置方法理解成“给 token 加一个额外属性”，很容易把它看轻。
而一旦你把它理解成“给 attention 补几何”，它的必要性就会非常自然。

## 本章和前后章节怎样接起来

上一章解决的是：

> 模型已经会读了，但还必须守住“只能读合法历史”的边界。

这一章解决的是：

> 当合法历史已经确定以后，模型怎样理解这些历史在序列中的几何关系？

下一章会继续解决：

> 一旦内容读取、因果约束和位置几何都具备了，为什么这些模块能被反复堆叠成稳定的 Transformer block？

所以本章在卷八里的角色非常清楚：

它不是附录，也不是补充知识。
它是把 attention 从“会按内容读”推进到“会在真正的序列空间里读”的关键一章。

## 常见误区

### 误区一：attention 已经会比较相关性，所以自然也知道顺序

不对。

内容相关性和序列几何是两回事。
attention 天然擅长内容匹配，但不天然知道排列关系。

### 误区二：causal mask 已经提供了方向，所以位置方法可有可无

不对。

mask 只给出了合法性边界，没有充分给出距离、邻接和相对排列结构。

### 误区三：位置方法是在补 token 的语义

不准确。

位置方法补的是几何信息，而不是词义本身。

### 误区四：绝对位置和相对位置只是两种写法，意义差不多

不对。

绝对位置更偏全局坐标，相对位置更偏关系结构，它们回答的问题本来就不同。

### 误区五：RoPE 之所以流行，只是因为某些大模型默认用了它

不对。

它受重视的根本原因，是它把位置直接写进了 query-key 匹配过程，而这正好卡在 attention 的核心位置。

### 误区六：位置方法只是长上下文模型才需要关心的事情

不对。

长上下文会放大它的重要性，但任何真正的序列建模从一开始就需要位置感。

## 这一章真正要记住的核心句子

如果你只记住本章八句话，应该记住下面这些。

1. attention 会按内容找相关信息，causal mask 会规定合法可见性，但两者都不足以单独提供序列几何。  
2. 位置方法补上的不是“额外小特征”，而是语言模型理解顺序、距离和排列关系所必需的几何信息。  
3. 绝对位置回答“我在整段中大概位于哪里”，相对位置回答“我离你有多远、以什么关系存在”。  
4. 最朴素的位置方法，是把内容表示与位置表示融合起来，让同样内容在不同位置上不再拥有完全相同的状态。  
5. 绝对位置方法很重要，但许多语言规律更关心相对距离和关系结构。  
6. RoPE 的关键不是“旋转”这个表面动作，而是把位置信息直接写进 query-key 匹配过程。  
7. causal mask 负责合法性，位置方法负责几何，这两者不是替代关系。  
8. 上下文越长，位置方法越会直接影响模型如何区分近邻与远距线索，以及如何在更长序列上保持稳定。

4. 为什么说 `x_t + p_t` 的意义不只是“多加一个向量”，而是让内容和位置从一开始就在同一表示空间里融合？

6. 用自己的语言解释：RoPE 为什么可以被理解成“把位置写进比较过程”，而不是“单纯给输入贴标签”？  
7. 为什么长上下文模型会比短上下文模型更敏感于位置方法的设计？
