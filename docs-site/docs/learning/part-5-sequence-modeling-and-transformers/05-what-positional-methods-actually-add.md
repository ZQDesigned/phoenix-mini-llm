# 05. 位置方法到底在补什么

## 为什么 Attention 还不够

到这里为止，你已经知道：

- Attention 能让当前位置按内容回查可见历史
- Q/K/V 和权重分配让这种回查变成可学习机制
- causal mask 保证模型不会偷看未来

但仍然有一个关键问题没有解决：

> 如果只给模型一串内容表示，而不告诉它顺序，它怎么区分“同样的 token 集合，只是前后次序不同”这种情况？

这就是位置方法必须出现的原因。

## 内容相同，不代表序列相同

设想下面两句话：

```text
dog bites man
man bites dog
```

它们包含的词几乎相同，但顺序变化让含义完全不同。

这说明语言不是“词袋”，而是一条有强顺序结构的序列。

如果模型没有办法感知：

- 谁在前
- 谁在后
- 两个位置相差多远

那么它就很难可靠地区分大量关键语言现象。

## Attention 为什么天然不自带顺序

Attention 本身做的事情是：

> 根据当前位置的 query，与各位置 key 比较相关性，再聚合 value。

这里最直接的判断依据是内容表示之间的匹配。

这意味着如果你完全不给位置信息，那么模型在很多情况下看到的只是：

> 一组内容向量彼此相关或不相关。

它并不会天然知道：

- 某个位置是不是在我前面 3 格
- 另一个位置是不是在我前面 30 格
- 两个完全一样的 token 谁更靠前

所以位置方法不是锦上添花，而是在补 Attention 原本没有的维度。

## 位置方法真正补的是哪类信息

位置方法补的不是语义本身，而是序列结构信息。

最核心的通常包括：

- 绝对位置：这是第几个位置
- 相对位置：它离我多远
- 方向关系：它在我左边还是右边

对自回归语言模型来说，右边未来位置虽然不会被访问，但“左边多远”仍然很重要。

因为：

- 近邻依赖和远程依赖的模式不同
- 某些结构对距离敏感
- 模型需要知道当前匹配的不只是“谁相关”，还有“它在多远处相关”

## 为什么绝对位置方法很直观

最朴素的办法就是：

> 给序列中每个位置都提供一份专属位置表示。

于是模型除了知道某个 token 是什么，还知道：

- 它在第 0 位
- 第 1 位
- 第 2 位

这种方式非常容易理解：

- token embedding 负责内容
- 位置表示负责顺序

它的优点是直观、实现简单。缺点是它更强调“编号位置”，而不一定最自然地表达“相对距离关系”。

## 为什么相对位置关系经常更符合语言需要

在很多语言现象里，模型真正关心的不一定是：

> 这个 token 是全局第 173 位。

更常关心的是：

> 它离我有多远，它在我前面 2 格还是 20 格。

因为很多依赖强度本来就和相对距离有关。

例如：

- 最近的修饰词往往更相关
- 很远处的信息虽然重要，但通常属于另一类依赖

因此现代很多方法会更强调把相对位置关系交给模型使用。

## RoPE 为什么会反复出现

RoPE 常被介绍成一种“旋转位置编码”，听起来容易让人一上来就陷进公式。

对当前阶段，更有价值的理解是：

> 它不是在额外塞一份位置向量，而是在 Attention 使用的表示里直接注入相对位置信息。

这使得模型在比较相关性时，天然能同时考虑：

- 内容相似性
- 相对位置关系

所以 RoPE 之所以流行，不是因为名字新，而是因为它在许多 decoder-only 场景里提供了很自然的位置建模方式。

## 位置方法和 causal mask 解决的是不同问题

这两个概念很容易被初学者混在一起。

### causal mask

解决的是：

> 哪些位置能不能看。

### 位置方法

解决的是：

> 即使能看，这些位置在序列中的先后与距离关系怎样被表示出来。

一个是可见性约束，一个是顺序信息注入。

两者都重要，但职责完全不同。

## 为什么位置方法不该被当成“可选增强”

如果完全没有位置方法，模型当然仍然能做一些统计拟合，但它在大量顺序敏感任务上会明显吃亏。

因为它只能依赖：

- token 内容
- 其他层间接学出的某些弱顺序线索

而语言中的很多核心现象，本来就是顺序驱动的。

所以在一个真正可用的 Transformer 语言模型里，位置方法不是“有更好，没有也能凑合”的组件，而是：

> 让内容建模真正落在序列建模上的必要部件。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> Attention 负责决定“该看哪里”，位置方法负责告诉模型“这些位置在序列中如何排列以及相距多远”；没有位置方法，模型就难以把内容相关性和顺序结构稳定结合起来。
