# 03. Query、Key、Value 与加权读取

## 这一章要完成的过渡

上一章已经把 attention 的问题背景讲出来了。

我们已经知道，序列建模真正困难的地方，不只是历史很多，也不是输入很长，而是当前位置必须能够在一大段历史里按需寻找信息。

它有时需要最近的局部搭配。
有时需要很远以前出现过的某个人名、代词先行词、定义过的对象或尚未闭合的句法结构。
还有时需要把分散在多个位置上的线索同时拉回来，形成一次新的判断。

只要你接受这一点，就会立刻发现：

> attention 首先不是“算一个相似度矩阵”，而是一套上下文读取系统。

但说到这里还不够。
因为“读取系统”仍然是抽象词。
真正关键的问题是：

> 一次内容驱动的读取，怎样被写成神经网络可以学习、可以并行计算、可以端到端反向传播的张量过程？

这一章就是在做这件事。

它要把上一章留下的抽象需求，压成一套正式、稳定、可计算的结构语言。
这套语言就是 `Query`、`Key`、`Value`。

因此，这一章不应被读成“终于开始讲 QKV 公式了”。
更准确地说，它是在回答：

> 为什么 attention 最终会长成 QKV 这种分工，而不是别的样子？

如果这一点讲透，后面的点积、缩放、softmax、多头注意力，都会显得自然很多。
如果这一点没有讲透，那么 QKV 很容易退化成三个需要背下来的缩写。

## 从“能看历史”到“会读历史”

要真正理解 QKV，第一步不是背定义，而是先把“读历史”这件事拆开。

假设当前模型已经处理到序列中的某个位置。
这个位置并不只是被动接收一段旧信息，而是在做一件主动的事：

> 它希望根据自己当前的状态，去历史里找一些此刻最有帮助的内容。

这句话里至少包含了四个动作。

第一，当前位置必须先形成一种需求。
它要表达的不是“我是谁”，而是“我现在想找什么”。

第二，历史中的每个候选位置必须暴露出某种可以被比较的特征。
否则当前位置无法判断自己应不应该参考它。

第三，当前位置必须用一套规则，去比较“我现在想找什么”和“各个历史位置提供了什么匹配线索”之间的关系。

第四，一旦比较完成，模型还需要真正把信息读回来。
这个“读回来”不能只是输出一个索引号，也不能只是说“第七个位置最相关”，而必须形成一个新的向量，写回当前表示流中，供后面的层继续使用。

这四步看似朴素，但已经说明一个非常重要的事实：

> attention 不是在做一次单点选择，而是在做一次带检索语义、带聚合语义的软读取。

只要是软读取，就意味着模型不是粗暴地拷贝某个旧位置。
它更像是在说：

> 我此刻最关心哪些历史位置，以及这些位置分别应该向我贡献多少内容。

这就是 QKV 真正生长出来的地方。

## 为什么一次读取天然会分裂成三种角色

很多初学者第一次看到 QKV，都会觉得这三个名字像是人为发明出来的复杂度。
他们会非常自然地问：

> 为什么每个位置不能只有一个向量，然后大家直接拿这些向量互相比较、互相读取？

这个疑问非常合理，而且恰恰打中了本章最核心的一点。

如果每个位置只有一份统一表示，那么同一个向量就必须同时承担三种完全不同的职责：

- 表达当前位置当前到底想找什么
- 暴露某个历史位置有哪些特征值得被别人匹配
- 在匹配发生之后，提供真正应该被读回来的内容

这三件事彼此相关，但并不是同一件事。

更准确地说，它们分别面向三种不同的关系：

- 面向“发起读取”的关系
- 面向“被比较”的关系
- 面向“被读回”的关系

如果把它们硬压成一个向量，模型当然仍有可能学到某些可用策略，但表达自由度会被明显压缩。

原因不难理解。

一个位置之所以容易被找到，未必是因为它完整保留了所有有用内容。
它也许只需要暴露几个很适合被匹配的方向。

反过来，一个位置真正应该贡献给当前计算的内容，也未必就是“拿来做匹配”的那几个方向本身。
某些方向很适合作为检索标签，却不一定适合作为被混合回来的内容载荷。

而当前位置此刻要找什么，也未必等于“我当前完整的全部状态”。
它更像是：

> 从我当前完整状态里投影出来的一种检索意图。

于是，三种角色就会自然分离：

- 我现在想找什么
- 你可以怎样被我找到
- 如果我找到你，你真正该给我什么

把这三句话分别命名以后，QKV 就出现了：

- `Query` 是当前读取需求
- `Key` 是候选位置暴露出的可匹配特征
- `Value` 是候选位置真正提供的内容表示

所以 QKV 不是“为了复杂而复杂”。
它是在给一次可训练的软检索分角色。

## 一个稳定类比：检索系统、目录标签与正文内容

为了让这三个角色变得更直观，可以先暂时离开神经网络，想一个足够接近的类比。

假设你在图书馆里找资料。

这个过程里其实天然就有三类东西：

- 你脑子里现在的问题
- 每本书对外暴露的题目、关键词、分类号和目录标签
- 书里真正值得阅读的正文内容

它们显然不是同一个对象。

你脑子里的问题，决定了你现在想找什么。
这很像 `Query`。

书的标题、分类与标签，决定了它怎样被别人搜到。
这很像 `Key`。

而你最终真正读回来的，是书里的正文内容，而不是目录标签本身。
这很像 `Value`。

这个类比不是为了把 attention 讲成搜索引擎，而是为了建立一个特别稳的直觉：

> 一次好的读取，通常都要求“查询语义”“可匹配接口”“真实内容”三者分离。

只要这个直觉站稳，你后面就不会把 QKV 当成三个神秘缩写，而会把它看成一次读取过程里的三种职责。

## Query、Key、Value 各自到底在表达什么

现在可以分别把三种角色讲细一点。

### Query：当前位置此刻的读取意图

最简洁的说法是：

> Query 是当前位置、当前层、当前时刻所形成的一种检索需求向量。

这句话里每个限定词都很重要。

它属于当前位置，意味着序列中的不同位置不会共享同一个 query。
每个位置都必须根据自己当前所处的上下文状态，形成“我现在要找什么”的判断。

它属于当前层，意味着同一个 token 在不同层里可以发出完全不同的读取需求。
浅层可能更关心局部搭配和表层关系，深层可能更关心实体延续、语义角色或段落级主题。

它属于当前时刻，意味着 query 不是一个静态标签。
它不是某个 token 永远固定携带的一句自然语言问题。
它是当前位置在这一层、这一轮计算里，根据当前隐藏状态动态长出来的检索方向。

所以 query 不应该被理解成人类可读的问题句子。
它真正表达的是：

> 站在我现在的表示位置，我希望从上下文里再补进哪类特征。

### Key：候选位置暴露出来的可匹配接口

`Key` 的核心不是“这个位置有多重要”，而是：

> 如果别人来找信息，他们应该根据我的哪些方向判断我适不适合被参考？

也就是说，key 面向的是“被检索”。

它不是对某个位置完整内容的全盘表达，也不是一个固定的全局重要性分数。
它更像一个匹配接口。

同一个位置对不同 query 的价值可以完全不同。
某个历史位置对当前 query 也许极其重要，对另一个 query 却几乎没用。
因此，attention 里的相关性不是“这个位置本身有多重要”，而是：

> 在当前这个 query 面前，它的 key 是否刚好对上了需要。

只要把这一点分清，就不容易把 key 误学成“注意力分数的来源标签”。
真正起作用的不是 key 自己，而是 query 与 key 之间的关系。

### Value：被关注之后真正读回来的内容

`Value` 是三者里最容易被轻视、但实际非常关键的一环。

很多入门讲解会把大部分注意力放在“怎么打分”上，于是 value 看起来像最后顺手乘一下的尾声。
这会造成很大误解。

attention 的真正输出不是 key 的加权和，而是 value 的加权和。
这意味着：

> query 决定你想找什么，key 决定谁更像你在找的对象，而 value 决定你最终真正拿回来的内容到底是什么。

因此，value 更接近正文内容，而不是检索索引。

一个位置完全可能用一套较紧凑的匹配特征来暴露自己，却用另一套更丰富、更适合被写回当前流的表示来充当 value。
这正是 key 和 value 分离的深层好处之一。

## 为什么三者都来自同一份隐藏状态

到这里又会出现第二个经典疑问：

> 如果 query、key、value 职责差别这么大，它们为什么通常都从同一份输入表示里长出来？

答案是：

> 因为同一个位置确实同时拥有“发起查询”“被别人匹配”“提供内容”这三种潜在能力，只是这三种能力需要被投影到不同角色空间中。

在标准 self-attention 里，某一层的输入通常是一份隐藏状态矩阵：

\[
H \in \mathbb{R}^{T \times d_{\text{model}}}
\]

其中 `T` 是序列长度，`d_model` 是模型隐藏维度。

接下来，模型会用三组不同的可学习参数，把同一份 `H` 投影成三种角色空间：

\[
Q = H W_Q,\quad K = H W_K,\quad V = H W_V
\]

这里非常值得停一下。

这说明 QKV 不是天上掉下来的三种人工特征，也不是预处理阶段写死的语法标签。
它们都是：

> 当前层在当前任务压力下，从同一份隐藏表示中学出来的三种角色投影。

同一个位置当然还是那个位置。
只是当它要扮演“我现在要找什么”这个角色时，它会被投影到 query 空间。
当它要扮演“我怎样被别人比较”这个角色时，它会被投影到 key 空间。
当它要扮演“我被选中后要贡献什么内容”这个角色时，它会被投影到 value 空间。

所以“三者同源、角色分化”是理解 self-attention 的一个特别稳的说法。

## 为什么必须用三组不同的投影，而不是直接复用同一个空间

如果三者都直接等于 `H`，会发生什么？

本质上，模型会被迫在同一个表示空间里同时完成三件事：

- 把当前需求表达出来
- 把候选接口表达出来
- 把内容本身表达出来

这并非逻辑上完全不可行，但会带来一个很强的耦合：

> 哪些方向适合做匹配，哪些方向适合做内容混合，哪些方向适合做查询，这三类需求会被迫互相绑死。

而真实的语言建模往往需要更大的自由度。

例如，某些方向非常适合表达“这个位置和代词解析有关”，于是适合进入 key。
但真正被读回来时，当前位置也许需要的不只是这个“可匹配标签”，而是一组更丰富的内容方向，它们更适合进入 value。

再例如，当前位置此刻的 query 也许更关心“我缺少哪类条件”，而不是“我完整地是什么”。
这也说明 query 空间和原始隐藏空间不应该被粗暴视为同一对象。

所以三组投影的本质作用不是机械地把矩阵乘三遍。
它是在给模型表达自由：

> 让检索需求、匹配接口、内容载荷分别在最适合自己的坐标系里被组织。

## 一次 attention 前向到底发生了什么

把角色分工说清之后，我们就可以把一次 attention 前向写成一条连续的过程。

假设当前位置是第 `t` 个位置。
它当前拥有一份隐藏表示 `h_t`。
历史上每个可见位置 `i` 也都拥有自己的隐藏表示 `h_i`。

那么一次读取会发生下面四步。

第一步，当前位置用自己的隐藏状态生成 query：

\[
q_t = h_t W_Q
\]

这一步相当于说：

> 我此刻在找什么？

第二步，所有候选位置各自生成自己的 key 和 value：

\[
k_i = h_i W_K,\quad v_i = h_i W_V
\]

这一步相当于说：

> 我怎样被别人找到？如果被找到，我又该贡献什么？

第三步，当前位置用 `q_t` 去和每个 `k_i` 做匹配比较，得到一组相关性分数：

\[
s_{t,i} = q_t \cdot k_i
\]

如果采用标准缩放点积注意力，则还会除以 \(\sqrt{d_k}\)：

\[
s_{t,i} = \frac{q_t \cdot k_i}{\sqrt{d_k}}
\]

第四步，把这一行分数经过 softmax 变成权重，再对所有 `v_i` 做加权和：

\[
\alpha_{t,i} = \mathrm{softmax}(s_{t,i}),\qquad
c_t = \sum_i \alpha_{t,i} v_i
\]

最后得到的 `c_t`，就是当前位置从上下文里按需读回来的新内容摘要。

如果把这条链压缩成一句话，就是：

> Query 决定找什么，Key 决定谁匹配，Value 决定最终读回什么，softmax 决定每个人贡献多少。

## 点积为什么会成为一个自然的评分方式

现在我们来回答 attention 里第一个最常见的公式问题：

> 为什么 query 和 key 之间常常用点积打分？

原因首先不在于“论文就是这么写的”，而在于点积本身就很适合表达一种匹配关系。

如果你还记得前面数学卷的几何直觉，点积和向量方向一致性、对齐程度、相似性有非常自然的联系。
当 `q_t` 和 `k_i` 在某些方向上高度对齐时，点积会变大；
当它们方向不一致时，点积会变小，甚至变成负数。

这恰好符合 attention 的需要。
因为 attention 并不需要一个绝对重要性标签。
它只需要一个东西来回答：

> 在当前位置当前这个需求面前，哪个候选位置更像我现在要找的对象？

点积正好能给出这样的相对比较。

当然，从概念上说，相关性不一定只能用点积表达。
只要某种评分函数既能比较 query 和 key，又能被端到端训练，它理论上都可以用。

但点积有三件事很占优势：

- 几何直觉自然
- 张量实现高效
- 与矩阵乘法高度兼容

这就是它成为经典选择的原因。

## 为什么还要除以 \(\sqrt{d_k}\)

很多人第一次看到缩放项，会把它当成经验技巧。
其实它背后有很明确的数值动机。

当 query 和 key 的维度 `d_k` 变大时，点积本身通常也会变大。
因为点积本质上是在对很多维度上的乘积做求和：

\[
q_t \cdot k_i = \sum_{j=1}^{d_k} q_{t,j} k_{i,j}
\]

维度越高，这个和越容易拥有较大的绝对值。

而一旦分数规模过大，后面的 softmax 就容易过早进入非常尖锐的状态。
也就是某一个位置权重接近 1，其余位置几乎都接近 0。

过度尖锐会带来两个问题。

第一，模型在训练初期会过快地做出非常武断的注意力分配。

第二，softmax 饱和以后，很多方向上的梯度会变小，训练不够平滑。

因此，除以 \(\sqrt{d_k}\) 的本质作用是：

> 把高维点积的典型数值尺度压回一个更适合 softmax 工作的范围。

它不是在改变 attention 的语义，而是在让这个语义更稳定地被数值系统承载。

## softmax 为什么不是附带步骤，而是读取协议的一部分

打分之后，attention 不会直接把原始分数拿去加权。
它必须先过 softmax。

这并不是为了让公式看起来更完整，而是因为原始分数本身还不适合作为读取权重。

原始分数有几个问题：

- 它们没有归一化
- 它们可能为负
- 它们之间还没有形成一组真正的“分配比例”

而 softmax 会同时完成三件非常关键的事。

第一，它把一组原始分数放进同一行的相对竞争关系里。
attention 的问题从来不是“每个位置单独有多重要”，而是“在这一轮读取里，哪些位置相对更值得分到注意力预算”。

第二，它把这些比较结果变成一组非负、总和为 1 的权重。
于是 attention 输出可以被理解成对 value 的凸组合。

第三，它保留了软选择。
这意味着模型不必在多个候选中硬选唯一一个来源，而可以同时保留主来源和次来源。

这对语言非常重要。
因为很多语言现象并不是单一历史位置独立决定的。
当前位置常常同时需要：

- 最近的局部搭配
- 更远的实体记忆
- 某种全局主题线索

所以 softmax 不是“打分之后顺便归一化一下”。
它是 attention 作为软读取协议的一部分。

## 为什么不是直接取最大值

既然有了分数，很多人自然会想：

> 既然最终就是找最相关的位置，为什么不直接取最大值，把那个位置的内容读回来？

这个想法看起来简洁，但会损失 attention 非常重要的能力。

首先，语言中的依赖往往不是单源的。
当前位置完全可能同时需要多个位置共同提供线索。
如果直接取最大值，就把这种多源融合粗暴地砍掉了。

其次，硬选择不利于平滑优化。
深度学习之所以强，很大程度上依赖很多中间步骤都可以被连续地优化。
softmax 提供的是连续可导的软分配。
而 `argmax` 更接近离散开关，训练起来要困难得多。

再次，硬选择会让模型过早做出不可逆的极端判断。
软选择则允许它在训练早期先分一点权重给多个可能来源，随着学习逐步把权重收紧。

所以 attention 的强大之处，从来不只是“能找到相关位置”，而是：

> 它能以一种可训练、可混合、可渐进收缩的方式找到相关位置。

## 为什么最终混合的是 value，而不是 key

到这里可以回到一个特别容易被忽视的问题：

> 既然权重是由 query 和 key 算出来的，为什么最后混合的不是 key，而是 value？

因为 key 的职责是“暴露可匹配接口”，不是“承担最终内容载荷”。

如果最终混合的是 key，就意味着模型只能把“为了更好被匹配而组织出来的那套方向”重新写回当前表示流。
这会让匹配空间和内容空间被迫绑定。

而引入 value 以后，模型就得到更大的结构自由：

> 哪些方向适合检索比较，由 key 决定；哪些方向适合真正写回当前表示，由 value 决定。

因此，attention 既像检索，又像重写。

它先利用 query 和 key 决定“从哪里拿信息”，再利用 value 决定“拿回来的信息以什么内容形式进入当前表示”。

这也是为什么 attention 输出通常不应被理解成“把历史某一格拷贝过来”。
更准确的说法是：

> 它把多个候选位置的内容表示，按照当前需求组织成了一份新的上下文向量。

## 从单个位置走到整段序列：矩阵视角到底在说什么

前面一直站在单个位置的角度讲 attention。
现在需要把它提升到整段序列的矩阵形式。

假设一整段序列的输入表示矩阵为：

\[
H \in \mathbb{R}^{T \times d_{\text{model}}}
\]

三组投影后得到：

\[
Q \in \mathbb{R}^{T \times d_k},\quad
K \in \mathbb{R}^{T \times d_k},\quad
V \in \mathbb{R}^{T \times d_v}
\]

此时，所有位置的 query 与所有位置的 key 可以一次性做矩阵乘法：

\[
S = \frac{QK^\top}{\sqrt{d_k}}
\]

这里的 `S` 形状是 `T × T`。

它非常值得牢牢记住，因为它已经把“谁在看谁”完整写出来了。

\[
S_{i,j}
\]

表示的是：

> 第 `i` 个位置发出的 query，与第 `j` 个位置暴露的 key 之间的原始匹配分数。

因此，行和列的语义必须分清：

- 行表示“谁在发起读取”
- 列表示“谁是候选来源”

接下来，对 `S` 的每一行做 softmax，得到注意力权重矩阵：

\[
A = \mathrm{softmax}(S)
\]

这里的 softmax 是按行做的。
因为每个位置都需要在自己的候选来源集合内部，分配一整行的注意力预算。

最后，再用这个权重矩阵去混合 value：

\[
C = A V
\]

于是得到上下文矩阵 `C`。
其中第 `i` 行 `c_i`，就是第 `i` 个位置从整段可见上下文中读回来的新内容摘要。

如果把整个流程压成一句矩阵化的话，就是：

> `QK^\top` 负责建立“所有读取者”和“所有候选来源”之间的匹配图，`softmax` 把匹配图变成读取权重图，`AV` 则把这张权重图真正转换成内容聚合结果。

## 为什么 attention 的输出应被理解成“表示重写”

一旦看到 `C = AV`，很多人还是会下意识把它理解成“从历史里拿了一点东西过来”。
这句话不算错，但还不够强。

更准确的理解是：

> attention 通过读取历史，重写了当前位置的表示。

因为当前位置在进入这一层时，只携带了一份旧的隐藏状态。
经过 attention 以后，它得到了一份由当前需求驱动、由上下文内容加权形成的新向量。

这份新向量不只是旧内容的补丁。
它会直接改变当前位置接下来如何被后续层理解。

所以 attention 既在“找信息”，也在“改写状态”。
它不是外挂检索器，而是主表示流的一部分。

这也解释了为什么后面的 Transformer block 里，attention 会和残差连接、层归一化、前馈网络一起协同工作。
它不是一个插在旁边的查询模块，而是表示系统本体的一部分。

## 多头注意力为什么会自然出现

当你已经理解 QKV 的职责分离以后，多头注意力其实不会再显得突兀。

单头 attention 的含义是：

> 用一套 query、key、value 投影空间，去建立一种读取关系。

但真实语言中的相关性并不只有一种。

同一个位置可能同时需要：

- 局部搭配关系
- 句法依赖关系
- 实体延续关系
- 主题相关关系
- 某种格式或位置模式

如果所有关系都挤在同一套投影空间里，模型虽然仍可工作，但不同关系可能会互相争夺表示容量。

多头注意力的自然想法就是：

> 既然一次读取可以有很多种关系视角，那就让模型并行地学出多套 QKV 投影，每一套都在自己的子空间里组织一种读取模式。

于是每个头都可以理解为：

- 一套自己的 query 空间
- 一套自己的 key 空间
- 一套自己的 value 空间
- 一张自己的注意力分配图

它们不是在做完全重复的事情。
更准确地说，它们是在并行地提供多种可能的上下文读取视角。

当然，实践中不同头学到的模式并不会总是整齐可解释。
但从结构设计动机上说，多头就是在给 attention 加入“多关系并行建模”的能力。

## QKV 到底解耦了什么

到这里，可以把这一章的深层结论再说得更凝练一点。

QKV 真正解耦的，不只是三个字母，而是三种原本容易被绑死的事情：

- “我现在缺什么信息”
- “历史中的谁值得我参考”
- “一旦参考它，我到底该把什么写回当前表示”

如果这三件事绑在一起，模型虽然仍能学，但会非常不灵活。

有了 QKV 以后，模型获得了三层自由：

第一，它可以单独学习如何表达读取意图。

第二，它可以单独学习什么特征最适合做匹配。

第三，它可以单独学习什么内容最适合被真正写回。

而 softmax 又把这些自由组织成一套可训练的软分配协议。

这就是为什么 attention 并不只是“相似度计算”。
它是一套完整的、可学习的、内容驱动的上下文读取语言。

## 常见误区

### 误区一：Q、K、V 只是必须背下来的三个缩写

不是。

它们对应的是一次读取中天然存在的三种职责：

- 当前需求
- 候选接口
- 内容载荷

如果脱离职责分工去背公式，后面几乎一定会重新糊掉。

### 误区二：key 和 value 分开只是实现习惯

不是。

分开以后，匹配空间和内容空间才能解耦。
这让“怎样被找到”和“找到后贡献什么”不必被迫写在同一个坐标系里。

### 误区三：attention 就是在找最相似的那个位置

不完整。

attention 做的是软分配，不是硬选择。
它允许多个来源共同贡献内容。

### 误区四：query 是一句人类可读的问题

不是。

query 是当前位置在当前层形成的向量化检索意图，而不是自然语言字符串。

### 误区五：attention 输出就是把旧位置的表示复制回来

不对。

attention 输出通常是多个 value 的加权组合，因此更像是一次新的上下文表示重写。

### 误区六：多头只是把同一件事重复很多遍

不准确。

多头的设计动机是让模型在多套关系子空间里并行组织读取，而不是机械复制同一张注意力图。

## 这一章真正要记住的核心句子

如果你只记住本章八句话，应该记住下面这些。

1. attention 首先是一套内容驱动的上下文读取机制，而不是一张相似度图。  
2. 一次读取至少包含三种不同职责：表达当前需求、暴露可匹配接口、提供真正内容。  
3. `Query` 表示“我现在想找什么”，`Key` 表示“我怎样被别人找到”，`Value` 表示“如果我被找到，真正该贡献什么”。  
4. QKV 都来自同一份隐藏状态，但通过不同投影进入不同角色空间，因此是“同源、分工”。  
5. query 和 key 的点积给出匹配分数，缩放项用于让高维点积更稳定地进入 softmax。  
6. softmax 不是附属步骤，而是在把一组原始分数变成一组可训练的软读取权重。  
7. attention 最终混合的是 value，而不是 key，因此它既在检索，也在重写表示。  
8. 多头注意力的自然动机，是让模型并行学习多套上下文读取关系，而不是把同一件事复制多次。  

## 练习题

1. 为什么说“我现在在找什么”“你怎样被我找到”“如果我找到你你该给我什么”是三种不同的结构职责？  
2. 假设没有 value，只有 query 和 key，再把 key 自己加权和写回当前表示，会损失什么表达自由？  
3. 为什么说 attention 的相关性不是某个位置的“全局重要性”，而是它相对当前 query 的局部价值？  
4. 为什么点积是一种自然的 query-key 匹配方式？为什么还需要除以 \(\sqrt{d_k}\)？  
5. 为什么 softmax 比直接取最大值更适合作为语言模型中的读取分配协议？  
6. 从矩阵角度解释 `S = QK^\top`、`A = softmax(S)`、`C = AV` 三步分别在表达什么。  
7. 为什么多头注意力不是“同一头做很多次”，而是“多套关系空间并行存在”？
