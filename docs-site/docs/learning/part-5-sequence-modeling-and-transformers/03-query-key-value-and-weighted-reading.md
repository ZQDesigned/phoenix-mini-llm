# 03. Query、Key、Value 与加权读取

## 为什么 Attention 要拆成 Q、K、V

当你第一次看到 `Q`、`K`、`V` 时，最常见的感受是：

> 这三个字母看起来很抽象，像某种必须硬记的缩写。

其实它们之所以存在，是因为 Attention 需要同时表达三件不同的事：

1. 我现在在找什么  
2. 每个历史位置能以什么方式被找到  
3. 找到之后，我真正要从那里拿走什么  

把这三件事分开，模型的信息读取会更灵活。

## Query：当前位置当前在找什么

query 表示的是：

> 按照当前位置当前层的需求，我现在要在历史里寻找哪类线索？

它不是自然语言问题，而是一种向量化的检索需求。

例如，当前位置可能更偏向寻找：

- 与当前主题最相关的历史位置
- 与当前实体一致的线索
- 对语法延续最有帮助的依赖

最重要的不是人类能否给它起名字，而是：

> 它表达的是当前位置自己的“查询意图”。

## Key：每个历史位置可以怎样被匹配

key 表示的是：

> 如果别人来找信息，我这个位置最适合通过什么方式被认出来？

也就是说，key 更像每个位置暴露出去的“可匹配标签”。

它不是词典标签，而是隐藏空间中的一组向量特征。

如果某个 key 与当前位置 query 很匹配，就说明：

> 对当前位置当前需要解决的问题来说，这个历史位置值得重点看。

## Value：如果你关注我，你真正拿走什么

value 的角色是：

> 一旦这个位置被关注，最终从这里读走的内容表示。

为什么不直接把 key 本身拿来当内容？

因为“如何匹配我”和“真正该从我这里取走什么信息”并不一定是同一回事。

一个位置也许因为某种语法线索被找到，但真正取走的可能是更综合的语义表示。

把 key 和 value 分开，会让模型在匹配与读取之间拥有更大自由度。

## 可以把 Q/K/V 想成“查资料”的三个角色

一个非常好用的类比是：

- Query：你现在要查什么
- Key：每份资料的索引标签
- Value：资料真正的内容

这个类比不完美，但足够帮助你建立第一层直觉：

> Attention 不是盲目翻全档案，而是先带着问题去查索引，再把相关内容按重要性拿回来。

## 匹配分数在表达什么

当 query 与各个 key 比较时，模型会得到一组匹配分数。

这些分数表达的是：

> 对当前位置当前的查询需求来说，每个历史位置的相关程度有多高。

分数越高，说明越值得重点关注。

分数越低，说明这个位置当前帮助不大。

这里你不必先死盯点积公式，更应该抓住一件事：

> 这些分数让“谁相关”这件事变成了可比较、可微、可学习的数值对象。

## softmax 把“相关程度”变成“权重分配”

匹配分数还不是最终读取权重，因为它们可能：

- 有正有负
- 大小范围不固定

softmax 的角色就是把它们转换成一组更适合加权聚合的权重分布。

于是模型不再只是知道“谁更相关”，而是进一步知道：

> 每个位置应该在最终读取结果里占多大比例。

这一步非常关键，因为它让 Attention 从“打分”走向了“按比例汇总内容”。

## 输出为什么是加权摘要，而不是硬性选一个位置

这也是很多初学者最容易误解的点。

Attention 通常并不是每次都只挑一个最佳位置，然后完全忽略其他位置。

更常见的情况是：

> 它会根据权重，把多个位置的 value 混合成一份新的上下文表示。

这有两个很重要的好处：

- 可以突出最关键的位置
- 又不必完全丢弃次要但仍有价值的信息

因此 Attention 的输出更像：

> 一份针对当前位置当前需求定制出来的历史信息摘要。

## 为什么这比“硬检索”更适合训练

如果模型必须每次做硬选择：

- 只选一个位置
- 其余全部作废

那么训练会更困难，因为这种离散决策不够平滑。

Attention 使用软权重的好处是：

- 信息可以渐进式重新分配
- 梯度能更平滑地推动相关性学习
- 模型可以在多个候选之间细腻权衡

所以“软性加权读取”不只是一个数学优雅点，它也和可训练性直接相关。

## 多头注意力为什么会在这里自然出现

一旦你理解了 Q/K/V 的作用，就会更容易明白多头的必要性。

因为一个位置往往不只需要一种查询方式。

它可能同时需要：

- 一种偏局部的语法相关性
- 一种偏长程的实体相关性
- 一种偏结构边界的相关性

多头注意力可以被理解成：

> 让模型在多个子空间里并行构造多套 Q/K/V 读取关系。

这样同一层里就不只存在一张“谁该看谁”的单一地图，而是多张并行的相关性地图。

## 为什么 Q/K/V 都是从当前表示投影出来的

这说明一个很重要的事实：

> Attention 不是在使用人工指定的固定特征，而是在当前隐藏表示基础上，动态生成适合当前层任务的查询、匹配和内容表示。

也就是说：

- Q/K/V 不是手工规则
- 它们是可学习投影后的结果

所以模型会在训练中自己学出：

- 什么特征适合拿来做匹配
- 什么内容适合拿来做聚合

这也是 Attention 之所以强大的原因之一。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> Query、Key、Value 之所以要分开，是因为 Attention 需要分别表达“我现在想找什么”“每个位置如何被匹配”“真正从该位置拿走什么内容”；最终输出不是单一拷贝，而是对多个 value 的加权摘要。
