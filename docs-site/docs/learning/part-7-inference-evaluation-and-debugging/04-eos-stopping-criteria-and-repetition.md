# 04. EOS、停止条件与重复问题

## 为什么“模型会不停写下去”不是一个奇怪边缘情况

很多初学者第一次写生成循环时，会很快发现一个现象：

> 如果不额外处理，模型好像可以一直写下去。

这并不奇怪。

因为从任务定义上看，语言模型本来就在做：

- 给定当前上下文
- 继续预测下一个 token

如果你没有告诉系统什么时候该停，它就会继续把“再下一个 token”这个问题无限重复。

所以停止条件不是可选细节，而是生成系统的基本组成部分。

## EOS 到底是什么

`EOS` 通常表示 “End Of Sequence”。

它的作用是：

> 让模型有机会学会“这段序列在这里应该结束”。

训练时，如果语料和样本组织把 `EOS` 正确纳入目标中，模型就会逐渐学习：

- 某些上下文后更适合收尾
- 结束本身也是一个可预测 token

这意味着“停下来”并不是纯外部强制，而可以部分来自模型分布本身。

## 为什么仅有 EOS 还不够

即使模型具备 `EOS` 概念，现实生成系统通常仍然会额外设置停止条件。

原因很直接：

- 模型不一定总能及时给出 EOS
- 小模型尤其容易拖长或循环
- 某些 prompt 下它可能迟迟不进入自然收尾状态

所以工程上通常还会配合：

- `max_new_tokens`
- 停止字符串
- 自定义终止规则

也就是说，停止机制一般是：

> 模型内在结束偏好 + 外部安全边界

共同决定的。

## 为什么 max_new_tokens 几乎总会存在

因为它提供了一个非常直接、非常可靠的硬上限。

无论模型当前行为多不稳定，只要设置了：

- 最多生成 `N` 个新 token

你至少可以保证：

- 生成不会无限继续
- 单次推理成本有明确上界
- 调试时行为可控

所以 `max_new_tokens` 往往不是因为模型“不会停”，而是：

> 任何实际系统都需要最坏情况边界。

## 什么是停止字符串或外部停止条件

有些应用不只是依赖单个 `EOS` token，还会根据：

- 某个固定字符串
- 某种格式边界
- 某个多 token 序列

来判断何时结束。

这是因为：

- 自然语言中的“结束”不总由单个 token 清晰表达
- 某些任务需要更具体的输出截断方式

例如聊天模板、代码块边界、特定分隔符等，可能都需要外部规则辅助。

这再次说明：

> 生成停止不是纯模型问题，也是一层解码协议问题。

## 重复为什么这么常见

重复是小型语言模型最常见、也最容易让人沮丧的问题之一。

典型表现包括：

- 单词反复出现
- 短短片段循环出现
- 句子结构开始转圈

这通常不是单一原因造成的，而是多个因素共同作用。

## 重复的第一类来源：模型本身没学稳

如果模型训练还不充分，或者数据过于单一，它可能会表现出：

- 对少数高频模式过度依赖
- 缺乏足够强的长程一致性
- 一旦进入熟悉短语，就不断沿着最保守路径继续

这类重复本质上是：

> 模型分布本身就过窄、过浅或过偏。

## 重复的第二类来源：解码过于保守

即使模型分布不算太差，过于保守的解码也会强化重复。

典型情况包括：

- greedy
- 极低 temperature
- 过小的 top-k

这些策略都会让系统更倾向：

- 不断选当前最稳的高频 token

于是局部最优路径被一遍遍重复。

## 重复的第三类来源：停止条件不清

有时模型其实已经接近自然结束，但由于：

- 没有学到稳定 EOS
- stop criterion 太弱

它会继续往后补一些低质量尾巴。

这时你看到的可能不是“整段生成都差”，而是：

> 本该结束之后仍被迫继续，结果进入循环和重复。

因此观察重复时，要分清：

- 它是从一开始就重复
- 还是在本应收尾之后开始失控

这两种情况往往意味着不同问题。

## 为什么重复不是单纯“模型太笨”

如果一看到重复就下结论：

> 模型太差。

那调试会非常低效。

更成熟的判断应该问：

- 模型训练是否足够
- 数据分布是否太单一
- greedy / temperature / top-k 是否过于保守
- EOS 与停止条件是否合理

因为相同的重复表象，背后可能对应完全不同的修复方向。

## 为什么“加大 temperature”有时能缓解重复，但也可能让文本更差

提高 temperature 会让分布更平，次高概率候选更容易被选中。

这有时能帮助模型：

- 跳出当前高频循环
- 不至于永远沿着第一名往下写

但代价也同样明显：

- 可能引入更多噪声
- 可能让文本变得不连贯

所以“更随机”不等于“更好”。它只是在：

> 用更开放的候选空间换取跳出循环的机会。

## 为什么重复问题特别适合用固定 prompt 做对照

如果你每次都换 prompt，就很难判断：

- 是模型本来就重复
- 还是某个 prompt 天生更容易引导循环

更好的方式是：

- 固定几个 prompt
- 比较不同 checkpoint
- 比较不同采样策略

这样你更容易分清：

- 重复是训练问题
- 还是解码问题
- 还是停止条件问题

## 什么叫自然结束

这也是一个值得明确的概念。

自然结束并不只是：

- 命中了 EOS

更重要的是：

- 语义有收束
- 句法有闭合
- 结构上像真的说完了

一个模型可能在技术上停下来了，但收尾仍然很突兀；也可能技术上还没停，但语义早就该停。

所以在评估停止行为时，你需要同时看：

- 模型是否停
- 停得是否自然

这也是为什么光看 token 级指标不足以完整评价生成质量。

## 对学习项目来说，最务实的停止策略是什么

在小型 LLM 学习阶段，一个稳妥策略通常包括：

- 正确训练并使用 EOS
- 始终设置 `max_new_tokens`
- 在需要时补充简单外部停止规则

这三者组合能保证：

- 模型有“学会结束”的可能
- 系统有兜底边界
- 特定场景下输出还能被更稳地截断

## 这一章最该带走的判断

请把下面这件事牢牢记住：

> 停止与重复问题不是生成系统的边角料，而是在“分布怎样继续被使用”这件事上最直接暴露出来的行为问题。

只要这个判断稳住，后面你看到模型停不下来、绕圈写、重复堆词时，就不会只会胡乱调温度，而会开始系统地问：

- 它有没有真正学到 EOS
- 外部停止条件够不够
- 采样是否过于保守
- 模型本身是否还没学稳
