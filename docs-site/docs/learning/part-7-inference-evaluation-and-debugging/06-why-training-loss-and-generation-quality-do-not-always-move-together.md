# 06. 为什么训练 loss 与生成质量不总同步

## 这一章要解决的，不是一个小现象，而是一整套评估误判

当你终于把数据、模型、训练循环都跑起来之后，几乎一定会遇到这个时刻：

- 图表上的训练 loss 在下降
- 验证 loss 也许也在下降
- 你怀着希望去看几条生成样例
- 然后发现文本依然很一般，甚至偶尔还不如前几轮顺眼

这时最危险的，其实不是模型，而是你的解释方式。

如果你把：

- “loss 下降”

和

- “生成质量上升”

理解成一条绝对同步、线性前进的关系，那么你接下来会非常容易做出一连串错误判断：

- loss 降了，就以为模型已经真的会写了
- 样例没达到预期，就以为训练目标一定错了
- 某次单样例看起来更顺，就以为模型整体显著变强了
- 某次单样例看起来更差，就以为训练正在退化

更成熟的理解应该是：

> loss 测量的是模型在真实历史条件下，对真实下一个 token 的平均预测质量；而生成质量测量的是模型把这些局部预测沿时间轴滚动展开、再经过某种解码策略之后，作为整段文本暴露出来的整体行为。

这两者高度相关。
但它们绝不是同一件事。

这一章的任务，就是把这条“相关但不等价”的关系讲透。

## 先从最根本的问题开始：loss 究竟在度量什么

如果不先把 loss 的意义说清楚，后面所有讨论都会浮在空中。

对最常见的 decoder-only 语言模型来说，训练目标通常是：

> 在每个位置上，提高真实下一个 token 的条件概率。

如果我们使用交叉熵训练，那么本质上在惩罚的是：

- 真实 token 概率太低
- 错误 token 概率分配太高

而这种惩罚不是对单个位置、单条样本孤立进行的。
它通常会对：

- 很多位置
- 很多样本
- 很多 batch

做平均。

所以更准确地说，loss 真正在回答的是：

> 在给定数据分布上，这个模型作为一个 next-token 条件概率估计器，平均表现得怎么样？

请注意这句话里的每个限定词：

- 是“给定数据分布上”
- 是“条件概率估计器”
- 是“平均表现”

这些限定词就是后面所有“为什么 loss 和生成样例会错位”的根源。

## loss 并不是在直接奖励“写出好文章”

这句话值得单独记住。

训练时，模型并没有一个神奇的标量在直接问：

- 这段输出有没有文采
- 这段回答是否结构完整
- 这篇长文是否信息密度高
- 这次解释是不是通俗、稳定又不绕圈

模型直接面对的，其实是一串很局部的问题：

```text
在这个真实前缀之后，真实语料里下一个 token 是什么？
```

于是训练系统直接奖励的是：

- 对真实 token 提高概率
- 对错误 token 降低概率

这件事非常强大。
因为语言正是由这些局部选择构成的。

但它同时也天然有限。

因为：

> “很多位置上的局部概率更准”并不自动等于“几十个位置滚动展开之后的整段文本一定更好”。

这不是训练目标错了，而是：

- 局部条件预测质量
- 和全局文本体验

本来就不是完全相同的对象。

## 为什么“局部更准”不会自动升级成“整体更好”

这是整章最核心的观念。

你可以把生成过程看成一个复合系统。

模型每一步做的是局部判断：

```text
给定当前上下文，下一 token 更可能是什么？
```

而用户看到的却是全局产物：

```text
几十个、上百个 token 连在一起形成的一段文本
```

从局部到全局，中间至少隔着几层放大机制：

1. 局部错误会累积
2. 模型会吃自己的输出
3. 解码策略会改变路径选择
4. 人类对文本的评价常常依赖高层结构

所以即便平均 token 预测质量提高了一点点，最终长文本质量也不一定以同样直线、同样平滑的方式改善。

这不是例外，而是常态。

## 第一层原因：训练时和生成时，模型其实活在两个不同世界

这是理解问题最有效的入口之一。

### 训练时的世界

训练阶段，模型在每个位置看到的历史通常都是真实历史。

也就是说：

- 第 20 个位置的预测，建立在真实前 19 个 token 上
- 第 57 个位置的预测，建立在真实前 56 个 token 上

这种做法就是 teacher forcing。

它的优点很大：

- 训练稳定
- 可并行
- 梯度路径清楚
- 数据利用效率高

但它也意味着：

> 模型是在“真实轨道”上学习局部预测。

### 生成时的世界

一旦开始推理，情况就变了。

在第一个新 token 之后，模型看到的上下文就逐渐变成：

- 真实 prompt
- 加上它自己刚刚生成出来的 token

这意味着只要某一步轻微偏一点，下一步就是在这个偏掉的上下文上继续前进。

所以训练时模型生活在：

- 老师不断扶正的真实轨道上

而推理时模型生活在：

- 自己一步步铺出来、且会不断反馈给自己的轨道上

这两种世界不相同，这就是第一层根本差异。

## teacher forcing 为什么会天然制造这种差异

这并不是某个框架偶然如此，而是训练目标和训练协议本身共同决定的。

在训练时，我们之所以让模型总站在真实历史上做局部预测，是因为这样可以：

- 稳定学习条件分布
- 避免早期错误连锁放大
- 让损失定义和梯度传播更清晰

但代价是：

> 模型在训练中很少真正面对“自己之前刚犯过一点错，现在还得继续在这个错误历史上写下去”的环境。

这意味着：

- 训练里的平均局部正确性
- 和推理时的自回归路径稳定性

并不是完全相同的能力。

所以当你看到：

- loss 下降了
- 但生成仍然会逐步发散

不要惊讶。
这恰恰是在提醒你：

- 模型学会了更多真实分布上的局部条件规律
- 但自由运行时的路径稳定性是另一个被放大的维度

## 第二层原因：loss 是平均量，而糟糕生成往往由少数关键错误触发

这一点极其重要。

loss 通常对很多 token 做平均。
它很擅长告诉你：

- 整体上真实 token 的概率是不是在上升
- 平均 surprisal 是否下降
- 数据分布上的局部预测是不是在变准

但很多糟糕生成并不是“处处都差”。
它们常常是：

> 前面大部分位置都还行，只在某个关键拐点犯了一个错，然后整段开始偏。

例如：

- 少了一个否定词，意思反了
- 在本该结束处没结束，开始拖尾
- 在代码生成里括号或缩进错了一处，后面全崩
- 在角色对话里切换错了说话人
- 在结构化回答里突然丢掉编号节奏

这些错误从 token 数量占比上看可能很小。
但对整段可读性的破坏极大。

于是就会出现一种很典型的现象：

> 模型在 99% 的局部位置上都略有改善，但那 1% 的关键位置仍足以把整段体验拖垮。

这说明：

- 平均指标
- 和高感知损失的关键事件

本来就不一定同步。

## 第三层原因：生成是路径问题，不是独立位置问题

训练 loss 更像是在许多位置上做并行平均。

但生成不是把很多独立位置的好坏简单相加。
生成更像是在走一条路径。

一条路径有个很重要的特性：

- 前面的选择会改变后面的状态空间

这意味着：

- 某一步哪怕只是选了一个“第二好但也不算太坏”的 token
- 后面整个可能性空间也可能已经变了

从这个角度看，生成质量不只是“单步判断分数高低”的函数。
它更像：

> 很多单步选择在状态空间里连成的一条轨迹。

而轨迹系统有一个很典型的性质：

- 小偏差可能累积成大体感差异

这也是为什么有些模型看起来：

- 单步局部预测都不算离谱
- 但长段生成就是会越来越散、越来越绕、越来越重复

## 一个简单例子：局部上都不算错，整体也可能越走越偏

假设 prompt 是：

```text
今天下午天气突然变差，所以我们决定……
```

模型在下一个 token 上可能有几种都不算离谱的方向：

- “取消”
- “改到”
- “继续”
- “暂时”

如果它选了“取消”，后面的轨道会很自然地朝活动取消展开。
如果它选了“改到”，轨道可能朝室内替代方案展开。
如果它选了“继续”，后面可能需要更多解释。

单看这一步，也许前三个选择都不算严重错误。
但它们会把后面整段文本带向完全不同的空间。

因此，生成的体感质量，很大程度上取决于：

- 一串局部选择形成的整体路径是否稳

而不只是：

- 每一步平均概率有没有都略好一点

## 第四层原因：loss 看的是分布，用户看到的是单次样例

这也是一个常被低估的断层。

loss 优化的是：

- 在词表分布上，把真实 token 推到更合理的位置

但用户看到的不是一整个分布。
用户看到的是：

- 某一次解码路径

这中间隔着一道非常重要的桥：

- 采样或 greedy 之类的解码决策

如果某一步模型分布里：

- 第一候选从 0.32 升到 0.40
- 第二候选从 0.28 降到 0.22

从 loss 角度看，这通常是进步。

但如果你用较高 temperature 采样，那么第二候选仍然有机会被抽中。
甚至一次不太理想的抽样，会把整条生成路径带偏。

这说明：

> loss 在分布层面的进步，并不保证每一次单样例都立刻显得更好。

它只意味着：

- 从平均分布角度看，模型更接近真实数据了

## 单次样例为什么方差很大

同一个模型、同一个 prompt、同一个 checkpoint，本来就可能生成出：

- 一次看起来很顺
- 一次略平庸
- 一次突然开始重复

只要你使用的是采样而不是完全 greedy，这种方差就天然存在。

因此，把一条样例直接和一个平滑下降的 loss 曲线逐点比较，常常会导致错觉：

- 曲线在变好，为什么这条样例不配合？

答案往往很简单：

- 你在拿稳定的平均量
- 对比一个高方差的单次路径结果

这本来就不应完全同步。

## 第五层原因：人类关心的高层文本品质，并不完全由 token-level 平均损失概括

loss 主要在观察：

- 真实 token 的局部概率是否足够高

但人类在意的高层品质经常包括：

- 主题是否稳定
- 结构是否清楚
- 是否逐步推进而不是绕圈
- 是否在合适时机自然结束
- 前后是否自洽
- 是否有不必要重复

这些性质很多都是：

- 长程的
- 结构性的
- 组合性的

而不是纯粹某一个 token 是否高概率就能完整表达。

因此会出现这样的情形：

- 局部 token 预测平均更准了
- 但篇章组织、整体节奏、长程连贯性没有同速改善

这不是说 loss 没价值，而是说：

> token-level 平均质量和篇章级整体质量，本来就不是一个维度的全部投影。

## 第六层原因：训练分布和你拿来观察的 prompt 分布可能不完全一致

loss 和生成样例错位，还有一个非常现实的原因：

> 你看样例的 prompt 分布，未必就是训练或验证时主要覆盖的分布。

例如：

- 训练语料偏叙述风格，你却更常看指令型问答
- 训练数据偏短句，你却喜欢看长解释
- 训练数据里某种主题不多，你却专门拿它来测试

于是模型虽然在：

- 训练/验证数据平均分布上确实进步了

但在你特别在意的某些 prompt 族上，改善可能并不明显，甚至几乎没动。

这也提醒你：

> 生成评估必须注意样例选择，不然你会把“局部场景没改善”误判成“整体没改善”。

## 第七层原因：采样策略本身会放大或压平模型的优缺点

这是卷十一反复要强调的一点。

生成样例不是只由模型决定的。
它还由：

- greedy
- temperature
- top-k
- top-p

这些策略共同决定。

于是同一个 checkpoint，完全可能出现：

- greedy 下显得比较保守但稳定
- 高 temperature 下显得更灵活但更散
- top-p 太高时更容易走到长尾错误

这意味着：

> 你在看“生成质量”的时候，其实常常在看“模型分布和解码协议共同作用的结果”。

而 loss 只在看：

- 模型分布本身与真实 token 的平均关系

所以两者天生不是同一测量对象。

## 为什么有时 loss 改善很明显，但体感提升却很慢

这是一种非常常见的中期训练现象。

原因通常包括：

### 第一，模型可能先学会很多“容易的局部规律”

例如：

- 高频词搭配
- 常见局部句法
- 常见标点模式

这些会很快拉低 loss。

### 第二，真正影响高层体感的能力改善更慢

例如：

- 长段一致性
- 结构推进
- 减少重复
- 更稳地处理较远依赖

这些往往需要更长训练或更强模型表达。

于是你会看到一种非常典型的现象：

- 前期 loss 下降得很漂亮
- 样例开始从“完全胡说”变成“勉强像话”
- 但从“勉强像话”到“明显好读”的提升却没有那么线性

这并不奇怪。
它是在说明：

- 简单局部模式比复杂篇章能力更早学会

## 为什么有时样例突然变好，但 loss 曲线看起来变化不大

反过来也会发生另一种情况：

- 某几个 checkpoint 之间，loss 改善不大
- 但样例突然明显更顺了

这也不是悖论。

可能原因包括：

### 第一，模型在某些关键结构模式上跨过了临界点

例如：

- 更稳定地学会了收尾
- 更少陷入重复
- 某类 prompt 下不再轻易跑偏

这些变化对体感影响极大，但在平均 token loss 里不一定巨大。

### 第二，你看的样例恰好命中了模型改善最大的那类模式

这说明样例本身带有选择偏差。

### 第三，解码策略和分布形状在那个 checkpoint 上刚好配合得更顺

所以样例“突然好很多”，并不总意味着整体统计指标有同等幅度跳跃。

## perplexity 为什么有帮助，但为什么也不能被神化

perplexity 本质上和平均 token-level 负对数概率高度相关。

它的优点很明显：

- 直观
- 可比较
- 在语言模型里历史上很常用

但它本质上回答的仍然是：

> 模型对真实下一个 token 的平均迷惑程度。

这与：

- 文本是否有文采
- 是否结构清晰
- 是否长段稳定

并不完全是同一件事。

因此，perplexity 应当被认真看待，但不能被神化。

它是：

- 非常重要的分布级指标

但不是：

- 唯一裁判

## 为什么“训练 loss 很低但生成很差”有时真的意味着出了问题

前面强调了两者不总同步，但这并不意味着：

- 任何错位都正常

有些强错位，确实是在报错。

例如：

- 训练 loss 很低，但生成极度重复
- 验证 loss 看起来不错，但样例总在错误地方结束
- 指标不错，但某些 prompt 下始终答非所问

这时可能在提醒你检查：

- tokenizer 是否和训练时一致
- 采样参数是否过激
- padding / loss mask 是否有问题
- 样例 prompt 分布是否严重偏离训练分布
- 模型是否在小数据上过拟合
- 评估脚本是否只看到了某种狭窄指标

所以正确结论不是：

- loss 和生成不一致没关系

而是：

> 你必须学会区分哪种不一致是正常统计现象，哪种不一致是在暴露系统问题。

## 一个很有用的判断：loss 是“平均地形”，样例是“具体路径”

如果你想要一个更稳的心智模型，可以这样记：

> loss 像是在看整个概率地形平均有多平滑、正确；样例像是在这张地形里真正走出一条具体路径。

这个比喻非常有用。

因为它能同时解释几件事：

### 第一，地形变好了，某条路径仍可能偶尔走歪

这对应：

- loss 降了
- 但单样例仍可能不好

### 第二，地形整体变化不大，某条路径却可能突然顺了

这对应：

- 指标改动不大
- 但某些样例体感突然改善

### 第三，地形和路径必须一起看

只看地形，你不知道用户真正怎么走。
只看路径，你又可能被偶然性误导。

这个心智模型几乎可以概括整章的方法论。

## 所以到底该怎么评估模型，而不是被单一证据牵着走

这正是这章最终想落到的实践结论。

一个更稳的评估方法，通常至少同时依赖三类证据。

### 第一类：训练和验证损失

它们回答：

- 模型是不是还在学
- 是否开始过拟合
- 整体 token-level 概率质量是否改善

### 第二类：perplexity 或相关分布级指标

它们回答：

- 模型在验证分布上的平均迷惑程度如何

### 第三类：定性样例检查

它们回答：

- 用户真正关心的长段体验如何
- 是否重复
- 是否跑偏
- 是否自然结束
- 是否逻辑还算连贯

这三类证据缺一不可。

只看第一类，你会高估训练曲线。
只看第三类，你又会被样例方差带偏。

## 为什么样例评估也必须有纪律，而不是随便看两条

如果你想避免误判，定性样例也要有基本纪律。

更好的做法通常是：

- 固定一组代表性 prompt
- 固定采样设置
- 定期在相同条件下比较不同 checkpoint

这样你看到的变化更可能来自：

- 模型本身

而不是来自：

- 每次 prompt 不一样
- 温度不一样
- top-p 不一样
- 随机性差异太大

也就是说，定性评估也应尽量：

- 控制变量

否则你很容易把采样噪声误当成模型进步或退步。

## 为什么“过拟合一小批样本”这个测试有时能帮助你解释强错位

如果你怀疑系统本身有问题，一个很有价值的测试是：

- 让模型对极小批数据过拟合

如果它连极小批都过拟合不好，那么：

- loss 和生成关系混乱

很可能说明的是链路问题，而不是“语言本来就难评估”。

反过来，如果极小批链路很通顺，但大规模训练里样例和 loss 仍有错位，那么更可能是：

- 分布问题
- 泛化问题
- 解码问题
- 高层长段质量问题

因此，这个测试在诊断“错位到底是正常现象还是系统异常”时很有帮助。

## 初学者在这里最容易犯的几个误解

### 误解一：loss 降了，生成一定同步变好

实际上它们相关，但中间隔着训练/推理环境差异和解码路径问题。

### 误解二：某条样例更差，就说明模型退化了

单样例方差往往很高。

### 误解三：perplexity 就是生成质量总分

它非常重要，但主要衡量的是分布级 token 预测质量。

### 误解四：loss 和生成不一致，就说明训练目标错了

很多不一致是正常现象，但强烈不一致也可能暴露其他链路问题。

### 误解五：定性评估可以随便看几条

没有固定 prompt 和固定采样条件，样例对比会非常不稳。

## 读完这一章之后，你应该能稳定回答什么

如果这一章真正起作用了，你至少应该开始能稳定回答：

- loss 在语言模型里到底在平均什么
- 为什么 teacher forcing 会让训练和推理环境天然不同
- 为什么局部 token-level 进步不会自动变成篇章级体验进步
- 为什么坏生成常常由少数关键位置错误放大
- 为什么解码策略会进一步放大或掩盖模型本身的优缺点
- 为什么单样例不能和平均 loss 简单一一对应
- 为什么评估必须联合使用损失、perplexity 和定性样例

如果这些问题能讲清楚，你后面做训练排障时就会稳很多。

## 本章之后去哪里

读完这章之后，最自然的下一步通常就是：

- 回到更系统的评估组合方法
- 或进入更具体的调试实践

因为到这里，你已经明白：

- 不能只看 loss
- 也不能只看几条样例

接下来要进一步学的是：

> 怎样把多种证据组合起来，形成真正可靠的训练判断。

## 小结

本章最核心的结论可以压缩成一句话：

> 训练 loss 度量的是模型在真实历史条件下，对真实下一个 token 的平均概率预测质量；生成质量度量的则是模型把这些局部预测通过自回归路径和具体解码策略展开之后，作为整段文本所表现出的整体行为，因此两者高度相关，但不会也不应该被误解成完全同步的一条直线。

一旦这个认识站稳，你就不会再把：

- 曲线下降

自动等价成：

- 文本已经写好了

你会开始更有层次地看待模型：

- 分布级进步
- 路径级稳定性
- 高层文本体验

这三者既互相关联，又各自需要独立被观察。
