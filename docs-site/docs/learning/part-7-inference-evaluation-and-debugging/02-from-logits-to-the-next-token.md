# 02. 从 logits 到下一个 token

## 为什么“模型输出文本”这句话过于粗糙

在用户视角里，你看到的是：

- 模型输出了一段字
- 句子被一行行打印出来

但在模型内部，真正直接输出的并不是文字，而是一组数值。

更准确地说，模型在当前最后一个位置产出的是：

> 对整个词表中每个 token 的未归一化打分。

这组打分就是 `logits`。

如果你不先把 “logits 到 token” 这条链讲清楚，后面所有采样策略都会显得像魔法开关。

## logits 到底是什么

最实用的定义是：

> logits 是模型对每个候选 token 给出的相对偏好分数。

它们通常具有这些特点：

- 可以是任意实数
- 可以有正有负
- 总和不需要等于 1
- 只有相对大小最重要

这说明 logits 不是概率，而更像：

> 概率分布形成之前的一层原始判断。

## 为什么模型不直接输出概率

这是一个很自然的问题。

如果最后要选 token，为什么不直接让模型输出 0 到 1 之间、总和为 1 的概率呢？

因为在训练和表示层面，logits 通常更方便：

- 数值空间更自由
- 线性输出层更自然
- 与交叉熵等损失函数配合更稳定

所以模型通常先输出 logits，再由后续步骤把它们转成可解释为分布的对象。

## softmax 在这里承担什么角色

softmax 的作用是：

> 把一组 logits 转成合法概率分布。

它做了两件关键事情：

- 把分数变成正权重
- 再把这些权重归一化，让总和为 1

于是你得到的就是：

- 每个 token 一个概率
- 全部 token 概率加起来等于 1

也就是说，softmax 是：

> 从“模型原始打分”走向“可采样分布”的桥梁。

## 为什么只看概率最大 token 不等于生成行为已经被定义

如果你有了 softmax 后的分布，一个最简单的想法就是：

> 那我永远选概率最大的那个不就行了？

这确实是一种策略，也就是后面会讲的 greedy decoding。

但它只是：

> 如何使用分布的其中一种方式。

模型本身并没有强迫你必须永远选最大值。

因为分布里可能存在这种情况：

- 最大概率 token 是 0.28
- 第二个是 0.25
- 第三个是 0.19

这时“只选最大值”和“允许在高概率区间内进行采样”，会得到完全不同的外显行为。

## 从 logits 到 token，中间至少经过了哪几层语义变化

这条链最好拆开看：

### 第一层：隐藏状态到 logits

模型的最后一层隐藏表示，被输出头映射到词表维度，得到每个 token 的原始分数。

### 第二层：logits 到分布

softmax 把原始分数转成概率分布。

### 第三层：分布到决策规则

你必须决定：

- 选最大值
- 还是按概率随机抽
- 还是先截断分布再抽

### 第四层：token id 到文本

被选中的 token id 最后再通过 tokenizer decode 回人类可读文本。

很多入门困惑，其实都来自把这四层混在一起。

## 为什么“下一个 token”不一定是“下一个字”

这是必须不断提醒自己的现实。

token 可能是：

- 一个字
- 一个词
- 一个子词片段
- 一个空格相关片段
- 一个特殊控制符号

因此从 logits 到 token 的决策，不一定对应“选一个完整自然语言词”。

模型真正选的是：

> 当前 tokenizer 定义下的基本离散单位。

这也是为什么 tokenizer 属于模型定义的一部分，而不是外围工具。

## 为什么当前最后一个位置的分布能决定下一个 token

在 decoder-only 语言模型里，当前位置的隐藏状态本身就是：

> 对左侧可见上下文的一次压缩表示。

当它经过输出头后，就得到：

> 在“看过这些前文”的条件下，对下一 token 的偏好。

所以最后一个位置对应的 logits，并不是随手一组分类分数，而是：

> 当前整段上下文条件下的 next-token 条件分布入口。

## argmax 是什么，它解决了什么

`argmax` 的意思是：

> 找到分数最大的那个索引。

如果你直接对 logits 或 softmax 后的概率做 argmax，本质上都在做同一件事：

- 找出当前最被模型偏好的 token

它解决的是“如果我只想要一个确定答案，该选哪个”的问题。

但它没有解决：

- 分布尾部是否应被截断
- 多个相近候选时是否允许探索
- 输出多样性该如何体现

所以 argmax 很重要，但它只回答了最朴素的单步决策问题。

## 为什么随机采样不是“故意让模型变差”

很多初学者第一次接触采样时，会本能觉得：

> 既然最大概率最靠谱，那随机采样是不是在故意偏离最优答案？

这并不准确。

因为语言本身经常不是单解任务。

在大量上下文中：

- 多个延续都合理
- 最大概率候选不一定比次高概率候选“绝对正确”
- 过度保守反而容易让文本僵化和重复

所以允许在分布里进行受控采样，并不是让模型故意犯错，而是：

> 让模型已学到的分布多样性有机会真正表现出来。

## 为什么分布尾部会成为问题

虽然语言模型输出的是完整词表分布，但词表通常很大。

这意味着即使经过 softmax：

- 仍然会有大量极低概率 token
- 它们单个概率虽小，但总数很多

如果你完全不控制这些尾部候选，采样时就可能出现：

- 跳出很怪的 token
- 语义和风格突然失稳
- 生成行为变得像“胡言乱语”

所以后面的 `top-k`、`top-p` 等策略，本质上都在回答：

> 我们要如何使用这整个分布，而不是盲目开放所有尾部。

## 为什么同一个 logits 分布会对应不同生成结果

因为模型只给出了：

> 当前每个候选 token 的相对可能性。

真正把它变成一个具体 token 的，是解码规则。

例如同一个分布下：

- greedy 可能永远取第 1 名
- top-k 采样可能在前几个高分候选里跳动
- top-p 采样可能根据分布形状动态放开不同数量的候选

所以模型输出和最终文本之间，永远隔着一层策略。

## 为什么 decode 不是“把 token id 变回文字”这么简单

很多工具和接口里都叫 `decode`，容易让人混淆两层意思。

### 狭义 decode

指 tokenizer 的：

- `token ids -> 文本`

### 生成语境里的 decode

常常指：

- 从当前分布中选出一个新 token

再把它接回上下文继续滚动。

所以在推理讨论里，“decode 阶段”并不是单纯做字符串转换，而是在：

> 持续执行 next-token 决策。

## 这一章最重要的路线图

请把这条链稳定地记住：

1. 模型最后一个位置先产出 logits  
2. softmax 把 logits 变成分布  
3. 某种解码策略从分布中决定一个 token  
4. 这个 token 再被追加到上下文中  
5. 最终 token 序列才会被 tokenizer 还原成文本  

只要这条路线图不丢，后面你再看 greedy、temperature、top-k、top-p 时，就知道它们不是在“改模型结构”，而是在改：

> 从分布走向具体 token 的决策规则。
