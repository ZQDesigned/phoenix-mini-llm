# 02. 从 logits 到下一个 token

## 这一章在整条主线里真正负责补哪一道认知断层

上一章已经把生成循环的最外层骨架搭出来了：

- 给定当前前缀
- 前向一次模型
- 取最后一个位置
- 决定下一个 token
- 把这个 token 接回上下文

这条描述对“流程感”很有帮助，但里面还藏着一条非常大的认知断层。

用户肉眼看到的是：

- 模型写出了一个字
- 模型吐出了一个词
- 模型继续写了一段文本

而模型主体真正直接给出的，却不是：

- 字符串
- 已经决定好的 token
- 甚至不是一个真正归一化的概率分布

它更接近于：

> 对整个词表的一组原始打分，也就是 logits。

如果这一层不讲透，后面所有采样参数都会显得像神秘按钮。

因为你根本不知道：

- temperature 在缩放什么
- top-k 和 top-p 在裁掉什么
- greedy 为什么看起来“更稳”，但又为什么更容易保守和重复
- 同一个 prompt 为什么在不同采样下会像换了一个模型

所以这一章真正要回答的问题很明确：

> 模型在每一步到底输出了什么？那组输出怎样从张量、分数和分布，一步一步变成用户最后看到的下一个 token？

## 先把一句非常常见但技术上太粗的话改写掉

日常交流里我们常说：

> 模型输出了一段文本。

这句话对用户体验层面完全没问题。
但如果拿它来理解模型内部发生的事，就会太粗糙。

更准确的链条其实是：

1. 模型对词表中所有候选 token 给出一组分数
2. 这组分数被解释成一种可形成分布的对象
3. 解码策略根据这组分布或分数做出一个离散选择
4. 选出的 token id 再被 tokenizer decode 成可读文本片段

也就是说，模型不是直接“吐出文字”。
它更像是在做这样一件事：

> 先对整个词表进行一次条件打分，再由解码过程把这种打分压成一个真正写出的离散下一步。

一旦这条链建立起来，生成就会从“神秘产出文本”重新变回：

- 隐藏状态
- 词表打分
- 分布形成
- 离散选择
- tokenizer 还原文本

这五段连续数据流。

## logits 到底是什么

最实用、最不绕弯的定义是：

> logits 是模型在当前上下文条件下，对词表中每个候选 token 给出的未归一化相对偏好分数。

这句话里每个词都很重要。

### “对词表中每个候选 token”

如果词表大小是 `V`，那么单步 logits 通常就是一个长度为 `V` 的向量。

也就是说，模型每一步都不是只想两个、三个候选。
它会对整个词表都给出一个分数。

### “未归一化”

这意味着这些数值：

- 不需要在 `0` 到 `1` 之间
- 不需要相加等于 `1`
- 可以是任意实数

所以 logits 不是概率。

### “相对偏好”

真正有意义的，不是某个 logit 的绝对数值，而是：

- 它和其他 token 分数相比高多少、低多少
- 前几名之间是否非常接近
- 第一名和长尾之间间隔有多大

也就是说，logits 更像：

- 一个候选排序地形

而不是：

- 已经完成解释的概率输出

### “当前上下文条件下”

同一个 token 在不同上下文下可以有完全不同的 logit。

这说明 logits 不是词本身的固定属性，而是：

> 当前前缀和当前模型参数共同作用后的条件判断结果。

## 从张量形状看，logits 究竟长什么样

这一步非常重要，因为很多人概念上知道模型会输出词表分数，但没有把它和前向张量流真正对上。

假设：

- batch size 是 `B`
- 当前序列长度是 `T`
- 模型隐藏维度是 `H`
- 词表大小是 `V`

在 decoder-only 语言模型里，经过多层 block 之后，你通常会得到某种最终隐藏表示：

\[
[B, T, H]
\]

然后通过最后的归一化和输出头，把每个位置的隐藏状态投影到词表维度：

\[
[B, T, V]
\]

这就是整段序列每个位置对应的 logits。

也就是说：

- 第 0 维区分不同样本
- 第 1 维区分序列中的不同位置
- 第 2 维区分词表中不同候选 token

这个张量视角非常关键，因为它揭示了一个容易被忽略的事实：

> 模型并不是只为“最后一个位置”准备输出，而是为序列里的每一个位置都准备了一整组词表分数。

只不过在推理时，我们通常只使用：

- 最后一个位置的那组 logits

来决定下一个 token。

## 为什么推理时通常只拿“最后一个位置”的 logits

这和训练阶段的行为不同，必须单独讲清楚。

在训练阶段，一整条样本里：

- 每个位置都要为右边的下一个 token 负责

因此：

- 整段序列的所有位置 logits

都可以参与 loss。

但在推理阶段，情况不同。

当当前前缀已经确定时，你真正想做的是：

> 基于整个已知前缀，决定“接下来”的那个 token。

这意味着：

- 对前缀内部更早位置的 logits，我们此刻通常不需要再重新做离散选择
- 真正相关的是当前前缀末尾那个位置的输出

因此，在推理单步中，更常见的做法是：

- 前向得到 `[B, T, V]`
- 取最后一个位置 `T-1`
- 得到 `[B, V]`
- 再从这组词表分数里选择一个 token

所以“取最后一个位置”不是框架习惯，而是：

> 自回归生成在时间上只需要决定下一步，因此当前只关心当前最末端位置对未来一步的预测。

## 为什么 logits 不是概率，但又已经几乎包含了选择结构

这一步的微妙之处在于：

- logits 不是概率
- 但它们又确实已经足够决定很多行为

例如：

- 如果某个 token 的 logit 比所有别的都高很多
- 那么即使还没做 softmax
- 你也已经知道它大概率会是最被偏好的候选

这是因为 softmax 虽然会把 logits 变成概率，但它不会随便打乱排序。

换句话说：

> logits 虽然不是概率，却已经携带了“谁更被偏好”这件最核心的结构信息。

这也是为什么很多推理调试里，工程师会先看 logits 的排序、间隔和相对形状，而不是只看最终采样结果。

## 为什么模型不直接输出概率

这是一个非常自然的问题：

> 如果最终目的是从候选中选一个 token，为什么不让模型直接输出概率，而要先输出 logits？

更完整的回答至少有四层。

### 第一，线性输出头天然先给出的是分数

模型最后一步通常是一个线性投影：

\[
H \rightarrow V
\]

这种投影非常自然地产生：

- 每个词表项一个未归一化分数

也就是 logits。

### 第二，训练时 logits 和交叉熵配合更自然

在数值实现上，深度学习框架通常更喜欢直接接收 logits，再在内部以数值稳定的方式组合：

- softmax
- log
- negative log likelihood

这比你手动先做 softmax 再传进去通常更稳。

### 第三，推理时我们常常还想在“变成概率之前”或“刚变成概率之后”再做控制

例如：

- temperature 实际会改变 logits 的相对间隔
- top-k / top-p 会对候选空间做裁剪
- 某些约束解码会对特定 token 做屏蔽或偏置

如果没有保留 logits 这个原始接口，很多控制都会不方便。

### 第四，logits 是训练和推理都适用的统一边界

它既能被训练目标自然使用，也能被推理协议进一步加工。

因此，logits 不是绕路。
它恰恰是：

> 模型主体和外部训练/推理机制之间最自然的接口层。

## softmax 在这里到底完成了什么

一旦我们有了某个位置对应的一组 logits：

\[
z_1, z_2, \ldots, z_V
\]

softmax 会把它们变成：

\[
p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}
\]

这一步做了两件本质上非常重要的事。

### 第一，把任意实数分数变成正值权重

因为指数函数总是正的。

### 第二，把这些权重归一化成和为 1 的分布

于是输出就从：

- 一组原始偏好分数

变成：

- 一个对词表的条件概率分布

这不仅是数值变换，更是语义切换。

## softmax 不是附带步骤，而是语义切换点

从 logits 到 softmax，最大的变化不在公式，而在意义。

### logits 的语义是

> 当前上下文下，对不同 token 的原始相对偏好。

### softmax 后的语义是

> 当前上下文下，对词表所有 token 的归一化条件分布。

这种变化很重要，因为后面所有采样策略都必须站在某种分布解释上工作。

如果你没有把这一步看清，后面就会误以为：

- temperature 只是“加一点随机性”
- top-p 只是“让结果更自然”

而实际上它们都在操作：

- 分布形状
- 候选空间
- 以及最终离散选择发生的概率地形

## 一个很关键的性质：加同一个常数，不会改变 softmax 分布

这是一个非常值得建立的直觉。

如果你把一整组 logits 都加上同一个常数 `c`：

\[
z_i' = z_i + c
\]

softmax 得到的分布不会改变。

为什么？

因为：

\[
\frac{e^{z_i+c}}{\sum_j e^{z_j+c}} = \frac{e^c e^{z_i}}{e^c \sum_j e^{z_j}} = \frac{e^{z_i}}{\sum_j e^{z_j}}
\]

这说明什么？

说明 softmax 真正关心的不是：

- 分数整体抬高了多少

而是：

- 分数之间的相对差距

这也是为什么 logits 更像一张相对偏好地形图，而不是一堆有绝对刻度意义的分数。

## 另一个更重要的性质：缩放会改变分布尖锐程度

如果加常数不改变分布，那么缩放呢？

如果把 logits 整体乘以一个系数，情况就不同了。

例如：

\[
z_i' = \frac{z_i}{\tau}
\]

这里的 `\tau` 就是 temperature 的核心形式。

它会改变：

- 前几名和其他候选之间的相对间隔被放大还是缩小

于是分布会变得：

- 更尖锐
- 或更平缓

这一步之所以重要，是因为它让你第一次真正看见：

> 解码不是在“凭空随机一下”，而是在改变同一组 logits 被解释成分布时的形状。

所以 softmax 和 temperature 应当一起理解，而不是拆开理解。

## 为什么最大概率 token 不等于“唯一正确输出”

很多人学到 softmax 后，会自然想：

> 那我就取概率最大的 token，不就行了吗？

这当然是一种完全合法的策略，也就是：

- greedy decoding

但问题在于，语言分布经常不是单峰且唯一无争议的。

在很多上下文下，可能会有：

- 多个都合理的后续
- 若干风格不同但都通顺的候选
- 一些次优但仍自然的延续方式

因此，“概率最大”并不等于：

- 这是唯一对的那个 token

它只意味着：

> 在当前模型看来，这是最被偏好的那个候选。

这个区分非常重要。

因为如果你把“最高概率”误解成“唯一答案”，那你后面很难真正理解：

- 为什么采样仍然有意义
- 为什么同一 prompt 会有多种高质量继续方式
- 为什么模型输出分布比单一路径更接近语言本身

## argmax 到底做了什么

当你使用 greedy 解码时，本质上你在做的是：

- 找到 logits 或 softmax 概率最大的那个索引

从数学上讲，softmax 不改变排序，所以：

- 对 logits 做 argmax
- 或对 softmax 后概率做 argmax

得到的 token 是一样的。

这说明 argmax 其实是在做一件很强的压缩：

> 把整个分布压成一个单点选择。

这种选择的优点是：

- 稳定
- 可复现
- 不引入额外采样随机性

但缺点也很明显：

- 更容易走向最保守的高频路径
- 更容易过早进入重复或模板化
- 对次优但有创造性的分支完全不给机会

因此，argmax 不是“最正确”的通用选择。
它只是：

- 对分布的一种极端使用方式

## 从概率分布到真正抽样，中间到底发生了什么

如果你不采用 greedy，那么下一步通常就是：

- 按某种分布去采样

这和 argmax 的区别非常大。

argmax 在说：

- 只看第一名

采样在说：

- 保留整个候选空间的相对概率结构
- 再从中真正抽一个结果

因此，在采样模式下：

- 第一名不再总是被选中
- 第二名、第三名，甚至更后面但仍保留一定概率的 token 也有机会出现

这会让输出更有变化性，也更接近“从分布中生成”的原意。

但这同时也意味着：

- 单次样例方差更大
- 低概率错误路径更容易被偶尔采出来

所以，从 logits 到 token 的过程，不只是模型主体在做事。
解码策略也在一起决定：

> 你到底怎样把这张概率地形图压成一条真实走出来的路径。

## 为什么 top-k 和 top-p 不该被理解成“风格参数”

很多人第一次用这些参数时，会把它们理解成：

- 一个让文本更有创意
- 一个让文本更稳定

这种说法对用户体验层面也许有点帮助，但在技术层面太模糊。

更准确地说：

- top-k 是在把候选空间裁成“前 k 个 token”
- top-p 是在把候选空间裁成“累计概率质量达到 p 的最小集合”

它们真正改变的是：

- 哪些 token 有资格被采样

而不是：

- 直接给模型加了什么风格人格

也就是说，它们都建立在 logits -> 分布 这条链已经存在的前提下。

只有这条链清楚，后面的采样策略才真正有地基。

## token id 还不是文本：为什么 tokenizer decode 仍然是关键一步

很多初学者在看到“选出了下一个 token”时，会下意识以为：

- 文本已经出来了

但严格来说，到这一步你拿到的往往还只是：

- 一个词表索引

这个索引怎样变成人类看到的文本，还取决于 tokenizer 的 decode 规则。

这一步为什么重要？

因为语言模型里 token 和人类直觉里的“词”往往不是一一对应的。

一个 token 可能是：

- 一个完整词
- 一个子词片段
- 一个前缀或后缀
- 一个空格加上后面的词干
- 一个字节序列片段

因此，从 token id 到可读文本，并不是简单查表替换那么肤浅。
它实际上依赖于：

- tokenizer 当初是怎样定义词表单元的
- whitespace 和标点怎样被编码
- 特殊 token 是否需要被跳过

所以在推理调试里，一个经常被低估的事实是：

> 有时候看起来像“模型生成奇怪文本”，其实问题一部分可能来自 token 切分或 decode 方式本身。

## 为什么“下一个 token”不等于“下一个词”

这也是必须尽早澄清的一点。

很多人说语言模型在预测“下一个词”，这在非常粗略的层面勉强能用。
但对现代 subword tokenizer 来说，这常常并不准确。

模型更常见的真实任务是：

> 预测下一个 token 单元。

而这个 token 单元可能只是：

- 一个词的一部分
- 一个词前面的空格加一段词干
- 一个特殊标记

这会直接影响你理解推理现象。

例如：

- 为什么模型看起来像“先生成了半个词”
- 为什么某些语言或代码里 token 边界很碎
- 为什么 top-k/top-p 在不同 tokenizer 下体感会不同

所以如果你把 token 和词混为一谈，很多细节会一直显得奇怪。

## 一个极小的数值例子：从 logits 到 token 真的发生了什么

假设某一步词表只有 5 个候选：

```text
[A, B, C, D, E]
```

模型给出的 logits 是：

```text
[2.0, 1.2, 0.3, -0.7, -1.4]
```

从 logits 角度看，你已经能读出一些结构：

- `A` 最被偏好
- `B` 次之
- `C` 还有一定可能
- `D`、`E` 明显更弱

如果做 softmax，得到的将是一组和为 1 的概率。

即便你不精确计算，也能看见：

- `A` 会占最大头
- `B` 仍保留一定质量
- 后面候选快速衰减

如果使用 greedy：

- 就会直接选 `A`

如果使用带一定温度的采样：

- `A` 仍然最可能被选中
- 但 `B`、甚至偶尔 `C` 也可能被抽中

如果再套上 top-k=2：

- 那么 `C`、`D`、`E` 将失去被采样资格

这整个例子说明：

> 从 logits 到 token，并不是一步跳转，而是一系列对“同一组偏好分数”的解释、裁剪和离散决策。

## 为什么高层生成行为会对 logits 形状极其敏感

只要理解了前面的链条，你就会明白：

- 最终是否重复
- 是否发散
- 是否保守
- 是否容易跑偏

这些行为都不只是“文本层现象”。
它们往往深深依赖于 logits 分布的形状。

例如：

- 如果前几名差距极大，greedy 和采样可能表现得很接近
- 如果前几名差距很小，采样会表现出更大分岔
- 如果长尾整体仍保留较高质量，高温采样就更容易走到不稳定区域

因此，解码调试本质上经常是在读：

- 分布形状

而不仅仅是在读：

- 输出文本表面

## 为什么训练时的交叉熵和推理时的 logits 是同一条链上的两端

这一点对整体理解非常重要。

训练时，模型在每个位置输出 logits。
然后交叉熵会问：

> 真实下一个 token 在这组 logits 所形成的分布里，位置是否足够高、概率是否足够大？

也就是说，训练阶段其实一直在做这样一件事：

- 让正确 token 在 logits 排序和概率分布里占据更合理的位置

而推理时，你只是把这件事换了一种使用方式：

- 不再直接拿真实 token 算 loss
- 而是从这组 logits 出发，真正做出一个下一个 token 选择

这说明训练和推理不是两套完全无关的体系。
它们共享同一个中间核心对象：

- logits

所以如果你真正理解 logits，训练目标和解码行为之间的关系就会清楚很多。

## 为什么“模型输出错了”有时应该先看 logits，而不是先看文本

很多初学者一看到生成结果不对，第一反应就是：

- 这段文本看起来不自然
- 这句答非所问
- 这段为什么重复

当然，文本现象很重要。
但如果要调试，常常需要再往里走一层：

> 当前这一步的 logits 长什么样？

例如：

- 正确 token 是否本来就在前几名里
- 错误 token 是不是因为采样才被选中
- 概率头部是否过于平坦
- 某些特殊 token 是否被异常抬高

这些问题只有回到 logits 层才能真正回答。

所以调试推理时，经常要建立一个新习惯：

- 不只看“模型写了什么”
- 还要看“模型当时到底在偏好什么”

## 为什么单次输出不能完整代表这一步的 logits 质量

这是另一个非常关键的现实。

最终用户看到的通常只有：

- 一个被选中的 token

但这个 token 只代表：

- 在当前策略下，从这张分布里走出的单一路径

它并不能完整告诉你：

- 第二名是不是也很合理
- 第三名是否和第一名几乎打平
- 整个分布是不是过平或过尖

因此，单次 token 选择只是 logits 分布的一次样本化或极端压缩结果。

如果你把它误认为：

- 模型内部判断的全部

那么你会错过很多真正重要的信息。

## 从工程实现看，常见调试打印为什么会包含 top-n token

很多推理调试工具不会只打印最终选中的 token。
它们还会打印：

- 前 5 名或前 10 名 token
- 各自对应概率

这不是多余信息。
它的价值在于：

- 让你看到模型到底是在“明显偏向某一候选”，还是“前几名非常接近”
- 让你区分模型本身没想到正确答案，还是正确答案想到但被采样错过

这种区分对调试非常关键。

因为：

- 如果正确候选根本不在高排名里，问题更可能在模型或数据
- 如果正确候选本来就在前几名里，问题更可能在解码策略或采样温度

这就是为什么“从 logits 到 token”必须被当成一条可观测链，而不是黑箱跳转。

## 初学者在这里最容易犯的几个误解

### 误解一：模型直接输出文本

实际上模型先输出的是词表级 logits。

### 误解二：logits 就是概率

实际上 logits 只是未归一化相对偏好分数。

### 误解三：softmax 只是可有可无的数学步骤

实际上它是从分数到分布的语义切换点。

### 误解四：选出 token 之后，token 和词就是一回事

实际上 tokenizer 的子词切分会让这个关系复杂得多。

### 误解五：生成好坏只看最后选中的 token

实际上分布形状和候选排序本身往往更值得调试。

## 小结

这一章最核心的结论可以压缩成一句话：

> 语言模型并不是直接输出文本，它先在每一步对整个词表给出一组未归一化相对偏好分数，也就是 logits；这些 logits 经过 softmax 形成条件分布，再由 greedy 或采样等解码策略压成一个离散 token，最后再通过 tokenizer decode 变成用户看到的文本片段。

一旦这个认识站稳，生成过程就不再像“模型神秘地吐字”。
它会重新变成一条可分析的数据流：

- 隐藏状态
- 词表打分
- 分布形成
- 解码策略
- token 还原文本

而这正是后面真正理解采样、重复、困惑度和调试的基础。
