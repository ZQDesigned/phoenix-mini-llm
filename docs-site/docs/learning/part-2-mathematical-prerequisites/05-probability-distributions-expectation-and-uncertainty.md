# 05. 概率分布、期望与不确定性

## 为什么语言模型天然会把我们带到概率

如果你把语言模型理解成：

> 给定前文，输出下一个 token

那么很容易误以为它是在做某种“唯一正确答案”任务。

但真实情况通常不是这样。

例如前文是：

```text
今天的天气真
```

后面可能接：

- 好
- 热
- 冷
- 不错

这些候选并不是完全等价，但也很少只有一个绝对唯一答案。

这说明语言模型更自然的任务形式是：

> 给定上下文，对多个可能后续给出一组相对可能性。

这就是分布预测。

## 什么是概率分布

概率分布最朴素的理解是：

> 当结果不止一种时，我们给每个候选结果分配一个发生可能性的大小。

一个合法分布通常满足：

- 每项都不小于 0
- 所有项加起来等于 1

例如：

```text
A: 0.6
B: 0.3
C: 0.1
```

在语言模型里，`A/B/C` 不再是几个简单字母，而是整个词表中的大量 token。

## 为什么模型输出的是分布，不是答案本身

这是因为模型面对的是不确定世界。

在很多上下文里：

- 多个延续都可能合理
- 某个候选只是更常见，而不是绝对正确
- 语言本身具有风格、开放性和多样性

如果模型只能给一个硬答案，它会失去大量关于“不确定性”的信息。

而分布能表达：

- 哪些候选更可能
- 哪些候选虽然可能，但不太像
- 当前模型对结果有多确定

这在生成、采样和评估时都很重要。

## 条件概率为什么是任务定义本身

语言模型不是在预测一个孤立 token，而是在预测：

\[
P(t_{k+1} \mid t_1, t_2, \dots, t_k)
\]

也就是：

> 已知前文时，下一个 token 的条件概率分布。

这里最关键的是“条件”两个字。

同一个 token 在不同前文下，概率可能完全不同。

所以语言模型的核心不是学“词本身有多常见”，而是学：

> 在不同上下文条件下，哪些 token 更容易出现。

## 什么叫不确定性

不确定性可以简单理解成：

> 当前我们还不能把概率几乎全部压到单一候选上。

有些上下文非常确定，例如：

```text
1 + 1 =
```

有些上下文则开放得多，例如：

```text
春天来了，我想起了
```

模型输出分布的价值就在于，它既能表达非常确定的局面，也能表达开放、分散的局面。

## 期望为什么值得提前认识

期望可以先理解成：

> 按照概率加权之后的平均结果。

你现在不一定需要马上做复杂计算，但要知道这个想法为什么重要：

- 训练时我们常常在对一批样本做平均
- 一个损失不是只看单个例子，而是看整体表现
- 很多“模型表现”本质上都是在观察某种期望行为

所以期望是把“单个样本发生了什么”过渡到“整体平均效果怎样”的桥梁。

## 为什么“平均”在机器学习里如此常见

因为我们通常不想让模型只对一个样本好，而是希望它在整体数据分布上都更好。

这意味着我们关心的不是某一次幸运预测，而是：

> 当样本不断从数据分布中抽出来时，模型平均会表现成什么样。

这就是为什么 batch loss、平均指标、验证集表现都会出现“求平均”的思想。

## 分布预测会怎样进入训练

一旦模型输出的是分布，下一个自然问题就是：

> 我怎么判断这组分布对不对？

这里就会走向后面几章的内容：

- logits
- softmax
- 交叉熵
- 对数概率

但在进入这些具体工具之前，你必须先接受一个更基础的事实：

> 语言模型训练的对象从一开始就是分布，而不是单个离散答案。

## 这一章结束后最重要的收获

你应该至少稳定理解：

- 语言模型面对的是条件分布预测任务
- 分布比“唯一答案”更适合表达语言的不确定性
- 期望帮助我们从单个样本走向整体平均表现
- 后面的损失函数其实是在衡量“模型给出的分布有多像目标分布”

这样进入 softmax 和交叉熵时，你就不会觉得它们是凭空出现的数学工具。
