# 07. 对数、信息量与为什么损失常写成对数概率

到上一章为止，你已经建立了一个非常关键的判断：

> 当任务天然存在多种可能结果时，模型最自然的输出形式不是直接宣布唯一答案，而是在候选空间上给出一张概率分布。

这已经让语言模型的目标比“普通分类题”清楚了很多。

但新的问题立刻会出现：

> 如果模型已经给出了概率分布，我们到底应该怎样评价它“分得好不好”？

很多初学者在这里第一次遇到一批容易让人本能警惕的词：

- `log`
- 对数概率
- 负对数似然
- 交叉熵
- 困惑度

如果这一步处理不好，就会出现一种很典型的学习断裂：

> 前面我还能理解模型在预测概率，为什么一到训练目标这里，突然全变成看起来很抽象的数学记号？

这一章的任务，就是把这条断裂缝上。

你不需要把它理解成一堂孤立的信息论课。
更准确地说，它在回答一个极其务实的问题：

> 当模型已经输出了一个分布，我们为什么通常不直接拿“原始概率”当训练目标，而要把它写成对数概率，甚至负对数概率？

一旦这个问题讲顺，后面很多看似分散的概念就会连成一条线：

- 序列概率为什么是连乘
- 为什么对数会把它改写成求和
- 为什么最小化负对数概率等价于最大化模型给真实答案的概率
- 为什么交叉熵是自然出现的
- 为什么困惑度会和 loss 联动

## 1. 先把对数本身讲清楚：它到底在问什么

很多人一看到 `log` 就会本能紧张。

这往往不是因为对数本身特别难，而是因为它在学校里经常先以定义和公式的形式出现，直觉却没有先站稳。

这里先用最朴素的语言说：

> 对数是在问：为了得到某个数，底数要把自己乘多少次？

例如：

\[
2^3 = 8
\]

那么：

\[
\log_2 8 = 3
\]

它的意思不是别的，就是：

> 以 2 为底，要把 2 连乘多少次，才能得到 8？

同理：

\[
10^2 = 100
\]

所以：

\[
\log_{10} 100 = 2
\]

这说明一件很基本的事：

> 对数本质上是指数运算的反方向问题。

只要这句直觉稳住，后面那些看上去更复杂的表达其实都还是在同一条线上。

## 2. 为什么机器学习里经常只写 `log`

你会发现很多机器学习材料直接写 `log`，并不总强调底数是 `2`、`10` 还是 `e`。

这并不是偷懒，而是因为在很多推导与实现里，我们更关心的是对数的结构性质：

- 它是不是单调变换
- 它能不能把乘法变加法
- 它在微积分和优化里是否方便

至于底数具体是什么，会影响数值尺度，却通常不会改变最核心的优化判断。

在机器学习里最常见的是自然对数，也就是以 \(e\) 为底的对数。
你不需要此刻把 \(e\) 看成某个神秘常数，只要先记住：

> 在连续优化和微积分里，自然对数经常最方便，所以工程实现里大量默认用它。

## 3. 对数的第一个核心价值：它把乘法变成加法

这是整章最值得反复记住的性质：

\[
\log(ab) = \log a + \log b
\]

如果有很多项相乘，同样成立：

\[
\log(a_1a_2\cdots a_n) = \log a_1 + \log a_2 + \cdots + \log a_n
\]

这条性质为什么重要？

因为只要你开始处理序列概率，就几乎注定会不断遇到很多概率项被乘在一起。

如果没有对数：

- 目标长成连乘
- 数值会变得极小
- 每一项对整体的贡献不容易拆开理解

一旦取对数：

- 连乘变成求和
- 每个位置的贡献可以单独读
- 求平均、比较和优化都会更自然

所以对数在这里不是“为了复杂而复杂”。

它是在做一件非常务实的事：

> 把原本难处理的乘法链条，改写成更容易分析和优化的加法结构。

## 4. 为什么语言模型里的序列概率天然是连乘

语言模型不是一次性判断整段文本“整体上对不对”。

它的基本任务形式是：

> 给定前面的 token，预测下一个 token 的条件概率。

设一段序列是：

\[
x_1, x_2, x_3, \ldots, x_T
\]

那么整段序列的联合概率可以按条件概率链写成：

\[
P(x_1, x_2, \ldots, x_T)
=
P(x_1)
P(x_2 \mid x_1)
P(x_3 \mid x_1, x_2)
\cdots
P(x_T \mid x_{<T})
\]

这里最重要的不是公式本身，而是它表达的结构：

- 整段文本不是靠一个神秘总分直接定义
- 它是许多局部条件判断连起来的结果
- 每个位置都在问“在已有历史下，下一个 token 有多可能”

只要你接受语言模型的目标是这条条件概率链，后面就会自然接受另一件事：

> 整段序列的概率，本来就会是许多小于 1 的数相乘。

这也正是对数一定会出现的根本原因。

## 5. 为什么原始序列概率会小得离谱

很多初学者第一次看到整段文本概率时会很不适应。

因为哪怕模型已经做得不错，整段概率的数值看起来也会非常小。

这其实完全正常。

我们用一个很温和的例子来感受一下。

假设一段很短的序列有四个可预测位置，模型给真实 token 的条件概率分别是：

- `0.8`
- `0.6`
- `0.5`
- `0.7`

那么整段概率就是：

\[
0.8 \times 0.6 \times 0.5 \times 0.7 = 0.168
\]

只是四步而已，整体概率已经明显变小。

如果序列很长，例如有一百个位置，而每一步真实 token 的平均概率哪怕达到 `0.2`，那么整体就是：

\[
0.2^{100}
\]

这个值会小到几乎不适合作为直觉分析对象。

所以在语言模型里，“整段概率很小”往往并不意味着模型很差。
更常见的原因只是：

> 长序列整体概率天然是很多小于 1 的条件概率连续相乘出来的。

这就是为什么你不能天真地拿“整段原始概率本身”直接当作训练和分析的核心读数。

## 6. 对数的第二个核心价值：它把极小值拉回更可读的尺度

对数除了把乘法变成加法，还有一个非常现实的效果：

> 它会压缩数值尺度。

很大的数取对数之后会没那么夸张；
很小的正数取对数之后会变成负数，但比较关系更容易读。

例如：

- \(\log(1) = 0\)
- \(\log(0.5)\) 是一个负数
- \(\log(0.01)\) 会更负

这意味着：

- 概率越接近 1，对数越接近 0
- 概率越小，对数越负

所以我们不必继续和极小概率值直接对打，而可以把它们搬到对数空间里。

这一步在数值和解释上都很关键。

## 7. 为什么对数概率通常是负的

只要概率 \(p\) 落在 \(0\) 和 \(1\) 之间，那么：

\[
\log p \le 0
\]

这并不神秘。

原因很简单：

- 小于 1 的数，不管以什么常见底数取对数，结果都会是负的
- 等于 1 时，对数才是 0

所以当你在训练里看到“对数概率是负数”时，不必惊慌。
这几乎是概率本身范围决定的自然结果。

更重要的是理解它在表达什么：

- 如果真实答案概率很高，那么对数概率更接近 0
- 如果真实答案概率很低，那么对数概率会变得更负

这已经隐含了一个非常有用的评价趋势：

> 越把真实答案看得不可能，对数概率就越小。

## 8. 为什么最大化概率，等价于最小化负对数概率

训练时，我们通常会把“希望模型给真实答案更高概率”写成一个最小化问题。

这里的关键就在于：

\[
-\log p
\]

当 \(p\) 变大时，\(-\log p\) 会变小；
当 \(p\) 变小时，\(-\log p\) 会变大。

所以：

- 最大化真实答案概率
- 最大化真实答案对数概率
- 最小化真实答案负对数概率

这三件事在优化方向上是一致的。

这是一个极其重要的桥。

因为它告诉你：

> 训练里常见的负对数形式，并不是把目标改掉了，而只是把同一个目标换成了更适合计算和优化的写法。

## 9. 为什么不直接用 `1 - p`

很多初学者第一次见到负对数概率时，都会本能地问：

> 如果我只是想让真实答案概率更高，为什么不直接用 `1 - p` 当损失？

这个问题非常好，因为它正好能帮你看清对数形式的优势。

### 第一，它和序列概率天然兼容

语言模型处理的不是单个位置，而是整条概率链。

当整体目标本来就是许多条件概率相乘时，对数能把它们直接改写成求和。
而 `1 - p` 没有这种结构优势。

### 第二，它会更严厉地惩罚“把真实答案看得极不可能”的错误

如果真实答案概率从 `0.9` 掉到 `0.8`，当然是变差了。
但如果从 `0.1` 掉到 `0.01`，这类错误的严重程度显然更大。

负对数正好能更敏感地放大这种差别。

### 第三，它会把概率、似然、信息量和交叉熵压到同一条主线上

这意味着后面的很多概念不会散掉，而会顺着同一套语言继续展开。

所以不是说 `1 - p` 在任何场景都毫无意义。
而是对语言模型这种序列条件概率任务来说，负对数形式天然更顺。

## 10. 为什么负对数概率会更重罚极低概率错误

观察一下 \(-\log p\) 的形状就很直观了。

当 \(p\) 接近 1 时，\(-\log p\) 很小，而且变化相对温和。
但当 \(p\) 逼近 0 时，\(-\log p\) 会迅速变大。

这意味着：

- 把真实答案从 `0.95` 降到 `0.85`，损失会变大，但增长有限
- 把真实答案从 `0.1` 降到 `0.01`，损失会暴涨很多

这非常符合训练直觉。

因为如果模型只是把第一名压得没那么稳，问题和“它几乎把真实答案判成不可能”不是一个量级。

负对数正好把这种差别体现出来。

## 11. 对数让长序列目标自然变成位置求和

这一点对语言模型至关重要。

从前面我们知道，整段序列概率是许多条件概率的连乘：

\[
P(x_1,\ldots,x_T)=\prod_{t=1}^{T} P(x_t \mid x_{<t})
\]

取对数之后，立刻变成：

\[
\log P(x_1,\ldots,x_T)=\sum_{t=1}^{T} \log P(x_t \mid x_{<t})
\]

如果再取负号，就得到：

\[
-\log P(x_1,\ldots,x_T)=\sum_{t=1}^{T} -\log P(x_t \mid x_{<t})
\]

这句话非常重要，因为它等于在说：

> 整段序列的训练代价，可以自然地拆成每个位置上“真实 token 被看得多不可能”的代价之和。

这正是后面 next-token loss 的核心形态。

它解释了为什么语言模型训练时会天然落成：

- 按位置计算
- 按 token 累积
- 再做平均

## 12. 为什么训练里常常还要再除以 token 数

如果你只做总和，那么长序列会天然拥有更大的绝对损失值。

这在某些场景下可以接受，但在训练和日志解读里常常不方便。

因为你通常更想知道的是：

> 平均每个 token 上，模型把真实答案看得有多不可能。

于是很自然地会再做一步：

\[
\frac{1}{T}\sum_{t=1}^{T} -\log P(x_t \mid x_{<t})
\]

这并不是把目标换掉，而是把“整段总代价”规范成“平均每个位置的代价”。

这一步会直接影响：

- 不同长度样本之间的可比性
- 训练日志的稳定解释
- perplexity 与 loss 的关系

## 13. 什么是似然，为什么它会在训练里自然出现

“似然”这个词很容易吓到人，其实概念并不复杂。

最朴素地说，当你手里已经有一份观测数据，而你想问：

> 在当前模型参数下，这份数据被模型解释得有多像真的会出现？

你看的就是似然。

如果模型参数记作 \(\theta\)，数据记作 \(x\)，那么：

\[
P(x \mid \theta)
\]

可以被理解成：

> 参数为 \(\theta\) 的模型，对观测数据 \(x\) 赋予了多大概率。

在训练里，你当然希望这件事尽量大。

也就是说，训练可以理解成：

> 找一组参数，让训练数据在这组参数下尽可能“像模型认为会发生的东西”。

这就是最大似然估计背后的最核心直觉。

## 14. 什么是负对数似然

既然我们希望似然大，那么直接最大化似然当然是一个自然想法。

但从前面的讨论我们已经知道：

- 概率连乘会极小
- 对数会把连乘变求和
- 最小化负对数等价于最大化原始概率

于是训练里更常见的写法就成了：

\[
-\log P(x \mid \theta)
\]

这就是负对数似然。

对于语言模型来说，它往往进一步展开成：

\[
\sum_{t=1}^{T} -\log P(x_t \mid x_{<t}, \theta)
\]

所以“负对数似然”不是另一个突然出现的新目标。
它只是把“让模型给真实序列更大概率”用更适合训练的形式写了出来。

## 15. 从“惊讶”理解负对数概率

理解负对数概率还有一个非常有力的直觉：惊讶。

如果某件事模型本来认为很可能发生，那么当它真的发生时，模型并不会太“惊讶”。
对应地，\(-\log p\) 会比较小。

如果某件事模型本来觉得几乎不可能发生，但它偏偏发生了，那么模型就会非常“惊讶”。
对应地，\(-\log p\) 会很大。

所以：

\[
-\log p
\]

可以被看成：

> 在当前模型分布下，真实结果带来的惊讶程度。

这条直觉非常重要，因为它能把信息论那套语言重新接回训练直觉：

- 概率越低，惊讶越大
- 惊讶越大，损失越大

## 16. 为什么信息量会自然长成负对数

信息论里，一个很核心的量叫作信息量。

最朴素的直觉是：

> 越不常见、越不容易提前猜到的事件，一旦发生，带来的“新信息”就越多。

这非常符合直觉。

例如：

- “明天太阳从东方升起”几乎不会让你获得多少新信息
- “明天凌晨上海下雪且积雪 20 厘米”如果发生，就会显得非常意外

而数学上，最自然满足这种直觉的一个形式，正是：

\[
I(x) = -\log P(x)
\]

因为它满足：

- 事件越稀有，概率越小，信息量越大
- 独立事件的联合信息量可以相加

这就把“负对数概率”从训练技巧，进一步连到了信息量。

## 17. 什么是熵

如果单个事件的信息量是：

\[
-\log P(x)
\]

那么一个分布整体的平均信息量就是：

\[
H(P) = E_{x\sim P}[-\log P(x)]
\]

这就是熵。

用直觉说，熵衡量的是：

> 从这个分布里抽样时，平均会带来多大惊讶。

如果一个分布非常尖，几乎总是落在少数几个结果上，那么平均惊讶较小，熵会较低。

如果一个分布很平，很多结果都差不多可能，那么平均惊讶较大，熵通常更高。

## 18. 高熵和低熵分别意味着什么

这个判断在语言模型里非常有用。

### 18.1 低熵通常意味着什么

低熵通常说明：

- 分布比较集中
- 模型觉得少数几个候选远比其他候选合理
- 当前判断相对明确

### 18.2 高熵通常意味着什么

高熵通常说明：

- 分布比较发散
- 多个候选都还保留不小的可能性
- 模型或任务本身仍然存在显著不确定性

这也是为什么后面温度调节、本身就是在部分地改写输出分布的熵特征。

## 19. 什么是交叉熵

现在终于可以走到训练里最常见的对象之一：交叉熵。

如果我们有两张分布：

- 真实目标分布 \(P\)
- 模型预测分布 \(Q\)

那么交叉熵可以写成：

\[
H(P, Q) = E_{x\sim P}[-\log Q(x)]
\]

这句话的意思是：

> 真实世界按 \(P\) 发生，而我们用模型分布 \(Q\) 来给这些真实结果打分时，平均会产生多大惊讶。

这一定义非常关键，因为它比“一个经验公式”更有解释力。

交叉熵不是平地冒出来的损失名词。
它是在回答一个非常具体的问题：

> 如果真实数据来自某个目标分布，而模型给出的是另一张分布，那么模型对真实数据平均有多意外？

## 20. 为什么分类和 next-token prediction 都会落成交叉熵

在普通分类任务里，目标通常是“正确类别是哪一个”。

这常常等价于一张 one-hot 分布：

- 正确类别概率是 1
- 其他类别概率是 0

这时交叉熵就会退化成：

\[
-\log Q(\text{正确类别})
\]

而在语言模型里，每个位置的 next-token prediction 本质上也是同样结构：

- 当前位置有一个真实下一个 token
- 模型给整张词表一张预测分布
- 我们看真实 token 在这张分布下被赋予了多少概率

因此，语言模型每个位置的损失自然也是交叉熵或等价的负对数似然。

这说明：

> 交叉熵并不是“分类专属公式”，而是在“真实答案来自一张目标分布，模型给出另一张预测分布”时最自然出现的目标之一。

## 21. 为什么说交叉熵就是“平均惊讶”

如果你不想先记公式，最值得记住的直觉就是：

> 交叉熵衡量的是模型面对真实数据时，平均会有多惊讶。

这句话非常有力量，因为它能帮助你统一理解很多现象：

- 交叉熵小，说明模型对真实数据没那么意外
- 交叉熵大，说明模型经常把真实答案看低了
- loss 下降，说明模型整体上越来越不对真实数据感到吃惊

这比死记“交叉熵是某某公式”更接近训练本质。

## 22. KL 散度为什么常和交叉熵一起出现

KL 散度经常会和交叉熵一起出现，但初学者此刻不用把它学得很重。

只需要先抓住一件事：

\[
H(P, Q) = H(P) + D_{KL}(P \parallel Q)
\]

这里的意思是：

- 真实分布自己的内在不确定性是 \(H(P)\)
- 模型分布和真实分布之间多出来的偏差，是 KL 散度

因此，最小化交叉熵，本质上会推动模型分布 \(Q\) 接近真实分布 \(P\)。

对 language modeling 来说，这正是我们想要的事情。

## 23. 为什么训练里常写 logits，而不是先显式写概率

代码里你经常会看到模型直接输出 logits，而不是显式输出概率。

这并不是因为概率不重要，恰恰相反，是因为：

> logits 是生成概率分布之前更适合数值计算和优化的中间表示。

模型先给每个候选一个未归一化分数。
然后通过 softmax，这些分数被压成合法分布。

所以训练时常见的做法不是：

1. 模型手工先算概率
2. 再手工取对数
3. 再手工算负对数损失

而是把 logits 直接交给数值稳定的交叉熵实现。

## 24. 为什么常用 `log_softmax`

如果你先算 softmax，再算 log，在数值上常常不够稳定。

更稳的做法是直接使用 `log_softmax` 一次性完成：

- 归一化
- 取对数

这样做的原因不是数学变了，而是工程上更稳：

- 防止数值上溢或下溢
- 避免不必要的中间误差
- 让实现更高效

所以 `log_softmax` 并不是另一套目标。
它只是同一条分布逻辑在工程实现里的更稳定写法。

## 25. 困惑度是什么，为什么它会和这里连起来

很多初学者会把 perplexity 也当成突然冒出来的新指标。

其实它和这里的主线完全连在一起。

如果平均每个 token 的负对数损失记作：

\[
L
\]

那么困惑度通常可以写成：

\[
\mathrm{PPL} = e^L
\]

或者在别的对数底下写成等价形式。

它的直觉可以理解成：

> 模型在每一步平均相当于还在多少个候选之间犹豫。

当然，这不是字面意义上的“真实候选个数”，而是一种用指数把平均惊讶重新翻译成人更容易感受的尺度。

所以困惑度不是脱离 loss 的另一个神秘体系。
它只是：

> 把平均负对数损失重新指数化后的另一种读法。

## 26. 为什么困惑度和 loss 会联动

既然困惑度本来就是由平均负对数损失指数化得到的，那么：

- loss 下降，perplexity 通常也会下降
- loss 上升，perplexity 通常也会上升

它们不是彼此独立的两个世界。

区别更多在于：

- loss 更直接地保留了训练目标本身的结构
- perplexity 更像把这种结构翻译成一个更便于人读的相对尺度

这就是为什么很多训练日志会同时看它们。

## 27. 为什么“训练 loss 下降”不总等于“生成观感一定更好”

这里必须补上一层非常重要的现实感。

前面我们一直在说：

- 负对数损失下降是好事
- 交叉熵下降说明模型对真实数据平均没那么惊讶了

这些都对。

但它们并不自动推出：

- 生成文本一定更自然
- 重复一定更少
- 对话一定更有帮助
- 长程一致性一定明显更强

原因在于，训练损失主要评价的是：

> 在训练目标定义下，模型对真实下一 token 分布的拟合程度。

而人类对生成质量的感受还会涉及：

- 解码策略
- 长程一致性
- 风格偏好
- 错误累积
- 任务形式和训练分布之间的偏差

所以 loss 是核心信号，但不是全部信号。

## 28. 为什么对数底数不是核心矛盾

有些初学者会担心：

> 如果我用自然对数，别人用以 2 为底的对数，会不会整个目标都不一样？

不用过度担心。

底数不同主要会改变数值尺度，相当于整体乘了一个常数因子。

这会影响：

- 你报告的具体数值大小
- 某些信息量单位的命名

但不会改变最本质的判断：

- 哪个模型更好
- 哪个预测更糟
- 为什么最小化负对数等价于最大化真实概率

所以底数是技术细节，不是这章真正的主矛盾。

## 29. 为什么这一章最终是在建立一张路线图

如果你现在回头看，会发现这章其实一直在搭一张连续路线图：

1. 语言模型输出的是条件概率分布。
2. 整段序列的概率是许多条件概率的连乘。
3. 连乘会导致极小数值，也不利于拆解分析。
4. 对数把连乘变成求和。
5. 负对数把“更高真实概率”翻译成“更小训练代价”。
6. 交叉熵把“模型预测分布”和“真实目标分布”接到一起。
7. 平均 token loss 与困惑度都只是这条主线上的不同读法。

这张路线图一旦稳住，后面你再看到：

- softmax
- cross entropy
- negative log likelihood
- perplexity

它们就不会再像散落术语，而会像同一机器里的连续齿轮。

## 30. 这一章最容易出现的误解

在收尾前，先把几种最常见的误解拆掉。

### 误解一：概率越小就说明模型一定很差

不是。

长序列整体概率天然会很小。
关键要看的是：

- 相对比较
- 平均每个位置的负对数代价

### 误解二：交叉熵只是经验公式

不是。

它是从分布比较、平均惊讶和负对数似然自然长出来的。

### 误解三：`-log p` 只是为了把负数变成正数

不是。

取负号只是表面现象。
真正重要的是：

- 更高真实概率对应更小代价
- 序列目标能被拆成求和
- 极低概率错误会被更强地惩罚

### 误解四：perplexity 比 loss 更“高级”

不是。

它更多是另一种读法，而不是另一个本体更强的目标。

### 误解五：一旦 loss 下降，生成质量就一定全面上升

不是。

loss 很重要，但它评价的是训练目标，不是全部用户体验。

## 31. 如果这一章最后只保留一句话

如果这一章最后只保留一句话，我希望是这一句：

> 对数概率之所以会成为语言模型训练的核心语言，不是因为它更花哨，而是因为语言模型本来就在处理一条条件概率链，而对数恰好把这条链改写成了既可解释、又可优化、又数值更稳定的训练目标。
