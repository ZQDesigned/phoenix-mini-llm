# 03. 对数、信息量与为什么损失常写成对数概率

到上一章为止，你已经建立了一个非常关键的判断：

> 当任务天然存在多种可能结果时，模型最自然的输出形式不是直接宣布唯一答案，而是在候选空间上给出一张概率分布。

这已经把语言模型的目标说清楚了一半。

模型不再只是吐出一个看起来神秘的分数，而是在每个位置上对整个候选空间表达偏好。可新的问题会立刻冒出来：

> 如果模型已经给出了一张概率分布，我们究竟应该怎样评价这张分布是“分得好”还是“分得不好”？

这时，很多初学者会第一次遇到一组容易让人本能警惕的词：

- `log`
- 对数概率
- 似然
- 负对数似然
- 交叉熵
- 困惑度

如果这一段只是被当成术语串过去，学习体验就会突然断掉。

前面你还在理解“模型给每个候选结果分配概率”这件事；一旦进入训练目标，材料却像忽然换成了另一门学科的符号游戏。于是很多人会留下一个非常错误但很常见的印象：

> 概率我大概能懂，但为什么训练一开始就要把它写成对数，甚至写成负对数，这大概只是机器学习社区的一种习惯吧。

这恰好是这一章要拆掉的误解。

这一章不是在额外补一堂独立的信息论课。
它真正要回答的是一个极其务实的问题：

> 当模型已经输出了一张分布，我们为什么通常不直接拿原始概率本身当训练目标，而要把它写成对数概率，甚至负对数概率？

只要这个问题被讲顺，后面很多看似分散的概念就会自然连起来：

- 序列概率为什么天然是连乘
- 为什么对数会把连乘改写成求和
- 为什么最大化真实答案的概率，等价于最小化负对数概率
- 为什么交叉熵会自然出现
- 为什么困惑度会和 loss 联动

也就是说，这一章真正要建立的，不是一堆公式，而是一条完整的损失主线。

## 对数首先解决的不是“数学体面”，而是乘法世界的问题

很多人第一次学对数时，会把它和学校里的记忆绑定在一起：

- 以几为底
- 指数和对数互逆
- 若干运算公式

这些当然都是真的，但对机器学习来说，还不够抓住重点。

如果只用最朴素的话说，对数真正擅长处理的是一种特殊结构：

> 当一个量不是通过“不断相加”长出来，而是通过“不断相乘”长出来时，对数会把这个乘法世界重新改写成加法世界。

这是整章最值得反复记住的性质：

\[
\log(ab)=\log a+\log b
\]

如果有很多项相乘，同样成立：

\[
\log(a_1a_2\cdots a_n)=\log a_1+\log a_2+\cdots+\log a_n
\]

这个性质看上去只是一个代数技巧，但它在语言模型里不是小技巧，而是决定性桥梁。

因为只要你开始处理序列概率，就几乎注定会不断遇到许多小于 `1` 的概率项连续相乘。

如果没有对数：

- 目标会表现成一长串连乘
- 数值会变得极小
- 每个位置各自做得好不好，不容易单独拆开来看

一旦引入对数：

- 连乘变成求和
- 每个位置的贡献可以被单独读出来
- 求平均、比较、优化都会自然许多

所以对数在这里不是为了让表达显得更学术。
它首先是在解决一个非常朴素的问题：

> 当模型面对的是一条乘法链时，怎样把它改写成更容易分析、更容易训练的形式？

## 序列概率天然会长成一条连乘链

只要你真正接受语言模型的基本任务形式，对数的出现就不再突兀。

语言模型不是一次性判断整段文本“整体上像不像正确答案”。
它在每一个位置上做的事情是：

> 给定前面的 token，预测下一个 token 的条件概率。

设一段序列写成：

\[
x_1,x_2,x_3,\ldots,x_T
\]

那么整段序列的联合概率可以按条件概率链分解成：

\[
P(x_1,x_2,\ldots,x_T)
=
P(x_1)
P(x_2\mid x_1)
P(x_3\mid x_1,x_2)
\cdots
P(x_T\mid x_{<T})
\]

这条式子最重要的不是形式本身，而是它表达的结构：

- 整段文本不是由一个神秘的“总分”直接决定
- 它是很多局部判断连起来的结果
- 每个位置都在问“在已有历史下，真实下一个 token 有多可能”

只要语言模型的目标是这条条件概率链，另一件事就立刻成为必然：

> 整段序列的概率，本来就会是一串小于 `1` 的数不断相乘出来的结果。

这时，对数不是被谁主观规定进来的。
它是被问题结构逼出来的。

## 为什么原始序列概率看起来总是小得离谱

初学者第一次看到整段文本的概率时，常常会本能地不适应。

因为哪怕模型已经不算差，整段概率看起来仍然会非常小，小到几乎无法用直觉直接理解。

这其实完全正常。

假设一段很短的序列有四个可预测位置，模型给真实 token 的条件概率分别是：

- `0.8`
- `0.6`
- `0.5`
- `0.7`

那么整段概率就是：

\[
0.8\times0.6\times0.5\times0.7=0.168
\]

只是四步而已，整体概率已经明显变小。

如果序列很长，例如有一百个位置，而模型每一步给真实 token 的平均概率哪怕达到 `0.2`，整体也会是：

\[
0.2^{100}
\]

这个值会小到几乎不再适合作为人类直觉分析的对象。

所以在语言模型里，“整段概率很小”通常并不说明模型一定很差。
更常见的原因只是：

> 长序列整体概率天然是很多小于 `1` 的条件概率连续相乘出来的。

这也是为什么一旦你还坚持直接用原始序列概率来做训练目标，就会同时遇到两类问题。

第一类是表达问题。
你很难把一条很长的乘法链看成“由很多局部判断组成的总目标”。

第二类是数值问题。
当数值不断接近 `0` 时，存储、比较和计算都会越来越不稳定。

于是，对数在这里承担了第二个非常现实的作用：

> 它把极小的乘法量，改写成更容易读、更容易算的加法量。

## 对数把整段目标改写成“每个位置各自贡献多少”

一旦对整段序列概率取对数，上面的连乘链就会立刻变成求和链：

\[
\log P(x_1,\ldots,x_T)
=
\log P(x_1)
+ \log P(x_2\mid x_1)
+ \log P(x_3\mid x_1,x_2)
+ \cdots
+ \log P(x_T\mid x_{<T})
\]

这一步的意义非常大。

原来你面对的是一个难以拆开的整体：

- 整段文本的联合概率

现在你得到的是一串可以逐位置理解的项：

- 第一个位置贡献了多少
- 第二个位置贡献了多少
- 第三个位置贡献了多少
- 后面每个位置又各贡献了多少

于是，语言模型的训练目标第一次呈现出一种非常清楚的面貌：

> 整段文本到底“让模型吃了多少损失”，其实就是每个位置上真实 token 的对数概率被逐项累加起来的结果。

这比“直接看整段概率”更接近训练系统的真实工作方式。

因为训练从来不是在感受一个抽象整体。
它是在每个位置上反复比较：

- 真实 token 被赋予了多大的概率
- 这个概率和模型本可以给出的更好概率还有多远

也就是说，对数不只是在修正数值尺度。
它还在把整体目标拆回局部判断。

## 为什么对数概率通常是负的

这里还有一个常见的不适感来源。

只要概率满足：

\[
0<p<1
\]

那么它的对数就会是负数：

\[
\log p<0
\]

例如：

- `log(0.9)` 是负的，但只略微负一点
- `log(0.1)` 会更负
- `log(0.001)` 则会非常负

这其实非常符合直觉。

如果一个真实事件被模型看得很有可能，那么对应的对数概率虽然仍是负数，但离 `0` 很近。
如果模型把真实事件看得极不可能，那么对应的对数概率就会非常小，也就是非常负。

所以对数概率的负号本身并不是坏事。
它只是反映了：

> “概率小于 `1`”这个事实，在对数坐标里会自然表现成负数。

但训练里我们通常不想把“更好”写成“更不负”。
我们更习惯把“更好”写成“损失更小”。

于是，负号会再出现一次。

## 为什么最大化概率，等价于最小化负对数概率

这一点其实比表面看起来更简单。

训练真正想要的是：

> 让模型给真实答案更高的概率。

如果我们在一个样本上只看真实答案的概率 \(p\)，那么“越大越好”当然没有问题。

但取对数以后，因为对数函数是单调递增的，最大化 \(p\) 与最大化 \(\log p\) 完全等价：

\[
\arg\max p = \arg\max \log p
\]

这意味着，对数并没有改变优化目标的方向。
它只是把目标换了一个更适合处理的坐标系。

再往前一步，如果我们把它写成负对数概率：

\[
-\log p
\]

那么“最大化 \(\log p\)”就等价于“最小化 \(-\log p\)”。

这就把概率学习自然改写成了更符合机器学习习惯的损失最小化问题。

于是你会得到一个非常重要的等价关系：

> 让模型给真实答案的概率越来越高
> 等价于
> 让真实答案的负对数概率越来越低。

从这里开始，负对数概率就不再像一种人为设计的公式。
它更像是：

> “我们本来就想最大化真实答案概率”这件事，在序列世界和优化语言里的自然写法。

## 为什么不直接用 `1-p` 当损失

很多初学者都会自然想到一个朴素替代方案：

既然目标是真实答案的概率越大越好，那么直接用：

\[
1-p
\]

不也能表达“概率越大，损失越小”吗？

这个想法并不愚蠢。
它说明你已经真的在问“损失到底想惩罚什么”。

但 `1-p` 之所以没有成为现代语言模型最自然的主目标，核心不是因为它完全错误，而是因为它丢掉了几件对序列建模极其重要的性质。

第一，它和序列概率的连乘结构结合得并不好。

语言模型面对的是许多条件概率被乘起来的整体目标。
`1-p` 并不能自然把这条乘法链拆回一条位置求和链。

第二，它对“自信地错”惩罚得不够重。

如果真实 token 的概率从 `0.1` 降到 `0.001`，这在建模上往往是非常严重的退化。
但 `1-p` 在靠近 `0` 时变化并不够敏感。
负对数概率则会把这种“把真实答案看得极不可能”的错误放大得更明显。

第三，它很难与似然、信息量、熵和交叉熵接成一条统一主线。

而现代机器学习真正需要的，不只是一个“凑合能用的惩罚函数”。
它更需要一个能同时兼容：

- 概率建模
- 序列分解
- 数值稳定
- 统计解释
- 优化实现

的统一目标形式。

负对数概率恰好具备这组性质。

## 似然不是另一个新术语，它只是换了观察角度

说到这里，似然就可以自然出现了。

很多人第一次听见“最大似然”时，会以为这又是概率以外的另一套神秘概念。
其实不是。

概率和似然用到的数学表达式可以非常相似，但它们问问题的角度不同。

如果你把参数 \(\theta\) 固定，把数据看成不确定的，那么你问的是：

\[
P(x\mid \theta)
\]

这时它是概率。

如果你把观测到的数据 \(x\) 固定，把参数 \(\theta\) 看成需要选择的对象，那么同一个表达式会被读成：

> 在这组参数下，当前这份数据看起来有多合理？

这时它被叫作似然。

也就是说，似然并不是一套新公式。
它只是把“数据已经观测到了”这个事实固定下来，然后反过来问：

> 哪些参数最能解释我已经看到的这份数据？

从训练角度看，这个视角非常自然。

我们手上已经有训练数据了。
现在想做的，不就是寻找一组参数，让这些已知数据在模型眼里尽可能“像应该出现的样子”吗？

这就是最大似然训练的朴素含义。

## 从单个样本到整个数据集，负对数似然怎样长成训练目标

如果对单个样本而言，我们希望最大化它在模型下的概率，那么对整个数据集而言，自然就希望让所有样本一起“尽可能可能”。

假设数据集为：

\[
\{x^{(1)},x^{(2)},\ldots,x^{(N)}\}
\]

如果把样本独立看待，整个数据集的似然会写成各样本概率的乘积：

\[
\prod_{i=1}^{N} P(x^{(i)}\mid \theta)
\]

你现在应该能立刻看出，这里又是一条乘法链。

所以对数再次自然出现：

\[
\log \prod_{i=1}^{N} P(x^{(i)}\mid \theta)
=
\sum_{i=1}^{N} \log P(x^{(i)}\mid \theta)
\]

于是，最大化整个数据集的对数似然，等价于最小化整个数据集的负对数似然：

\[
\mathcal{L}(\theta)
=
-\sum_{i=1}^{N} \log P(x^{(i)}\mid \theta)
\]

对于语言模型而言，每个样本本身又是一串 token 条件概率的乘积。
所以“样本之间求和”和“样本内部按位置求和”这两层结构会自然叠在一起。

最终你看到的训练目标，看起来像是在许多位置上不断把真实 token 的负对数概率加起来。

这不是为了把目标写复杂。
而是因为：

- 数据集层面天然会连乘
- 序列层面天然也会连乘
- 对数会把两层连乘都稳定地压成求和

## 从“惊讶”理解负对数概率，会更接近人类直觉

如果你只把 `-log p` 看成一个优化目标，它已经足够成立了。
但它还有一个非常强的直觉解释：

> 它可以被看成模型面对真实事件时的“惊讶程度”。

为什么这样说？

因为当真实事件概率高时：

- 模型本来就觉得它很可能发生
- 真正发生时，并不“意外”
- 对应的 `-log p` 较小

当真实事件概率很低时：

- 模型本来不看好它
- 它却真的发生了
- 这对模型来说是一次更大的“打脸”
- 对应的 `-log p` 就会很大

这正好符合训练想惩罚的东西：

> 不是普通地错，而是“把真实答案看得极不可能”地错。

所以负对数概率的好处不只是数值方便。
它在语义上也很清楚：

> 模型越不相信真实答案，代价就越大。

## 信息量为什么会自然长成 `-log p`

如果把刚才的“惊讶程度”再抽象一点，就会得到信息量。

信息论里常把一个事件发生所携带的信息量写成：

\[
I(x)=-\log P(x)
\]

这不是随便拍脑袋定义出来的。
它非常自然地满足我们对“信息量”直觉上的几个要求。

第一，越常见的事，信息量越少。

如果某件事几乎注定发生，它真的发生时，并没有给你提供多少新信息。

第二，越罕见的事，信息量越大。

如果模型几乎不认为它会发生，而它偏偏真的发生了，那么这件事对模型来说就提供了更强的纠偏信号。

第三，独立事件的信息量应该可以相加。

如果两个独立事件一起发生，它们的总信息量，应该等于各自信息量之和。
而这正是对数把乘法变加法所保证的性质。

这说明信息量并不是后来硬嫁接进机器学习的。
相反：

> 当你已经接受“序列概率是连乘结构”，又接受“训练需要一个能表达惊讶与惩罚的目标”时，`-log p` 几乎是自然长出来的。

## 熵和交叉熵，本质上都是“平均惊讶”

有了单个事件的信息量以后，往前再走一步就能得到熵。

如果一张分布里的事件各自概率不同，那么这张分布的平均信息量就是熵：

\[
H(P)=-\sum_x P(x)\log P(x)
\]

用直觉说，熵回答的是：

> 在这张分布下，平均来看，一个事件发生会让你有多意外？

如果分布非常尖锐，几乎所有质量都集中在少数几个候选上，那么真正发生的结果通常不太意外，熵就比较低。

如果分布比较平，很多候选看起来都差不多可能，那么你在看到真实结果之前就更不确定，熵就比较高。

交叉熵则是在问另一个更贴近训练的问题：

> 如果真实世界服从分布 \(P\)，但模型给出的却是分布 \(Q\)，那么按真实世界的抽样频率来看，模型平均会有多惊讶？

它写成：

\[
H(P,Q)=-\sum_x P(x)\log Q(x)
\]

这和熵的差别只有一个，但意义极大。

熵用的是“真实分布对自己的惊讶”。
交叉熵用的是“真实分布在模型分布下会遭遇的惊讶”。

训练时，我们当然更关心后者。
因为目标不是理解“真实世界本身有多不确定”，而是理解：

> 模型当前这张分布，离真实分布还差多少。

## 为什么分类和 next-token prediction 都会落成交叉熵

你现在可以理解一个机器学习里非常经典的现象了：

无论是普通分类，还是语言模型的 next-token prediction，最终都很自然地落成交叉熵。

原因不在于这是一种“行业默认配置”。
而在于它们有同一个抽象结构：

- 模型要在候选空间上给出一张分布
- 真实答案对应着某种目标分布
- 我们想让模型分布越来越接近目标分布

在标准分类里，目标分布通常是一张 one-hot 分布：

- 正确类别位置为 `1`
- 其他位置为 `0`

这时交叉熵会退化成非常熟悉的形式：

\[
-\log Q(y_{\text{true}})
\]

也就是说，在 one-hot 目标下，交叉熵就是“正确答案的负对数概率”。

语言模型在每个位置上做的其实仍是同一件事。
只是它的候选空间不是几个类别，而是整个词表。

于是 next-token prediction 的 loss，本质上仍然是：

> 真实下一个 token 在当前词表分布下的负对数概率。

这就把“概率”“似然”“信息量”“交叉熵”压回到了同一条主线上。

## 为什么实现里常常直接从 logits 出发

到这里，你可能已经注意到一个实现层面的现象。

理论上我们一直在说概率、对数概率和交叉熵。
但到了代码里，经常看到的却是：

```python
loss = F.cross_entropy(logits, targets)
```

而不是先手动算：

```python
probs = softmax(logits)
loss = -log(probs[target])
```

这里的关键并不只是“框架替你省代码”。
更重要的是数值稳定。

logits 是归一化之前的原始分数。
从 logits 到概率通常要经过 softmax：

\[
\text{softmax}(z_i)=\frac{e^{z_i}}{\sum_j e^{z_j}}
\]

如果你先显式做 softmax，再显式取对数，就可能在数值上遇到：

- 指数爆炸
- 极小概率下溢
- 精度损失

所以现代框架通常会直接把：

- softmax
- 取对数
- 挑出真实类别位置
- 求平均

合并成一个数值上更稳定的计算过程。

这也是为什么 `log_softmax` 会比“先 softmax 再 log”更自然。

它不是另一种数学目标，而是：

> 同一个目标在实际数值计算里的更稳定实现。

## 为什么语言模型的 loss 经常还是“按 token 平均”

如果你把所有位置的负对数概率直接加起来，长度更长的样本自然会得到更大的总损失。

这并不总是错误，因为它确实犯了更多位置上的预测任务。
但如果你想比较不同 batch、不同样本长度或者不同实验配置下的表现，只看总和就不太方便。

所以工程上经常会再做一步：

> 把总负对数概率按参与计算的 token 数量取平均。

于是你看到的语言模型 loss，经常更接近：

\[
\frac{1}{T}\sum_{t=1}^{T}-\log P(x_t\mid x_{<t})
\]

这个平均值的好处是，它更像在回答：

> 平均每个位置上，模型面对真实 token 时有多惊讶？

这比整段总和更利于实验之间的横向比较。

所以你现在可以把语言模型 loss 理解成一句非常直白的话：

> 模型在所有需要预测的位置上，平均有多不相信真实下一个 token。

## 困惑度为什么会和这里连起来

困惑度之所以常和这一章的内容一起出现，不是因为它突然引入了另一套评价体系。
恰好相反，它只是对平均负对数概率的另一种表达方式。

如果平均负对数概率记作：

\[
\ell = -\frac{1}{T}\sum_{t=1}^{T}\log P(x_t\mid x_{<t})
\]

那么困惑度通常写成：

\[
\text{PPL}=e^{\ell}
\]

如果使用以 `2` 为底的对数，也会写成：

\[
\text{PPL}=2^{H}
\]

你不必急着背这些式子。
更重要的是抓住它的直觉含义：

> 困惑度是在把“平均惊讶”重新指数化，改写成一个更像‘平均有效候选数’的量。

如果模型在每个位置上都非常确定，而且常常把真实 token 看得很可能，那么平均负对数概率会低，困惑度也会低。
如果模型在每个位置上都很迷茫，或者常常把真实 token 看得不太可能，那么平均负对数概率会高，困惑度也会高。

所以困惑度不是比 loss 更高级的神秘指标。
它和 loss 之间本来就是直接相连的。

## 为什么 loss 下降，不自动等于生成观感一定全面变好

讲到这里，必须提前埋下一个对后文非常重要的提醒。

既然训练目标是负对数概率，既然交叉熵和困惑度又都能从这里长出来，那么是不是只要 loss 一直下降，生成质量就一定会同步全面上升？

不能这么简单理解。

原因不是因为训练目标没意义。
而是因为训练目标衡量的是：

> 在真实数据分布下，模型平均给真实 token 分到多大概率。

这当然非常重要，也和语言建模能力高度相关。
但真实生成时，你还会同时受到很多别的因素影响：

- 采样策略
- 温度
- top-k / top-p
- 重复惩罚
- prompt 形式
- 评估样例的覆盖范围

更关键的是，loss 是平均量。
平均量下降，说明整体分布拟合在改进，但它不保证每一种主观观感都同步、线性地改善。

所以这一章建立的是训练目标的统计基础，而不是对所有生成体验的一键解释。

这也是为什么后面你还需要单独学习：

- 困惑度怎样解释
- 生成质量为什么和 loss 只部分同步
- 推理时的采样策略到底在改写什么

## 这一章真正想留下的主线

如果把整章压缩成最核心的一条链，可以写成：

> 语言模型面对的是序列条件概率问题；序列概率天然表现成许多条件概率的连乘；对数把连乘改写成求和，并把极小概率变成更可处理的量；最大化真实序列概率因此自然等价于最小化负对数概率；而单个事件的负对数概率又正好可以被理解成惊讶和信息量，于是交叉熵、困惑度和训练 loss 都顺理成章地落到同一条主线上。

这条链一旦稳住，后面很多实现细节都会突然变得更自然。

例如：

- 为什么框架爱用 `cross_entropy`
- 为什么语言模型 loss 是按 token 算的
- 为什么 perplexity 和 loss 会联动
- 为什么 `log_softmax` 是自然实现形式

更重要的是，你不会再把“对数概率”看成训练阶段额外冒出来的怪东西。
你会知道它是从序列概率结构里自然长出来的。
