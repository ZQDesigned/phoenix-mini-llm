# 01. 为什么学语言模型还要先学数学

## 最常见的误解：现在框架这么强，还学数学干什么

很多初学者一开始都会产生类似想法：

> 现在已经有 PyTorch、Transformers、自动求导和现成教程了，我是不是可以直接写代码，不用先补数学？

这类想法并不奇怪，因为现代框架确实帮我们做掉了大量底层工作。

但它不能替你完成一件更根本的事：

> 帮你理解模型里的对象到底是什么，它们为什么这样连接，以及哪里出了问题。

如果缺少这层理解，你会很快陷入下面的状态：

- 能照着教程跑命令，但换个场景就不会判断
- 能把某段模型代码抄下来，但不知道张量变形是否合理
- 能看懂 API 名字，但不知道 loss 为何这样定义

所以这里要学的数学，不是为了让你变成理论研究者，而是为了让你具备最基本的解释力。

## 在模型世界里，数学首先是一种描述语言

先把“学数学”从一种沉重想象里解放出来。

对语言模型开发者来说，数学首先不是考试题，而是描述系统的语言。

例如：

- 向量在描述一个对象的数值表示
- 矩阵在描述一种线性变换
- 概率分布在描述模型对候选结果的偏好
- 损失函数在描述当前预测与目标之间的差距

如果没有这套语言，你面对的就不再是一个有结构的系统，而是一堆只能死记的接口。

## 代码能运行，不代表你已经理解

这是学习大模型时非常容易踩的坑。

当一份训练脚本成功跑起来时，人很容易以为：

> 我已经掌握这个东西了。

但真正的理解能力体现在另外几个时刻：

- batch shape 不对时，你能不能迅速定位哪一维错了
- loss 不下降时，你能不能判断是目标、优化还是数据流的问题
- 生成结果怪异时，你能不能区分是 tokenizer、mask 还是采样出了错

这些判断都不是靠背命令得到的，而是靠你对模型内部对象的数学直觉。

## 语言模型真正反复使用的数学只有几层

这也是一个重要安心点。

你不是要先学完一整套高等数学课程，才能碰语言模型。对入门实现来说，真正高频反复出现的主要是下面几层：

### 第一层：数值表示与维度组织

你需要知道：

- 什么是标量、向量、矩阵、张量
- 什么是 shape
- 为什么同一堆数字换一种组织方式，语义就完全变了

### 第二层：矩阵运算与线性变换

你需要知道：

- 矩阵乘法为什么能表达“特征重组”
- 线性层为什么本质上是一种投影和组合
- 模型为什么总在不同维度空间之间来回映射

### 第三层：函数、复合与非线性

你需要知道：

- 模型不是只在乘矩阵，它是在做函数复合
- 如果没有非线性，很多层线性层堆起来仍然只是一个线性变换
- “深度”为什么会带来额外表达力

### 第四层：概率与对数概率

你需要知道：

- 语言模型为什么不是输出一个确定答案，而是输出分布
- 为什么条件概率是任务定义本身
- 为什么训练里会出现 `log`、负对数似然和交叉熵

### 第五层：梯度与优化

你需要知道：

- loss 只是“错得多不多”，梯度才告诉你“该往哪改”
- 参数更新为什么能逐渐改善模型
- 学习率、稳定性和收敛不是神秘调参，而是训练动力学问题

## 数学在这里不是附属背景，而是错误定位能力

如果一定要说学这些基础最现实的价值是什么，可以直接说：

> 它会决定你遇到错误时，是只能盲试，还是能有效缩小范围。

举例来说：

- 不懂 shape，很难查张量维度错位
- 不懂线性变换，很难看懂投影层到底在改变什么
- 不懂分布，很难理解为什么生成质量和 loss 不总是同步
- 不懂梯度，很难判断训练不稳定是不是数值和优化问题

也就是说，数学不是装饰知识，而是工程判断力的底座。

## 初学者最该避免的两种极端

### 第一种极端：完全跳过基础

这种路线的问题是，后面所有高级概念都会悬空。

你会不断遇到：

- “我知道这个名词，但我说不清它为什么存在”
- “我知道这行代码常见，但我不知道它在防什么问题”

### 第二种极端：先陷进过深的理论证明

另一种错误是走向反方向，觉得一定要先学完整套抽象数学，才配接触模型。

这同样没有必要。

对实现一个小型语言模型来说，更合理的目标是：

> 先建立足够支撑阅读、实现和排障的数学直觉，再随着项目深入逐步补更深的理论。

## 这一卷真正要帮你完成什么

这卷不会要求你立刻推导复杂论文公式。它更关注几个务实目标：

- 把模型里的主要对象翻译成可以理解的数值结构
- 把常见运算翻译成可以解释的变换过程
- 把训练目标翻译成可以追踪的概率问题

做到这一点之后，你再进入神经网络、tokenizer 和 Transformer，感受会完全不同。

你不再只是“看到熟悉术语”，而是开始知道：

> 这些术语究竟在整台模型里承担哪种数学角色。
