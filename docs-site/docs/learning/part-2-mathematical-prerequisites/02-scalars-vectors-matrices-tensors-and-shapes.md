# 02. 标量、向量、矩阵、张量与 shape

## 为什么这一章必须在很前面

在语言模型代码里，你会非常高频地看到这类对象：

- `[B, T]`
- `[B, T, H]`
- `[B, T, V]`
- `reshape`
- `transpose`
- `matmul`

如果你对这些对象没有稳定直觉，那么几乎所有实现都会显得杂乱。

问题不在于你记不住 API，而在于你脑中没有画面：

- 这个张量现在装的是什么
- 每一维的语义是什么
- 某个变形到底有没有破坏语义

所以在深度学习里，shape 不是小细节，而是理解模型结构的第一语言。

## 从最小单位开始：标量

标量就是单个数。

例如：

```text
0.25
```

它没有方向，也没有多个位置，就是一个独立数值。

在模型里，很多重要对象都可能暂时表现成标量：

- 一个 loss
- 一个学习率
- 某个单独权重值

标量最重要的意义不是“它很简单”，而是提醒你：

> 更复杂的对象，本质上都是许多标量按结构组织起来的结果。

## 向量：一串有顺序的数

向量可以先理解成：

> 一组按顺序排布的数值，它们共同表示一个对象的多个属性。

例如：

```text
[0.2, -1.1, 3.4]
```

在模型世界里，一个向量可能表示：

- 一个 token 的 embedding
- 一个样本的一组特征
- 某个位置的隐藏状态

关键不在于向量长度，而在于：

> 每一维虽然难以直接用人类语言命名，但这些维共同构成了一个可计算表示。

## 矩阵：把很多向量组织在一起

矩阵就是二维数表。

例如：

```text
[
  [1.0, 2.0],
  [3.0, 4.0],
]
```

你可以把它看成：

- 多个向量按行堆起来
- 一个线性变换的参数表
- 一批样本的特征表

同样一个矩阵，在不同上下文里语义可以完全不同。

这说明一个重要事实：

> 形状只告诉你维度个数，不会自动告诉你维度语义。语义必须结合上下文解释。

## 张量：更一般的多维数值容器

在工程语境里，一个最实用的理解是：

> 张量就是带 shape 的多维数值容器。

你暂时不必先进入更抽象的数学张量定义。对我们实现模型来说，更重要的是：

- 它有几维
- 每一维代表什么
- 数据怎样在这些维之间流动

所以很多时候“张量”这个词，不是在强调某种神秘对象，而是在提醒你：

> 你面对的不是单个数，而是一块有结构的数值空间。

## 什么是 shape

shape 就是张量在每个维度上的长度描述。

例如：

- `[128]`
- `[32, 128]`
- `[4, 256, 512]`

这些数字不只是在告诉你“总共有多少个数”，更重要的是在告诉你：

> 这些数被分成了几层结构，每层结构各有多长。

在模型实现里，shape 经常比具体数值本身更重要。因为很多错误首先暴露的不是“数值不对”，而是“结构不对”。

## 为什么同样数量的元素，shape 不同语义就不同

设想你有 4096 个数。

它们可以是：

- `[4096]`
- `[64, 64]`
- `[8, 512]`
- `[2, 4, 512]`

虽然总元素个数一样，但语义完全不同：

- 第一种像单个长向量
- 第二种像二维表
- 第三种像 8 个长度为 512 的表示
- 第四种像 2 个 batch、每个 batch 有 4 个位置、每个位置一个 512 维向量

这说明在深度学习里，“有多少个数”远不够，真正关键的是：

> 这些数按什么层次组织。

## 语言模型里最常见的维度语义

语言模型里会反复出现几类维度。

### `B`：batch size

一次并行送进模型的样本数。

### `T`：sequence length

每个样本当前包含的 token 位置数。

### `H`：hidden size

每个位置在隐藏空间中的表示维度。

### `V`：vocab size

词表大小，也就是输出层候选 token 的类别数。

于是一个典型中间表示会长成：

\[
[B, T, H]
\]

而最终 logits 会长成：

\[
[B, T, V]
\]

只要你能对这些形状形成稳定画面，后面看模型结构会顺很多。

## 维度不只是数字，它们有角色

这也是很多初学者第一次看模型代码时容易忽略的地方。

在 `[B, T, H]` 里：

- `B` 不是“第一个数字”
- `T` 不是“第二个数字”
- `H` 不是“第三个数字”

它们分别承担不同角色。

如果你把它们随便对调，就不只是格式变化，而是语义被破坏。

例如把 `T` 和 `H` 搞反，就相当于把“序列位置轴”和“特征维度轴”混成一类对象，后面的矩阵运算很可能就不再成立。

## reshape、transpose 和 permute 为什么常见

因为不同计算希望数据按不同视角排布。

例如：

- 有时你想把多个维度合并起来批量计算
- 有时你想把某个维度换到前面，方便做矩阵乘法
- 有时你只是改变视角，并没有改变底层元素总数

这类操作本身不神秘，但它们有一个前提：

> 你必须清楚改变的是“表示方式”还是“语义角色”。

如果只是为了让代码跑通而盲目 reshape，通常迟早会把语义打乱。

## shape 其实就是模型调试时的第一道防线

很多 bug 在数值层面很晚才暴露，但在 shape 层面会很早显示异常。

例如：

- 输出维度少了一层
- 词表维和隐藏维写反了
- batch 和时间维错误合并
- 右移目标后长度不匹配

所以在真正写小型 LLM 时，一个很实用的习惯是：

> 几乎把每个重要中间张量都先在脑中标出形状语义。

这会比“等报错再查”高效得多。

## 这一章结束后你至少应该带走什么

你不一定已经熟练做复杂矩阵推导，但至少应该稳定掌握：

- 标量、向量、矩阵、张量是逐层扩展的结构
- shape 描述的是结构，不只是元素个数
- 语言模型里最常见的是 `batch / sequence / hidden / vocab` 这些轴
- 很多实现判断首先是 shape 判断，而不是公式判断

后面当我们开始讲矩阵乘法和线性层时，这些对象就会真正动起来。
