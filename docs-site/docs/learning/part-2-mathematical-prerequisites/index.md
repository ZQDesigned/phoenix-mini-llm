# 卷二 数学对象、线性代数与表示空间

> 本卷属于第一编“数学与数值世界”，负责建立模型内部最底层的对象语言、空间语言与几何直觉。

如果把大型语言模型当成一台复杂机器，那么这一卷处理的是它最底层、最沉默、却最不可跳过的部分：

> 模型内部到底把什么东西表示成了什么数，这些数怎样组成对象，这些对象又怎样在一连串变换中流动、比较和被重新组织。

很多初学者第一次学大模型，会把注意力集中在更显眼的地方：

- Transformer 结构图
- Attention 公式
- 训练脚本
- 推理采样

这很自然。
因为这些内容看起来更像“大模型本体”。

但真正让人长期迷路的，常常恰好不是这些高处的结构，而是脚下这层对象语言没有站稳。

只要你对下面这些概念仍然只有模糊印象：

- 标量
- 向量
- 矩阵
- 张量
- 维度
- shape
- 矩阵乘法
- 点积
- 投影
- 相似度

那么后面几乎每碰到一个新结构，你都要重新硬扛一遍理解成本。

你会频繁经历这种状态：

- 看见公式时，知道符号在动，但不知道对象在动什么
- 看见张量形状时，知道有几维，但不知道每一维在语义上代表什么
- 看见某层线性映射时，知道代码能运行，但不知道它为什么能承担这种角色
- 看见相似度分数时，知道结果参与了 attention，却说不清为什么“比较方向”会比“比较数值大小”更自然

这说明你缺的不是更多术语，而是一套能持续复用的底层语言。

这一卷就是来建立这套语言的。

## 2.1 为什么学习大模型必须先经过这一卷

很多面向工程实作的教程，会把数学准备压缩成很短的预备部分，然后立刻进入代码。

这种写法对于已经学过相关内容、只是来回忆的人当然高效。
但对真正从零起步的人来说，风险很大。

因为语言模型内部并不会直接处理：

- “一句话的意思”
- “一段文章的主题”
- “这个回复听起来像不像人写的”

它首先处理的是数值对象。

更具体地说，它会先把原本看起来像语言、词语和句子的东西，翻译成：

- 向量表示
- 矩阵变换
- 张量批处理
- 相似度计算
- 概率分布

也就是说，模型不是先理解语义，再顺手做数学。
恰好相反：

> 它必须先在数学对象层面运作，语义效果才可能在高层逐步长出来。

如果这个起点没有站稳，后面的很多内容就都会像“把很多高阶模块堆在一起”，而不是一条连续的系统主线。

所以这一卷不是为了考数学。
它是为了让你真正拥有后面所有章节都要复用的共同语言。

## 2.2 这一卷想解决的并不是“数学不够多”，而是“对象感不够稳”

初学者最常见的数学焦虑，不一定来自不会算。
更多时候，来自不知道这些数学对象在模型里到底扮演什么角色。

例如：

- 明明学过矩阵乘法，但一到神经网络里就觉得陌生
- 明明知道向量可以有很多维，但一看到 `batch_size x seq_len x hidden_size` 就开始混乱
- 明明知道点积有公式，但一遇到 attention score 就不知道为什么它会自然出现

这类困惑的根源，不是“公式记不住”，而是：

> 你没有把这些对象重新放回模型语境，建立它们在真实学习系统里的角色感。

这一卷因此会特别强调三件事。

### 第一，数字不是孤立存在的，数字会组成对象

一个单独的数和一整组数，在建模里承担的意义完全不同。

你不能把：

- 一个标量
- 一个向量
- 一个矩阵
- 一个三维或更高维张量

只看成“数字个数不同的数组”。

它们在模型里对应的是完全不同的结构层次。

### 第二，计算不是纯粹的算术，计算是在搬运和改写表示

矩阵乘法之所以重要，不是因为它是一条基础规则。
而是因为它能把一组表示系统地变换成另一组表示。

### 第三，几何直觉不是装饰，而是理解相似度与注意力的前提

如果你只把向量看成“很多数字排在一起”，那么后面看 attention 时就很难真正理解“比较谁和谁更对齐”到底在说什么。

所以这一卷最重要的目标，不是让你会做一堆纸笔题，而是让你建立稳定的对象感、变换感和几何感。

## 2.3 这卷里的“数学”到底指什么

这里有必要先把预期说清楚。

很多人一看到数学，就会出现两种相反的误判。

第一种误判是过度恐慌：

> 我是不是必须先把整套高数、线代、概率论完整学完，才能回来继续读这本书？

第二种误判是过度轻视：

> 现在框架都这么成熟了，数学大概已经不重要了，最多查查 API 就能做事。

这两种判断都不对。

在这套知识档案里，这一卷需要的数学有一个很明确的边界：

### 你不需要把数学当成独立考试科目去准备

这里不会要求你先完成一整套脱离语境的大学数学课程。

### 但你必须接受数学是模型的母语之一

如果你希望完全避开：

- 向量空间
- 线性映射
- 函数复合
- 概率分布
- 对数概率

那么你最终得到的只能是脚本级熟悉，不会是结构级理解。

### 更准确地说，这卷要教的是“带场景的数学”

也就是：

- 为什么这个对象会在模型里出现
- 为什么它在这里比别的对象更自然
- 如果你不理解它，后面会在哪里反复卡住

因此，数学在这里既不是门槛，也不是装饰。
它是理解机器内部工作方式的工具。

## 2.4 为什么这一卷的名字是“数值表示与线性代数”，但内容会逐步碰到函数、概率与对数

这一点需要在卷首就提前说明。

从目录上看，这一卷的起点非常明确：

- 标量、向量、矩阵、张量
- shape
- 矩阵乘法
- 点积与相似度

这些内容显然属于数值表示与线性代数的核心地带。

但如果只停在这里，地基还是不够完整。

因为后面的学习系统很快就会问：

- 这些对象怎样形成函数
- 为什么只靠线性不够
- 为什么预测会落成概率分布
- 为什么损失会使用对数概率

所以这一卷虽然从线性代数起步，却不会机械地把自己封死在“只谈矩阵，不谈其他”。

更准确的理解是：

> 这一卷先建立对象与空间，再把读者轻轻推进到函数、概率和对数这些即将成为训练语言核心的桥接概念。

也正因为如此，这一卷和后面的：

- [Part 3. 函数、导数、概率与信息](/learning/part-3-functions-calculus-probability-and-information)

并不是割裂的两块材料，而是同一条数学地基主线上的前段与后段。

## 2.5 这一卷到底在替后面哪几类问题铺路

如果你想知道“为什么非学这卷不可”，最好的办法不是记住抽象口号，而是提前看清它将在后面替你节省哪些理解成本。

### 第一类：张量形状相关的问题

后面你会频繁看到：

- `batch_size`
- `seq_len`
- `hidden_size`
- `vocab_size`
- `num_heads`

这些东西一旦出现在同一个张量里，就不再只是“几个整数参数”。
它们会直接变成结构约束。

如果 shape 感不稳，你会反复在最基础的地方卡住。

### 第二类：线性层和投影相关的问题

后面无论是：

- embedding
- Q、K、V 投影
- 输出投影
- 前馈网络

本质上都在大量复用线性映射语言。

如果你对矩阵乘法只是“会按规则算”，而没有“它在改变表示空间”这层直觉，那么这些模块会看起来像很多不同的小魔法。

### 第三类：相似度和 attention 相关的问题

后面 attention 的核心之一就是比较：

- 当前查询与哪些历史表示更相关
- 哪些位置在当前上下文里更值得读取

这时点积、方向、对齐和相似度就不再是抽象数学对象，而是建模核心。

### 第四类：概率与损失相关的问题

当你看到 softmax、交叉熵和负对数概率时，如果你此前没有建立起：

- 分布
- 不确定性
- 对数
- 信息量

这些概念的基本直觉，就会觉得训练目标像从天而降。

所以这卷的意义，不只在当前几章，更在于它会不断在后面被回用。

## 2.6 初学者在这一卷最容易遇到的三种错觉

### 错觉一：这些对象我在别处见过，所以大概已经会了

这很常见。

你可能在：

- 高中
- 大学公共课
- 别的编程教程

里都见过向量、矩阵、函数、概率这些词。

但“见过”不等于“会在模型语境里使用”。

真正重要的问题是：

> 当这些对象进入神经网络和语言模型之后，你能不能立刻说出它们现在承担什么角色。

### 错觉二：我先把代码写出来，数学以后慢慢补

这也很常见。

短期看，这条路似乎进展很快。
你很快就能：

- 导入框架
- 建个模型
- 跑个前向

但一旦遇到：

- shape 对不齐
- logits 维度不明白
- attention score 算不通
- loss 为什么这样定义说不清

你就会发现自己一直在补最基础的洞。

### 错觉三：数学就是公式，理解公式就够了

这也是常见误解。

公式当然重要，但如果你只记公式，不记：

- 对象是什么
- 运算在改变什么
- 这个变化为什么有意义

那么所有公式都会很快退化成机械符号。

这一卷会尽量避免这种写法。
它更看重你能不能把对象放回场景里理解。

## 2.7 这一卷包含哪些章节

这一卷当前由七章组成，它们不是松散并列的专题，而是一条逐步向上抬高抽象层次的连续路线。

这一章先处理学习姿态问题。

它不会急着给你很多公式，而是先把几件事说清楚：

- 为什么数学在这里不是附加技能
- 为什么初学者最怕“只会跟着跑，不会解释”
- 本书希望你用什么方式学这些概念

这一章的作用是校正预期。

### 第二章：[02. 标量、向量、矩阵、张量与 shape](/learning/part-2-mathematical-prerequisites/02-scalars-vectors-matrices-tensors-and-shapes)

这一章处理最基础的对象语言。

它会让你逐渐稳定地区分：

- 一个数

- 多维结构中的每一维在说什么

只要这章真正读透，后面的张量流动就不会再显得像“屏幕上的一堆维度标签”。

### 第三章：[03. 矩阵乘法、线性变换与维度流动](/learning/part-2-mathematical-prerequisites/03-matrix-multiplication-linear-transformations-and-dimensional-flow)

这一章负责把矩阵乘法从算术规则提升为结构语言。

它会回答：

- 维度为什么要对齐
- 输出维度为什么会变化
- 线性层到底在“做什么”
- 为什么神经网络里这么多模块都在重复使用矩阵乘法

### 第四章：[04. 长度、点积、相似度与几何直觉](/learning/part-2-mathematical-prerequisites/04-length-dot-products-similarity-and-geometric-intuition)

这一章把表示对象放回几何视角。

你会开始真正理解：

- 向量不仅有值，还有方向
- 点积为什么能表达对齐程度
- 相似度为什么自然服务于检索和注意力

### 第五章：[05. 函数、复合与为什么非线性重要](/learning/part-2-mathematical-prerequisites/05-functions-composition-and-why-nonlinearity-matters)

这一章是从对象和空间走向“系统行为”的第一座桥。

它会帮助你看到：

- 模型本质上是一组复合函数
- 只靠线性为什么表达力不够
- 非线性为什么不是装饰，而是深度网络成立的条件之一

### 第六章：[06. 概率分布、期望与不确定性](/learning/part-2-mathematical-prerequisites/06-probability-distributions-expectation-and-uncertainty)

它会回答：

- 什么叫概率质量如何分配
- 不确定性为什么是学习问题的一部分

### 第七章：[07. 对数、信息量与为什么 loss 使用 log probability](/learning/part-2-mathematical-prerequisites/07-logarithms-information-and-why-loss-uses-log-probability)

- 为什么概率一旦连乘，对数几乎必然出现

这一章之后，你再进入 softmax、交叉熵和语言模型目标时，会轻松很多。

## 2.8 为什么这一卷的顺序不能随便打乱

这一卷的排列顺序不是形式问题，而是理解成本问题。

如果顺序错了，初学者会很容易陷入看似熟悉、实则悬空的状态。

### 如果你跳过对象层，直接去看变换层

你会觉得矩阵乘法像在处理“没说明白的一堆表格”。

### 如果你跳过变换层，直接去看相似度和 attention

你会知道有一个分数被算出来，但不知道它为什么能代表相关性。

### 如果你跳过函数与非线性，直接去看神经网络

你会把网络当成“很多线性层堆起来”，却不明白表达力为什么会真的增强。

### 如果你跳过概率与对数，直接去看损失

你会记住交叉熵公式，却说不清它为什么是这么写，而不是别的写法。

所以这卷最好不要按“我觉得这个词更热门”来跳读。
更好的方式是按层推进，让每一层自然长出下一层。

## 2.9 读这一卷时，正确的阅读方法是什么

这卷最不适合的读法，是把它当成数学公式速查表。

更适合的读法是：

### 第一步：先问“这一章在回答什么问题”

例如：

- 为什么需要向量而不是很多散数
- 为什么需要矩阵乘法而不是普通加减乘除
- 为什么需要相似度而不是逐项比较

### 第二步：再问“这一章引入的对象是什么”

比如：

- shape
- 线性映射
- 点积
- 分布
- 对数概率

### 第三步：最后才去看公式细节

因为如果你一上来就只盯公式，最容易发生的事情是：

你会记住符号，却记不住问题。

### 第四步：自己反复说出对象含义

例如看到一个张量时，尝试自己说：

- 第一维是什么
- 第二维是什么
- 为什么会有这一维
- 如果这一维变化，语义会怎么变

这类自述练习对初学者特别重要。

这一卷不是独立的小数学补丁。

### 往后接机器学习与神经网络

## 2.11 读完这一卷之后，你应该能稳定说清哪些事

在继续进入更高层内容之前，你至少应该能比较稳定地说明下面这些问题。

1. 为什么模型内部首先处理的是数值对象，而不是自然语言意义本身。  
2. 标量、向量、矩阵、张量之间的差别不仅是维度数量，更是组织层次不同。  
3. shape 为什么是一种结构契约，而不是调试时才看的附加信息。  
4. 矩阵乘法为什么本质上是在做线性变换，而不只是很多乘加。  
5. 点积和相似度为什么会自然进入 attention 这样的机制。  
6. 为什么从线性代数走到函数、概率和对数，是一条连续主线而不是突然换题。  

如果这些问题你还说不稳，不要急着向下推进。

真正经济的学习路径，从来不是“先把后面的词都扫一遍”，而是：

> 把底层对象语言先练到足够熟，让后面所有结构都能在这套语言里被重新解释。

## 2.12 如果你现在只能记住这一卷的一句话

可以先记住这一句：

> 语言模型看起来在处理文本，实际上它首先在处理向量、矩阵、张量与分布；只有先学会这些对象如何存在、如何变换、如何比较，后面的模型结构才会真正可理解。

只要这句话没有丢，你在后面遇到任何更复杂的结构时，都会知道该往哪里回溯。
