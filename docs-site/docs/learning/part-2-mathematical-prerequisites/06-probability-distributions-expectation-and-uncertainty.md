# 02. 概率分布、期望与不确定性

走到这一章时，读者通常已经接受了几件重要事实：

- 模型内部处理的是数值对象，而不是人类语言里的直接含义。
- 模型可以被看成输入到输出的参数化函数。
- 神经网络最后吐出的，往往不是一句现成答案，而是一组需要进一步解释的数值。

但一进入概率这条线，很多人的直觉会突然变得不稳定。

原因通常不是不会算，而是更早的一层误解没有拆干净：

> 人们太容易把语言模型想成一台“应该直接给出唯一标准答案”的机器。

一旦这样理解，后面的很多核心概念都会显得别扭：

- 为什么模型不直接输出一个确定 token？
- 为什么要保留一整个分布？
- 为什么同一个上下文下可以有多种合理续写？
- 为什么采样策略会显著改变结果？
- 为什么交叉熵、困惑度、校准和不确定性全都绕着概率转？

所以这一章的任务，不是往你面前堆一堆抽象概率公式，而是先重新校正任务观：

> 语言世界本来就不是处处只有唯一后续的确定系统，因此模型最自然的表达方式，不是直接宣布“唯一答案”，而是给候选结果分配不同的可能性权重。

只要这个判断站稳，概率分布、条件概率、期望和不确定性就不再像额外附加的数学负担，而会变成语言模型任务本身所要求的对象语言。

## 为什么语言模型不能只输出“一个答案”

很多初学者第一次听到“预测下一个 token”时，会下意识把它理解成学校里的填空题：

> 前文已经给定，后面理应只有一个唯一正确答案。

这种直觉在少数极度确定的例子里似乎成立。比如：

```text
1 + 1 =
```

这类前缀后面的合理续写确实很集中。

可一旦回到真实语言，这种“唯一标准答案”直觉很快就会崩掉。

例如：

```text
今天天气真
```

后面可能接：

- 好
- 热
- 冷
- 不错
- 糟

这些候选当然不是等可能的，但也很少只有一个可以被称为“宇宙中唯一正确”。

再比如：

```text
她推开门，发现桌上放着一封
```

后面可能是：

- 信
- 便签
- 纸条
- 邀请函

这说明真实语言有一个极根本的特征：

> 即使上下文已经提供了大量约束，后续仍然常常不是唯一值，而是一组带不同可能性的候选。

只要这件事成立，模型最自然的任务形式就不再是“直接说出唯一正确答案”，而是：

> 在所有候选后续之间分配相对可能性。

这正是概率为什么会进入语言模型。概率不是后来被强行套上的数学外壳，而是任务本身要求的一种表达方式。

## 概率到底在描述什么

很多人对概率的早期印象来自掷硬币、掷骰子、抽球这类例子。这些例子有帮助，但也容易制造一种误会：

> 概率好像只是课本里研究随机小游戏的工具。

对语言模型来说，一个更稳定的理解应该是：

> 只要一个系统面对多个可能结果，而这些结果出现的机会并不相同，就需要一种语言来表达这种“可能性结构”。

概率正是在做这件事。

它不是在表达“某个命题真不真”的程度，而是在表达：

- 在当前信息下，哪些结果更应被看重。
- 哪些结果相对不那么可能。
- 当前判断到底有多确定。

这层理解一旦站稳，很多东西都会自然起来：

- 模型输出为什么不是一个 token，而是一整排分数。
- 为什么同一个 prompt 下可以有多种合理续写。
- 为什么有时我们想保守生成，有时又想保留更多随机性。

你会开始明白，概率在语言模型里不是装饰性术语，而是输出解释的主语。

## 从“可能发生什么”开始：样本空间并不只属于掷骰子

要让后面的术语稳定下来，最好先区分几件基础事。

讨论一个带不确定性的系统时，第一件要做的事，是先说清楚：

> 到底有哪些结果是可能发生的？

在掷骰子里，这张清单是：

\[
\{1, 2, 3, 4, 5, 6\}
\]

在语言模型里，如果我们把“预测下一个 token”看成一次带不确定性的选择，那么这张清单就可以理解成：

> 当前词表中所有可能成为下一个位置续写的 token。

也就是说，语言模型面对的是一个极大的离散候选空间。后面所有的概率分配，都发生在这个空间上。

这一步看似简单，却非常重要。因为很多人一上来就直接盯住“模型最后选了哪个 token”，却忘了更根本的一层：

> 在选择发生之前，模型面对的是整个候选空间，而不是某一个现成答案。

只要这个视角立住，后面的“分布”才有真正落脚的地方。

## 什么是概率分布

现在可以正式进入本章最重要的对象：概率分布。

最朴素地说，概率分布就是：

> 对一组可能结果，给出一整套非负且总和为 1 的可能性分配规则。

这个定义里有三层关键信息。

第一，它不是单个概率，而是一整套分配。

很多人第一次学概率时，脑子里只有“某个结果的概率是多少”。比如“掷到 6 的概率是 \(1/6\)”。这当然没错，但分布讲的是更完整的结构：1 的概率是多少，2 的概率是多少，一直到所有候选都被分配完。

第二，所有概率都必须非负。

“负的可能性”在解释上没有意义。一个结果的概率可以是零，表示在当前假设或当前模型下它被认为不会发生；但它不能是负数。

第三，全部概率加起来必须等于 1。

这表示：所有可能性都已经被这套分配完整覆盖。总和小于 1，说明还有可能性没有交代清楚；总和大于 1，则说明这组数已经不再能被解释成一套合法分布。

这也是为什么后面 softmax 会如此自然。它的作用之一，就是把任意一组原始分数压成一套合法分布。

## 为什么“第一名是谁”远远不是全部

初学者看分布时，最容易只盯着最高概率候选。

例如，设想下面两种情况。

第一种：

```text
token A: 0.92
token B: 0.03
token C: 0.02
token D: 0.03
```

第二种：

```text
token A: 0.31
token B: 0.27
token C: 0.21
token D: 0.21
```

两种情况下第一名都是 `token A`，但它们表达的状态完全不同。

第一种是在说：模型非常确定，大部分概率质量已经压在一个候选上。

第二种是在说：虽然 `token A` 暂时排第一，但其他候选也并没有被拉开太远，模型仍然保留了显著不确定性。

这说明分布真正重要的，不只是“谁排第一”，而是：

- 头部有多尖。
- 尾部有多长。
- 候选之间的差距有多大。
- 不确定性被压缩到了什么程度。

后面你理解采样、困惑度、校准和重复生成时，这些直觉都会被反复调用。

## 什么叫条件概率，为什么语言模型天然活在条件世界里

光有概率分布还不够，因为语言模型从来不是在真空里预测。它总是在某个上下文条件下做判断。

这就是条件概率要进入的地方。

条件概率最朴素的意思是：

> 在某些信息已经给定的前提下，再去衡量另一个结果出现的可能性。

记号上常写成：

\[
P(A \mid B)
\]

意思是：在 \(B\) 已经成立的条件下，\(A\) 的概率是多少。

对语言模型来说，最典型的形式就是：

\[
P(x_t \mid x_1, x_2, \dots, x_{t-1})
\]

这表示：

> 在前面所有 token 都已经给定的情况下，第 \(t\) 个 token 是什么的概率分布。

这几乎就是 next-token prediction 的核心句法。

所以语言模型不是在问“这个 token 本身概率是多少”，而是在问：

> 在这段上下文已经成立的情况下，各个候选 token 分别有多大可能成为下一个位置的续写？

这也是为什么语言模型从根上就是条件概率模型。它不是在研究孤立 token 的总体频率，而是在研究“给定历史之后的后续分布”。

## 语言模型为什么不直接输出概率，而先输出 logits

现在可以把一个常见的工程现象接回概念层。

很多人第一次看模型输出时会发现：网络最后并不直接给出概率，而是先给出一组叫 logits 的数。这些数可能很大，也可能为负，甚至完全不在 `0` 到 `1` 之间。

为什么会这样？

因为网络本体更自然的做法，是先输出一组相对偏好分数，而不是直接在前向过程中强行保持合法概率分布。然后再通过 softmax，把这组分数变成：

- 全部非负
- 总和为 1
- 可解释成概率

的一整套分配。

这样做有一个很大的好处：模型在内部可以先自由表达相对偏好，再由一个统一的分布化步骤把这些偏好压成可比较的概率结构。

所以 logits 不是“奇怪的伪概率”，而是：

> 概率分布形成之前的原始偏好坐标。

理解这一层后，后面的 softmax、交叉熵和采样才会连成一条完整的链。

## 什么叫不确定性，它并不只是“模型差”

讲到这里，可以正式把“不确定性”引进来。

很多初学者一看到分布比较平，就下意识认为：

> 模型是不是不行？

这个判断太粗糙。

更准确地说，不确定性至少有两类来源。

第一类，来自任务本身。

真实语言里，很多上下文天然就允许多种合理续写。即使一个非常强的模型面对这样的前缀，也不应该被期待只剩一个唯一延续。这不是模型不够好，而是语言本来就带开放性。

第二类，来自模型自身的认知不足。

如果训练数据不够、表示能力不够、上下文理解不充分，模型也可能因为自己分不清候选而给出一个更平、更散的分布。

这两种不确定性在表面上都可能表现成“分布不够尖”，但它们的含义完全不同：

- 前者更像“问题本身开放”。
- 后者更像“模型自己还没学清楚”。

这层区分一旦立住，后面你就不会把所有不确定都粗暴理解成“模型坏了”。

## 尖分布和平分布：最实用的不确定性直觉

从工程角度看，最常用的不确定性直觉其实很朴素。

如果一个分布非常尖，通常意味着模型当前比较确定：大量概率质量被压到了极少数候选上。

如果一个分布比较平，通常意味着模型当前不够确定：多个候选仍然保留了明显权重。

这当然不是绝对规律，因为有时模型也可能以非常自信的方式犯错。但作为入门层面的直觉，它非常实用。你可以把它当成一种快速判断：

- 尖，通常意味着“我更偏向某几个候选”。
- 平，通常意味着“我还没有非常明确的偏向”。

这种直觉后面会直接影响你对 temperature、top-k、top-p 和重复生成问题的理解。

## 期望到底是什么，为什么它不是“考试题里的加权平均”那么简单

讲完分布之后，下一步自然就是期望。

很多人第一次学期望时，会把它记成一个公式化操作：

\[
\mathbb{E}[X] = \sum_x x P(x)
\]

这个公式当然是对的，但如果只把期望当成“考试题里的加权平均”，它很快就会变成一个死记对象。

更有用的理解是：

> 期望是在当前分布下，对结果做的一种概率加权平均，因此它表达的是“如果把所有可能结果及其权重综合起来，我整体上大概会落在哪”。

也就是说，期望不是在告诉你“必然会发生什么”，而是在告诉你：

> 在这套不确定性结构下，平均意义上的中心趋势大概在哪里。

这层理解特别重要，因为它能立刻帮你摆脱一个常见误解：

期望值不一定是某次真实观察里会直接出现的那个值。

例如，掷骰子的期望是 `3.5`，但单次掷骰子不可能掷出 `3.5`。这说明期望更像一种“分布重心”，而不是“一次具体实现结果”。

## 为什么期望在机器学习里非常自然

一旦你把期望理解成“按概率权重综合所有可能结果”，它在机器学习里的自然性就会变得非常明显。

因为训练和推理里，我们经常要处理的都不是单个确定结果，而是某个分布下的整体行为。例如：

- 平均损失，本质上就是一种期望式思路。
- 对不同样本的平均表现，本质上也在接近期望。
- 概率模型的很多目标函数，都在衡量某种平均意义下的表现。

更广义地说，只要一个系统面对的是“可能结果 + 对应权重”，期望就几乎必然会出现。它是一种把分布整体压缩成某个可比较统计量的方法。

当然，压缩总会损失信息。期望只能给你中心趋势，不能单独告诉你分布有多散、多偏或多不确定。但这恰恰也能帮你理解：

> 为什么机器学习里常常不只看均值，还要看方差、熵、分位数或整个分布形状。

## 从期望走向方差：为什么“平均上差不多”还不够

只知道期望还远远不够。因为两个分布完全可能拥有差不多的期望，却表现出完全不同的不确定性结构。

例如：

- 一个分布可能非常集中地围绕某个中心。
- 另一个分布可能非常分散，但加权平均之后刚好得到相似的中心值。

如果你只看期望，就会错把这两个系统当成差不多。

这就是为什么我们需要“离散程度”这层概念，而方差正是在表达这种信息。

对初学者来说，这里最重要的不是把方差公式立刻推得很熟，而是先抓住它的直觉：

> 期望告诉你分布大概围绕哪里，方差告诉你它围绕这个中心到底散得有多开。

把这层直觉放回语言模型语境，你就会更容易理解为什么：

- 有些上下文下模型分布很集中，采样变化小。
- 有些上下文下模型分布很分散，生成结果波动大。

也就是说，不确定性不只是“有没有多个候选”，还包括“这些候选的权重到底分散到了什么程度”。

## 为什么语言模型必须保留分布，而不是只保留 argmax

既然最后总要选一个 token，为什么模型不干脆只保留当前最大值对应的候选，而非要保留整套分布？

这是一个非常重要的问题。

因为一旦你只保留 argmax，也就是“当前第一名”，你会立刻丢掉大量关键信息：

- 第二名和第一名差多远？
- 分布到底很尖还是很平？
- 其他候选是不是也仍然合理？
- 当前判断到底是高度确定，还是只是勉强领先？

这些信息对推理策略非常关键。贪心解码、温度采样、top-k、top-p 之所以有意义，都是因为：

> 我们不只关心第一名是谁，还关心整个候选结构。

换句话说，分布不是“生成前的中间垃圾”，而是模型对世界当前判断的完整表达。

## 条件分布怎样一步步长成整段文本

到这里，可以把概率观点再往前推进一步。

语言模型并不是只做一次条件预测，然后事情就结束了。它真正做的是：

1. 先看当前上下文。
2. 给出下一个 token 的条件分布。
3. 选出或采样出一个 token。
4. 把这个新 token 接回上下文。
5. 再对新的位置重新给出条件分布。

这样一步步滚动下去，整段文本就被长出来了。

所以整台语言模型的生成过程，本质上是一连串条件分布决策的串联。它不是先在脑子里想好整段话，再一次性吐出来，而是：

> 每一步都在当前条件下重新分配候选后续的概率质量。

这也是为什么概率不是只属于训练目标，它同样属于推理过程的核心机制。

## 概率分布和采样策略为什么必须一起理解

如果你只学分布，不学采样，理解会停在一半。

因为模型给出分布之后，系统还要决定：

> 到底怎样从这套分布里选出下一个 token？

这里常见的策略包括：

- 直接取最大概率的候选。
- 调整 temperature 后再采样。
- 只保留前 `k` 个候选再采样。
- 只保留累计概率达到某个阈值的一部分候选再采样。

这些策略为什么会改变输出？

因为它们都在重新加工原始分布，要么只截取头部，要么把分布压尖或拉平，要么在不同程度上保留随机性。

所以“模型行为”和“推理行为”一定要分开理解：

- 模型行为：它给出了什么分布。
- 推理行为：我们怎样从这个分布里做决定。

这层区分一旦清楚，后面很多“模型怎么突然变笨了”“为什么同一个模型忽然变得很发散”的问题，就更容易定位到底是模型本体问题，还是采样策略问题。

## 为什么“不确定性”不是应该被彻底消灭的东西

很多初学者会觉得，一个理想模型应该永远高度确定。好像越尖的分布就一定越好，越平的分布就一定越差。

这种想法同样需要纠正。

如果一个问题本身就允许多种合理续写，那么一个成熟模型保留一定不确定性，往往反而更诚实。强行把所有场景都压成极尖的单峰分布，并不等于模型更聪明，很多时候只意味着它更武断。

所以我们真正希望的，不是“模型永远确定”，而是：

> 当世界本身明确时，模型能变得明确；当世界本身开放时，模型能以合理方式保留开放性。

这其实已经非常接近后面要讨论的校准问题了。一个好的概率模型，不只是会给出高概率和低概率，还应该让这些概率和真实世界里的相对可信度尽量匹配。

## 概率视角会怎样改变你看语言模型的方式

学到这里，最好回头看看自己的任务观有没有变化。

如果没有概率视角，语言模型很容易被误学成：

> 一台直接吐出单一答案的文本机器。

可有了概率视角之后，你会开始用另一种方式理解它：

- 它在每一步面对的是一个大候选空间。
- 它输出的首先是对这个候选空间的偏好分配。
- 这个偏好分配是条件性的，取决于前面的上下文。
- 生成不是一次性决定，而是分布决策的连锁过程。
- 不确定性不是噪声残渣，而是任务本身的一部分。

这套理解会直接改变你后面看待 softmax、交叉熵、采样、重复生成和困惑度的方式。

## 初学者在这里最容易犯的几个误解

这里把几个最常见的误解集中拆掉。

第一个误解是：语言模型理应直接输出唯一正确答案。

错。真实语言大多数时候并不提供唯一续写，模型更自然的表达方式是给候选结果分配概率。

第二个误解是：概率只是为了训练公式好写，和模型本体关系不大。

错。概率正是模型表达候选后续结构的核心语言。

第三个误解是：只看最高概率候选就够了。

错。分布的整体形状、不确定性和头尾结构同样重要。

第四个误解是：分布平就一定说明模型很差。

错。分布平可能来自模型不足，也可能来自任务本身天然开放。

第五个误解是：期望就是最可能出现的那个结果。

错。期望是分布的加权中心，不一定对应某次具体观测值。

第六个误解是：采样策略只是输出层的小技巧，和模型理解无关。

错。采样策略会直接改变我们如何消费模型给出的分布，因此必须和分布一起理解。

## 这一章真正要记住的核心句子

如果只能记住一句话，请先记住这一句：

> 语言模型不是在直接宣布唯一答案，而是在给定上下文的条件下，对整个候选词表分配概率质量；期望和不确定性则帮助我们理解这套分配的中心趋势与分散程度。

## 读完这一章之后，你应该能稳定回答这些问题

- 为什么语言模型天然需要概率，而不是只需要确定答案？
- 什么是概率分布，为什么它必须非负且总和为 1？
- 条件概率为什么是 next-token prediction 的核心句法？
- 为什么模型先输出 logits，而不是直接输出概率？
- 期望到底表示什么，它和“最可能结果”有什么区别？
- 为什么分布形状和不确定性对推理很关键？

## 如果现在只能先记住一个最重要的习惯

请先养成这个习惯：

> 每次看到模型输出，不要急着只问“第一名是谁”，而要先问“这是一种什么形状的分布，它到底有多确定，它在给哪些候选保留空间”。

这个观察习惯会在后面的训练、推理和调试章节里不断帮到你。

## 小结

这一章把几个看似分散的词重新接回了同一条主线：

- 候选空间
- 概率分布
- 条件概率
- 不确定性
- 期望

它们共同回答的是同一件事：

语言模型为什么不应该被理解成“直接输出标准答案的机器”，而应该被理解成“一台在上下文条件下持续分配可能性权重的系统”。

后面当你看到 softmax、交叉熵、困惑度和采样策略时，请把它们都放回这条主线里看。那样你会更容易意识到，它们并不是若干孤立技巧，而是同一个概率建模视角在不同位置上的展开。
