# 02. 概率分布、期望与不确定性

走到这一章，读者通常已经接受了几件关键事实：

- 模型内部处理的是数值对象，而不是神秘语义
- 模型可以被理解成输入到输出的参数化函数
- 神经网络最终会吐出一组数，表达它对不同候选结果的偏好

但只要一进入“概率”这条线，很多人的直觉会突然变得不稳定。

原因往往不是不会算，而是更前面的一层误解没有拆掉：

> 人们太容易把语言模型误看成一种“应该给唯一标准答案”的系统。

一旦这样看，后面很多核心概念都会显得别扭：

- 为什么模型不直接输出一个确定 token
- 为什么要保留一整个分布
- 为什么采样策略会改变结果
- 为什么同一个上下文下常常有多种合理续写
- 为什么交叉熵、困惑度和 calibration 都围着概率打转

所以这一章的任务，不是把你推进一堆抽象概率公式里。
它真正要建立的是一种更稳定的判断：

> 语言世界从来不是处处只有唯一后续的确定系统，因此模型最自然的表达方式，不是直接宣布“唯一答案”，而是给不同候选结果分配相对可能性。

只要这个判断站稳，概率分布、条件概率、期望和不确定性就不再像额外加上的数学内容，而会变成语言模型本来就必须使用的对象语言。

## 为什么语言模型不能只输出“一个答案”

很多初学者第一次听到“预测下一个 token”时，会不自觉把它想成学校里的填空题：

> 前文已经给出，后面应该只有一个唯一正确答案。

在极少数高度确定的例子里，这种直觉看上去似乎成立。

例如：

```text
1 + 1 =
```

这类前缀后面的合理续写确实很集中。

但一旦进入真实语言，这种“唯一标准答案”直觉很快就会崩掉。

例如：

```text
今天天气真
```

后面可能接：

- 好
- 热
- 冷
- 不错
- 糟

这些候选显然不是等可能的，但也很少只有一个可以被称为“宇宙中唯一正确”。

再比如：

```text
她推开门，发现桌上放着一封
```

后面可能是：

- 信
- 便签
- 纸条
- 邀请函

这说明真实语言有一个根本特征：

> 即使上下文已经提供了大量约束，后续仍常常不是唯一值，而是一组带不同可能性的候选。

只要这件事成立，模型最自然的任务形式就不再是“直接给出唯一正确答案”，而会变成“在所有候选后续之间分配相对可能性”。这正是概率为什么会进入语言模型。

概率不是后来强行套上去的数学外壳，而是任务形式本身要求的表达语言。

## 概率到底在描述什么

在学校里，概率经常和掷硬币、掷骰子、抽球这些例子一起出现。这些例子当然有帮助，但也很容易让人误会：

> 概率好像只是课本里研究随机小游戏的工具。

更稳的理解应该是：

> 只要一个系统面对多个可能结果，而这些结果出现的机会并不相同，就需要一种语言来描述这种“可能性结构”。

概率正是在做这件事。

换句话说，概率最朴素的角色不是神秘数学量，而是：

> 在给定信息条件下，对不同结果分配多少可能性权重。

这个定义非常重要，因为它能立刻纠正一个常见误解：

概率不是在表达“某件事真不真”的程度。

更准确地说，概率表达的是：

- 在当前信息下，哪些结果更应被看重
- 哪些结果相对不那么可能
- 当前判断到底有多确定

这层理解一旦站稳，后面很多事情都会自然起来：

- 为什么模型输出的不是一个 token，而是一整排分数
- 为什么同一个 prompt 可以有多种合理续写
- 为什么有时我们想保守生成，有时又想保留更多随机性

## 从结果集合到概率分布：先把“可能发生什么”说清楚

为了让后面术语稳定下来，先用非常轻的方式区分几件基础事。

当我们讨论一个随机过程时，最先需要的是“可能发生什么”这张清单。

在掷骰子里，这张清单是：

\[
\{1,2,3,4,5,6\}
\]

在语言模型里，如果我们把“预测下一个 token”看成一次带不确定性的选择，那么这张清单就可以理解成：

> 词表里所有可能成为下一个位置续写的 token。

一旦这张清单明确了，概率分布做的事情就很清楚了：

> 它不是挑一个结果出来，而是给整个候选集合做一整套可能性分配。

这意味着分布关心的不是某一项孤立数值，而是整个候选空间的结构布局。也正因为如此，“第一名是谁”虽然重要，却远远不是全部。

## 什么是概率分布

现在可以正式进入本章最重要的对象。

最朴素地说，概率分布就是：

> 对一个样本空间中的所有可能结果，给出一整套非负且总和为 1 的可能性分配规则。

这个定义里有三层关键信息。

第一，它不是单个概率，而是一整套分配。

很多人第一次接触概率时，会把“概率”理解成某一个结果的数值。比如“掷到 6 的概率是 \(1/6\)”。这当然没错，但分布讲的是更完整的结构：1 的概率是多少，2 的概率是多少，直到所有候选都被分配完。

第二，所有概率都必须非负。

“某个结果的可能性权重是负的”在解释上没有意义。概率可以等于零，表示在当前模型或当前假设下，这个结果被认为不会出现；但它不能小于零。

第三，全部概率加起来必须等于 1。

这表示：所有可能性都已经在这套分配里被完整考虑了。总和小于 1，说明还有可能性没有交代清楚；总和大于 1，则说明这组数已经不再能被解释成一套合法概率分配。

这也是为什么后面 softmax 会如此自然。它的作用之一，就是把任意一组原始分数压成一套合法分布。

## 为什么“分布结构”比“第一名是谁”更重要

初学者看分布时，最容易只盯着第一名。

例如，两个分布的最高概率候选都可能是同一个 token，但它们的整体结构却完全不同。

设想下面两种情况。

第一种：

```text
token A: 0.92
token B: 0.03
token C: 0.02
token D: 0.03
```

第二种：

```text
token A: 0.31
token B: 0.27
token C: 0.21
token D: 0.21
```

两种分布的第一名都是 `token A`，但它们表达的状态完全不同。

第一种是在说：模型非常确定，候选几乎被压扁成了一个主峰。

第二种是在说：虽然 `token A` 暂时排第一，但其他候选也并没有被甩开很多，模型仍然保留了明显不确定性。

这说明分布真正重要的，往往不是“第一名是谁”，而是：

- 头部有多尖
- 尾部有多长
- 候选之间差距有多大
- 不确定性被压缩到了什么程度

后面你理解采样、困惑度、校准和幻觉问题时，这层直觉都会被反复调用。

## 什么叫不确定性，它从哪里来

说到这里，可以正式把“不确定性”引进来。

不确定性并不只是“模型差”的另一种说法。更准确地说，它至少有两种来源。

第一种来源是任务本身的不确定性。

真实语言里，很多上下文天然就允许多种合理后续。即使一个非常强的模型面对这样的前缀，也不应被期待只保留一个唯一延续。这不是模型不够好，而是语言本身就不是完全确定系统。

第二种来源是模型自己的认知不足。

如果训练数据不够、表示能力不够、上下文理解不充分，模型也可能因为自己分不清候选而表现出更平、更散的分布。

这两种不确定性在表面上都可能让分布变平，但它们的含义不同：

- 前者更像“问题本身就开放”
- 后者更像“模型自己还没学清楚”

只要这层区分先站稳，你后面就不会把所有不确定都粗暴理解成“模型坏了”。

## 尖分布和平分布：最实用的不确定性直觉

从工程角度看，最常用的不确定性直觉其实很朴素。

如果一个分布非常尖，往往意味着模型当前相对确定：它把大量概率质量压到了少数候选上。

如果一个分布比较平，往往意味着模型当前不够确定：多个候选都还留着较高权重。

这当然不是绝对规则，但它已经足够实用。

例如：

- 高温度采样通常会把分布拉平
- 低温度采样通常会让分布更尖
- 模型遇到陌生或歧义前缀时，也更可能输出较平分布

所以看分布时，一个非常好用的问题不是“第一名是谁”，而是：

> 当前模型到底有多确定，它的概率质量是怎样组织起来的？

## 条件概率为什么是语言模型真正的核心

到这里，就必须把“条件”重新摆回主位。

语言模型最根的任务不是给 token 一个无条件频率表，而是：

\[
P(x_{t+1} \mid x_1,\dots,x_t)
\]

也就是：

> 在已经看到前文的条件下，下一个位置各个候选 token 的概率是多少？

这就是条件概率。

只要你把语言模型的任务定义成这样，很多后续结构都会立刻找到位置：

- prompt 会重要，因为它就是条件的一部分
- conversation history 会重要，因为它改变条件
- position 会重要，因为前后顺序决定条件结构
- causal mask 会重要，因为它保证当前位置只能依赖左侧条件

也就是说，语言模型真正的核心不是“概率”三个字本身，而是：

> 条件概率。

模型不是在空中猜词，而是在特定前缀约束下重新分配下一步可能性。

## 联合概率、边缘概率和条件概率之间是什么关系

虽然你现在不需要把概率论形式体系全部学完，但至少要建立一个稳定关系网。

边缘概率可以粗略理解成：不管别的变量怎样，只看某个变量自己出现的概率。

联合概率是在问：几个事件同时出现的概率是多少。

条件概率则是在问：在已经知道一部分信息的前提下，另一个事件出现的概率是多少。

对语言模型来说，这三种语言并不是彼此分离的。

我们关心单个位置 token 的条件概率，但整段文本又可以被理解成一串条件概率连起来的联合结构。这就是为什么序列建模天然会和联合概率、条件概率纠缠在一起。

## 为什么整段文本会和联合概率连接起来

假设一段 token 序列是：

\[
x_1, x_2, \dots, x_T
\]

那么整段文本的联合概率可以写成：

\[
P(x_1, x_2, \dots, x_T)
=
P(x_1)P(x_2\mid x_1)\cdots P(x_T\mid x_{<T})
\]

这里最重要的不是公式推导，而是它表达的结构：

> 一整段文本不是靠某个神秘“总评分”被定义的，而是由一串局部条件判断连起来的。

这也是为什么“预测下一个 token”虽然看起来是局部任务，却足以支撑整段文本建模。因为只要每一步的条件分布被学对，整段序列的联合结构就能被逐步建立起来。

## 经验分布：模型真正是在向谁学习

现在再把概率往训练数据方向接一步。

现实中，模型并不是直接面对“世界真实分布”这件纯抽象事。它真正看到的是语料，也就是一个有限但很大的样本集合。

所以从训练角度看，模型最先接触到的其实是：

> 数据集中已经出现出来的经验分布。

也就是说，语料里哪些模式高频、哪些低频、哪些搭配常见、哪些上下文更容易跟某种后续连在一起，这些都会先以经验频率的形式显现出来。

模型训练的工作，某种意义上就是在尽可能让自己的输出分布去逼近这些经验规律。

这就是为什么“数据分布”会成为后面一切问题的源头之一。模型学到的从来不是脱离语料的抽象真理，而首先是：

> 训练语料里那些可以被统计出来、并可由参数逼近的规律。

## 为什么机器学习里到处都是“平均”

接下来必须引入另一个在训练里几乎无处不在的对象：期望。

最朴素地说，期望就是带权平均。

如果一个随机变量可能取多个值，而每个值都有对应概率，那么期望就是：

> 按概率作为权重，把这些可能结果做平均。

它不是“最可能值”的同义词，也不是“实际一定会发生的值”。它表达的是：

> 在这套不确定性结构下，长期或总体上更能代表整体水平的平均结果。

这为什么重要？

因为机器学习几乎到处都在做某种平均：

- 对一个 batch 的 loss 取平均
- 对很多位置的 token 损失取平均
- 对很多样本的表现做总体评价
- 用若干随机 mini-batch 估计整体训练趋势

如果没有期望这个对象，你会看到一堆“平均”操作，却很难意识到它们其实共享同一套统计语言。

## 为什么 batch loss 常常只是总体期望的一次局部估计

很多初学者第一次看训练时，会以为某一步 `loss` 就代表了“模型真实水平”。

更准确的理解应该是：

> 单个 batch 的 loss 往往只是总体目标的一次局部采样估计。

原因很简单。你不可能每一步都把整个数据分布完整看一遍，所以训练只能不断从总体里抽出一小批样本，用这一小批样本的平均损失来近似整体目标。

这就会自然带来两个后果：

- 每一步 loss 本来就可能有波动
- 局部波动并不等于整体趋势改变

只要这层理解站稳，后面你看 loss 曲线时就不会把每一次小抖动都误判成模型突然坏掉或突然学会了什么。

## 为什么语言模型的目标也天然会落成期望问题

语言模型虽然看起来在做 next-token prediction，但训练时真正优化的往往不是某一个位置、某一个样本，而是：

> 在整体数据分布上，模型给真实后续分配概率的平均表现。

这意味着它天然就是一个期望问题。

换句话说，我们并不是只在乎某一个 token 的概率分得对不对，而是在乎：

- 对很多位置平均起来，模型有没有把真实 token 越来越往高概率方向推
- 对很多样本平均起来，模型整体的预测分布是否越来越接近数据规律

所以“期望”不是后面才会突然出现的统计小工具，而是训练目标本来就在做的事情。

## 什么叫校准，为什么它和不确定性有关

再往前走一步，你会遇到一个非常重要但常被忽视的词：校准。

最朴素地说，校准是在问：

> 模型给出的概率，和真实世界中这些概率所对应的发生频率，到底是不是大致匹配？

如果模型总是把某些候选说成“90% 很可能”，但现实中它们远没有那么常对，那么这个模型虽然也会输出分布，却不一定是一个校准良好的分布系统。

这说明：

> 会给概率，不代表概率就一定可信。

所以概率分布的学习，不只是“第一名排得对不对”，也还包括“这些概率值本身是否有解释意义”。

这件事和后面的评估、温度调节、幻觉理解都会重新接上。

## 为什么这一章会自然走向对数概率和交叉熵

到这里，你已经接受了几件事：

- 模型应该输出分布，而不是唯一答案
- 语言模型的核心任务是条件概率预测
- 整段文本概率会由很多局部条件概率链起来
- 训练目标最终会落成总体平均表现

新的问题就会自然出现：

> 既然模型已经给出了概率分布，我们究竟该怎样评价它“分得好不好”？

这时，仅仅停在“有分布”还不够。

你需要进一步进入：

- 对数概率
- 负对数似然
- 交叉熵
- 困惑度

这些对象之所以会出现，不是因为后面的章节突然开始“更数学”，而是因为：

> 一旦你真的要拿概率分布来训练模型，就必须有一套办法衡量真实答案在这份分布里究竟获得了多少偏好，以及这种偏好应该怎样在序列和样本层面被聚合。

这正是下一章要继续回答的问题。

## 这一章最后应该留下什么

如果这一章最后只留一个判断，那应该是这句：

> 语言模型之所以天然需要概率分布，不是因为研究者喜欢用概率，而是因为真实语言在给定上下文后通常仍然存在多种可能后续；模型必须表达这种可能性结构，而训练则是在让模型输出的条件分布越来越接近数据里出现的规律。

这句话一旦站稳，后面你再进入：

- 对数概率
- 交叉熵
- 困惑度
- 采样
- 校准

就不会觉得这些概念是凭空追加的公式，而会知道它们都在继续处理同一个核心问题：模型怎样表达、学习并使用不确定性。
