# 06. 概率、softmax 与交叉熵

如果你后面要真正理解这些词：

- logits
- token 分布
- next-token prediction
- loss
- perplexity

那么这一章几乎绕不过去。

因为语言模型最底层做的事情，并不是“直接给出下一个词”，而是：

> 在当前上下文条件下，对整个候选空间给出一份概率分布。

而一旦问题被写成“给候选空间分配概率”，你就会自然遇到三样东西：

- 概率分布
- softmax
- 交叉熵

如果这些概念不稳，你后面即使记住“模型训练目标叫预测下一个 token”，也不会真正理解为什么训练代码最后总会落成那一行 loss。

更严重的是，你会形成一种很常见的假理解：

> 模型好像先神秘地产生一些数，再神秘地喂给一个叫 `cross_entropy` 的函数，训练就自己开始了。

这一章的职责，就是把这条链从头拆开。

## 先从最朴素的问题开始：为什么预测常常不是“只选一个答案”

很多初学者第一次理解机器学习时，会把预测想成下面这种形式：

- 输入一个样本
- 模型返回一个答案
- 答案对或不对

这种想法在最粗糙的层面没有错，但它还太扁平。

因为真实世界里，很多预测问题并不是：

> 现在只可能有一个唯一答案，其他答案都完全不可能。

更常见的情况是：

> 有多个候选，其中一些更合理，一些较不合理，但它们不是全有或全无的关系。

例如看到一句话：

```text
今天天气真
```

后面可能接：

- 好
- 热
- 冷
- 不错
- 糟

这些候选当然不一样，但它们都不是逻辑上彻底不可能。

这意味着模型真正要学的，不应该只是：

> 最后拍板说一个词。

而更应该是：

> 对所有候选词给出一份合理的相对可能性分配。

这就把我们带进了概率分布。

## 什么叫概率分布

概率分布最朴素的理解是：

> 面对多个候选结果时，我们给每个结果分配一个发生可能性的大小。

这些可能性通常满足两个基本条件：

1. 每一项都不小于 `0`。
2. 所有项加起来等于 `1`。

例如对三个候选事件：

```text
A: 0.7
B: 0.2
C: 0.1
```

这就是一份合法分布。

它表达的不是：

- A 一定发生
- B 完全不会发生
- C 可以忽略

而是：

> 在当前条件下，A 最可能，B 次之，C 更小，但三者都属于候选空间的一部分。

## 为什么机器学习喜欢输出分布，而不是只输出一个类别

因为分布比“一个硬答案”包含更多信息。

看下面两种输出。

第一种：

```text
猫: 0.51
狗: 0.49
鸟: 0.00
```

第二种：

```text
猫: 0.99
狗: 0.01
鸟: 0.00
```

如果只看最终答案，两者都会选择“猫”。

但它们表达的模型状态显然完全不同：

- 第一种是犹豫的
- 第二种是极有把握的

分布保留了这种不确定性结构，而“只输出一个类别标签”会把大量信息压扁。

这就是为什么现代分类模型、语言模型和很多预测系统，都更喜欢先输出分布，再决定怎样使用这份分布。

## 语言模型为什么天然是分布预测问题

对语言模型来说，这一点尤其自然。

因为语言本来就是充满不确定性的。

给定前文之后，下一个 token 经常不是唯一的。

例如：

```text
今天会议决定
```

后面可能接：

- 延期
- 继续
- 取消
- 召开

不同候选在不同语境里的概率会不同，但它们很少像数学定理那样只有一个绝对唯一答案。

于是语言模型需要学的，不是：

> 遇到这个前文时，永远死板地吐出某一个 token。

而是：

> 在当前上下文条件下，对整个词表中的 token 给出一组合理的相对可能性。

这正是分布预测。

## 为什么“候选空间是整个词表”这件事很关键

在普通分类问题里，候选类别可能只有几个：

- 猫 / 狗 / 鸟
- 正样本 / 负样本
- 好评 / 中评 / 差评

但语言模型不一样。

它的候选空间通常是：

> 整个词表中的所有 token。

这意味着在每一个被监督的位置上，模型都要面对一个很大的多分类问题。

如果词表有 `V` 个 token，那么模型在每个位置上，其实就是在做：

> 从 `V` 个候选里，对每个候选分配条件概率。

所以语言模型从机器学习角度看，本质上可以被理解为：

> 一个超大类别空间上的条件分布预测器。

这句话非常重要。
后面你再看到 logits、softmax、cross-entropy 时，就不会觉得这些东西像“LLM 特有黑魔法”，而会知道：

> 它们只是大词表分类在序列场景里的自然展开。

## 什么是 logits

现在我们进入第一个高频词：`logits`。

模型直接输出的通常不是概率，而是一组 logits。

你可以先把 logits 理解成：

> 每个候选 token 的未归一化分数。

这些分数有几个特征：

- 它们可以是任意实数
- 可以为正
- 可以为负
- 大小差异可能很大

例如对三个候选 token，模型可能给出：

```text
好: 2.4
冷: 0.3
热: -1.1
```

这些数表达了模型偏好：

- `2.4` 比 `0.3` 大，说明模型更偏向“好”
- `0.3` 比 `-1.1` 大，说明模型更偏向“冷”而不是“热”

但这些数本身还不是概率分布，因为：

- 它们可以小于 `0`
- 它们加起来不等于 `1`
- 它们没有直接满足概率约束

所以 logits 更像是：

> 概率分布之前的一层自由分数空间。

## 为什么模型不直接输出概率

这是一个非常自然的问题：

> 如果最后要的是概率，为什么模型不一开始就直接输出概率？

原因主要有三个。

第一，概率空间约束太强。

如果你要求模型直接输出一组概率，它必须同时满足：

- 每项非负
- 总和为 `1`

这会给模型输出层带来额外约束。

而 logits 没有这些限制，它们只是任意分数。
这让模型更容易先学出一套“相对偏好”，再由后处理把偏好映射成概率。

第二，分数空间更便于数值优化。

很多损失函数实现都不是真的先显式算出概率，再单独算 loss。
它们会直接基于 logits 做更稳定的数值计算。

这就是为什么很多框架里你常见的不是：

```python
softmax(logits) -> loss
```

而是：

```python
cross_entropy(logits, target)
```

因为这个函数内部通常会以更稳定的方式同时完成 softmax 与对数概率计算。

第三，模型更容易先学相对排序。

从学习的角度看，模型先学会：

- 谁应该更高
- 谁应该更低
- 差距应当多大

往往比一开始就被迫满足严格概率约束更自然。

所以“先输出 logits，再把 logits 变成分布”是一个非常合理的设计。

## logits 最重要的直觉：它们表达的是相对偏好

初学者很容易误以为 logits 必须有某种直接语义，比如：

- `3.2` 就表示 `320%` 的把握
- `-1.7` 就表示“不可能”

这都是误解。

单个 logit 的绝对值本身并没有直观概率语义。

真正重要的是：

> 不同候选之间的相对大小关系。

例如：

```text
token A: 5.0
token B: 4.8
token C: 0.2
```

这说明：

- A 和 B 都被高度偏好
- C 明显更弱
- A 只是略强于 B

而不是说：

- A 本身“有 5 成概率”
- B “有 4.8 成概率”

logit 不是概率百分比。
它是为后续映射到概率服务的原始分数。

## softmax 在做什么

现在我们进入第二个核心部件：`softmax`。

softmax 的作用是把一组 logits 变成一份合法概率分布。

它完成了两件事：

1. 把任意分数转换成正的权重。
2. 把这些权重归一化成总和为 `1` 的分布。

于是模型就能从“任意实数分数”过渡到“可解释为概率的结果”。

如果只记角色，不记公式，那它就是：

> logits 通往概率分布的桥梁。

## softmax 为什么要“先拉开，再归一化”

你可以这样理解 softmax 的过程。

第一步，把分数差异转成正权重。

如果某个候选分数更高，它就应该得到更大的权重。
如果某个候选分数更低，它就应该得到更小的权重。
而且这个权重不能是负数，因为概率不允许为负。

第二步，把权重变成总和为 `1` 的东西。

就算我们已经有了一堆正权重，它们也还不一定是概率。

例如：

```text
候选 A: 10
候选 B: 3
候选 C: 1
```

这只是三份权重。
要把它们解释成概率，就必须再做归一化，把总量压到 `1`。

这就是 softmax 的基本任务。

## 一个具体例子：从 logits 到概率

假设模型给出三个 logits：

```text
好: 2.4
冷: 0.3
热: -1.1
```

你不需要手算精确值，但从直觉上可以知道：

- “好”的概率应该最大
- “冷”居中
- “热”最小

而且 softmax 之后：

- 三项都必须是正数
- 三项之和必须等于 `1`

一个可能的结果会像：

```text
好: 0.85
冷: 0.10
热: 0.05
```

注意这里发生了两层变化：

1. 排序被保留了。
2. 结果现在已经能被当成概率解释了。

所以 softmax 并不是“随便换一种写法”，而是从分数空间进入概率空间的正式步骤。

## softmax 最值得理解的四个性质

### 第一，排序不会被颠倒

如果一个 token 的 logit 比另一个大，那么经过 softmax 之后，它的概率仍然会更大。

这意味着：

> softmax 不会颠倒模型偏好，只会把偏好变成概率表达。

所以：

- `argmax(logits)`
- `argmax(softmax(logits))`

得到的是同一个候选。

### 第二，它会把差距转成竞争优势

logits 的差距越大，softmax 之后概率往往越尖锐。

例如：

```text
A: 10
B: 1
C: 0
```

这和：

```text
A: 1.0
B: 0.9
C: 0.8
```

虽然两者排序相同，但 softmax 之后的分布形状会很不一样。

前者更像：

> A 几乎碾压其他候选。

后者更像：

> A 略占优势，但竞争仍然存在。

所以 softmax 不只关心谁最大，也关心候选之间差多少。

### 第三，同时加同一个常数，分布不变

例如：

```text
[2, 1, 0]
```

和：

```text
[102, 101, 100]
```

softmax 结果是一样的。

为什么？

因为真正起作用的不是绝对水平，而是相对差值。

这条性质在数值稳定里非常重要。
很多实现会先减去最大 logit，再做后续计算，就是在利用这一点。

### 第四，整体缩放会改变分布尖锐程度

如果把所有 logits 差距整体放大，softmax 后的分布会更尖锐。

如果把差距整体缩小，分布会更平缓。

这件事和后面推理阶段的 `temperature` 有直接关系。

虽然这里先不深入采样策略，但你至少要知道：

> softmax 不只是把分数映射成概率，它还会把“分数差距”转成“置信度形状”。

## 为什么训练时不能只看 argmax

到这里，一个很自然的问题会出现：

> 如果最终我们只关心哪个 token 最大，为什么训练时不直接根据 argmax 对不对来优化？

因为 argmax 太粗糙了。

它只保留最后一个硬判断：

- 对
- 或错

但它丢掉了太多有用信息。

看下面两个模型输出，假设真实答案都是“好”。

模型 A：

```text
好: 0.45
冷: 0.50
热: 0.05
```

模型 B：

```text
好: 0.001
冷: 0.998
热: 0.001
```

如果只看 argmax，两者都可能被判成错。

但这两个“错”的性质完全不同：

- 模型 A 已经几乎猜对了
- 模型 B 则是非常自信地猜错了

如果训练信号只告诉你“都错了”，那就太浪费了。

我们更希望训练能区分：

- 稍微错一点
- 错得离谱
- 自信地错
- 犹豫地错

分布式损失正是为此而存在的。

## 真实目标到底是什么

在训练时，每个位置都会有一个真实目标 token。

例如词表里有几千、几万甚至更多候选，但当前这个位置真正应该出现的是：

```text
token #57
```

那么好的模型应该做到：

- 给 `#57` 较高概率
- 给无关 token 较低概率

于是训练真正关心的问题就变成：

> 在模型给出的整份分布里，真实目标 token 拿到了多少概率质量？

这句话非常关键。

因为它说明训练不是在问：

> 模型最终选没选中？

而是在问：

> 模型有没有把足够多的概率压到正确答案上？

这就自然把我们带到交叉熵。

## 交叉熵最朴素的直觉

交叉熵损失可以先非常直白地理解成一句话：

> 它惩罚模型对真实答案不够自信，尤其惩罚把高概率给错对象的情况。

如果真实目标 token 被模型分到很高概率，那么 loss 会较小。

如果真实目标 token 只拿到很低概率，那么 loss 会较大。

这非常符合训练目标，因为我们真正想要的是：

> 在正确位置上，把概率质量尽量压到真实 token 上。

## 为什么“真实 token 的概率越高，loss 越低”是合理的

假设真实 token 是：

```text
目标 = "好"
```

如果模型给出：

```text
好: 0.85
冷: 0.10
热: 0.05
```

我们会觉得这个模型表现不错。

如果模型给出：

```text
好: 0.08
冷: 0.55
热: 0.37
```

那它显然做得很差。

交叉熵做的事，就是把这种“对真实答案的信心差异”压成一个可优化的数值。

所以它不是武断选择的损失，而是和预测目标高度匹配的。

## 为什么交叉熵会特别惩罚“自信地错”

这是交叉熵最值得建立直觉的地方之一。

如果模型只是稍微把真实答案放低一点，loss 会变差，但还不至于特别极端。

但如果模型对一个错误答案极其自信，同时给真实答案极低概率，那么 loss 会明显变大。

为什么这是合理的？

因为这类错误比“犹豫地错”更危险。

看两个例子，真实答案都是“好”。

例子一，犹豫地错：

```text
好: 0.45
冷: 0.50
热: 0.05
```

例子二，自信地错：

```text
好: 0.001
冷: 0.998
热: 0.001
```

这两者都可能在 argmax 上错，但第二种明显更糟。

交叉熵把这种差别清楚地刻画出来了。
这也是为什么它在分类和语言模型训练里如此自然。

## one-hot 目标到底在表达什么

在多分类设置里，真实目标常被写成 one-hot 形式。

例如词表有三个候选：

- 好
- 冷
- 热

如果真实答案是“好”，那目标分布就可以写成：

```text
好: 1
冷: 0
热: 0
```

这叫 one-hot，不是因为它本身神秘，而是因为：

> 它把“当前监督信号只明确指向一个真实类别”写成了分布形式。

于是训练时，本质上是在比较：

- 模型预测分布
- 目标分布

两者之间有多不一致。

所以你可以把交叉熵理解成：

> 预测分布与目标分布之间的一种不匹配度量。

## 为什么这里会用到对数概率

前面的数学卷已经讲过：

- 对数能把乘法结构变成加法结构
- 小概率事件的对数会把“罕见程度”显式放大
- 负对数概率天然可以被解释成“惊讶度”

这些东西在这里会真正落地。

当真实答案的概率很高时：

- 对数概率更接近 `0`
- 负对数概率较小

当真实答案的概率很低时：

- 对数概率会很负
- 负对数概率会变大

所以“对真实答案的负对数概率”恰好是一种非常自然的损失写法。

你可以把它理解成：

> 模型把正确答案看得越不可能，它对这个样本的惊讶度就越大，损失也就越大。

这就是为什么很多地方也会把交叉熵与负对数似然联系起来讲。

## 为什么框架里常常直接写 `cross_entropy(logits, target)`

到这里你就能理解一个常见现象了。

很多框架不会让你先手写：

1. logits
2. softmax
3. 对数
4. 负号
5. 取真实类别
6. 求平均

而是直接给你：

```python
cross_entropy(logits, target)
```

这不是因为中间步骤不重要，而是因为：

> 中间逻辑已经固定且常见，框架可以把它们封装成一个更稳定、更高效的接口。

所以初学者最该做的，不是只会调这个函数，而是知道它内部在逻辑上完成了什么：

- 把 logits 变成可比较的分布意义
- 抓住真实目标对应的概率
- 用负对数形式把它变成损失

这样你后面看到任何现成 API，都不会把它误学成黑箱。

## 什么叫数值稳定，为什么这里特别重要

softmax 和对数都很容易遇到数值问题。

例如：

- 某些 logit 特别大
- 指数运算可能溢出
- 某些概率特别小
- 取对数时数值可能非常极端

这就是为什么实现里经常会用：

- 先减去最大 logit
- 用 `log_softmax`
- 把 softmax 与交叉熵合并实现

这些技巧的目的不是改变数学意义，而是：

> 在有限精度的数值计算里，尽量保持结果稳定可靠。

这也提醒你一件事：

现代机器学习里的很多“框架函数”，并不是为了藏公式，而是为了把公式变成可在真实硬件上稳定运行的实现。

## 为什么语言模型的 loss 能在很多位置同时算

在普通分类任务里，一条样本常常只给一个标签。

但语言模型不一样。

一条长度为 `T` 的序列样本，往往在很多位置上都可以产生监督。

例如：

```text
我 喜 欢 你
```

可以形成多次局部预测：

- 给定“我”，预测“喜”
- 给定“我 喜”，预测“欢”
- 给定“我 喜 欢”，预测“你”

这意味着一条样本内部，其实有多个位置都在做“对整个词表分配分布、再与真实 token 比较”的动作。

于是语言模型训练可以被理解成：

> 在很多位置上同时重复同一类大词表分类问题。

这也解释了为什么语言模型的输出常常是：

```text
[B, T, V]
```

而标签常是：

```text
[B, T]
```

因为每个样本、每个位置，都对应一份词表分布和一个真实 token 编号。

## 为什么说语言模型训练是在很多位置上重复做同一类事情

到这里，一条非常重要的连续性已经出现了。

语言模型看起来像是在做很复杂的文本生成。

但从训练视角看，它其实在重复下面这件事：

1. 给当前位置生成一组 logits。
2. 用 softmax 把 logits 解释成词表分布。
3. 找到真实下一个 token。
4. 用交叉熵衡量模型给它分了多少概率。

然后把这个过程沿着很多样本、很多位置并行展开。

所以训练语言模型最核心的那一行 loss，不是一个突然出现的工程细节。
它是这一整章逻辑的必然终点。

## 为什么交叉熵下降不自动等于“生成一定好看”

到这里也必须顺手拆掉一个常见误解。

交叉熵下降当然通常是好信号。
它说明模型在训练目标下，确实越来越愿意把概率压到真实 token 上。

但它不自动保证：

- 生成文本一定流畅
- 长程结构一定稳
- 重复问题一定消失
- 推理采样一定好看

为什么？

因为训练时优化的是：

> 在真实数据分布上，对每个监督位置的真实 token 概率分配。

而生成时你还会额外引入：

- 采样策略
- 停止条件
- 上下文积累误差
- 长序列滚动效应

所以交叉熵是核心训练信号，但不是唯一质量定义。

这也是为什么后面还要专门讲：

- perplexity
- 定性样例
- 训练 loss 与生成质量不完全同步

## 为什么这章是进入 LLM 主体前的硬前置

如果你现在回头看后面那些常见的大模型术语，你会发现它们突然变得更可解释了。

例如：

- logits：原来只是词表分数
- next-token prediction：原来只是位置级大词表分类
- loss：原来就是对真实下一个 token 的交叉熵
- perplexity：原来是基于这类对数概率损失衍生出的衡量方式

也就是说，这一章做的不是再引入几个新名词。

它做的是把后面整条语言模型训练主线的输出端和损失端彻底打通。

如果这里没有站稳，后面你会一直觉得：

- 模型先吐 logits
- 然后神秘地算了 loss

而不会真正知道：

> 训练目标为什么恰好长成这样。

## 读完本章后，你应该能稳定回答什么

如果这一章真正起作用了，你应该能够稳定解释下面这些问题：

- 为什么很多预测任务更自然地写成分布预测
- logits 和概率之间到底差在哪
- softmax 到底在做什么，而不是“让数字好看一点”
- 为什么训练时不能只看 argmax 对不对
- 交叉熵为什么会惩罚“自信地错”
- one-hot 目标到底在表达什么
- 负对数概率为什么会自然进入损失
- 为什么语言模型训练可以理解成很多位置上的大词表分类

如果这些问题还答不稳，后面进入真正的 next-token 训练目标时，你仍然会觉得自己在背黑话。

## 小结

这章最想留下的主句可以浓缩成这样：

> 模型先输出 logits 这种自由分数，再通过 softmax 把它们变成对候选空间的概率分布，最后用交叉熵衡量它把多少概率质量分给了真实答案。

把它放回语言模型里，这句话还可以再具体一点：

> 语言模型训练本质上是在每个有效位置上，对整个词表做一次分布预测，然后检查真实下一个 token 拿到了多少概率，并把这个差距累积成可优化的损失。

只要这一层真正站稳，后面的：

- next-token prediction
- perplexity
- 采样
- 生成质量

就都会重新回到同一条清楚的训练逻辑上：

> 模型到底怎样把“更可能的下一个 token”写成可以学习的数值目标。
