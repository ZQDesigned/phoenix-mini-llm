# 04. 概率、softmax 与交叉熵

## 为什么这一章是进入语言模型前的硬前置

如果你后面要真正理解：

- logits
- token 分布
- next-token prediction
- loss

那么这一章几乎绕不过去。

因为语言模型最底层是在做分布预测，而分布预测天然会把我们带到：

- 概率
- softmax
- cross-entropy

如果这些概念不稳，你后面即使知道训练目标叫“预测下一个 token”，也不会真正理解它为什么会落实成那一行 loss 代码。

## 什么叫概率分布

概率分布最朴素的理解是：

> 面对多个候选结果时，我们给每个结果分配一个发生可能性的大小。

这些可能性通常满足：

- 每一项都不小于 0
- 所有项加起来等于 1

例如对三个候选：

```text
A: 0.7
B: 0.2
C: 0.1
```

这就是一个分布。

在语言模型里，这些候选不是 `A/B/C`，而是整个词表中的 token。

## 语言模型为什么天然是分布预测问题

给定一句话的前文时，下一个 token 往往不是唯一可能。

例如：

```text
今天天气真
```

后面可能接：

- 好
- 热
- 冷
- 不错

它们的可能性当然不同，但不是只有一个候选拥有绝对唯一地位。

这说明模型需要学的不是一个死板答案，而是：

> 在当前上下文条件下，对整个词表给出一组合理的相对可能性。

这正是分布预测。

## logits 是什么

模型直接输出的通常不是概率，而是一组 logits。

你可以把 logits 理解成：

> 每个候选 token 的未归一化分数。

它们可以是任意实数：

- 正数
- 负数
- 大小差异很大

logits 的相对大小表达模型偏好：

- 更大的 logit 通常表示更偏好
- 更小的 logit 通常表示更不偏好

但它们本身还不是合法概率分布，因为：

- 可能有负数
- 总和不一定是 1

## softmax 在做什么

softmax 的作用是把一组 logits 变成概率分布。

它完成了两件事：

1. 把所有分数转成正数权重  
2. 把权重归一化成总和为 1 的分布  

于是模型就能从“任意分数”过渡到“可解释为概率的分布”。

你不需要现在死背公式，但必须牢牢记住它的角色：

> softmax 是 logits 通往概率分布的桥梁。

## 为什么不直接让模型输出概率

一个自然问题是：

> 既然最后要概率，为什么模型不直接输出概率？

因为在训练和数值计算里，让模型先输出 logits 更方便也更稳定。

原因包括：

- logits 不需要先满足概率约束
- 许多损失函数实现会直接基于 logits 做更稳定计算
- 模型内部学习相对分数通常比直接硬约束概率更自然

所以“输出 logits，再交给 softmax 或带 softmax 的损失函数处理”，是非常常见的模式。

## 什么叫正确预测

在训练时，每个位置都会有一个真实目标 token。

比如词表里有很多候选，但当前这个位置真正应该出现的是：

```text
token #57
```

那么一个好的模型应该做到：

- 给 `#57` 较高概率
- 给其他无关 token 较低概率

于是训练的核心就变成：

> 当真实目标是某个 token 时，模型当前给它的概率高不高？

这就自然引出了交叉熵。

## 交叉熵为什么是合理的损失

交叉熵损失的直觉可以先说成一句话：

> 它惩罚模型对真实答案不够自信，尤其惩罚把高概率给错对象的情况。

如果真实目标 token 被模型分到很高概率，那么 loss 会较小。

如果真实目标 token 只拿到很低概率，那么 loss 会较大。

这非常符合训练目标，因为我们想让模型学会：

> 在正确位置上，把概率质量尽量压到真实 token 上。

## 为什么“真实 token 的概率越高，loss 越低”

从直觉上看，这是完全合理的。

假设真实 token 是：

```text
目标 = "好"
```

如果模型给出分布：

```text
好: 0.85
冷: 0.10
热: 0.05
```

我们会觉得它做得不错。

如果模型给出：

```text
好: 0.08
冷: 0.55
热: 0.37
```

那它显然做得很差。

交叉熵做的事，就是把这种“对真实答案的信心”差异压成一个可优化的数字。

## 交叉熵不是在比较“最终选了谁”，而是在比较整个分布

这是一个很重要的理解点。

训练时，模型不只是被要求“最终 argmax 选对”。它被要求的是：

> 在整个分布层面，把真实 token 推到更高概率的位置。

这意味着一个模型即使最终没选对，只要它已经把真实答案的概率往上推了一些，训练也仍然能得到有方向的信息。

这正是分布式学习的好处。它提供的不是“对/错”二元反馈，而是更细腻的误差信号。

## 为什么语言模型的 loss 可以对所有位置同时算

对于一段长度为 `T` 的序列，模型通常会给每个位置都输出一份词表分布。

训练时，我们会对每个可监督位置都计算交叉熵，然后求平均或求和。

这意味着：

> 一次前向传播，不只是产生一个监督信号，而是产生整段序列上很多位置的监督信号。

这也是为什么语言模型训练效率可以比“每次只监督一个位置”高很多。

## logits、softmax、cross-entropy 之间的关系

你现在应该把这三者看成一条连续链，而不是三个分散术语。

### logits

模型给出的未归一化分数。

### softmax

把分数变成概率分布。

### cross-entropy

根据真实目标，评价这个分布好不好。

连起来就是：

> 模型先对词表候选打分，再把打分转成分布，然后依据真实 token 判断分布是否合理。

这条链以后会在语言模型的每个训练 step 中不断重复。

## 为什么这和下一个 token 预测正好对上

语言模型训练的目标是：

> 给定前文，预测下一个 token。

而“预测一个 token”最自然的方式，本来就是：

- 把词表中的所有 token 视作候选类别
- 给这些类别一个分布
- 用真实目标类别监督它

所以从机器学习角度看，语言模型并不神秘。它只是把分类问题扩展到了：

- 很大的词表空间
- 序列中的很多位置
- 带上下文条件的场景

## 这一章真正要记住的核心句子

如果这一章只保留一句话，它应该是：

> 语言模型训练时，模型先为词表输出 logits，softmax 把 logits 变成概率分布，交叉熵再根据真实目标 token 判断这份分布是否足够好；这就是“预测下一个 token”在数学上的基本落点。
