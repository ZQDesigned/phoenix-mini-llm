# 05. 梯度、反向传播与优化

## 为什么 loss 还不够

前一章我们已经知道：

- 模型输出 logits
- softmax 把 logits 变成分布
- 交叉熵告诉我们当前预测有多差

于是一个自然问题就出现了：

> 既然已经知道错得多不多，为什么模型不能自己变好？

答案是：

> loss 只告诉你“现在差多少”，还没有告诉你“参数应该往哪个方向改”。

而训练真正需要的，恰恰是方向。

## 梯度最朴素的理解：误差对参数的敏感度

梯度可以先非常直白地理解成：

> 如果我把某个参数改动一点点，loss 会朝哪个方向变化，变化有多明显？

也就是说，梯度回答的是：

- 往上调会更好还是更坏
- 往下调会更好还是更坏
- 改这一点的影响大不大

如果你把 loss 想成山地高度，那么梯度就是当前位置最陡的上升方向。

而我们想做的是下降，所以训练通常会往梯度的反方向走。

## 为什么导数会成为学习的工具

在一元函数里，你也许已经见过导数表示斜率。

在神经网络里，参数很多很多，于是我们不再只问：

> 这个函数在一点上的斜率是多少？

而是问：

> loss 对每个参数的变化率分别是多少？

这些变化率拼在一起，就是梯度。

所以导数在神经网络中的角色，不是抽象数学练习，而是：

> 告诉优化器怎样调参数最有希望降低误差。

## 反向传播在做什么

如果模型只有一个参数，那求梯度并不难。

但神经网络里通常有很多层、很多中间变量、很多参数。如果你每次都手工对每个参数重新推一遍梯度，几乎不可能高效训练。

反向传播解决的正是这个问题。

它的最重要直觉是：

> 利用链式法则，把最终 loss 对各层中间结果的影响一层层往回传，从而高效求出所有参数的梯度。

你不必把“反向传播”想成一种神秘算法。它其实就是：

1. 先做前向计算，记录中间依赖关系  
2. 从 loss 开始，按依赖反向传递梯度  
3. 得到每个参数的梯度  

现代框架中的 autograd，核心就是在自动做这件事。

## 链式法则为什么是核心

神经网络是由很多函数复合而成的。

例如：

\[
x \rightarrow h_1 \rightarrow h_2 \rightarrow logits \rightarrow loss
\]

某个早期参数并不直接连到 loss，但它会通过很多中间步骤间接影响最终结果。

链式法则告诉我们：

> 要看最早那个参数怎样影响最终 loss，可以把每一段局部变化率按依赖路径乘起来。

这就是为什么反向传播可以逐层进行。因为整张计算图里的全局梯度，能被拆成很多局部梯度的组合。

## 为什么“前向”和“反向”必须被区分

很多初学者第一次训练模型时，会把整个过程看成“一口气跑一下网络”。但真正理解训练，必须把两件事分开：

### 前向

输入经过各层，得到 logits 和 loss。

### 反向

从 loss 往回传播，得到各参数梯度。

这两个阶段承担完全不同的职责：

- 前向负责算“现在表现怎样”
- 反向负责算“参数该怎么改”

如果把这两者混成一团，你后面会很难理解：

- 为什么推理时只要前向，不要反向
- 为什么有些 bug 出在前向逻辑，有些出在梯度路径
- 为什么 `no_grad` 和 `eval` 这种概念存在

## 优化器在做什么

当梯度算出来之后，还差最后一步：

> 具体怎样根据梯度修改参数？

这就是优化器的职责。

最简单的想法可以写成：

\[
\theta \leftarrow \theta - \eta \nabla_\theta L
\]

这里：

- `\theta` 是参数
- `\eta` 是学习率
- `\nabla_\theta L` 是梯度

这就是梯度下降的基本形态。

优化器的本质就是：

> 根据当前梯度，决定参数实际更新的步子怎么走。

## 学习率为什么如此重要

学习率控制的是每一步更新的幅度。

### 学习率太大

可能会导致：

- loss 上下乱跳
- 训练不稳定
- 直接数值爆炸

### 学习率太小

可能会导致：

- loss 下降非常慢
- 看起来训练在跑，其实几乎没学到什么

所以学习率不是一串随手填的超参数，而是整个优化过程的节奏控制杆。

你后面做语言模型训练时，如果模型“不学习”，学习率永远都应该是最早排查的对象之一。

## 梯度为什么会消失或爆炸

既然反向传播依赖链式法则，一旦链很长、层很多，就可能出现两类问题：

### 梯度消失

往回传时，梯度越传越小，前面层几乎拿不到有效学习信号。

### 梯度爆炸

往回传时，梯度越传越大，参数更新突然失控。

这也是为什么深层网络需要很多稳定训练的设计，例如：

- 合理初始化
- 残差连接
- 归一化
- 梯度裁剪

它们并不是“附加美化”，而是在帮模型维持可训练性。

## 为什么现代框架会自动求导

你现在不需要自己手推每一层的梯度代码，原因就在于现代框架会：

- 跟踪前向中的张量运算
- 构建计算图
- 根据计算图自动反向求导

这让你能把精力更多放在：

- 任务定义
- 模型结构
- 数据流
- 调试逻辑

而不是把大量时间花在手工实现梯度公式上。

但要注意：

> autograd 会自动算梯度，不代表你可以不理解梯度在做什么。

因为一旦训练不收敛、loss 异常或梯度为零，你仍然需要靠概念判断问题在哪。

## 优化不是“神奇地越来越好”，而是带噪声地逼近更好

还有一个重要现实感必须建立：

> 训练过程通常不是一条平滑直线，而是带噪声、局部波动、逐步逼近更好解的过程。

尤其在 mini-batch 训练中，每一步看到的数据只是整体分布的一小部分，因此梯度本身就是带噪声的估计。

这也是为什么训练曲线常常会：

- 下降中有波动
- 短期上下抖动
- 长期趋势才逐渐显现

理解这一点，能帮你避免把正常训练波动误判成实现 bug。

## 这一章真正要记住的核心句子

如果这一章只记住一句话，它应该是：

> loss 告诉模型“现在错了多少”，梯度告诉模型“该往哪个方向改”，反向传播负责高效算出这些梯度，优化器再根据梯度和学习率真正更新参数；这四者合在一起，才构成了“模型在学习”的机制。
