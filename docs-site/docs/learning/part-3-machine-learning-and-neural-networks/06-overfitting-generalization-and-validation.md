# 06. 过拟合、泛化与验证集

## 为什么“loss 在降”还不够让人放心

很多初学者第一次训练模型时，会自然地盯着一个数字看：

> loss 有没有下降？

这是必要的，但远远不够。

因为一个模型即使训练集 loss 持续下降，也可能同时发生另一件事：

> 它越来越会记住训练样本，但并没有真正学到可迁移的规律。

这就是过拟合问题。

## 什么叫泛化

泛化可以先理解成：

> 模型不仅在见过的数据上表现好，在没见过但分布相近的新数据上也能表现好。

如果一个语言模型只会在训练集片段上表现好，而换一批相似但未参与训练的数据就明显变差，那么它学到的更多是记忆，而不是可靠规律。

学习真正有价值的地方，恰恰在泛化。

## 什么叫过拟合

过拟合最朴素的定义是：

> 模型把训练数据中的偶然性、噪声或局部细节也学得太死，导致它对新样本表现变差。

它通常表现成：

- 训练损失继续下降
- 验证损失不再下降，甚至开始上升

这说明模型越来越擅长“迎合训练集”，却没有继续提升对新数据的预测能力。

## 什么叫欠拟合

与过拟合相对的，是欠拟合。

欠拟合意味着：

> 模型连训练集本身都没有学好。

它可能来自：

- 模型太弱
- 训练时间太短
- 学习率或优化过程不合适
- 数据表示方式有问题

一个欠拟合模型通常表现为：

- 训练损失很高
- 验证损失也很高
- 两边都没有形成理想下降

## 为什么需要训练集和验证集

如果你只有一份数据，并且一直用它来更新参数，那么你很难知道模型到底是在：

- 学习一般规律
- 还是越来越会记住这份数据

于是我们通常把数据分成至少两部分：

### 训练集

用于真正更新参数。

### 验证集

不参与参数更新，只用于观察模型对未参与训练数据的表现。

验证集的存在，相当于给训练过程加了一面镜子。它帮助你判断：

> 模型现在的进步，是真进步，还是只对训练集有效。

## 训练损失和验证损失应该怎样一起看

这是最基础也最重要的阅读训练曲线的方法。

### 情况 1：训练损失下降，验证损失也下降

这是理想情况，通常说明模型既在训练集上学到东西，也在验证集上改善。

### 情况 2：训练损失下降，验证损失停滞或上升

通常意味着模型开始过拟合。

### 情况 3：两者都不怎么降

通常优先怀疑：

- 训练没真正跑对
- 学习率不合适
- 数据或目标构造有问题
- 模型容量不足

如果你学会了这三种基本阅读方式，已经能避免很多初学者最常见的误判。

## 为什么语言模型也离不开验证集

有些人会误以为语言模型数据量很大，所以：

> 好像只要一直训练下去就行。

实际上语言模型同样需要验证集，而且原因非常充分：

- 你仍然要判断模型是否在学泛化规律
- 你仍然要比较不同超参数配置
- 你仍然要决定哪个 checkpoint 更值得保留

尤其在小型学习项目里，验证集的重要性甚至更高，因为你的数据通常没有工业级大，也更容易过拟合。

## loss 不是唯一指标，但仍然是核心指标

训练语言模型时，你最终当然还会看：

- 生成样例
- 重复程度
- 是否容易跑偏

但这并不意味着 loss 不重要。

更准确的说法是：

> loss 是最直接的训练信号，样例是行为层观察，两者必须一起看。

如果只看样例，你可能会被一次偶然好输出误导。

如果只看 loss，你又可能忽略模型在真实文本行为上的问题。

## 正则化为什么会出现

既然过拟合存在，那么训练中自然会出现一类问题：

> 有没有办法让模型别把训练集记得太死？

这就引出了正则化思路。

你现在不必提前掌握所有技术细节，但应该知道常见方向包括：

- dropout
- weight decay
- 更好的数据覆盖
- 适当控制模型容量
- 提前停止

它们共同试图缓解的，是“训练集越来越好，泛化却没有同步变好”的问题。

## 过拟合并不总是坏消息

这句话听起来有点反直觉，但对学习项目非常重要。

如果你故意拿极少量数据训练，并且模型很快把它记住，这反而可能是好消息。

为什么？

因为这说明：

- 数据进入模型的路径通了
- 目标构造大概率没错
- 参数真的在更新

所以在调试阶段，“刻意过拟合一个极小数据集”常常是健康检查，而在正式训练阶段，“越来越严重的过拟合”才是需要抑制的问题。

你必须区分这两种场景。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> 真正有价值的学习不是把训练集记住，而是在未参与训练的数据上也保持合理表现；因此训练损失、验证损失和样例观察必须一起使用，验证集存在的意义就是帮助你区分“学会了规律”和“记住了样本”。
