# 02. 标量、向量、矩阵、张量与 shape

很多初学者第一次认真看深度学习代码时，会立刻被一连串看上去很技术、却又很抽象的东西包围：

- `input_ids.shape == [B, T]`
- `hidden_states.shape == [B, T, H]`
- `logits.shape == [B, T, V]`
- `x = x.view(...)`
- `x = x.transpose(...)`
- `x @ w`

如果你对这些对象只有一种模糊感觉：

> 它们大概都是一堆数字，只是维度不一样。

那么后面几乎每一章都会显得难。

你会不断遇到下面这些困惑：

- 这个张量里到底装的是什么
- 为什么这里只是多了一维，语义就完全变了
- 为什么 shape 明明对得上，结果模型还是学错了
- 为什么注意力、线性层、softmax、loss 全都和张量结构绑得这么紧

所以这一章的任务不是教你背几个术语，而是让你建立一种更稳的对象感：

> 神经网络内部的一切，最终都会落成某种有结构的数值对象；理解这些对象怎样被组织，就是理解模型内部语言的第一步。

这也是为什么这章必须放得很靠前。

因为如果对象层没站稳，后面无论你再学：

- 注意力
- Transformer block
- 混合精度
- KV cache
- 训练损失

都会像是在看一台机器的中后段，却没有真正理解它最基础的材料是什么。

## 1. 先抓住整章最核心的一句话

在进入细节之前，请先记住这句话：

> 标量、向量、矩阵、张量，不是四种互不相干的神秘材料，而是同一种基本材料在不同结构层级上的组织形式。

更具体地说：

- 标量是单个数
- 向量是按顺序排成一条的一组数
- 矩阵是按行列组织起来的一组向量
- 张量是更一般的多维组织形式

它们的差别首先不在于“高级程度”，而在于：

> 数字被放在了什么结构里，而这个结构又承载了什么语义。

这句话里最重要的四个字是：

> 结构承载语义

因为往后你会越来越强烈地感受到：

- 同样一批数字，换个 shape，语义可能完全改变
- 同样是三维张量，不同轴角色会对应完全不同的对象
- 很多 bug 首先是结构 bug，然后才表现成数值 bug

所以整章真正要建立的，不是术语记忆，而是“结构眼睛”。

## 2. 为什么机器学习里的对象最后都要写成数

人类理解世界靠的是很多种形式：

- 语言
- 图像
- 声音
- 动作经验
- 空间直觉

但模型做计算时，不会直接处理“意义本身”。
它真正操作的是：

- 数字
- 数字之间的排列
- 数字之间的运算

于是所有原始对象都必须先被写成某种数值形式：

- 温度变成实数
- 图片变成像素网格
- 文本变成 token 序列
- 类别变成类别编号或目标分布

这一步经常会让初学者不舒服。

因为你会本能地觉得：

> 世界明明这么丰富，为什么最后都要变成数字？

答案不是简单的“因为计算机只会算数”。

更准确地说：

> 只有当对象被翻译成结构化数值以后，模型才能用统一的线性运算、非线性变换和梯度更新去加工它们。

也就是说，数值化不是附属步骤，而是整个学习系统成立的前提。

而一旦进入数值化世界，你最先面对的就一定是：

- 一个对象由几个数表示
- 这些数怎样排布
- 哪一维代表样本，哪一维代表时间，哪一维代表特征

这些问题的答案，就是标量、向量、矩阵、张量与 shape。

## 3. 标量：最小的数值单位

最简单的数值对象是标量。

标量就是一个单独的数。

例如：

```text
3
-1.2
0.0005
```

它没有多个位置，也没有额外结构。你看到的就是一个值。

### 3.1 为什么标量并不“低级”

很多人会把标量想成“最简单，所以最不重要”的对象。

实际上它的重要性恰好在于：

> 后面所有更复杂的对象，本质上都还是很多标量按某种结构组织起来的结果。

也就是说：

- 向量不是另一种材料，它只是很多标量排成了一条线
- 矩阵不是另一种材料，它只是很多标量按行列摆好
- 张量也不是另一种材料，它只是更一般的多维组织

所以以后你面对复杂张量时，不妨先退回到这一层：

> 这仍然只是一堆标量，只是这些标量现在被赋予了更高层的结构关系。

### 3.2 在模型里，哪些对象会表现成标量

很多关键量在某一时刻都会表现成标量：

- 一个 loss 值
- 一个学习率
- 某个参数元素
- 某个梯度元素
- 某个位置上某个 token 的一个 logits 值

例如训练时你常看到：

```python
loss.item()
```

这通常就是把一个只有单个值的张量读成普通数值。

### 3.3 标量不只是“一个数”，它还有上下文意义

这一点非常重要。

同样是 `0.5`，它可能表示：

- 概率 `0.5`
- 学习率的一半
- 某层权重中的一个元素
- 某次训练的 loss
- 某个向量坐标

数字本身完全一样，但语义完全不同。

这说明一个基本事实：

> 数值从来不是脱离上下文独立存在的。

后面你看向量、矩阵、张量时也必须保持同样警惕：

- 形状告诉你结构
- 上下文告诉你语义

## 4. 向量：有顺序的一组数

接下来是向量。

一个最朴素的向量可以写成：

```text
[2.3, -0.7, 5.1]
```

它比标量多出来的关键特征是：

> 它不是单个值，而是按顺序排列的一组值。

这个“按顺序”特别重要。

因为如果你把里面的值重新打乱，很多时候它就不再表示同一个对象了。

### 4.1 为什么向量不是“随便一串数字”

向量最容易被误解成：

> 只是几个数字放在一起。

但向量真正关键的地方在于：

> 不同位置的数字共同描述同一个对象，而每个位置在结构上都有角色。

例如在二维平面里，一个点可以写成：

\[
[x, y]
\]

这里：

- 第一个位置代表横向坐标
- 第二个位置代表纵向坐标

你不能随便把它们交换。

这说明了一件很根本的事：

> 向量不是“值的集合”，而是“带位置角色的有序结构”。

### 4.2 向量可以表示什么

向量的用途非常广。

它可以表示：

- 一个二维或三维坐标
- 一条样本的特征
- 一个词的 embedding
- 一层隐藏状态中的某个位置表示
- 一组 logits

这正是为什么“表示”这个词很重要。

在深度学习里，向量经常不是在记录日常可读字段，而是在记录：

> 模型内部当前如何描述某个对象。

例如，一个 token 的 embedding 向量不等于这个 token 的文字定义。

它更像是：

> 模型用一组数，在内部空间里给这个 token 分配的位置和属性。

### 4.3 向量为什么既像点，又像箭头

从几何上看，向量可以有两种非常有用的读法：

- 它可以被看成空间中的一个点
- 它也可以被看成从原点出发的一支箭头

这两种读法都很重要。

把向量看成点，你更容易理解：

- 表示空间
- 聚类
- 相似点靠近

把向量看成箭头，你更容易理解：

- 方向
- 长度
- 点积
- 投影

后面 attention、相似度、线性投影这些内容，都会大量依赖这种几何直觉。

## 5. 矩阵：很多向量的组织方式，也是变换规则的写法

如果向量是一条有顺序的数列，那么矩阵就是：

> 按行和列组织起来的一组数。

最直观的写法像这样：

\[
\begin{bmatrix}
1 & 2 & 3 \\
4 & 5 & 6
\end{bmatrix}
\]

它比向量多了一层结构：

- 不只是单条排列
- 还要区分行和列

### 5.1 矩阵的第一种直觉：很多向量堆起来

你可以把矩阵先看成：

- 很多行向量堆在一起

或者：

- 很多列向量堆在一起

这两种看法都成立，只是强调的角度不同。

这非常有帮助，因为它让矩阵不再显得神秘。
它仍然只是：

> 向量的进一步组织。

### 5.2 矩阵的第二种直觉：线性变换的参数表

在深度学习里，矩阵更重要的身份通常不是“表格”，而是：

> 线性变换的参数写法。

例如：

\[
y = Wx
\]

这里的 \(W\) 就不是普通数据表，而是在定义：

> 输入向量 \(x\) 怎样被重新读取、重新组合，并写成新的输出向量 \(y\)。

这就是为什么你在网络里到处都看到矩阵。

因为大量层本质上都在做：

- 读取输入表示
- 按新的方向重新混合
- 写到新的表示空间

### 5.3 为什么同一个矩阵，语义可以完全不同

很多初学者看到矩阵时会默认觉得：

> 它既然是个二维表，那语义应该比较固定。

其实完全不是。

同样是矩阵，它可能表示：

- 一批样本按行排在一起
- 一个 embedding 表
- 一层线性权重
- Q/K/V 投影矩阵
- 注意力分数图

所以矩阵的“二维性”本身并不决定语义。
真正决定语义的是：

- 每一维在数什么
- 它处在模型链路的哪个位置
- 这个对象是数据、参数，还是中间计算结果

## 6. 张量：更一般的多维数值对象

到了张量，很多初学者会觉得突然进入了一个“高级区”。

其实最实用的理解非常朴素：

> 张量就是更一般的多维数值对象。

也就是说：

- 标量可以看成 0 维张量
- 向量可以看成 1 维张量
- 矩阵可以看成 2 维张量
- 更高维对象就是更一般的张量

在工程语境里，张量往往只是：

> 一个可能有很多轴的数值容器。

### 6.1 为什么深度学习里总爱说“张量”

因为深度学习里你非常少只处理：

- 单个数
- 单个向量
- 单张二维表

更常见的情况是：

- 一批样本
- 每条样本里又有时间位置
- 每个位置上又有隐藏特征
- 还可能再分多头、多通道或多类别空间

于是对象天然就会长成三维、四维、五维甚至更高维的结构。

这时再分别叫“数组”“表格”“矩阵”已经不够了。

所以“张量”更像一个总称：

> 任何带多维结构的数值对象，我都先可以把它叫成张量。

### 6.2 工程里的“张量”和数学里的“张量”不完全一样

这一点值得顺手提醒一下。

在严格数学里，“张量”有更精细的定义，和多重线性代数有关。

但在深度学习工程里，大家大量使用“tensor”这个词时，通常更接近在说：

> 带 shape 的多维数值数组。

你现在不必被这个术语分歧吓到。

对当前学习阶段来说，更重要的是工程语义：

> 张量最难的地方不在“维度多”，而在“每一维都有角色”。

## 7. 什么是 shape，为什么它比元素总数更重要

现在进入这章真正的核心对象之一：shape。

shape 描述的是：

> 这个张量在每个轴上分别有多长。

例如：

- `[3]` 表示长度为 3 的一维向量
- `[2, 3]` 表示 2 行 3 列的矩阵
- `[B, T, H]` 表示一个三维张量

很多初学者一开始会把 shape 理解成：

> 只是打印出来方便看一眼的尺寸信息。

这远远低估了它的重要性。

更成熟的理解是：

> shape 不是显示信息，而是对象逻辑结构的压缩摘要。

### 7.1 为什么 shape 比元素总数更重要

设想下面两个对象：

- shape = `[2, 6]`
- shape = `[3, 4]`

它们元素总数都是 12。

但它们的结构完全不同。

一个更像：

- 两个对象，每个对象 6 个值

另一个更像：

- 三个对象，每个对象 4 个值

这说明“元素总数相同”并不代表结构相同。

而在机器学习里，结构变化通常就意味着：

- 语义变化
- 运算合法性变化
- 后续层能不能正确读取它的方式也变化

### 7.2 shape 不只是“多大”，更是“怎么组织”

所以你以后读 shape 时，不要只读成：

> 这个张量一共有几维、每维几个数。

更好的读法是：

> 这些维度分别在数什么，它们一起把对象组织成了什么样。

只要这层理解站稳，后面你看任何张量都更容易进入对象语义，而不是只看尺寸。

## 8. 轴、维度与“这一维到底在数什么”

shape 里每一个数字都对应一个轴。

例如 shape `[B, T, H]` 就表示：

- 第一个轴长度是 `B`
- 第二个轴长度是 `T`
- 第三个轴长度是 `H`

但真正重要的问题不是长度本身，而是：

> 每个轴到底在数什么？

例如：

- `B` 可能在数 batch 里的样本个数
- `T` 可能在数序列位置
- `H` 可能在数每个位置的隐藏特征维度

这就是为什么我前面一直强调：

> 张量真正难的地方不在“多维”，而在“每一维都有角色”。

### 8.1 为什么轴语义必须由你主动读出来

代码不会总是替你把语义写全。

很多时候你只看到：

```python
x.shape == [32, 128, 512]
```

如果你只知道这是个三维张量，而不知道：

- 32 是 batch
- 128 是 sequence length
- 512 是 hidden size

那么你其实还没有真正读懂这个对象。

以后你看任何 shape，都应该逼自己主动问一句：

> 这一维到底在数什么？

这是一个非常小的习惯，但它能帮你挡掉大量结构性错误。

## 9. 在语言模型里，最常见的几类轴

现在把对象感拉回语言模型主线。

大语言模型里最常见的几类轴，基本就是下面这些。

### 9.1 `B`：batch size

表示一次并行处理多少条样本。

如果 `B = 32`，通常意味着这一批里有 32 条训练样本。

### 9.2 `T`：sequence length

表示序列长度，也就是一条样本里有多少个位置。

在语言模型里，它通常对应：

- token 位置数
- 上下文窗口长度

### 9.3 `H`：hidden size

表示每个位置上的隐藏表示维度。

也就是：

> 模型内部用多少个数来描述当前位置。

### 9.4 `V`：vocab size

表示词表大小。

当输出 shape 里最后一维是 `V` 时，通常意味着：

> 当前位置上，模型为整个词表里的每个候选 token 都给出了一项分数或概率。

### 9.5 `heads`：注意力头数

多头注意力会额外引入一个头轴。

它表示：

> 模型把信息读取拆成多少套并行子视角。

### 9.6 `d_head`

表示单个注意力头内部的特征维度。

它常常满足：

\[
H = heads \times d_{head}
\]

理解这条关系非常重要，因为后面你会反复做：

- hidden 拆头
- 多头再合并回 hidden

## 10. 一个完整的小例子：从 token id 到 logits

为了让这些轴不要停留在抽象名词上，我们走一遍完整的小链路。

### 第一步：输入 token id

假设输入 shape 是：

\[
[B, T]
\]

例如：

- `B = 4`
- `T = 8`

这表示：

> 一批 4 条样本，每条样本长度 8 个 token 位置。

这里的元素通常不是连续实数，而是 token id。

### 第二步：查 embedding 表

经过 embedding 之后，shape 变成：

\[
[B, T, H]
\]

这意味着：

> 每个 token id 被替换成一个长度为 `H` 的向量表示。

现在每个位置不再只是一个离散编号，而是一整组隐藏特征。

### 第三步：进入若干层 Transformer block

中间很多层处理之后，shape 往往仍然是：

\[
[B, T, H]
\]

这里最容易产生一个误解：

> shape 没变，所以对象大概也没本质变化。

这不对。

shape 不变只说明结构类型没变：

- 仍然是一批样本
- 每条样本仍然有 `T` 个位置
- 每个位置仍然用 `H` 维表示

但这不代表表示内容没变。
恰恰相反，模型的主要工作之一，就是在保持整体结构类型相似的同时，不断重写内部表示。

### 第四步：投影到词表空间

最后，输出常常变成：

\[
[B, T, V]
\]

这表示：

> 对 batch 中每个样本的每个位置，模型都给出了对整个词表中每个 token 的一项分数。

这一步非常关键，因为它说明：

> 最后一维换了，语义就完全换了。

原来最后一维 `H` 代表隐藏表示空间；
现在最后一维 `V` 代表词表候选空间。

所以 shape 的变化从来都不是纯尺寸变化，它常常意味着：

> 对象角色被重写了。

## 11. 为什么“同样一批数字”换个 shape，语义可能彻底变掉

这是整章必须压实的一条判断。

很多初学者会本能地觉得：

> 只要元素没变，换个形状大概只是外观变化。

现实没这么简单。

如果你把：

\[
[B, T, H]
\]

误写成别的结构，哪怕元素总数一样，语义也可能完全错位。

例如：

- 原来你以为最后一维在数隐藏特征
- 结果现在最后一维其实在数时间位置

这会导致：

- 后面的矩阵乘法在错误语义上进行
- softmax 沿错误的轴归一化
- loss 对错对象做比较

也就是说，结构一旦错位，后面即使数值还能算下去，也已经不是同一个任务了。

所以以后看到 reshape 或 permute 时，你一定要本能地追问：

> 这里只是改外观，还是把语义轴也换掉了？

## 12. `reshape`、`view`、`transpose`、`permute` 到底在干什么

这几个操作是张量阅读里最常见也最容易出事故的地方。

### 12.1 `reshape` / `view`

它们更接近：

> 在不改变元素总数的前提下，重新组织张量外观。

例如，把 `[B, T, H]` 改成 `[B*T, H]`，常见于：

- 把所有位置摊平
- 方便统一做某种逐位置运算

但这里有个前提：

> 你必须清楚自己在“摊平”的到底是哪几层结构。

### 12.2 `transpose` / `permute`

它们更接近：

> 交换轴顺序。

例如，把：

\[
[B, T, heads, d_{head}]
\]

变成：

\[
[B, heads, T, d_{head}]
\]

这类操作在 attention 里极其常见，因为很多矩阵乘法要求特定轴顺序。

### 12.3 为什么这些操作既常见又危险

因为它们都可能让代码“数值上还能跑”，但对象语义已经错了。

所以它们的危险不在于 API 难记，而在于：

> 你很容易只看到形状变化，却没追踪语义变化。

## 13. 为什么“每一维代表什么”比“API 怎么写”更重要

很多初学者第一次学张量操作时，会把重点放在：

- `view` 怎么用
- `permute` 参数顺序怎么写
- `transpose` 和 `reshape` 有什么语法区别

这些当然要会，但真正决定你会不会读懂模型的，不是 API 记忆，而是：

> 你能不能把每一维翻译成人话。

例如看到：

\[
[B, heads, T, T]
\]

你要能立刻说出：

> 一批样本；每个样本里有多头；每个头上都为每个 query 位置保留了一整列对所有 key 位置的关系分数。

只有这样，你才不是“看到四维张量”，而是真正读懂了它。

## 14. 批处理为什么会天然增加一个轴

很多对象本来只是一条样本的结构。

例如单条序列的 token id 可以是：

\[
[T]
\]

但训练时你通常不会一次只喂一条样本，而会并行喂一批。

于是自然而然会多出一个 batch 轴：

\[
[B, T]
\]

这说明一个很有用的规律：

> 很多时候，增加一个轴，不是因为对象本体变复杂了，而是因为我们在并行处理更多同类对象。

这个规律后面会反复出现：

- 单个向量变成一批向量
- 单条序列变成一批序列
- 单个注意力头变成多头并行

理解这一点能让你更从容地看待“维度变多”。

## 15. 为什么序列问题又会再多一个位置轴

如果是普通表格任务，一条样本常常可以直接写成一个特征向量：

\[
[H]
\]

但语言模型处理的是序列。

只要对象变成序列，就必须显式保留“位置”这一层结构。

于是你几乎一定会看到：

\[
[T, H]
\]

或者带 batch 的版本：

\[
[B, T, H]
\]

这说明序列任务和普通表格任务之间最根本的结构区别之一就是：

> 序列任务天然会多出一个位置轴，而这个轴绝不能和特征轴混掉。

## 16. 位置轴和特征轴为什么绝对不能混

这是语言模型最核心的结构纪律之一。

位置轴回答的是：

> 序列里现在是第几个位置。

特征轴回答的是：

> 模型用多少个数来描述这个位置。

这两个问题看起来都对应一串数字，但语义完全不同。

如果把它们混掉，就等于把：

- “哪一个位置”

和

- “怎样描述这个位置”

混成了一件事。

这会直接破坏：

- 注意力的读写逻辑
- 位置编码或位置方法的意义
- 输出投影和 loss 的对齐关系

所以以后你只要看到 shape，就应该自动先区分：

- 哪些轴是在数对象个数
- 哪些轴是在数特征维度

## 17. 为什么 embedding 表既像矩阵，又不是普通样本表

embedding 表常常 shape 是：

\[
[V, H]
\]

这看起来像普通矩阵，但它的语义和“样本表”完全不同。

这里：

- `V` 是词表大小
- `H` 是每个 token 的表示维度

所以它更像是：

> 一张从离散 token id 到连续向量表示的查询表。

每一行不是“一条训练样本”，而是：

> 一个词表项当前在表示空间中的可学习位置。

这就是为什么我前面一直强调：

> 同样是矩阵，语义可能完全不同。

## 18. 注意力里的四维张量为什么其实并不可怕

很多人第一次看到注意力分数张量：

\[
[B, heads, T, T]
\]

会本能地觉得：

> 四维，已经完全画不出来了，肯定很可怕。

其实你只要坚持“逐轴翻译”，它并不可怕。

这个 shape 可以读成：

- 一批样本
- 每个样本有多个头
- 每个头里有一条 query 位置轴
- 每个 query 位置都会对应一整条 key 位置轴

也就是说，这个对象本质上并没有超出你前面学过的世界。

它只是把：

- batch
- 多头
- 位置到位置关系

同时组织进了一个更高维结构里。

所以高维张量最怕的不是“维数多”，而是你放弃逐轴翻译。

只要不放弃，它就仍然是可读对象。

## 19. 广播为什么会让 shape 判断更微妙

广播是张量计算里非常方便的一种机制。

它允许某些较小 shape 的对象，在满足规则时自动扩展，与较大对象一起运算。

例如：

- 一个 bias 向量 `[H]`
- 可以被加到 `[B, T, H]` 上

因为它会沿着前面的轴自动扩展。

### 19.1 为什么广播方便

因为你不必真的手工把 bias 复制成整个三维张量。
框架会替你在逻辑上完成扩展。

### 19.2 为什么广播也危险

因为有时它会让代码“能跑”，但你没意识到：

- 它到底沿着哪一维在复制
- 这种复制是不是符合你的任务语义

所以广播的危险在于：

> 它可能帮你掩盖结构理解不清的问题。

## 20. shape 是调试语言模型时的第一道防线

很多人以为调试模型主要是看：

- loss 曲线
- 梯度范数
- 生成样例

这些当然重要。

但在更靠前的一层，shape 往往才是第一道防线。

因为很多错误一开始根本不是“模型不够聪明”，而是：

- batch 轴和位置轴弄混了
- 输出维度和目标维度错位了
- heads 拆分后没按预期重排
- softmax 沿错轴做了
- `view` 把语义结构摊坏了

这类错误常常先表现成：

- 模型能跑
- 数字也能算
- 但学出来的东西很怪

所以对大模型工程来说，一个非常有用的习惯是：

> 一旦结果不对，先怀疑结构，再怀疑数值，再怀疑更高层逻辑。

## 21. 读一个 shape 时，应该怎样把它翻译成人话

这是本章最实用的技能之一。

以后你看到任何 shape，都可以强迫自己做下面四步。

### 第一步：先数有几维

不要急着看数值含义，先确认对象层级有多深。

### 第二步：给每一维命名

例如：

\[
[32, 128, 512]
\]

不要只看成“三个数字”，而要翻译成：

- `B = 32`
- `T = 128`
- `H = 512`

### 第三步：把它说成人话

例如：

> 一批 32 条样本；每条样本长度 128；每个位置用 512 维隐藏向量表示。

### 第四步：问它在任务链路里扮演什么角色

它是：

- 输入？
- 中间表示？
- 参数表？
- 分数图？
- 输出分布接口？

只有完成第四步，你才算真正读懂一个张量对象。

## 22. 初学者在这一章最常见的误区

最后把几种最常见的误区拆掉。

### 误区一：维度越多，模型越高级

不是。

维度多通常只是说明：

- 你同时保留了更多结构轴
- 或者在并行处理更多同类对象

它不自动等于“更高级”。

### 误区二：shape 对得上就一定没问题

不是。

shape 对得上只说明尺寸兼容。
它不保证语义兼容。

### 误区三：只要会用 API，张量操作就不难

不是。

真正的难点不在 API，而在你是否追踪了轴语义。

### 误区四：张量就是“数组换个高级名字”

不完全对。

在工程上它确实是多维数组，但学习难点恰恰在于：

> 这些多维结构不是中性的，它们带着明确任务语义。

### 误区五：语义都写在数字里

不是。

数字只给出长度，真正的语义必须由你结合任务和上下文读出来。

## 23. 如果这一章最后只保留一句话

如果这一章最后只保留一句话，我希望是这一句：

> 标量、向量、矩阵、张量和 shape 的核心，不是让你记住几种对象名字，而是让你建立一种稳定判断：模型内部始终在处理带结构的数值对象，而真正决定对象意义的，不只是数字本身，更是数字怎样被分轴组织、每一轴到底在数什么。

2. 为什么 shape 比元素总数更重要？
