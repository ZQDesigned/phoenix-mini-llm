# 04. 长度、点积、相似度与几何直觉

这一章的任务，不是把几个线性代数术语补完，而是建立一层后面会被反复调用的几何直觉。

很多初学者第一次接触 attention 时，会把它看成一种很突然的“上下文读取技巧”。
表面上看，它确实伴随着一批陌生词：

- query
- key
- value
- score
- mask
- softmax

但只要把这些名字暂时拿掉，你会发现 attention 的核心动作非常朴素：

> 给定当前这一步的表示，我怎样判断上下文里哪些表示和它更对得上、哪些不那么对得上？

这里的“对得上”，在最底层并不是一句自然语言描述，而是一类几何比较。

你需要知道：

- 一个向量有多长
- 一个向量朝什么方向
- 两个向量是不是方向接近
- 一个向量在另一个方向上的分量有多大
- 当长度和方向同时进入比较时，结果会发生什么偏差

如果这一层没有站稳，后面你即使记住了点积、缩放点积注意力、cosine similarity 或归一化，也很容易停留在“会写公式，但解释不稳”的状态。

所以本章要做的是把下面这条线真正接起来：

1. 向量为什么不只是数字列表，还是空间中的几何对象。
2. 长度与方向分别在表达什么。
3. 点积为什么会同时混入长度与方向。
4. 相似度为什么常常更关心方向而不是绝对量级。
5. 投影为什么是理解读取、对齐与注意力的桥梁。
6. 高维空间虽然不可视，但几何语言仍然有效。

## 向量首先是对象，其次才是公式

在入门阶段，把向量看成一串有顺序的数字当然没有错。

```text
[2.1, -0.7, 5.4]
```

这确实就是一个向量。

但如果你长期只把它当成“一个数组”，后面很多机器学习概念都会显得莫名其妙。因为在模型里，同一个向量通常同时有四种身份。

第一，它是数值列表。你可以逐维读取它、送进矩阵乘法、和别的向量做算术。

第二，它是空间中的一个点。如果每一维都是一根坐标轴，那么这个向量也对应空间中的一个位置。

第三，它是从原点出发的一支箭头。只要你接受这个视角，长度、方向、角度、投影这些几何概念就都会自然出现。

第四，它是某个对象当前的内部表示。在模型里，一个向量可能代表一个 token、一个句子片段、一个样本，或者某层里的中间状态。也就是说，它不仅是数学对象，还是语义载体。

真正有用的理解不是四选一，而是这四种视角同时成立。后面的表示学习几乎总是在这些视角之间切换：代码层面它是张量切片，几何层面它是一个方向，语义层面它又在表示某个对象的当前状态。

## 为什么几何直觉不是装饰，而是表示学习的骨架

很多人会把几何想成“帮助理解的图像化说法”，仿佛真正严肃的内容只存在于公式里。这个想法对语言模型并不准确。

表示学习这件事，本来就在持续做几何意义上的工作：

- 把对象放进一个空间
- 让相似对象的表示更接近
- 让不相似对象的表示更可分
- 沿某些方向读取有用信息
- 压低无关方向上的响应

你甚至可以把许多神经网络操作重新描述成一句几何话：

> 在表示空间里重新布置点、方向和分量，使某些关系更容易被读取出来。

只要你开始这样看问题，很多概念都会突然从“术语”变回“动作”。
线性层是在改写坐标表示。
点积是在读两个方向的对齐程度。
归一化是在控制量级。
attention 是在一组候选表示里，按当前查询方向决定该重点读取谁。

## 长度：向量有多大，并不只是数字和更大

如果把向量看成一支从原点出发的箭头，那么最自然的问题之一就是：这支箭头有多长？

对二维向量

\[
x = (x_1, x_2)
\]

长度写作：

\[
\|x\| = \sqrt{x_1^2 + x_2^2}
\]

更一般地，对 \(n\) 维向量

\[
x = (x_1, x_2, \dots, x_n)
\]

长度写作：

\[
\|x\| = \sqrt{x_1^2 + x_2^2 + \dots + x_n^2}
\]

这是最常见的欧几里得范数，也就是我们日常最直觉的“几何长度”。

如果你暂时不想记公式，也可以先记住它的意义：长度是在回答“这个向量整体上有多强、多大、多远离原点”。

在模型里，长度常常不止有一种含义，它可能表示：

- 某个特征响应得很强
- 某层激活整体量级偏大
- 某个 token 表示在当前空间里离原点更远
- 某个方向上的成分特别突出

这也是为什么“长度”不能被简单理解成“数大一点”。长度是一种整体量级，而不是某一维局部偏大。

## 为什么长度本身会带来问题

一旦你开始比较两个向量，你很快就会发现一个麻烦：

> 如果只看数值乘积或总和，长度大的向量往往天然更容易显得“重要”。

假设两个向量方向几乎一样，但其中一个只是整体放大了十倍。那么从几何角度看，它们表达的方向关系其实没有变，只是量级不同。可如果你的比较方式没有把“量级”与“方向”分开，它们的相似度分数就会被长度严重放大。

这件事在后面的神经网络里非常重要。因为表示既可能携带“内容方向”，也可能携带“激活强度”。如果比较机制把二者混为一谈，你就很容易得到一种不稳定的读法：不是谁更匹配，而是谁数值更大。

这也是后面为什么会出现：

- 归一化
- cosine similarity
- 注意力缩放

这些看似技术性的设计。它们背后处理的，本质上都是“怎样让量级不要过度污染比较”。

## 方向：为什么语义相近经常更像“朝向接近”

如果长度是在回答“有多大”，那么方向就在回答“朝哪里”。

在表示学习里，方向通常比绝对大小更接近“语义关系”。

原因很简单。很多时候我们关心的不是一个对象激活得多强，而是它主要沿哪些特征方向展开。你可以把它想成：

- 长度更像“音量”
- 方向更像“旋律的走向”

两个句子、两个 token、两个隐藏状态，可能一个激活强、一个激活弱，但只要它们主要沿着相近的特征方向展开，它们在表示空间里就可能具有相似的角色。

这就是为什么在很多建模场景里，人们会特别关注方向接近，而不是简单关注数值总量接近。

## 点积：同时读取长度和方向

点积是后面最重要的基础操作之一。对两个向量 \(a\) 和 \(b\)，它的定义写作：

\[
a \cdot b = \sum_i a_i b_i
\]

从“数组视角”看，这件事只是把对应位置相乘再求和。

但从几何视角看，它有一个更有解释力的形式：

\[
a \cdot b = \|a\| \|b\| \cos \theta
\]

这里的 \(\theta\) 是两个向量之间的夹角。

这条式子非常关键，因为它说明点积不是单纯在读方向，也不是单纯在读长度，而是在同时读两者：

- 两个向量越长，点积越容易变大
- 两个向量方向越接近，\(\cos \theta\) 越接近 1，点积越大
- 两个向量互相垂直时，\(\cos \theta = 0\)，点积为 0
- 两个向量方向相反时，\(\cos \theta < 0\)，点积为负

所以点积最自然的语言不是“把数字乘一乘”，而是：

> 它在衡量两个向量的对齐程度，但这个对齐会同时受到方向与量级的影响。

这句话几乎会一路用到 attention。

## 把点积理解成“一个向量在读另一个向量”

还有一种很有用的理解方式是把点积看成“读取”。

假设 \(b\) 定义了一个你关心的方向，那么 \(a \cdot b\) 可以被看成：向量 \(a\) 在方向 \(b\) 上响应得有多强。

这就是为什么在线性层里，一行权重常常可以理解成“一个读取方向”；为什么在分类头里，某个类别对应的权重向量像是在问“输入当前有多像我关心的方向”；为什么在 attention 里，query 和 key 的点积会被用来决定“当前查询更该去读谁”。

一旦你接受“点积是一种读取动作”，很多公式就不再只是运算规则，而更像是在回答一个具体问题：

> 这个表示在我关心的方向上，到底有多大响应？

## 余弦相似度：只看方向，尽量剥离量级

如果点积同时混入了长度和方向，那么一个自然的问题就是：

> 如果我只想比较朝向，而不想让长度影响过大，该怎么办？

这就引出余弦相似度：

\[
\cos(a, b) = \frac{a \cdot b}{\|a\| \|b\|}
\]

它做的事情很直接：把点积除以两个向量的长度，于是剩下的主要就是方向关系。

如果两个向量方向几乎一致，余弦相似度接近 1。
如果它们接近垂直，结果接近 0。
如果方向相反，结果接近 -1。

这使它很适合回答一种特定问题：

> 不考虑谁激活更强，只看它们是不是朝着相近的特征方向展开。

在文本表示、检索、聚类、embedding 分析里，这种比较非常常见。因为很多时候我们在意的是“是不是一种相似模式”，而不是“谁绝对更大”。

## 为什么 attention 常用点积，而不是直接用余弦相似度

到这里你可能会自然地问：既然余弦相似度更纯粹地表示方向，为什么 Transformer 里的注意力打分常写成点积，而不是直接写成 cosine similarity？

这里有几层原因。

第一，点积计算非常自然，和矩阵乘法能够很好地结合。把一批 query 与一批 key 放在一起时，点积形式可以直接高效地批量计算。

第二，模型有时确实希望保留一部分量级信息。不是所有任务里“只看方向”都最好，有时激活强度本身也携带了有用信号。

第三，即便使用点积，后续也会通过缩放和 softmax 来控制数值行为，而不是完全裸奔地让大长度统治结果。

因此，实际系统里常见的不是“纯几何教科书最理想的比较”，而是“表达力、可训练性、效率之间的工程折中”。

## 投影：为什么它是理解读取与注意力的桥

如果你把点积看成读取，那么投影就是这个读取动作的几何展开。

所谓把向量 \(a\) 投影到方向 \(b\) 上，本质上是在问：

> \(a\) 中有多少成分，是沿着 \(b\) 这个方向展开的？

如果 \(b\) 是单位向量，那么 \(a \cdot b\) 就直接给出了这个方向上的标量分量。

如果 \(b\) 不是单位向量，就还要考虑它自己的长度。

这层直觉非常重要。因为后面许多“读取谁、保留什么、压低什么”的结构，都可以重新解释为：

- 先定义若干方向
- 再看输入在这些方向上分别有多强
- 最后按这些方向上的响应组织输出

线性层是这样。
分类头是这样。
attention 本质上也是这样，只是它不是拿固定权重方向去读输入，而是让当前 token 产生一个 query，再拿这个 query 去和上下文的 key 逐个比较，动态决定更该读取哪些 value。

## 高维空间为什么仍然可以谈几何

初学者常有一个误解：二维和三维里谈长度、角度、方向、投影还比较直观，到了几百维、几千维的隐藏空间，几何直觉大概就“失效”了。

这并不准确。

真正失去的只是肉眼可视化，不是几何关系本身。

高维空间里仍然有：

- 长度
- 方向
- 夹角
- 投影
- 距离
- 子空间

这些对象照样定义良好，甚至正因为维度高，它们才成为理解模型行为的重要语言。

你虽然无法把 1024 维向量画在纸上，但你仍然可以严肃地讨论：

- 两个 token 表示是否更接近
- 某一层是否把某类模式推到更可分的区域
- 某个方向是否承载了某种特征
- 注意力查询是否在寻找特定类型的上下文

高维不是几何的终点，而是几何真正开始承担解释任务的地方。

## 为什么后面的归一化、缩放和稳定训练都离不开这一章

到这里，你应该已经能看清一些后续设计为什么会自然出现。

如果点积会把长度和方向混在一起，而高维下向量长度与数值波动又可能很大，那么训练时就会出现几个连锁问题：

- 分数容易因为量级过大而失控
- softmax 输入过大时会变得很尖锐
- 梯度可能因此不稳定
- 不同 batch、不同层的激活尺度可能互相污染

这正是为什么后面会看到各种尺度控制机制：

- layer normalization
- RMSNorm
- attention score scaling
- 合理的参数初始化

它们并不是“后来又额外加上的工程技巧”，而是建立在同一事实之上：

> 一旦表示要通过长度、方向和点积进入训练系统，量级管理就会变成核心问题。

## 把本章放回语言模型的语境里

现在可以把整章压缩回一句更贴近语言模型的话：

当模型把一个 token 映射成高维向量后，后面的很多计算其实都在问：

- 这个表示整体激活有多强
- 它主要朝哪些方向展开
- 它和别的表示是不是方向接近
- 在某个读取方向上，它响应得够不够强

这时，长度、点积、相似度与投影就不再只是数学名词，而是整个表示学习系统的基础动词。

后面进入 attention 时，你会看到 query 和 key 的点积不再像突然冒出来的公式。它只是把本章建立的几何语言继续往前推进了一步：

> 当前这个表示，正在问上下文里谁和我更对齐，谁更值得被我读取。

## 本章应当留下的稳定直觉

如果这一章读完后，你只能记住几个公式，那还不够。

更稳的收获应该是下面这些直觉：

1. 向量既是数字列表，也是空间中的几何对象与语义表示。
2. 长度回答“有多大”，方向回答“朝哪里”。
3. 点积同时读取长度和方向，因此既有解释力，也会带来量级污染。
4. 余弦相似度更像“只比较方向”的版本。
5. 投影是在问一个表示沿某个方向到底有多少成分。
6. 高维空间虽然看不见，但几何语言依然是理解表示学习的主语言。

只要这几层真正站稳，后面你再遇到 embedding、分类头、attention score、归一化或缩放点积时，就不会觉得它们是互不相干的小技巧，而会看见它们共享的一层共同骨架。

\[
\|x\| = \sqrt{x_1^2 + x_2^2 + \cdots + x_n^2}
\]

这个公式看起来熟悉，因为它本质上就是勾股定理在高维空间中的延伸。

### 为什么平方再开根

初学者经常会问：

> 为什么不是把每一维绝对值直接加起来，而是平方后再开根？

一个直觉是：

- 平方可以消掉正负号
- 平方会让每一维的贡献都按“能量”方式累积
- 最后开根号，是把整体量纲拉回原来的长度尺度

如果不平方，你会遇到正负抵消的问题。
如果平方后不再开根，你得到的是“长度的平方”，它有时也有用，但不再是原本的距离尺度。

所以：

\[
\|x\|^2 = x_1^2 + x_2^2 + \cdots + x_n^2
\]

和

\[
\|x\| = \sqrt{x_1^2 + x_2^2 + \cdots + x_n^2}
\]

都很重要，只是语义不同。

前者常被看成“总能量”或“平方长度”。
后者才是通常说的长度。

## 长度除了表示距离，还经常代表“信号强度”

如果你只在几何课里学过长度，很容易把它理解成纯空间概念：

- 离原点多远
- 箭头伸出去多长

但在机器学习里，长度经常还隐含另一层含义：

> 当前表示整体有多强。

例如一个向量长度很大时，常常可能意味着：

- 某些维度激活得很强
- 整体响应量级很高
- 这个表示在后续计算里更容易主导结果

这里要特别小心。

“长度大”并不自动等于“更好”或“更有语义”。
但它常常意味着：

> 数值能量更强，因而更容易影响后续线性组合、点积或归一化前的比较结果。

所以在模型里，长度不只是几何量。
它经常还承担：

- 激活规模
- 信号量级
- 数值强度

的含义。

这也是后面归一化、cosine similarity 和 scaled dot-product 会频繁出现的重要原因。

## 为什么长度会成为问题

假设你要比较两个表示是不是“像”。

现在有两种情况：

1. 两个向量方向几乎一致，但其中一个长度非常大
2. 两个向量长度差不多，但方向明显不同

如果你的比较方法同时混入“方向”和“长度”，那么第一种情况往往会得到很大的分数。

这意味着一个很关键的事实：

> “谁更大”和“谁更像”不是同一件事。

很多机器学习任务真正想比较的是：

- 模式是否对齐
- 角色是否相近
- 方向是否一致

而不是单纯比较谁量级更高。

所以长度会立刻把我们带到一个更重要的问题：

> 当量级和方向同时存在时，我们到底想保留哪部分信息？

后面很多方法都是在回应这个问题：

- 点积保留了长度和方向
- cosine similarity 更强调方向
- 归一化会压掉长度差异
- 缩放点积会控制维度变大后分数的数值膨胀

所以理解长度，不是只学一个公式。
而是在学：

> 比较关系时，长度会怎样干扰或帮助我们。

## 什么叫向量的方向

如果长度回答的是“它有多大”，那么方向回答的是：

> 它朝哪里指。

在二维空间里，这很直观：

- 有的箭头朝右上
- 有的箭头朝左下
- 有的几乎平行
- 有的几乎垂直

在高维空间里你虽然无法直接画出来，但概念并没有变。

一个向量各维度之间的组合方式，决定了它在空间里的朝向。

方向为什么重要？

因为在表示学习里，方向往往比绝对大小更接近“模式关系”。

例如两个向量可能：

- 长度不同
- 但方向非常接近

这常常意味着：

- 它们编码的结构相似
- 它们对某些读取器会产生相似响应
- 它们在当前任务里承担的角色接近

所以当后面你看到有人说：

- 两个表示更相似
- 某个方向更有语义

很多时候，说的就是：

> 它们在表示空间中的方向关系更接近。

## 长度和方向为什么必须分开想

初学阶段最容易把这两件事混成一团。

但长度和方向对应的是不同问题：

- 长度在问“有多强”
- 方向在问“像不像”

这两者可以一起变化，也可以分开变化。

例如下面三种情况就完全不同：

### 情况一：长度变了，方向没变

这可以理解成：

- 同一种模式更强或更弱了
- 语义角色可能没变，但量级变了

### 情况二：方向变了，长度差不多

这常常意味着：

- 描述的模式关系真的变了
- 表示的语义角色可能改变了

### 情况三：长度和方向都变了

这时就需要更小心地分析，到底是谁在主导后续比较结果。

只要把这件事想清楚，你后面就不会再把任何“相似度分数”天真地理解成一个单义量。

因为很多分数实际上都在混入这两个因素。

## 什么是点积

点积最直接的定义是：

> 把两个等长向量对应位置相乘，再全部加起来。

如果：

\[
a = (a_1, a_2, \ldots, a_n)
\]

\[
b = (b_1, b_2, \ldots, b_n)
\]

那么它们的点积是：

\[
a \cdot b = a_1b_1 + a_2b_2 + \cdots + a_nb_n
\]

这是代数定义。

它看起来像一个普通算式。
但它的重要性极高，因为它同时携带了两类信息：

- 对应维度是否在共同贡献
- 两个向量整体的长度与方向关系如何

所以点积不是“一个方便的公式”而已。
它是连接代数计算和几何比较的一座桥。

## 从代数角度看，点积到底在做什么

先把点积想成逐项乘积的总和。

这意味着：

- 如果某一维两个数同号，而且都比较大，那么这一维会贡献正的大值
- 如果某一维一个正一个负，那么这一维会贡献负值
- 如果某一维有一个接近零，那么这一维几乎不贡献

所以点积其实在逐维地回答：

> 在每一个坐标方向上，这两个向量是在同向合作、反向对冲，还是几乎没关系？

最后把这些维度的结果加总起来，你得到的是一个整体重合程度。

这也是为什么点积很适合用来比较表示：

> 它会把很多维上的一致和冲突一起整合成一个总分数。

## 从几何角度看，点积又在做什么

点积最重要的几何公式是：

\[
a \cdot b = \|a\| \|b\| \cos \theta
\]

其中：

- \(\|a\|\) 是 `a` 的长度
- \(\|b\|\) 是 `b` 的长度
- \(\theta\) 是它们之间的夹角

这个公式非常关键。

因为它明确告诉你：

> 点积不是只看方向，也不是只看长度，而是把两者乘在了一起。

所以只要理解这个公式，很多现象就会变得非常清晰：

- 长度大，会把点积放大
- 方向接近，\(\cos \theta\) 会更大
- 方向相反，\(\cos \theta\) 会为负
- 彼此接近垂直时，\(\cos \theta\) 接近零

这也是为什么点积既强大又危险：

> 它很有信息量，但它混合了你未必想同时保留的因素。

## 为什么“点积既是代数又是几何”这件事这么重要

很多基础公式只停留在代数层面。

但点积之所以在机器学习里极其高频，恰恰因为它天然兼有两层身份：

### 代数身份

它可以直接在张量里高效计算。

### 几何身份

它可以被解释成长度和方向共同作用下的重合程度。

这意味着当你在代码里看到大规模矩阵乘法、批量相似度计算时，不要只想着：

- 这是在做乘加

更应该问：

- 这些乘加在几何上比较的是什么
- 模型为什么要保留长度
- 模型为什么有时要把长度影响拿掉

一旦这样想，你读模型就会更像在理解系统，而不是在盯着算子。

## 点积为正、为零、为负时分别意味着什么

这个问题很适合建立最基本的符号直觉。

### 点积为正

通常意味着：

- 两个向量整体上更偏同向
- 它们在很多重要维度上更像“同向贡献”

这不一定意味着完全相似。
但至少说明整体重合倾向是正的。

### 点积接近零

通常意味着：

- 它们之间整体重合不强
- 或者很多维度的正负贡献互相抵消
- 在理想几何解释下，可以对应近似垂直

但要小心：

“接近零”不一定意味着“完全无关”。
它只说明在当前坐标系统下，整体对齐不强。

### 点积为负

通常意味着：

- 它们整体更偏反向
- 在关键维度上的贡献更多是在相互对冲

所以点积的符号本身就已经带有很强的方向信息。

## 为什么“点积大”不一定等于“非常像”

这是初学者最容易犯的错误之一。

很多人一看到分数大，就立刻理解成：

> 它们一定非常相似。

这不稳。

因为点积大可能来自两种不同原因：

1. 两个向量方向确实很接近
2. 其中一个或两个向量的长度很大

也就是说：

> 点积大，可能是“真的很像”，也可能只是“真的很大”。

这就是为什么很多情况下需要进一步问：

- 我此刻到底想比较方向，还是比较方向加量级

而这正是 cosine similarity 会自然出现的原因。

## 什么是 cosine similarity

cosine similarity 的定义是：

\[
\cos(a, b) = \frac{a \cdot b}{\|a\| \|b\|}
\]

你可以看到，它本质上就是把点积除以两个向量长度的乘积。

这样做之后，原来几何公式里的长度项被消掉了，只剩下：

\[
\cos \theta
\]

也就是说，cosine similarity 真正保留的是：

> 方向关系

而它主动压掉的是：

> 纯粹由长度带来的放大效应

这就是它的核心语义。

所以不要把 cosine similarity 想成“更高级的点积”。
更准确地说，它是在回答另一个问题：

> 如果我只关心朝向有多接近，而尽量不让量级主导结果，会怎样？

## 为什么名字里会有 cosine

这不是命名装饰。

它的名字直接揭示了几何本质。

在平面几何里，两个向量夹角越小，它们越接近平行同向。

而：

- 夹角很小时，\(\cos \theta\) 接近 `1`
- 夹角接近 `90°` 时，\(\cos \theta\) 接近 `0`
- 夹角接近 `180°` 时，\(\cos \theta\) 接近 `-1`

所以 cosine similarity 其实是在把“夹角”变成一个更方便的数值指标。

这也解释了为什么它特别适合表达：

- 朝向接近
- 模式类似
- 方向相像

而不是表达：

- 总量有多大
- 能量有多高

## cosine similarity 为什么在表示学习里这么常见

因为很多表示学习任务并不想让量级主导比较结果。

例如你可能真正关心的是：

- 两个词向量是不是语义方向接近
- 两个样本表示是不是模式相似
- 两个隐藏状态是不是承担了类似角色

在这些场景里，如果一个表示只是因为整体数值大，就把相似度分数抬高，那通常不是你想要的。

所以 cosine similarity 的价值就在于：

> 它帮助你更纯粹地看“方向关系”。

这也是为什么在嵌入检索、相似度搜索、聚类或某些表示分析里，cosine 特别常见。

## 为什么机器学习里既需要点积，也需要 cosine

这两者不是替代关系。
它们各自服务不同目的。

### 点积更适合同时保留方向和量级

如果量级本身就是有意义的信息，那么点积很自然。

例如：

- 某些激活就是应该又看方向又看强度
- 某些打分机制就是想让大响应更占优势

### cosine 更适合强调方向关系

如果你想尽量剥离“谁更大”这个因素，那么 cosine 更合适。

例如：

- 词向量语义相似
- 表示空间近邻搜索
- 某些嵌入比较分析

所以真正重要的不是记住“哪个更好”。

而是学会问：

> 我此刻到底想让比较结果保留哪些信息？

## 什么叫投影

投影是本章最值得真正吃透的概念之一。

一个非常直观的说法是：

> 投影是在问，一个向量在另一个方向上到底占了多大分量。

想象你拿着一束灯光，把一支箭头投到某个方向线上。

你得到的那段“影子长度”，就是投影最直观的感觉。

在向量语言里，投影回答的是：

> 如果我只关心 `b` 这个方向，那么 `a` 在这个方向上到底贡献了多少？

这件事之所以重要，是因为后面很多模型操作，本质上都可以被理解成某种方向读取。

## 用点积理解投影

如果先不要求完整向量投影，只问：

> `a` 在 `b` 的方向上投影出的标量大小是多少？

那么最关键的量就是：

\[
\frac{a \cdot b}{\|b\|}
\]

如果 `b` 已经是单位向量，也就是长度为 `1`，那么这个值就更简单：

\[
a \cdot b
\]

这件事非常重要。

因为它告诉你：

> 点积可以被理解成“沿某个方向读取分量”的操作。

也就是说，一个方向向量 `b` 不只是用来比较像不像。
它还可以被理解成：

> 一个读取器，它在问 `a` 沿着我这条方向有多强。

这正是后面线性层和注意力中很多读取行为的几何核心。

## 向量投影和标量投影要分清

这里最好区分两件事。

### 标量投影

它回答的是：

> 在目标方向上有多长。

这是一个数。

### 向量投影

它回答的是：

> 在目标方向上那部分真正的向量成分是什么。

这是一个向量。

对初学者来说，先抓住标量投影已经足够。

因为这层理解已经能帮助你看懂很多机器学习里的“打分”操作：

> 一个方向向量像一个探针，去读取另一个向量在这个方向上的响应强度。

## 为什么投影是理解线性层的桥

在线性层里，每个输出维本质上都可以理解成：

> 用一组权重定义一个方向，然后读取输入在这个方向上的响应。

如果写成：

\[
z = w^\top x + b
\]

那么忽略偏置时，`w^\top x` 就可以被理解成：

- 一个点积
- 一个方向读取
- 一个投影相关量

也就是说，单个线性输出维不是凭空产生的。

它是在问：

> 输入向量在我这组权重所代表的方向上，有多强？

这正是为什么前面说每个输出维都像一个模式探测器。

从几何角度看，它就是一个方向读取器。

## 为什么投影也是理解 Attention 的桥

到了 attention，这件事会以另一种形式再次出现。

attention 里的 query 和 key 做点积：

\[
q \cdot k
\]

这件事如果只从代数看，像是在算一个分数。

但如果从几何角度看，你可以理解成：

> 当前 query 所代表的读取方向，与这个 key 所代表的可匹配方向，重合得有多强。

换句话说，它像是在问：

> 如果 query 正在寻找某类方向，那么 key 在这个方向上是不是对得上？

这当然不是全部 attention 语义。
但它已经抓住了最底层的几何骨架。

所以本章不是在提前偷讲 attention。
而是在为你提前铺平最基础的理解桥梁。

## 为什么“表示空间”这个说法不是修辞

后面你会反复听到“表示空间”。

如果几何直觉不稳，这个词很容易显得像文学说法。

其实它非常字面。

所谓表示空间，就是：

> 这些表示向量真实所在的那个高维空间。

既然它是一个空间，那么立刻就有很多空间问题：

- 哪些点离得更近
- 哪些方向更重要
- 某一层把点重新挪到了哪里
- 为什么某类样本在某层后变得更容易分开

也就是说，“表示空间”不是修辞。
它是在提醒你：

> 模型内部的表示关系，很多时候最好直接用空间关系来理解。

## 什么叫“相似”，为什么它不该被想得太神秘

在机器学习里，“相似”这个词很容易被过度神秘化。

很多人会把它理解成一种非常高级、接近人类语义判断的东西。

但在最底层，模型里的相似通常先从下面几类东西起步：

- 坐标上的重合
- 方向上的接近
- 某些读取方向上的响应相似
- 某些下游任务所需特征的共同出现

这意味着：

> 模型里的“相似”首先是表示层面的相似，而不是先验的人类语言学相似。

当然，好的表示空间最终可以让很多人类语义关系在其中显现出来。
但那是更高层结果。

基础层一定要先站稳：

> 相似度分数首先是在比较表示对象之间的几何关系。

## 为什么高维空间虽然难画，但几何并没有失效

这是很多初学者会卡住的地方。

他们会说：

> 二维、三维我还能想象，到了 512 维、4096 维，几何不是就失效了吗？

不会。

真正变化的不是几何规则失效，而是：

- 你的可视化能力失效了

这两件事必须严格分开。

即使在高维空间里，下面这些关系仍然完全成立：

- 长度依然可以定义
- 点积依然可以定义
- 方向接近与否依然有意义
- 投影依然可以定义
- 归一化依然可以定义

所以高维空间的困难，不是概念崩了。
而是你不能再靠脑海里画一张简单图来辅助。

这时更重要的就是：

> 把二维三维里的直觉，升级成可以不用画图也能稳定工作的抽象几何直觉。

这正是本章在做的事。

## 为什么高维里“直觉偏差”会变大

虽然几何没有失效，但高维确实会让某些人类直觉变差。

例如：

- 很多随机向量彼此会更接近“近似正交”
- 长度和点积的数值分布会随维度改变
- 少量局部想象图不再足以代表整体行为

这意味着你在高维里必须更依赖：

- 定义
- 公式
- 统计规律

而不能只依赖低维画图经验。

所以一个成熟的学习者，不是放弃几何。
而是学会：

> 在高维里继续用几何语言思考，但不再要求所有东西都能被肉眼想象成平面图。

## 为什么归一化会频繁出现

只要长度会影响比较，而你又不总想让长度主导结果，归一化就会自然出现。

最常见的归一化想法是：

> 把向量缩放到长度为 `1`。

如果：

\[
\hat{x} = \frac{x}{\|x\|}
\]

那么 \(\hat{x}\) 就是单位向量。

单位向量的核心价值在于：

- 它保留了方向
- 它把长度统一了

于是很多比较会变得更纯粹地关注：

- 谁和谁方向更接近

这就是为什么 cosine similarity 本质上就是：

- 先把向量长度因素拿掉
- 再比较方向

很多归一化方法虽然形式更复杂，但底层直觉常常都和这里类似：

> 控制量级，避免某些比较或更新被纯数值大小绑架。

## 为什么 Attention 里的缩放点积不是随手加的

在注意力里，你常会看到：

\[
\frac{q \cdot k}{\sqrt{d}}
\]

很多初学者会把这个 `sqrt(d)` 当成：

- 工程小技巧
- 魔法常数
- 作者试出来的经验项

这不对。

它背后有相当明确的数值动机。

一个非常粗糙但够用的直觉是：

> 维度 `d` 变大时，点积往往更容易因为很多维度的累积而变得数值偏大。

一旦分数过大，后面的 softmax 就更容易变得过尖：

- 某几个位置几乎吃掉全部概率
- 梯度更容易不稳定
- 学习会变得更脆弱

所以除以 `sqrt(d)` 的意义在于：

> 控制点积分数随维度增长而产生的数值膨胀，让它保持在更合适的范围。

也就是说，这不是装饰。
它是一个非常典型的：

- 数学定义
- 统计尺度
- 数值稳定性

共同作用下的设计选择。

## 用一个更统一的视角回看：长度、点积、cosine、投影到底是什么关系

走到这里，可以把这几个概念压到同一张图里。

### 长度

回答：

> 这个表示整体有多大、有多强。

### 点积

回答：

> 两个表示在长度和方向共同作用下，整体重合得有多强。

### cosine similarity

回答：

> 如果尽量剥离长度，只看方向，它们有多接近。

### 投影

回答：

> 这个表示沿着某个指定方向，真正占了多大分量。

一旦把它们放回这张统一关系图里，你后面再看到模型里的各种打分、读取、投影，就不会再觉得是四套彼此独立的数学工具。

它们其实在围绕同一个核心问题打转：

> 模型怎样比较、读取和重写向量表示之间的关系。

## 这一章和前后章节是怎样接上的

它和前一章的关系是：

- 前一章讲矩阵乘法和线性变换
- 这一章补上变换后的表示要怎样被比较、解释和读取

它和后一批章节的关系是：

- 线性层会沿某些方向读取输入
- 激活和表示学习会重新组织空间关系
- attention 会直接调用点积、方向匹配和缩放思想

换句话说，这一章正处在一个非常关键的位置：

> 它把“有向量了”推进到“知道怎样比较向量之间的结构关系了”。

如果这一层走稳，后面很多结构都会自然得多。

## 初学者在这一章最容易犯的几个错误

### 错误一：仍然把向量只看成数字列表

这样你会看不见长度、方向、投影这些关系层。

### 错误二：把点积只当成公式，不问它在比较什么

这样你会记住算子，但丢掉几何意义。

### 错误三：把“点积大”直接等同于“非常相似”

你会忽略长度放大效应。

### 错误四：把 cosine similarity 理解成“点积升级版”

它不是升级版。
它是在回答另一个更偏方向的问题。

### 错误五：把投影理解成纯几何附录

实际上它是理解线性读取和注意力匹配的桥。

### 错误六：一听高维就放弃几何语言

高维让画图困难，不让几何失效。

## 本章小结

把整章压缩成最核心的几条，就是：

1. 向量既可以看成数字列表，也可以看成空间中的点或从原点出发的箭头。
2. 长度描述的是整体量级，方向描述的是朝向；两者在模型里常常分别对应“有多强”和“像不像”。
3. 点积同时保留长度和方向信息，因此它既强大又需要谨慎解释。
4. cosine similarity 本质上是在尽量剥离长度影响后比较方向关系。
5. 投影可以被理解成“沿某个方向读取分量”，这是理解线性层和注意力的重要桥梁。
6. 高维空间并没有让几何失效，只是让你不能再依赖低维画图，而必须依赖更稳定的抽象直觉。
7. 后面很多看起来高级的模型结构，底层都在复用这些基础几何关系。

这就是为什么这一章必须在 attention 之前真正学懂。
