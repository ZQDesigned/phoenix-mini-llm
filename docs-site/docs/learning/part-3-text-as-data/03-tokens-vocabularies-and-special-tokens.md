# 03. Token、词表与 special token

## 为什么文本不能直接进神经网络

前面我们已经知道：

- 神经网络处理的是数值张量
- 模型输出的是分布
- 文本文件底层是一串字符和字节

于是接下来必须解决一个非常现实的问题：

> 文本怎样变成模型可以处理的离散输入单位？

这就是 token 化问题。

## 什么是 token

token 可以先理解成：

> 模型输入输出空间里的基本离散单位。

它不一定等于：

- 一个字
- 一个词
- 一个英文单词

它可能是：

- 单个字符
- 子词片段
- 标点
- 空格相关片段
- 某些特殊控制符号

所以当你听到“预测下一个 token”时，必须意识到：

> 这个 token 是模型定义出来的离散单位，而不是自然语言本身天然就给好的单位。

## 为什么 token 化是一种建模选择

很多初学者会把 tokenizer 当成纯预处理器，好像“随便选一个都差不多”。

这是不对的。

tokenizer 的选择会影响：

- 输入长度
- 词表大小
- 稀有词处理方式
- 模型在不同语言现象上的学习难度

也就是说，token 化不是外壳，而是：

> 你如何切开语言、如何定义模型观察世界的基本颗粒度。

## 字符级、词级、子词级各有什么问题

### 字符级

优点是：

- 词表小
- 不容易遇到未登录词

缺点是：

- 序列会很长
- 模型需要跨更多位置才能拼出词义

### 词级

优点是：

- 人类直觉上更接近“词”
- 单个 token 语义粒度较大

缺点是：

- 词表容易膨胀
- 稀有词和新词问题严重

### 子词级

这是很多现代语言模型常用的折中方案。

它试图在：

- 词表规模
- 序列长度
- 稀有词可分解性

之间取得更平衡的结果。

所以今天大量模型使用 BPE、SentencePiece 一类方法，并不是“因为大家都这么做”，而是因为它们在实践上常常更合适。

## 什么是词表

词表就是：

> tokenizer 允许模型识别和输出的全部 token 集合。

每个 token 在词表中都有自己的 id，于是模型看到的输入序列会变成：

```text
[42, 119, 7, 803, ...]
```

这说明词表不是一本单纯的“字符串清单”，而是：

- 输入空间
- 输出空间
- embedding 查表空间
- 最终分类空间

的共同定义。

## 为什么词表大小是个关键超参数

词表越大：

- 单个 token 可能携带更丰富的局部语义
- 但 embedding 和输出头会更重
- 分类空间也会更大

词表越小：

- 参数压力变小
- 但序列会更长
- 模型需要在更多 token 上拼装词义

所以词表大小不是“越大越高级”，而是要和：

- 语料语言特征
- 模型规模
- 训练预算

一起平衡。

## 什么是 special token

special token 指的是那些不主要承载普通自然语言词义，而是承担结构或控制作用的 token。

常见例子包括：

- BOS：序列开始
- EOS：序列结束
- PAD：补齐占位
- UNK：未知 token
- 分隔符、角色标记等

这些 token 的价值不在于“它们也属于词表”，而在于：

> 它们定义了模型如何理解边界、结构、开始、结束和格式控制。

## 为什么 special token 不是小细节

很多模型行为其实都依赖这些边界标记。

例如：

- EOS 会影响模型是否知道该停
- 分隔符会影响模型怎样区分不同段落或不同说话人
- PAD 会影响 batch 对齐和 mask

所以如果 special token 定义不稳，后果可能不是“输出有点怪”，而是：

> 任务边界本身被定义错了。

## tokenizer 为什么属于模型定义的一部分

这是必须牢牢记住的判断。

如果你换了 tokenizer，哪怕模型结构一个字没改，很多事情也已经变了：

- 输入 token 序列变了
- 词表 id 变了
- embedding 含义变了
- 输出头类别空间变了

这说明 tokenizer 不是“模型外部的预处理插件”，而是：

> 模型输入输出协议的一部分。

因此，一个 checkpoint 往往不能随便脱离原 tokenizer 使用。因为它们本来就是一套共同定义。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> token、词表和 special token 共同定义了语言模型观察与生成文本的离散世界；tokenizer 不是外部脚手架，而是模型定义的一部分，因为它直接决定了输入边界、输出类别和序列结构。
