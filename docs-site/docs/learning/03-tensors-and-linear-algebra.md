# 03. Tensor 与线性代数直觉

很多人开始学语言模型时，不是先被论文劝退，而是先被 shape 劝退。

你经常会看到这种东西：

- `input_ids.shape == [batch, seq]`
- `hidden.shape == [batch, seq, hidden]`
- `logits.shape == [batch, seq, vocab]`
- `q.shape == [batch, heads, seq, head_dim]`

如果这些符号在你脑子里只是“二维、三维、又一个四维”，那后面几乎所有模型代码都会像雾里看花。你也许能机械地照着写，但你很难真正知道：

- 每一维在表示什么
- 某一层到底在改哪一维
- 为什么一段矩阵乘法是合法的
- 为什么 transpose 之后 attention 才算得通
- 一旦 shape 出错，该先怀疑哪一步

这一章的目标不是把你训练成线性代数专家，而是建立一种足够稳定的直觉：

> 让你看到语言模型里的 tensor 时，脑子里自动浮现它代表的对象、维度含义和流动方向。

这是后面几乎所有章节的共同地基。

## Tensor 并不神秘，它首先只是“带形状的数字容器”

在 PyTorch 里，`torch.Tensor` 最实用的理解就是：一块带 shape 的多维数字容器。

很多新手第一次听到 tensor 这个词，会以为它是一种非常特殊、非常难懂的数学对象。其实在学习项目阶段，更有用的理解是：

> tensor 的难点不在于它多高级，而在于你是否始终知道每一维代表什么。

例如，一个 shape 为：

\[
[2, 3, 4]
\]

的张量，可能表示：

- 2 张图片，每张 3 行 4 列
- 2 条样本，每条 3 个位置，每个位置 4 维向量
- 2 个 batch，每个 batch 3 个 token，每个 token 4 个类别分数

也就是说，单纯知道“这是三维张量”几乎没有意义。真正重要的是：

> 你能不能说清楚每一维的语义。

这也是为什么在语言模型里，shape 从来不只是打印出来看看，而是一种阅读和调试语言。

## 先把四个最常见的维度名字认稳

语言模型里最常反复出现的维度名字，通常是下面这几类：

- `batch`
- `seq`
- `hidden`
- `vocab`

如果你能把这四个维度真正读顺，后面大量代码会突然开始变得可读。

### `batch`

表示一次并行处理多少条样本。

### `seq`

表示每条样本中有多少个 token 位置，也就是序列长度。

### `hidden`

表示每个位置当前被表示成多宽的向量，也就是隐藏表示维度。

### `vocab`

表示词表大小，也就是某个位置上最终要在多少个离散候选 token 中做分配或选择。

这四个词一旦读顺，你看到：

\[
[batch, seq, hidden]
\]

时就不会只想到“三维”，而会想到：

> 一批样本，每条样本有一串 token，每个 token 当前都被写成一个向量。

## 为什么语言模型天然会反复出现三维张量

很多初学者最容易困惑的点之一是：

> 为什么一到语言模型，张量就动不动三维、四维？

从结构上看，这其实非常自然。

第一步，一次训练通常不只处理一条样本，这就产生了 `batch` 维度。

第二步，每条样本是一串 token，这就产生了 `seq` 维度。

第三步，每个 token 在模型内部都会被表示成一个向量，这就产生了 `hidden` 维度。

于是三维张量自然出现：

\[
[batch, seq, hidden]
\]

你可以把它想象成：

- 最外层是一叠样本
- 每个样本是一排 token
- 每个 token 上挂着一个向量

一旦这个图像建立起来，三维张量就不再陌生。

## `input_ids`、`hidden`、`logits`：三种必须最先看懂的 shape

对语言模型学习项目来说，有三种 shape 是必须第一时间吃透的。

### 1. `input_ids`

最常见形状是：

\[
[batch, seq]
\]

它表示：

- 一个 batch 中有多少条样本
- 每条样本里有多少个 token id

注意，这里每个位置上的值通常还是离散整数编号，不是连续向量。

### 2. embedding 之后的隐藏状态

最常见形状是：

\[
[batch, seq, hidden]
\]

这表示：

- batch 中有多条样本
- 每条样本中有多个 token 位置
- 每个 token 位置现在都拥有一个 `hidden` 维向量表示

### 3. 最终 logits

最常见形状是：

\[
[batch, seq, vocab]
\]

这表示：

- 每条样本的每个位置
- 都对应一组对整个词表的候选分数

如果你能把这三种 shape 真正吃透，后面大量语言模型代码都会突然开始变得可读。

## `batch` 维度到底在帮你做什么

`batch` 的存在，是为了并行处理多条样本。

假设：

```text
batch_size = 4
```

这表示模型一次同时看 4 条训练样本。

### 为什么不一条一条处理

因为现代硬件，尤其 GPU，更擅长大规模并行计算。

使用 batch 的好处包括：

- 吞吐更高
- 设备利用率更好
- 梯度估计通常更稳定

### 它的代价是什么

- 显存占用更高
- 数据需要被整理成统一形状
- 训练过程会带入更明显的统计层含义

所以 `batch` 从来不是“数学多出来的一维”，它反映的是：

> 模型训练时正在同时处理多少条样本。

## `seq` 为什么不只是“长度”这么简单

`seq` 表示每条样本的 token 长度。

它经常也被叫作：

- sequence length
- context length
- max sequence length

很多初学者第一次见到它时，只把它当成“句子长度”。这还远远不够。

对语言模型来说，`seq` 同时影响：

- 模型一次能看到多长前文
- 数据该如何打包
- attention 的计算规模
- 中间激活值占用
- 推理时每一步的成本

对小型语言模型学习项目来说，`seq` 是特别敏感的维度。很多时候，模型能不能在你的设备上稳定跑起来，不只是由层数决定，也非常取决于序列长度。

所以你看到 `seq` 时，不要只把它看成“句子长度”，而要把它看成：

> 模型的视野边界和计算成本边界。

## `hidden` 到底是什么

`hidden` 表示每个 token 在模型内部被表示成多宽的向量。

例如：

```text
hidden_size = 384
```

意思不是“这个 token 有 384 个字符”，而是：

> 模型用一个 384 维连续向量来承载这个 token 当前的内部表示。

### 为什么需要高维向量

因为语言模型要表达的不是“这个 token 的编号是多少”，而是很多上下文和统计相关的信息，例如：

- 它和哪些其他 token 常一起出现
- 它在当前位置承担什么作用
- 它在当前上下文中的语义倾向
- 它和其他位置之间的关系线索

单个标量根本不够承载这些信息，因此模型需要高维表示空间。

一个很有帮助的直觉是：

> `hidden` 可以被理解成模型给每个 token 分配的内部思考空间宽度。

这个说法不严格，但对初学者非常有帮助。

## `vocab` 维度为什么通常出现在最后

`vocab` 对应词表大小。

当模型最终输出 logits 时，最后一维通常就是 `vocab_size`，因为模型需要回答：

> 对词表里的每一个候选 token，我分别打多少分？

因此形状：

\[
[batch, seq, vocab]
\]

的含义就是：

- 每条样本
- 每个位置
- 都对应整张词表上的一组候选分数

这也是为什么语言模型最后的输出层经常非常大：它必须覆盖整个词表空间。

## embedding 到底在做什么

这是理解前向传播最重要的一步之一。

`input_ids` 本身只是离散整数编号。例如：

```text
[101, 42, 932, 7]
```

这些数字对神经网络来说没有天然的几何意义。它们更像标签，而不是可以直接做相似度计算的对象。

embedding 的作用就是：

> 把离散 token id 映射成连续向量。

于是 shape 会从：

\[
[batch, seq]
\]

变成：

\[
[batch, seq, hidden]
\]

这一步极其关键，因为它意味着模型终于能在连续空间里对 token 进行比较、组合和改写。

换句话说，embedding 不是一个“很前面的小步骤”，而是语言进入神经网络主体的第一道门。

## 为什么矩阵乘法会在模型里反复出现

很多初学者第一次看模型代码时，会觉得矩阵乘法出现得过于频繁，像某种公式传统。

其实它反复出现是有结构原因的。

线性层可以写成：

\[
y = Wx + b
\]

这意味着：

- 输入向量被一组可学习权重重新读取
- 原有特征被混合
- 输出被写进一个新空间

所以矩阵乘法在模型里真正承担的不是“数学仪式感”，而是：

> 表示重组。

无论是 embedding 之后的投影、QKV 生成、前馈层扩维压缩，还是输出头投到词表空间，本质上都在用矩阵乘法把当前表示重写到另一个更适合当前子任务的空间里。

## 一个最核心的线性代数直觉：矩阵乘法不是数字游戏，而是“按方向重写表示”

如果你只把矩阵乘法理解成一套行乘列的规则，后面很容易迷路。

对语言模型最有用的理解是：

> 矩阵乘法是在用一组可学习方向，重新读取和重组当前表示。

举个非常粗略但有用的直觉：

- 输入向量里装着当前 token 的信息
- 矩阵里的每一行像一个“读取模板”
- 输出的每个维度都在问：“输入在我这个方向上的响应有多强？”

于是，一次线性变换就等于：

> 把当前对象翻译进一套新的内部坐标系。

这就是为什么“投影”“映射”“表示空间”这些词会在后面反复出现。

## 为什么 transpose、reshape 和 view 这么危险

很多初学者一开始最容易在这类操作上出问题：

- `reshape`
- `view`
- `transpose`
- `permute`

原因不是这些函数难，而是它们会改变你对各个轴的解释方式。

最危险的地方在于：

> 有些操作不会报 shape 错，但会把语义悄悄弄坏。

例如，一个张量从：

\[
[batch, seq, hidden]
\]

变成：

\[
[batch, heads, seq, head\_dim]
\]

如果你只看数字是否对得上，而没搞清楚：

- 哪一维现在代表头数
- 哪一维现在代表时间位置
- 哪一维现在代表每头特征宽度

那么后面的 attention 计算很可能在形状合法的情况下语义全错。

所以在语言模型里，shape 错误有两种：

- 数字对不上，程序直接报错
- 数字对得上，但轴语义错了，程序不报错却行为异常

后者往往更危险。

## attention 为什么会进一步长出四维张量

你前面已经看到，标准隐藏状态往往是：

\[
[batch, seq, hidden]
\]

可到了多头注意力，你经常会看到：

\[
[batch, heads, seq, head\_dim]
\]

为什么会多出 `heads` 这一维？

因为多头注意力并不是用一个单一注意力视角去读历史，而是把总的隐藏维拆成若干头，让多个子空间并行地比较和读取。

这里最重要的结构关系是：

\[
hidden = heads \times head\_dim
\]

也就是说，总的特征宽度被拆成了多份，每份由一个 head 负责。

所以四维张量并不是“突然更复杂”，而是：

> 三维隐藏状态在进入多头结构之后，被重新解释成“样本、头、位置、头内特征”四个层次。

## 为什么点积会在 attention 里自然出现

一旦你有了向量表示，就很自然会问：

> 两个位置的表示到底有多相像？

点积之所以反复出现，是因为它提供了一种非常自然的相容性评分方式。它不只是“把数乘起来再加总”，而是在回答：

> 这两个向量在当前空间里对齐得有多好？

所以后面当你看到 query 和 key 做点积时，最好不要只把它看成一个公式片段，而要把它理解成：

> 当前读取意图和历史候选之间的相容性比较。

这就是线性代数在语言模型里的真实位置：它不是外加装饰，而是在提供模型内部最基本的比较、投影和重组语言。

## 为什么说 shape 是一种调试语言

很多新手把 shape 只当成一种“程序报错信息”，只有出错了才看。这个习惯要尽快改掉。

更成熟的做法是：

> 在写模型时，shape 本身就是一套随时帮助你确认对象语义的调试语言。

例如你看到：

\[
[batch, seq, vocab]
\]

脑中就应该马上知道：

- 这里已经是词表分数，不是隐藏状态
- 这里最后一维不能再被当成 hidden 去做 attention
- 这里如果要算 loss，就要和 target 的位置一一对齐

再比如你看到：

\[
[batch, heads, seq, seq]
\]

你就应该意识到：

- 这里更像是注意力分数或权重
- 最后两个 `seq` 分别对应查询位置和被读取位置

只要这个习惯建立起来，你写模型和读源码时的稳定性会明显提高。

## 初学者在这里最容易犯的几个误解

第一个误解是：tensor 是一种非常高级、必须先彻底数学化才能理解的对象。

不对。学习项目阶段最重要的是先把它理解成“带 shape 的数字容器”，再把每一维语义读稳。

第二个误解是：知道张量是几维就已经够了。

不对。真正重要的是每一维在表示什么，而不是单纯几维。

第三个误解是：只要数字能对上，shape 就没问题。

不对。数字合法但轴语义错误，是语言模型里最常见也最危险的问题之一。

第四个误解是：矩阵乘法只是公式习惯。

不对。它在模型里反复出现，是因为它承担表示重组和空间投影的职责。

第五个误解是：embedding 只是很前面的一步，不算模型主体。

不对。embedding 是离散 token 进入连续表示空间的第一道门。

## 这一章真正要记住的核心句子

如果只能记住一句话，请记住这一句：

> 在语言模型里，tensor 首先不是抽象数学名词，而是带 shape 的对象容器；线性代数也不只是公式规则，而是在提供模型内部的投影、比较、重组与表示流动语言。

## 读完这一章之后，你应该能稳定回答这些问题

- 为什么语言模型天然会反复出现三维和四维张量？
- `batch`、`seq`、`hidden`、`vocab` 分别在说什么？
- `input_ids`、隐藏状态和 logits 的 shape 有什么根本区别？
- embedding 到底把什么变成了什么？
- 为什么矩阵乘法会在模型里反复出现？
- 为什么很多 shape bug 其实是轴语义 bug？

## 如果现在只能先养成一个习惯

请先养成这个习惯：

> 每当你看到一个 tensor，不要先问“它几维”，而要先问“每一维代表什么对象，这些对象现在正朝哪一步流动”。

只要这个习惯稳定下来，后面的模型实现和调试就会顺很多。

## 小结

这一章真正搭起来的，不是几条孤立的 shape 规则，而是一种阅读模型的底层姿势：

- 看见 tensor，就看见对象语义
- 看见矩阵乘法，就看见表示重组
- 看见新维度，就追问它在任务里承担什么角色

后面你再去学 attention、Transformer block、loss 和训练循环时，请一直带着这个姿势。那样你看到的就不再是很多神秘张量操作，而是一条能被解释的表示流。
