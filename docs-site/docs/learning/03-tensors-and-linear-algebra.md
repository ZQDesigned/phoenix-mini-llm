# 03. Tensor 与线性代数直觉

## 这一章要解决什么问题

很多人开始学语言模型时，不是先被论文劝退，而是先被 shape 劝退。

你经常会看到这种东西：

- `input_ids.shape == [batch, seq]`
- `hidden.shape == [batch, seq, hidden]`
- `logits.shape == [batch, seq, vocab]`

如果这些符号在你脑子里只是“二维、三维、又一个三维”，那后面所有模型代码都会像雾里看花。你也许能机械地照着写，但你很难真正知道：

- 每一维在表示什么
- 某一层到底在改哪一维
- 为什么一段矩阵乘法是合法的
- 一旦 shape 出错，该先怀疑哪一步

这一章的目标不是把你训练成线性代数专家，而是建立一种足够稳定的直觉：

> 让你看到语言模型里的张量时，脑子里自动浮现它代表的对象、维度含义和流动方向。

这是后面几乎所有章节的共同地基。

## 第一件事：tensor 并不神秘，它只是“带形状的数字容器”

在 PyTorch 里，`torch.Tensor` 本质上可以理解成一个多维数组。

很多新手第一次听到 tensor 这个词，会以为它是一种非常特殊、非常难懂的数学对象。其实在学习项目阶段，更有用的理解是：

> tensor 就是一块带 shape 的数字容器，关键不在于它多高级，而在于你是否始终知道每一维代表什么。

### 为什么 shape 比“有没有三维”更重要

同样是一个三维张量：

\[
[2, 3, 4]
\]

它可能表示：

- 2 张图片，每张 3 行 4 列
- 2 条样本，每条 3 个位置，每个位置 4 维向量
- 2 个 batch，每个 batch 3 个 token，每个 token 4 个类别分数

也就是说：

> 单纯知道“它是三维”没有意义，必须知道每一维的语义。

这也是为什么在语言模型里，shape 从来不只是打印出来看看，而是一种阅读和调试语言。

## 第二件事：语言模型最常见的张量长什么样

在语言模型学习项目里，你会反复遇到几种特别核心的 shape。

### 1. `input_ids`

最常见形状是：

\[
[batch, seq]
\]

它表示：

- 一个 batch 中有多少条样本
- 每条样本里有多少个 token id

注意，这里每个位置上的值通常还是离散整数编号，不是连续向量。

### 2. embedding 后的隐藏状态

最常见形状是：

\[
[batch, seq, hidden]
\]

这表示：

- batch 中有多条样本
- 每条样本里有多个 token 位置
- 每个 token 位置现在都拥有一个 `hidden` 维向量表示

### 3. 最终 logits

最常见形状是：

\[
[batch, seq, vocab]
\]

这表示：

- 每条样本的每个位置
- 都对应一组对整个词表的打分

如果你能把这三种 shape 真正吃透，后面大量语言模型代码都会突然开始变得可读。

## 第三件事：为什么语言模型天然会出现三维张量

初学者最容易困惑的点之一是：

> 为什么一到语言模型，张量就动不动三维、四维？

从最基本的结构看，其实非常自然。

### 第一步：一次通常不只处理一条样本

这就产生了 batch 维度。

### 第二步：每条样本是一串 token

这就产生了序列维度，也就是 `seq`。

### 第三步：每个 token 会被表示成向量

这就产生了特征维度，也就是 `hidden`。

于是三维张量自然出现：

\[
[batch, seq, hidden]
\]

你可以把它想象成：

- 最外层是一叠样本
- 每个样本是一排 token
- 每个 token 上挂着一个向量

一旦你建立这个图像，三维张量就不再陌生。

## 第四件事：batch 维度到底在帮你做什么

`batch` 的存在是为了并行处理多条样本。

假设：

```text
batch_size = 4
```

就表示模型一次同时看 4 条训练样本。

### 为什么不一条一条处理

因为现代硬件，尤其 GPU，更擅长大规模并行计算。

用 batch 的好处包括：

- 吞吐更高
- 设备利用率更好
- 梯度估计通常更稳定

### 它的代价是什么

- 显存占用更高
- 数据需要被整理成统一形状
- 训练过程设计稍微复杂一些

所以 batch 维度不是“数学多出来的一维”，它反映的是：

> 模型训练时正在同时处理多少条样本。

## 第五件事：sequence 维度为什么在语言模型里如此重要

`seq` 表示每条样本的 token 长度。

它经常也被叫作：

- sequence length
- context length
- max sequence length

### 为什么它不只是“长度”这么简单

因为它会同时影响：

- 模型一次能看到多长前文
- 数据该如何打包
- attention 的计算规模
- 中间激活值占用
- 推理时每一步的成本

对小型语言模型学习项目来说，`seq` 是特别敏感的维度。很多时候，模型能不能在你的设备上跑起来，不只是由层数决定，也非常取决于序列长度。

所以你看到 `seq` 时，不要只把它看成“句子长度”，而要把它看成：

> 模型的视野边界和计算成本边界。

## 第六件事：hidden 维度到底是什么

`hidden` 表示每个 token 在模型内部被表示成多宽的向量。

例如：

```text
hidden_size = 384
```

意思不是“这个 token 有 384 个字符”，而是：

> 模型用一个 384 维连续向量来承载这个 token 当前的内部表示。

### 为什么需要高维向量

因为语言模型要表达的不是“这个 token 的编号是多少”，而是很多统计和上下文相关的信息，例如：

- 它与哪些其他 token 常一起出现
- 它在当前位置承担什么作用
- 它在当前上下文中的语义倾向
- 它和其他位置的关系线索

单个标量根本不够承载这些信息，因此模型需要高维表示空间。

### 一个重要直觉

你可以把 hidden 维度理解成：

> 模型给每个 token 分配的内部思考空间宽度。

这个说法不精确，但对初学者很有帮助。

## 第七件事：vocab 维度在表示什么

`vocab` 对应词表大小。

当模型最终输出 logits 时，最后一维通常就是 `vocab_size`，因为模型需要回答：

> 对词表中的每一个候选 token，我分别打多少分？

因此形状：

\[
[batch, seq, vocab]
\]

的含义是：

- 每条样本
- 每个位置
- 都对应整张词表上的一组候选分数

这也是为什么语言模型最后的输出层经常非常大：它必须覆盖整个词表空间。

## 第八件事：embedding 到底在做什么

这是理解前向传播最重要的一步之一。

原始 `input_ids` 只是整数编号，例如：

```text
[5, 19, 204, 7]
```

模型不能直接拿这些整数去做高质量表示学习，所以需要 embedding。

### embedding 的本质是什么

最朴素的理解就是：

> 一张大表。

这张表的形状通常可以写成：

\[
[vocab\_size, hidden\_size]
\]

其中：

- 每一行对应一个 token id
- 每一列对应这个 token 表示中的一个维度

### 当你输入 token id 时发生了什么

如果某个 token id 是 `17`，embedding 做的事本质上不是复杂推理，而是：

> 从这张表中取出第 17 行向量。

所以很多人会说 embedding 像“查表”。这个比喻非常准确，尤其在学习阶段。

### 一个最小例子

```python
import torch

input_ids = torch.tensor([[1, 2, 3], [4, 5, 6]])
embedding_table = torch.randn(10, 4)
hidden = embedding_table[input_ids]

print(input_ids.shape)  # [2, 3]
print(hidden.shape)     # [2, 3, 4]
```

这里真正发生的是：

1. 原来每个位置只有一个整数 id  
2. 现在每个位置都换成了一个长度为 4 的向量  
3. 所以张量从二维变成三维

这就是从离散符号世界进入连续表示世界的第一步。

## 第九件事：为什么线性层通常只改变最后一维

这是语言模型代码里最重要的 shape 直觉之一。

假设你有一个张量：

\[
[batch, seq, hidden]
\]

然后你接一个线性层，把 `hidden` 投影到另一个维度，例如 `out_dim`。你通常会得到：

\[
[batch, seq, out\_dim]
\]

### 为什么前两维通常不变

因为线性层本质上是在对“最后一维上的向量”做变换，而不是在改变：

- 你有几条样本
- 你有几个 token 位置

这意味着：

> 它是在“每个位置上分别改写这个向量”，而不是在打乱整个序列结构。

### 为什么这件事很重要

因为你后面会不断看到：

- Q/K/V 投影
- FFN 的升维和降维
- 输出层映射到词表

它们几乎都遵守这个直觉：

> 保留 batch 和 seq，改最后一维。

## 第十件事：矩阵乘法为什么是阅读模型代码时必须会看的东西

你现在不需要成为矩阵推导高手，但你必须形成最基本的维度敏感性。

最基础的规则是：

\[
A \in \mathbb{R}^{m \times n}, \quad B \in \mathbb{R}^{n \times p}
\Rightarrow
AB \in \mathbb{R}^{m \times p}
\]

### 这在语言模型里会不断出现

例如：

- 隐藏状态乘投影矩阵
- query 与 key 转置点积
- attention 权重再乘 value

你看到任何矩阵乘法时，第一反应都应该是：

> 维度真的能对上吗？

这会极大降低你后面读 attention 和 transformer block 时的恐惧感。

## 第十一件事：Attention 为什么会引入更多维度

到目前为止你最熟悉的可能还是：

\[
[batch, seq, hidden]
\]

但 attention 常常还会引入 `heads` 维度，形成像这样的形状：

\[
[batch, heads, seq, head\_dim]
\]

### 这意味着什么

模型把原来的隐藏维度拆成了多个头，每个头各自处理一部分表示空间。

所以这不是“凭空多出一维”，而是：

> 原来的表示被重新组织成多头结构，以便并行学习不同依赖模式。

这个阶段你不需要一下子吃透所有细节，但需要知道：

- 四维张量并不意味着更神秘
- 很多时候只是多加了一层结构化拆分

## 第十二件事：shape 为什么不只是打印信息，而是调试信息

很多人已经养成了打印 shape 的习惯，但仍然不会真正“读 shape”。

例如，你打印出：

```text
[4, 256, 384]
```

如果你只是说“这是个三维张量”，那几乎没提供任何信息。

真正有效的阅读方式应该是：

> 这是 4 条样本，每条 256 个位置，每个位置 384 维隐藏表示。

再比如，如果你本来预期输出应该是 logits，但结果最后一维却不是词表大小，那就说明某层映射可能错了。

所以 shape 的作用包括：

- 验证你对数据流的理解
- 快速发现层间接口错误
- 帮助你定位是 batch、seq 还是特征维出了问题

## 第十三件事：为什么“张量直觉”比“记 API”更重要

很多初学者会试图通过记住很多库函数来获得安全感，例如：

- `view`
- `reshape`
- `transpose`
- `permute`
- `matmul`

这些函数当然要学，但如果你没有张量直觉，记住 API 也帮不了你太多。

因为真正困难的从来不是“函数名是什么”，而是：

- 你为什么现在要换形状
- 你换完之后每一维代表什么
- 你这一步是不是把 batch、seq、hidden 的语义弄乱了

所以学习顺序应该是：

1. 先建立维度语义  
2. 再学习如何用 API 操作这些维度

而不是反过来。

## 第十四件事：从 0 开始学习时，最值得反复练习的三个形状问题

你可以反复问自己下面三个问题。

### 问题 1

这个张量的每一维在表示什么？

### 问题 2

这一层是在保留 batch 和 seq，只改最后一维，还是在重排维度结构？

### 问题 3

如果这一步错了，最可能错在哪个维度的语义上？

只要你长期坚持这样看代码，后面遇到更复杂的 attention 和 block 结构时，都会稳很多。

## 第十五件事：初学者最容易误解的几点

### 误区 1：tensor 很高级，所以先不用试图完全理解

不对。你后面几乎所有代码都在操作 tensor，越早建立直觉越重要。

### 误区 2：三维张量很复杂

未必。很多时候它只是“很多样本、很多位置、很多维特征”自然叠出来的。

### 误区 3：只要 `shape` 数字对，就一定没问题

也不对。数字对不代表语义一定对。维度含义错了，代码照样可能继续运行。

### 误区 4：embedding 是神秘特征提取器

对初学阶段来说，更准确的理解是“查表得到向量表示”。

### 误区 5：线性层会全面改变整个张量结构

通常不是。大多数情况下它只在最后一维上做投影。

> **这一章真正要你练出来的能力**
>
>   你不需要一开始就会推导复杂公式，但你必须学会把 shape 看成一门语言：看到张量时，能说出每一维的语义；看到变换时，能说出它到底改了哪一维、为什么改。后面很多模型代码是否可读，几乎取决于你这一步有没有站稳。

## 练习题

1. 为什么 `input_ids` 通常是二维，而 embedding 后的隐藏状态通常是三维？
2. `hidden` 维度和 `vocab` 维度分别在表达什么？
3. 为什么大多数线性层可以理解成“只改最后一维”？
4. 如果某一层输出的最后一维不是你预期的词表大小，你最先该怀疑什么？
5. 为什么“形状数字正确”并不自动等于“语义正确”？

下一章会把这些张量对象真正放进训练闭环中，也就是：

到那里你会第一次看到，这些 shape 不只是“存在于模型里”，而是在一整条学习链中不断流动和改变。
