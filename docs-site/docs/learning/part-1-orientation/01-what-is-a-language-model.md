# 01. 什么是语言模型

如果这本知识档案要真正成为一本能带着初学者走到语言模型内部的书，那么第一章就不能只做一种礼节性的开场白。

它必须先做一件更基础、也更严格的工作：

> 把“语言模型”这个词重新说准。

很多人第一次接触大模型时，先看到的是现象：

- 它会聊天
- 它会写文章
- 它会翻译
- 它会做总结
- 它会解释代码

这些说法并不假。问题在于，它们都属于结果层的描述，而不是任务层的定义。

结果层的描述只能告诉你这个系统看上去像什么，不能告诉你它在计算意义上究竟在做什么。一旦起点就停在这里，后面大量关键概念都会被读歪：

- 为什么训练目标会落成预测下一个 token
- 为什么模型输出是一整排 logits，而不是一句现成答案
- 为什么推理是一 token 一 token 地往后走
- 为什么同一个 prompt 可以生成多种不同文本
- 为什么模型会表现出知识性，却又会一本正经地产生幻觉

所以这一章的目标不是介绍一个“很厉害的文本系统”，而是先替整套书定下一条更稳的坐标轴：

> 语言模型首先是一个在给定上下文条件下，为下一个离散符号分配概率的模型；它的各种表面能力，都是这个底层任务不断滚动展开后的外在表现。

后面你看到的 tokenizer、embedding、attention、softmax、cross-entropy、sampling，本质上都在围绕这句话展开。

## 从“会说话”到“会建模”：为什么第一定义不能从对话开始

如果你第一次使用的是聊天界面，那么很自然会把语言模型理解成一种问答机器。你输入一句话，它回一句话；你继续追问，它继续回答。表面上看，这像一个在和人对话的系统。

但真正的学习不能只停在界面。

从系统内部看，对话并不是一个独立存在的新物种。它只是某种底层建模方式，在特定上下文格式下的一个外在形态。更准确地说，当你看到“模型在对话”时，系统内部通常在做的是下面这件事：

1. 把你当前输入的内容和之前的对话历史拼成一段长的上下文。
2. 把这段上下文切成一串 token。
3. 根据这串 token，预测下一个位置最可能出现什么 token。
4. 从候选 token 中选出一个。
5. 把它接回上下文末尾，再继续预测下一步。

换句话说，聊天只是“不断预测下一步”这个底层机制的一种可见表现。写作、摘要、翻译、代码补全，本质上也都可以被重新写成同一类动作：给系统一段前缀，然后让它继续往后生成。

这就是为什么如果第一章把语言模型直接定义成“会聊天的模型”，后面很多结构就会显得像为了聊天临时搭出来的小技巧；但如果你先把它看成“序列条件概率模型”，那么聊天、写作、翻译这些能力就会重新回到同一条主线上。

## 为什么“语言”必须先被改写成序列

人类日常使用语言时，最先感受到的是意义、语气、句法、主题、修辞和上下文氛围。我们不会把一句话首先看成一串离散符号。对机器来说却恰好相反。

只要你想让机器处理语言，你就必须先完成一个更基础的翻译：

> 把原本连续、含混、富有语义阴影的人类文本，改写成一个有顺序的离散序列对象。

这里最关键的是“有顺序”和“离散”这两个词。

“离散”意味着模型看到的不是不可分割的一整段意义流，而是一个个可枚举的基本单位。这个单位未必等于“词”，它可能是字符、子词片段、标点、空格模式或特殊控制符，但它必须是可以被列举、索引和计数的。

“有顺序”意味着同样一批单位，只要排列次序不同，整体含义就可能完全不同。`春天 来了` 与 `来了 春天` 包含的元素一样，但顺序一变，句子就不再相同。这说明语言模型要面对的对象不是“词的集合”，而是“带顺序的符号流”。

一旦这件事成立，后面很多看起来复杂的结构都会开始变得自然：

- 为什么样本里会有序列长度这个维度
- 为什么模型必须显式或隐式知道位置信息
- 为什么训练目标不是“理解整段文本”，而是“在前缀条件下预测下一步”
- 为什么推理会变成不断延长同一条前缀序列

如果这一层不先立住，后面你会不断误把语言模型想成某种在“整体句意”上直接运算的系统；而那种理解方式会让几乎每一个底层模块都失去位置。

## 语言模型到底在建模什么

现在可以把讨论推进到更严格的一步。

很多人会说，语言模型在“学习文本”。这句话听上去没问题，但还是太粗。真正准确的问题不是“它学不学文本”，而是“它学文本中的什么关系”。

更稳的说法应该是：

> 语言模型学习的是，在已经观察到一段前文的条件下，哪些后续 token 更可能出现，哪些不那么可能出现。

这句话比“会生成文本”更重要，因为它把建模对象从“结果”转回了“规律”。

如果模型只是保存一堆完整句子，它当然也可以在某些情况下复现文本，但那不是现代语言模型的关键。现代语言模型真正吸收的是文本分布中的结构：

- 局部搭配规律
- 句法延续模式
- 叙述风格习惯
- 指令与回复之间的统计关系
- 语义主题在较长上下文中的延展倾向

因此，语言模型不是在“背诵一份文本档案馆”，而是在把大量分布规律压进参数里。它看到的是海量前缀和后续之间的对应关系，最终学会的是：在这样的前文下，后面更像会出现什么。

这也是为什么一个模型可以生成从未在训练语料中逐字出现过的新句子。因为它学的不是原句目录，而是生成原句的统计结构。

## 什么叫条件概率，为什么它是语言模型的母语

如果把前面的定义再写得正式一点，我们就会得到语言模型最经典的形式：

\[
P(t_{k+1} \mid t_1, t_2, \dots, t_k)
\]

这里的 \(t_1, t_2, \dots, t_k\) 表示已经出现的 token 序列，而 \(t_{k+1}\) 表示下一个位置的 token。

这条式子读起来可以非常朴素：

> 在我已经看见前面这些 token 的条件下，下一个位置上各个候选 token 分别有多大可能出现？

这就是条件概率的最实用理解。

它之所以重要，是因为自然语言本来就不是一个确定系统。面对同一个前缀，后面往往不止一种合理延续。

例如前缀：

```text
今天 天气 很
```

后面可能是：

- 好
- 冷
- 热
- 不错

这些候选并不是“一个真、其他全错”的关系，而是“都可能成立，但概率不同”。这就决定了语言模型的底层任务不可能是输出一个唯一正确答案，它必须输出一整份关于候选后续的概率结构。

这件事会一路影响后面整本书：

- 因为要输出概率结构，模型最终层不会只给一个答案词，而会给整个词表的分数。
- 因为候选不止一个，采样策略才会显著影响生成风格。
- 因为训练是让真实后续的概率变大，交叉熵和负对数概率才会进入损失定义。

如果你能把“语言模型的母语是条件概率”这句话先记住，后面很多看似分散的数学和工程设计就会更好理解。

## 为什么“只预测下一步”却足以生成整段文本

初学者最自然的疑问之一是：如果模型每次只猜下一个 token，它怎么能写出一整段文章，甚至是一篇结构完整的回答？

这个问题的答案建立在一个很重要的概率事实之上：一段长序列的整体概率，可以被拆成一串局部条件概率的连乘。

如果一段 token 序列是：

\[
t_1, t_2, t_3, \dots, t_n
\]

那么它的整体概率可以写成：

\[
P(t_1, t_2, \dots, t_n)
=
P(t_1)\cdot P(t_2 \mid t_1)\cdot P(t_3 \mid t_1,t_2)\cdots P(t_n \mid t_1,\dots,t_{n-1})
\]

你现在不需要记住“链式分解”这个术语，更重要的是理解它背后的直觉：

> 一整段文本并不是必须整体一次性决定出来；它可以被拆成一系列“在已有前缀下做下一步决策”的局部动作。

因此，一个会做

\[
P(t_{k+1} \mid t_1,\dots,t_k)
\]

的模型，只要不断把自己刚生成的 token 接回上下文，就可以逐步把局部能力滚动成整段输出。

这也是自回归生成的本质。它不是“模型突然学会了写长文”的神秘跃迁，而是“局部下一步预测能力”在时间轴上的连续展开。

### 一个直观的生成例子

假设当前前缀是：

```text
风 从 操场 那边 吹 过来
```

模型在这个位置上可能认为以下几个 token 的概率比较高：

- `，`
- `了`
- `时`

如果系统根据当前解码策略选中了 `，`，新的上下文就变成：

```text
风 从 操场 那边 吹 过来 ，
```

然后模型再以这个更长的前缀为条件，重新分配下一步 token 的概率。就这样一步步向后滚动，文本被慢慢长出来。

因此，语言模型不是先在脑中写好一整篇文章再一次性交给你，而是在每一步都根据当前可见前缀重新做局部概率判断。整段文本只是这一串局部判断在时间上的连锁结果。

## 为什么“上下文”这个词其实是核心中的核心

很多人第一次接触语言模型时，会把“上下文”理解成一种背景说明，像是写在题目下面的附加条件。但在语言模型里，上下文不是附属材料，它就是条件项本身。

这件事值得说得非常重：

> 没有上下文，就没有被约束的下一步分布；上下文不是背景，而是模型当前推理位置的输入主体。

这也是为什么同一个问题换一种前缀方式，模型表现会显著变化。你可以把模型理解成一个持续响应上下文变化的分布生成器。前缀一变，下一个 token 的概率结构就跟着变。

比如：

```text
请 用 正式 的 语气 解释
```

和：

```text
请 用 轻松 的 语气 解释
```

这两段前缀只差了几个 token，但模型后续的高概率词分布可能会完全不同。前者会更偏向规整、抽象、书面化的延续，后者则更可能走向口语、比喻和轻松表达。

这件事往后会不断出现，只是名字不同：

- prompt
- system prompt
- conversation history
- few-shot examples
- instruction template

这些东西在更高层接口上看起来很不一样，但本质都在做同一件事：修改模型此刻可见的上下文，于是修改下一步 token 的条件分布。

## 为什么模型看到的通常不是“词”，而是 token

到这里我们还需要再向下走一层现实感。

人类谈语言时，天然会先谈词、短语、句子和段落。但现代语言模型内部真正直接面对的最小离散单位，通常不是这些自然语言对象本身，而是 token。

token 可能是：

- 一个字
- 一个字符
- 一个完整单词
- 一个子词片段
- 一个标点
- 一个特殊控制符

也就是说，当我们说“预测下一个 token”时，这里的 token 绝不是一个可以轻描淡写跳过的术语。它决定了：

- 模型输入空间怎样被切分
- 词表规模有多大
- 序列长度会增长到什么程度
- 一个位置上究竟在预测什么样的基本单位

为什么不直接用“词”来定义？因为真实世界里的语言并不配合我们把“词”当成唯一稳定单位。

例如：

- 英文里的空格边界并不适合所有语言
- 中文原本没有天然空格
- 稀有词和新词会迅速让整词词表爆炸
- 数字、符号、专有名词和拼写变体经常让“整词单位”不够灵活

所以现实中的做法更常是：找一种更灵活的离散切分方式，让文本既能保持可操作性，又不会让词表规模失控。这就是 tokenizer 后面会承担的工作。

这一章你只需要先建立一个稳定事实：

> 语言模型不是直接在“句意”上做运算，它首先是在 token 序列上做建模。

## 模型到底输出什么：答案，还是分布？

如果你只从聊天界面看模型，会很容易以为它“输出了一句话”。但这是人类界面层的结果，不是模型内部的第一输出。

从内部看，模型在一个位置上通常先输出的是：

> 针对整个词表里每个候选 token 的一组分数。

这组分数通常被叫做 logits。它们还不是概率，但表达了模型对各个候选 token 的相对偏好。后面通过 softmax，这些分数才会被转换成一个概率分布。

这一步很重要，因为它告诉我们一件事：模型并不是在每一时刻“直接想到了正确答案词”，而是在为所有候选后续分配偏好权重。真正的输出 token，还要再经过一层解码选择。

因此，模型和采样器在职责上其实是分开的：

- 模型负责给出候选后续的分布信息。
- 解码策略负责根据分布信息选出最终 token。

这也是为什么同一个模型在不同采样设置下，可以表现出非常不同的文本风格。模型本体没变，变的是“如何从分布里选词”的策略。

## 为什么语言模型既可以稳定，又可以多样

很多初学者第一次看到同一个 prompt 能生成多种不同答案时，会把这种现象理解成“模型不稳定”。这其实只说对了一半。

模型确实不是一个确定性公式，它不是输入同一句话就必须逐字吐出同一句回答。但它也不是完全随机的。真正发生的是：

- 分布中通常有少数高概率候选，保证整体结构不会完全失控。
- 同时分布中又常常存在多个都合理的后续，于是不同采样选择会保留一定多样性。
- 一旦早期某一步选项发生差异，后续上下文也会跟着改变，于是整段生成会逐渐分叉。

这说明语言模型的生成行为既有结构稳定性，也有概率系统天然带来的不唯一性。它稳定的不是“逐字结果”，而是“在很多局部条件下的高概率延续模式”；它多样的则是“同一条件下不只存在一种可接受后续”。

从学习角度看，这恰好说明我们真的在处理一个分布系统，而不是一个唯一答案系统。

## 为什么“下一个 token 预测”并不是低级补字游戏

初学者对语言模型最常见的轻视，往往来自一句听起来很合理的话：

> 原来它只是预测下一个 token，那不就是高级一点的自动补全吗？

这句话的问题不在形式，而在对信息量的严重低估。

“下一步”只是形式局部，并不意味着所需信息也局部。很多时候，为了合理预测一个位置上的 token，模型必须隐含地利用整个前缀中的多层结构：

- 句法是否闭合
- 指代对象是谁
- 当前说话风格是什么
- 用户指令要求了什么格式
- 前文主题延续到了哪里
- 某个名词与前面哪些信息存在长距离约束

也就是说，语言模型表面上是在做“一个位置”的判断，但这个判断往往被很长的一段上下文共同约束。任务形式局部，信息需求却可能极其全局。

这也是为什么一个统一的“next-token prediction”目标，在规模足够、数据足够、模型足够的情况下，能够支撑出这么多表面上差异巨大的能力。

## 语言模型是不是在背句子

这是另一个必须尽早拆开的误解。

很多人会说，模型看过海量文本，所以它本质上只是记住了很多句子。这个说法有一部分直觉来源，但它不够准确，甚至会直接误导后续理解。

如果模型真的只是逐句存档，那么面对训练语料中没出现过的完整表达，它应该几乎无能为力。但现实里，我们不断看到模型能生成大量未曾逐字出现过的新句子、新段落和新组合。

这说明真正支撑泛化能力的，不是原句检索，而是：

> 对大量语言分布规律的参数化吸收。

模型可能学到：

- 某种时间状语和天气叙述如何搭配
- 某类解释任务常用什么句法组织
- 某种文学描写常如何展开比喻
- 指令和答复之间最常见的结构关系

当这些模式被压进参数后，模型就有能力在从未见过的完整句子上重新组合它们。

### “不是背句子”不等于“完全没有记忆”

这里也需要防止走向另一个极端。说模型不是句子数据库，不代表模型完全不会发生记忆现象。现实中模型确实可能：

- 记住高频模板
- 复现某些非常独特的固定表达
- 在特定条件下泄露训练片段

但这些记忆现象不是它全部能力的解释，更不是它最核心的能力来源。更准确的理解应该是：

> 模型既会发生局部记忆，也会在更大范围内学习统计结构；真正支撑泛化的，是后者。

## 为什么模型能在没见过的句子上工作

理解了上一节，这个问题就顺下来了。

假设模型从未见过一句完整的话：

```text
午后 的 雨 停 了 以后 ， 教室 玻璃 上 的 水痕 像 被 风 重新 排过。
```

它仍然可能生成类似句子。原因不是它事先见过这句原文，而是它可能已经在别处学到：

- “午后”“雨停以后”这类时间和天气关系
- “玻璃”“水痕”“风”之间的共现场景
- 汉语描写句的节奏和修辞组织方式

于是，虽然完整句子从未出现过，组成句子的规律却早已被模型学过。这就是泛化最直观的样子：不是复制旧句，而是按已学规律生成新组合。

## 语言模型是在“理解”吗

这是一个很容易陷入空泛争论的问题。对初学者而言，最有帮助的不是急着给出哲学裁决，而是先稳住两个判断。

第一个判断是：不要轻易把语言模型神化成“和人一样理解世界的主体”。它没有人类那样的身体经验、感官闭环和长期行动结构，所以不能简单把它的表现直接等同于人类理解。

第二个判断是：也不要把它贬成“只是随机词拼接”。如果它真的只是随机拼接，就不可能长期保持语法、风格、格式和任务要求上的稳定结构。

更稳妥的说法应该是：

> 语言模型首先是一个在文本分布上训练出来的统计系统，它既不等于人类式理解，也绝不只是无结构的随机胡编。

这个判断在当前阶段已经足够好，因为它既能防止神化，也能防止轻视。

## 语言模型为什么会表现出知识性，又为什么会出现幻觉

很多初学者会在真正使用模型后经历一种矛盾感：它明明知道很多事情，为什么又会有时非常自信地说错？

这个矛盾只有放回训练目标里才看得清。

语言模型的训练目标并不是建立一个显式、带来源、可核验的事实数据库。它学的是：在什么文本前缀下，什么样的后续更可能出现。因此，大量人类知识如果已经沉积在文本中，模型自然会吸收出很强的知识性。

它会学到：

- 常见事实共现
- 领域术语关系
- 问题与答案的典型表达
- 解释和论述的通用结构

但与此同时，它并没有天然拥有“逐条外部查证”机制。它追求的是高概率、形式合理、上下文连贯的后续，而不保证每一步都经过独立真值校验。这就留下了幻觉空间。

因此，模型“知道很多”与模型“并不总可靠”不是互相矛盾的两件事。它们恰恰是同一训练目标下自然出现的两面：

- 文本分布中沉积了大量知识，于是模型显得很有知识性。
- 训练目标不是事实验证，于是模型可能在缺乏真值保证时生成似是而非的内容。

## 为什么同一个底层系统能统一对话、摘要、翻译和补全

到这里可以回看最开始那个现象层问题：既然语言模型底层只是条件概率建模，它为什么能支撑这么多不同应用？

答案在于，这些应用虽然表面形式不同，但都可以被改写成“给定某种前缀，继续生成合理后续”的问题。

对话时，你把历史轮次和新问题写进前缀里，模型继续生成下一轮回复。

摘要时，你把原文和“请总结”的指令写进前缀里，模型继续生成更短、更压缩的后续文本。

翻译时，你把源语言文本和目标语言要求写进前缀里，模型继续生成目标语言序列。

代码补全时，你把已有代码写进前缀里，模型继续生成后续代码 token。

这些表面差异巨大的任务，在底层上都变成了：

> 修改前缀条件，然后继续做下一步 token 分布估计。

这就是为什么现代大语言模型可以用一种相对统一的训练主线覆盖如此多的应用形态。

## 为什么我们在本项目里聚焦 decoder-only 语言模型

后面你会接触到很多名字：自回归模型、decoder-only、encoder-decoder、masked language model。它们都属于更大的语言建模世界，但这套知识档案的主线会先聚焦一种最适合从零理解的结构：

> 给定前缀，持续预测下一步 token 的 decoder-only 自回归模型。

原因并不复杂。因为这一主线最直接对应我们刚刚建立的任务定义：

\[
P(t_{k+1} \mid t_1, \dots, t_k)
\]

也就是说，这一章不是在给出所有语言模型范式的总百科，而是在先替本书接下来的主要路线校准坐标。只要这个坐标先站稳，后面再看其他变体时，你也会更容易知道它们究竟改动了哪里。

## 为什么训练阶段和使用阶段看起来不一样

很多初学者第一次真正进入实现细节时，会觉得这里有个奇怪的断裂：训练时模型像在批量处理很多样本，推理时模型却像在一步一步写作。为什么两种形态差别这么大？

答案是：它们执行的是同一个底层任务，只是运行方式不同。

训练时，我们希望模型在大量真实前缀上都学会给真实下一步更高概率，所以会把很多位置同时拿出来做监督学习。这看起来像批量训练。

推理时，我们不再知道真实下一步是什么，而是让模型自己根据当前前缀给出分布，再由解码策略选出一个 token，接着继续往后走。这看起来像滚动生成。

所以表面差异很大，底层却是一致的。训练是在教会模型“局部下一步应该怎么判断”，推理则是在不断调用这项局部能力，把它滚动展开成完整输出。

## 为什么这一章会决定后面整本书的顺序

现在你应该已经能看见，这章并不是背景介绍，而是整套书的任务源头。只要你接受“语言模型本质上是在给定上下文时估计下一个 token 的条件分布”，后面的学习顺序几乎会被这个定义强行推出来。

因为对象是文本序列，所以我们必须先解决：

- 文本编码
- 分词
- token 边界
- 训练样本如何从连续 token 流中切出来

因为 token 必须变成可计算表示，所以我们必须进入：

- 向量
- embedding
- 隐藏状态
- 表示空间

因为模型要在前缀条件下读取上下文，所以我们必须理解：

- 序列依赖
- 注意力机制
- 因果 mask
- 位置方法

因为模型要输出一整份分布，所以我们必须理解：

- logits
- softmax
- 交叉熵
- 对数概率

因为模型最终要连续生成，所以我们还必须进入：

- 自回归推理
- sampling
- 停止条件
- KV cache

也就是说，第一章讲清楚了什么是语言模型，后面整套学习地图才真正有了起点。

## 这一章最后应该留下什么

如果读完这一章，你脑中只留下“它会聊天、会写作”，那是不够的。更稳的收获应该是下面这条总定义：

> 语言模型不是简单的文本生成器，而是在给定上下文时，对下一个 token 的条件分布做估计，并把这一局部预测能力不断滚动展开成完整序列输出的模型。

这句话里几乎已经埋下了整本书的关键词：

- 上下文
- token
- 条件分布
- 下一步预测
- 滚动生成

只要这几个词真的站稳，后面你再进入 tokenizer、embedding、attention、loss、sampling 时，就不会觉得它们是散乱的零件，而会知道它们都在服务同一台机器。

## 本章读完后你应该能稳定回答的问题

在进入下一章之前，请确认自己至少能用自己的话回答下面这些问题：

1. 为什么“会聊天、会写作”只是现象描述，而不是语言模型的底层定义？
2. 什么叫“给定前缀预测下一个 token 的条件分布”？
3. 为什么“只预测下一步”仍然能生成长段文本？
4. 为什么语言模型面对的基本对象是 token 序列，而不是直接的“句意整体”？
5. 为什么模型先输出的是分布相关分数，而不是一个现成答案词？
6. 为什么模型既会表现出知识性，又会产生幻觉？
7. 为什么对话、摘要、翻译和代码补全可以在同一底层框架里被统一？

如果这些问题里有任何一个你现在仍然说不顺，那么不要急着往后翻。因为这章不是暖场，而是后面整条主线的任务坐标系。
