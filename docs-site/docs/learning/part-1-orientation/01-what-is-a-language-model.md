# 01. 什么是语言模型

## 先纠正一句最常见但不够准确的话

很多人第一次接触大语言模型时，最容易听到的描述是：

> 它会写文章、会聊天、会回答问题。

这句话不能说错，但它只是现象描述，不是任务定义。

如果你只停留在这个层面，那么后面一切真正重要的概念都会变得模糊：

- 为什么训练目标是预测下一个 token
- 为什么会有 logits 和 softmax
- 为什么模型生成出来的话有时合理、有时跑偏
- 为什么它明明“没见过这句话”，却还能生成类似风格的内容

因此，我们必须先把语言模型的定义讲准确。

## 更准确的定义：语言模型在估计条件分布

从最本质的角度看，一个语言模型在做的事情是：

> 给定前文，估计后续 token 的概率分布。

如果把一句文本写成一串 token：

\[
t_1, t_2, t_3, \dots, t_n
\]

那么语言模型做的是不断估计：

\[
P(t_{k+1} \mid t_1, t_2, \dots, t_k)
\]

也就是说：

> 当前已经看到前面的内容时，下一个位置最可能出现哪些 token？

这一定义非常重要。因为它告诉你，语言模型最底层并不是“在理解整段话的哲学意义”，而是在做一连串条件概率判断。

## 为什么“预测下一个 token”会表现成会聊天、会写作

很多初学者会立刻产生疑问：

> 只做下一个 token 预测，怎么会长成一个能写长文、能对话的系统？

关键在于，这个预测过程是可以连续滚动进行的。

模型先根据当前上下文预测下一个 token：

```text
今天 天气 很
```

它可能给出：

- 好
- 冷
- 热
- 不错

之类候选。

一旦选出一个 token，例如“好”，新的上下文就变成：

```text
今天 天气 很 好
```

然后模型再继续预测下一步。

这件事不断重复，就形成了整段文本。

所以所谓“生成一段话”，本质上并不是模型一口气写出全文，而是：

> 它把整段输出拆成一个又一个条件分布决策，然后把这些决策接起来。

## 语言模型看到的不是词，而是 token

这里还需要立刻补一层现实感。

你看到的是：

- 字
- 词
- 句子
- 段落

但模型内部真正直接处理的通常不是这些自然语言单位本身，而是 token。

token 可能是：

- 单个字符
- 整个词
- 子词片段
- 标点或控制符

不同 tokenizer 会把同一段文本切成不同 token 序列。

因此当我们说“预测下一个 token”时，那个“token”不是一个随手可换的小名词，而是模型输入输出空间的真实基本单位。

## 语言模型不是在背句子

另一种常见误解是：

> 模型训练就是把海量文本背下来。

为什么这句话不够准确？

因为如果只是背句子，它最多做到：

- 见过的句子会复现
- 没见过的句子就不会处理

但现实中的语言模型显然不只是这样。它经常会：

- 生成训练集中没有逐字出现过的新句子
- 在不同上下文里灵活调整表达
- 组合出新的结构与内容

这说明它学到的不是单纯的原句存档，而是某种更抽象的统计结构。

更准确的说法应该是：

> 模型通过大量文本，学习“在什么上下文里，什么 token 更可能出现”的统计规律。

这并不意味着它像人一样理解世界，但它也绝不是一个简单的文本查重机。

## 语言模型为什么能在“没见过的句子”上工作

要理解这点，最有帮助的想法是：

> 模型学的是分布，不是句子列表。

假设你从未见过下面这句话：

```text
雨停之后，操场边的银杏叶像刚刚被擦亮。
```

但如果你看过足够多中文文本，你大致知道：

- “雨停之后”后面常会接场景描述
- “银杏叶”常和颜色、季节、地面、风景搭配
- “像刚刚被擦亮”是符合汉语修辞习惯的表达

语言模型做的事与此类似，只不过它不是靠人类直觉，而是靠参数化统计学习。

它并不需要见过每一个完整句子，只要它足够稳定地学到了局部和全局模式，就能在新上下文里给出合理延续。

## 语言模型输出的首先不是文字，而是分数

对人类来说，模型“说了一句话”。

但从模型内部看，它先做的事情不是吐出文字，而是对词表中的所有候选项给出一组分数，也就是 logits。

这些分数可以理解成：

> 在当前位置条件下，模型对各候选 token 的相对偏好。

之后再经过：

- softmax
- greedy 选择
- 或采样策略

才会真正落成某一个 token。

所以：

- 模型本身主要负责给出分布
- 解码策略负责从分布里做选择

这也是为什么同一个模型换不同采样策略，表现会像换了一个“性格”。

## 会聊天、会写作、会补全，本质上是同一个任务的不同界面

你可能已经注意到，许多表面不同的功能其实都能被统一进“条件下一个 token 分布”这个框架：

### 文本补全

给定开头，让模型继续往后写。

### 问答

把问题写成 prompt，让模型继续生成回答。

### 对话

把前面的轮次拼进上下文，让模型预测下一轮 token。

### 摘要

给一段长文本和一条“请总结”的提示，让模型生成摘要文本。

它们表面上像不同功能，但模型底层依然是：

> 在当前上下文条件下，不断预测下一步。

所以你越早把这个统一视角建立起来，后面越不容易被“应用表象”带偏。

## 语言模型知道“事实”吗

这是必须正视的问题。

如果模型能回答很多问题，人们自然会问：

> 它到底是在知道事实，还是只是在模仿语言表面？

对初学者来说，一个稳妥的理解方式是：

> 语言模型首先学到的是语言分布和与语言共同出现的大量世界模式，而不是以数据库形式存放一份精确世界真值表。

这会带来两个结果：

### 第一，它确实能表现出相当强的知识性

因为大量世界知识本来就被编码在文本里。

### 第二，它也会犯“看起来很自信但其实不对”的错误

因为它的训练目标从来不是：

> 对每个事实做带来源校验的真值判定。

而是：

> 在当前上下文里给出高概率的语言延续。

这就是为什么语言模型可以很聪明，同时也会幻觉。

## 语言模型和“真正理解”之间是什么关系

这是一个很大也很容易跑偏的话题。对于当前学习目标，更有用的是保持两个判断同时成立：

### 判断 1：不要把它神化成人类式理解

它不是人，也不是像人那样通过身体经验和行动闭环理解世界。

### 判断 2：也不要把它贬成“只是随机胡编”

它的能力来自对大规模语言统计结构的稳定学习，因此会在很多任务上表现出很强的结构性。

学习语言模型时，最重要的不是先给它下哲学定义，而是先搞清楚：

> 训练目标、输入表示、模型结构和生成机制怎样共同导致了这些行为。

## 为什么这个定义会决定后面整套知识的顺序

一旦你承认语言模型本质上是在估计：

\[
P(t_{k+1} \mid t_1, \dots, t_k)
\]

那么后面所有知识都自然有了位置：

- 因为输入是文本，所以要解决 tokenizer
- 因为输入必须可计算，所以要有 embedding
- 因为要看长上下文，所以要有 Attention
- 因为要输出分布，所以会有 logits 和 softmax
- 因为要训练这个分布，所以会有 cross-entropy
- 因为要持续生成，所以会有自回归推理和采样

也就是说，“什么是语言模型”不是一章礼节性的开场白，它其实是整套书的总起点。

## 这一章真正要记住的核心句子

如果这一章最后你只记住一句话，那应该是：

> 语言模型的本质不是“会生成文本”，而是“在给定上下文时，对下一个 token 的条件分布做估计，并把这种局部分布决策不断滚动连接成完整文本”。

理解了这句话，后面的 tokenizer、loss、Attention、采样，都会开始变得顺理成章。

## 练习题

1. 为什么“会写文章、会聊天”只是语言模型的现象描述，而不是任务定义？
2. 什么叫“给定前文预测下一个 token 的条件分布”？
3. 为什么语言模型并不是简单地把训练语料逐句背下来？
4. 为什么同一个模型换不同采样策略，输出会明显不同？
5. 语言模型为什么既能表现出知识性，又会出现幻觉？
