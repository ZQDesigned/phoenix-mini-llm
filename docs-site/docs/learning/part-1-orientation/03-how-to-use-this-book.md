# 03. 怎样使用这套知识档案

## 这不是词典，也不是项目 README

如果你把这套文档当成词典来查，效果会很差。

原因很简单。语言模型相关知识并不是一组彼此独立的名词，它们是有严格依赖顺序的。

例如，你如果还没理解：

- 什么叫条件概率
- 什么叫表示空间
- 什么叫损失函数

那么你即使勉强记住了：

- Attention
- logits
- cross-entropy

也很难真正知道它们在模型里为什么存在。

所以这套知识档案最合理的使用方式，不是“哪里不会查哪里”，而是：

> 先按主路线顺序阅读，再在复刻过程中回查对应章节。

## 阅读时最该建立的不是“记住”，而是“关系”

技术学习里一个很常见的误区是把目标设成：

> 我要把这些概念都记住。

单纯记住术语并不会自动变成理解。真正更重要的是概念之间的关系：

- token 和词表是什么关系
- embedding 和 hidden state 是怎样衔接的
- logits、softmax 和交叉熵之间是什么关系
- Attention、位置方法和 causal mask 共同定义了什么
- 训练、推理和评估为什么是一条连续链路

你在阅读时应该持续问自己：

> 这个概念是为了解决什么问题？它出现在整条链的什么位置？它依赖前面的哪层知识？

只要这个问题一直在脑子里，阅读就会更接近真正学习，而不是术语堆积。

## 最推荐的阅读顺序

### 第一遍：完整走主线

第一遍不要过度跳读，直接按分册顺序往下走：

1. 入门与学习地图  
2. 数学与神经网络基础  
3. 文本为什么能变成训练数据  
4. Transformer 与语言模型主体  
5. 训练一个小型语言模型  
6. 推理、评估与调试  

这一遍的目标不是把所有细节都吃透，而是先形成一张稳定地图。

### 第二遍：结合复刻教程阅读

当你开始进入复刻教程后，阅读方式会改变。你会更自然地在这些时刻回查：

- 实现 tokenizer 时，回到文本与 token 分册
- 实现模型时，回到 Transformer 分册
- 写训练器时，回到训练分册
- 调采样时，回到推理分册
- 排查异常时，回到评估与调试分册

这时同一章节会比第一次阅读更容易真正变成你的东西，因为你已经有了项目上下文。

## 什么时候应该停下来，不继续往后赶

初学者最常见的问题之一，是太急着进入“后面更酷的部分”。

例如：

- 还没弄懂损失函数，就急着看 Attention
- 还没弄懂张量形状，就急着拼模型
- 还没弄懂训练和推理的区别，就急着调 sampling

更好的判断标准不是“我是不是已经读到后面了”，而是：

> 我能不能用自己的话解释这一层知识为什么存在？

如果还不能，就应该停下来回看，而不是赶进度。

## 这套文档和复刻教程的边界

你需要非常清楚两者不是同一种东西。

### 学习主线

职责是讲：

- 为什么有这个概念
- 这个概念解决什么问题
- 它和前后知识怎么衔接

### 复刻教程

职责是讲：

- 按什么顺序建项目
- 哪些文件怎么写
- 哪些命令怎么跑
- 每个阶段怎么验证

如果你把学习主线当成教程，就会觉得它“不够直接”。

如果你把教程当成学习主线，就会发现自己“能抄出来，但解释不清楚”。

这两条线需要配合，而不是互相替代。

## 怎样判断自己是真的理解了

一个很实用的标准是看你能不能做到以下三件事。

### 第一，能解释

不是重复原文，而是能用自己的话说明：

- 这个概念是什么
- 解决什么问题
- 为什么不能少

### 第二，能预测

例如在学完某个概念后，你大致能猜到：

- 如果 mask 错了会怎样
- 如果 tokenizer 不一致会怎样
- 如果学习率过大可能发生什么

这说明你开始形成因果判断了。

### 第三，能迁移

换一个项目、换一个文件结构、换一个命名方式，你仍然能看出：

- 哪一部分在做 embedding
- 哪一部分在做 block
- 哪一部分在做 loss

这说明你掌握的是通用结构，而不是只记住了当前仓库的样子。

## 阅读时最值得做的事：自己写解释

如果你想真正把这套知识变成自己的，最有效的方法之一是：

> 每读完一个主题，尝试不用看原文，自己写一小段解释。

例如：

- 什么是 logits
- 为什么 next-token prediction 要右移一位
- 为什么 causal mask 不能错
- 为什么一个小模型更适合学习

只要你一写，就会立刻暴露自己到底是“看懂了”，还是“看着像懂了”。

## 这一章真正要记住的核心句子

如果这一章只记一句话，那应该是：

> 这套知识档案最有效的使用方式，是先按顺序建立整张地图，再在复刻与调试过程中带着问题回查；目标不是背术语，而是形成概念之间的因果关系。
