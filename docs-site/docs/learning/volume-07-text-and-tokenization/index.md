# 卷七 文本怎样进入模型：语料、编码与分词

> 本卷属于第三编“文本、分词与语言建模”，负责先把自然语言改写成机器可以编码、切分、统计和监督的离散对象。

走到这里，读者通常已经稳住了两件大事：

- 机器学习问题怎样被定义
- 神经网络怎样通过损失、梯度和优化逐步学习

但你还没有真正进入语言模型最独特的一层。

因为到目前为止，你学到的大多还是“通用学习系统”的语言。

而语言模型之所以特殊，不只是因为它最后会生成文本。
更根本的原因在于：

> 它从一开始就必须把自然语言重写成一套机器可以切分、存储、比较、统计和监督的离散对象体系。

这正是本卷的任务。

## 为什么文本问题不能被缩成“预处理”

很多资料会把这一层叫作“数据预处理”。

这个说法不算错，但太弱了。

因为它很容易让初学者误会成：

- 只是训练前顺手清理一下数据
- 只是为了兼容库接口
- 只是工程同学负责的外围部分

在语言模型里，这一层远不止如此。

它至少在做四件根本的事：

1. 定义模型能够看见什么单位。
2. 定义序列怎样被切开和组织。
3. 定义后面概率到底在哪些离散单位上展开。
4. 定义训练代价会沿着什么边界增长。

所以这不是外围工作。

它实际上在决定：

> 语言模型从第一步开始，到底是在对什么东西建模。

## 为什么这一卷必须和“语言建模目标”拆开

旧写法最容易把下面这些内容糊在一起：

- 语料从哪里来
- 文本怎样编码
- token 怎样切分
- 样本怎样打包
- 为什么目标是右移一位

它们当然彼此相关，但并不属于同一层。

更稳的顺序应该是：

1. 先把文本变成稳定、可操作的离散对象。
2. 再讨论这些对象怎样被组织成序列预测问题。

所以本卷只专注于第一步：

> 机器怎样获得“能被拿来建模的文本单位”。

下一卷再继续回答：

> 当这些单位已经存在之后，语言模型为什么会自然长成条件概率预测问题。

## 这一卷到底在建立什么认识

读完本卷，你应该逐步建立一个越来越稳的判断：

### 第一，机器并不直接处理“自然语言意义”

机器首先处理的是：

- 字节
- 码点
- 规范化后的文本表示
- token 边界
- token id

这意味着人类平时说的“词”“句子”“一段意思”，并不是机器天然拥有的单位。

### 第二，token 不是天生存在的，而是建模选择

对人类来说，词看起来很自然。

但在语言模型里：

- 用词做单位会遇到长尾问题
- 用字符做单位会让序列太长
- 用子词做单位是在词级压缩与字符级灵活性之间折中

所以 tokenization 不是字典查询，而是建模权衡。

### 第三，词表大小和切分粒度会反过来塑造后面的模型成本

词表越大，并不只意味着“认识的词更多”。

它还会影响：

- embedding 参数量
- 输出头参数量
- 未登录形式的处理方式
- 序列长度
- 训练和推理成本

### 第四，语料分布不是背景条件，而是学习对象的一部分

模型最终学到的，不是“语言本身”这个抽象整体。

它学到的是：

> 你喂给它的那类文本分布，在当前切分方式和当前训练目标下所呈现出的延续规律。

所以语料来源、清洗方式和分布偏向，本来就是模型能力边界的一部分。

## 为什么这卷对从零学习的人尤其关键

从零开始的读者最容易在这里低估难度。

原因很简单：

你每天都在读字、写字、说话，所以会本能地觉得：

- 文本本来就在那里
- 词也本来就在那里
- 模型只要“看懂”就行了

但机器没有这种天然语言直觉。

它不会直接看见：

- 词
- 句子
- 主题
- 语义连贯

它只能看见一条经过若干次重写之后的离散符号流。

本卷就是在把这条重写路径完整摊开。

## 本卷的四章分别在做什么

### 第一章：[01. 语料、样本与数据分布](/learning/volume-07-text-and-tokenization/01-corpora-samples-and-data-distribution.md)

这一章先回答语言模型最早的输入问题：

- 语料是什么
- 为什么“文本很多”不等于“数据就合适”
- 分布、覆盖、噪声和偏差为什么会直接影响模型后面学到什么

### 第二章：[02. Unicode、字节与文本规范化](/learning/volume-07-text-and-tokenization/02-unicode-bytes-and-text-normalization.md)

这一章把文本从“人类看见的字符”往下拆到底层表示：

- 文本为什么必须被编码
- 字节、字符、码点为什么不是一回事
- 规范化为什么会影响后续切分稳定性

### 第三章：[03. Token、词表与 special token](/learning/volume-07-text-and-tokenization/03-tokens-vocabularies-and-special-tokens.md)

这一章开始进入建模单位本身：

- token 是什么
- 词表在模型里扮演什么角色
- special token 为什么不是附加标记，而是协议的一部分

### 第四章：[04. 子词分词、BPE 与 tokenizer 训练](/learning/volume-07-text-and-tokenization/04-subword-tokenization-bpe-and-tokenizer-training.md)

这一章解释为什么现代 tokenizer 往往会落在子词层：

- 纯词级和纯字符级各自有什么代价
- 子词方案在折中什么
- BPE 怎样一步步长出常用片段
- tokenizer 训练实际上在优化什么边界

## 这一卷读完后，你应该怎样看待 tokenizer

读完本卷后，最重要的变化之一应该是：

> 你不再把 tokenizer 看成训练前顺手跑一下的小工具。

你会更自然地把它看成：

- 输入空间定义器
- 序列长度调控器
- 词表成本控制器
- 未登录形式处理器
- 后续建模行为的前置约束

这是一种很重要的视角转变。

因为只有这样，后面你在看样本窗口、next-token 目标、上下文长度和 attention 时，才会意识到它们并不是孤立设计。
