# 06. 语言模型训练目标

## 这一章要解决什么问题

到这里，你已经知道：

- 文本会被切成 token
- token 会被表示成张量
- 模型训练依赖前向、损失、反向和参数更新

但在这些环节中间，还卡着一个最关键的问题：

> 一段 token 序列，究竟怎样变成语言模型真正要学习的监督目标？

如果这一点没有完全讲清楚，后面就会出现一种非常危险的情况：

- 模型结构看起来对
- 训练循环也能跑
- loss 也有数值

但模型学到的任务根本不是你以为的那个任务。

这类问题尤其麻烦，因为它们经常不会直接让程序崩掉，而是会变成：

> 模型能训练，但越训练越像在学错东西。

所以这一章的目标，是把 next-token prediction 的任务定义从头讲透。

## 第一件事：语言模型训练不是在“一次性预测整句话”

这是最先要纠正的误解之一。

很多人会说：

> 语言模型根据前文生成一句完整的话。

这句话在直觉层面没有问题，但如果把它当成训练定义，就太模糊了。

### 更准确的说法是什么

语言模型训练的核心任务是：

> 在序列的每一个位置上，根据当前位置之前出现的 token，预测下一个 token 的分布。

注意它有两个特点：

1. 它发生在每一个位置上  
2. 它预测的是“下一个 token”，不是“整段结局”

所以如果一段序列是：

```text
A B C D
```

模型学到的不是“一次把 `D` 预测出来”，而是：

- 看到 `A`，学会预测 `B`
- 看到 `A B`，学会预测 `C`
- 看到 `A B C`，学会预测 `D`

整段语言能力，就是很多局部条件预测叠加起来的结果。

## 第二件事：为什么输入和目标通常是同一段序列的错位版本

假设你现在有一段 token 序列：

```text
[BOS, A, B, C, EOS]
```

训练时，最常见的做法是把它拆成：

- 输入：`[BOS, A, B, C]`
- 目标：`[A, B, C, EOS]`

### 为什么必须这样错开一位

因为模型每个位置真正要回答的问题都是：

- 如果我现在只看到 `BOS`，下一个应该是什么？
- 如果我现在看到 `BOS A`，下一个应该是什么？
- 如果我现在看到 `BOS A B`，下一个应该是什么？

也就是说，训练目标本质上总是在做：

> 用当前位置之前的内容，预测右边一位。

这也是为什么人们经常说：

> 语言模型的训练目标是“右移一位”的。

## 第三件事：为什么这不是随手切片，而是任务定义本身

很多初学者看到：

```python
input_ids = tokens[:-1]
targets = tokens[1:]
```

会把它理解成某种工程实现细节，好像只是一种方便写代码的方式。

其实不是。

### 这一步在定义什么

它在定义：

- 模型到底看到了什么
- 模型到底该为哪个位置负责
- 模型的错误到底怎样与真实答案对应

如果这一位错开关系错了，你训练的就不再是：

> 根据前文预测后文

而会悄悄变成别的任务。

所以“右移一位”不是技巧，而是语言模型训练任务的本体之一。

## 第四件事：teacher forcing 到底是什么

这是训练和推理差异里最关键、也最容易被一笔带过的概念之一。

### 它的基本含义

训练时，即使模型在某一位置预测错了，下一个位置继续训练时，输入仍然来自真实数据，而不是来自模型刚才的错误输出。

这就是 teacher forcing。

### 为什么这样做

因为训练阶段的目标，是让模型在真实上下文条件下学会预测规律。

如果你训练时就让模型不断吃自己刚才预测出来的错误 token，那么：

- 错误会在很早阶段迅速连锁放大
- 梯度信号会更混乱
- 训练会更难稳定

所以 teacher forcing 的本质可以理解成：

> 训练时先让模型在“正确上下文”里学会条件概率，再在推理阶段面对真正的自回归滚动。

## 第五件事：为什么训练时“低 loss”不自动等于推理时“输出好”

这正是 teacher forcing 带来的一个重要现实后果。

训练时，模型始终站在真实上下文上作答；推理时，它必须基于自己刚刚生成出来的 token 继续往后走。

这意味着：

- 训练阶段的环境更“干净”
- 推理阶段的环境更“脆弱”

所以一个模型在训练时表现不错，并不自动意味着：

- 推理时不会重复
- 推理时不会跑偏
- 推理时一定逻辑连贯

理解这一点之后，你后面再遇到“loss 可以，但生成一般”的情况，就不会立刻觉得矛盾。

## 第六件事：logits 在训练目标里到底扮演什么角色

模型前向一般不会直接输出“已经归一化好的概率”，而是输出 logits。

### logits 是什么

它们是每个位置上，对词表所有候选 token 的未归一化分数。

例如某个位置可能得到：

```text
time: 4.8
day: 2.1
night: 1.5
dragon: -0.8
```

这些分数还不是概率，但它们已经表达了模型偏向哪个 token。

### 为什么训练时通常直接把 logits 交给 cross-entropy

因为 cross-entropy 内部通常会稳定地完成：

- softmax
- 对数变换
- 负对数似然

所以模型不需要先自己把分数变成概率。它只需要负责：

> 把每个候选 token 打出一组合理分数。

## 第七件事：为什么 cross-entropy 很适合这个任务

在语言模型的每个位置上，模型面对的问题可以抽象成：

> 在整张词表里，哪一个 token 才是这一位置真正的正确答案？

这本质上是一个多分类问题。

cross-entropy 的核心作用就是：

- 如果模型给正确类别很高概率，损失变小
- 如果模型给正确类别很低概率，损失变大

### 你现在最需要掌握的不是推导，而是判断

也就是：

> 它正在把“正确 token 是否被高置信度选中”变成一个可以优化的标量。

理解这一点，后面很多实现细节都会更自然。

## 第八件事：为什么因果约束是训练目标的一部分，而不是“模型实现细节”

这点极其重要。

对 decoder-only 语言模型来说，模型在预测当前位置后一个 token 时，只能看当前位置及其之前的内容，不能看到未来。

很多人会把这当成 Attention 层里的一个工程技巧，觉得 mask 只是实现时顺手加上的东西。其实不是。

### 如果不加因果约束会怎样

假设模型在预测序列中第 `t` 个位置的目标时，能直接看到：

- 第 `t+1` 个 token
- 或者更后面的 token

那么训练任务就被破坏了。模型学到的就不再是：

> 根据前文预测后文

而会变成：

> 在已经偷看答案的前提下复述答案

### 这为什么很危险

因为此时训练 loss 甚至可能看起来很好看，但推理时一旦没有未来真值可偷看，表现会立刻崩掉。

所以 causal mask 的本质不是“Attention 的一个小配件”，而是：

> 训练目标正确成立所必需的约束。

## 第九件事：语言模型的训练目标写成数学形式是什么

如果你想把它写成更紧凑的形式，一个长度为 `T` 的序列训练目标可以写成：

\[
\sum_{t=1}^{T} -\log P(x_t \mid x_{<t})
\]

这句话的意思很朴素：

- 对序列中的每个位置
- 看模型给正确 token 分配了多少条件概率
- 概率越低，惩罚越大
- 把这些位置的惩罚加起来

### 为什么这和前面的直觉完全一致

因为我们前面一直在说：

> 模型要根据前文，把正确的下一个 token 推到更高概率位置。

这个公式只是把同一件事写得更紧凑。

## 第十件事：为什么概率越低，损失越大

你不需要立刻进入全部数学证明，但必须形成这个非常基本的因果感：

如果模型给正确 token 的概率很低，那么：

\[
-\log P(x_t \mid x_{<t})
\]

会变大。

反过来，如果模型给正确 token 的概率很高，这一项损失就会更小。

这正符合训练目标：

- 让正确 token 的概率更高
- 让整体损失更低

## 第十一件事：为什么训练时常常把 `[batch, seq, vocab]` 展平

在 PyTorch 里，你经常会看到这样一段写法：

```python
loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),
    targets.view(-1),
)
```

这对初学者很容易产生困惑：

> 明明这是序列模型，为什么最后又把它展平成二维和一维？

### 原因是什么

从损失函数的视角看，batch 中每个位置上的预测，都可以看成一次分类样本：

- 输入是一组长度为 `vocab` 的分数
- 正确答案是一个 token id

因此，把：

\[
[batch, seq, vocab]
\]

展平成：

\[
[batch \times seq, vocab]
\]

本质上是在说：

> 把所有位置上的分类样本一起交给损失函数统一计算。

### 这会不会让模型“忘记顺序”？

不会。

因为顺序结构早已在前面的模型计算中通过：

- token 顺序
- 位置编码
- causal attention

体现出来了。

这里展平只是为了让损失计算更方便，并不意味着模型结构变成了无序。

## 第十二件事：为什么 special token 会直接影响训练目标

很多初学者会觉得 special token 只是一些工程标记，例如：

- `BOS`
- `EOS`
- `PAD`
- `UNK`

但在训练目标里，它们并不只是边缘角色。

### 例如 `BOS`

它帮助模型明确：

> 这是一个序列开始点。

### 例如 `EOS`

它帮助模型学习：

> 序列在什么地方该结束。

### 为什么这件事重要

如果开始和结束边界模糊，模型学到的序列结构就会变得含混。

因此 special token 既影响 tokenizer，也影响训练目标本身。

## 第十三件事：为什么“输入和目标完全相同”是错误训练目标

假设你错误地把：

- 输入：`[BOS, A, B, C]`
- 目标：`[BOS, A, B, C]`

对应在一起。

### 这会发生什么

模型此时更像是在学：

> 当前看到什么，就把它自己复述出来。

这已经不是我们需要的 next-token prediction。

### 为什么这种错误危险

因为它有时不会立刻报错。程序仍然可以：

- 正常前向
- 正常算 loss
- 正常反向

但模型学到的任务已经偏了。

这就是为什么训练目标错误比普通语法错误更可怕：它往往是静默发生的。

## 第十四件事：为什么“能训练”不等于“训练目标正确”

这是学习语言模型时必须反复提醒自己的事情。

如果你把下面任意一个环节写错：

- 输入和目标没有右移一位
- causal mask 没有限制未来
- special token 语义混乱
- 打包长度和训练目标不匹配

程序仍然可能：

- 不报错
- 有 loss
- 甚至看起来还在下降

但此时模型学到的已经不是你想训练的任务。

所以对于语言模型来说，训练目标并不是“结构外的附属设置”，而是和模型结构同等重要的部分。

## 第十五件事：把整章压缩成一句完整的话

如果你想把这一章的核心记成一句话，可以记成：

> 语言模型训练的本质，是让模型在每个位置上根据前文预测右边一位的 token；为此，输入和目标必须错位构造，训练时使用 teacher forcing，模型必须被因果约束禁止偷看未来，而最终损失则通过对正确 token 的条件概率进行惩罚来定义。

如果这句话你能慢慢拆开解释，说明这一章已经真正进入你的理解里了。

## 常见误区

### 误区 1：语言模型是在“整段生成句子”

从最终效果看可以这么说，但从训练定义看，更准确的是“逐位置预测下一个 token”。

### 误区 2：输入和目标右移只是实现上的小技巧

不对。这一步直接属于任务定义。

### 误区 3：teacher forcing 和推理过程差不多

不对。训练时真实后续已知，推理时必须依赖模型自己的输出。

### 误区 4：causal mask 只是 Attention 的附属优化

不对。它是训练目标正确成立的必要条件。

### 误区 5：loss 在降就说明目标一定定义对了

不对。很多目标错位问题都可能在程序正常运行的情况下悄悄发生。

> **这一章真正要你守住的底线**
>
>   语言模型训练目标一旦定义错，程序往往仍然能跑，loss 甚至也可能下降，但模型学到的已经不是“根据前文预测后文”。因此右移目标、teacher forcing 和因果约束必须被当成任务本体来理解，而不是被当成后期补上的技巧。
