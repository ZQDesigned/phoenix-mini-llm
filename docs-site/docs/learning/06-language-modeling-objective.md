# 06. 语言模型训练目标

## 这一章要解决什么问题

到这里，你已经知道：

- 文本会被 tokenizer 切成 token
- token 会被打包成固定长度训练块
- 模型训练依赖前向、损失、反向和参数更新

但中间还有一个最关键的问题必须被完全讲清楚：

> 一段 token 序列到底怎样变成语言模型的输入和目标？

如果这个问题理解不稳，后面即便模型结构、训练循环、设备处理全都写对了，训练目标本身也可能已经错了。更糟糕的是，这类错误经常不会让程序立刻崩掉，而是会变成“模型能训练，但学出来不对”的隐蔽 bug。

这一章的目标，就是把 next-token prediction 的训练定义彻底讲清楚。

## 第一件事：语言模型训练不是在预测“整句话”

这是最先要纠正的误解。

很多人会说：

> 语言模型的任务是根据前文生成一句完整的话。

这句话在直觉层面可以接受，但作为训练定义并不准确。

### 更准确的说法是

语言模型训练的核心任务是：

> 在序列的每一个位置上，根据当前位置之前的 token，预测下一个 token 的分布。

也就是说，它不是整段地一次性预测结尾，而是：

- 位置 1 预测 token 2
- 位置 2 预测 token 3
- 位置 3 预测 token 4
- ...

整段文本的能力，是很多局部条件概率叠加出来的。

## 第二件事：输入和目标为什么是同一段序列的错位版本

假设你有一段 token 序列：

```text
[BOS, A, B, C, EOS]
```

训练时，常见做法是把它拆成：

- 输入：`[BOS, A, B, C]`
- 目标：`[A, B, C, EOS]`

### 为什么要这样拆

因为模型在每个位置回答的问题都是：

- 看到 `BOS`，下一个应该是什么？
- 看到 `BOS, A`，下一个应该是什么？
- 看到 `BOS, A, B`，下一个应该是什么？

换句话说，模型总是在做“向右看一位”的预测。

### 这就是为什么上一章要按 `seq_len + 1` 打包

因为只有当你拿到长度 `L + 1` 的训练块时，才能构造：

- 长度为 `L` 的输入
- 长度为 `L` 的目标

这一步不是打包技巧，而是任务定义本身的要求。

## 第三件事：teacher forcing 到底是什么

这是训练和推理差异里最容易被忽略的一点。

### 训练时，模型不会把自己刚才预测错的 token 再喂给自己

训练阶段使用的通常是 `teacher forcing`，意思是：

- 模型在当前位置做预测
- 但下一步继续训练时，输入仍然来自真实数据序列
- 而不是来自模型上一时刻自己采样出的输出

### 为什么要这样做

因为这样训练会更稳定：

- 梯度信号更清晰
- 模型能在真实上下文上学习条件概率
- 不会因为前一步一个随机错误，立刻把后续整段训练带偏

### 这和推理形成鲜明对比

推理阶段没有真实后续 token 可以喂，所以只能把自己刚生成的 token 接回去继续滚动。也正因为此，训练时“低损失”并不自动意味着推理时一定表现好。

## 第四件事：logits 到底是什么

模型前向通常不会直接输出“已经归一化的概率”，而是输出 logits。

### logits 可以理解成什么

它们是对词表中每个 token 的未归一化分数。

例如某一位置上，模型也许给出：

```text
time: 4.8
day: 2.1
night: 1.5
dragon: -0.8
...
```

这还不是概率，但它已经表达了偏好顺序。

### 为什么训练时常常直接把 logits 交给 cross-entropy

因为 cross-entropy 通常内部会稳定地完成：

- softmax
- 对数
- 负对数似然计算

手动拆开虽然概念上可行，但数值上和工程上都更麻烦。

## 第五件事：为什么 causal mask 是任务定义的一部分

很多人会把 mask 想成某种实现技巧。对 decoder-only 语言模型来说，它其实是训练定义不可分割的一部分。

### 模型为什么不能偷看未来

假设你在预测序列中第 `t` 个位置的目标 token。如果模型在计算时能直接看到第 `t+1` 或更后面的真实 token，那么训练任务就被破坏了。

因为此时模型学到的不是：

> 根据前文预测后文

而变成了：

> 在知道答案的前提下复述答案

这种训练会带来一个危险后果：

- 训练损失可能很好看
- 但推理阶段一旦失去“未来真值”，表现立刻坍塌

### 所以 causal mask 的真正职责是

> 保证每个位置只能看见自己和自己之前的位置，绝不能看见未来。

这是 decoder-only 模型之所以成立的基本约束。

## 第六件事：语言模型目标的数学形式是什么

如果你想把它写成最紧凑的数学表达，一个长度为 `T` 的序列训练目标可以写成：

\[
\sum_{t=1}^{T} -\log P(x_t \mid x_{<t})
\]

这句话的意思是：

- 对序列中每个位置
- 计算模型给正确 token 分配的条件概率
- 取负对数
- 再把所有位置的损失加起来

### 为什么概率越低，损失越大

因为如果模型把正确 token 赋予很低概率，那么：

\[
-\log P(x_t \mid x_{<t})
\]

就会变大。反过来，如果正确 token 概率很高，损失就会变小。

这正符合训练目的：让模型逐渐把正确 token 提到更高概率位置。

## 第七件事：实际代码里 logits 和 targets 是怎样进入损失的

在 PyTorch 中，你常会看到类似这样的写法：

```python
import torch
import torch.nn.functional as F

logits = torch.tensor([
    [[2.0, 0.5, -1.0], [0.1, 1.8, 0.2]]
])  # [batch=1, seq=2, vocab=3]

targets = torch.tensor([[0, 1]])

loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),
    targets.view(-1),
)
```

### 为什么要 `view(-1, vocab)` 和 `view(-1)`

因为从损失函数的角度看，每个位置上的预测都是一条分类样本：

- 预测分布维度是 `vocab`
- 正确类别是一个 token id

把 `[batch, seq, vocab]` 展平后，你等价于在说：

> 把 batch 里所有位置都看成独立分类点，一起计算平均分类损失。

### 这不意味着模型真的忽略了序列结构

序列结构早已在前面的模型计算中通过 attention 和因果约束体现出来了。这里展平只是为了方便统一计算损失。

## 第八件事：为什么“能训练”不代表目标定义正确

这是一类非常危险的错觉。

如果你把下面任意一项写错：

- 输入和目标没有错开一位
- mask 没有限制未来
- special token 处理错位
- 打包长度不是 `seq_len + 1`

程序仍然可能：

- 不报错
- 有 loss
- 甚至看起来还能下降

但模型学到的已经不是你以为的任务。

所以在语言模型项目里，任务定义本身必须像模型结构一样被严肃对待。

<Callout title="这一章的工程后果" tone="warning">
  一旦你把右移逻辑、target 构造或 causal mask 写错，训练脚本往往仍然能执行，但损失含义已经变了。这类 bug 极其隐蔽，必须靠 shape 检查、极小数据过拟合测试和明确的目标理解一起抓。
</Callout>

## 一个更具体的例子：为什么“输入和目标完全相同”是错的

假设你错误地把：

- 输入：`[BOS, A, B, C]`
- 目标：`[BOS, A, B, C]`

对应起来。

那模型就不再是在学“根据前文预测下一个 token”，而是在学“当前位置自己是什么”。

这会让任务定义发生本质偏移。换句话说，你训练的就不是语言模型目标，而是某种近似拷贝任务。

这也是为什么“右移一位”看上去像小细节，实际上却是任务的核心。

## 三个最常见的误区

### 误区 1：训练目标是在预测整句话

不是。模型是在每个位置上分别预测下一个 token，整段输出只是这些局部预测串起来的结果。

### 误区 2：输入和目标可以直接相同

如果相同，任务定义就错了，因为模型不再是在学习 next-token prediction。

### 误区 3：只要有 cross-entropy，就不需要 causal mask

完全错误。没有 causal 约束，模型就可能偷看未来，训练损失会失真。
