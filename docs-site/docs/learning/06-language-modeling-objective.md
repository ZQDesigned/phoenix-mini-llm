# 06. 语言模型训练目标

## 这一章真正要解决什么问题

走到这里，很多初学者已经知道：

- 文本不会直接进入模型，而要先变成 token
- token 会被组织成张量
- 模型训练大致围绕前向、损失、反向和参数更新展开

但在这些环节中间，仍然卡着一个最关键的问题：

> 一段 token 序列，究竟怎样变成语言模型真正要学习的监督目标？

如果这个问题没有彻底讲清楚，后面会出现一种非常危险的状态：

- 模型结构看起来没错
- 训练脚本也能正常跑
- loss 甚至也在下降

可模型学到的任务，根本不是你以为的那个任务。

这类错误尤其麻烦，因为它们经常不会让程序直接崩掉。
更常见的现象反而是：

- 训练能继续
- 指标会变化
- 输出也像是在“生成东西”

但整条学习链路从一开始就歪了。

因此，这一章不只是解释一个实现技巧。
它在回答语言模型最核心的定义问题之一：

> 语言模型到底在优化什么？

## 不要先说“模型会写文本”，先说“模型在每个位置上预测什么”

很多人谈语言模型时，最自然的说法是：

> 它根据前文生成一句完整的话。

这句话在直觉层面没有问题，但如果把它当成训练目标定义，就太粗糙了。

因为训练时，模型并不是“一次性预测整句话”。

更准确的说法应该是：

> 在序列的每一个位置上，模型根据当前位置之前的 token，预测下一个 token 的条件分布。

这句话比“它会续写”更重要。

因为它明确了三件事：

### 第一，训练目标是按位置定义的

模型不是只在句子末尾做一次预测。
它在序列中每一个可预测位置都要承担责任。

### 第二，预测对象是“下一个 token”

不是整段未来，不是语义总结，而是更具体的离散下一步。

### 第三，预测结果首先是分布，不是直接答案

模型本质上是在学习：

- 给哪些 token 更高概率
- 给哪些 token 更低概率

一旦这三件事站稳，后面的右移一位、交叉熵、teacher forcing 才会真正变得自然。

## 语言模型目标最朴素的形式：给定历史，预测下一步

把问题写得最简单，可以得到一句几乎足够统领整章的话：

> 给定已经出现的 token 历史，预测下一个 token 更可能是什么。

如果把它再展开一点，就是：

- 看到第 1 个位置之前的内容，预测第 1 个位置的目标
- 看到第 2 个位置之前的内容，预测第 2 个位置的目标
- 看到第 3 个位置之前的内容，预测第 3 个位置的目标
- 如此重复，直到序列末尾

因此，一段文本样本并不是被模型“整体理解一次然后整体输出”。
训练时它更像是被拆成了很多局部条件预测事件。

例如，如果序列是：

```text
[BOS, A, B, C, EOS]
```

那么模型在训练中会面对的不是一个“大问题”，而是许多局部问题：

- 看到 `BOS`，下一个更可能是什么
- 看到 `BOS A`，下一个更可能是什么
- 看到 `BOS A B`，下一个更可能是什么
- 看到 `BOS A B C`，下一个更可能是什么

这就是语言模型训练目标最核心的局部结构。

## 为什么这不是“整段预测”，而是“逐位置条件预测”

这件事看起来细小，实际上决定了整个语言模型为什么会长成今天这样。

如果你误以为语言模型训练的是：

- “整句话应该是什么”

那么后面的许多机制都会显得很怪：

- 为什么要有 causal mask
- 为什么训练和推理都围绕序列前缀展开
- 为什么生成是一 token 一 token 地滚动

而一旦你接受训练目标其实是：

- “在每个位置上，根据左边历史预测右边下一个 token”

这些机制就会立刻变得合理。

因为它们都在服务同一个约束：

> 当前位置不能偷看未来，只能依赖已经出现的历史。

所以，“逐位置条件预测”不是小细节，而是语言模型目标最关键的骨架。

## 为什么输入和目标常常是“同一段序列右移一位的两个版本”

这也是初学者最容易看见、却最容易低估的一步。

假设你有一段 token 序列：

```text
[BOS, A, B, C, EOS]
```

训练时最常见的组织方式是：

- 输入：`[BOS, A, B, C]`
- 目标：`[A, B, C, EOS]`

也就是把同一段序列拆成：

- 去掉最后一个 token 的输入序列
- 去掉第一个 token 的目标序列

这看起来像切片技巧，但它本质上是在定义任务。

为什么？

因为这正好对应了：

- 看到 `BOS` 预测 `A`
- 看到 `BOS A` 预测 `B`
- 看到 `BOS A B` 预测 `C`
- 看到 `BOS A B C` 预测 `EOS`

也就是说，所谓“右移一位”，其实就是把：

> 左边历史

和

> 右边下一个目标

严格对齐起来。

## 右移一位不是工程技巧，而是任务本体

很多初学者第一次看到：

```python
input_ids = tokens[:-1]
targets = tokens[1:]
```

会把它理解成一种实现上的便利写法，好像只是为了代码好写。

这是一种常见误判。

更准确地说：

> 这一步不是实现细节，而是在定义语言模型训练任务本身。

因为它同时决定了：

- 模型在每个位置看到哪些上下文
- 每个位置到底该为哪个 token 负责
- 损失应该把哪一个输出位置和哪一个真实答案比对

只要这组对齐关系错了，你训练的就不再是“根据历史预测下一 token”，而会悄悄变成另一个问题。

因此，这一步在概念上极其重要。

它不是“为了方便”，而是：

> 语言模型监督信号的核心构造方式。

## 为什么语言模型看起来像“自己给自己造标签”

和很多监督学习任务相比，语言模型有一个很特别的地方：

它的目标往往不是由外部人工标签额外附加的。

相反，它通常是：

- 从原始文本本身构造出来的

这也是为什么语言模型训练常被称为一种典型的自监督学习。

它并不是“没有监督”。
更准确地说：

> 监督信号不是由人工另写标签提供，而是由原始序列的内部结构自动生成。

例如一段文本本身就已经隐含了大量训练事件：

- 如果左边是这个前缀，右边出现的下一个 token 是什么

这意味着文本不仅是内容，也是标签来源。

这种结构有两个重要后果。

### 第一，海量原始文本可以直接成为训练资源

不必每条都人工标注任务标签。

### 第二，模型学到的是序列内部条件依赖

而不是外部标注任务的单一步映射。

这正是语言模型和很多传统监督任务非常不同的地方。

## 为什么目标不是一个 token，而是一整排位置上的 token

初学者经常会下意识地把语言模型训练理解成：

- 输入一段前文
- 输出一个下一个 token

这个想法在单步上没错，但训练时还不够完整。

因为训练通常希望一次前向就利用整段序列里的多个监督位置。

换句话说，模型不是只在最后一个位置上学一次，而是会在所有可预测位置上同时学。

这意味着一条长度为 `T` 的 token 序列，常常会在一次前向里贡献接近 `T-1` 个监督事件。

这件事很关键，因为它解释了：

- 为什么语言模型训练效率并不只是“每次学一个 token”
- 为什么 loss 常常是对整段位置损失做平均
- 为什么一段样本里每个位置都能提供学习信号

所以你应该把语言模型的训练样本理解成：

> 一次前向里同时打包了很多个“根据左边预测右边”的局部事件。

## teacher forcing 到底是什么

训练和推理的差别，几乎一定会在这里第一次正式出现。

teacher forcing 最朴素的定义是：

> 训练时，即使模型在某个位置预测错了，下一位置继续训练时，输入仍然使用真实历史，而不是模型刚才自己生成的错误 token。

这个定义看似简单，但非常重要。

因为它意味着：

- 训练阶段，模型总是在真实上下文上学习
- 推理阶段，模型必须开始吃自己刚刚生成出来的 token

这两个条件并不相同。

也正因为如此，语言模型才会天然存在一种训练和推理之间的落差感。

## 为什么训练阶段要用 teacher forcing

很多人会好奇：

> 如果推理时模型最终要吃自己的输出，为什么训练时不从一开始就这样做？

原因是，如果你在训练早期就让模型不断吃自己刚才生成的错误 token，那么：

- 早期错误会立刻连锁放大
- 后续上下文会迅速变得混乱
- 学习信号会变得更不稳定
- 训练难度会显著上升

而 teacher forcing 的作用就是：

> 先让模型在“正确历史”条件下学会局部条件分布，再把真正的滚动生成交给推理阶段。

这是一种非常务实的训练协议。

它并不是说“推理不重要”，而是说：

- 先把局部条件预测学会
- 再面对自回归滚动带来的误差累积问题

## 为什么训练和推理不是同一件事

一旦 teacher forcing 建立起来，就必须正式接受一个现实：

> 训练时模型所处的上下文环境，和推理时模型所处的上下文环境，并不完全相同。

训练时：

- 当前输入历史主要来自真实数据

推理时：

- 当前输入历史会越来越多地来自模型自己刚才生成出的 token

这个差别会带来非常重要的后果。

### 第一，训练 loss 很好并不自动意味着生成质量很好

因为训练环境比推理环境更干净。

### 第二，模型在推理时可能会逐步放大自己的早期小错误

因为错误 token 一旦被写进上下文，就会影响后面每一步。

### 第三，解码策略会比很多传统任务更重要

因为输出本身会回流成后续输入。

这就是为什么后面我们必须专门讨论：

- 自回归生成
- 采样
- 重复
- 停止条件

它们都不是训练目标之外的偶然附加品，而是训练目标在运行时必然暴露出的另一面。

## 模型在每个位置上到底输出什么

到这里，我们已经知道每个位置上模型都要预测下一个 token。

但模型真正直接输出的并不是：

- 文本字符串
- token 本身
- 一个已经决定好的答案

更准确地说，模型通常先输出的是：

- 对整个词表每个候选 token 的一组分数，也就是 logits

这些 logits 表达的是：

> 在当前上下文下，模型对各候选 token 的相对偏好。

然后通过 softmax，它们会被转成一个概率分布。

也就是说，语言模型目标并不是：

- 让模型直接吐出唯一正确 token

而更像是：

> 让模型在每个位置上学会给真实下一个 token 分配尽可能高的概率。

这句话非常重要。

因为它把目标从“答案匹配”改写成了：

- 分布优化

这也是交叉熵会自然进入主线的原因。

## 为什么词表级输出是语言模型目标的自然结果

如果目标是预测“下一个 token 更可能是什么”，那么模型在每个位置就必须面对一个候选集合：

- 整个词表

这意味着语言模型的输出接口天然是：

- 每个位置对应一个大小为 `vocab_size` 的分布或分数向量

因此，输出张量通常会带着这样的结构直觉：

```text
[batch_size, sequence_length, vocab_size]
```

最后一维之所以存在，不是因为框架习惯这么设计，而是因为：

> 模型必须在词表所有候选之间表达相对偏好。

所以词表维不是实现巧合，而是目标定义自然要求出来的接口。

## 交叉熵为什么会成为语言模型训练的核心损失

既然模型每个位置输出的是：

- 对整个词表的概率分布倾向

而目标是：

- 真实下一个 token 应该被高概率对待

那么损失函数就必须回答：

> 当前分布对真实目标 token 的分配，到底有多不合理？

交叉熵之所以适合这里，是因为它正好在做这件事。

你可以先用最直观的方式理解它：

- 真实 token 的概率越高，损失越小
- 真实 token 的概率越低，损失越大

而且如果模型把真实 token 看得极不可能，损失会明显惩罚这种错误。

因此，语言模型目标的核心不是：

- “猜中一个 token 就行”

而是：

> 在每个位置上，把真实下一个 token 放到尽可能合理的概率位置上。

## 为什么一个序列样本的损失通常是“位置损失的平均”

如果一条样本里有很多可预测位置，那么模型也会在这些位置上产生很多个局部损失。

于是就会自然出现一个问题：

> 一整条样本的损失该怎样汇总？

最常见的做法通常是：

- 对所有有效位置的 token-level 损失求平均

这背后的直觉并不复杂：

- 每个位置都提供一个监督事件
- 这些监督事件共同代表这条样本上的整体预测质量

因此，一条序列的损失本质上是：

> 许多“当前前缀预测下一个 token”事件的平均表现。

这也是为什么语言模型训练看似在学整段文本，实际上却始终扎根于：

- 逐位置局部预测

## padding、mask 和“哪些位置应该计入损失”为什么重要

真实训练里，并不是每个位置都一定应当参与损失。

例如：

- 某些样本为了凑齐 batch 长度而使用了 padding
- 某些位置可能是特殊符号，不应当像普通预测位那样处理

这意味着语言模型训练目标不仅仅是：

- 有一段输入
- 有一段右移目标

还必须进一步明确：

- 哪些位置是真正有效的监督位置
- 哪些位置只是填充或结构控制，不应当干扰损失

如果这一层处理错了，就会出现非常麻烦的问题：

- 模型开始学会去预测 padding
- 有效位置和无效位置被混在一起
- loss 数值看起来还在动，但目标已经被污染

因此，“哪些位置计入损失”也是任务定义的一部分，而不是小修小补。

## 为什么 next-token prediction 看起来局部，却能支撑复杂能力

这是几乎所有初学者都会问的一个好问题：

> 只是预测下一个 token，为什么最后会长出看起来很复杂的语言能力？

答案不在于“下一个 token”这个动作本身有多神秘，而在于：

> 这个动作会在海量不同上下文上反复发生。

模型不是只预测一个下一个 token。
它是在：

- 不同主题
- 不同风格
- 不同长度
- 不同结构
- 不同领域

的大量前缀上，反复学“接下来什么更可能”。

这会迫使模型逐步压缩出很多有用规律：

- 词法搭配
- 句法结构
- 局部语义连续性
- 更长距离依赖
- 话题延续模式

因此，看似局部的目标之所以能长出更复杂的行为，不是因为它暗藏魔法，而是因为：

> 当这个局部目标在足够大的分布上被反复优化时，模型为了把每一步都做好，就不得不学会越来越丰富的内部规律。

## 为什么训练目标不直接等于“真实世界里的语言理解”

这也是必须尽早讲清的一点。

语言模型目标虽然很强大，但它并不等于：

- 完整语言理解的全部定义

从训练机制上看，模型始终在做的是：

- 条件概率预测

这件事可以支撑出很多强能力，但它也有边界。

它不意味着：

- 模型天然拥有和人类一样的语义 grounding
- 模型已经直接被训练去执行所有下游任务
- 只要 next-token loss 够低，就保证所有行为都完美

因此，理解语言模型目标时，既要避免低估它，也要避免神化它。

更稳的说法是：

> next-token prediction 是一个非常强、非常通用、可扩展性极高的训练目标，但它仍然只是一个训练目标，而不是全部智能问题的完整定义。

## 为什么训练目标会决定后面几乎所有系统设计

一旦语言模型目标被明确定义成：

- 根据历史预测下一 token

很多后续设计都会自然跟着长出来。

例如：

- 需要 tokenizer：因为目标对象是离散 token
- 需要因果约束：因为当前位置不能偷看未来
- 需要词表级 logits：因为要在全词表上分配偏好
- 需要交叉熵：因为要比较真实 token 的概率分配
- 需要自回归推理：因为训练目标本来就是按历史逐步展开

也就是说，训练目标不是系统里的一个局部选择。

更准确地说：

> 它是后面很多结构和协议共同依赖的源头。

如果这一章没有真正看懂，后面许多设计都会显得像“工程师习惯这么做”。
而一旦这一章看懂，很多东西就会开始显得非常必然。

## 初学者在这里最容易犯的四个误解

### 误解一：语言模型一次性预测整段输出

这会让你无法真正理解逐位置损失和自回归生成。

### 误解二：右移一位只是代码技巧

这会让你低估任务定义本身的重要性。

### 误解三：训练和推理本来就该完全一致

这会让你后面很难理解 teacher forcing 带来的差异。

### 误解四：loss 下降就等于生成一定好

这会让你低估推理协议、采样策略和误差累积的影响。

## 这一章读完后，你应该能稳定回答什么

如果这章真正起作用了，那么你至少应该能逐步说清：

- 为什么语言模型目标不是“整体写一句话”，而是“逐位置预测下一 token”
- 为什么输入和目标通常是同一段序列的错位版本
- 为什么右移一位不是实现细节，而是任务本体
- 为什么训练阶段要使用 teacher forcing
- 为什么训练和推理会天然存在环境差异
- 为什么词表级 logits 和交叉熵会自然出现
- 为什么 next-token prediction 虽然局部，却能支撑复杂能力

如果这些问题你能稳定讲出来，那么后面的：

- causal mask
- logits
- perplexity
- sampling
- autoregressive generation

都会顺畅很多。

## 这一章之后该去哪里

如果你在走快速导读线，最自然的下一步通常是：

- [07. 从 MLP 到 Attention](/learning/07-from-mlp-to-attention)

因为一旦训练目标已经清楚，下一个自然问题就是：

> 如果模型必须根据越来越长的历史去预测下一个 token，它为什么不能一直停留在简单前馈结构里？

而如果你正在按长读主线深入读整本知识档案，那么这一章对应的更深入展开通常在：

- 卷七 文本怎样进入模型：语料、编码与分词

这些卷会继续把这一章建立的目标定义压到更完整的模型主体上。

## 小结

这一章最核心的结论可以压缩成一句话：

> 语言模型训练的本体，不是一次性写出整段文本，而是在序列的每个位置上，根据左边已经出现的 token，预测右边下一个 token 的条件分布。

围绕这个定义，很多看似分散的设计都会自然长出来：

- 右移一位的输入与目标
- teacher forcing
- 词表级 logits
- 交叉熵损失
- 因果约束
- 自回归推理

因此，理解语言模型目标，不是在记一个“常见做法”。
而是在看清：

> 为什么今天的小型语言模型，从数据组织到模型结构，再到训练与推理协议，会整体长成现在这个样子。
