# 01. 你到底在做什么

## 这一章要解决什么问题

很多初学者一进入“大模型开发”这个主题，第一反应就是去找这些内容：

- Attention 怎么写？
- PyTorch 里哪个 API 对应哪一层？
- 怎么下载数据集？
- 怎么把模型放到 GPU 上？

这些问题当然都重要，但它们都晚了一步。真正更靠前的问题是：

> 你到底在试图构建什么系统？

如果这个问题没回答清楚，后面的每一段代码都只会像一堆局部技巧。你也许能抄出一个 `train.py`，能抄出一个 `TransformerBlock`，但你不会真正知道这些东西为什么存在、怎样配合、哪些地方可以改、哪些地方不能乱动。

这一章的目标，是先把整座系统的轮廓搭起来。读完之后，你应该能明确：

- 语言模型的输入和输出到底是什么。
- 训练和推理为什么是同一个模型的两种完全不同使用方式。
- 参数、token、上下文窗口、词表这些词分别在约束什么。
- 为什么一个合理的学习目标应该是“小而完整”，而不是盲目追求参数规模。

## 你现在不需要会什么

你不需要在开始这一章之前就懂：

- 微积分推导
- Transformer 论文
- CUDA 编程
- 大规模分布式训练

你真正需要的只有：

- 基本 Python 语法
- 能在终端里运行命令
- 愿意对概念做慢一点、扎实一点的理解

## 第一件要搞清楚的事：语言模型到底在做什么

### 从表面看，它在“生成文字”

这是大家最容易看到的一面。你给一个 prompt，例如：

```text
Once upon a
```

模型继续往后写：

```text
time there was a small dragon...
```

所以直觉上你会觉得：语言模型是在“写句子”。

这没错，但还不够精确。

### 从训练定义看，它其实在做“下一个 token 预测”

一个 decoder-only 语言模型最根本的任务不是“写故事”，而是：

> 给定前面的 token，预测下一个 token 的概率分布。

注意这里有两个关键词：

- `给定前面的 token`
- `概率分布`

这意味着模型的输出并不是一句完整文本，而是某个位置上“所有候选 token 的分数”。例如面对前文：

```text
Once upon a
```

模型输出的内部结果更像：

```text
time: 0.41
day: 0.18
night: 0.11
small: 0.03
...
```

然后系统再从这个分布里选出一个 token，把它接回输入，继续下一步预测。

也就是说，“写一整段文字”其实只是很多次“预测下一个 token”串起来的结果。

## 为什么这一定义这么重要

因为它决定了你之后对整个项目的理解方式。

如果你把模型想成“会说话的黑箱”，你后面看到任何代码都会觉得像魔法。

但如果你始终记住模型的根任务是“根据前文给出下一个 token 分布”，那么你后面看到：

- tokenizer
- logits
- cross-entropy
- causal mask
- sampling

这些东西时，就会知道它们都不是凭空出现的，而是在服务这个定义。

## 第二件事：token 到底是什么，为什么不是“字”或“词”

很多人第一次接触语言模型时，会天然地把输入想成：

- 按字符处理
- 或按单词处理

但真实情况通常不是这样。

### token 是模型的最小离散单位

模型并不直接理解原始字符串，它看到的是 token 序列。token 可能是：

- 一个完整单词
- 一个单词的一部分
- 一个标点符号
- 一个常见前缀或后缀
- 某种 byte-level 切分片段

例如词 `unbelievable`，并不一定会作为一个整体 token 出现。它可能被拆成：

```text
un
believ
able
```

也可能被拆成完全不同的若干片段，这取决于 tokenizer 的词表和训练方式。

### 为什么不直接按“词”处理

因为自然语言里有太多问题会立刻出现：

- 生僻词和新词层出不穷
- 不同语言的词边界并不总是简单
- 纯按词切分会让词表膨胀得很快

而子词级 tokenization 可以在词表规模和表达能力之间取得更好的平衡。

### 为什么这和模型本身强相关

因为 tokenizer 决定了模型到底在学什么单位。

如果 tokenization 变了，下面这些东西都会一起变：

- `vocab_size`
- embedding 层大小
- 输出头大小
- 训练样本长度分布
- 某些 prompt 的编码方式

所以 tokenizer 从来不是“模型前的杂事”，而是模型定义的一部分。

## 第三件事：训练和推理不是一回事

初学者非常容易混淆这两种过程，因为两者都在“把 token 喂给模型”。但它们本质上是不同的工作方式。

### 训练时，你已经知道正确答案

训练数据里，一整段 token 序列是现成的。例如：

```text
[BOS, once, upon, a, time, EOS]
```

训练时你会让模型在每个位置上都回答“下一个 token 应该是什么”，然后用真实答案计算损失。

这意味着：

- 训练时模型总能看到真实前文
- 即使某一步它预测错了，下一步也仍然使用正确 token 继续训练

这就是后面会讲到的 `teacher forcing`。

### 推理时，你没有正确答案

真正生成文本时，情况完全不同。你只能这样做：

1. 给 prompt
2. 预测下一个 token
3. 把这个 token 接回去
4. 再预测下一个

如果某一步选错了，后面所有步骤都会基于这个错误继续滚动。

所以训练和推理最大的区别不是“代码函数不同”，而是信息条件不同：

- 训练时：真实答案已知
- 推理时：真实答案未知

这也是为什么一个模型“训练 loss 看起来不错”，并不自动意味着它“推理表现就一定好”。

## 第四件事：参数到底是什么

很多人会说“模型把知识记在参数里”，这句话方向上没错，但很容易让人形成一个误解：

> 好像模型像数据库一样，把句子一条条存进去了。

这不是参数更准确的含义。

### 参数是一大堆可训练的数字

这些数字分散在不同层里，例如：

- embedding 矩阵
- Q/K/V 投影矩阵
- 前馈网络线性层
- norm 的可学习权重

训练的过程，本质上就是不断微调这些数字，让模型在统计意义上更擅长预测下一个 token。

### 参数不是“规则库”，更像可调函数

模型并不会显式存一条规则：

```text
如果看到 once upon a，就一定输出 time
```

它学到的是一种分布式统计结构。也就是说，很多参数一起决定：

- 哪些 token 在相似上下文里更可能共现
- 哪些位置之间存在重要依赖
- 哪些表示在多层变换后能帮助预测正确 token

这也是为什么参数量大不等于“更懂”，而只是表示模型拥有更大的可调表示容量。

## 第五件事：上下文窗口在限制什么

语言模型不是无限回看整部小说。一次前向传播里，它只能处理固定长度的 token 序列，这个长度通常叫：

- context length
- sequence length
- max sequence length

### 这个限制不只是“最多看多长”

它还会直接影响：

- 数据怎么打包
- 显存占用
- 注意力计算规模
- 训练速度
- 推理时的成本

在小型语言模型项目里，把 `max_seq_len` 从 `256` 提到 `512`，代价并不只是“序列长了一倍”。尤其在标准 attention 下，相关中间张量和注意力矩阵的成本会增长得更快。

所以 context length 不是一个装饰参数，而是一条工程边界。

## 为什么你的学习项目不该一开始就追求“大”

这是本章里最容易被忽视、但最关键的一点。

### “大模型开发”不等于“你必须自己从 0 训练一个巨型模型”

如果你的目标是学习，真正有价值的是：

- 你是否能自己写出整个链路
- 你是否能解释每个模块的职责
- 你是否能定位 bug
- 你是否能在不同设备和配置下稳定运行它

这些能力和参数量并不成正比。

### 小而完整，比大而失控更有学习价值

对学习项目来说，一个数千万参数量级、可以在有限显存下跑起来的模型，已经足以覆盖所有关键环节：

- tokenizer
- embedding
- attention
- transformer block
- loss
- training loop
- checkpoint
- generation
- KV cache
- sampling

这已经是完整语言模型工程，而不是玩具。

### 为什么 6GB 显存约束会改变你的目标

因为训练成本不是只看“模型参数本身占多少显存”。训练时显存还要容纳：

- 参数
- 梯度
- 优化器状态
- 激活值
- 中间 attention 张量

这意味着即便某个模型“参数量看起来不大”，训练时也可能立刻 OOM。

所以一个认真负责的学习项目，必须把目标定义成：

> 在可承受的硬件预算内，做出一个结构完整、行为可解释、工程可复现的小型语言模型。

这正是一个合格学习项目应有的定位。

<Callout title="学习项目的正确目标" tone="note">
  一个好的小型语言模型学习项目，目标不是“参数量惊人”，而是从数据准备、Tokenizer、模型、训练到采样的整条链路都清晰可读、可修改、可复刻。
</Callout>

## 一个非常小的概率模型实验

在进入神经网络之前，先看一个完全不依赖深度学习的例子：

```python
from collections import Counter, defaultdict

text = "banana bandana"
counts = defaultdict(Counter)

for left, right in zip(text[:-1], text[1:]):
    counts[left][right] += 1

for char, next_chars in counts.items():
    total = sum(next_chars.values())
    probs = {k: round(v / total, 2) for k, v in next_chars.items()}
    print(char, probs)
```

这个程序做的事情非常朴素：

1. 读取一段文本
2. 统计某个字符后面常跟哪些字符
3. 给出经验概率

它还不是语言模型，但它已经展示了语言模型最核心的结构：

- 看前文
- 给后文分布

真实神经语言模型做的，只是把这种统计关系从“手工计数表”换成“可训练参数函数”。

## 这一章最重要的三个误区

### 误区 1：模型是在“背答案”

模型当然会利用训练语料中的统计模式，但这不意味着它像数据库一样原样存句子。它学习的是一种分布式函数近似，而不是一份直接可查询的全文副本。

### 误区 2：参数量越大，学习效果越好

对研究和工业训练来说，大模型有其价值；但对学习项目来说，参数量过大只会迅速放大：

- 训练时间
- 调试难度
- 显存压力
- 失败成本

### 误区 3：只要能生成文字就说明模型“懂了”

不是。生成文本只是外部现象。你仍然需要结合：

- 训练损失
- 验证损失
- 重复程度
- prompt 稳定性
- 采样策略影响

才能判断模型到底学到了什么。
