# 01. 你到底在做什么

## 这一章要解决什么问题

很多初学者一上来就钻进 “Attention 怎么写” 或 “PyTorch API 怎么调”，但真正的问题更靠前：你到底在试图构建什么系统？如果这个问题没有讲清楚，后面的每个模块都只会变成零散技巧。

这一章的目标，是先在脑子里搭出一张地图。你会知道：

- 语言模型的输入和输出到底是什么。
- `训练` 和 `推理` 为什么是两件行为完全不同的事。
- 参数、token、上下文窗口这些词分别约束什么。
- 为什么这个项目的合理目标是“小而完整”，而不是盲目追求更大参数量。

## 你需要先知道什么

- Python 基本语法。
- 终端里运行命令的基本方式。

除此之外，不要求你已经学过机器学习。

## 核心概念

### 1. 语言模型在做“下一个 token 预测”

一个 decoder-only 语言模型的核心任务很简单：

> 给定前面的 token，预测下一个 token 出现的概率分布。

例如你输入：

```text
Once upon a
```

模型不会直接“理解故事”，它会输出一个概率分布，告诉你接下来更可能出现 `time`、`day`、`night` 或别的 token。

### 2. token 不是“字”，也不一定是“词”

语言模型通常不直接处理原始字符，而是先把文本切成 token。一个 token 可能是：

- 一个单词的一部分
- 一个完整单词
- 一个标点符号
- 一个常见前缀或后缀

这就是为什么你会看到 tokenizer、词表、special tokens 这些看起来和“模型”无关的东西。它们其实决定了模型究竟在学什么单位。

### 3. 训练和推理是两种完全不同的工作方式

训练时：

- 你已经知道正确答案
- 你把整段 token 序列一次性交给模型
- 你通过损失函数告诉模型“哪里猜错了”

推理时：

- 你没有正确答案
- 你只能根据模型刚输出的结果继续往后生成
- 你要决定是选概率最大的 token，还是保留随机性

所以训练关心的是：`如何从数据中更新参数`。推理关心的是：`如何用已有参数稳定地产生文本`。

### 4. 参数是模型记住“偏好”的地方

模型的参数本质上是一大堆数字。训练过程不是把知识“存成规则”，而是不断调整这些数字，让模型在统计意义上更擅长预测下一个 token。

你可以把参数理解成模型内部的可调旋钮：

- token embedding 告诉模型不同 token 的表示
- Attention 相关参数决定它如何比较不同位置的信息
- FFN 参数决定非线性变换如何发生

### 5. 上下文窗口决定模型一次最多看多长

模型不是无限回看全部历史，而是在一次前向传播里只能处理固定长度的序列。这个长度常被叫做：

- context length
- sequence length
- max sequence length

在 `phoenix-mini-llm` 里，这个值直接影响：

- 显存占用
- 数据打包方式
- 注意力计算规模

## 最小必要数学

这一章只需要一个公式：条件概率。

\[
P(x_t \mid x_1, x_2, \dots, x_{t-1})
\]

它的意思是：在前面已经出现的 token 条件下，第 `t` 个 token 出现的概率。

整个语言模型训练，其实就是不断逼近一连串这样的条件概率。

## 最小代码实验

下面这个例子不是神经网络，只是一个极简的“下一个字符统计器”。它的作用是让你看到：即使最原始的语言模型，也是在做“根据前文预测后文”。

```python
from collections import defaultdict, Counter

text = "banana bandana"
counts = defaultdict(Counter)

for left, right in zip(text[:-1], text[1:]):
    counts[left][right] += 1

for char, next_chars in counts.items():
    total = sum(next_chars.values())
    probs = {k: round(v / total, 2) for k, v in next_chars.items()}
    print(char, probs)
```

这个程序做的事很朴素：

1. 读一段文本
2. 观察每个字符后面最常接什么
3. 输出经验概率

真正的神经语言模型把“字符统计表”换成了可训练参数，但任务本质相同。

## 常见误区

### 误区 1：模型是在“背答案”

模型确实会利用训练数据中的统计规律，但它不是把每句话原样存起来。它学到的是一种概率结构，而不是一份可搜索的全文数据库。

### 误区 2：参数量越大，学习项目越好

对学习项目来说，大模型往往只会增加等待时间和调试难度。一个 30M 到 100M 量级、结构完整、能跑通训练与生成链路的小模型，学习价值远高于一个你根本训练不动的大模型。

### 误区 3：只要能生成文字就说明模型“懂了”

生成文本只是外部现象。你仍然需要看训练损失、验证损失、重复输出、过拟合程度和提示词鲁棒性，才能判断这个模型到底有没有学到有用的模式。

<Callout title="本项目的正确目标" tone="note">
  `phoenix-mini-llm` 的目标不是做一个参数量惊人的模型，而是做一个从数据准备、Tokenizer、模型、训练到采样全部链路都清晰可读的学习项目。
</Callout>
