# 01. batch、token、step 与 epoch 到底在统计什么

## 为什么训练一开始就会遇到一堆“计量单位”

很多初学者第一次看训练日志时，最容易先被一堆单位淹没：

- `batch size`
- `micro batch`
- `step`
- `global step`
- `tokens seen`
- `epoch`

如果这些词没有建立起稳定关系，后面几乎所有训练讨论都会变得含糊。

因为训练不是一个抽象动作，而是一段有明确节奏的过程。你必须知道：

> 模型每一次更新，到底消耗了多少数据、经过了多少位置、当前训练进度该怎样描述。

这正是这一章要讲清楚的内容。

## 先建立一个最粗的画面：训练是不断重复的小循环

一个最简化的训练循环可以写成：

```text
取一批样本
-> 做前向计算
-> 算 loss
-> 做反向传播
-> 更新参数
-> 再取下一批样本
```

问题在于，这个“取一批样本”和“更新一次参数”之间，其实藏着很多统计口径。

例如：

- 一批样本里有多少序列
- 每条序列有多少 token
- 一次参数更新前累积了多少小批次
- 训练集总共被扫过了几轮

如果不把这些单位分清，你很容易在比较实验时混淆：

- 你比较的是更多数据，还是更多更新次数
- 模型看到的 token 变多了，还是只是 batch 变大了
- loss 变化来自训练更久，还是来自每次更新更稳定

## 什么是 sample，什么是 batch

先从最基础的对象开始。

### sample

在语言模型训练里，一个 sample 通常指一条可直接送入模型的训练样本。

在最常见的设置下，它往往是：

- 一段固定长度的 token 序列输入
- 以及和它右移对齐的目标序列

也就是说，sample 不是“整篇原始文章”，而是：

> 被整理成统一形状、能直接进入 loss 计算的一条训练单元。

### batch

batch 就是把多条 sample 组织在一起，形成一次并行前向和反向所使用的数据块。

如果每条样本长度是 `T`，一次拿 `B` 条，那么输入张量常见形状就是：

\[
[B, T]
\]

在进入 embedding 后会变成：

\[
[B, T, H]
\]

因此 batch 的第一意义是并行计算单位，而不是某种抽象训练概念。

## 为什么训练喜欢 batch，而不是永远一条一条喂

原因很现实。

### 第一，硬件并行效率

现代 GPU 更擅长一次处理一块整齐数据，而不是大量碎小工作。

### 第二，梯度估计更稳定

如果你每次只看一条样本，梯度很容易带着很大波动。

当多个样本一起参与时，你得到的梯度更接近“在这一小块数据上的平均更新方向”。

### 第三，日志与吞吐更容易衡量

batch 提供了清晰统计单位，让你能讨论：

- 每 step 处理多少样本
- 每秒处理多少 token
- 显存利用率与 batch 的关系

但这并不意味着 batch 可以无限增大。越大通常意味着：

- 显存占用更高
- 单步耗时更长
- 训练动力学也会发生变化

所以 batch 是训练效率和资源约束之间的一个核心平衡点。

## 什么是 batch size

batch size 最常见的意思是：

> 一次前向 / 反向中并行处理的样本数。

例如：

- `batch_size = 8`
- 每条样本长度 `seq_len = 256`

那么单次前向处理的 token 数量就是：

\[
8 \times 256 = 2048
\]

这已经能看出一个重要事实：

> batch size 本身不能单独说明“数据量有多大”，因为它必须和序列长度一起看。

## 为什么 token 数经常比样本数更重要

语言模型与许多普通任务不同的地方在于：

> 样本内部本身就是长度为 `T` 的序列。

所以只说“我每次用了 8 条样本”往往信息不够。

更有意义的说法通常是：

- 每次更新看了多少 token
- 整个训练总共看了多少 token

原因很简单：

- `8 x 64` 和 `8 x 512` 虽然 batch size 同样是 8，但训练负担完全不同
- attention 成本对序列长度非常敏感
- 模型学到的上下文范围也直接受序列长度影响

因此在语言模型里，token count 是比 sample count 更接近真实训练负载的单位。

## 什么是 step

step 最常见的意思是：

> 一次参数更新。

也就是说，当你完成了一轮前向、反向，并调用优化器让参数真的改变一次，这通常就记作一个 training step。

很多日志里的：

- `step=1000`

并不是说模型看了 1000 条样本，而是说：

> 参数已经被更新了 1000 次。

这一定义非常关键，因为大量训练超参数都以 step 为节奏：

- 每多少 step 评估一次
- 每多少 step 保存 checkpoint
- warmup 持续多少 step
- 总训练进行多少 step

## 什么是 global step

global step 通常只是强调：

> 这是整个训练过程累计到现在的参数更新次数。

它用来区分局部循环计数，例如：

- 当前 epoch 内第几个 batch
- 某个恢复训练后的局部步数

一旦你开始支持 resume 训练，global step 就尤其重要，因为它决定：

- 学习率调度当前进行到哪里
- checkpoint 命名位置
- 日志曲线横轴对不对

## 为什么“一个 batch 不一定等于一个 step”

这是很多初学者第一次接触梯度累积时最容易混淆的点。

如果你直接处理一个 batch，然后立刻更新参数，那么：

- 1 个 batch
- 1 次 backward
- 1 次 optimizer step

确实会对上。

但在梯度累积里，不是这样。

你可能会：

- 连续处理 4 个小 batch
- 每个都做 backward
- 但先不更新参数
- 第 4 个小 batch 结束后才做一次真正参数更新

这时：

- 4 个 micro batch
- 1 个 optimizer step

所以 “step” 的定义应该始终锚定在：

> 参数有没有真的更新一次。

## 什么是 micro batch 和 effective batch

这两个词在小显存训练里尤其重要。

### micro batch

单次真正送进显存进行前向 / 反向的小批次。

例如：

- `micro_batch_size = 2`

### gradient accumulation steps

累积多少个 micro batch 才更新一次参数。

例如：

- `gradient_accumulation_steps = 8`

### effective batch

从参数更新视角看，相当于一次更新总共汇聚了多少样本。

如果：

- `micro_batch_size = 2`
- `gradient_accumulation_steps = 8`

那么 effective batch size 就近似是：

\[
2 \times 8 = 16
\]

如果再考虑多卡训练，还要继续乘设备数。

所以 effective batch 不是某个新的神秘对象，而是：

> 从优化器真正看到的平均梯度规模去描述，一次更新等价于多少样本共同作用。

## 什么是 epoch

epoch 最常见的定义是：

> 整个训练集被完整扫过一遍。

如果训练集总共有 10,000 条样本，而每个 batch 含 100 条，那么理论上：

- 100 个 batch 左右会组成 1 个 epoch

这个定义在很多经典机器学习任务里很自然，因为：

- 数据集大小固定
- 一轮一轮扫完很直观

## 为什么语言模型里 epoch 有时没那么核心

在小型、固定数据集实验里，epoch 仍然很有意义。

但在语言模型世界里，它有时不如 step 或 token count 那么核心，原因有几个。

### 第一，数据可能非常大

如果语料特别大，一次完整扫完的时间成本可能并不适合拿来当主要节奏。

### 第二，数据可能被重新打包

当你把文档 concat 再切块时，“完整扫过一遍原始文档”这个概念会变得不那么直观。

### 第三，很多训练控制本来就按 step 走

例如：

- 总共训练 50,000 step
- 每 500 step 评估
- 每 1,000 step 存 checkpoint

这时训练真正的控制语言更像是：

> 以 step 和 token 为主，epoch 只是辅助统计。

## token seen 为什么在语言模型里非常重要

token seen 指的是：

> 到当前为止，模型总共消费了多少 token 作为训练输入。

这个单位之所以重要，是因为它更接近“模型到底看了多少语言现象”。

例如，两次实验：

- 实验 A：`batch=8, seq_len=128`
- 实验 B：`batch=4, seq_len=256`

如果它们 step 数相同，那么每 step 消费的 token 数其实一样，都是 1024。

从“模型总共看到多少 token”的角度，它们训练进度可能更接近；但从显存模式和依赖范围来看，它们又不完全等价。

这说明 token seen 既重要，又不能替代其他单位。

## 为什么比较实验时必须先统一口径

很多训练比较之所以失真，就是因为比较口径没统一。

例如你说：

> 这个配置训练得更久。

到底是指：

- 更多 step
- 更多 epoch
- 更多 token

这三件事不一定等价。

再例如你说：

> 这个 batch 更大。

你可能指：

- micro batch 更大
- effective batch 更大
- 每 step token 数更多

这些也不完全等价。

所以一个成熟训练记录至少要把下面这些量分开：

- micro batch size
- sequence length
- gradient accumulation steps
- effective batch size
- current step
- tokens seen

只有这样，后面讨论学习率、吞吐和稳定性才会有准确背景。

## 小显存学习项目里最实用的口径是什么

如果你的目标是实现并理解一个能在较小显存上运行的小型 LLM，一个很实用的习惯是同时盯住四个量：

### 1. `micro_batch_size`

它决定你单次前向 / 反向是否放得下。

### 2. `sequence_length`

它决定上下文窗口与 attention 成本。

### 3. `gradient_accumulation_steps`

它决定你如何在不增加峰值显存的前提下扩大有效 batch。

### 4. `global_step` 和 `tokens_seen`

它们分别描述更新进度和语言暴露量。

这四个量一旦稳定，你对训练系统的掌控感会明显提升。

## 这一章结束后你应该能稳定回答什么

至少你应该能清楚区分：

- sample 和 batch 的关系
- micro batch、effective batch 和 step 的关系
- step 与 epoch 的区别
- 为什么语言模型里 token count 往往比“样本条数”更关键

只要这些单位混着用，后面很多训练讨论都会继续模糊。把它们讲清，是训练分册真正的起点。
