# 02. 优化器到底在改什么

## 为什么很多人会把优化器误当成“最后顺手调一下的组件”

初学者第一次写训练代码时，常会把这些步骤记成固定模板：

```python
loss.backward()
optimizer.step()
optimizer.zero_grad()
```

然后觉得优化器大概只是模板里的一个名字。

这是不够的。

因为训练过程中真正让模型变好的，不是 loss 这个数字本身，而是：

> 参数如何根据误差信号发生改变。

而决定“怎样改”的那一层机制，就是优化器。

## 先把三层对象分清楚：loss、gradient、update

训练时至少有三件事不能混在一起。

### loss

loss 回答的是：

> 现在模型错得多不多。

### gradient

gradient 回答的是：

> 每个参数朝哪个方向动，会更有希望让 loss 降下来。

### update

update 回答的是：

> 那么这次到底要把参数改多少、按什么规则改。

优化器主要站在第三层。

它不是在定义任务，也不是在计算梯度，而是在决定：

> 如何把梯度真正转成一次参数更新。

## 最朴素的更新规则：顺着负梯度走一步

如果先不管现代优化器的复杂性，一个最基础的想法是：

\[
\theta \leftarrow \theta - \eta \nabla_\theta L
\]

这里可以直觉地读成：

- `\theta` 是参数
- `\nabla_\theta L` 是 loss 对参数的梯度
- `\eta` 是步长，也就是学习率

这个式子表达的思想非常简单：

> 如果梯度告诉你朝某个方向会让 loss 变大，那就往反方向走一点。

这就是最基本的梯度下降思路。

## 为什么“往反方向走”还远远不够

如果现实训练真这么简单，那优化器就不会成为一个专门主题了。

真正困难的地方在于：

- 梯度会有噪声
- 不同参数的尺度不同
- 不同时刻的训练状态差异很大
- 一味照当前梯度生硬地走，可能很不稳定

所以更成熟的优化器要解决的不只是“方向”，还包括：

- 如何平滑震荡
- 如何适应不同参数尺度
- 如何在早期和后期采用更合理的更新行为

## 可以把优化器想成“参数更新策略”

这是最实用的理解。

不要把优化器只看成一个类名，而要看成：

> 一组把梯度加工成实际更新的规则。

这组规则至少要回答：

- 当前梯度要不要直接照单全收
- 过去几步的梯度信息要不要记住
- 某些参数是不是应该更保守
- 权重衰减该怎样加入

所以优化器的差异，本质上是：

> 不同的参数更新哲学。

## 为什么随机小批量训练会让优化器更重要

在理想化情形里，如果你每次都能看到整个数据分布的真实平均梯度，更新会相对更干净。

但实际训练常常不是这样。

我们通常只看一个 batch，或一组累积 batch。

这意味着当前梯度往往只是：

> 对整体训练目标的一个带噪声近似。

所以优化器不仅在“执行更新”，也在帮助你：

- 对抗梯度波动
- 把短期噪声和长期方向区分开
- 让训练过程更稳定

## SGD 为什么重要，即使你最后常用的是 AdamW

很多小型 LLM 项目最后会用 AdamW，但 SGD 仍然值得先理解，因为它最能暴露更新本质。

SGD 的核心精神是：

> 在一个小批量数据上估计梯度，然后沿负梯度方向更新。

它让你清楚看见训练最底层的形态：

- 数据给出误差
- 误差生成梯度
- 梯度推动参数移动

后面的更复杂优化器，本质上都建立在这个骨架之上。

## 为什么 Adam / AdamW 会在语言模型训练里这么常见

因为它们在实际深度学习中通常更稳、更省心，尤其对初学者和中小规模实验很友好。

直觉上，Adam 一类方法在做两件很有帮助的事：

### 第一，记住梯度的移动平均

它不会只看这一瞬间的梯度，而是会结合过去一段时间的信息，帮助更新更平滑。

### 第二，按参数维度自适应地缩放步长

不同参数维的梯度尺度可能差异很大。Adam 类方法会在一定程度上自动调节：

- 某些维走得更谨慎
- 某些维走得更果断

这会显著提升早期训练的可用性。

## 为什么 AdamW 比 “Adam 加一点 weight decay” 更值得单独提

很多初学者会以为：

> AdamW 不就是 Adam 再随便加个正则项吗？

但工程上之所以常把 AdamW 单独拿出来，是因为：

> 权重衰减怎样与自适应更新结合，并不是一个无关紧要的实现细节。

你现在不必先记复杂推导，但要先知道：

- weight decay 不只是“防过拟合口号”
- 它会参与参数更新规则
- 把它处理得更清楚，通常有助于训练行为更可控

这也是为什么现代训练里常会直接说“用 AdamW”，而不是模糊地说“Adam 再带点正则”。

## weight decay 到底在补什么

最实用的理解是：

> 它在给参数施加一种不要无边界膨胀的压力。

如果没有这种约束，某些参数可能会在训练中越长越大，带来：

- 泛化变差
- 数值不稳
- 表示过度依赖某些大权重

但要注意，weight decay 不是万灵药。它不能替代：

- 合理数据
- 合理学习率
- 合理模型结构

它更像是一种辅助性的更新约束。

## 优化器为什么和学习率不能分开谈

这是很多人第一次调训练时最容易误解的一点。

他们会问：

> 我到底该先选哪个优化器？

更准确的理解应该是：

> 优化器定义更新规则，学习率定义更新幅度；两者共同组成训练动力学。

同一个优化器在不同学习率下，可能表现得像完全不同的训练系统。

因此：

- 不是 “优化器选对了就行”
- 也不是 “学习率单独调一调就行”

它们必须放在同一张图里理解。

## 优化器在训练日志里真正影响什么

虽然优化器本身不会直接出现在模型结构里，但它会深刻影响你看到的训练现象：

- loss 下降是否平滑
- 早期训练是否容易发散
- 相同步数下收敛速度如何
- 后期是否容易卡住

如果你发现：

- loss 大幅震荡
- 明明梯度有值，模型却像学不动
- 换个学习率后行为突然完全不同

那就说明你观察到的，往往不是“模型结构自己在说话”，而是：

> 结构、优化器和学习率共同作用后的结果。

## 对小型语言模型学习项目来说，应该怎样理解优化器选择

一个很务实的结论是：

### 第一，不要把优化器家族比较当成最前期重点

你一开始最重要的是先理解：

- 更新发生在哪里
- 参数是不是在真的改变
- 学习率和 loss 是否在健康互动

### 第二，使用成熟默认值是合理的

对于小型 decoder-only 学习项目，AdamW 往往是一个很稳妥的起点。

这不是因为它“永远最优”，而是因为：

- 它足够常见
- 文档和经验较多
- 对学习项目来说，先把其余链路做对更重要

### 第三，把优化器看成训练协议的一部分

它不是可以最后随便替换的装饰品，而是训练定义里的核心一环。

## 初学者最常见的三个误区

### 误区一：loss 会自己让模型变好

不会。loss 只是度量，真正改变参数的是优化步骤。

### 误区二：只要调用了 `optimizer.step()` 就等于训练正常

不对。如果：

- 梯度没算对
- 学习率不合理
- 更新顺序错了

那参数虽然在动，不代表是在朝正确方向动。

### 误区三：优化器只是“框架推荐值”

也不对。它本质上是在定义模型怎样吸收误差信号。

## 这一章结束后你最该稳住的理解

至少应该稳住下面这条链：

1. loss 告诉你现在有多错  
2. gradient 告诉你往哪边改更可能变好  
3. optimizer 决定这次到底怎么改、改多少  

只要这条链清楚，后面进入学习率、warmup 和稳定性技巧时，你就不会再把它们看成孤立技巧，而会把它们看成同一套训练动力学的不同部分。
