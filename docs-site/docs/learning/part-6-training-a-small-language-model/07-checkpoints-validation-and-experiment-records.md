# 07. checkpoint、验证集与实验记录

## 这些内容不是“训练完再补的工程外壳”，而是训练本体的一部分

很多初学者第一次做语言模型训练时，会天然地把下面这些事情排到非常后面：

- 保存 checkpoint
- 跑验证集
- 记录训练日志
- 管理实验配置

仿佛真正重要的是：

- 模型结构
- 优化器
- 学习率
- 数据

而 checkpoint、验证和日志只是“等训练跑起来以后再说”的包装层。

这种理解会让你在真正训练时很快陷入混乱。

因为如果没有这些机制，你几乎无法稳定回答下面这些最基本的问题：

- 当前训练到底已经进行到哪里
- 这一次最好的结果出现在第几步
- loss 下降是训练集独有现象，还是验证集也在变好
- 中断之后怎样续训才算真正续上
- 两次实验到底改了什么、差了什么

也就是说，这些内容并不是训练结束后的附加礼仪，而是：

> 让训练过程能够被观察、被恢复、被比较、被解释的核心基础设施。

如果把训练看成一个完整系统，那么：

- 优化器在定义参数如何移动
- 学习率在定义移动节奏
- checkpoint、验证集和实验记录则在定义：这条移动轨迹能不能被你看懂、保存下来并拿来比较

这就是为什么本章必须放在训练卷里，而不是放到文档末尾当成杂项附录。

## 先问一个最现实的问题：如果训练中断，你剩下什么

训练语言模型是一件耗时且资源受限的事。

哪怕是小模型，你也很可能遇到：

- 电脑休眠
- 进程被杀
- 显存异常
- 代码改动需要重启
- 想中途切换策略

这时真正的问题不是：

> 训得顺不顺。

而是：

> 如果它现在停了，我手里到底保留了什么？

如果你没有 checkpoint，没有日志，没有配置记录，那么训练一旦中断，你留下的可能只有：

- 一些模糊印象
- 一段屏幕截图
- 记不太清的 loss 数字

这几乎等于什么都没留下。

而一旦你有了完整 checkpoint 和实验记录，中断就不再意味着“从零重来”，而更像是：

> 当前训练轨迹被暂停了，我可以从某个明确状态接回去。

所以 checkpoint 的第一个意义，不是备份，而是：

> 让训练过程拥有时间连续性。

## checkpoint 到底在保存什么

初学者一听到 checkpoint，最容易想到的是：

> 把模型权重存一下。

这只说对了一部分。

更完整的说法是：

> checkpoint 保存的是某一时刻的训练状态快照。

这个“训练状态”至少应该包括：

- 模型参数
- 优化器状态
- 当前 step 或全局更新计数

很多时候还应该包括：

- 学习率调度器状态
- 当前 best 验证指标
- 随机种子或相关上下文
- 配置元信息

如果缺了这些东西，你保存的就不再是“训练状态”，而只是“部分模型状态”。

这两者差别非常大。

## 为什么只保存模型权重往往不够

这是学习项目里最高频的误区之一。

很多人会觉得：

> 反正模型最重要，只要 `model.state_dict()` 在，后面就都能接上。

这个判断对“只做推理”也许够用，但对“继续训练”经常不够。

为什么？

因为训练不只依赖当前参数值，还依赖：

- 优化器内部已经积累的统计
- 学习率调度当前处在哪个阶段
- 训练已经走到了第几步

如果你只恢复模型权重，而把其余状态都丢掉，那么恢复后的训练会变成一种很别扭的混合体：

- 模型知道自己在哪
- 训练器却忘了自己之前是怎么走到这里的

这会带来非常真实的后果。

例如：

- 动量类优化器像突然失忆
- AdamW 内部统计从头来过
- warmup / decay 节奏对不上
- 恢复后 loss 气质明显变怪

所以“只保存模型参数”严格来说不算完整续训，它更像：

> 从一个旧参数点重新开始一种部分重置的训练。

## 优化器状态为什么必须被视为训练历史的一部分

上一章你已经学过：

> 优化器不是一个静态公式，而是带内部状态的更新系统。

这点在 checkpoint 里尤为重要。

以 AdamW 为例，它内部会维护与每个参数相关的统计信息。即使你现在不深入所有数学细节，也应该知道：

> 这些内部统计决定了“下一步怎么走”。

所以如果你保存了参数、却没有保存优化器状态，那么恢复后虽然模型参数值一样，但：

- 下一步更新的行为已经不一样了

这就像你把一辆正在行驶中的车的位置复原了，却把它的速度、方向盘状态和惯性全部清空，然后说“这还是同一段驾驶过程”。

显然不是。

因此，优化器状态不是辅助信息，而是：

> 训练轨迹的一部分。

## step 为什么不是普通日志数字，而是真正的状态

很多人第一次记录 step 时，会把它看成纯展示字段：

> 就是日志里那个方便看的计数器。

这同样不够准确。

在一个真实训练系统里，step 往往决定了很多事情：

- 当前学习率调度走到哪里
- warmup 是否结束
- 下次什么时候评估
- 下次什么时候保存 checkpoint
- 当前累计已经看了多少 token

也就是说，step 不只是用来“显示训练进度”，它实际上在参与控制训练节奏本身。

所以如果恢复训练时 step 丢了，很多看似独立的逻辑都会错位。

这就是为什么一个真正可恢复的 checkpoint，通常必须保存：

> 当前全局 step 或其他能恢复训练节奏的等价状态。

## 调度器状态为什么也常常必须保存

如果你的训练里用到了：

- warmup
- cosine decay
- linear decay
- milestone 调度

那么调度器就不仅仅是一个初始化阶段的配置项，而是：

> 训练全过程里的时间函数。

一旦你中途恢复，却没有恢复调度器状态，就可能出现：

- 参数是旧的
- optimizer state 是旧的
- 但学习率节奏突然变成新的

这等于把训练轨迹在动力学上接错了。

所以在使用 scheduler 的训练里，恢复 checkpoint 时必须认真问一句：

> 我恢复的，到底只是模型和优化器，还是连训练节奏也一起恢复了？

如果后者没有做到，就不能算真正续训。

## 为什么验证集不是“训练结束后的验收”，而是训练过程中的导航仪表

现在从保存状态转到“判断当前训练是不是在变好”。

很多初学者最开始只盯着训练 loss，看着它下降就觉得：

> 模型正在变好。

这是一种非常危险的简化。

因为训练集上的 loss 下降只说明：

> 模型越来越会拟合自己已经见过、并参与过参数更新的数据。

它并不自动说明：

> 模型对未参与当前更新的数据也在同步变好。

这正是验证集存在的意义。

验证集的职责不是给训练结束后发成绩单，而是：

> 在训练过程中持续提醒你，当前模型到底是在学会泛化，还是只是在越来越熟悉训练集。

## 为什么训练损失和验证损失必须一起看

这是整个训练判断体系里最核心的一组对照。

### 训练损失回答的是

> 模型在用于参数更新的数据上，现在拟合得怎样。

### 验证损失回答的是

> 模型在没有参与这一步参数更新的数据上，表现是否也在改善。

只看训练损失，你很容易发生下面这种误判：

- 训练 loss 一直降
- 于是你觉得模型越来越强

但真实情况可能是：

- 训练 loss 继续降
- 验证 loss 已经停滞甚至变坏

这时模型并不是“继续学得更好”，而更可能是：

> 在进一步挤压训练集，却没有把这种改进转移到未见数据上。

因此，一个成熟训练流程不会只记录训练损失，还会明确规定：

- 每隔多少 step 跑一次验证
- 用哪一份固定验证数据
- 以什么指标判断“目前最好”

## 为什么验证集必须尽量固定

有些初学者会在每次验证时随便抽一批样本，然后觉得“差不多能看趋势”。

这在某些粗略 smoke test 里也许勉强够用，但一旦你想真正比较实验，很快就会出问题。

因为如果验证样本每次都变，那么你看到的波动里混杂了两种东西：

- 模型自己真的变了
- 验证集合成本身也变了

这会大幅削弱你对训练趋势的判断能力。

所以更成熟的做法通常是：

> 让验证集在一次训练过程中尽量固定，至少保证比较是在同一把尺子上发生的。

这就是为什么验证不是“随便测测”，而是：

> 用固定参照系持续照镜子。

## 为什么 checkpoint 和验证集常常会绑定在一起

一旦你理解了验证集的作用，就会自然明白为什么训练系统经常会同时维护：

- latest checkpoint
- best validation checkpoint

因为“最近一次保存”和“最值得保留的一次保存”未必是同一个东西。

例如：

- 第 10,000 step 是最近一次
- 第 8,400 step 的验证损失却最好

如果你的目标是：

- 恢复最新训练进度

那 latest 更重要；

如果你的目标是：

- 挑出当前泛化最好的模型用于推理或后续分析

那 best validation checkpoint 更重要。

因此 checkpoint 策略从来不是单一问题，而是两个问题耦合：

1. 我怎样保存训练进度  
2. 我怎样判断哪份状态最值得保留  

而第二个问题通常正是验证集在回答。

## 训练记录为什么不是“好看图表”，而是理解训练因果的基础

接下来谈实验记录。

很多初学者对“记录实验”这件事的第一印象是：

> 这是团队协作或工业平台才需要的东西。

实际上，只要你在做任何超过一次的训练尝试，它就已经是必要能力。

为什么？

因为一旦你调整了：

- learning rate
- warmup
- gradient accumulation
- context length
- tokenizer
- dropout

你就已经在进行实验比较了。

如果你没有留下系统化记录，那么后面你很容易陷入这种状态：

> 我记得上一次好像更稳，但我记不清当时到底改了什么。

这并不是小问题，而是会直接阻断学习。

因为没有记录，你就无法把：

- 直觉印象

变成：

- 可验证的因果比较。

## 一个最低限度有用的实验记录应该包含什么

你当然不需要一开始就搭一整套工业实验平台。

但一个足够好的学习项目，至少应该留下下面这些可追溯信息：

- 训练开始时间
- 当前代码版本或配置版本
- 模型配置
- tokenizer 或词表信息
- 训练超参数
- train / validation 指标曲线
- checkpoint 保存点
- 当前 best checkpoint 对应的指标

只要这些信息齐全，你之后就能真正回答：

- 这次训练为什么比上次稳
- 哪一次崩坏是从哪一步开始的
- 为什么某个 checkpoint 值得保留

而不是只剩下模糊印象。

## 为什么“我大概记得那次训练更好”几乎没有研究价值

人的记忆在训练调参这件事上非常不可靠。

假设你同时改了：

- 学习率
- accumulation
- 序列长度

然后只凭印象说：

> 上次那个版本好像更稳。

这个结论几乎没有可操作性，因为你不知道：

- 是哪一个因素导致改善
- 是否只是验证样本不同
- 是否只是训练步数不一样
- 是否只是当时 loss 看起来更好看

而实验记录的作用恰恰就在于：

> 把“我感觉”替换成“我能对照出哪些条件变化导致哪些指标变化”。

这就是为什么记录不是形式主义，而是训练学习能力的一部分。

## 什么叫可恢复训练

很多人会说：

> 我有 checkpoint，所以训练可恢复。

这句话经常说得太快。

真正的“可恢复训练”应该意味着：

> 如果训练现在中断，我能够以尽量接近中断前的训练状态继续下去，而不是只从一个看起来像的参数点重新开始。

这通常要求至少做到：

- 模型参数恢复
- 优化器状态恢复
- scheduler 状态恢复
- step 恢复
- 训练配置明确

如果 इनमें缺了一块，你得到的很可能只是：

- 模型参数继续用

而不是：

- 同一段训练轨迹真正延续

这两者不要混淆。

## 为什么配置记录和 checkpoint 一样重要

有些人把 checkpoint 看得很重，却低估了配置记录。

这会导致一种很尴尬的情况：

> checkpoint 文件还在，但你已经说不清它到底是怎么训练出来的。

例如你可能不知道：

- 当时用的词表大小
- context length 是多少
- warmup 持续多久
- accumulation 是几步
- 是否开了 AMP

这时 checkpoint 虽然还“存在”，但它的可解释价值已经大幅下降。

所以一个真正成熟的训练系统会把：

- 张量状态

和：

- 配置背景

一起视为实验资产。

## 为什么数据版本信息也应该被记录

对语言模型来说，数据不仅是“有没有”，而是：

- 用了哪份语料
- 哪个切分版本
- 哪个 tokenizer
- 哪些过滤和规范化策略

一旦这些东西变了，训练结果就可能发生本质差异。

所以在实验记录里，只记模型超参数而不记数据侧关键信息，通常是不够的。

更准确的做法是至少能回答：

> 这次训练到底是在什么数据定义之上发生的？

否则你后面即使能重放代码，也未必能真正复现实验。

## latest、best、periodic checkpoint 分别在服务什么

很多训练系统会同时维护几类 checkpoint。

### latest checkpoint

服务于：

> 中断恢复和继续训练。

它回答：

> 如果现在断了，我从哪接上最快？

### best checkpoint

服务于：

> 按验证指标挑出当前最值得保留的模型状态。

它回答：

> 到目前为止，哪一步泛化表现最好？

### periodic checkpoint

服务于：

> 做更细粒度回溯、对比和阶段分析。

它回答：

> 如果我想回看第 2k、4k、6k step 附近发生了什么，我有没有状态可用？

这三类保存各有作用，并不是互相替代关系。

## 为什么“只保存 best”并不总够用

有些人觉得：

> 既然最终只关心最优模型，那我只保存 best checkpoint 就好了。

这对某些很短的小实验也许勉强够，但一旦训练中断或你想继续训练，就会暴露问题。

因为 best checkpoint 未必是：

- 最新状态
- 最适合继续训练的状态

所以如果你只保存 best，却不保存 latest，你可能会丢失训练续航能力。

反过来，如果你只保存 latest，却不标 best，又会让你很难知道：

> 当前最值得拿去评估或部署的到底是哪份状态。

因此两者通常都应该有。

## 为什么验证频率本身也是训练策略的一部分

验证不是“有空就跑一下”，它本身也是训练系统设计的一部分。

如果你验证太少，问题会是：

- 很久才发现过拟合
- 错过最好 checkpoint
- 对中期趋势不敏感

如果你验证太频繁，问题会是：

- 训练被大量打断
- 计算成本增加
- 小实验里时间被监控开销吃掉

所以验证频率本质上是在平衡：

- 观察密度
- 训练吞吐

对小型学习项目，通常要找到一个：

> 足够经常看到趋势、又不至于让评估本身过重的折中频率。

## 为什么“验证集更好”不一定自动等于“生成质量一定更好”

这一点也需要成熟对待。

验证损失通常是非常重要的指标，但它并不是唯一现实目标。

因为语言模型最终常常还要看：

- 生成样例
- 重复问题
- 停止行为
- 风格和连贯性

所以更准确的理解是：

> 验证集是训练过程中最关键的泛化镜子之一，但它仍然需要和后面的推理观察结合起来看。

这也解释了为什么后面的推理与评估卷还会继续展开这些内容。

不过即便如此，验证集仍然不能省，因为：

> 没有它，你连最基础的“训练集进步有没有转化成未见数据进步”都无法判断。

## 为什么日志是训练理解力的一部分

日志的价值不只是“看起来更专业”，而是让训练从黑箱变成可观察过程。

对学习项目，至少值得持续记录：

- step
- train loss
- validation loss
- learning rate
- grad norm
- tokens seen
- checkpoint 保存事件

这些日志让你能够回头回答：

- 什么时候开始真正下降
- 哪一步之后开始不稳
- 学习率变化是否对应了 loss 行为变化
- 验证最优点和训练最优点是不是同一步

没有日志，你就很难形成真正可检验的解释。

## 为什么图表不是装饰，而是时序理解工具

数值表格当然有用，但训练很多重要现象是时序性的：

- warmup 后有没有变稳
- decay 后验证是否改善
- 某个 checkpoint 前后是否出现梯度尖峰

这些问题在图表上往往更容易看清。

所以画曲线不是为了汇报好看，而是为了获得：

> 对训练轨迹形状的直觉。

而训练理解力的一大部分，本来就来自你是否能读懂：

- 曲线什么时候是正常波动
- 什么时候已经在慢慢坏掉

## 为什么训练记录也要覆盖失败实验

很多初学者只愿意保留“成功的那次”，失败实验就想直接删掉。

这会丢失很多真正有学习价值的东西。

失败实验往往告诉你：

- 哪个学习率太激进
- 哪个 AMP 路径不稳
- 哪种数据处理会出问题
- 哪个 checkpoint 策略不够用

所以更成熟的实验文化应该是：

> 不只是记录成功配置，也记录那些明确证明“不该这么做”的失败配置。

这也是知识档案与单次实验笔记的差别所在。

## checkpoint 为什么也服务于调试，而不只是续训

很多时候你需要 checkpoint，并不是为了把整场训练跑完，而是为了：

- 回放某个阶段的模型行为
- 比较早期和中期输出差异
- 确认某次崩坏是不是从某一阶段开始埋下问题

这说明 checkpoint 在训练里还有另一重意义：

> 它是训练时间轴上的“状态采样点”。

没有这些采样点，你只能看最终结果，很难理解训练到底经历了什么。

## 对小型学习项目来说，什么算“足够好的训练基础设施”

你当然不需要一上来就复刻工业平台。

但一个足够好的入门标准至少应该做到：

- checkpoint 可以恢复训练
- 有 latest 和 best 两类状态
- 日志里能看到核心指标
- 配置与数据关键信息可回溯
- 验证集固定且定期评估

只要这几件事做到了，你就已经拥有了：

> 一套真正可观察、可恢复、可比较的小型训练系统。

这比“只会跑一遍然后截图”强很多，而且这正是初学者最应该尽快建立的习惯。

## 为什么这章和前面几章必须连起来读

本章不是在和前面的优化器、学习率、稳定性章节平行列举。

它实际上是在补：

> 当前这套训练动力学，怎样被你保存、观察和比较。

前面几章讲的是：

- 参数怎么改
- 训练怎么起步
- 不稳定怎样被控制

而本章讲的是：

- 这些过程怎样被长期追踪
- 中断后怎样真正续上
- 哪个阶段的状态最值得保留
- 哪些实验结论是可以复现和比较的

只有把它们放到一起，你才会真正把“训练”理解成一个系统，而不是几段零散代码。

## 常见误区

### 误区一：只保存模型参数就等于能恢复训练

不对。

完整续训通常还需要优化器、scheduler、step 等状态。

### 误区二：验证集是训练结束后才需要看的

不对。

验证集是训练过程中判断泛化是否在同步改善的核心仪表。

### 误区三：日志只是为了画好看的图

日志本质上是在提供训练时序证据。

### 误区四：只记录成功实验就够了

失败实验往往同样重要，因为它们告诉你边界在哪里。

### 误区五：checkpoint 只是保险，不是学习工具

实际上它也在帮助你回看训练不同阶段的状态和行为。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> checkpoint、验证集和实验记录不是训练外壳，而是训练系统能够被恢复、被观察、被比较、被解释的基础设施；没有它们，你也许偶尔能把模型训起来，但几乎无法真正理解这次训练为什么有效、哪里最好、下次如何复现。

## 练习题

1. 为什么只保存 `model.state_dict()` 通常不足以称为“可恢复训练”？
2. 为什么优化器状态、step 和 scheduler 状态都应该被视为训练状态的一部分？
3. 为什么验证集不是训练结束后的验收，而是训练过程中的导航仪表？
4. latest checkpoint 和 best validation checkpoint 各自服务什么目标？
5. 为什么实验记录必须包含配置和数据定义，而不仅仅是 loss 曲线？
6. 为什么失败实验同样应该被记录下来？
7. 为什么 checkpoint 同时服务于续训、比较和调试？

## 自测问题

如果现在不看任何代码，只让你用自然语言解释下面三件事，你应该能够尽量稳定地讲清楚：

- 为什么一个真正可恢复的训练系统保存的是“训练状态”，而不是单独的模型权重
- 为什么验证集和 checkpoint 天然会绑在一起，形成“保存什么”和“哪份值得保留”的双重逻辑
- 为什么实验记录不是为了写报告，而是为了让训练结论具有因果可比性和复现能力

如果这三件事还讲不顺，就说明你对训练的理解仍然停留在“把 loss 跑下来”层面，而没有真正进入“把训练变成一条可追踪轨迹”的层面。
