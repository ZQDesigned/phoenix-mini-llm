# 学习主线总览

这一部分不是项目说明书，也不是源码导读。它是一套面向初学者的、按顺序展开的大语言模型基础知识档案，目标非常明确：

> 让一个从 0 开始学习的人，在完整读完这 12 章之后，真正理解做出一个小型 decoder-only 语言模型所需要的核心基础，而不是只会照着命令把现成仓库跑起来。

这里的“基础”不是几个术语的罗列，而是你能真正解释：

- 语言模型到底在做什么。
- 文本为什么不能直接输入模型。
- token、embedding、hidden state、logits 各自是什么。
- 为什么训练目标是 next-token prediction。
- 为什么需要 Attention、Transformer Block、位置编码、归一化和残差连接。
- 为什么训练、推理、评估和调试都是模型学习过程的一部分。

## 这一部分不做什么

这部分内容刻意不把重点放在：

- 某个仓库的文件树。
- 某个脚本的命令行参数。
- 某个函数名或类名。
- 某个具体项目的工程约定。

这些内容当然重要，但它们属于：

- [复刻教程](/tutorials)
- [踩坑记录](/pitfalls)

学习主线的职责是先帮你建立“通用理解”。这样你在后面看任何一个小型 LLM 项目时，都不会被表面的工程组织带着跑。

## 这一部分适合谁

它适合以下读者：

- 会一点 Python，但从未自己实现过语言模型的人。
- 听过 Transformer、Attention、Tokenizer 这些词，但还没有形成稳定理解的人。
- 能看懂一段 PyTorch 代码，却无法把它放进完整训练链路中的人。
- 想亲手做一个小型语言模型，而不是只想启动别人的现成项目的人。

如果你完全没有 Python 基础，建议先补最基本的：

- 变量、函数、类、模块导入
- 终端执行命令
- 基本文件路径概念

## 为什么学习一个“小”模型反而更合理

很多初学者一上来就把目标理解成：

> 我要自己从 0 训练一个很大的模型。

这通常会让学习过程立刻失真。因为你会同时被下面这些问题压住：

- 显存不够
- 训练太慢
- 数据处理太重
- 工程复杂度陡增
- 很多问题根本看不清

一个学习项目更合理的目标是：

> 做出一个小而完整、概念清楚、每一层都能讲明白、每一个环节都能自己修改的小型语言模型。

这类模型的价值在于：

- 你能真正看懂每个组成部分。
- 你能在合理时间内完成训练和生成闭环。
- 你能自己定位错误，而不是把所有异常都归因于“模型太大太复杂”。

## 学习主线和复刻教程是什么关系

你可以把整个文档站理解成两层内容：

- `学习主线` 负责讲“为什么”。
- `复刻教程` 负责讲“怎么一步步做出来”。

两者缺一不可。

如果你只读学习主线，不动手做项目，你会停留在“我看懂了概念”的阶段。

如果你只看复刻教程，不建立概念地基，你会停留在“我可以照着抄，但不会独立判断”的阶段。

正确的使用方式通常是：

1. 顺序读学习主线前 8 章，把基础概念打稳。
2. 开始进入复刻教程，亲手实现项目。
3. 在复刻过程中遇到问题时，再回来看后面的训练、推理、调试章节。

<Callout title="推荐的阅读方式" tone="note">
  学习主线应该像读一本入门教材一样顺序阅读，而不是当词典查。复刻教程则应该像实验手册一样边读边做。先建立模型，再进入项目，学习效率会高很多。
</Callout>

## 你读完之后应该达到什么标准

如果这套知识档案真的起作用，读完后你至少应该能做到：

- 用自己的话解释语言模型为什么是在学“下一个 token 的条件分布”。
- 看到 `input_ids`、`embedding`、`hidden state`、`logits` 等对象时，知道它们的含义和形状。
- 解释为什么 tokenizer、special token、上下文长度和词表大小都不是小细节。
- 说清楚 Attention、位置编码、残差、归一化、FFN 分别在做什么。
- 理解训练、推理、评估与调试之间的关系，而不是把它们看成互不相干的步骤。

如果你读完之后仍然只能说“我听过这些名词”，那说明你还没有真正把知识吸收成自己的判断。

## 这部分内容的定位是什么

它不是论文替代品，但也不是一页式摘要。

它追求的是：

> 只保留一个初学者从 0 到能做出小型语言模型所必须理解的内容，并把这些内容讲到足够慢、足够细、足够能落地。

所以你会看到这里既不会为了炫技去塞过多高级主题，也不会为了“简洁”而把关键概念压成一句话。

## 现在该从哪里开始

如果你准备正式进入这条学习路线，直接从 [01. 你到底在做什么](/learning/01-what-you-are-building) 开始。

如果你已经进入复刻过程，但发现自己在某一层反复卡住，就回到对应章节把概念补稳。对于学习项目来说，最宝贵的成果从来不是“跑通一次”，而是：

> 你真的知道自己在做什么，以及为什么这样做。
