# 05. 从 token 流到固定长度训练样本

## 语料切成 token 之后，为什么还不能直接训练

很多人第一次完成 tokenizer 之后，会本能觉得：

> 文本已经变成 token id 了，那现在是不是直接喂给模型就行？

还不行。

因为此时你得到的往往只是：

- 一篇篇文档的 token 序列
- 或一条很长的 token 流

而模型训练真正需要的是：

> 一批形状整齐、长度可控、能直接组成张量并计算监督目标的样本。

这就是为什么从 token 流到训练样本，仍然需要一层额外组织。

## 为什么训练通常偏爱固定长度样本

现实文本长度天然不一致：

- 一句评论可能很短
- 一篇文章可能很长
- 对话轮次长度也很不稳定

但训练时，如果每个样本长度都任意不同，会带来很多麻烦：

- batch 很难高效组织
- 张量形状不整齐
- Attention 成本不好控制
- 显存使用不稳定

因此在语言模型训练里，一个常见策略是：

> 把 token 流组织成固定长度的连续块。

这样模型每次看到的就是统一长度 `L` 的上下文片段。

## “固定长度”并不意味着“自然语言天然这样分段”

这点很重要。

模型看到的训练块，很多时候并不是人类语义上天然完整的一句或一段，而是：

> 从连续 token 流中切出来的一段固定窗口。

这说明训练样本边界并不总等于语言边界。

这么做并不是因为模型“不需要语义边界”，而是因为：

- 固定长度更利于训练效率
- 语言模型本来就在学局部条件延续
- 长文也可以通过许多连续片段被局部覆盖

## 两种常见组织方式：按文档切块与跨文档拼接

### 按文档独立切块

每篇文档各自 token 化，再从内部切出固定长度样本。

优点是：

- 文档边界更清楚
- 不容易在样本里混入跨文档断裂

代价是：

- 末尾往往有剩余 token
- 利用率可能不高

### 跨文档拼接成连续 token 流

把多篇文档连接起来，再整体切块。

优点是：

- token 利用率更高
- 实现上更适合流式处理

代价是：

- 需要更明确地处理边界标记
- 如果边界管理不好，模型可能把本不相关的文档连续性也学进去

两种方法都能工作，关键不在于哪一个绝对正确，而在于：

> 你是否清楚样本是怎样被定义出来的，以及这种定义会让模型学到什么。

## 为什么 BOS、EOS 与分隔符会在这里变得重要

一旦你开始拼样本边界，就必须明确：

- 序列开始在哪里
- 序列结束在哪里
- 不同文档或不同段落之间是否需要显式标记

这时 special token 就不再只是词表中的几个特殊项，而是直接参与了训练样本组织。

例如：

- EOS 可以告诉模型一段文本在这里收束
- 分隔符可以告诉模型这里发生了结构切换

如果边界完全不做管理，模型会更难学到：

- 什么时候应该自然停下
- 什么是文档间的不连续

## 为什么 batch 需要同形状张量

深度学习框架在做并行训练时，通常希望一个 batch 里的样本能堆成一个整齐张量。

如果每个样本长度都不同，就必须：

- pad 到相同长度
- 再配合 mask 告诉模型哪些位置是真实内容、哪些只是占位

而对于自回归小模型训练，许多实现会直接使用固定长度块，这样可以减少额外复杂度。

所以“固定长度样本”首先是一个非常实用的训练工程选择。

## 为什么上下文长度是样本组织的硬约束

设样本长度为 `L`，那么模型训练时一次最多就只能看到这 `L` 个位置的上下文关系。

这意味着：

- 样本长度越大，单样本可见上下文越长
- 但 Attention 成本和显存消耗也会更高

因此样本长度不是一个纯数据处理参数，而是：

> 数据组织方式与模型计算成本之间的共同边界。

很多训练配置之所以要保守上下文长度，根本原因就在这里。

## 样本打包其实在提前规定模型“如何看世界”

这是一种非常值得建立的系统视角。

当你决定：

- 文档怎样拼接
- 是否保留边界
- 样本长度多大

你实际上已经在规定：

> 模型一次通常会在怎样的上下文窗口里学习语言延续。

例如，如果样本长度很短，模型会更多学习局部延续。

如果样本长度更长，它就有机会利用更远的依赖关系。

所以样本打包并不是简单的工程流水线，而是建模定义的一部分。

## 训练样本常见的形状长什么样

在完成打包后，你通常会得到类似：

\[
[B, T]
\]

的整数张量。

这里：

- `B` 是 batch size
- `T` 是固定长度的 token 序列长度

注意此时还只是 token id 张量，不是模型内部的 `[B, T, H]` hidden state。

也就是说，样本组织发生在 embedding 之前。

## 从样本到监督目标还差最后一步

即使你已经有了固定长度 token 样本，训练仍然还没真正闭合。

因为模型不仅需要输入，还需要明确知道：

> 在这串 token 上，每个位置到底该为哪个目标负责？

这就引出了下一章：为什么训练目标会表现成“右移一位”。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> token 化之后的文本还不是训练样本；语言模型训练通常需要把连续 token 组织成固定长度、边界可控、可批量堆叠的样本块，而这种打包方式本身会影响模型一次能看多远、怎样理解文本连续性以及训练成本落在哪个量级。
