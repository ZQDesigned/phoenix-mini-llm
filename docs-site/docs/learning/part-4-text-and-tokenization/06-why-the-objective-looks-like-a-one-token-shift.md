# 06. 为什么训练目标表现成右移一位

## 最容易被误判成“切片技巧”的，其实正是任务定义本体

几乎每个刚开始写语言模型数据集的人，都会很快遇到类似这样的代码：

```python
inputs = tokens[:-1]
targets = tokens[1:]
```

很多人第一次看到这一行，会本能觉得：

- 这只是为了让两个数组长度一致
- 这只是为了方便后面算 loss
- 这只是某种常见的工程写法

这些理解都抓到了一点表面现象，但真正关键的地方却没被看见。

更准确的说法应该是：

> 这不是“方便切片”的写法，而是语言模型训练任务在数据层面的直接定义。

因为这一步同时决定了：

- 模型当前位置能看见什么
- 模型当前位置应该对哪个 token 负责
- 每个位置上的 loss 到底和哪个真实答案对齐

只要这层关系没有彻底讲清楚，后面很多看似复杂的内容都会一直带着雾：

- 为什么目标序列来自同一段文本，而不是外部人工标签
- 为什么 attention 必须加因果约束
- 为什么训练能在整段序列上同时算很多个位置的损失
- 为什么推理时模型只能一 token 一 token 地往后写
- 为什么训练 loss 不错，推理时却仍可能出现重复或跑偏

这一章要做的，就是把这条从目标定义到运行行为的链条系统讲透。

## 不要先说“模型会写文本”，先说“模型在每个位置上要预测什么”

很多日常描述都会说：

> 语言模型会根据前文生成一句话。

这句话在直觉层面没有错。
但如果你拿它来指导训练目标，就会显得太宽、太粗。

更精确也更有力量的定义是：

> 在序列的每一个位置上，模型都要根据左边已经出现的 token 历史，预测下一个 token 的条件分布。

这句话至少澄清了三件事。

### 第一，目标是按位置定义的

模型不是只在句子末尾做一次“大预测”。
它在每个可监督位置都要承担责任。

### 第二，预测对象是“下一个 token”

不是整段未来，不是整句摘要，也不是一个全局主题标签。

### 第三，模型首先学习的是分布，而不是唯一答案字符串

也就是说，模型要学的是：

- 在当前前缀下，哪些 token 更合理
- 哪些 token 较不合理

只要这三件事站稳，后面的“右移一位”就不会再显得像一种突兀的低级技巧。

## 为什么语言模型目标天然会落成 next-token prediction

这并不是谁拍脑袋发明出来的一种奇怪任务。

它之所以自然，是因为语言本身就带着一种非常适合自监督学习的结构：

- 一个 token 之后，总会接着另一个 token
- 一段前缀之后，总会接着某种更可能的后续

只要你手上有一段真实文本，你就已经隐含拥有大量监督事件：

- 看到当前位置左边的历史
- 右边真实出现的下一个 token 是什么

这意味着你不需要额外人工再去标：

- 这一句应该接哪个词
- 这一段应该接哪个字

因为文本本身已经把这种监督关系带在里面了。

所以 next-token prediction 的强大之处，不在于它看起来多复杂，而在于它同时满足了几件极其稀缺的事：

- 监督信号天然存在
- 目标形式统一
- 可以大规模扩展
- 不依赖人工标签

这也是为什么它会成为现代语言模型预训练的核心目标。

## 一条序列真正提供的，不是一个答案，而是很多个监督事件

这是初学者最容易忽略的一点。

很多人会下意识觉得：

- 我给模型一段前文
- 它预测一个后续

这个说法在单步推理上可以接受，但在训练上还不够。

因为训练时，一条序列通常不是只贡献一个监督目标，而是同时贡献很多个。

例如有序列：

```text
[BOS, A, B, C, EOS]
```

它提供的监督事件至少包括：

- 看到 `BOS`，预测 `A`
- 看到 `BOS A`，预测 `B`
- 看到 `BOS A B`，预测 `C`
- 看到 `BOS A B C`，预测 `EOS`

也就是说，一条序列不是“一次问题”。
它更像是一整排并排摆好的局部条件预测问题。

这件事非常重要，因为它解释了：

- 为什么一次前向可以同时产生很多个位置的 loss
- 为什么语言模型训练并不低效地只学一个 token
- 为什么右移一位后，整段序列里几乎每个位置都能成为监督点

## 从序列概率链式分解看，右移一位其实几乎是不可避免的

如果把语言模型写得更抽象一点，它在做的事情可以表述为：

> 学习整条序列的概率结构。

而一条序列的联合概率，天然可以被链式分解成一连串条件概率：

```text
P(x1, x2, x3, ..., xT)
= P(x1) * P(x2 | x1) * P(x3 | x1, x2) * ... * P(xT | x1...xT-1)
```

这个分解极其关键。

因为它告诉你：

- 如果我想学习整段序列的概率
- 我并不需要一次性发明“整段输出”
- 我只需要把每一步“给定历史预测下一项”的条件概率学好

一旦你接受这个分解，训练目标就会自然落成：

- 根据左边历史，预测右边下一 token

而把输入和目标序列错开一位，恰好就是在把这件事写成可以批量处理的张量形式。

所以“右移一位”并不是随手想出来的切片花招。
它几乎是：

> 用统一张量形式表达序列条件概率链式分解的最直接方法之一。

## 为什么输入和目标通常来自同一段序列

这件事对很多第一次学监督学习的人来说，很容易产生违和感。

因为在很多传统任务里，你习惯看到：

- 一份输入
- 一份外部标签

例如：

- 图片和类别标签
- 特征表和价格标签

而在语言模型里，你却会发现：

- 输入来自原始文本
- 目标也来自原始文本

这会让人忍不住问：

> 这是不是在“拿自己监督自己”？

答案是：从训练数据结构上看，确实可以这么理解。

但更准确的说法是：

> 文本序列本身天然携带了“前缀 -> 下一个 token”这种监督结构，因此目标不需要额外人工标注，就可以从同一段序列内部构造出来。

这正是自监督学习最有代表性的例子之一。

因此：

- 输入与目标来自同一段序列

不是偷懒，也不是投机，而是：

> 语言对象本身就允许这样构造监督。

## 一个最朴素的例子：为什么会出现 `tokens[:-1]` 和 `tokens[1:]`

假设你有如下 token 序列：

```text
[BOS, A, B, C, EOS]
```

如果训练目标是“根据历史预测下一 token”，那最自然的对齐关系就是：

- 输入：`[BOS, A, B, C]`
- 目标：`[A, B, C, EOS]`

你可以把它逐位置展开看：

| 输入位置可见历史 | 目标 token |
|---|---|
| `BOS` | `A` |
| `BOS A` | `B` |
| `BOS A B` | `C` |
| `BOS A B C` | `EOS` |

这样一来，每个输入位置上的隐藏状态，都可以被解释成：

> 基于当前位置及其左侧历史，对右侧下一个 token 的预测准备状态。

这正是右移一位的本质。

## 为什么“右移一位”不是写法偏好，而是责任对齐

如果你把这一步只看成：

- 把两个数组错开了一格

你还是低估了它。

更深的理解应该是：

> 右移一位是在给每个位置分配预测责任。

具体来说：

- 第 `t` 个位置的输入表示，应该为第 `t+1` 个 token 负责

这个责任分配关系一旦错掉，模型仍然可能训练，但训练目标就已经偏离。

例如可能出现的错误包括：

- 当前位置去预测自己
- 整个目标错位两格
- 最后一个位置责任丢失
- padding 位置误参与损失

因此，你看到的不是简单切片，而是：

- 一套位置到目标的精确责任映射

这就是为什么“右移一位”必须被当成任务定义，而不是当成代码习惯。

## 如果不右移一位，会发生什么

这个问题反过来问，反而很能暴露本质。

假设你不做右移，而让输入和目标完全相同：

```text
inputs  = [A, B, C, D]
targets = [A, B, C, D]
```

那模型在第一个位置就会被训练成：

- 看到 `A`，预测 `A`

这显然不是我们要的 next-token prediction。

甚至更糟的是，如果模型在某种实现里能直接利用当前位置 token 自身信息，它会更倾向学一种近似复制任务，而不是条件续写任务。

因此，只要你的目标是：

- 基于过去预测未来

那么“把未来一位对齐到当前位置责任上”几乎就是必须的。

## 为什么因果约束会自然跟着右移目标一起出现

一旦你说：

> 当前位置负责预测右边的下一个 token

就立刻会出现一个强约束：

> 当前位置在形成表示时，不能偷看未来 token。

否则会怎样？

如果当前位置在计算过程中已经直接看到了真实未来，那么训练目标就会变得不诚实：

- 模型不是在学“根据历史预测未来”
- 而是在学“带着未来信息去复述未来”

这当然会污染整个任务。

因此，右移目标和因果 mask 并不是两个碰巧总一起出现的技巧。
它们其实在共同服务同一个定义：

- 当前位只能用左侧历史
- 当前位要对右侧下一个 token 负责

所以：

- 右移目标负责定义“该预测谁”
- 因果 mask 负责限制“能看见谁”

这两者缺一不可。

## logits 在这里到底扮演什么角色

训练时，模型在每个位置上通常不会直接输出：

- 已经选好的 token
- 或一段字符串

模型更常见的输出是：

- 对整个词表大小的一组 logits

如果词表大小是 `V`，那么每个位置最终都会对应一个长度为 `V` 的分数向量。

这些 logits 的意义是：

> 在当前上下文下，模型对词表中每个候选 token 的相对偏好。

而训练目标真正要求的是：

> 在这组偏好里，把真实下一个 token 放到尽可能高的概率位置上。

因此，右移一位之后，模型不是在和一个字符串比较。
它是在：

- 每个位置输出词表级 logits
- 然后把这些 logits 和该位置负责的真实下一个 token id 对齐

只有这层对齐明确，交叉熵才真正有落脚点。

## 为什么语言模型的损失通常是“所有有效位置 token-level 损失的平均”

既然一条序列会提供很多位置监督事件，那么训练时自然就会出现一个问题：

> 一整条序列的损失怎么汇总？

最常见的做法是：

- 对所有有效预测位置上的 token-level loss 求平均

你可以把这理解成：

- 每个位置都是一个小型分类问题
- 整段样本由许多这类小问题组成
- 一条样本的损失就是这些小问题的整体平均表现

这就是为什么语言模型训练常常看起来像：

- 在整段样本上一次前向
- 但内部其实同时做了很多个局部监督

也正因为如此，语言模型训练虽然目标是“预测下一 token”，却并不等于“每次训练只学一个 token”。

## teacher forcing 为什么是右移目标的自然训练协议

走到这里，训练和推理的差别开始真正进入主线。

teacher forcing 最朴素的含义是：

> 训练时，即使模型在某个位置预测错了，下一位置继续训练时，输入仍然使用真实序列中的 token，而不是模型刚才错误生成出来的 token。

为什么这件事会自然出现？

因为只要你的输入是：

- 从原始文本中切出来的真实窗口

而目标又是：

- 这个真实窗口右移一位后的序列

那么训练阶段天然就是站在“真实历史”上学习每个位置的条件分布。

也就是说：

- 输入端始终来自真值
- 目标端也来自真值

这正是 teacher forcing 的典型训练环境。

## 为什么训练时要站在真实历史上学，而不是立刻喂模型自己的错误输出

这也是一个初学者常常会问的合理问题：

> 如果推理时模型最终要靠自己滚动生成，为什么训练时不从第一天就这样做？

原因非常直接。

如果训练一开始就让模型不断吃自己刚生成的错误 token，那么：

- 早期错误会立刻累积
- 后续上下文会迅速偏离真实分布
- 学习信号会变得非常嘈杂
- 训练稳定性明显下降

而 teacher forcing 的逻辑是：

> 先让模型在正确上下文上，把“局部条件分布预测”这件事学会，再把滚动误差累积问题留给推理时去面对。

这不是说推理问题不重要。
而是说：

- 先学好局部条件预测
- 再处理模型自生成历史带来的连锁效应

从训练策略上，这通常更稳。

## 为什么训练和推理因此天然不完全一致

只要 teacher forcing 存在，你就必须尽早接受一个现实：

> 训练阶段和推理阶段，模型所处的上下文条件并不相同。

训练阶段：

- 模型每一步大多站在真实历史上作答

推理阶段：

- 模型越来越多地站在自己刚刚生成出来的历史上作答

这个差别会带来很多后面真正能看到的现象。

例如：

- 训练 loss 看起来不错，但长生成时仍会开始偏题
- 模型短续写还可以，长续写却逐渐重复
- 某个早期低概率错误一旦被采样出来，后面整段都可能被带偏

所以，如果你以后看到：

- 训练指标还可以
- 推理观感却一般

不要立刻觉得矛盾。

这往往正是在提醒你：

- 训练目标学到了局部条件分布
- 但推理时的滚动运行环境又放大了另一层问题

## padding 和“忽略某些位置的 loss”为什么会紧挨着这里出现

真实训练里，并不是所有位置都一定应该参与监督。

最常见的例子就是：

- 样本为了组成 batch 被 padding 到统一长度

如果这些 padding 位置仍然被当成普通预测目标来计算 loss，就会出现问题：

- 模型开始学着预测 padding
- 训练目标被大量无意义位置污染
- loss 的语义被扭曲

因此，一旦你定义了右移目标，就必须进一步问：

> 哪些位置是有效监督位置，哪些位置应该被忽略？

这也是为什么很多实现里会进一步维护：

- attention mask
- loss mask
- 或者把某些目标位置设为 ignore index

它们不是“为了解决 batch 技术问题”附加出来的。
它们是在保护训练目标本身的纯度。

## EOS 和序列结尾为什么值得被认真看待

如果你把目标定义成：

- 根据左边预测右边下一 token

那么序列何时结束，也会自然进入训练目标。

这就是 `EOS` 常常很有用的原因。

它不是只给推理时一个“停一下”的信号。
更重要的是，它让训练阶段也能学到：

- 一个序列在什么样的上下文之后更像应该结束

因此，序列末尾不是 loss 自然消失的地方。
更成熟的处理通常是：

- 把“结束”也当作一个可预测事件

这样模型后面在推理时才更有机会：

- 学会什么时候自然收尾

## 文档边界、EOS 和跨文档拼接为什么会共同影响目标语义

如果你上一章已经接受：

- 样本窗口可能跨越文档边界

那么在这一章里你就必须进一步意识到：

- 边界如何被编码
- 会直接改变监督目标的含义

例如：

- 如果文档末尾有 `EOS`
- 新文档开始前还有显式分隔符

那么模型就能学到：

- “这里本来是一个结束事件”
- “后面开始的是另一段新上下文”

反过来，如果边界被粗糙吞掉，那么模型看到的监督就会变成：

- 文档尾词后面自然接另一个文档开头词

这显然不是你真正想训练的连续性。

因此，右移目标并不是独立于样本组织存在的。
它会把样本边界设计产生的每一种相邻关系，全部吸收为监督信号。

## 为什么 next-token prediction 看起来局部，却能逼模型学很多层规律

这几乎是每个初学者都会问的一个问题：

> 只是预测下一个 token，为什么最后能长出看起来很复杂的语言能力？

这里最重要的直觉是：

- 目标动作很局部
- 但训练覆盖的上下文分布很大

模型不是只学一次“下一个 token 是什么”。
它是在海量不同前缀上，反复被要求：

- 在词法层面接得自然
- 在句法层面接得合理
- 在语义层面不要明显跳脱
- 在风格层面保持一定一致性
- 在更长依赖上维持结构

只要你想把这些局部条件预测都做得更好，模型就会被迫在内部压缩出越来越多有用规律。

因此：

- 目标局部

并不等于：

- 学到的内部表示一定局部

恰恰相反，很多更高层能力正是从这个局部目标的大规模重复中逐步浮现出来的。

## 右移目标为什么会决定后面的几乎所有设计

只要训练目标被定义成：

- 给定左历史，预测右侧下一 token

那么后面很多系统设计都会顺着它长出来。

例如：

- 需要 tokenizer，因为目标对象是离散 token
- 需要词表级输出，因为要在整个候选空间上分配偏好
- 需要交叉熵，因为要把真实 token 的概率偏差变成损失
- 需要 causal mask，因为当前位置不能偷看未来
- 需要自回归生成，因为推理时模型要把自己刚预测出的 token 再接回历史
- 需要采样，因为输出首先是分布而不是确定答案

也就是说，右移一位目标绝不是数据集层面的一个角落决定。

更准确地说：

> 它是后面模型结构、训练协议和推理协议共同依赖的根部定义之一。

## 如果把目标错位一格，为什么程序可能还跑，但模型已经学错

这是一个非常现实的警告。

因为很多与目标对齐有关的 bug，并不会直接报错。

例如：

- 输入和目标长度仍然一致
- 张量 shape 看起来也都正确
- loss 还能顺利算出来

但如果对齐关系错了，模型可能在学：

- 复制当前位置
- 预测错误的相邻位
- 在无效位置上承担责任

这类错误尤其危险，因为表面现象常常只是：

- loss 变化诡异
- 输出像是总差一拍
- 训练似乎有进展，但生成始终不自然

所以在语言模型里，目标对齐是一类必须高度警惕的错误源。

它的危险恰恰在于：

- 看起来一切都能跑
- 但训练本体早就偏了

## 一个很有用的心智模型：每个位置都在说“轮到我预测右边那个”

如果你想用一句简单直觉把这整章记住，一个非常有用的心智模型是：

> 在训练时，序列里的每个有效位置都在说：轮到我根据左边历史，去为右边那个 token 负责。

这句话把很多分散概念都串起来了。

### “根据左边历史”

对应的是：

- 上下文
- 因果约束
- teacher forcing 下的真实前缀

### “轮到我”

对应的是：

- 位置级隐藏状态
- 位置级 logits

### “为右边那个 token 负责”

对应的是：

- 右移一位目标
- token-level loss

只要这个心智模型稳定了，语言模型训练目标就不再会显得零碎。

## 初学者在这一章最容易犯的几个误解

### 误解一：语言模型是在一次性预测整段输出

这会让你很难理解为什么 loss 是逐位置定义的。

### 误解二：右移一位只是方便切片

这会让你忽视责任对齐和任务本体。

### 误解三：teacher forcing 只是训练技巧

它其实是在定义训练时模型所处的上下文条件。

### 误解四：训练和推理理应完全一致

实际上二者天然有环境差异。

### 误解五：padding 只影响工程，不影响目标

如果无效位置不被正确忽略，目标本身就会被污染。

## 读完这一章之后，你应该能稳定回答什么

如果这一章真正起作用了，你至少应该开始能比较稳定地回答下面这些问题：

- 为什么语言模型目标是逐位置的 next-token prediction
- 为什么输入和目标通常来自同一段序列
- 为什么目标看起来像原序列右移一位
- 为什么右移一位不是实现技巧，而是责任对齐
- 为什么 causal mask 和右移目标本质上服务于同一任务定义
- 为什么 teacher forcing 会让训练和推理不完全相同
- 为什么 loss 是按有效位置累积的，而不是“整句只算一次”
- 为什么 padding、EOS 和文档边界会直接影响监督语义

只要这些问题真正站稳，后面你再看：

- 交叉熵
- perplexity
- 自回归生成
- 采样
- 重复问题

都会顺畅很多。

## 本章之后去哪里

如果你沿着卷六继续往后读，那么这一章之后最自然的方向通常是：

- 回到更高层的“序列为什么更难”
- 再进入 attention 与 Transformer

因为到这里，你已经清楚了：

- 文本怎样变成 token
- token 怎样变成训练样本
- 样本内部监督为什么看起来要右移一位

下一步自然就是追问：

> 当模型必须在越来越长的历史上做这种逐位置条件预测时，为什么简单结构会不够，而 attention 又为什么会变得必要？

## 小结

这一章最核心的结论可以压缩成一句话：

> 语言模型训练目标之所以表现成“输入序列与目标序列右移一位”，不是因为这是一种方便切片的写法，而是因为模型在每个位置上都被要求根据左边可见历史，对右边下一个 token 的条件分布负责；而 teacher forcing、causal mask、词表级 logits、token-level 交叉熵、padding 屏蔽和自回归推理，都是围绕这一定义自然长出来的。

一旦这个认识真正站稳，语言模型训练就不再像是在背几段框架代码。
你会开始看见：

> 从数据到目标、从目标到结构、从结构到推理，其实都在服务同一条序列条件预测主线。
