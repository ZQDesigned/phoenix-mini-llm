# 06. 为什么训练目标表现成右移一位

## 很多实现里最容易被低估的一行代码

当你第一次写语言模型数据集时，常会看到类似逻辑：

```python
inputs = tokens[:-1]
targets = tokens[1:]
```

很多人第一次看到这段代码，会把它理解成一种方便切片的工程写法。

实际上不是。

它表达的正是语言模型训练任务最核心的定义之一：

> 给定当前位置之前的 token，预测它右边那个 token。

所以“右移一位”不是实现小技巧，而是任务本身在数据层面的落地。

## 语言模型不是一次预测整段结局

先把一个常见误解纠正掉。

很多人会说：

> 语言模型根据前文生成一句完整的话。

这句话在日常描述里没问题，但如果拿来当训练定义，就太粗了。

更准确的定义是：

> 在序列的每一个位置上，模型都要根据到当前位置为止的可见上下文，预测下一个 token 的分布。

这意味着如果一段 token 序列是：

```text
A B C D
```

模型训练时学的是：

- 看到 `A`，预测 `B`
- 看到 `A B`，预测 `C`
- 看到 `A B C`，预测 `D`

也就是说，整段语言能力其实是由许多局部 next-token 预测叠加出来的。

## 为什么输入和目标通常来自同一段序列

设你有一段 token：

```text
[BOS, A, B, C, EOS]
```

那么一个最典型的训练样本会被拆成：

- 输入：`[BOS, A, B, C]`
- 目标：`[A, B, C, EOS]`

这正对应了模型要学的事情：

- 见到 `BOS` 时，后面应该接什么
- 见到 `BOS A` 时，后面应该接什么
- 见到 `BOS A B` 时，后面应该接什么

换句话说，目标序列不是另一份独立标注，而是：

> 原序列向右错开一位之后得到的监督对象。

## 为什么这是任务定义，而不是“切片方便”

如果你把这一步只当成代码习惯，就容易低估它的重要性。

实际上它在同时定义三件事：

1. 模型当前位置能看见什么  
2. 模型当前位置必须为哪个 token 负责  
3. loss 怎样和真实目标一一对齐  

一旦这个对齐关系搞错了，模型虽然还能训练，但它学到的任务就会偏掉。

这也是为什么 next-token prediction 常被说成：

> 一个任务定义极简单、但边界绝不能错的目标。

## teacher forcing 在这里扮演什么角色

训练时，即使模型在某个位置预测错了，下一个位置的输入仍然使用真实 token，而不是刚才那个错误输出。

这就是 teacher forcing。

它的好处是：

- 模型始终在真实上下文里学习条件分布
- 错误不会在训练早期疯狂连锁放大
- 梯度信号更稳定

这意味着训练阶段的环境比真实生成环境更“干净”。

而这也正解释了为什么：

- 训练 loss 可以不错
- 生成时仍然可能重复或跑偏

因为推理阶段不再有 teacher forcing，模型必须吃自己刚生成出来的 token。

## 为什么每个位置的 logits 都能贡献监督信号

如果样本长度是 `T`，模型通常会输出：

\[
[B, T, V]
\]

的 logits。

这里的每个位置都对应一份对词表的分布预测，因此每个位置都能和真实目标 token 对齐，并计算一份交叉熵。

这意味着一次前向传播并不是只产生一个监督信号，而是产生：

> 一整段序列上多个位置的监督信号。

这正是语言模型训练效率高的一个重要原因。

## 为什么“当前位置不能偷看未来”属于这个目标本身

现在你应该能更清楚地看到 causal mask 的地位了。

如果模型在预测某位置的目标时，能直接看到它右边的真实 token，那么“右移一位预测”这件事就被破坏了。

模型学到的将不是：

> 根据前文预测后文

而更像是：

> 在已经偷看到答案的情况下复述答案

所以 causal mask 不是后续 Attention 章节里的附属插件，而是从这一章开始就已经被要求的东西。

## 为什么语言模型的监督看起来简单，但其实非常强

有些初学者会觉得：

> 只预测下一个 token，会不会目标太弱？

实际上，这个目标之所以强，是因为它在大规模文本上不断重复。

为了在每一个位置都把右边 token 预测好，模型必须逐渐学会很多统计结构：

- 词法共现
- 语法延续
- 主题一致性
- 长短程依赖
- 文本边界

也就是说，监督信号形式虽然简单，但累积起来非常丰富。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> 语言模型训练中“输入和目标错开一位”的写法，不是工程习惯，而是 next-token prediction 在数据层面的直接定义：当前位置使用左侧上下文作条件，右侧那个 token 作为真实答案。
