# 01. 语料、样本与数据分布

## 为什么“找很多文本来训练”远远不够

很多人第一次谈训练语言模型时，会说：

> 先找很多文本来训练。

这句话方向没错，但它太粗糙了。

因为对模型而言，“很多文本”不是一个真正有操作意义的对象。模型不会理解“很多”这种模糊描述，它只会接触到：

- 某些具体来源的文本
- 某些具体格式的文本
- 某些具体比例混合出来的文本
- 某些带着噪声、重复、偏差和缺口的文本

更准确的说法应该是：

> 我们需要一份语料，而语料本身带着自己的分布、风格、边界和问题，它会直接塑造模型学到什么。

这句话非常关键。

因为很多初学者在最开始就会犯一个判断错误：

> 语言模型是在从“语言本身”中学习。

更准确的说法其实是：

> 语言模型是在从某一份具体语料的具体统计分布中学习。

这两句话差别很大。

前者听起来像模型会自动抓住一种抽象的、普世的语言本质。

后者则提醒你：

- 数据来源不同，模型气质会不同
- 数据质量不同，模型缺陷会不同
- 数据覆盖不同，模型能力边界也会不同

所以这章要建立的第一件事就是：

> “数据很多”不是充分描述，“语料长什么样”才是问题本体。

## 什么叫语料

语料就是用来训练模型的文本集合。

它可以来自很多地方，例如：

- 书籍
- 论文
- 网页
- 论坛帖子
- 对话记录
- 代码仓库
- 新闻报道
- 维基类条目
- 说明文档
- 用户生成内容

这些文本看起来都叫“文本”，但它们在统计性质上差异很大。

例如：

- 书籍常常更长、更完整，句子结构更规整
- 论坛帖子更碎片化，更口语，也更容易带噪声
- 代码文本有强结构性、符号密集、重复模式多
- 新闻报道话题集中、风格相对统一、时间性更强
- 对话语料有角色切换、短句、上下文依赖和礼貌模式

所以“语料”不是一个大口袋，而是一个带来源结构的统计世界。

模型最后学到的东西，很大程度上就是这个统计世界的压缩结果。

## 语料不是中性的

这点必须单独强调。

模型不会从语料中学到“纯语言本质”，它会学到：

- 语料里常见的词汇分布
- 常见的句法形式
- 常见的话题和论述方式
- 常见的角色关系和语气风格
- 常见的格式习惯
- 语料内部的偏差、噪声、重复和错误

这意味着：

> 训练语料长什么样，模型最后往往也会带着类似气质。

如果你的语料几乎全是短口语句子，那么模型通常不太可能自然写出长篇严谨论述。

如果你的语料主要来自论坛和弹幕，模型就更容易学到：

- 碎片化表达
- 强情绪词
- 省略结构
- 网络俚语

如果语料大量来自技术文档和代码，模型就会更容易形成：

- 更强的格式敏感性
- 更密集的术语共现
- 更高的符号和结构规则依赖

所以语料不是透明容器，它本身就在定义模型行为的概率空间。

## 模型学到的到底是“语言”，还是“分布”？

一个更精确的回答是：

> 模型是通过学习语料分布中的规律，间接获得某种语言能力。

为什么要这样说？

因为模型训练时真正看到的不是：

- “什么是语法”
- “什么是风格”
- “什么是事实”

这些带解释性的抽象标签。

它看到的是：

- 哪些 token 经常一起出现
- 哪些句式常常接在某些上下文后面
- 哪些话题周围常伴随哪些词
- 哪些文体里常用哪些结构

也就是说，模型直接学习的是：

> 分布、频率、共现、条件关系和结构重复。

而我们后来观察到的“语言能力”，往往就是这些统计结构被压进参数之后的外显结果。

所以当你说模型“懂语言”时，至少在训练层面上，更接近的说法其实是：

> 模型在一个足够大的语料分布中，学会了能够支持语言任务的统计规律。

## 什么叫数据分布

“分布”这个词在这里非常关键。

最朴素地说，数据分布指的是：

> 你的训练数据里，什么内容更常见，什么内容更少见，它们以什么方式共同出现。

例如：

- 高频词和低频词各占多少比例
- 哪些主题反复出现，哪些主题几乎缺席
- 哪种文体占大头，哪种文体只是少量点缀
- 某些符号、格式、段落结构如何分布
- 某些语言或方言混合出现的比例如何

如果把训练语料看成一个统计生态，分布描述的就是这个生态的组成结构。

模型不会把这些差异当成背景噪声自动忽略掉，它会认真学习它们。

所以当我们说模型在“学语言”时，更准确地说，它也在学：

> 这份语料里语言是怎样分布的。

## 频率只是分布的一小部分

很多人第一次理解分布，会立刻想到词频。

这当然没错，但还远远不够。

分布不只包括：

- 单词出现几次

还包括：

- 某些词和哪些词更常一起出现
- 某些词更常出现在什么主题里
- 某种句法模式在什么文体里更常见
- 某些结构是局部高频，还是全局高频
- 某些文本是否只在特定上下文里才会出现

例如两个语料库里，“训练”这个词频率可能一样高，但它们的含义生态可能完全不同：

- 一个语料里多是健身训练
- 一个语料里多是机器学习训练

这说明分布不是单点频率，而是一个更大范围的条件关系网络。

这也是为什么语言模型能够学到的不只是单词表面频率，而是更复杂的上下文模式。

## 为什么同样的模型，换一份语料，出来的“性格”会变

因为模型结构本身不决定话题偏好、风格比例、事实覆盖和表达习惯。

这些东西很大程度上来自：

- 语料组成
- 混合比例
- 清洗方式
- 样本构造方式

例如同一个小型 decoder-only 结构：

- 用儿童故事训练，会偏向短句、叙事和简单词汇
- 用技术文档训练，会偏向定义、列举和术语
- 用中英混合论坛语料训练，会更容易产出混语和口语转折

这说明：

> 模型结构决定它能以什么形式学习，语料决定它更可能学到什么内容。

把这两者分清楚，对后面理解 tokenizer、训练、评估和泛化都很重要。

## 原始语料、token 流、训练样本不是一回事

另一个常见误解，是把原始语料直接等同于训练样本。

实际上，训练链路里通常至少有三层对象：

1. 原始语料  
2. 处理后的 token 流  
3. 最终训练样本  

这三层必须分开理解。

### 第一层：原始语料

这通常是：

- 文本文件
- 文档集合
- 抓取下来的网页正文
- 论坛帖子记录
- 代码文件

此时它还是“原始文本世界”。

### 第二层：处理后的 token 流

经过：

- 清洗
- 规范化
- tokenizer 切分

之后，文本会变成 token 序列。

这时对象已经不是“文章”或“段落”，而是离散 id 或 token 串。

### 第三层：最终训练样本

为了训练方便，你通常还要把 token 流重新组织成：

- 固定长度块
- 带边界的片段
- 输入与目标对齐后的样本

这时候才真正形成模型一次前向会消费的训练样本。

很多实现错误，恰恰发生在这三层被混成一层时。

## 为什么“样本”不是天然存在的

现实世界里的文本天然是文档、句子、段落、对话轮次、代码文件。

但训练时模型真正看到的“样本”，往往是人工构造出来的。

例如你可能会：

- 先把文档清洗
- 再切成 token
- 再拼成固定长度窗口
- 再做右移一位，得到输入和目标

这说明样本不是“语料本来就长这样”，而是：

> 你为了让模型能稳定训练，而从语料中切出来的一种训练单位。

所以训练样本本身就是建模定义的一部分。

这和很多初学者的直觉很不一样。

他们以为只要有文本，样本就“自然存在”。

其实不是。样本是什么、怎么切、长度多长、边界是否保留，这些都会影响训练结果。

## 文档边界为什么重要

这件事常被低估。

假设你把两篇完全不相关的文档直接拼接在一起，中间没有任何边界信息。

那么模型看到的 token 流就会包含一些原本不属于自然上下文的跨文档相邻关系。

例如：

- 一篇新闻结尾的最后一句
- 紧接另一篇代码文档开头的第一句

模型不会自动知道“这其实是两个世界”，除非你显式告诉它。

所以文档边界、分隔符和 packing 策略不是小细节，而是：

> 你是否允许模型把哪些 token 当成同一上下文的一部分。

这会直接影响它学到什么样的条件分布关系。

## 为什么样本长度需要被管理

现实中的文本天然长短不一。

有的只有一句话，有的是整篇文章，有的甚至是多轮对话或长代码文件。

但神经网络训练通常更喜欢结构整齐的张量，所以你通常需要决定：

> 一次让模型看到多长的连续 token 片段？

这就是上下文长度和样本打包问题。

你不能简单把原始语料原封不动塞进模型，因为：

- 长度不统一
- batch 很难组织
- 显存和计算成本不可控
- 训练吞吐不稳定

所以“文本变样本”的过程，本身就是训练任务定义的一部分。

一旦你确定了样本长度，实际上你也在隐含定义：

- 模型一次最多直接看多远
- 哪些长程关系有机会被纳入同一训练窗口
- 训练预算将主要花在哪种跨度的依赖上

## 上下文窗口不是“越长越好”这么简单

很多人第一次接触大模型时，会天然觉得：

> 上下文越长当然越好。

方向上未必错，但在训练阶段这个问题更复杂。

更长的样本意味着：

- 更高的显存和算力成本
- 更少的 batch 容量
- 每一步训练更重
- 数据打包方式更敏感

更短的样本意味着：

- 吞吐更轻
- 训练更稳
- 但模型更少看到长距离依赖

所以上下文长度本质上是在平衡：

- 学习长距离关系的机会
- 训练成本
- 样本组织难度

这也是为什么“小型学习项目”的推荐配置常常不会一上来就追超长上下文。

## 清洗为什么不是可有可无的“预处理附属品”

如果原始语料里包含大量杂质，模型会把这些杂质也当成规律来学。

常见杂质包括：

- 网页导航残留
- 重复页脚
- 抓取错误
- 编码异常
- 无意义模板文本
- 大段重复内容
- 半截文档
- 格式噪声

很多初学者会觉得：

> 模型这么强，应该会自己忽略这些东西。

不能这样乐观。

模型擅长学习高频重复模式，而噪声和模板恰恰常常就是高频重复模式。

所以如果你不清理：

- 它可能学会大量无意义固定模板
- 它可能高估某些格式的正常性
- 它可能把抓取瑕疵当作常见文本结构

清洗的意义，不是把语料变得“完美”，而是尽量避免让训练预算浪费在明显无价值模式上。

## 重复数据为什么特别危险

重复数据不只是“有点浪费存储空间”。

它更可能带来下面这些问题：

- 模型对某些表达模式过度记忆
- 训练集看起来很大，实际信息量却没那么大
- 某些片段在训练中被异常放大
- 验证时可能因为近重复而高估泛化

尤其在小型学习项目里，数据总量本来就有限，如果里面还塞了很多重复，模型更容易：

- 记住具体句子
- 以为某些局部模式极其重要
- 输出风格异常单一

所以“去重”不是工业级项目才关心的事情。对小项目来说，它往往更重要。

## 数据质量和数据规模是两个不同问题

初学者很容易只问：

> 数据量越大越好吗？

但真正更准确的问题应该是：

> 数据量、数据质量和数据分布是否与目标相匹配？

例如一份很大的语料如果：

- 重复很多
- 噪声很大
- 风格极度单一
- 结构被网页模板污染

那么它未必比一份更干净、更匹配目标的小语料更适合学习项目。

这并不是在说“大数据没用”，而是在强调：

> 规模不是唯一维度，分布和质量同样决定模型最后学到什么。

如果把语料比作食材，那么数据量是重量，数据质量和分布则决定你到底在喂模型什么。

## 什么叫覆盖，为什么覆盖不等于平均

很多人听见“数据要覆盖广”，就会以为：

> 各种主题都平均放一点就行。

事情没这么简单。

覆盖至少涉及三层问题：

### 第一，主题覆盖

你的语料有没有包含你希望模型处理的主题范围？

### 第二，文体覆盖

即使主题类似，不同文体也会差很多，例如：

- 问答
- 叙述
- 代码注释
- 正式说明文
- 对话

### 第三，难度覆盖

是不是只有短句和浅结构，还是也有更复杂的长文、层级说明和复杂组合关系？

所以覆盖不是简单拼盘，而是：

> 让目标使用场景中真正重要的结构模式，在训练里能被足够看见。

## 训练集、验证集、测试集到底在分什么

很多初学者会把数据集切分理解成一种机械动作：

- 训练集 80%
- 验证集 10%
- 测试集 10%

这种数字本身不是重点。

真正重要的是：

> 让不同子集承担不同职责，并且尽量避免信息泄漏。

### 训练集

训练集负责参与参数更新。

模型在它上面会不断看到样本并调整参数。

### 验证集

验证集不参与参数更新，它负责帮助你观察：

- loss 是否继续下降
- 是否开始过拟合
- 某些超参数设置是否更合理

### 测试集

测试集应该尽量留到最后，用来给更正式的最终评估。

如果你反复根据测试集调模型，它就不再是真正独立的评估窗口了。

## 为什么验证集不应该只是“随手抽一些句子”

验证集的作用不是完成形式要求，而是：

> 成为你观察模型泛化趋势的一面镜子。

如果这面镜子本身有问题，你就会被误导。

例如：

- 验证集和训练集高度重复
- 验证集只覆盖极窄话题
- 验证集风格和目标使用场景差很远

这都会让你对模型好坏产生错误判断。

所以更合理的想法是：

> 验证集应该尽量代表你关心的目标分布，同时又不参与训练。

这比“比例切多少”重要得多。

## 什么叫分布偏移

如果训练数据和你真正使用时面对的数据差别很大，就会出现分布偏移。

例如：

- 训练时主要是新闻，使用时却主要是聊天问答
- 训练时主要是书面中文，使用时却是网络口语
- 训练时几乎没有代码，使用时却想让模型续写程序

这时即使训练 loss 看起来不错，模型表现也可能不理想。

因为模型学到的是：

> 训练分布里的规律。

而不是任何场景下都自动成立的万能规则。

这也是为什么很多“模型怎么学不会我的任务”的问题，本质上其实是数据分布不匹配，而不是结构代码写错了。

## 小型学习项目为什么更要认真对待数据分布

在工业级大模型里，海量数据常常会在一定程度上平均掉一部分局部问题。

但在小型学习项目里，数据规模通常更有限，这意味着：

- 偏差更容易直接进入模型
- 重复更容易造成过拟合
- 风格单一更容易造成输出单一
- 某些脏数据更容易占据显著比例

因此，小项目并不意味着可以随便找点文本就开练。相反：

> 数据越小，分布管理越需要认真。

因为在小数据里，任何局部问题都更容易被放大。

## 对学习项目来说，什么样的语料更合适

如果你的目标是“从零理解一个小型语言模型”，那比起追求看起来巨大的数据规模，更合理的目标通常是：

- 来源清楚
- 风格相对稳定
- 清洗成本可控
- 主题不要过度发散
- 重复率尽量低
- 能支持你观察训练趋势

例如，一个相对干净的中等规模单一领域文本集合，常常比一个巨大但混乱的抓取拼盘更适合教学式实验。

原因很简单：

- 你更容易解释模型为什么学成这样
- 你更容易排查问题来自哪里
- 你更容易把 loss 曲线和生成现象对应起来

学习项目的首要目标不是“拥有最多数据”，而是：

> 让数据链路足够清楚，能支撑你理解模型行为。

## 该怎样描述一份语料，才算真正说清楚

以后当你描述自己的训练数据时，不要只说：

- 我有很多文本
- 我有几百万字
- 我抓了很多网页

更有价值的描述应该包括：

- 来源是什么
- 主要文体是什么
- 语言范围是什么
- 是否做了清洗和去重
- 是否保留了文档边界
- token 化前后规模大概怎样
- 打算怎样切训练样本
- 验证集如何划分

只有这样，你才是在描述一个真正可理解的训练数据系统。

## 这一章与后面章节怎么接上

这一章建立的是数据层的全局地图。

接下来你会继续看到：

- 文本底层编码和规范化
- token 如何被定义
- 词表怎样训练
- token 流怎样打包成样本
- 为什么训练目标看起来像“右移一位”

这些都不是与本章无关的新话题，而是在继续回答同一个大问题：

> 一份原始文本语料，究竟怎样一步一步变成模型真正学习的对象？

如果本章没有读稳，后面 tokenizer、packing 和 next-token objective 都会显得像零散工程步骤。

## 这一章真正要记住的核心句子

如果这一章只记一句话，它应该是：

> 语言模型不是在从“很多文本”里学抽象语言，而是在从某一份具体语料的具体分布中学习；语料来源、清洗方式、样本构造和验证划分，都会直接塑造模型最终学到的东西。

## 练习题

1. 为什么“很多文本”不是对训练数据的充分描述？
2. 为什么说模型学习的是语料分布中的规律，而不是某种脱离语料的“纯语言本质”？
3. 原始语料、token 流和训练样本为什么必须区分？
4. 文档边界和样本长度为什么都属于建模定义的一部分？
5. 为什么数据质量和数据规模不能被混成同一个问题？
6. 验证集真正承担的职责是什么？
7. 为什么小型学习项目反而更需要认真管理数据分布？
