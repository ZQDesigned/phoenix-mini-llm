# 01. 语料、样本与数据分布

很多人第一次谈训练语言模型时，会把起点说成一句几乎人人都会说的话：

> 先找很多文本来训练。

这句话方向当然没有错，但它还远远不够。

因为对模型来说，“很多文本”根本不是一个能直接参与计算的对象。
模型不会理解“很多”这种模糊判断，它真正会接触到的永远是更具体的东西：

- 某些来源的文本
- 某些体裁的文本
- 某些时间段的文本
- 某些清洗规则处理过的文本
- 某些重复、噪声、偏差与空缺并存的文本

换句话说，模型并不是在从一种抽象的“语言整体”中学习。
它是在从一份非常具体、带着来源结构和统计形状的语料中学习。

这句话之所以重要，是因为它会立刻改变你看待数据的方式。

如果你说：

> 模型在学习语言，

这听起来像是在学某种几乎脱离具体材料的普遍能力。

但如果你说：

> 模型在学习这份语料所呈现出来的条件分布和统计规律，

那你就会立刻意识到：

- 数据来源会塑造模型气质
- 数据比例会塑造模型偏好
- 数据质量会塑造模型缺陷
- 数据缺口会塑造模型盲区

这也正是本章真正的起点。

这一章并不是想把“找数据”写成工程清单。
它想建立的是一种更稳的训练视角：

> 语料不是背景条件。
> 语料本身就是语言模型要压缩、近似和继承下来的统计世界。

## 语料首先不是“文本堆”，而是模型将要面对的统计世界

“语料”这个词最朴素的定义，当然可以写成：

> 用来训练模型的文本集合。

但如果只停在这里，它还是太平。

更准确一点说，语料是：

> 一份带有来源、风格、主题、格式、重复结构、噪声与缺口的文本总体，它在训练中充当模型所面对的经验世界。

这就像一个学生的全部阅读材料。
你给他什么，他就主要从什么里归纳规律。
如果材料极窄，他的认知也会极窄。
如果材料充满偏差，这种偏差也会直接进入他的判断体系。

语言模型没有超出这条规律。
它既不会跳出数据自动获得世界知识，也不会替你纠正语料内部所有偏差。

它最先做的事情，恰恰是非常忠实地学习：

- 什么更常出现
- 什么几乎不出现
- 什么总跟什么一起出现
- 什么风格更像“正常句子”
- 什么写法更像“一个合理延续”

所以语料不是模型学习过程中的燃料而已。
它更像是模型成长时所处的环境。

环境越单一，模型越容易单一。
环境越混乱，模型越容易混乱。
环境越有系统性偏差，模型越可能把偏差学成常识。

## 训练语言模型时，真正被学习的首先不是“意义”，而是条件分布

这句话值得停下来讲清楚。

人类讨论语言时，很容易首先想到：

- 语义
- 语法
- 语气
- 事实
- 逻辑

但模型训练时真正直接接触到的，并不是这些解释性标签。

它接触到的是一连串更底层的统计事实：

- 某些 token 在什么上下文里更常出现
- 某些结构在什么主题中高频共现
- 某种句法模式在什么风格中更稳定
- 某些表达后面更可能接什么表达

也就是说，模型首先学习的是：

> 条件分布、频率结构、共现关系和延续规律。

后来我们说模型“会写”“会续写”“懂一点上下文”，本质上都是这些统计规律被压进参数后的外显结果。

这不是在贬低模型能力。
恰恰相反，这能帮助你更准确地理解训练。

如果模型最终表现出某种语言风格、某种话题偏好、某种事实盲区，那么第一件应该回头看的事情，通常不是“它为什么突然有了这种性格”，而是：

> 这份语料到底把怎样的条件分布交给了它？

## 什么叫数据分布，为什么它不是一个抽象统计学口号

很多资料会很快用到“数据分布”这个词，但不真正解释它在语言模型里到底指什么。

在这里，分布可以先用一句非常直白的话来理解：

> 你的语料里，什么东西多，什么东西少，它们以怎样的方式共同出现。

这包括但远不止词频。

它还包括：

- 主题分布
- 体裁分布
- 语言或方言比例
- 长短句比例
- 标点和格式习惯
- 代码、表格、对话、叙事、说明文各自占多少
- 某些写法在什么上下文下出现

例如，同样都叫“中文语料”，它们的分布也可能完全不同。

一份语料可能主要是：

- 网络论坛
- 口语化表达
- 短句
- 情绪词
- 热点时事

另一份语料则可能主要是：

- 技术文档
- 说明性写作
- 专有名词
- 长句
- 结构化段落

从人类角度看，两者都算“中文文本”。
但对模型来说，它们几乎是两个不同的统计宇宙。

所以“分布”在语言模型里不是抽象统计学装饰词。
它实际上是在回答：

> 模型训练期间，什么样的语言现实被高频呈现给了它，什么样的语言现实又几乎从未出现。

## 频率只是最浅的一层，真正决定模型行为的是条件结构

初学者第一次理解分布，最容易先停在词频上。

这当然是入口，但远远不够。

如果一个词在语料中出现很多次，你只能知道它“常见”。
可语言模型真正要学习的不是单点常见性，而是：

> 在什么条件下，它常和哪些别的东西一起出现。

例如，“训练”这个词在两个语料库里词频可以一样高，但它所处的条件结构可能完全不同。

在一个语料里，它经常出现在：

- 健身
- 比赛
- 体能
- 教练

在另一个语料里，它经常出现在：

- 模型
- 参数
- 损失
- 反向传播

这说明模型真正学到的，并不是一个孤立“词有多常见”的世界。
它学到的是：

> 一个由上下文、条件和共同出现关系构成的统计网络。

这也正是为什么语言模型可以生成连贯文本。
它不是靠记住单词表，而是靠学到：

- 这类上下文后面什么更可能
- 这种主题里什么表达更自然
- 某种句法结构怎样继续延伸

所以分布理解得越深，你就越不会把语料想成一堆散词。
你会更自然地把它看成一张由局部与全局条件关系交织成的语言生态网。

## 为什么同样的结构，换一份语料，最后产出的模型“性格”会明显不同

很多初学者在接触小型语言模型实验时，都会发现一个很直观的现象：

> 模型结构没怎么变，可是换一份数据，输出风格和能力边界却变了很多。

这并不奇怪。
因为模型结构决定的是：

> 它能以什么形式去压缩、表示和预测序列规律。

而语料决定的是：

> 它到底最常接触到哪些规律、哪些风格、哪些题材、哪些表达制度。

同一个 decoder-only 结构：

- 用儿童故事语料训练，输出通常更叙事化、词汇更简单
- 用技术文档训练，输出更定义化、术语更集中
- 用论坛帖子训练，输出更口语、碎片化和情绪化
- 用代码语料训练，输出会更结构敏感，括号、缩进和标识符模式更稳

所以训练中至少要分清两种来源：

- 模型结构给了它怎样的表达上限
- 语料分布给了它怎样的经验世界

把这两者混为一谈，会让后面很多判断失真。
你会错误地把本属于语料的效果，当成结构神奇地“自动长出来”的能力。

## 原始语料、token 流和训练样本是三种不同层次的对象

很多人初学时会把这三件事混成一件：

- 文本
- token
- 训练样本

可实际上，它们对应的是训练链路里完全不同的三层对象。

第一层是原始语料。

它可能是：

- 一堆网页正文
- 一批 Markdown 文档
- 一组小说文本
- 一堆代码文件
- 一批对话记录

这个阶段的对象还是“人类意义上的文本材料”。

第二层是 token 流。

当语料经历：

- 清洗
- 编码解码一致化
- 文本规范化
- tokenizer 切分

之后，它会变成一条条 token 序列。

到这里，文本材料已经被改写成了模型可以消费的离散符号流。

第三层是训练样本。

token 流还不能直接训练，因为模型训练通常要求：

- 固定或受控长度
- 成批堆叠
- 明确目标对齐关系

于是 token 流还要进一步被切成：

- 窗口
- 片段
- batch 内的样本单元

这时才真正得到训练循环中的 `input_ids` 和 `targets`。

只要这三层不分清，你后面讨论数据问题时就很容易混乱。

因为：

- 某些问题属于原始语料选择问题
- 某些问题属于 tokenizer 边界问题
- 某些问题属于样本打包和窗口定义问题

它们都和“数据”有关，但不是同一个层面。

## 样本不是自然存在的，而是从语料中切出来的观察窗口

这是从文本进入训练时最重要的认知变化之一。

原始语料里自然存在的东西，可能是：

- 一篇文章
- 一段对话
- 一个函数文件
- 一个段落

但训练时真正送进模型的“样本”，往往并不是这些天然边界本身。

很多时候，样本只是：

> 从更长 token 流里切出来的一个局部观察窗口。

例如一篇长文，并不会总是整篇一次性进模型。
它可能被切成许多固定长度片段。

这意味着模型训练中接触到的基本单位，不一定是“完整文章”或“完整对话”。
它更常见的是：

> 来自更大语料的一段局部历史。

这个事实很关键，因为它会影响后面很多事情：

- 模型能看到多长上下文
- 样本边界会不会切断语义
- 文档边界如何被表示
- 序列结尾应该怎样处理

所以“样本”并不是语料天生给好的。
它是你在训练制度下，从语料里人为切出来的观察单位。

## 语料质量的重要性，不在于“更干净更好看”，而在于它决定模型最终把什么当作正常世界

很多初学者一听“数据清洗”，会想到非常朴素的卫生直觉：

> 脏数据删掉，干净数据留下。

这个方向当然没错，但如果只这样理解，还是太浅。

语料质量之所以重要，不只是因为乱七八糟的数据看起来不好。
更深层的原因是：

> 模型会把高频出现且稳定存在的现象，当作世界的一部分去认真学习。

于是如果语料里充满：

- 损坏的编码文本
- 大量模板噪声
- 机器拼接残片
- 重复页面
- 杂乱标签
- 无意义字符堆

模型不会主动说“这个我不学”。
它会把这些东西也吸进去。

这就像一个学生长期阅读充满错字、断句错误和重复垃圾段落的材料。
这些东西最终会进入他的语言直觉。

所以高质量语料真正保护的，不只是训练效率。
它保护的是：

> 模型关于“什么是正常文本世界”的基本统计印象。

## 重复数据为什么比看起来更严重，因为它不只是浪费样本，还会系统性放大某些局部规律

初学者通常能直觉理解：

> 重复数据不太好。

但很多人低估了它到底为什么坏。

如果某些文本、模板或表达在语料中大量重复，带来的问题不只是“白白多看了几遍”。

更重要的是：

> 它会把某些局部模式的人为权重抬得过高，让模型误以为它们比真实世界里更普遍、更重要。

这会带来几类后果：

- 某些模板化表达过于高频
- 某些主题被不成比例放大
- 验证时看上去某些模式很强，其实只是重复记忆
- 长尾内容被相对挤压

所以重复数据本质上是在改写分布。

它不仅增加样本数，更改变样本权重。
而语言模型学的恰恰是分布。

于是重复不是后勤浪费，而是统计扭曲。

## 偏差不是训练之后才出现的道德问题，而是语料从一开始就携带的结构事实

“偏差”这个词容易让人误以为它只属于后期社会性讨论。

但从训练机制看，偏差首先是一个非常直接的统计问题。

如果语料在来源、语言、地区、阶层、题材、写作体裁、价值立场上明显不均衡，模型就会自然继承这种不均衡。

这不是模型训练后突然长出的毛病。
它是语料本身的一部分结构事实。

例如，如果语料里某类群体的表达极少、某类主题几乎缺席、某类措辞系统性被负面语境包围，那么模型学到的条件分布也会带着这些倾向。

所以“偏差问题”不是只属于伦理附录。
它首先属于语料分布问题：

> 你的训练数据到底把怎样的世界呈现为常态，又把怎样的世界排除在常态之外？

只要语料有边界，偏差就几乎不可避免。
关键不在于幻想完全中立，而在于：

- 你是否知道偏在哪里
- 你是否知道缺了什么
- 你是否知道这种偏差会怎样影响模型输出

## 数据覆盖决定的，不只是“会不会这道题”，而是模型把哪些事情视为可延续的常见模式

覆盖不足最容易被想成：

> 某个领域数据不够，所以模型不会那个领域。

这当然是结果之一。
但它还有更深的影响。

如果某类写法、主题、语言现象几乎没出现在训练语料中，那么模型不仅不会“系统掌握”它。
它甚至可能不会把这种现象视为一个稳定可预测的语言制度。

换句话说，覆盖影响的不只是知识清单。
它影响的是模型对“什么是常见、什么是自然、什么是像一个合理延续”的内部判断。

因此语料覆盖不足带来的后果，常常不只是：

- 回答事实不准

还可能包括：

- 风格不稳
- 结构不自然
- 某类表达总显得生硬
- 某类上下文中延续非常别扭

这再次说明，语料不是给模型补背景知识。
它是在定义模型的统计常识。

## 训练集、验证集和测试集的切分，首先是分布观问题，而不是文件分三份这么简单

很多人第一次做数据切分，会很自然地把它理解成：

- 这些文件做训练
- 那些文件做验证
- 剩下的做测试

这当然是操作形式，但真正重要的是：

> 切分之后，各部分是否仍然在合理地代表你想研究的分布关系。

如果切分不认真，你很可能遇到这些问题：

- 验证集与训练集高度近重复
- 某一来源几乎只落进训练集，没有进入验证
- 某些主题只出现在某一份切分里
- 时间顺序导致分布前后发生系统偏移

这时即便“形式上完成了切分”，它在统计意义上也未必可信。

所以切分不是文件管理动作。
它是在定义：

> 训练时模型看见什么，评估时我们又用什么来检验它是否真的跨出了训练材料本身。

这和下一卷的泛化问题会直接接起来。

## 对学习项目来说，最重要的不是追求最大语料，而是先学会看见语料的形状

初学者最容易被“大模型叙事”带偏的一点是：

> 好像只要数据越大，问题就会自动变小。

这并不稳。

在学习项目阶段，真正更重要的能力往往不是“立刻拿到最大语料”。
而是：

> 学会描述语料、拆开语料、观察语料，并理解语料会怎样进入模型。

你至少要能回答：

- 这份语料主要来自哪里
- 它大概是什么风格
- 它包含哪些语言现象
- 它缺哪些东西
- 它有没有明显重复与噪声
- 它最后是怎样变成 token 流和样本的

只要这些问题答不出来，你即便把模型跑起来，也很难真正理解训练到底在学什么。

所以学习项目阶段，一个规模适中但形状清晰的语料，往往比一个巨大却完全没被理解的语料更有教学价值。

## 这一章真正想留下的主线

如果把整章压缩成最核心的一条链，可以写成：

> 语言模型训练的起点并不是“找很多文本”这么简单，而是把一份具体语料当成模型将要面对的统计世界；模型训练时直接学习的首先不是抽象意义上的语言本质，而是这份语料中由频率、共现、上下文和延续关系构成的条件分布；因此语料来源、风格比例、重复程度、噪声水平、覆盖范围和结构偏差，都会直接塑造模型最终把什么视为常见、自然、值得延续的模式；原始语料、token 流和训练样本是三种不同层次的对象，样本也不是天然存在的，而是从更大 token 流中切出来的局部观察窗口；重复数据会扭曲分布权重，覆盖缺口会塑造能力边界，切分方式会影响后续泛化判断；真正重要的不是语料有多大，而是你是否能看见它的统计形状，并理解它将怎样进入后面的编码、分词和训练制度。

这条主线站稳之后，你后面再看：

- 文本清洗
- tokenizer 训练
- 样本打包
- 验证切分

就不会把它们看成互不相关的数据流程。
你会知道它们都在服务同一件事：

> 把一份真实而有偏、有边界、有统计结构的文本世界，稳定地改写成模型可学习的经验分布。

## 读完本章后，你应该能稳定回答什么

如果这一章真正读稳了，你应该能够不用背定义，而是用自己的话稳定回答下面这些问题：

- 为什么“很多文本”不是对训练数据的充分描述
- 语料为什么应该被看成模型将要面对的统计世界
- 模型训练时首先学到的为什么是条件分布而不是抽象意义标签
- 数据分布具体在语言模型里指什么
- 频率和条件结构之间的差别到底是什么
- 为什么同样结构换一份语料，模型性格会明显变化
- 原始语料、token 流和训练样本分别属于哪一层
- 为什么样本不是天然存在的，而是从语料中切出来的窗口
- 重复、噪声、偏差和覆盖缺口会怎样进入模型
- 为什么数据切分首先是分布问题，而不是文件管理问题

只要这些问题能够稳定答出来，这一章就已经完成了最重要的任务：

> 它让“语料、样本与数据分布”不再只是训练前的准备工作，而变成了你理解语言模型到底在从什么经验世界中学习的基础章节。
