# 02. 概率、softmax 与交叉熵

如果你后面要真正理解这些词：

- logits
- token 分布
- next-token prediction
- loss
- perplexity

那么这一章几乎绕不过去。

因为语言模型最底层做的事情，并不是“直接给出下一个词”，而是：

> 在当前上下文条件下，对整个候选空间给出一份概率分布。

这句话表面上不复杂，但它会立刻把很多后续概念全部拖进来。

只要你接受“模型输出的首先是一份分布”，你就必须继续回答：

- 这份分布到底是怎样从网络内部长出来的
- 为什么模型不直接输出一个类别 id
- logits 到底是什么，它和概率是什么关系
- softmax 为什么会成为一个自然接口
- 目标分布到底长什么样
- 为什么最终 loss 会写成交叉熵

如果这些问题彼此分开讲，读者很容易留下这样一种破碎印象：

> softmax 是一个常见函数，交叉熵是一个常见损失，logits 是框架里经常出现的中间量，它们碰巧总一起出现。

这恰好是本章要拆掉的误解。

这几样东西之所以总是一起出现，并不是因为它们碰巧适配。
它们本来就在回答同一件事：

> 当模型面对很多候选结果时，怎样把内部偏好写成一个可比较、可训练、可回传误差的输出接口？

这一章真正要建立的，就是这条输出接口主线。

## 神经网络输出的第一件事，不是答案，而是偏好结构

初学者最容易带着日常语言习惯进入模型世界。

在人类视角里，我们会说：

- 这张图片是猫
- 这句话下一个词应该是“模型”
- 这条评论是正面的

于是人很容易把模型输出也想成：

> 它应该直接说出答案。

但从训练角度看，这种想法太粗了。

因为“直接说答案”会立刻丢掉大量对训练非常重要的信息。

假设一个模型面对三个候选类别：

- A
- B
- C

如果它只输出：

```text
B
```

你根本不知道它是在下面哪一种状态里做出的这个选择：

- 非常确信 B，A 和 C 几乎不可能
- 勉强偏向 B，A 其实也很接近
- 几乎完全不确定，只是 B 略高一点点

这三种内部状态，对训练来说差别极大。

因为训练真正关心的，从来不只是：

> 选对了没有。

它还关心：

> 模型给不同候选结果分配了怎样的相对偏好，它离理想偏好结构还有多远。

所以神经网络输出的第一件事，不应该被理解成“答案”，而应该被理解成：

> 一张关于候选空间的偏好地图。

这也正是概率分布会进入主线的原因。

## 只输出一个类别，不足以支持学习；模型需要的是一整张候选分布

训练之所以偏爱分布，而不是单一类别，核心原因在于分布保留了更多可学习信号。

如果模型只输出最终选中的类，那么训练信号会极度稀薄。

例如：

- 选对了，但信心很低
- 选错了，但真实答案其实排第二
- 选错了，而且把真实答案看得极不可能

这些情况在“只看最终类别”的视角里几乎都会被压扁成粗糙的几种结果。

但如果模型输出的是一张分布，你就可以看见更多内部结构：

- 正确类别得到了多大概率
- 错误类别里谁最接近
- 模型到底是在“略微偏错”还是“自信地错”
- 分布整体是尖锐还是平缓

这些信息对训练非常重要。

因为训练要做的不是一次性给模型贴一个“对/错”标签，而是反复推动它：

> 把真实答案的概率提高，同时重新整理整个候选空间里的相对偏好。

从这个角度看，概率分布不是锦上添花。
它是让“输出端还能继续被优化”这件事成立的基础。

## 语言模型为什么尤其天然地长成分布预测问题

在普通分类里，候选空间也许只有几个类别。
在语言模型里，问题会变得更明显。

因为语言模型在每个位置上面对的不是：

- 正类
- 负类

这种简单结构。

它面对的是整个词表里的所有 token 候选。

假设当前词表大小是 `V`，那么模型在每个位置上其实都在问：

> 在这 `V` 个 token 里，下一个最合理的 token 分别应该被看成多大概率？

这件事有两个直接后果。

第一，输出天然就是一个多类竞争问题。

第二，模型不能只知道“最高的是谁”，还必须知道：

- 最高的有多高
- 第二高离它多远
- 真实 token 当前排在什么位置

所以语言模型比很多传统任务更容易迫使你接受一件事：

> 预测的对象不是单一答案，而是候选空间上的一张分布。

也正因为如此，后面你看到的：

- logits
- softmax
- cross entropy

都不应该被理解成额外技术细节。
它们是在给这张分布搭建输出接口。

## logits 不是概率，它们是网络在归一化之前给出的原始偏好分数

现在可以进入一个最经常被误解的词了：logits。

很多初学者第一次看到 logits 时，会模糊地觉得它们像“还没 softmax 的概率”。
这句话有一点方向感，但还不够准确。

更准确的说法是：

> logits 是网络在归一化之前给出的原始偏好分数。

也就是说，logits 本身还不满足概率分布必须满足的条件：

- 每一项在 `0` 到 `1` 之间
- 所有项加起来等于 `1`

logits 可以是任意实数：

- 正的
- 负的
- 很大
- 很小

它们表达的是：

> 模型当前觉得每个候选结果相对有多值得被偏好。

这时最值得抓住的直觉不是“它像半成品概率”。
而是：

> logits 更像一组还没被归一化的竞争分数。

谁更大，说明模型更偏向谁。
但在没有进一步处理前，它们还不是可以直接读作概率的对象。

## 为什么模型不直接输出概率，而要先输出 logits

这是另一个非常值得认真问的问题。

如果目标本来就是得到一张概率分布，那为什么不让网络最后一层直接输出概率？

原因并不只是“框架习惯这样设计”。
更深的原因在于 logits 是一种更灵活、更好优化的中间接口。

首先，logits 不受概率约束。

如果最后一层直接输出概率，那么网络每次更新都必须直接在一个受限空间里活动：

- 每一项都不能小于 `0`
- 每一项都不能大于 `1`
- 所有项还必须始终和为 `1`

这种约束会让参数更新和输出组织都更别扭。

而 logits 作为任意实数，没有这种负担。
网络可以先自由地表达相对偏好，再由一个专门的归一化机制把它变成概率。

其次，logits 更自然地表达“相对竞争”。

很多任务里，重要的不是某个候选单独有多大，而是：

> 它相对于其他候选到底高了多少。

logits 恰好非常适合表达这件事。

最后，logits 还能让训练实现更稳定。

因为实际计算中，我们往往不会先显式把 logits 变成概率，再单独取对数。
而是直接在 logits 层面完成更稳定的联合计算。

所以 logits 的存在，不是在绕弯。
它是在给概率输出留一个更自然、更灵活的中间表达层。

## softmax 在做的，不是魔法，而是把相对偏好改写成可比较的分布

一旦你接受：

- 网络先输出一组原始偏好分数
- 这些分数还不是概率

那么 softmax 的职责就会突然变得非常清楚。

softmax 在做的是：

> 把一组相对偏好分数，改写成一张可比较、可归一化的概率分布。

它的定义是：

\[
\text{softmax}(z_i)=\frac{e^{z_i}}{\sum_j e^{z_j}}
\]

第一次看到这个式子时，很多人会被形式吓到。
其实先抓直觉更重要。

softmax 做了三件事。

第一，它把原始分数转成严格为正的量。

第二，它让更大的分数被更强地放大。

第三，它再用整体和做归一化，让所有项加起来正好等于 `1`。

于是你得到的不再是一串彼此孤立的原始分数，而是一张真正的候选竞争分布。

这张分布可以直接回答：

- 当前最可能的是谁
- 真实答案当前得到多少概率
- 竞争候选之间差距有多大

所以 softmax 不是“最后顺手归一化一下”。
它是在把网络的内部偏好，正式翻译成训练和推理都能使用的输出接口。

## softmax 最该理解的是竞争关系，而不是公式形式

很多人背过 softmax 公式，却仍然不理解它。
原因往往是他们只看见了指数和归一化，却没看见竞争。

softmax 最值得抓住的直觉，是：

> 它不是分别处理每个候选，然后再拼起来。
> 它是在让所有候选一起竞争总概率质量。

这意味着：

- 某个候选分数上升，不只会提升自己
- 它还会挤压其他候选所占的概率空间

这件事非常重要，因为多类预测本来就是相对竞争问题。

在语言模型里，你并不是在独立判断：

- “这个 token 是不是正确”
- “那个 token 是不是正确”

你是在判断：

> 在同一个位置上，这整个词表里的候选，彼此之间应该怎样分配概率质量。

所以 softmax 真正塑造的是一场竞争，而不只是一个归一化动作。

## logits 和 softmax 一起，构成了“内部偏好到外部分布”的桥

到这里你可以把这一段压成一句更稳定的话：

> logits 负责表达内部偏好，softmax 负责把这种偏好改写成外部分布。

这两个角色不要混。

如果把 logits 当概率，就会误解网络到底输出了什么。
如果把 softmax 当附属步骤，就会误解分布接口到底是怎么成立的。

两者真正配合起来时，模型才第一次获得一套像样的输出端：

1. 网络内部先自由表达相对偏好
2. softmax 再把这些偏好放到统一概率尺度里
3. 训练于是可以开始比较“这张分布离目标分布还有多远”

这第三步，正是交叉熵要接手的地方。

## 目标分布不是“正确标签”四个字就能糊过去的

讲输出端时，一个经常被说得过粗的概念就是“标签”。

很多材料会直接说：

- 预测分布已经有了
- 标签也已经有了
- 然后算交叉熵

这容易让初学者以为标签只是一个孤零零的类别 id。

更准确的说法其实是：

> 训练并不只是在拿一个类别 id 对比分布。
> 它是在拿模型分布和某种目标分布做比较。

在最常见的标准分类里，这个目标分布通常是 one-hot。

也就是说：

- 正确类别位置为 `1`
- 其他类别位置为 `0`

这背后真正表达的是：

> 理想状态下，全部概率质量都应该压到真实答案上。

当然，现实里也可能存在更柔和的目标分布，例如标签平滑、蒸馏目标、多标签结构等。
但在最基础的入门阶段，one-hot 目标已经足够让你看清交叉熵为什么自然出现。

## 交叉熵的本质，是用目标分布去衡量模型分布有多“意外”

前一卷你已经从信息量角度见过交叉熵。
这一章里，我们要重新从输出接口角度看它。

如果目标分布是 \(P\)，模型分布是 \(Q\)，那么交叉熵写成：

\[
H(P,Q)=-\sum_x P(x)\log Q(x)
\]

这条式子表面看还是信息论语言。
但在神经网络输出端，它其实在回答一件非常直接的事：

> 如果真实世界按目标分布来产生答案，那么模型给出的这张分布，平均会有多“意外”？

在 one-hot 目标下，这件事会变得尤其直白。

因为只有真实类别那个位置的权重是 `1`，其他位置都是 `0`。
所以交叉熵会退化成：

\[
-\log Q(y_{\text{true}})
\]

也就是说，在最常见的分类和 next-token prediction 场景里，交叉熵其实就是：

> 真实答案的负对数概率。

这一下，整条链就完全闭合了：

- 网络先输出 logits
- logits 经过 softmax 变成分布
- 目标分布指出“理想答案应该落在哪”
- 交叉熵则衡量模型对真实答案到底有多不相信

所以交叉熵不是“最后套上的常见损失”。
它是这套输出接口自然长出来的评价函数。

## 为什么交叉熵特别惩罚“自信地错”

交叉熵之所以长期占据主线，不只是因为它和概率兼容。
它还有一个非常符合训练需求的特征：

> 它会特别严厉地惩罚“把真实答案看得极不可能”的错误。

这件事你可以直接从：

\[
-\log p
\]

里看出来。

如果真实答案概率是：

- `0.9`
- `0.5`
- `0.1`
- `0.001`

那么对应的负对数概率增长并不是线性的。

也就是说，当模型把真实答案从“有点不确定”推到“几乎不相信”时，代价会迅速变大。

这非常合理。

因为训练真正最想纠正的，往往不是“略微分错一点”的情况。
而是：

> 模型用很强的置信度，把真实答案压得几乎没有位置。

从学习信号角度看，这类错误最值得被重罚。

所以交叉熵的“惩罚曲线”并不是随便长成这样的。
它恰好符合训练想强调的修正方向。

## 为什么训练时不能只看 argmax

一旦你理解了分布输出和交叉熵，再回头看 `argmax` 就会发现它的信息量其实很少。

`argmax` 只会告诉你：

> 当前概率最高的是谁。

但它会抹掉下面这些对训练很重要的事实：

- 第一名和第二名差距有多大
- 真实答案是排第二还是排最后
- 当前分布是非常尖锐还是非常平缓
- 模型是在略微偏错还是自信地错

所以 `argmax` 更适合做一种推理阶段的粗决策。
它不适合承担训练目标。

训练真正要优化的是整张分布。
而不是“第一名的名字”。

这也是为什么模型哪怕已经选对类别，loss 仍然可能不低。
因为训练并不满足于“只是碰巧选对”。
它还想推动模型：

> 把正确答案的概率继续推高，并重新整理整张候选分布。

## 为什么语言模型的交叉熵会在很多位置上同时重复发生

在普通分类里，一条样本常常只对应一次输出分布。

但语言模型更特别。

对于一个长度为 `T` 的序列，它通常不是只做一次分类，而是在很多位置上重复做同一种事情：

> 给定当前位置之前的历史，对整个词表给出一张分布，然后用真实下一个 token 计算一次交叉熵。

于是你会在一个 batch 里看到这样的结构：

- `batch`
- `sequence length`
- `vocab size`

模型会在每个位置上输出一整张词表分布。
再把每个位置的真实 token 拿来分别计算 loss。

从这个角度看，语言模型训练并不神秘。
它本质上是在很多位置上反复做同一种多类分布比较。

只是这个多类分类问题：

- 候选空间很大
- 位置很多
- 上下文不断变化

所以规模看起来吓人。

但结构上，它仍然是在重复：

> logits → softmax → 真实 token 目标 → 交叉熵

## 为什么框架通常直接写 `cross_entropy(logits, target)`

到这里，代码层面常见的一条写法就会变得非常自然：

```python
loss = F.cross_entropy(logits, target)
```

而不是先手动写：

```python
probs = softmax(logits)
loss = -log(probs[target])
```

这不只是为了省事。
更重要的是数值稳定。

如果你先显式做 softmax，再显式取对数，就可能在数值上遇到：

- 指数爆炸
- 极小概率下溢
- 浮点精度损失

而现代框架通常会把：

- softmax
- 取对数
- 挑出真实类别位置
- 求平均

合并成一个更稳定的内部计算过程。

所以你在代码里看到的 `cross_entropy(logits, target)`，不应该被理解成：

> 框架偷偷做了一些你不懂的黑箱事。

更准确的理解是：

> 它在用更稳定的方式，计算你已经在理论上理解过的那条输出接口链。

## softmax 和交叉熵不是两门内容，而是一条接口的前后两半

现在可以把本章最重要的结构压缩得更清楚一些了。

很多初学者会把 softmax 和交叉熵分别理解成：

- 一个常见激活函数
- 一个常见损失函数

这种记忆方式会让它们继续显得松散。

更稳的理解应该是：

> softmax 和交叉熵是一条输出接口的前后两半。

前一半在做：

> 把原始偏好分数翻译成概率分布。

后一半在做：

> 用目标分布衡量这张概率分布离理想状态还有多远。

所以它们不是“常常一起出现”。
而是：

> 只要你选择了“候选空间上的分布输出”这种建模方式，softmax 与交叉熵就几乎会自然捆在一起。

这就是为什么它们在分类、语言模型、序列标注乃至很多别的任务里反复出现。

## 为什么交叉熵下降，不自动等于生成观感一定全面变好

讲到这里，还必须提前埋下一个后文很重要的提醒。

既然交叉熵这么自然，又和真实答案概率直接相关，那是不是只要交叉熵持续下降，生成效果就一定会同步全面变好？

不能这么简单理解。

原因不是因为交叉熵没意义。
恰好相反，它非常有意义。

但它衡量的是：

> 在真实数据分布下，模型平均给真实答案分到了多大概率。

这当然和语言建模能力强相关。
但生成观感除了这个，还会同时受到：

- 采样策略
- 温度
- top-k / top-p
- 重复问题
- prompt 形式
- 评估样例覆盖范围

等因素影响。

更关键的是，交叉熵是平均量。
平均量下降，说明整体分布拟合在改进，但它不保证每一种主观观感都同步、线性地改善。

所以这一章建立的是：

> 输出接口和训练目标为什么长成现在这样。

它不是在保证：

> 只要 loss 下降，一切用户体验都会自动同步上升。

这个界限必须先立住。

## 这一章真正想留下的主线

如果把整章压缩成最核心的一条链，可以写成：

> 神经网络在输出端首先给出的不是答案，而是一组原始偏好分数；这些分数就是 logits，它们表达相对竞争关系，但还不是概率；softmax 把 logits 改写成可比较、可归一化的候选分布；目标端则不是一个孤零零的类别 id，而是一张理想分布，在最常见情形下它表现成 one-hot；交叉熵于是自然承担起“目标分布与模型分布差多远”的衡量工作，并在 one-hot 场景下退化成真实答案的负对数概率；语言模型训练只是在许多位置上不断重复这条输出接口链。

这条主线一旦稳住，后面很多实现细节都会突然变得自然：

- 为什么输出头常常先给 logits
- 为什么训练代码直接吃 logits 而不是显式概率
- 为什么 token prediction 是个分布问题
- 为什么交叉熵会成为如此核心的损失
- 为什么 perplexity 会和这里继续连起来

更重要的是，你不会再把“softmax”和“交叉熵”记成两个独立名词。
你会知道它们是同一条输出接口在前后两个位置上的自然角色。

## 读完本章后，你应该能稳定回答什么

如果这一章真正读稳了，你应该能够不用背诵公式，而是用自己的话稳定回答下面这些问题：

- 为什么模型输出的首先应该是一张候选分布，而不是一个类别 id
- logits 到底是什么，它为什么不是概率
- 为什么模型不直接在最后一层强行输出概率
- softmax 真正补上的是什么角色
- 为什么说 softmax 关心的是候选之间的竞争关系
- 目标分布和 one-hot 到底在表达什么
- 为什么交叉熵会自然退化成真实类别的负对数概率
- 为什么语言模型训练是在很多位置上重复这条分布比较过程

只要这些问题能够稳定答出来，这一章就已经完成了最重要的任务：

> 它让“logits、softmax、交叉熵”不再像训练脚本里的固定搭配，而像多类输出接口一旦成立之后，自然长出来的一整套结构语言。
