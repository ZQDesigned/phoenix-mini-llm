# 09. 一个完整小型语言模型由什么组成

## 这一章要解决什么问题

前面几章你已经分别理解了很多部件：

- token 和词表
- next-token prediction
- Attention
- Transformer Block
- 位置信息

现在要做的，不再是继续认识零件，而是把这些零件拼成一整台机器。

这一章要回答的问题是：

> 一个真正可训练、可推理、可扩展的小型 decoder-only 语言模型，到底由哪些部分组成？这些部分之间又是怎样衔接的？

如果这个问题不清楚，你后面即使能看懂若干文件，也很难真正理解自己到底在实现什么。

## 从全局先看一遍：完整模型是一条前向数据流

一个典型的小型 decoder-only 语言模型，如果把细节都暂时折叠起来，最核心的数据流是：

```text
token ids
-> token embeddings
-> 位置信息注入
-> 多层 transformer blocks
-> final norm
-> 线性输出头
-> logits
-> （训练时）loss
```

这条链就是整台模型的骨架。

你之后在不同项目里看到：

- 类名不一样
- 文件拆分不一样
- 某些层细节不一样

都不影响这个骨架仍然成立。

所以学会完整模型的第一步，不是背具体仓库结构，而是建立这条前向路径的全局感。

## 为什么离散 token 必须先变成连续向量

模型最开始拿到的输入只是整数编号，例如：

```text
[17, 923, 81, 4, 204]
```

这些整数本身没有“大小上的语义”。`204` 并不比 `81` 语义更强，`923` 也不表示它离 `924` 更近。

它们只是词表里的索引。

但神经网络后续要做的是：

- 矩阵乘法
- 点积相似度
- 非线性变换
- 梯度更新

这些都要求输入处在一个连续的向量空间里。

于是第一步必须是 embedding：

\[
[B, T] \rightarrow [B, T, H]
\]

这里：

- `B` 是 batch size
- `T` 是序列长度
- `H` 是隐藏维度

你可以把 embedding 看成：

> 一张可学习的查表系统，词表中每个 token 都对应一行长度为 `H` 的向量。

这一步做完之后，模型才真正拿到可计算、可学习的输入表示。

## embedding 层到底学到了什么

embedding 常被初学者误解成“把 token 转成浮点数”的步骤。其实它远不止如此。

一个训练中的 embedding 表，会逐步学出：

- 哪些 token 在统计上更相近
- 哪些 token 更常出现在相似上下文中
- 哪些词形、词缀、符号具有某种模式关联

这意味着 embedding 不是纯粹的输入适配器，它本身也是模型知识的一部分。

对于一个小型语言模型来说，embedding 层通常会占据相当可观的参数量，尤其当词表较大而隐藏维度也不小时更是如此。

## 为什么“位置”必须在模型一开始就进入表示

token embedding 只告诉模型：

> 这是什么 token。

但语言还需要知道：

> 它出现在什么位置。

因此在模型刚开始处理序列时，就必须把位置信息注入表示。否则后面的多层 block 都是在没有顺序感的前提下工作。

位置注入的具体方式可以不同：

- 把绝对位置向量加到 embedding 上
- 在注意力内部使用 RoPE
- 用相对位置偏置影响打分

但从系统角度看，意义都一样：

> 模型不能只知道“有哪些 token”，还必须知道“这些 token 按什么顺序排列”。

## 多层 block 在完整模型里扮演什么角色

embedding 只是把离散输入送入连续空间，真正的大部分表示学习都发生在多层 block 里。

你可以把多层 block 理解成模型的主体推理管道。

每一层都会做两件核心事情：

- 让当前位置与可见历史发生交互
- 让当前位置在融合完上下文后重新组织自己的表示

如果只有一层，模型当然也能工作，但表示加工轮次非常有限。

多层堆叠的意义是：

> 模型不是只看一眼上下文，而是在多个层次上反复读取、改写、细化内部表示。

这就是为什么深度会带来能力提升。不是因为“层数越多越神秘”，而是因为每一层都在给表示更多一次结构化处理机会。

## 为什么 block 的接口通常固定成 `[B, T, H]`

完整模型之所以容易理解，一个关键原因是：

> 主体部分的大多数层都围绕同一种张量形状工作。

也就是：

\[
[B, T, H] \rightarrow [B, T, H]
\]

这带来几个重要好处。

### 第一，堆叠很自然

上一层的输出可以直接作为下一层的输入。

### 第二，残差容易成立

因为输入和输出形状一致，才能做直接相加。

### 第三，模型像在同一语言表示空间里不断细化

这让整个结构更像一条连续的加工管道，而不是每一层都切换完全不同的表示接口。

## 最终归一化为什么常常单独存在

在很多 decoder-only 模型里，多层 block 结束后，还会有一层 final norm。

它的作用可以简单理解成：

> 在把最终隐藏表示送去做词表分类之前，再做一次整体整理。

为什么需要这一步？

因为经过多层叠加后，最后的隐藏状态虽然已经包含丰富语境信息，但其数值分布和尺度未必最适合直接进入输出头。

final norm 的存在，通常能让输出阶段更稳定，也更符合整体架构的数值习惯。

它不是最显眼的部件，但它属于完整模型中常见且合理的收口步骤。

## 输出头到底在做什么

经过多层 block 之后，每个位置都拥有了一个上下文感知的隐藏向量。现在模型要做的事是：

> 对于当前位置，词表里的每个 token 分别有多可能成为下一个 token？

于是需要一个输出头，把：

\[
[B, T, H]
\]

映射到：

\[
[B, T, V]
\]

其中 `V` 是词表大小。

这个输出就是 logits。

### logits 不是概率

这一点必须非常牢固。

logits 是未归一化分数。它们表示：

> 在当前位置下，模型对词表各项的相对偏好。

经过 softmax 之后，你才得到真正的概率分布。

训练时通常直接把 logits 送入 cross-entropy，而不是先手动做 softmax，因为很多框架会把数值更稳定的实现封装在一起。

## 输入 embedding 和输出头为什么常常会共享权重

很多语言模型会做 weight tying，也就是让输入 embedding 表和输出头的参数共享或强绑定。

为什么这是个合理想法？

因为这两件事并不是毫无关系：

- 输入时，模型要把词表项映射到内部表示空间
- 输出时，模型要判断当前位置的隐藏表示更像词表中的哪一项

这意味着：

> 输入空间和输出空间，本来就围绕同一个词表展开。

共享权重通常有几个好处：

- 减少参数量
- 让输入输出空间更一致
- 在很多实践中效果不错

你不需要先把它当成必须项，但应该知道它是完整模型里一个常见而且有清晰动机的设计。

## 完整模型除了前向路径，还包含一份“配置定义”

一个小型语言模型并不只是若干层代码。它还隐含着一整套结构定义，也就是配置。

最常见的关键超参数包括：

- `vocab_size`
- `max_seq_len`
- `hidden_size`
- `num_layers`
- `num_heads`
- `intermediate_size`
- `dropout`

这些数字不是装饰性设置，而是模型定义的一部分。

### `vocab_size`

决定输入输出空间有多大。

### `max_seq_len`

决定模型单次最多可见多长上下文。

### `hidden_size`

决定每个位置内部表示的宽度。

### `num_layers`

决定模型会做多少轮 block 级别的表示改写。

### `num_heads`

决定多头注意力把表示分成多少个并行子空间。

### `intermediate_size`

决定 FFN 中间扩展空间的大小，也代表逐位置非线性加工容量。

### `dropout`

决定训练时正则化强度。

真正重要的不是死记它们的名字，而是理解：

> 它们共同定义了模型的容量、成本和行为边界。

## 为什么这些超参数必须一起看

初学者很容易逐个看数字，比如：

> `hidden_size` 越大越好吗？

这类问法本身就有问题，因为模型设计不是逐个旋钮独立调节，而是整体预算平衡。

例如：

- 增大 `hidden_size` 会增加 Attention 和 FFN 的参数量与计算量
- 增大 `num_layers` 会增加深度、显存和训练时间
- 增大 `max_seq_len` 会显著提高序列相关成本
- 增大 `vocab_size` 会直接扩大 embedding 和输出头规模

所以一个合理的小模型设计，核心不是“把每个参数都尽量调大”，而是：

> 在数据规模、设备预算、学习目标之间找到一组能完整跑通的平衡值。

## 参数量大致从哪里来

当你听到“这个模型多少 M 参数”时，不要只把它当作一个宣传数字。更好的做法是知道参数主要来自哪里。

### embedding 参数

大致规模与：

\[
V \times H
\]

有关。

词表越大、隐藏维度越宽，embedding 越重。

### 注意力参数

注意力内部通常至少包含：

- `Q` 投影
- `K` 投影
- `V` 投影
- 输出投影

它们的规模通常与 `H × H` 同阶。

### FFN 参数

如果 FFN 从 `H` 扩到 `I` 再回到 `H`，那么参数规模大致与：

\[
H \times I + I \times H
\]

有关。

这也是为什么在很多 Transformer 里，FFN 往往是参数大户之一。

### 多层叠加

单层参数一旦确定，总体参数量还要乘上层数 `L`。

所以当你设计模型时，要同时考虑：

- 单层有多重
- 要堆多少层

## 训练显存并不只取决于参数量

这是理解“小模型能不能在某台机器上训练起来”的关键。

很多人会先看参数量，再问：

> 既然参数不算多，为什么还是显存不够？

因为训练时显存不只装参数，还要装：

- 梯度
- 优化器状态
- 前向中间激活
- Attention 相关临时张量

其中激活和序列长度关系很大，所以：

> 两个参数量差不多的模型，如果上下文长度不同，训练成本可能差很多。

这也是为什么理解完整模型时，不能只盯着“M 参数”一个数字。

## 一个“完整小模型”到底意味着什么

对学习项目来说，“完整”比“大”更重要。

一个完整的小模型，通常至少应该具备：

- 明确的 tokenizer 和词表
- token embedding
- 位置信息方法
- 多层 causal Transformer block
- final norm
- LM head
- 训练时的 loss 路径
- 推理时的自回归调用方式

这意味着它不只是“能前向一下”，而是：

> 从输入、到建模、到输出、到训练、到生成，这条链都闭合了。

对于学习来说，这种完整性非常重要。因为你能看到的将不只是单个模块，而是整个语言模型系统怎样首尾衔接。

## 训练视角和推理视角看的是同一台模型

一个常见误解是把“训练模型”和“生成模型”想成两套主体结构。

更准确的理解是：

> 主体结构通常是同一台模型，训练和推理的区别主要体现在外层调用协议上。

训练时：

- 输入一段 token
- 同时准备目标 token
- 利用所有位置的预测计算 loss

推理时：

- 输入一个 prompt
- 只关心最后一个位置的 logits
- 选出下一个 token
- 接回上下文，继续循环

也就是说，模型主体是共享的，变化的是：

- 是否传入目标
- 是否需要 loss
- 是否启用缓存
- 外层循环怎样组织

理解这一点，会让你后面写代码时更容易区分“模型结构”和“运行协议”。

## 为什么上下文长度是硬边界

`max_seq_len` 不是一个普通配置项，它是完整模型设计里的硬约束。

它决定了：

- 单个样本最多能看多长历史
- 注意力矩阵会有多大
- 训练和推理成本大致落在哪个量级

对小型项目来说，一个常见错误是：

> 一上来就把上下文长度设得很大，觉得这样模型会更强。

实际上，上下文越长，成本通常涨得非常快。对初学者更合理的策略常常是：

> 先用一个较保守、可以完整训练和调试的长度，把整条链打通，再逐步提高。

## 小而完整，为什么比大而失控更有学习价值

很多人刚接触大模型时，会本能地把学习目标设成“尽量做大”。但对从零构建的小型项目来说，更高价值的目标通常是：

> 做出一台你能完整解释、完整训练、完整调试、完整生成的模型。

原因很简单。

如果模型太大，你可能会遇到：

- 训练根本起不来
- 调试成本过高
- 很多实验看不清因果
- 出问题时不知道从哪里下手

而一个小而完整的模型虽然能力有限，但它能让你真正理解：

- 数据怎样进入模型
- 表示怎样层层变化
- loss 怎样驱动学习
- 生成怎样从分布变成文本

这才是学习阶段最宝贵的能力。

## 初学者最容易误解的几点

### 误区 1：完整模型就是“把层堆起来”

不对。完整模型是输入空间、顺序信息、上下文建模、输出分布和训练目标共同构成的系统。

### 误区 2：只要能输出 logits，模型就已经完整

不够。你还需要考虑 loss 路径、推理协议、上下文边界和词表定义。

### 误区 3：参数量越大，学习价值越高

通常不是。对初学者来说，可解释、可训练、可调试比盲目放大更重要。

### 误区 4：tokenizer 不属于模型本身

不对。tokenizer 决定了输入输出空间，它本来就是模型定义的一部分。

### 误区 5：训练模型和推理模型是两套主体

也不对。大多数情况下，是同一主体结构被不同外层协议调用。

## 这一章真正要建立的全局图景

如果这一章只保留一张脑内结构图，它应该是这样的：

> 一台小型 decoder-only 语言模型，是一条从离散 token 出发，经 embedding 和位置方法进入多层 Transformer block，再通过输出头产生词表分布，并同时服务训练与推理的完整系统。

理解了这张图，你后面再看任何“模型类”代码，都不会只看到零散函数，而会看到它在实现哪一段系统路径。
