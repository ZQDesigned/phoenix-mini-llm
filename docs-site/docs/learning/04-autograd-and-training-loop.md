# 04. 自动求导与训练闭环

## 这一章要解决什么问题

到目前为止，你已经知道：

- 语言模型在做下一个 token 预测
- token 会被映射成向量
- 模型内部主要是在处理 tensor 和 shape

但真正让模型“从不会到会”的，不是这些静态部件本身，而是训练闭环。也就是下面这条链：

1. 前向传播
2. 计算损失
3. 反向传播
4. 参数更新

如果这一条链你没有真正看懂，那么训练代码在你眼里永远只会像一段固定模板。你能抄，但不会调，不会查错，也不会知道后面出现的梯度累积、混合精度、梯度裁剪到底是在加强哪一环。

这一章的目标，就是把这条链讲透。

## 第一件事：训练不是“执行脚本”，而是不断修正参数

语言模型最开始并不会说话。更准确地说，它最开始只是一个带随机参数的函数。

这意味着：

- 你给它输入，它当然会输出结果
- 但这些结果一开始几乎没有可用意义

训练的作用就是：

> 通过反复比较“模型当前输出”和“正确答案”的差异，逐步调整参数，让模型的输出分布朝正确方向移动。

所以训练从来不是“再跑一遍前向”，而是“让参数发生有方向的变化”。

## 第二件事：前向传播到底在做什么

### 前向传播不是学习，它是在“当前参数下作答”

当前向发生时，模型做的事情其实很朴素：

- 读取输入
- 按当前参数执行一系列计算
- 产生输出

如果这是语言模型，那么输出通常是一批 logits，也就是每个位置对整个词表的未归一化分数。

例如在一个典型的小型 decoder-only 语言模型里，前向大致会把：

```text
input_ids -> embeddings -> blocks -> final norm -> lm head -> logits
```

串起来。

### 为什么说“前向本身不等于学习”

因为前向只是在回答：

> 按照当前这套参数，我现在会给出什么结果？

如果你不把这个结果和正确答案比较，不计算损失，不回传梯度，不更新参数，那么模型不会自动变好。

## 第三件事：损失函数为什么是训练闭环的桥梁

模型前向拿到的是输出，但训练需要的是“这个输出到底好不好”的度量。

这就是损失函数的职责。

### 对语言模型来说，常见损失是什么

最常见的是 cross-entropy。它在做的事情可以直观理解为：

- 看模型给正确 token 分配了多高的分数
- 正确 token 越被压低，损失越大
- 正确 token 越被抬高，损失越小

### 为什么语言模型用的是 logits 而不是直接概率

因为模型最后通常直接输出 logits。你当然可以手动：

1. 对 logits 做 softmax
2. 再取对数
3. 再构造损失

但实际训练中，框架通常会把这些步骤稳定地组合进 cross-entropy 中，这样数值表现更好。

## 第四件事：自动求导到底自动了什么

很多初学者第一次看到 `loss.backward()` 会有两种误解：

- 误以为它在“自动训练模型”
- 或误以为它只是某种必要但不必理解的固定仪式

两种都不对。

### 自动求导在做什么

当你用 PyTorch 构建前向计算时，框架会在内部记录一张计算图。这个图描述了：

- 当前输出是怎样由前面一系列张量运算得到的
- 哪些张量依赖哪些参数

当你调用：

```python
loss.backward()
```

框架就会沿着这张图反向传播，计算每个参数对损失的梯度，并把结果写到参数的 `.grad` 中。

### 它没有做什么

它不会自动：

- 清空旧梯度
- 更新参数
- 调整学习率

这些都需要训练循环显式控制。

## 第五件事：优化器才是真正修改参数的人

理解这一点非常关键：

- `backward()` 负责算梯度
- `optimizer.step()` 负责用梯度更新参数

你可以把梯度理解成“建议”，把优化器理解成“执行更新的人”。

最常见的训练步骨架是：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

### 这三行分别在干什么

#### `optimizer.zero_grad()`

清掉上一轮残留梯度。

因为在 PyTorch 里，梯度默认是累加的。如果你不清零，那么本轮梯度会叠在上一轮上面，除非你本来就是有意做梯度累积。

#### `loss.backward()`

沿计算图计算当前损失对每个参数的梯度。

#### `optimizer.step()`

根据当前梯度和优化器规则，实际更新参数。

只有这一步之后，模型参数才真的变了。

## 第六件事：一个最小训练闭环到底长什么样

下面是一段非常小的示意代码：

```python
import torch

x = torch.tensor([[1.0]])
y = torch.tensor([[2.0]])

linear = torch.nn.Linear(1, 1)
optimizer = torch.optim.SGD(linear.parameters(), lr=0.1)

for step in range(5):
    optimizer.zero_grad()
    pred = linear(x)
    loss = torch.nn.functional.mse_loss(pred, y)
    loss.backward()
    optimizer.step()
    print(step, float(loss))
```

虽然它不是语言模型，但已经完整体现了训练的四步：

1. 前向得到预测
2. 计算损失
3. 反向得到梯度
4. 更新参数

如果损失在大体上下降，就说明参数在朝更合理的方向移动。

## 第七件事：为什么学习率重要，但你现在不需要先学很多优化理论

参数更新的最简化形式常写成：

\[
\theta \leftarrow \theta - \eta \nabla_\theta L
\]

其中：

- \(\theta\) 是参数
- \(\eta\) 是学习率
- \(\nabla_\theta L\) 是损失对参数的梯度

你现在不需要推导它，但必须建立一个非常重要的直觉：

- 梯度告诉你“往哪里改”
- 学习率告诉你“每次改多大”

如果学习率太小：

- 模型学得非常慢

如果学习率太大：

- 损失可能震荡
- 甚至直接发散或变成 NaN

这也是为什么后面训练工程章节会非常重视优化器和调度器。

## 第八件事：为什么“会跑”不等于“训练正确”

这是训练闭环里最容易踩的坑之一。

一个训练脚本可能满足：

- 没有报错
- loss 也在变化
- GPU 也在跑

但仍然可能有严重问题，例如：

- 目标序列构造错了
- 梯度没清零
- 参数根本没更新
- loss 缩放有误
- 训练和评估路径混在一起

所以判断训练是否正确，不能只看“它动起来了”，而要看你是否理解每一步在做什么。

## 第九件事：语言模型里的训练闭环和这个最小例子有什么关系

在真实的小型语言模型训练里，训练代码当然会更复杂，里面会加入：

- batch
- `input_ids` 和 `targets`
- cross-entropy
- 梯度裁剪
- 梯度累积
- 混合精度
- 中间状态保存
- 验证集评估

但这些复杂结构并没有改变训练闭环的核心骨架。它们只是在解决现实工程问题，例如：

- 显存不足怎么办
- 数值稳定性怎么保证
- 中断训练后怎么恢复
- 如何判断模型是否真正进步

所以你现在最该做的不是急着记那些工程细节，而是先把最小闭环理解扎实。

<Callout title="为什么这一章是后面所有训练工程的地基" tone="warning">
  后面你会看到梯度累积、混合精度、梯度裁剪、定期评估和中间状态保存。如果最小训练闭环没有理解清楚，那么这些东西看起来都会像随机拼装的技巧，而不是在增强同一条训练链。
</Callout>

## 一个更接近语言模型的最小损失例子

下面这段代码展示了 logits 与 targets 如何进入 cross-entropy：

```python
import torch
import torch.nn.functional as F

logits = torch.tensor([
    [[2.0, 0.5, -1.0], [0.1, 1.8, 0.2]]
])  # [batch=1, seq=2, vocab=3]

targets = torch.tensor([[0, 1]])

loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),
    targets.view(-1),
)

print(loss)
```

这里有两个你必须看懂的点：

1. `logits` 的最后一维是词表大小
2. `targets` 存的是每个位置正确 token 的 id

这正是语言模型训练的核心监督方式。

## 三个最常见的误区

### 误区 1：`backward()` 会自动更新参数

不会。它只负责计算梯度。参数真正改变发生在 `optimizer.step()`。

### 误区 2：loss 下降一次就说明训练链路正确

不一定。真正要看的，是：

- 趋势是否合理
- 在极小数据上是否可过拟合
- 验证损失和训练损失之间关系是否正常

### 误区 3：训练循环只是固定模板，不需要理解

这是后面最容易让你失去调试能力的想法。因为后面一旦出现：

- NaN
- 发散
- 显存不足
- 训练中断后的恢复异常

你就必须回到训练闭环理解每一步在解决什么。
