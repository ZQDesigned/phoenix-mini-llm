# 04. 自动求导与训练闭环

到目前为止，你已经知道：

- 语言模型的目标是预测下一个 token
- 文本会被变成 token 序列
- 模型内部会把 token 表示成张量和向量

但这些都还是“静态结构”。真正让模型从“完全不会”逐渐变成“越来越会”的，不是静态结构本身，而是一条不断重复的学习闭环：

1. 前向传播
2. 计算损失
3. 反向传播
4. 参数更新

如果你对这条链的理解停留在“训练代码里总会写这几行”，那么后面你几乎一定会遇到一个问题：

> 能抄代码，但不会判断训练到底有没有真的发生。

更严重的是，后面出现的很多训练概念都会变得很空：

- 梯度累积
- 学习率调度
- 混合精度
- 梯度裁剪
- checkpoint 恢复

它们看起来像很多独立技巧，但其实都在围绕同一条训练链工作。

这一章的目标，就是把“模型为什么会学”讲清楚。

## 训练不是“执行一次脚本”，而是“不断修正参数”

先从最基本的事实开始。

一个刚刚初始化好的语言模型，虽然已经拥有：

- embedding
- attention
- block
- 输出层

但它一开始并不会“懂语言”。

更准确地说，它只是一个带随机参数的函数。

这意味着什么？

如果你给它输入一串 token，它当然也会输出一组 logits。因为从计算角度看，矩阵乘法、归一化、非线性变换都能正常执行。

但这些输出在一开始几乎没有学习价值。因为参数还没有被调成“更擅长预测正确 token”的状态。

训练真正做的事情是：

> 不断比较“模型当前给出的答案”和“真实答案”之间的差异，然后沿着能减少这种差异的方向微调参数。

所以训练从来不是“再跑一遍模型”，而是：

> 让参数朝着更会预测的方向缓慢移动。

一旦你把这一点抓稳，后面几乎所有训练概念都会自然归位。

## 前向传播到底在做什么

前向传播是训练闭环的第一步，但它本身还不是学习。

最朴素的定义就是：

- 给模型输入
- 让当前参数参与计算
- 得到当前输出

如果这是语言模型，那么输入通常是一段 token id 序列，输出通常是一段 logits，也就是：

> 对每个位置的下一个 token，各候选词表项分别得到多少分。

为什么前向传播本身不等于学习？

因为前向只回答一个问题：

> 按照当前这组参数，如果我现在要作答，我会怎么答？

它并没有告诉你：

- 答得对不对
- 错在什么地方
- 应该怎样改参数

所以前向传播只是“先交卷”，并不自动包含“批改”和“改进”。

很多初学者会把前向当成模型的主要内容，把训练当成“后面补几步”。更合理的理解应该是：

- 前向决定模型如何作答
- 训练闭环决定模型如何从作答中变得更会作答

两者缺一不可。

## 损失函数为什么是训练链里最关键的桥

前向得到输出之后，模型还不知道自己答得怎么样。

此时必须出现一个桥梁，把：

- 模型给出的输出
- 真实目标

连接起来，形成一个可优化的信号。

这就是损失函数的职责。

最直观的理解是：

> 损失把“你答得有多差”压缩成一个可供优化的数字。

如果模型给正确 token 的分数太低，损失就会更大；如果模型给正确 token 的分数更高，损失就会更小。

对语言模型来说，这一步尤其关键，因为模型最终输出的是整张词表上的分数，而真实目标只告诉你：

> 在这个位置上，哪个 token 才是训练数据里的正确后续。

损失函数的任务，就是把“整张词表上的偏好结构”和“正确后续是谁”接起来。

所以 loss 不是可有可无的评分器，它是训练闭环真正接上“正确答案”的地方。

## 为什么语言模型常用 cross-entropy

语言模型的每个位置，本质上都在做一件事：

> 在整张词表里，应该把哪个 token 当成当前的正确后续？

这就是一个标准的分类问题，而 cross-entropy 正是最常见的分类损失之一。

它背后的核心思想并不神秘：

> 如果正确 token 得到的概率越高，损失越低；如果正确 token 得到的概率越低，损失越高。

你现在不需要把所有公式推到最深，但必须先抓住这层概念关系。因为后面无论是 perplexity、训练曲线，还是“模型答错了为什么会被惩罚”，都和这条关系直接相连。

## 为什么模型通常输出 logits，而不是直接输出概率

这是一个非常常见的初学者疑问。

既然我们最终关心概率，为什么模型不直接输出概率，而是先输出 logits？

logits 可以理解成：

> 未归一化的候选分数。

例如模型在某个位置也许会给出：

```text
time: 4.8
day: 2.1
night: 1.5
dragon: -0.8
```

这些数不是概率，但已经表达了偏好顺序。

为什么不直接输出概率？因为在实际训练中，先输出 logits 更自然也更稳定。常用的损失函数会在内部完成：

- softmax
- 对数处理
- 负对数似然计算

也就是说：

> 模型负责给分，损失函数负责把“给分”和“正确答案”连起来。

这个分工非常自然，也正是现代深度学习训练里最常见的形式。

## 自动求导真正自动的是什么

很多人第一次看到：

```python
loss.backward()
```

都会产生一种错觉，好像它是某种“自动训练模型”的魔法开关。

这理解不对。

当你用 PyTorch 做前向计算时，框架会在内部记录一张计算图。你可以把它理解成：

> 一份关于“当前输出是怎样一步一步由输入和参数算出来的”依赖记录。

当你调用：

```python
loss.backward()
```

框架就会沿着这张计算图反向传播，计算出：

- 每个参数对当前 loss 的影响方向
- 每个参数对当前 loss 的影响强弱

这些信息会以梯度的形式写到参数上。

所以自动求导真正自动的，是：

> 求梯度这件事。

它没有自动做下面这些事情：

- 清空旧梯度
- 修改参数
- 选学习率
- 保存 checkpoint
- 判断这次训练是不是有意义

这些仍然需要训练循环的其他部分来完成。

## 梯度到底应该怎样理解

“梯度”这个词如果只按数学定义理解，很容易显得抽象。

对学习阶段来说，一个更有用的直觉是：

> 梯度告诉你：如果想让当前 loss 下降，每个参数大致应该往哪个方向改，以及这个方向的敏感程度有多大。

注意，梯度不是最终更新本身。

它更像一种建议：

- 这个参数往大一点改还是往小一点改
- 改得快一点还是慢一点

然后真正执行这些建议的，是优化器。

这个区别非常重要，因为很多后续训练技巧本质上都在围绕梯度做文章，例如：

- 梯度累积
- 梯度裁剪
- 梯度缩放
- 梯度清零

如果你把梯度和参数本身混在一起，后面这些技巧就会显得非常散。

## 优化器到底在做什么

当梯度已经被算出来之后，训练还差最后一步：根据这些梯度真的去改参数。

这就是优化器的职责。

最基本的优化器思路非常简单：

> 如果某个参数往某个方向改能让 loss 降一点，那就沿着那个方向走一小步。

最经典的形式可以写成：

\[
\theta \leftarrow \theta - \eta \nabla_\theta L
\]

这里：

- \(\theta\) 表示参数
- \(\nabla_\theta L\) 表示梯度
- \(\eta\) 表示学习率

你现在不必先深究所有优化器变体，但必须先抓住一件事：

> 优化器不是“又一个模块”，而是把梯度建议真正变成参数移动的执行者。

没有它，梯度只是一堆计算结果，不会自动让模型变好。

## 学习率为什么会成为训练里最敏感的旋钮之一

学习率决定的是：

> 每次根据当前梯度更新参数时，到底迈多大一步。

如果学习率太小，训练会很慢，loss 下降也可能非常迟缓。

如果学习率太大，参数就可能在损失面上跨得过猛，导致：

- loss 抖动
- 不收敛
- 甚至直接发散成 `nan`

这说明学习率不是一个外围调参项，而是训练链中控制“更新步幅”的核心旋钮。

也正因为如此，后面才会出现：

- warmup
- scheduler
- 不同优化器的默认学习率差异

这些东西不是附加技巧，而是在围绕“步子该迈多大”这个核心问题做细化。

## 为什么需要 `zero_grad()`

很多人第一次看训练循环时，都会疑惑：

> 既然每次都会重新算梯度，为什么还要先清空旧梯度？

原因是，在 PyTorch 里，梯度默认是累加到参数上的，而不是自动覆盖。

也就是说，如果你连续两次 `backward()`，而中间没有清零，那么第二次看到的梯度就会包含前一次的残留。

这在某些场景下是刻意要利用的，例如梯度累积；但在普通训练步骤里，如果你忘了清零，训练就会悄悄变味。

所以：

```python
optimizer.zero_grad()
```

不是某种固定仪式，而是在明确地告诉系统：

> 现在开始新一轮梯度统计，不要把上一轮的残留带进来。

## 一个最小训练循环到底长什么样

如果把所有细节压缩掉，一个最小训练循环可以被理解成下面这几步：

1. 取一批样本
2. 做前向传播
3. 计算 loss
4. 清空旧梯度
5. 做反向传播
6. 调用优化器更新参数

写成 PyTorch 伪代码大致像这样：

```python
for batch in dataloader:
    optimizer.zero_grad()
    logits = model(batch["input_ids"])
    loss = compute_loss(logits, batch["targets"])
    loss.backward()
    optimizer.step()
```

这几行代码非常短，但它们串起来的，是一整条学习闭环。

真正需要你读懂的不是语法，而是每一步在链里承担什么职责：

- `model(...)` 负责当前作答
- `compute_loss(...)` 负责把作答和正确答案接起来
- `backward()` 负责求出应该怎样改
- `step()` 负责真的去改

## 为什么说训练闭环才是“模型真的在学”的地方

一个模型能前向，不代表它会学。

一个模型能输出 logits，不代表它会学。

一个模型能算出 loss，甚至也还不代表它一定会学。

只有当下面整条链都真的成立时，你才能说：

> 模型正在学习。

这条链包括：

- 数据和目标是对的
- 前向输出和目标语义能对上
- loss 真能反映“答错多少”
- backward 真算出了合理梯度
- optimizer 真按这些梯度修改了参数
- 下一轮前向的行为因此发生了可积累的改善

这也是为什么很多训练 bug 看起来模型“在跑”，但其实学不到东西。因为出问题的不一定是前向，而可能是整条闭环中的任何一环。

## 为什么 tiny batch overfit 是如此重要的测试

如果你要判断一条训练闭环是否真的成立，最值得做的测试之一就是：

> 让模型去过拟合一小批极小样本。

这项测试的价值在于，它把问题压缩得非常小。如果模型在极小样本上都不能迅速把 loss 降下去，那么你就知道问题更可能出在：

- 数据构造
- 标签右移
- mask
- loss 定义
- 梯度传播
- 学习率设置

反过来，如果它可以稳定过拟合极小样本，那么至少说明从数据到更新的主链大概率是通的。

所以 tiny batch overfit 不是“额外测试”，而是训练闭环最有信息量的验证手段之一。

## 为什么 `train()` 和 `eval()` 模式也属于训练闭环

很多人把：

```python
model.train()
model.eval()
```

理解成一种礼貌性的框架写法。

其实它们关系到模型当前使用什么行为模式。

例如，某些层在训练和推理时行为不同：

- dropout 在训练时会随机丢弃，在推理时不会
- 某些归一化相关层在不同模式下会有不同统计策略

这说明训练闭环并不只是 `backward()` 和 `step()` 的事情，它还包括：

> 模型当前是处于学习模式，还是处于评估模式。

如果这点没管对，实验结果很容易失真。

## 为什么 `torch.no_grad()` 也值得尽早理解

在训练时，我们需要构建计算图并保存梯度信息，因为后面要反向传播。

但在纯推理或评估时，这些梯度记录通常并不需要。

这时使用：

```python
with torch.no_grad():
    ...
```

的意义在于：

- 省显存
- 减少不必要的图记录
- 提高推理效率

也就是说，“要不要记录梯度”本身就是一种运行模式选择。训练阶段和推理阶段之所以开销不同，这也是原因之一。

## 初学者在这里最容易犯的几个误解

第一个误解是：只要模型能前向并输出 logits，就说明它已经在学习。

不对。前向只是当前作答，学习发生在完整训练闭环里。

第二个误解是：`loss.backward()` 会自动完成整个训练。

不对。它只负责求梯度，不负责清空旧梯度、更新参数或保存模型。

第三个误解是：loss 只是一个打印出来观察的数字。

不对。loss 是把模型输出和真实目标接起来的优化桥梁。

第四个误解是：梯度就是参数本身的一部分。

不对。参数描述模型当前长什么样，梯度描述这一步里参数应该怎么改。

第五个误解是：训练循环里的那些固定写法只是框架模板。

不对。每一步都在承担明确职责，缺任何一环都会让学习失效或变味。

## 这一章真正要记住的核心句子

如果只能记住一句话，请记住这一句：

> 模型之所以会学，不是因为它能前向算出结果，而是因为训练闭环把“当前作答”和“真实答案”连成了一条可反向追责、可沿梯度更新参数的链。

- 为什么前向传播本身不等于学习？

- 优化器到底在执行什么？

## 如果现在只能先记住一个排障原则

请先记住这个原则：

> 训练一旦异常，不要只盯着 loss 数字本身，而要沿着“输入、前向、目标、loss、梯度、更新”这条闭环逐段排查，问清楚到底哪一环没有真的成立。

这会比盲调超参数有效得多。

## 小结

这一章真正搭起来的，是一张训练因果图：

- 前向负责当前作答
- loss 负责连接正确答案
- backward 负责追责到参数
- optimizer 负责真的执行参数移动

一旦这张因果图站稳，后面你再遇到学习率、梯度裁剪、混合精度、梯度累积和 checkpoint 恢复时，就不会觉得它们是很多彼此独立的小技巧。你会知道，它们都在围绕同一件事工作：

让这条训练闭环更稳定、更高效、更可控。
