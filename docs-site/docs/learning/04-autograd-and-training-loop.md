# 04. 自动求导与训练闭环

## 这一章要解决什么问题

到目前为止，你已经知道：

- 语言模型的目标是预测下一个 token
- 文本会被变成 token 序列
- 模型内部会把 token 表示成张量和向量

但这些都还是“静态结构”。真正让模型从“完全不会”逐渐变成“越来越会”的，不是静态结构本身，而是一条不断重复的学习闭环：

1. 前向传播  
2. 计算损失  
3. 反向传播  
4. 参数更新

如果你对这条链的理解停留在“训练代码里总会写这几行”，那么后面你几乎一定会遇到一个问题：

> 能抄代码，但不会判断训练到底有没有真的发生。

更严重的是，后面出现的很多训练概念都会变得很空：

- 梯度累积
- 学习率调度
- 混合精度
- 梯度裁剪
- checkpoint 恢复

它们看起来像很多独立技巧，但其实都在围绕同一条训练链工作。

这一章的目标，就是把“模型为什么会学”讲清楚。

## 第一件事：训练不是“执行一次脚本”，而是“不断修正参数”

先从最基本的事实开始。

一个刚刚初始化好的语言模型，虽然已经拥有：

- embedding
- attention
- block
- 输出层

但它一开始并不会“懂语言”。

更准确地说，它只是一个带随机参数的函数。

### 这意味着什么

如果你给它输入一串 token，它当然也会输出一组 logits。因为从计算角度看，矩阵乘法、归一化、非线性变换都能正常执行。

但这些输出在一开始几乎没有学习价值。因为参数还没有被调成“更擅长预测正确 token”的状态。

### 训练真正做的是什么

训练的本质是：

> 不断比较“模型当前给出的答案”和“真实答案”之间的差异，然后沿着能减少这种差异的方向微调参数。

所以训练从来不是“再跑一遍模型”，而是：

> 让参数朝着更会预测的方向缓慢移动。

一旦你把这一点抓稳，后面几乎所有训练概念都会自然归位。

## 第二件事：前向传播到底在做什么

前向传播是训练闭环的第一步，但它本身还不是学习。

### 前向传播最朴素的定义

前向传播就是：

- 给模型输入
- 让当前参数参与计算
- 得到当前输出

如果这是语言模型，那么输入通常是一段 token id 序列，输出通常是一段 logits，也就是：

> 对每个位置的下一个 token，各候选词表项分别得到多少分。

### 为什么前向传播本身不等于学习

因为前向只回答一个问题：

> 按照当前这组参数，如果我现在要作答，我会怎么答？

它并没有告诉你：

- 答得对不对
- 错在什么地方
- 应该怎样改参数

所以前向传播只是在“出题后先交卷”，并不自动包含“批改”和“改进”。

### 一个很重要的心理转折

很多初学者会把前向当成模型的主要内容，把训练当成“后面补几步”。这其实是倒过来的。

更合理的理解是：

- 前向决定模型如何作答
- 训练闭环决定模型如何从作答中变得更会作答

两者缺一不可。

## 第三件事：损失函数为什么是训练的桥梁

前向得到输出之后，模型还不知道自己答得怎么样。

此时必须出现一个桥梁，把：

- 模型给出的输出
- 真实目标

连接起来，形成一个可优化的信号。

这就是损失函数的职责。

### 损失在做什么

最直观的理解是：

> 损失把“你答得有多差”压缩成一个可供优化的数字。

如果模型给正确 token 的分数太低，损失就会更大；如果模型给正确 token 的分数更高，损失就会更小。

### 为什么语言模型常用 cross-entropy

因为语言模型的每个位置，本质上都在做一件事：

> 在整张词表里，应该把哪个 token 当成正确答案？

这就是一个标准的分类问题，而 cross-entropy 正是最常见的分类损失之一。

### 对学习阶段最重要的理解

你现在不需要把所有公式推到最深，但必须明白：

> loss 不是可有可无的评分器，它是训练闭环真正接上“正确答案”的地方。

如果没有损失，模型就只能输出结果，却不知道该朝哪边改。

## 第四件事：为什么语言模型通常直接输出 logits，而不是概率

这是一个很常见的初学者疑问。

既然我们最终关心概率，为什么模型不直接输出概率，而是先输出 logits？

### logits 是什么

logits 是未归一化分数。

比如模型在某个位置也许会给出：

```text
time: 4.8
day: 2.1
night: 1.5
dragon: -0.8
```

这些数不是概率，但已经表达了偏好顺序。

### 为什么不直接输出概率

因为在实际训练中，直接输出 logits 更方便也更稳定。常用的损失函数会在内部完成：

- softmax
- 对数处理
- 负对数似然计算

也就是说：

> 模型负责给分，损失函数负责把“给分”和“正确答案”连起来。

这个分工非常自然。

## 第五件事：什么叫自动求导

很多人第一次看到：

```python
loss.backward()
```

都会有一种错觉，好像它是某种“自动训练模型”的魔法开关。

这理解不对。

### 自动求导真正自动的是什么

当你用 PyTorch 进行前向计算时，框架会在内部记录一张计算图。你可以把它理解成：

> 一份关于“当前输出是怎样一步一步由输入和参数算出来的”依赖记录。

当你调用：

```python
loss.backward()
```

框架就会沿着这张计算图反向传播，计算出：

- 每个参数对当前 loss 的影响方向
- 每个参数对当前 loss 的影响强弱

这些信息会以梯度的形式写到参数上。

### 自动求导没有自动做什么

它不会自动：

- 清空旧梯度
- 改参数
- 保存模型
- 选学习率

所以自动求导自动的只是：

> 求梯度这件事。

学习本身还要靠后面的步骤配合完成。

## 第六件事：梯度到底应该怎样理解

“梯度”这个词如果一开始只按数学定义理解，很容易很抽象。

对学习阶段来说，一个更有用的直觉是：

> 梯度告诉你：如果想让当前 loss 下降，每个参数大致应该往哪个方向改、改多大更敏感。

### 梯度不是最终更新本身

它更像一种建议：

- 这个参数往大一点改还是往小一点改
- 改得快一点还是慢一点

然后真正执行这些建议的，是优化器。

### 为什么梯度和参数不是一回事

参数是模型当前“长什么样”的数字。

梯度是当前这一轮训练里，针对 loss 给出的“该怎么改”的局部信号。

这个区别非常重要，因为很多后续训练技巧本质上都在围绕梯度做文章，例如：

- 梯度累积
- 梯度裁剪
- 梯度缩放

## 第七件事：优化器才是真正更新参数的人

如果把训练闭环拆开来看：

- 前向传播得到答案
- 损失函数给出错误大小
- 自动求导计算出梯度
- 优化器根据梯度修改参数

所以优化器的职责是：

> 把“应该怎么改”的梯度信号，变成真正的参数更新动作。

### 一个最常见的训练步骨架

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

这三行不是仪式，而是在分别做三件不同的事。

#### `optimizer.zero_grad()`

清理上一轮遗留梯度。

#### `loss.backward()`

根据当前 loss 计算每个参数的梯度。

#### `optimizer.step()`

真正执行参数更新。

只有第三步发生后，模型才真的“变了”。

## 第八件事：为什么 PyTorch 里默认要手动清梯度

这件事对很多初学者来说非常反直觉。

大家通常会想：

> 新一轮训练为什么不自动覆盖旧梯度？

因为在 PyTorch 里，梯度默认是累加的。

### 这有什么好处

这不是一个奇怪设计，而是为了支持某些训练模式，例如：

- 梯度累积

也就是说，默认累加让你有机会把多次小 batch 的梯度先叠起来，再统一更新。

### 如果你不想累加怎么办

那就每轮都显式清零。

所以你看到 `zero_grad()` 时，不能把它理解成某种多余步骤，而要理解成：

> 我现在要开始这一轮新的梯度统计了。

## 第九件事：一个最小训练闭环到底长什么样

下面是一段极小的训练代码：

```python
import torch

x = torch.tensor([[1.0]])
y = torch.tensor([[2.0]])

linear = torch.nn.Linear(1, 1)
optimizer = torch.optim.SGD(linear.parameters(), lr=0.1)

for step in range(5):
    optimizer.zero_grad()
    pred = linear(x)
    loss = torch.nn.functional.mse_loss(pred, y)
    loss.backward()
    optimizer.step()
    print(step, float(loss))
```

虽然这不是语言模型，但它已经完整体现了训练闭环：

1. 当前参数下做前向  
2. 计算输出与真实答案差多远  
3. 通过反向传播得到梯度  
4. 根据梯度修改参数  

如果 loss 大体下降，就说明参数正在朝更合理的方向移动。

### 为什么这个极小例子很重要

因为它帮你看见：

> 语言模型训练虽然复杂得多，但骨架没有变。

后面加上的 batch、序列、cross-entropy、多层模型，都是在这个骨架上扩展出来的。

## 第十件事：学习率到底在控制什么

参数更新的最简形式常写成：

\[
\theta \leftarrow \theta - \eta \nabla_\theta L
\]

其中：

- \(\theta\) 是参数
- \(\nabla_\theta L\) 是梯度
- \(\eta\) 是学习率

你现在不需要沉迷公式，但必须建立一个非常扎实的直觉：

> 梯度告诉你方向，学习率告诉你步子多大。

### 学习率太小会怎样

- 参数每次只移动一点点
- 模型学得很慢
- 看起来训练在跑，但进步很有限

### 学习率太大会怎样

- 参数跳得太猛
- loss 抖动甚至发散
- 训练可能非常不稳定

所以很多训练失败，根本原因不是结构不对，而是：

> 你让参数走路时步子迈得不合适。

## 第十一件事：为什么“loss 在变”不等于“训练正确”

这是训练闭环里最危险的一种错觉。

一个训练脚本可能满足：

- 没报错
- GPU 在跑
- loss 数字在变化

但仍然可能有严重问题，例如：

- 目标构造错了
- 梯度没有正确清理
- 参数根本没更新
- 学习率极度不合理
- 训练和评估路径混在一起

也就是说：

> 训练脚本会跑，不代表模型真的在按你想要的方式学习。

所以真正的理解不应该停在“我知道该写哪三行”，而要推进到：

- 为什么这三行要按这个顺序出现
- 哪一步如果出错，表面上仍然可能继续运行

## 第十二件事：语言模型训练为什么只是这个闭环的扩展版

当你从极小线性层训练例子切换到真实语言模型时，复杂度当然会大幅上升。你会开始看到：

- batch
- `input_ids`
- `targets`
- cross-entropy
- 多层模型
- 梯度裁剪
- 梯度累积
- 混合精度
- 验证集

但最重要的判断是：

> 这些复杂度不是在替换训练闭环，而是在同一条闭环上叠加更多现实需求。

也就是说：

- 前向仍然是前向
- loss 仍然是 loss
- backward 仍然是在算梯度
- step 仍然是在改参数

一旦你把这条主线抓稳，后面再遇到更复杂训练代码时，就不会觉得它是在表演魔法，而会知道它只是把同一条闭环扩展得更完整了。

## 第十三件事：为什么训练闭环一旦理解错，后面所有训练工程都很难学懂

后面你一定会看到很多“工程层”概念：

- 梯度累积
- 混合精度
- 梯度裁剪
- 学习率调度
- checkpoint 恢复

如果训练闭环没看懂，这些东西就会显得像：

- 随机技巧
- 到处加点复杂度
- 只存在于别人项目里的“模板代码”

但如果闭环清楚，你就会知道：

- 梯度累积是在改“什么时候 step”
- 混合精度是在改“前向和反向怎么更省资源”
- 梯度裁剪是在保护“step 之前的梯度不要过大”
- 调度器是在调“每次 step 的步子多大”

也就是说，它们全都在围绕同一个系统运转。

## 第十四件事：从学习角度看，自动求导到底值钱在哪里

如果没有自动求导，你当然也能理论上手推所有梯度，但在真实模型里几乎不可行。因为模型会包含：

- 很多层
- 很多矩阵运算
- 很多中间结果

自动求导真正解放你的地方在于：

> 你可以把主要精力放在“模型结构是否合理、目标定义是否正确、训练流程是否健康”上，而不是把时间消耗在手动求每一项导数。

这也是为什么 PyTorch 对学习项目如此友好。它把最繁重的求导劳动自动化了，让你能把认知资源放在更重要的建模问题上。

## 第十五件事：初学者最容易误解的几点

### 误区 1：前向传播本身就是训练

不对。前向只是给出当前参数下的答案，不会自动让模型变好。

### 误区 2：`loss.backward()` 会自动训练模型

不对。它只负责计算梯度，真正更新参数还要靠优化器。

### 误区 3：优化器只是固定模板中的一个对象

不对。它直接决定参数怎样更新。

### 误区 4：loss 在变化就说明训练没问题

不对。很多错误目标或错误流程也会产生“看起来在变化的 loss”。

### 误区 5：后面的训练技巧和这条闭环没关系

不对。大多数训练工程技巧，本质上都在增强这条闭环的不同部分。

> **这一章真正要你理解的不是三行模板，而是一条学习因果链**
>
>   模型之所以会学，不是因为训练脚本里出现了某些熟悉函数名，而是因为：前向给出答案，损失衡量错误，自动求导把错误变成梯度，优化器把梯度变成参数更新。只要这条因果链没在你脑子里站稳，后面所有训练工程都会显得空。
