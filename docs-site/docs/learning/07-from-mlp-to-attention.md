# 07. 为什么要有 Attention

## 这一章要解决什么问题

到这一章为止，你已经知道：

- 文本会被切成 token
- token 会变成向量
- 模型训练的目标是预测下一个 token

接下来必须回答一个核心结构问题：

> 当序列里有很多 token 时，模型究竟应该怎样利用前文？

如果这个问题没有讲透，Attention 就会一直像一个只能背公式的名词。你可能会记住 `Q`、`K`、`V`，也知道有一个 `softmax(QK^T / sqrt(d))V` 的公式，但仍然不知道：

- 为什么要发明这种机制
- 它到底在解决什么困难
- 它和普通前馈网络、固定窗口方法有什么本质区别

这一章的目标，就是把 Attention 还原成一个非常具体的问题解法：

> 模型需要一种办法，让每个位置都能按内容动态决定“应该关注前面哪些位置”，而不是只能使用固定规则读取上下文。

## 第一件事：语言模型最难的地方，不是“对一个 token 做复杂计算”

这是理解 Attention 的起点。

很多初学者第一次想象语言模型时，会以为困难主要来自：

- 词很多
- 参数很多
- 神经网络很深

这些都是真的，但语言模型真正麻烦的地方在于：

> 每个位置需要的信息来源不是固定的，而是随上下文变化的。

例如同一个词，在不同句子里可能要依赖完全不同的历史信息：

- 有时只需要看前一个词
- 有时需要看前几十个 token
- 有时需要追踪主语
- 有时需要追踪实体名
- 有时需要判断前面一句话的叙事方向

所以问题的核心不是“这层网络够不够复杂”，而是：

> 它有没有能力根据当前内容，动态选择应该参考哪些历史位置。

## 第二件事：为什么普通 MLP 不擅长解决这个问题

先把最自然的疑问讲清楚：

> 既然多层感知机可以拟合复杂函数，为什么不直接用 MLP 处理序列？

### MLP 的强项是什么

MLP 擅长的是：

- 对固定形状输入做一系列非线性变换
- 在给定输入结构下学习复杂映射

如果你的输入是：

- 一组固定特征
- 一个小向量
- 没有强烈“位置之间动态交互”需求的数据

那么 MLP 很可能是一个好起点。

### 语言模型的难点和 MLP 的短板在哪

语言模型处理的不是单个向量，而是一整段序列。真正关键的问题不是：

> 当前位置能不能做非线性变换？

而是：

> 当前位置该从前面的哪几个位置取信息？

MLP 本身没有一种天然机制去表达这种“按内容路由信息”的行为。你当然可以把整段序列展平后交给它，但那会带来几个问题：

- 输入长度通常要固定得很死
- 位置之间的作用关系是写死在参数里的
- 很难形成“这个位置今天重点看第 3 个 token，明天重点看第 27 个 token”这种动态能力

因此，MLP 可以处理向量，但不擅长承担语言模型里最关键的“动态上下文选择”任务。

## 第三件事：固定窗口方法为什么也不够

在 Attention 之前，人们也并不是完全没有做法。你可以想到一些固定窗口策略，例如：

- 只看前 2 个 token
- 只看前 5 个 token
- 使用固定卷积窗口
- 使用手工设计的上下文特征

这些方法在某些局部模式上可以有效，但它们有共同限制：

> 它们提前规定了“哪些位置值得看”，而不是让模型根据内容自己决定。

这会导致一个问题：

- 如果真正重要的信息刚好落在窗口内，模型还算幸运
- 如果真正重要的信息在窗口外，模型就根本拿不到

语言理解里很多依赖关系不是固定长度的，因此“固定窗口”不适合作为通用答案。

## 第四件事：Attention 的核心想法可以先不用公式来理解

先给出一个纯直觉版本：

> 对于序列中的每一个位置，模型都应该能够向当前可见上下文发起一次“查询”，根据匹配程度从不同位置收集信息，再把这些信息聚合成当前位置新的表示。

这句话里已经包含了 Attention 的本质：

- 不是固定看哪几个位置
- 不是平均所有位置
- 而是“先比较，再选择，再聚合”

这就是为什么 Attention 更像一个**动态读取上下文的机制**，而不是一个普通层名字。

## 第五件事：Q、K、V 不是神秘字母，而是三种职责

现在可以引入最常见的三个角色。

### Query：我现在想找什么

当前位置会携带一个“查询向量”。它表达的不是一句自然语言问题，而是：

> 按照当前层当前位置信息的需要，我现在希望在上下文里寻找哪类线索？

### Key：我这里能提供什么线索

上下文中的每个位置，也会携带一个“键向量”。它表达的是：

> 如果别人来找信息，我这个位置值得被怎样匹配？

### Value：如果你关注我，你真正拿走什么内容

位置被匹配上之后，真正被聚合走的通常是另一份表示，也就是 value。

### 为什么要分成三份

因为“如何匹配我”和“你最终从我这里读走什么信息”并不一定是同一回事。

所以 `Q`、`K`、`V` 三者分别承担：

- 查询需求
- 可匹配线索
- 实际内容载体

理解这一点，比记住字母本身更重要。

## 第六件事：Attention 的真正输出，不是某个历史位置，而是一个加权摘要

很多初学者会误以为 Attention 像是在“挑出最重要的那个 token”。这不完全对。

更准确的说法是：

> Attention 为当前位置构造了一个对历史信息的加权摘要。

这意味着：

- 某个位置可以被强烈关注
- 多个位置也可以同时以不同权重参与
- 输出通常是很多 value 的加权组合，而不是单一硬选择

这使得模型既能：

- 强调关键位置
- 又不必完全抛弃次要信息

## 第七件事：公式到底在表达什么

标准缩放点积注意力写成：

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V
\]

不要急着把它当成需要死记的公式，把它拆成三步看。

### 第一步：`QK^T` 计算匹配分数

这是在问：

> 每个 query 和每个 key 的相似程度有多高？

分数越高，说明当前位置越应该从那个历史位置读信息。

### 第二步：`softmax` 把分数变成权重

这一步的作用是：

- 让所有候选位置的分数变成可比较的权重分布
- 权重大表示更值得关注
- 权重小表示影响较弱

### 第三步：权重乘以 `V`

这一步相当于：

> 按照刚刚算出来的权重，把各个位置的信息汇总起来。

最终得到的就是当前位置新的上下文感知表示。

## 第八件事：为什么要除以 `sqrt(d)`

如果不做这个缩放，随着向量维度变大，点积结果可能会变得很大，从而让 softmax 过于尖锐：

- 某一项几乎接近 1
- 其他项几乎接近 0

这会让训练更不稳定，也不利于模型在多个候选位置之间形成细致权衡。

所以除以：

\[
\sqrt{d}
\]

可以理解成一种尺度修正，让分数落在更适合 softmax 工作的范围内。

## 第九件事：多头注意力为什么比单头更强

如果只有一个头，那么模型在这一层里只能使用一套相关性模式。

而多头注意力的想法是：

> 把表示空间切成多个子空间，让不同头并行学习不同类型的依赖关系。

这不意味着每个头都会变成“人类可解释的小专家”，但它确实带来了一个重要优势：

- 一个头可以更关注局部搭配
- 另一个头可以更关注长程依赖
- 还有的头可能更关注语法或边界模式

所以多头的价值是：

> 给模型更多并行表达不同关系的机会。

## 第十件事：为什么语言模型里的 Attention 必须是 causal 的

到这里有一个非常关键的限制必须加入：

> 当前位置不能偷看未来。

如果模型在预测第 `t` 个位置之后的 token 时，能直接访问更后面的真实 token，那么训练任务就被破坏了。

### 这会导致什么问题

模型看起来也许会在训练时得到很漂亮的 loss，但它实际上学到的是：

> 在知道后文答案的情况下复述答案。

而推理时根本没有未来真值可以看，所以表现会立刻坍塌。

因此，decoder-only 语言模型中的 self-attention 必须加上因果约束，也就是：

- 当前位置可以看自己和之前的位置
- 不能看未来位置

这就是 causal attention。

## 第十一件事：Attention 不是在替代位置信息

很多初学者学到这里会问：

> 如果 Attention 已经能比较所有位置了，那为什么还需要位置编码？

答案是：

> 因为“比较谁”和“知道谁在前谁在后”是两回事。

如果完全不给模型位置信息，那么同样一组 token 只是换了顺序，模型很难准确区分它们的时序关系。

所以真正可用的 Transformer 一般还会配合某种位置表示方式，例如：

- 绝对位置编码
- 正弦位置编码
- 相对位置方法
- RoPE

Attention 负责动态选择，位置编码负责告诉模型“这些位置在序列里的相对或绝对关系”。

## 第十二件事：从一个小例子理解“动态关注”比死记公式更重要

假设当前位置想找“和自己最相关的历史信息”。如果它面对三个候选位置：

- 位置 A：高度匹配
- 位置 B：中等匹配
- 位置 C：几乎不匹配

那么经过打分和 softmax 后，模型可能得到类似：

```text
A: 0.75
B: 0.20
C: 0.05
```

最终输出就是对三个 value 的加权组合。

这个例子说明了 Attention 最核心的特征：

> 不是每次都看固定位置，而是每次根据当前内容，重新计算“谁值得看”。

## 第十三件事：Attention 解决了什么，没有解决什么

理解边界非常重要。

### Attention 解决了什么

- 让每个位置能动态读取上下文
- 让依赖关系由内容决定而不是由固定窗口决定
- 为长距离信息交互提供统一机制

### Attention 没有单独解决什么

- 它没有替代位置编码
- 它没有替代归一化和残差
- 它没有替代逐位置的非线性变换
- 它没有自动保证训练稳定

所以：

> Attention 是 Transformer 的核心部件之一，但不是完整模型本身。

## 第十四件事：初学者最容易误解的几点

### 误区 1：Attention 就是在“平均所有 token”

不是。它是按内容动态计算权重后的加权聚合。

### 误区 2：Q、K、V 是人为写死的语法标签

不是。它们通常由可学习投影产生，是模型自己学出来的表示。

### 误区 3：有了 Attention，模型就自然会理解长文本

不对。它只是提供了动态读取上下文的能力，真正效果还取决于：

- 数据
- 训练
- 模型规模
- 位置编码

### 误区 4：多头只是“复制几份 Attention”

也不对。多头的价值在于把表示能力拆成多个并行子空间。

<Callout title="这一章真正要你记住的不是公式，而是问题定义" tone="note">
  Attention 之所以重要，不是因为它长得像一道高级公式，而是因为语言模型需要一种机制，让每个位置都能按内容动态决定自己该从哪里读取信息。理解了这一点，Transformer 结构才会真正开始变得清晰。
</Callout>
