# 07. 从 MLP 到 Attention

## 这一章要解决什么问题

到这里你已经知道语言模型的输入、目标和训练方式，但还有一个关键问题没回答：

> 为什么不能只用普通前馈网络，而要引入 Attention？

如果这个问题想不清楚，Attention 就会一直像一种“Transformer 必须配备的魔法组件”，而不是一个为了解决特定信息流问题而出现的结构。

## 你需要先知道什么

- 理解 token 序列和隐藏状态。
- 理解语言模型必须在每个位置上根据前文预测下一 token。

## 核心概念

### 1. MLP 不擅长处理“不同位置之间的动态关联”

一个普通 MLP 擅长做的是：

- 把固定长度输入映射成固定长度输出
- 在每层做非线性变换

但在语言模型里，关键困难不是“对单个 token 做复杂变换”，而是：

- 第 20 个 token 需要决定自己该关注第 3 个还是第 19 个 token
- 这个关注关系会随着上下文变化

MLP 本身没有一套天然机制去表达“当前位置应该动态参考哪些其他位置”。

### 2. Attention 的核心任务是“按需读上下文”

Self-attention 可以粗略理解成：

1. 每个位置发出一个查询：我现在想找什么信息？
2. 每个位置提供一个键：我这里有什么信息值得被匹配？
3. 每个位置提供一个值：如果你关注我，就把这份信息拿走

这样当前位置就能根据查询与所有键的匹配程度，决定自己该从哪些位置聚合信息。

### 3. Q、K、V 不是神秘符号，而是三种不同角色

- `Q`：当前位置正在找什么
- `K`：每个位置能提供什么线索
- `V`：真正被拿来加权聚合的信息

为什么不直接只用一个向量？因为“匹配谁”和“读出什么”是两种不同职责。

### 4. 点积相似度决定注意力强弱

最常见的注意力权重来自：

\[
QK^\top
\]

如果某个 query 和某个 key 的点积更大，说明两者更匹配，模型就更倾向于从那个位置取信息。

### 5. causal self-attention 只允许看当前位置及其之前

对语言模型来说，attention 不是任意双向读取，而是有顺序限制的。当前位置可以参考前文，但不能参考未来。

## 最小必要数学

标准缩放点积注意力可写成：

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V
\]

你现在需要掌握的是三个层次：

1. `QK^T` 计算匹配分数
2. softmax 把分数变成权重
3. 权重乘 `V` 得到聚合后的上下文表示

## 最小代码实验

```python
import torch

q = torch.tensor([[1.0, 0.0]])
k = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
v = torch.tensor([[10.0, 0.0], [0.0, 20.0]])

scores = q @ k.T
weights = torch.softmax(scores, dim=-1)
output = weights @ v

print("scores:", scores)
print("weights:", weights)
print("output:", output)
```

这个例子里：

- 第一个 key 与 query 更匹配
- 所以输出更偏向第一个 value

你可以把它想象成“当前位置在上下文里查找最相关的信息，再把对应内容读出来”。

## 常见误区

### 误区 1：Attention 就是在“平均所有 token”

不是。它是一个**加权聚合**，不同位置的权重通常不同，而且是动态计算出来的。

### 误区 2：Q、K、V 是从外部手工指定的

在神经网络里，Q、K、V 通常来自可学习线性投影。也就是说，模型会自己学会怎样表示“要找什么”和“可提供什么”。

### 误区 3：Attention 解决了一切

Attention 很强，但它不是完整模型。它负责跨位置读写信息，后面还需要残差连接、归一化、前馈网络等结构来稳定训练并提高表示能力。

<Callout title="为什么这一章是分水岭" tone="note">
  一旦你理解 Attention 的职责，Transformer 就不再是一坨不可拆分的黑箱，而是“按需读上下文 + 做局部变换 + 稳定堆叠”的组合系统。
</Callout>
