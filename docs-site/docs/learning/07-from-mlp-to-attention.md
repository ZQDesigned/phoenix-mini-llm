# 07. 为什么要有 Attention

## 这一章要解决什么问题

到这里为止，你已经知道语言模型在做什么：

- 它接收一串 token
- 它为每个位置预测下一个 token
- 它通过梯度下降不断调整参数

但你还没有真正回答一个结构层面的核心问题：

> 当模型面对一整段上下文时，它到底应该怎样“使用前文”？

这不是一个实现细节，而是语言模型主体结构最根本的问题。

因为对语言来说，最难的地方从来不是“把一个 token 变复杂”，而是：

> 当前这个位置到底该从之前的哪些位置拿信息？

如果这个问题没有讲透，那么你后面看到 `Q`、`K`、`V`、多头注意力、KV cache、RoPE 这些词时，只会觉得它们像一套被硬塞进项目里的术语集合，而不会知道它们为什么存在。

这一章的目标，是把 Attention 还原成一个非常朴素的问题解法：

> 模型需要一种机制，让每个位置都能根据当前内容，动态决定自己应该重点参考哪些历史位置。

## 先把问题看准：序列建模最难的是“信息路由”

很多初学者第一次接触语言模型时，会把困难想成下面这些事情：

- 词表很大
- 参数很多
- 网络很深
- 训练很慢

这些都是真的，但它们都不是最核心的结构困难。

语言模型真正棘手的地方在于：

> 同一个位置在不同上下文里，需要依赖的信息来源完全可能不同。

例如，一个句子里的当前位置，有时只需要看前一个 token：

```text
I am going to the ...
```

这里模型很可能只需要局部上下文就能做出不错判断。

但有时它需要参考更早的位置：

```text
The book that I bought yesterday, after waiting for two weeks, was ...
```

当模型要继续这个句子时，真正关键的信息可能出现在很久之前。

再例如，在一段对话里：

```text
User: 我想买一台轻薄本。
Assistant: 你的预算大概是多少？
User: 六千左右。
Assistant: 那我会先排除一些高端游戏本，因为 ...
```

当模型预测最后一句时，它需要记住“预算大概是多少”这个线索，而不是只看最近几个 token。

所以问题的本质不是：

> “我能不能对当前 token 做复杂计算？”

而是：

> “我能不能让当前 token 按内容去查找真正相关的历史信息？”

这就进入了信息路由的问题。所谓信息路由，你可以先把它理解成：

> 模型必须决定，历史序列里哪些部分应该被当前这个位置读到，哪些部分应该影响很小，哪些部分几乎不该参与。

如果没有这种能力，模型就只能靠固定规则读上下文。而语言的依赖关系恰恰不是固定的。

## 为什么“固定规则读上下文”不够

最容易想到的办法，是用固定窗口。

例如：

- 永远只看前 2 个 token
- 永远只看前 8 个 token
- 用一个固定大小的卷积窗口
- 手工设计一些局部特征

这种方法并不是完全没用。很多局部模式确实能靠短窗口捕捉到，比如：

- 常见搭配
- 局部语法
- 标点附近的短依赖

但一旦语言现象跨出这个窗口，问题就出现了。

例如：

```text
如果你读完整本说明书之后，仍然不知道那个开关的作用，那么你需要重新检查第一页里提到的安全提示，因为 ...
```

这时真正重要的信息可能离当前位置非常远。固定窗口如果看不到，它就不是“看得不太准”，而是“根本拿不到”。

这类方法有一个共同限制：

> 它们提前规定了“值得看哪些位置”，而不是让模型在运行时根据内容自己决定。

而语言恰恰要求后一种能力。

## 为什么单纯靠 MLP 也不自然

另一个直觉是：

> 既然多层感知机足够强，为什么不把整个上下文展平成一个大向量，直接交给 MLP？

这在小玩具任务上不是完全不行，但它并不适合作为现代语言模型主体，原因有几层。

### 第一层原因：输入结构不自然

MLP 最擅长的是处理固定形状输入。可语言序列天然带有顺序和位置之间的关系。

如果你把一段长度为 `T` 的序列直接展平成一个大向量，那么：

- 输入长度必须被提前钉死
- 每个位置都被写死在一组参数坐标里
- 一旦想支持更长或不同长度，结构会变得很不灵活

### 第二层原因：关系被“烙死”在参数里

如果一个当前位置有时该看第 3 个 token，有时该看第 17 个 token，有时该看第 42 个 token，MLP 当然理论上可能学出来。

但问题在于，这种“今天重点看哪里”的机制并不是 MLP 的天然工作方式。它更像是在让一个本来不擅长动态查找的结构，硬背出很多特殊情况。

MLP 很强，但它天然表达的是：

> 对一个整体输入做固定形式的非线性变换。

而语言模型真正需要的更像是：

> 当前位置先决定自己要找什么，再去上下文里按内容检索。

这不是 MLP 最顺手的能力。

## 只靠“压缩整段历史”为一个向量，也有明显瓶颈

在 Transformer 普及之前，序列模型常常会让历史信息逐步被压进一个较小的状态里。

你现在不需要系统学习整套 RNN 家族，但需要理解一个很重要的直觉：

> 如果模型必须把越来越长的历史，持续压缩到有限大小的状态里，那么它会面临信息瓶颈。

设想一下，你一边读一部长小说，一边被要求：

> 你不能保留原文，只能把已经读过的所有内容压缩成一段固定长度的摘要，并且以后只能依赖这个摘要继续回答问题。

理论上这段摘要可以很聪明，但随着上下文越来越长，真正可用的信息选择会变得很难。

语言模型当然可以学习出某种压缩方式，但这种方式的问题在于：

- 早期信息可能被后续内容不断挤压
- 想精准找回某个具体细节并不自然
- 当前需要什么，只能依赖已有状态中是否正好保留了它

这和“需要时再去原始上下文中按内容查找”相比，灵活性差很多。

Attention 的价值，正是在这里变得清楚：

> 它不是强迫所有历史先被压缩成一个固定瓶颈，而是让当前位置在需要时可以直接回到可见历史中做内容检索。

## 把 Attention 先当成“按内容检索”的机制

在不写任何公式之前，你可以先用一个图书馆比喻来理解它。

想象你正在写一句话的下一个词。你手里有一个“当前问题”：

> 现在我最需要的历史线索是什么？

历史上下文里的每个位置，都像一本可供查询的小卡片。每张卡片都告诉你两件事：

- 我大概和哪类问题相关
- 如果你真的查我，我能提供什么信息

于是当前位置会做三件事：

1. 形成自己的查询需求  
2. 和历史各位置比较匹配程度  
3. 按匹配程度聚合那些位置携带的信息  

这就是 Attention 最朴素的工作方式。

它的要点不在于“看所有位置”，而在于：

> 先比较，再决定权重，再聚合信息。

所以 Attention 和“把所有 token 做个平均”完全不是一回事。

## Query、Key、Value 分别是什么

现在可以把最常见的三个术语接进来。

### Query：当前位置现在在找什么

当前位置会产生一个向量，它表达的不是一句自然语言问题，而是：

> 按当前层、当前位置的状态来看，我此刻需要从历史里寻找什么类型的线索？

例如，它可能更偏向寻找：

- 与当前实体相关的历史位置
- 能帮助决定语法形式的线索
- 和当前主题最相关的上下文片段

它不需要人类给它标注“请去找主语”或“请去找引用对象”。这些都是模型自己在训练中学出来的统计需求。

### Key：每个历史位置能被怎样匹配

上下文中的每个位置，也会各自产生一个向量，表示：

> 如果有人来找信息，我这个位置适合被怎样识别？

你可以把它理解成“可检索标签”，但这个标签不是离散词，而是连续向量空间中的匹配线索。

### Value：如果你关注我，你最终读走什么

位置被关注之后，真正被聚合的通常是 value。

也就是说，一个位置可以这样理解自己：

- `key` 负责告诉别人怎么找到我
- `value` 负责告诉别人从我这里真正拿走什么

### 为什么不直接只保留一份向量

这是初学者常见疑问：

> 既然每个位置本来就有隐藏状态，为什么还要拆成 `Q`、`K`、`V`？

因为“如何匹配”和“提供什么内容”并不一定是同一件事。

一个位置可能因为某种语义特征而被找到，但被找到之后，真正有用的是它携带的另一部分综合表示。

把这两个职责分开，会让模型更灵活。

## 从一个小例子理解加权读取

假设当前位置要预测后续词，它在历史里看到 4 个可见位置。经过匹配之后，得到一个分数表：

```text
位置 1: 2.8
位置 2: 0.4
位置 3: 1.9
位置 4: -0.2
```

这些数字还不是最终权重，它们只是“匹配得有多像”的原始打分。

接着，模型会把这些分数变成一组更适合比较的权重，例如：

```text
位置 1: 0.59
位置 2: 0.07
位置 3: 0.28
位置 4: 0.06
```

于是当前位置就不会“一刀切地只读一个位置”，而是：

- 主要参考位置 1
- 次要参考位置 3
- 让位置 2 和位置 4 的影响较小

最后输出的是四个 value 的加权组合。

这个例子里最重要的理解不是具体数值，而是：

> 当前位置每次都会根据上下文重新计算“谁更值得看”，而不是永久使用同一套固定规则。

## Attention 公式到底在表达什么

标准缩放点积注意力常写成：

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V
\]

第一次看到这行公式时，很多人会本能地想背它。其实更好的方式是把它拆成一条数据流。

### 第一步：`QK^T` 计算匹配分数

这是在回答：

> 每个 query 和每个 key 的匹配程度有多高？

匹配高，说明当前位置更应该从那个位置读信息。

匹配低，说明那个位置和当前需求相关性较弱。

这里常用的是点积相似度。你不必把它神化成唯一正确选择，只需要理解：

> 点积提供了一种高效、可学习的“向量相似性”度量。

### 第二步：除以 `sqrt(d)` 做尺度修正

如果向量维度很大，点积数值容易变得过大。这样一来，后面的 softmax 会过于尖锐，导致训练不稳定。

为什么会这样？

因为 softmax 很敏感。当某些值远大于其他值时，它会几乎把全部权重压到一个位置上：

```text
0.999, 0.001, 0.000, ...
```

这会让模型更难在多个候选之间形成细致权衡。

因此除以 `sqrt(d)` 可以理解为：

> 把分数缩回更适合 softmax 工作的范围。

它不是“数学装饰”，而是训练稳定性相关的一步尺度管理。

### 第三步：`softmax` 把分数变成权重分布

这一步做的事情是：

- 把原始打分转成可比较的非负权重
- 让权重总和变成 1

于是模型就能把“匹配程度”变成真正可用于加权聚合的系数。

### 第四步：用权重组合 `V`

最后，模型按这些权重对 value 做加权求和。

这相当于说：

> 我不会简单拷贝某个历史位置，而是基于当前需求，从多个位置读取一份上下文摘要。

注意，“摘要”不等于“平均”。因为不同位置的权重并不一样。

## Attention 矩阵在描述什么

当模型同时处理一整个序列时，并不是只有一个 query。

序列中的每个位置都会产生自己的 query，于是你可以把整层注意力想成一个二维匹配表：

- 行：谁在提问
- 列：谁可能被读取

这个表中的每个格子，都代表：

> 某个位置对另一个位置的关注程度。

如果把整个序列都放在一起看，这就形成了注意力矩阵。

这个矩阵的价值在于，它让“位置之间如何交换信息”变成了显式、可学习的结构。

和固定窗口不同，这张表不是人为写死的，而是在每次前向传播中根据当前内容动态算出来的。

## 语言模型里的 Attention 必须是因果的

到这里，有一个对语言模型至关重要的限制必须加入：

> 当前位置不能偷看未来。

为什么？

因为我们的任务定义是：

> 根据前文预测下一个 token。

如果在训练时，位置 `t` 能直接看到 `t+1` 甚至更后面的真实 token，那么这个任务就被破坏了。

模型表面上可能学得很好，loss 甚至会非常漂亮，但它学到的其实是：

> 在已经知道答案的情况下，把答案再抄一遍。

这会造成一个严重问题：

- 训练时表现很好
- 推理时表现崩掉

因为推理阶段根本没有未来 token 可看。

所以 decoder-only 语言模型必须使用因果注意力，也常叫 causal self-attention。

它的规则很简单：

- 当前位置可以看自己
- 可以看之前的位置
- 不能看未来的位置

这通常通过 mask 来实现。

## Mask 不是修饰项，而是任务定义的一部分

初学者有时会把 mask 当成一个很小的工程细节。其实不是。

如果没有正确的因果 mask，那么你实现的就不是我们要的自回归语言模型。

你得到的将会是另一种任务：

> 在看见完整句子的情况下预测某个位置。

这和从左到右生成文本不是同一个问题。

因此，mask 的重要性几乎和 loss 定义本身一样高。它直接决定模型到底在学什么。

## 为什么要有多头注意力

如果只有一个头，那么一层注意力里只有一套匹配模式。

这并非完全不能工作，但表达能力会受到限制。因为序列中的相关性并不只有一种。

同一个位置同时可能需要：

- 一个偏局部的语法线索
- 一个偏长程的实体线索
- 一个偏边界或结构的线索

多头注意力的核心想法是：

> 把隐藏表示拆成多个子空间，让不同头并行学习不同类型的关注关系。

这不意味着每个头都一定能被人类清楚命名成“这个头负责主谓一致，那个头负责代词回指”。现实中很多头的作用没那么整齐。

但多头的总体价值很明确：

- 它允许模型同时保留多种信息路由模式
- 它降低了“所有关系都挤在一套注意力里”的压力
- 它让同一层具备更丰富的表示能力

## 多头不是简单复制，而是并行子空间建模

你可以把多头理解成“复制很多份注意力”，但这只是最表面的说法。

更准确地说，是：

> 先把表示投影到多个不同子空间，再在每个子空间里独立做一次注意力，最后把结果拼回去。

这样做的意义在于：

- 每个头看到的是同一位置在不同投影下的表示
- 不同头可以形成不同的相似性判断
- 拼接后再投影回统一隐藏空间

这让模型不仅“多看几次”，而且“从不同角度看几次”。

## Attention 解决了什么，又没有解决什么

理解边界非常重要。很多术语之所以让人混乱，是因为它们的职责被说大了。

### Attention 解决了什么

- 动态决定该读哪些历史位置
- 让依赖关系由内容决定，而不是由固定距离决定
- 为长距离交互提供统一机制
- 让整个序列内的信息交换更直接

### Attention 没有单独解决什么

- 它没有自己提供顺序信息
- 它没有自己保证深层训练稳定
- 它没有自己完成逐位置强非线性加工
- 它没有自动降低训练成本

所以 Attention 很重要，但它不是完整模型。它只是完整 Transformer 系统里解决“信息路由”的那个核心部件。

## 为什么还需要位置编码

一个很自然的问题是：

> 如果 Attention 已经可以在所有位置之间比较相关性，为什么还需要位置编码？

答案是：

> 因为“谁和谁相关”与“谁在前谁在后”不是一回事。

如果完全不给位置信息，那么模型在某种意义上只看到一组内容向量。顺序发生变化时，许多重要差别并不会被可靠表达。

例如：

```text
dog bites man
man bites dog
```

它们包含几乎相同的词，但顺序变化导致含义完全不同。

Attention 本身负责动态读取，位置编码负责告诉模型：

- 这些 token 在序列中的先后关系是什么
- 它们之间的相对距离大致怎样

所以两者是配合关系，而不是替代关系。

## Attention 让“内容寻址”成为可能

如果要用一句话概括 Attention 的革命性变化，可以说：

> 它让模型从“按固定结构读历史”转向“按内容检索历史”。

这件事的重要性非常大。因为一旦模型可以内容寻址，它就不再必须：

- 事先知道依赖距离
- 只依赖最近几个 token
- 把所有历史都压缩进一个单一状态瓶颈

它可以在每个位置、每一层、每一次前向传播中重新决定自己的读取路径。

这正是 Transformer 能在语言任务上表现强大的关键原因之一。

## Attention 的代价是什么

任何能力都不是白来的。Attention 带来的主要代价之一，是计算和内存成本。

如果序列长度是 `T`，那么所有位置两两打分的那张表，规模大致和 `T × T` 有关。

这意味着：

- 序列越长，计算越贵
- 显存占用也会显著上升

这就是为什么上下文长度一变长，训练和推理成本都会明显增加。

所以 Attention 不是“既灵活又没有代价”的免费午餐。它用更高的全局交互成本，换来了更强的动态依赖建模能力。

这也是后面为什么会出现：

- KV cache
- 长上下文优化
- 稀疏注意力
- 各种高效注意力变体

因为一旦你理解了 Attention 的好处，也就会自然理解大家为什么一直在优化它的成本。

## 看到注意力图，不要过度神话解释性

很多学习资料会展示注意力热力图。它们很有帮助，因为能让你看到“模型在某些位置上关注了哪里”。

但需要保持一个理性态度：

- 注意力图能提供线索
- 注意力图不是完整解释
- 某个头看起来像学到了某种规律，不代表所有行为都能被简单归因

也就是说，注意力图适合作为理解工具，但不要把它误当成“模型内部思想的完整窗口”。

## 初学者最容易误解的几点

### 误区 1：Attention 就是在平均所有 token

不是。它是先算匹配，再按权重聚合。不同位置的影响大小通常差别很大。

### 误区 2：`Q`、`K`、`V` 是人类手工定义的规则标签

不是。它们通常是由当前隐藏表示经过可学习线性投影产生的，是训练中学出来的表示。

### 误区 3：有了 Attention，模型自然就会理解长文本

不对。Attention 只提供了动态读取上下文的能力。实际效果还取决于：

- 数据质量
- 模型规模
- 位置方法
- 训练是否充分

### 误区 4：多头就是把同一件事重复做很多次

不完全对。多头更像是在多个子空间里并行建模不同关系模式。

### 误区 5：mask 是后期优化细节

不对。对自回归语言模型来说，因果 mask 是任务定义的一部分。

## 这一章真正要记住的核心句子

如果这一章你最后只记住一句话，那么应该是：

> Attention 的本质不是一条公式，而是一种内容驱动的信息路由机制：当前位置会根据自己的需要，动态决定该从可见历史中的哪些位置读取信息。

理解了这句话，后面的 Transformer Block、KV cache、推理加速、长上下文成本，都会开始变得顺理成章。
