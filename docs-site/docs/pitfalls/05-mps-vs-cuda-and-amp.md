# 05. MPS 与 CUDA 的精度差异

## 发生背景

这个项目明确面向一种非常典型的开发流程：

- 在 macOS 上编写代码和做小规模验证
- 在 Windows + NVIDIA GPU 上正式训练

这意味着你迟早会面对一个事实：MPS 和 CUDA 不是同一个运行时环境。

## 现象

常见现象包括：

- macOS 上能跑，Windows CUDA 上数值表现不同
- CUDA 开启 AMP 后 loss 行为改变
- 同一随机种子下，两边结果不完全一致

## 一开始的错误判断

最容易出现的误判是：

- “两边结果不一样，一定有一边错了”
- “MPS 能跑通，就代表 CUDA 也一定没问题”
- “AMP 只是更快，不会影响训练行为”

这些结论都过于乐观。

## 最终原因

MPS 与 CUDA 的差异来自多个层面：

- 支持的算子集合不同
- 混合精度实现不同
- 数值误差累积方式不同
- 内存管理策略不同

因此你不能把“设备后端”看成一个可随意替换的黑盒。

## 诊断过程

正确的排查顺序通常是：

1. 先在两边都用最保守配置验证逻辑正确性。
2. 再逐步在 CUDA 上开启 AMP、增大 batch 或调整配置。
3. 比较的是趋势和稳定性，而不是逐步浮点值完全相同。

## 修复方式

工程上最稳妥的做法是：

- 设备检测统一封装
- 混合精度只在 CUDA 条件启用
- 非 CUDA 路径优先走更保守的普通精度

例如：

```python
if training_config.amp and device.type == "cuda":
    ...
```

## 如何避免再次踩坑

1. 在 macOS 上把目标定义为“验证逻辑”和“小规模 smoke run”，不要把它当最终训练平台。
2. 在 Windows CUDA 上再做显存与精度调优。
3. 当两边行为不一致时，先缩小配置，把问题收敛到最小复现实验。

<Callout title="真正该追求的一致性" tone="note">
  你要追求的是训练趋势、接口行为和工程逻辑的一致，而不是每一步的浮点结果逐位一致。
</Callout>
