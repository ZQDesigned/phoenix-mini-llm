# 06. 过度覆写 dumi 默认布局

## 发生背景

在文档站初版里，为了追求“更有设计感”的视觉效果，对 `dumi` 默认主题做了大量全局覆写：背景渐变、玻璃态卡片、头部和正文容器的统一重绘，甚至直接去改默认布局类名。

## 现象

最终表现出来的不是“更成熟”，而是：

- 信息层级被装饰压过
- 侧栏、正文和首页的节奏被打乱
- 响应式表现变差
- 站点看起来不像技术文档，而像半成品视觉实验

## 一开始的错误判断

最容易出现的错误判断是：

- 以为问题只是配色不好
- 以为再多加一点自定义样式就能救回来
- 以为视觉问题和内容结构无关

实际上，问题根源在于“过度对抗默认布局”。

## 最终原因

`dumi` 默认主题已经替文档站处理了很多成熟约束：

- 正文宽度
- 标题和导航关系
- 侧栏与内容区的响应式行为
- 首页 hero/features 的节奏

当你用一大坨全局样式强行改写这些区域时，实际上是在同时破坏这些成熟约束。

## 修复方式

这次重构的原则变成：

1. 优先使用 `themeConfig`
2. 优先通过 frontmatter 和 markdown 组织内容
3. 只在局部组件上做表达性增强
4. 把全局样式控制在“品牌色、轻度间距和阅读友好”范围内

## 如何避免再次踩坑

- 不要把“设计感”建立在覆盖默认布局骨架之上。
- 对文档站来说，阅读顺序和内容层级永远优先于装饰。
- 想改样式时，先问自己：这是不是可以通过内容结构而不是全局覆写解决？

<Callout title="这次重构的关键经验" tone="note">
  不是所有页面都适合用“产品官网式”设计语言。技术文档首先是阅读工具，其次才是视觉作品。
</Callout>
