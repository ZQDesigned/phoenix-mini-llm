推荐路径

如果你想真正从 0 学会做一个小语言模型，建议按这个节奏推进。

Step 1

先搭认知地图

先看卷一到卷十，把“文本为什么要变成 token”“为什么训练目标是右移一位”“为什么 Attention 会出现”这一整条链先建立起来。

Step 2

再开始复做工程

跟着 10 章复刻教程从项目骨架一路做到训练与采样，不跳步骤，不直接复制现成代码结论。

Step 3

碰到问题再回坑位日志

当环境、设备、Tokenizer 元数据或部署路径出问题时，再回到踩坑记录，按案例定位问题和约束。

学完后你应该会

不是“把项目跑起来”，而是能把同类模型重新做一遍，并解释每个设计为什么存在。

解释机制

你能解释 token、embedding、cross-entropy、attention、checkpoint、KV cache 在同一台模型里分别扮演什么角色。

独立落地

你能从空目录开始配置 `uv`、组织 Python 包、准备语料和 tokenizer，再把训练与推理链路完整接起来。

跨平台推进

你能在 macOS 上做开发验证，在 Windows + CUDA 上做正式训练，并知道哪些差异需要在项目结构里提前处理。

系统排错

当 loss 不降、采样异常、路径错乱或 Pages 部署有偏差时，你知道应该先检查哪一层，而不是盲目改代码。

项目聚焦

这套项目关注什么

  • 一个适合学习的小型 decoder-only 语言模型
  • 从语料、Tokenizer、模型、训练到生成的完整链路
  • 可以在有限显存约束下跑通并理解的实现

项目不追求

这套项目不做什么

  • 不把重点放在超大参数规模或“伪大模型”营销感上
  • 不把文档写成只会教人复制命令的部署说明
  • 不把工程化包装成脱离原理的黑箱脚手架
